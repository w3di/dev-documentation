## 1. Элемент form — атрибуты и поведение

### Базовая структура

Элемент `<form>` является контейнером для интерактивных элементов управления, предназначенных для отправки данных на сервер. Браузер при обработке формы создаёт внутренний объект, ассоциированный с `HTMLFormElement` интерфейсом.

```html
<form
  action="/api/submit"
  method="POST"
  enctype="multipart/form-data"
  novalidate
  autocomplete="on"
  accept-charset="UTF-8"
  rel="noopener"
  target="_self"
  name="registration"
>
  <!-- элементы формы -->
</form>
```

### Атрибут action

Атрибут `action` определяет URL, на который отправляются данные формы. Если `action` опущен или является пустой строкой, данные отправляются на URL текущей страницы.

```html
<!-- Абсолютный URL -->
<form action="https://api.example.com/submit">

<!-- Относительный URL -->
<form action="/api/submit">

<!-- Пустой или опущенный — отправка на текущую страницу -->
<form action="">
<form>
```

> **Важно:** Атрибут `formaction` на кнопке `<button>` или `<input type="submit">` переопределяет `action` формы. Это позволяет иметь несколько кнопок отправки с разными целевыми URL.

```html
<form action="/save">
  <button type="submit">Сохранить</button>
  <button type="submit" formaction="/save-draft">Сохранить как черновик</button>
  <button type="submit" formaction="/preview">Предпросмотр</button>
</form>
```

### Атрибут method

Определяет HTTP-метод отправки данных. Спецификация HTML допускает три значения:

| Значение   | Описание                                                       | Кодирование данных                |
|------------|----------------------------------------------------------------|-----------------------------------|
| `GET`      | Данные добавляются к URL как query string                      | `application/x-www-form-urlencoded` |
| `POST`     | Данные отправляются в теле запроса                             | Зависит от `enctype`              |
| `dialog`   | Закрывает `<dialog>`, в котором находится форма                | Данные не отправляются            |

```html
<!-- GET: данные в URL -->
<form method="GET" action="/search">
  <input name="q" value="html forms">
  <!-- Результат: /search?q=html+forms -->
</form>

<!-- POST: данные в теле -->
<form method="POST" action="/api/users">
  <input name="username" value="developer">
</form>

<!-- dialog: закрытие диалога -->
<dialog id="confirm">
  <form method="dialog">
    <button value="yes">Да</button>
    <button value="no">Нет</button>
  </form>
</dialog>
```

> **Gotcha:** `method="dialog"` устанавливает `returnValue` диалога в значение кнопки, которая была нажата. Это позволяет определить выбор пользователя после закрытия.

```javascript
dialog.addEventListener('close', () => {
  console.log(dialog.returnValue); // "yes" или "no"
});
```

### Атрибут enctype

Определяет MIME-тип кодирования данных при `method="POST"`:

| Значение                            | Описание                                         | Когда использовать                   |
|-------------------------------------|--------------------------------------------------|--------------------------------------|
| `application/x-www-form-urlencoded` | По умолчанию. Ключ=значение, разделены `&`       | Простые текстовые данные             |
| `multipart/form-data`               | Каждое поле в отдельном блоке с boundary          | Загрузка файлов, бинарные данные     |
| `text/plain`                        | Данные не кодируются                             | Отладка (не для production)          |

```html
<!-- Для загрузки файлов ОБЯЗАТЕЛЬНО multipart/form-data -->
<form method="POST" enctype="multipart/form-data" action="/upload">
  <input type="file" name="avatar">
  <button type="submit">Загрузить</button>
</form>
```

> **Критично:** Если при наличии `<input type="file">` не указать `enctype="multipart/form-data"`, браузер отправит только имя файла, а не его содержимое. Это одна из самых частых ошибок при работе с формами.

Формат `multipart/form-data` выглядит так в HTTP-запросе:

```
POST /upload HTTP/1.1
Content-Type: multipart/form-data; boundary=----WebKitFormBoundaryABC

------WebKitFormBoundaryABC
Content-Disposition: form-data; name="username"

developer
------WebKitFormBoundaryABC
Content-Disposition: form-data; name="avatar"; filename="photo.jpg"
Content-Type: image/jpeg

[бинарные данные файла]
------WebKitFormBoundaryABC--
```

### Атрибут novalidate

Отключает встроенную валидацию браузера при отправке формы. Элементы формы по-прежнему имеют состояния валидации (`:valid`, `:invalid`), но браузер не блокирует отправку и не показывает всплывающие подсказки.

```html
<!-- Валидация отключена на уровне формы -->
<form novalidate>
  <input type="email" required>
  <button type="submit">Отправить</button>
</form>

<!-- Или на уровне конкретной кнопки -->
<form>
  <input type="email" required>
  <button type="submit">Отправить</button>
  <button type="submit" formnovalidate>Сохранить черновик</button>
</form>
```

### Атрибут autocomplete

Управляет автозаполнением для всех элементов формы. Принимает значения `on` (по умолчанию) или `off`.

```html
<form autocomplete="off">
  <!-- Все поля по умолчанию без автозаполнения -->
  <input name="secret-code" type="text">

  <!-- Но конкретное поле может переопределить -->
  <input name="email" type="email" autocomplete="email">
</form>
```

### Атрибут rel

Определяет отношение между текущим документом и целью `action`. Поддерживаемые значения:

- `noopener` — целевой контекст не имеет доступа к `opener`
- `noreferrer` — заголовок `Referer` не отправляется
- `opener` — целевой контекст имеет доступ к `opener`

```html
<form action="https://external-service.com/process" rel="noopener noreferrer" target="_blank">
  <button type="submit">Обработать на внешнем сервисе</button>
</form>
```

### Свойства HTMLFormElement

```javascript
const form = document.querySelector('form');

// Коллекция всех элементов формы
form.elements; // HTMLFormControlsCollection

// Доступ к элементам по имени или индексу
form.elements.username; // <input name="username">
form.elements[0];       // первый элемент

// Количество элементов
form.length; // число

// Программная отправка
form.submit();       // отправляет БЕЗ вызова события submit
form.requestSubmit(); // отправляет С вызовом события submit и валидацией

// Сброс формы
form.reset();
```

> **Важно:** `form.submit()` не вызывает событие `submit` и не проверяет валидацию. Для корректной отправки с валидацией используйте `form.requestSubmit()`. Этот метод был добавлен позже и поддерживается во всех современных браузерах.

## 2. Input types — все типы HTML5

### Текстовые типы

#### type="text"

Базовый однострочный текстовый ввод. Принимает любые символы.

```html
<input type="text"
  name="username"
  placeholder="Введите имя"
  maxlength="50"
  minlength="3"
  size="30"
  pattern="[A-Za-z0-9_]+"
  spellcheck="false"
  autocomplete="username"
>
```

#### type="password"

Маскирует вводимые символы. Браузеры обычно отключают автодополнение и копирование из поля.

```html
<input type="password"
  name="password"
  minlength="8"
  maxlength="128"
  autocomplete="new-password"
  aria-describedby="password-hint"
>
<p id="password-hint">Минимум 8 символов, одна заглавная буква и цифра</p>
```

> **Безопасность:** Атрибут `autocomplete="new-password"` подсказывает менеджерам паролей, что это поле для создания нового пароля. Для входа используйте `autocomplete="current-password"`.

#### type="email"

Встроенная валидация email. Браузер проверяет наличие `@` и базовый формат. На мобильных устройствах показывает клавиатуру с символом `@`.

```html
<!-- Один email -->
<input type="email" name="email" required>

<!-- Множественные email через запятую -->
<input type="email" name="emails" multiple>

<!-- С паттерном для более строгой валидации -->
<input type="email"
  pattern="[a-z0-9._%+-]+@[a-z0-9.-]+\.[a-z]{2,}$"
  title="Введите корректный email адрес"
>
```

> **Gotcha:** Встроенная валидация email крайне минимальна. Строка `user@localhost` пройдёт валидацию. Для production всегда используйте серверную валидацию и дополнительный `pattern`.

#### type="url"

Валидирует URL. Требует наличия протокола (http://, https://, ftp:// и т.д.).

```html
<input type="url" name="website" placeholder="https://example.com">
```

#### type="tel"

Не имеет встроенной валидации, так как форматы телефонов различаются по странам. На мобильных показывает цифровую клавиатуру.

```html
<input type="tel"
  name="phone"
  pattern="\+7\s?\(\d{3}\)\s?\d{3}-?\d{2}-?\d{2}"
  placeholder="+7 (999) 123-45-67"
  title="Формат: +7 (999) 123-45-67"
>
```

#### type="search"

Семантически идентичен `text`, но браузеры могут отображать кнопку очистки и запоминать историю поиска.

```html
<input type="search"
  name="q"
  placeholder="Поиск..."
  aria-label="Поиск по сайту"
  list="search-suggestions"
>
<datalist id="search-suggestions">
  <option value="HTML формы">
  <option value="CSS Grid">
  <option value="JavaScript async">
</datalist>
```

### Числовые типы

#### type="number"

Принимает числовые значения. Браузер показывает стрелки увеличения/уменьшения (spinners).

```html
<input type="number"
  name="quantity"
  min="1"
  max="100"
  step="1"
  value="1"
>

<!-- Дробные числа -->
<input type="number" name="price" min="0" step="0.01">

<!-- Любое числовое значение без ограничения шага -->
<input type="number" name="measurement" step="any">
```

> **Gotcha:** `type="number"` НЕ подходит для ввода номеров кредитных карт, телефонов, почтовых индексов — это не числа в математическом смысле. Для таких данных используйте `type="text"` с `inputmode="numeric"` и `pattern`.

```html
<!-- Правильно для кредитной карты -->
<input type="text"
  inputmode="numeric"
  pattern="[\d ]{13,19}"
  name="card-number"
  autocomplete="cc-number"
>
```

#### type="range"

Ползунок для выбора числового значения в диапазоне. По умолчанию от 0 до 100.

```html
<label for="volume">Громкость: <output id="volume-output">50</output></label>
<input type="range"
  id="volume"
  name="volume"
  min="0"
  max="100"
  step="5"
  value="50"
  oninput="document.getElementById('volume-output').value = this.value"
>
```

### Типы даты и времени

Все типы даты и времени используют ISO 8601 формат для значений.

| Тип               | Формат значения          | Пример              | Поддержка       |
|-------------------|--------------------------|----------------------|-----------------|
| `date`            | `YYYY-MM-DD`             | `2026-03-22`         | Хорошая         |
| `time`            | `HH:MM` или `HH:MM:SS`  | `14:30`              | Хорошая         |
| `datetime-local`  | `YYYY-MM-DDTHH:MM`       | `2026-03-22T14:30`   | Хорошая         |
| `month`           | `YYYY-MM`                | `2026-03`            | Средняя         |
| `week`            | `YYYY-Www`               | `2026-W12`           | Средняя         |

```html
<!-- Выбор даты -->
<input type="date" name="birthday" min="1900-01-01" max="2026-12-31">

<!-- Выбор времени с секундами -->
<input type="time" name="alarm" step="1">

<!-- Дата и время без часового пояса -->
<input type="datetime-local"
  name="meeting"
  min="2026-01-01T00:00"
  max="2026-12-31T23:59"
>

<!-- Месяц -->
<input type="month" name="expiry" min="2026-01">

<!-- Неделя -->
<input type="week" name="sprint" min="2026-W01" max="2026-W52">
```

> **Важно:** `type="datetime"` (с часовым поясом) устарел и удалён из спецификации. Используйте `datetime-local` и обрабатывайте часовые пояса на сервере. Firefox долгое время не поддерживал date/time inputs, предоставляя fallback к text. С 2023 года поддержка полная во всех основных браузерах.

### Специальные типы

#### type="color"

Открывает системный палитр цветов. Значение всегда в формате `#rrggbb` (lowercase).

```html
<input type="color" name="theme-color" value="#3498db">
```

> **Ограничение:** Нет поддержки alpha-канала (прозрачности). Значение всегда 6 символов hex без alpha. Для выбора цвета с прозрачностью нужен кастомный пикер.

#### type="file"

Открывает системный диалог выбора файла.

```html
<!-- Один файл -->
<input type="file" name="document" accept=".pdf,.doc,.docx">

<!-- Множество файлов -->
<input type="file" name="photos" multiple accept="image/*">

<!-- Камера на мобильных -->
<input type="file" name="selfie" accept="image/*" capture="user">
<input type="file" name="document-scan" accept="image/*" capture="environment">
```

Атрибут `accept` поддерживает:
- MIME types: `image/*`, `video/*`, `audio/*`, `application/pdf`
- Расширения файлов: `.jpg`, `.png`, `.pdf`
- Комбинации: `image/*,.pdf`

> **Безопасность:** Атрибут `accept` лишь фильтрует диалог выбора — пользователь может выбрать любой файл через "Все файлы". Всегда валидируйте тип файла на сервере.

#### type="hidden"

Невидимое поле, отправляемое с формой. Используется для CSRF-токенов, идентификаторов и метаданных.

```html
<input type="hidden" name="_csrf" value="abc123token">
<input type="hidden" name="user_id" value="42">
<input type="hidden" name="form_version" value="2">
```

> **Безопасность:** Хотя `hidden` поля не видны на странице, они полностью доступны через DevTools. Никогда не храните в них секретные данные, которые пользователь не должен видеть.

#### type="checkbox"

Двоичный переключатель. При отправке формы отправляется только значение отмеченных чекбоксов.

```html
<!-- Простой чекбокс -->
<label>
  <input type="checkbox" name="agree" value="yes" required>
  Я согласен с условиями
</label>

<!-- Группа чекбоксов -->
<fieldset>
  <legend>Навыки</legend>
  <label><input type="checkbox" name="skills" value="html"> HTML</label>
  <label><input type="checkbox" name="skills" value="css"> CSS</label>
  <label><input type="checkbox" name="skills" value="js"> JavaScript</label>
</fieldset>
```

> **Gotcha:** Если чекбокс не отмечен, его значение НЕ отправляется с формой вообще. Для серверной обработки это означает отсутствие ключа. Решение — скрытое поле перед чекбоксом:

```html
<input type="hidden" name="newsletter" value="no">
<input type="checkbox" name="newsletter" value="yes">
<!-- Если отмечен — отправится "yes", если нет — "no" (из hidden) -->
```

Свойство `indeterminate` позволяет установить третье визуальное состояние (не отправляется как значение):

```javascript
checkbox.indeterminate = true; // Визуально "полуотмеченный"
```

#### type="radio"

Взаимоисключающий выбор в группе с одинаковым `name`.

```html
<fieldset>
  <legend>Способ оплаты</legend>
  <label><input type="radio" name="payment" value="card" required> Карта</label>
  <label><input type="radio" name="payment" value="cash"> Наличные</label>
  <label><input type="radio" name="payment" value="crypto"> Криптовалюта</label>
</fieldset>
```

> **Важно:** `required` на радиокнопках работает для всей группы. Достаточно указать `required` на одной кнопке в группе — браузер не даст отправить форму без выбора.

#### type="submit", type="reset", type="button"

```html
<!-- Submit — отправка формы -->
<input type="submit" value="Отправить">

<!-- Reset — сброс всех полей к начальным значениям -->
<input type="reset" value="Сбросить">

<!-- Button — без встроенного поведения -->
<input type="button" value="Нажми" onclick="doSomething()">
```

> **Best Practice:** Предпочитайте `<button>` элемент вместо `<input type="submit/reset/button">` — он более гибок, поддерживает вложенный HTML-контент и проще стилизуется.

#### type="image"

Графическая кнопка отправки. При клике отправляет координаты клика.

```html
<input type="image" src="/images/submit-btn.png" alt="Отправить" width="100" height="40">
<!-- При клике отправятся: x=32&y=15 (координаты клика внутри изображения) -->
```

## 3. Constraint Validation API

### Обзор API

Constraint Validation API — это встроенный в браузер набор свойств и методов для работы с валидацией форм. Он доступен на всех элементах формы, реализующих интерфейс `HTMLInputElement`, `HTMLSelectElement`, `HTMLTextAreaElement` и `HTMLButtonElement`.

### Свойство validity

Свойство `validity` возвращает объект `ValidityState` со следующими булевыми флагами:

| Свойство          | Описание                                                        |
|-------------------|-----------------------------------------------------------------|
| `valid`           | `true`, если элемент проходит все проверки                      |
| `valueMissing`    | `true`, если `required` и значение пустое                       |
| `typeMismatch`    | `true`, если значение не соответствует типу (email, url)        |
| `patternMismatch` | `true`, если не соответствует `pattern`                         |
| `tooLong`         | `true`, если длина превышает `maxlength`                        |
| `tooShort`        | `true`, если длина меньше `minlength`                           |
| `rangeUnderflow`  | `true`, если значение меньше `min`                              |
| `rangeOverflow`   | `true`, если значение больше `max`                              |
| `stepMismatch`    | `true`, если значение не кратно `step`                          |
| `badInput`        | `true`, если ввод не может быть преобразован (например, буквы в number) |
| `customError`     | `true`, если установлена кастомная ошибка через `setCustomValidity()` |

```javascript
const email = document.querySelector('input[type="email"]');

email.addEventListener('input', () => {
  const v = email.validity;

  if (v.valueMissing) {
    console.log('Поле обязательно');
  } else if (v.typeMismatch) {
    console.log('Некорректный формат email');
  } else if (v.patternMismatch) {
    console.log('Email не соответствует паттерну');
  } else if (v.valid) {
    console.log('Email корректен');
  }
});
```

### Свойство validationMessage

Возвращает локализованное сообщение об ошибке, которое браузер показал бы пользователю. Пустая строка, если элемент валиден.

```javascript
const input = document.querySelector('input[required]');
input.value = '';
console.log(input.validationMessage);
// Chrome: "Заполните это поле."
// Firefox: "Заполните это поле."
// Зависит от языка браузера
```

### Методы валидации

#### checkValidity()

Проверяет валидность элемента. Возвращает `true`/`false` и генерирует событие `invalid` при невалидности. Не показывает визуальных подсказок.

```javascript
const input = document.querySelector('#email');

if (!input.checkValidity()) {
  // Элемент невалиден, событие 'invalid' уже сгенерировано
  console.log(input.validationMessage);
}

// Проверка всей формы
const form = document.querySelector('form');
if (form.checkValidity()) {
  // Все элементы формы валидны
}
```

#### reportValidity()

Аналогичен `checkValidity()`, но дополнительно показывает стандартную всплывающую подсказку браузера у первого невалидного элемента.

```javascript
const form = document.querySelector('form');

// Программная проверка с показом ошибки
if (!form.reportValidity()) {
  // Браузер показал подсказку у первого невалидного поля
  return;
}
```

#### setCustomValidity(message)

Устанавливает кастомное сообщение об ошибке. Непустая строка делает элемент невалидным. Пустая строка снимает кастомную ошибку.

```javascript
const password = document.querySelector('#password');
const confirm = document.querySelector('#confirm-password');

confirm.addEventListener('input', () => {
  if (confirm.value !== password.value) {
    confirm.setCustomValidity('Пароли не совпадают');
  } else {
    confirm.setCustomValidity(''); // Снять кастомную ошибку
  }
});
```

> **Критичный gotcha:** После вызова `setCustomValidity()` с непустой строкой элемент будет невалидным НАВСЕГДА, пока вы не вызовете `setCustomValidity('')`. Поэтому обязательно сбрасывайте кастомную ошибку при каждом вводе.

```javascript
// Типичная ошибка — забывают сбрасывать
input.addEventListener('input', () => {
  // НЕПРАВИЛЬНО: ошибка установлена, но никогда не сбрасывается
  if (input.value.length < 3) {
    input.setCustomValidity('Минимум 3 символа');
  }
  // Добавить:
  // else { input.setCustomValidity(''); }
});
```

### CSS-псевдоклассы валидации

```css
/* Элемент проходит валидацию */
input:valid {
  border-color: green;
}

/* Элемент не проходит валидацию */
input:invalid {
  border-color: red;
}

/* Элемент в диапазоне min/max */
input:in-range {
  background: lightgreen;
}

/* Элемент вне диапазона */
input:out-of-range {
  background: lightcoral;
}

/* Обязательное поле */
input:required {
  border-left: 3px solid blue;
}

/* Необязательное поле */
input:optional {
  border-left: 3px solid gray;
}

/* Пользователь взаимодействовал с полем (новый селектор) */
input:user-invalid {
  border-color: red;
}
```

> **Best Practice:** Используйте `:user-invalid` (ранее `:user-interacted` в Chromium) вместо `:invalid` для отображения ошибок. `:invalid` применяется сразу при загрузке страницы (пустое required поле уже invalid), а `:user-invalid` — только после взаимодействия пользователя.

### Событие invalid

```javascript
const input = document.querySelector('input');

input.addEventListener('invalid', (e) => {
  // Предотвращаем стандартную всплывающую подсказку
  e.preventDefault();

  // Показываем свою ошибку
  const errorEl = input.nextElementSibling;
  errorEl.textContent = input.validationMessage;
  errorEl.hidden = false;
});
```

## 4. Атрибуты валидации

### required

Делает поле обязательным для заполнения. Пустое значение блокирует отправку.

```html
<input type="text" name="name" required>
<select name="country" required>
  <option value="">Выберите страну</option>
  <option value="ru">Россия</option>
</select>
<textarea name="comment" required></textarea>
```

> **Gotcha:** Для `<select>` значение первого `<option>` должно быть пустой строкой, чтобы `required` работал корректно. Если `value` первого option не пустой, select считается заполненным.

### pattern

Регулярное выражение для валидации. Автоматически якорится на начало и конец (`^...$`).

```html
<!-- Только латинские буквы и цифры -->
<input type="text" pattern="[A-Za-z0-9]+" title="Только латинские буквы и цифры">

<!-- Российский телефон -->
<input type="tel" pattern="\+7\d{10}" title="Формат: +7XXXXXXXXXX">

<!-- Пароль: минимум 8 символов, буквы и цифры -->
<input type="password" pattern="(?=.*\d)(?=.*[a-zA-Z]).{8,}"
  title="Минимум 8 символов, хотя бы одна буква и одна цифра">
```

> **Важно:** Атрибут `title` показывается в стандартной всплывающей подсказке валидации как дополнительная информация. Всегда указывайте `title` вместе с `pattern` для объяснения ожидаемого формата. Паттерн НЕ применяется к пустому значению — для обязательности используйте `required` дополнительно.

### min, max

Определяют допустимый диапазон для числовых и date/time типов.

```html
<input type="number" min="0" max="100">
<input type="date" min="2026-01-01" max="2026-12-31">
<input type="time" min="09:00" max="18:00">
<input type="range" min="0" max="11" step="0.1">
```

### minlength, maxlength

Ограничивают длину текстового ввода в символах (Unicode code points).

```html
<input type="text" minlength="3" maxlength="50">
<textarea minlength="10" maxlength="500"></textarea>
```

> **Поведение:** `maxlength` физически не позволяет ввести больше символов. `minlength` только показывает ошибку при отправке — пользователь может ввести меньше символов. Валидация `minlength` не срабатывает для пустых полей (нужен `required`).

### step

Определяет допустимый шаг значения. Значение должно быть кратно `step` от базового значения (`min` или 0).

```html
<!-- Целые числа (по умолчанию step="1" для number) -->
<input type="number" step="1">

<!-- Шаг 0.5 -->
<input type="number" min="0" max="10" step="0.5">

<!-- Шаг 15 минут для времени -->
<input type="time" step="900">

<!-- Любое значение (отключает проверку шага) -->
<input type="number" step="any">
```

> **Gotcha:** Для `type="time"` значение `step` указывается в секундах. `step="60"` — шаг 1 минута, `step="3600"` — шаг 1 час, `step="1"` — показывает поле секунд.

## 5. Элементы форм

### select

Выпадающий список для выбора одного или нескольких вариантов.

```html
<!-- Простой выбор -->
<select name="city" required>
  <option value="">Выберите город</option>
  <option value="msk">Москва</option>
  <option value="spb" selected>Санкт-Петербург</option>
  <option value="nsk">Новосибирск</option>
</select>

<!-- Множественный выбор -->
<select name="languages" multiple size="5">
  <option value="js">JavaScript</option>
  <option value="py">Python</option>
  <option value="go">Go</option>
  <option value="rs">Rust</option>
  <option value="ts">TypeScript</option>
</select>

<!-- С группировкой -->
<select name="car">
  <optgroup label="Немецкие">
    <option value="bmw">BMW</option>
    <option value="audi">Audi</option>
  </optgroup>
  <optgroup label="Японские">
    <option value="toyota">Toyota</option>
    <option value="honda">Honda</option>
  </optgroup>
</select>
```

### textarea

Многострочное текстовое поле.

```html
<textarea
  name="bio"
  rows="5"
  cols="40"
  maxlength="1000"
  minlength="10"
  placeholder="Расскажите о себе..."
  wrap="soft"
  spellcheck="true"
  required
></textarea>
```

Атрибут `wrap`:
- `soft` (по умолчанию) — переносы строк при отправке НЕ добавляются
- `hard` — переносы строк добавляются в места визуального переноса (требует `cols`)
- `off` — без автоматического переноса, горизонтальная прокрутка

### button

```html
<!-- Submit (по умолчанию внутри формы!) -->
<button type="submit">Отправить</button>

<!-- Явная кнопка без поведения -->
<button type="button" onclick="openModal()">Открыть модальное окно</button>

<!-- Reset -->
<button type="reset">Сбросить</button>

<!-- С HTML-контентом внутри -->
<button type="submit">
  <svg>...</svg>
  <span>Отправить заявку</span>
</button>

<!-- Переопределение атрибутов формы -->
<button type="submit"
  formaction="/api/draft"
  formmethod="POST"
  formenctype="multipart/form-data"
  formnovalidate
  formtarget="_blank"
>
  Сохранить черновик
</button>
```

> **Критичный gotcha:** `<button>` внутри `<form>` по умолчанию имеет `type="submit"`. Если вы хотите кнопку, которая НЕ отправляет форму, обязательно указывайте `type="button"`. Это одна из самых частых ошибок.

### fieldset и legend

Группировка связанных элементов формы. Важно для accessibility — screen readers объявляют `legend` при входе в группу.

```html
<fieldset>
  <legend>Адрес доставки</legend>
  <label>
    Город: <input type="text" name="city">
  </label>
  <label>
    Улица: <input type="text" name="street">
  </label>
  <label>
    Дом: <input type="text" name="building">
  </label>
</fieldset>

<!-- Отключение всей группы -->
<fieldset disabled>
  <legend>Дополнительные опции (недоступно)</legend>
  <label><input type="checkbox" name="gift"> Подарочная упаковка</label>
  <label><input type="checkbox" name="express"> Экспресс доставка</label>
</fieldset>
```

> **Важно:** `disabled` на `<fieldset>` отключает ВСЕ вложенные элементы управления. Это удобнее, чем отключать каждый элемент по отдельности. Но элементы внутри `<legend>` НЕ отключаются.

### label

Связывает текстовую метку с элементом управления. При клике на label фокус переходит на связанный элемент.

```html
<!-- Явная связь через for/id -->
<label for="email">Email:</label>
<input id="email" type="email" name="email">

<!-- Неявная связь через вложенность -->
<label>
  Email:
  <input type="email" name="email">
</label>
```

> **Accessibility:** Каждый элемент формы ДОЛЖЕН иметь связанный `<label>`. Без него screen readers не могут объявить назначение поля. Placeholder НЕ является заменой label.

### output

Отображает результат вычисления или действия пользователя.

```html
<form oninput="result.value = parseInt(a.value) + parseInt(b.value)">
  <input type="range" id="a" name="a" value="50"> +
  <input type="number" id="b" name="b" value="25"> =
  <output name="result" for="a b">75</output>
</form>
```

### datalist

Предоставляет список предложений для input. В отличие от `<select>`, пользователь может ввести произвольное значение.

```html
<input type="text" name="browser" list="browsers">
<datalist id="browsers">
  <option value="Chrome">
  <option value="Firefox">
  <option value="Safari">
  <option value="Edge">
</datalist>

<!-- Также работает с другими типами -->
<input type="range" min="0" max="100" step="25" list="quarters">
<datalist id="quarters">
  <option value="0" label="0%">
  <option value="25" label="25%">
  <option value="50" label="50%">
  <option value="75" label="75%">
  <option value="100" label="100%">
</datalist>
```

## 6. FormData API

### Создание FormData

`FormData` — интерфейс для программной работы с данными формы. Ключевое преимущество — автоматическая обработка файлов и правильное кодирование `multipart/form-data`.

```javascript
// Из существующей формы
const form = document.querySelector('form');
const formData = new FormData(form);

// Пустой объект, заполняемый вручную
const formData = new FormData();
formData.append('username', 'developer');
formData.append('email', 'dev@example.com');

// Из формы с указанием submitter (для определения кнопки отправки)
const button = document.querySelector('button[type="submit"]');
const formData = new FormData(form, button);
// Включает name/value кнопки в данные
```

### Чтение данных

```javascript
const formData = new FormData(form);

// Получить значение по ключу
formData.get('username');      // строка или File
formData.getAll('skills');     // массив всех значений для ключа

// Проверка наличия ключа
formData.has('email');         // true/false

// Перебор всех записей
for (const [key, value] of formData) {
  console.log(`${key}: ${value}`);
}

// Альтернативные итераторы
formData.keys();    // Iterator ключей
formData.values();  // Iterator значений
formData.entries(); // Iterator [key, value]
```

### Модификация данных

```javascript
const formData = new FormData();

// Добавление (можно множество значений для одного ключа)
formData.append('tag', 'html');
formData.append('tag', 'css');
formData.append('tag', 'js');
formData.getAll('tag'); // ['html', 'css', 'js']

// Установка (заменяет все значения для ключа)
formData.set('tag', 'typescript');
formData.getAll('tag'); // ['typescript']

// Удаление
formData.delete('tag');
formData.has('tag'); // false
```

### Работа с файлами

```javascript
// Добавление файла из input
const fileInput = document.querySelector('input[type="file"]');
const file = fileInput.files[0];
formData.append('avatar', file);

// Добавление файла с кастомным именем
formData.append('avatar', file, 'my-photo.jpg');

// Добавление Blob как файла
const blob = new Blob(['Hello, World!'], { type: 'text/plain' });
formData.append('document', blob, 'hello.txt');

// Добавление canvas как изображения
const canvas = document.querySelector('canvas');
canvas.toBlob((blob) => {
  formData.append('screenshot', blob, 'screenshot.png');
});
```

### Отправка с fetch

```javascript
// FormData автоматически устанавливает Content-Type: multipart/form-data
const response = await fetch('/api/submit', {
  method: 'POST',
  body: formData,
  // НЕ устанавливайте Content-Type вручную!
  // Браузер добавит boundary автоматически
});
```

> **Критичный gotcha:** При использовании `FormData` с `fetch` НИКОГДА не устанавливайте заголовок `Content-Type` вручную. Браузер автоматически устанавливает `multipart/form-data` с корректным `boundary`. Если вы укажете Content-Type вручную, boundary будет отсутствовать и сервер не сможет разобрать данные.

```javascript
// НЕПРАВИЛЬНО
fetch('/api', {
  method: 'POST',
  headers: { 'Content-Type': 'multipart/form-data' }, // НЕТ!
  body: formData,
});

// ПРАВИЛЬНО
fetch('/api', {
  method: 'POST',
  body: formData, // Content-Type установится автоматически
});
```

### Конвертация FormData

```javascript
// В URLSearchParams (только для текстовых данных, без файлов)
const params = new URLSearchParams(formData);
const queryString = params.toString(); // "username=dev&email=dev%40example.com"

// В обычный объект (осторожно с множественными значениями)
const obj = Object.fromEntries(formData);
// Множественные значения потеряются! Только последнее сохранится

// Безопасная конвертация с сохранением множественных значений
const safeObj = {};
for (const [key, value] of formData) {
  if (safeObj[key]) {
    if (!Array.isArray(safeObj[key])) {
      safeObj[key] = [safeObj[key]];
    }
    safeObj[key].push(value);
  } else {
    safeObj[key] = value;
  }
}

// Отправка как JSON (без файлов)
fetch('/api', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify(Object.fromEntries(formData)),
});
```

## 7. Accessibility форм

### Связывание label с элементами

Каждый интерактивный элемент формы должен иметь доступное имя (accessible name). Наиболее надёжный способ — элемент `<label>`.

```html
<!-- Способ 1: явная связь (предпочтительный) -->
<label for="username">Имя пользователя</label>
<input id="username" type="text" name="username">

<!-- Способ 2: неявная связь -->
<label>
  Имя пользователя
  <input type="text" name="username">
</label>

<!-- Способ 3: aria-label (когда визуальная метка отсутствует) -->
<input type="search" aria-label="Поиск по сайту" name="q">

<!-- Способ 4: aria-labelledby (ссылка на другой элемент) -->
<h2 id="contact-heading">Контактная информация</h2>
<input type="tel" aria-labelledby="contact-heading" name="phone">
```

### aria-describedby

Связывает элемент с дополнительным описанием. Screen reader прочитает описание после имени поля.

```html
<label for="password">Пароль</label>
<input type="password" id="password" name="password"
  aria-describedby="password-requirements password-strength"
  required minlength="8"
>
<p id="password-requirements">Минимум 8 символов, включая цифры и буквы</p>
<p id="password-strength" aria-live="polite"></p>
```

### aria-invalid

Сообщает assistive technology, что элемент содержит ошибку.

```html
<label for="email">Email</label>
<input type="email" id="email" name="email"
  aria-invalid="true"
  aria-describedby="email-error"
>
<p id="email-error" role="alert">Введите корректный email адрес</p>
```

```javascript
// Динамическое управление
function validateField(input, errorEl) {
  if (!input.checkValidity()) {
    input.setAttribute('aria-invalid', 'true');
    errorEl.textContent = input.validationMessage;
    errorEl.hidden = false;
  } else {
    input.removeAttribute('aria-invalid');
    errorEl.textContent = '';
    errorEl.hidden = true;
  }
}
```

### Группировка fieldset/legend

```html
<form>
  <fieldset>
    <legend>Личная информация</legend>
    <label for="first-name">Имя</label>
    <input id="first-name" type="text" name="firstName" required>

    <label for="last-name">Фамилия</label>
    <input id="last-name" type="text" name="lastName" required>
  </fieldset>

  <fieldset>
    <legend>Тип аккаунта</legend>
    <label><input type="radio" name="type" value="personal"> Личный</label>
    <label><input type="radio" name="type" value="business"> Бизнес</label>
  </fieldset>

  <fieldset>
    <legend>Уведомления</legend>
    <label><input type="checkbox" name="notify_email"> По email</label>
    <label><input type="checkbox" name="notify_sms"> По SMS</label>
    <label><input type="checkbox" name="notify_push"> Push-уведомления</label>
  </fieldset>
</form>
```

> **Важно:** Группы radio-кнопок и связанных checkbox ОБЯЗАТЕЛЬНО должны быть обёрнуты в `<fieldset>` с `<legend>`. Без этого screen reader не понимает контекст группы.

### Живые уведомления об ошибках

```html
<!-- Контейнер для ошибок с aria-live -->
<div aria-live="polite" aria-atomic="true" id="form-errors">
  <!-- Ошибки добавляются динамически -->
</div>

<!-- Или role="alert" для немедленного объявления -->
<div role="alert" id="submit-error" hidden>
  Пожалуйста, исправьте ошибки в форме
</div>
```

### Чеклист доступности форм

1. Каждое поле имеет `<label>` или `aria-label`
2. Обязательные поля помечены `required` и визуально (не только цветом)
3. Ошибки связаны с полями через `aria-describedby`
4. Группы радиокнопок/чекбоксов обёрнуты в `fieldset/legend`
5. Фокус перемещается на первое поле с ошибкой при невалидной отправке
6. Цветовой контраст ошибок соответствует WCAG 2.1 AA (минимум 4.5:1)
7. Ошибки объявляются screen readers через `aria-live` или `role="alert"`
8. Подсказки к полям видны не только по hover (доступны с клавиатуры)

## 8. Кастомные элементы форм

### Form-Associated Custom Elements

С появлением API `ElementInternals` стало возможно создавать кастомные элементы, которые полноценно участвуют в формах — отправляют данные, валидируются, сбрасываются.

```javascript
class CustomInput extends HTMLElement {
  // Обязательный статический флаг
  static formAssociated = true;

  #internals;
  #input;

  constructor() {
    super();
    this.#internals = this.attachInternals();

    const shadow = this.attachShadow({ mode: 'open' });
    shadow.innerHTML = `
      <style>
        :host { display: inline-block; }
        :host(:state(invalid)) input { border-color: red; }
        input { padding: 8px; border: 1px solid #ccc; border-radius: 4px; }
      </style>
      <input type="text" part="input">
    `;

    this.#input = shadow.querySelector('input');
    this.#input.addEventListener('input', () => this.#handleInput());
  }

  #handleInput() {
    const value = this.#input.value;
    // Устанавливаем значение, которое будет отправлено с формой
    this.#internals.setFormValue(value);

    // Валидация
    if (this.hasAttribute('required') && !value) {
      this.#internals.setValidity(
        { valueMissing: true },
        'Это поле обязательно',
        this.#input
      );
    } else {
      this.#internals.setValidity({});
    }
  }

  // Callback при сбросе формы
  formResetCallback() {
    this.#input.value = '';
    this.#internals.setFormValue('');
  }

  // Callback при восстановлении формы (навигация назад/вперёд)
  formStateRestoreCallback(state, mode) {
    this.#input.value = state;
  }

  // Callback при изменении disabled состояния формы/fieldset
  formDisabledCallback(disabled) {
    this.#input.disabled = disabled;
  }

  // Callback при ассоциации с формой
  formAssociatedCallback(form) {
    console.log('Ассоциирован с формой:', form);
  }

  // Стандартные свойства форм-элемента
  get form() { return this.#internals.form; }
  get name() { return this.getAttribute('name'); }
  get type() { return this.localName; }
  get validity() { return this.#internals.validity; }
  get validationMessage() { return this.#internals.validationMessage; }
  get willValidate() { return this.#internals.willValidate; }

  checkValidity() { return this.#internals.checkValidity(); }
  reportValidity() { return this.#internals.reportValidity(); }
}

customElements.define('custom-input', CustomInput);
```

### CustomStateSet

Позволяет определять кастомные CSS-состояния для компонента:

```javascript
class ToggleSwitch extends HTMLElement {
  static formAssociated = true;
  #internals;

  constructor() {
    super();
    this.#internals = this.attachInternals();
  }

  toggle() {
    if (this.#internals.states.has('checked')) {
      this.#internals.states.delete('checked');
      this.#internals.setFormValue('off');
    } else {
      this.#internals.states.add('checked');
      this.#internals.setFormValue('on');
    }
  }
}
```

```css
  background: green;
}

  background: gray;
}
```

### Файловая загрузка с прогрессом

```javascript
function uploadWithProgress(form) {
  return new Promise((resolve, reject) => {
    const xhr = new XMLHttpRequest();
    const formData = new FormData(form);

    xhr.upload.addEventListener('progress', (e) => {
      if (e.lengthComputable) {
        const percent = Math.round((e.loaded / e.total) * 100);
        updateProgressBar(percent);
      }
    });

    xhr.addEventListener('load', () => {
      if (xhr.status >= 200 && xhr.status < 300) {
        resolve(JSON.parse(xhr.responseText));
      } else {
        reject(new Error(`Upload failed: ${xhr.status}`));
      }
    });

    xhr.addEventListener('error', () => reject(new Error('Network error')));
    xhr.addEventListener('abort', () => reject(new Error('Upload cancelled')));

    xhr.open('POST', form.action);
    xhr.send(formData);
  });
}
```

> **Примечание:** `fetch` API до сих пор не поддерживает upload progress. Для отслеживания прогресса загрузки файлов используйте `XMLHttpRequest` или потоковый API с `ReadableStream`.

### Паттерн с валидацией перед отправкой

```javascript
class FormController {
  constructor(form) {
    this.form = form;
    this.errors = new Map();

    this.form.setAttribute('novalidate', '');
    this.form.addEventListener('submit', (e) => this.handleSubmit(e));

    // Валидация при потере фокуса
    this.form.querySelectorAll('input, select, textarea').forEach(field => {
      field.addEventListener('blur', () => this.validateField(field));
      field.addEventListener('input', () => this.clearError(field));
    });
  }

  validateField(field) {
    // Сначала проверяем встроенную валидацию
    if (!field.checkValidity()) {
      this.setError(field, field.validationMessage);
      return false;
    }

    // Кастомные правила
    const customValidator = this.customValidators.get(field.name);
    if (customValidator) {
      const error = customValidator(field.value, this.form);
      if (error) {
        this.setError(field, error);
        return false;
      }
    }

    this.clearError(field);
    return true;
  }

  setError(field, message) {
    this.errors.set(field.name, message);
    field.setAttribute('aria-invalid', 'true');

    const errorEl = document.getElementById(`${field.id}-error`);
    if (errorEl) {
      errorEl.textContent = message;
      errorEl.hidden = false;
    }
  }

  clearError(field) {
    this.errors.delete(field.name);
    field.removeAttribute('aria-invalid');

    const errorEl = document.getElementById(`${field.id}-error`);
    if (errorEl) {
      errorEl.textContent = '';
      errorEl.hidden = true;
    }
  }

  async handleSubmit(event) {
    event.preventDefault();

    // Валидируем все поля
    let firstInvalid = null;
    this.form.querySelectorAll('input, select, textarea').forEach(field => {
      if (!this.validateField(field) && !firstInvalid) {
        firstInvalid = field;
      }
    });

    if (firstInvalid) {
      firstInvalid.focus();
      return;
    }

    // Отправка
    const formData = new FormData(this.form);
    try {
      const response = await fetch(this.form.action, {
        method: this.form.method || 'POST',
        body: formData,
      });

      if (!response.ok) {
        const errors = await response.json();
        this.handleServerErrors(errors);
        return;
      }

      this.onSuccess(await response.json());
    } catch (error) {
      this.onError(error);
    }
  }
}
```

### Атрибут autocomplete

Атрибут `autocomplete` управляет автозаполнением браузера и подсказками менеджеров паролей. Использует стандартизированные токены из спецификации WHATWG.

### Отключение автозаполнения

```html
<!-- Полное отключение (браузеры могут игнорировать) -->
<input type="text" autocomplete="off">

<!-- Более надёжное отключение (hack) -->
<input type="text" autocomplete="nope">
<input type="text" readonly onfocus="this.removeAttribute('readonly');">
```

> **Gotcha:** Браузеры (особенно Chrome) часто игнорируют `autocomplete="off"` для полей логина и пароля, считая, что это вредит пользовательскому опыту. Спецификация разрешает браузерам переопределять `autocomplete="off"`. Для чувствительных данных используйте `autocomplete="off"` в сочетании с нестандартным значением `name` и JavaScript-управлением.

### Конвенции именования полей

Для корректной работы автозаполнения важно использовать правильные имена полей:

```html
<!-- Браузеры лучше распознают эти имена -->
<input name="email" type="email">           <!-- email -->
<input name="phone" type="tel">             <!-- телефон -->
<input name="firstName" type="text">        <!-- имя -->
<input name="lastName" type="text">         <!-- фамилия -->
<input name="address" type="text">          <!-- адрес -->
<input name="city" type="text">             <!-- город -->
<input name="zip" type="text">              <!-- индекс -->
<input name="username" type="text">         <!-- логин -->
<input name="password" type="password">     <!-- пароль -->
```

> **Best Practice:** Всегда используйте и атрибут `autocomplete` с правильным токеном, и семантически понятный `name`. Это обеспечивает наилучшую совместимость с менеджерами паролей (1Password, Bitwarden, LastPass) и встроенным автозаполнением браузера.
