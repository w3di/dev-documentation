# Closure замыкается на переменную, а не на значение

## Не снимок значения

- Частое заблуждение: closure якобы **захватывает значение** в какой-то момент (snapshot). Это неверно.
- **Нельзя замкнуться на значение** (closing over a value) — такого понятия не существует.
- Замыкаются на **переменную**: сохраняется **живая связь (live link)** с ней. В момент доступа видно текущее значение переменной, а не то, что было раньше.

```js
var teacher = "Kyle";
var myTeacher = function(){
    console.log(teacher);
};
teacher = "Suzy";
myTeacher();   // "Suzy", не "Kyle"
```

- На момент создания `myTeacher` переменная `teacher` равна `"Kyle"`, затем меняется на `"Suzy"`.
- При вызове функция печатает `"Suzy"` — замкнулись на переменную `teacher`, а не на значение `"Kyle"`.
- **Думать о closure как о сохранении доступа к переменным, а не о захвате значений.**

## Классическая ловушка: closure в цикле

```js
for (var i = 1; i <= 3; i++) {
    setTimeout(function(){
        console.log(`i: ${i}`);
    }, i * 1000);
}
// печатает 4, 4, 4
```

- Ожидается `1, 2, 3`, но печатается `4, 4, 4`.
- **Причина:** существует только **одна** переменная `i` на все три функции. Все три замкнулись на одну и ту же `i`.
- К моменту срабатывания таймеров цикл завершился, и `i` равна `4`.
- **Простая арифметика:** чтобы получить три разных значения, нужно три разных переменных.

## Решение 1: новый block scope в каждой итерации

```js
for (var i = 1; i <= 3; i++) {
    let j = i;
    setTimeout(function(){
        console.log(`j: ${j}`);
    }, j * 1000);
}
// печатает 1, 2, 3
```

- Чтобы создать несколько переменных с одним именем, нужны новые scopes.
- Раньше использовали IIFE; с ES6 и block scoping достаточно `let` в теле итерации.
- `let j` создаёт **новую `j` в каждой итерации** → три отдельных `j` → значения `1, 2, 3`.

## Решение 2: let прямо в for

```js
for (let i = 1; i <= 3; i++) {
    setTimeout(function(){
        console.log(`i: ${i}`);
    }, i * 1000);
}
// печатает 1, 2, 3
```

- Проблема `for (var i ...)` мучила разработчиков около 20 лет.
- В **ES6** решили: если в заголовке `for` использовать `let`, для **каждой итерации** автоматически создаётся новая `i`.
- Closure «магически» работает, потому что замыкается на новую переменную каждой итерации. JavaScript сам присваивает новой `i` значение, которое было у предыдущей в конце итерации.

**Нюансы:**
- Это работает для всех синтаксических форм цикла: `for`, `for..of`, `for..in` — у каждой есть `for let`-вариант (новая переменная в каждой итерации). `forEach` — не синтаксис, а итератор (там и так своя функция).
- В заголовке `for` нельзя `const`: `i++` модифицирует переменную → ошибка. Нужен `let`.

## Главное

- Closure сохраняет **связь с переменной**, а не **снимок значения**: при вызове видно текущее значение.
- Чтобы замкнуться на несколько разных значений, нужно несколько разных **переменных** (новые scopes).
- В цикле `var` создаёт одну переменную на все итерации (отсюда `4,4,4`); `let` создаёт новую переменную на каждую итерацию (отсюда `1,2,3`).
