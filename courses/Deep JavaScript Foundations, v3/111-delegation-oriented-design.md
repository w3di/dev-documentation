# Delegation-Oriented Design

## Delegation как design pattern меняет подход к задачам

- **Delegation** — это не только другой стиль кода, но и другой способ проектирования и решения задач.
- Пример-сценарий: страница логина с двумя контроллерами.
  - **AuthController** — аутентификация, общение с сервером.
  - **LoginFormController** — UI: текстовые поля, кнопки, сообщения об ошибках.
- Нужно, чтобы оба набора поведения как-то сосуществовали и взаимодействовали.

## Старые подходы к композиции

1. **Composition through inheritance** (композиция через наследование) — видение 1980-х–90-х.
   - Один контроллер — parent class, другой — child class.
   - Инстанцируем → получаем `pageInstance` со всеми методами обоих.
2. К середине–концу 90-х глубокие (15 уровней) inheritance-цепочки признали anti-pattern → лозунг **«composition over inheritance»**.
3. **Composition через свойство**: инстанцировать оба класса, один экземпляр сделать свойством другого.
   - Доступ ко всем методам в одном месте, но «уродливо» при росте числа свойств.
4. **Mixin composition**: инстанцировать оба класса и **скопировать** все методы из одного в другой.
- Все варианты решают одну задачу: логически разделить две вещи, но заставить их сосуществовать (быть скомпонованными).

## Ответ delegation: peer-to-peer вместо parent-child

- Главный сдвиг: перестать думать «parent/child», начать думать **peer-to-peer** (равноправные).
- `LoginFormController` просто **linked to** `AuthController` через prototype chain.
- Это два отдельных конкретных объекта (не классы), с ними можно работать и по отдельности.

```js
var AuthController = {
  authenticate() { /* this.username ... */ },
  handleResponse() { /* this.displayError(...) */ }
};

var LoginFormController = Object.create(AuthController);
LoginFormController.onSubmit = function() {
  // ...
  this.authenticate();          // делегируется в AuthController
};
LoginFormController.displayError = function() { /* ... */ };
```

## Виртуальная композиция через общий this

- В `onSubmit` вызывается `this.authenticate()`, но у `LoginFormController` метода нет → он **делегируется** в `AuthController`.
- При вызове `this` всё равно указывает на `LoginFormController`.
- Так через «unicorn magic» ключевого слова `this` два объекта **виртуально композируются** на время вызова — они в общем контексте через `this` и могут обращаться к свойствам/методам друг друга:
  - `authenticate` читает `this.username` — это свойство `LoginFormController`.
  - `handleResponse` при ошибке вызывает `this.displayError()` — метод `LoginFormController`.
- Суть: два отдельных конкретных объекта делают свою работу, а когда нужна кооперация — они не вызывают `instanceA.b()`, а связаны через prototype chain и просто делят общий call context.

## Независимая тестируемость

- Раздельные объекты, связанные только через prototype chain, гораздо легче тестировать независимо.
- Чтобы протестировать `LoginFormController`, замокав `AuthController`: достаточно прото-линковать `LoginFormController` на mock-объект — код менять не нужно (меняется только линковка, например через `__proto__`).
- Чтобы протестировать `AuthController`: создать `MockLoginFormController`, делегирующий в `AuthController`.
- Тесты полностью отделены от кода: не нужен test dependency injection — меняется только место prototype-линковки.
- При 3–5 объектах в цепочке можно мокать разные части, изолируя и тестируя нужное.

## Итоговый аргумент

- DNA JavaScript — это **prototype delegation**; именно её язык делает хорошо.
- Даже с обильным сахаром над классами они не соответствуют природе JavaScript.
- Призыв: больше использовать delegation, а не наслаивать всё более сложный class-синтаксис.

## Главное

- Delegation решает задачу композиции иначе: **peer-to-peer** связь объектов вместо parent-child иерархий и copy-mixins.
- Объекты связываются через prototype chain и виртуально композируются на время вызова, делясь общим `this`-контекстом.
- Делегируемый метод (`this.authenticate()`) находится вверх по цепочке, но `this` остаётся исходным объектом — оба объекта видят свойства/методы друг друга.
- Раздельные, лишь прото-связанные объекты независимо тестируемы: мок ставится сменой линковки, без DI.
