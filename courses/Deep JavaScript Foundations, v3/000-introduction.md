# Введение: зачем глубоко изучать JavaScript

## Почему важно знать сам JavaScript

- Сегодня многие не пишут «чистый» JavaScript: используют TypeScript, другие языки (Go, Clojure), а в продакшен отправляют код после множества трансформаций Babel.
- Несмотря на это, понимать сам язык по-прежнему критично: фреймворки (React, Vue, Angular, jQuery) построены на тех же фундаментальных принципах.

## Пример: оператор `++` ломает наивную ментальную модель

- В **postfix**-позиции (`x++`) оператор возвращает значение, а затем инкрементирует: `x++` вернёт 40, после чего `x` станет 41.
- В **prefix**-позиции (`++x`) сначала идёт инкремент, потом возврат: оба выражения дадут 42.
- Распространённая (но неточная) ментальная модель: `x++` эквивалентно `x = x + 1`.

```
let x = 40;
x++;   // вернёт 40, x = 41
++x;   // вернёт 42, x = 42
```

- Вопрос: что произойдёт, если применить `++` к строке, представляющей число (например, `"5"`)?
- Наивное ожидание: вернётся строка `"5"`, затем она приведётся к числу и обновится до 6.
- Реальность: сначала значение приводится к числу (**coercion** — приведение типов), и `x++` возвращает уже **число** `5`, а не строку `"5"`.
- То есть приведение к числу происходит до инкремента — это «середина», а не чистый «after».

## Главная идея курса

- Разработчики строят ментальные модели кода, и когда возникают баги, винят язык: «JavaScript плохо спроектирован».
- Удивление от поведения языка не означает, что язык виноват. Ответственность разработчика — понять, как работает инструмент.
- Большинство разработчиков других сообществ (C++, Java) читали спецификацию своего языка; разработчики JavaScript — почти никогда.
- **Источник истины** — это спецификация (specification), а не движок (engine) и не MDN.
- Алгоритм действий при непонятном поведении:
  1. Спросить: что согласно спецификации должно произойти?
  2. Сравнить: совпадает ли наблюдаемое поведение со спецификацией?
  3. Если не совпадает — это баг в реализации; если совпадает — баг в собственном мышлении (неверная ментальная модель).

## Главное

- Понимание самого JavaScript остаётся фундаментом, даже когда пишут на TypeScript или через фреймворки.
- Наивные ментальные модели (вроде `x++` = `x = x+1`) приводят к багам; реальное поведение нужно проверять.
- Единственный авторитетный источник поведения языка — спецификация, а не движок или MDN.
- Большинство багов возникает из-за расхождения между мысленной моделью разработчика и фактическим поведением кода.
