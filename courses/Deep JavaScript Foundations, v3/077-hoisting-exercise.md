# Упражнение: рефакторинг с помощью hoisting

## Задача

Дан существующий код, использующий разные **function declarations** и **inline function expressions**. Нужно отрефакторить его, опираясь на знания о hoisting. **Поведение не меняется — меняется только стиль кода.**

## Что нужно сделать

1. Найти **inline function expressions**, которые не используют окружающие лексические переменные (не closed over). Для них нет механической причины быть inline — только стилевое предпочтение. Такие функции можно вынести наружу как function declarations.
2. Выносить функции в более внешний scope там, где они не обязаны быть вложенными.
   - Чем **более плоская и простая** структура scope, тем легче читать и понимать код.
   - Чем глубже вложенность, тем труднее отслеживать границы scope.
3. Использовать **function hoisting**: разместить исполняемый код сверху, а все функции — снизу.

В текущей версии кода весь исполняемый код находится внизу. Благодаря function hoisting его можно перенести наверх, а определения функций — вниз.

## Главное

- Цель упражнения — переписать код, используя hoisting, **без изменения поведения**.
- Выносить функции в более внешний scope, если они не используют локальные переменные → более плоская структура.
- Раскладка «исполняемый код сверху, функции снизу» использует function hoisting и улучшает читаемость.
