# Иерархия типов функций

## Предпочтения по типам функций

- Существует субъективная иерархия предпочтительности форм объявления функций.
- Порядок предпочтения (от лучшего к худшему):
  1. **function declaration** (объявление функции).
  2. **named function expression** (именованное функциональное выражение).
  3. **anonymous function expression** (анонимное функциональное выражение), включая arrow functions.
- Уверенность в превосходстве разная:
  - Преимущество declaration над named function expression — мягкое, не жёсткое правило.
  - Преимущество named function expression над anonymous — значительное и принципиальное.

## Почему имя важно

- Главная цель — чтобы код максимально эффективно сообщал о своём назначении, понятном «с первого взгляда».
- Имя функции напрямую сообщает её цель: `double it` говорит больше, чем чтение тела `x * 2`.
- Читатель не должен мысленно исполнять код и разбирать частные случаи, чтобы понять, что функция делает.
- Даже для коротких функций (например, удвоение переменной) предпочтительно дать имя, а не экономить символы.

## Когда допустима анонимная arrow function

- Anonymous function expression в форме arrow function используется только в одном случае — ради **lexical `this`** (лексической привязки `this`).

## Главное

- Иерархия: function declaration → named function expression → anonymous function expression.
- Граница между двумя последними формами наиболее принципиальна: имя несёт смысл и улучшает читаемость.
- Цель именования — самодокументируемый код, понятный с первого взгляда.
- Anonymous arrow function оправдана только ради лексического `this`.
