# Block scoping

## Что такое block scoping

- **Block scoping** — scoping с помощью блоков (фигурных скобок `{}`) вместо функций.
- Принцип тот же, что у function scope: спрятать переменную, чтобы снизить риск naming collision, защитить деталь и будущий рефакторинг.
- Механизм легче IIFE: блок не переопределяет поведение `return`/`break` и не является expression.

```js
{
  let anotherTeacher = "Suzy";
  // ...
}
```

## let и const делают блок scope

- `var` внутри блока исторически привязывается к внешнему функциональному или глобальному scope, а не к блоку.
- Чтобы не ломать старый код, добавили новые формы объявления — `let` и `const`.
- **Важно:** блок не является scope сам по себе; он становится scope только при наличии `let` или `const` внутри.
- Типичное заблуждение — считать все фигурные скобки scope; это не так.

## Как применять block scoping

- `let` следует использовать там, где блочное scope уже естественно и очевидно по дизайну, а не искать поводы усложнить код ради нового ключевого слова.
- Пример: временная переменная `tmp` внутри `if` для обмена значений. Раньше `var tmp` внутри `if` уже стилистически сигнализировал «эта переменная только для блока» (хотя `var` всё равно цеплялся к функции).
- Теперь `let` позволяет реально обеспечить то, что раньше лишь обозначалось стилем.
- Минус неявного «hijacking» scope: теперь `if`-блок приходится просматривать на наличие `let`, чтобы понять, является ли он scope.

## «let — это новый var» — миф

- Лозунг «let is the new var» (и «const is the new let») и совет «глобально заменить все `var` на `let`» — крайне плохая идея.
- Это создаёт баги и неправильно использует возможность.
- `let` — не сплошная замена `var`, а дополнительный инструмент; у `var` остаётся своё назначение.

## Главное

- Block scoping прячет переменные через `{}` с `let`/`const`; блок — это scope только при наличии `let`/`const`.
- `let` уместен там, где блочность переменной уже естественна, а не везде ради моды.
- «let — новый var» — миф: `let` дополняет `var`, а не вытесняет его.
