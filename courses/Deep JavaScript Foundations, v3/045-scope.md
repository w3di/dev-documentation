# Scope: введение в lexical scope

## Что такое scope

- **Scope** (область видимости) — это то, где движок ищет идентификаторы (переменные).
- Первое рабочее определение: scope — это «место, где мы ищем вещи».
- Ищем мы **identifiers** (идентификаторы), то есть переменные.

## Две роли переменной

- Любая переменная в программе находится в одной из двух ролей:
  1. **target** — переменная получает присваивание (ей назначают значение).
  2. **source** — из переменной извлекают (retrieve) значение.
- Других ролей у переменных не существует.
- При обработке кода движок для каждой переменной отвечает на два вопроса: в какой она позиции (target/source) и какому scope принадлежит.

## Метафора «шарики и вёдра»

- Обработка scope — это игра «сортировки цветных шариков по цветным вёдрам».
- **marble** (шарик) = идентификатор/переменная.
- **bucket** (ведро) = scope (область видимости).
- Движок находит переменную, определяет её «цвет» и кладёт в ведро соответствующего цвета.

## JavaScript — компилируемый язык

- Распространённое заблуждение: JS выполняется построчно сверху вниз (как интерпретируемый язык).
- На самом деле перед выполнением есть отдельный этап обработки (parsing/compilation).
- **Доказательство:** при синтаксической ошибке на строке 10 ошибка выдаётся сразу, до выполнения строк 1–9. Значит, код сначала обрабатывается целиком.
- Сравнение: в Bash-скрипте при ошибке на строке 4 строки 1–3 уже выполнятся — там нет предобработки. В JS этого не происходит.
- Правильный критерий «компилируемости» — обрабатывается ли код перед выполнением, а не модель распространения бинарника.

## Этапы компиляции (compiler theory)

- В теории компиляторов четыре стадии (иногда первые две объединяют):
  1. **lexing / tokenization** — разбор на токены.
  2. **parsing** — превращение потока токенов в **AST** (abstract syntax tree, абстрактное синтаксическое дерево).
  3. **code generation** — генерация исполняемой формы из AST.
- JS-парсер обрабатывает исходник и выдаёт промежуточное представление (похожее на bytecode), которое исполняет встроенная виртуальная машина движка.

## Когда происходит сортировка шариков

- Сортировка шариков по вёдрам происходит на этапе компиляции, НЕ во время выполнения.
- Если считать, что это происходит в runtime, возникает неверная ментальная модель и реальные баги.
- При компиляции создаётся план **lexical environment** (лексического окружения): где находятся все scope и какие идентификаторы в них лежат.
- JS — **two-pass system** (двухпроходная): сначала обработка и настройка scope, затем выполнение.

## Откуда берутся вёдра (scope)

- Если идентификаторы — это шарики, то вёдра — это единицы scope.
- В JS единицами scope являются:
  - **functions** (функции).
  - **blocks** (блоки) — появились в ES6.
- Вёдра создаются при встрече scope во время обработки кода; шарики создаются при встрече ссылки на переменную.

## Главное

- Scope — это механизм поиска идентификаторов; каждая переменная находится в позиции target (получает значение) или source (отдаёт значение).
- JavaScript обрабатывает код в два прохода: компиляция (определение всех scope и идентификаторов) → выполнение.
- Принадлежность переменной к scope (цвет шарика) определяется на этапе компиляции и неизменна — это позволяет движку эффективно оптимизировать код.
- Единицы scope в JS — функции и (с ES6) блоки.
