# Hoisting: пример работы var и function

## Пример с подменой значения

Рассмотрим код, где переменная `teacher` используется раньше своего объявления, а функция `otherTeacher` вызывается до своего определения.

```js
var teacher = "Kyle";
otherTeacher();
function otherTeacher() {
    console.log(teacher);   // line 5
}
```

- Функция `otherTeacher` **hoisted** (поднята) — доступна для вызова до строки её объявления.
- Объявление `var teacher` тоже поднимается в начало scope (условно на «строку 4.5»).
- При этом **поднимается только объявление, не присваивание**. Присваивание `"Kyle"` происходит на своей строке.
- Поэтому на строке 5 печатается `undefined`, а не `"Kyle"`.

**Важно:** это классическая ловушка. Понять её помогает модель **two pass system** (двухпроходная обработка): сначала компиляция создаёт «синий marble» `teacher` в scope (инициализированный в `undefined`), и только потом выполняется код.

## var hoisting vs function hoisting

Не всё hoisting одинаково полезно — стоит разделять два случая.

### Присваивание раньше объявления (var)

- Присваивание переменной раньше места её `var`-объявления почти все программисты считают плохим стилем.
- Автор согласен с большинством: так делать не стоит (за крайне редкими исключениями).

### Вызов функции раньше объявления (function)

- Вызов функции до строки её `function`-объявления — другой случай.
- Многие относятся к **function hoisting** спокойно или положительно.
- Автор считает его не просто допустимым, а **полезным для читаемости**: позволяет разместить исполняемый код сверху, а определения функций — снизу.

## Главное

- Hoisting поднимает **объявление**, но не присваивание: `var teacher` существует с начала scope как `undefined`.
- Мыслить нужно как о **two pass system**: сначала компиляция (создание marbles), затем выполнение.
- **var hoisting** (присваивание раньше объявления) — плохой стиль; **function hoisting** — полезный приём для читаемости кода.
