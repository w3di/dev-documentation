# Разрешение this в Arrow Functions

## Объекты — не области видимости

- Частая ошибка: думать, что фигурные скобки `{}` всегда создают **scope** (область видимости).
- `{}` — это блоки и тела функций, но **объекты не являются областями видимости**.
- Если стрелка определена внутри объектного литерала, её родительская лексическая область — **не объект**, а ближайшая реальная область (функция или global).
- Типичный баг (сотни вопросов на Stack Overflow): «почему стрелка не получает `workshop` как контекст?» — потому что объект `workshop` не scope.

## Пример

- Стрелка внутри объектного литерала на верхнем уровне → её родительская область **global**, а не `workshop`.
- Свойства объекта (`teacher` и т.п.) **не участвуют в lexical scope** — это члены объекта, а не лексические идентификаторы.

## Когда использовать arrow functions

- Использовать стрелку стоит **только** когда нужно поведение **lexical this**.
- Альтернатива lexical this — хак `var self = this`. Имя `self` — плохое: `this` никогда не указывает на саму функцию, а на **контекст**. Если уж делать хак, то `var context = this`.
- Lexical this через стрелку лучше, чем `var self = this`, и даже лучше, чем `function.bind`, потому что точно соответствует ментальной модели «нужно, чтобы `this` вёл себя лексически».
- В общем случае стрелки не рекомендуются (они анонимны и хуже самодокументируются), но для lexical this это правильный инструмент.

## Если используешь стрелку — компенсируй минусы анонимности

1. Нет self-reference для рекурсии/отвязки.
2. Нет имени — задай через name inference (присвой переменной или свойству), иначе будет `anonymous`.
3. Сделай назначение функции явным для читателя, не заставляя читать тело.

> Есть авторское ESLint-правило, требующее, чтобы стрелочные функции использовали `this` (запрещает стрелки без lexical this) — спорное и редко применяемое.

## Итог по this

- Arrow function — **не пятое правило** привязки `this`. Правил по-прежнему 4.
- В стрелке `this` вообще не применяется, поэтому новых правил не нужно.
- Чтобы понять `this`: найти call site функции, которая определяет `this`, и применить 4 правила.

## Главное

- Объекты не являются областями видимости; стрелка внутри объектного литерала ищет `this` в реальной охватывающей области, не в объекте.
- Стрелку стоит применять только ради lexical this — это лучше, чем `var self = this` или `.bind`.
- Arrow functions не добавляют нового правила к привязке `this`; правил остаётся 4.
