# Происхождение closure

## Closure как фундаментальная идея

- **Closure** опирается на понимание **lexical scope** — это база, без которой closure не понять.
- Это одна из самых распространённых и важных идей в computer science, при этом многие не могут дать ей точное определение.
- Если писать на JavaScript дольше трёх часов, вы уже сталкивались с closure — постоянно и часто неосознанно. Используется не только в functional programming, но и в асинхронном коде (AJAX, таймеры) и многих других местах.

## Историческая справка

- Идея closure **предшествует** компьютерным наукам — пришла из **lambda calculus**.
- В программировании появилась рано (Lisp), но долго считалась «академической» фичей, не для обычных разработчиков.
- Brendan Eich в 1995 году в Netscape хотел поместить в браузер **Scheme** (функциональный язык). Ему сказали сделать язык, похожий на Java. В итоге JavaScript внешне похож на Java/C++ (фигурные скобки, точки с запятой), но по сути ближе к Scheme.
- Ключевые концепции functional programming, включая closure, были в языке практически с первого дня — одна из причин успеха и живучести JavaScript.
- Сегодня closure есть в каждом языке — настолько эта идея важна.

## Об определении

- Академическое / математическое определение closure (lambda calculus, Wikipedia, учебники CS) автор считает бесполезным для практики.
- Вместо этого предлагается **observational** (наблюдательное) определение: что в наших программах наблюдаемо иначе из-за наличия closure в языке.

## Главное

- Closure строится на понимании lexical scope.
- Идея пришла из lambda calculus и Lisp, в JavaScript появилась в 1995 году.
- Полезнее наблюдательное определение closure, а не академическое.
