# Executing Code: выполнение и lookup идентификаторов

## Декларация vs исполнение в одной строке

- Строка `var teacher = "Kyle"` — это две разные вещи:
  - `var teacher` — обрабатывается компилятором (создание шарика).
  - `teacher = "Kyle"` — обрабатывается движком при выполнении (присваивание).
- При выполнении объявлений уже нет — они «скомпилированы». Остаётся только исполняемый код.

## target vs source (LHS / RHS)

- Переменная либо **target** (получает присваивание), либо **source** (отдаёт значение).
- Старая терминология: **LHS** (left-hand side) и **RHS** (right-hand side) — левая/правая часть от знака `=`.
- Современно: **L-value** / **R-value**. Для простоты — source и target.
- Позицию (target/source) компилятор фиксирует ещё при построении AST. Знать позицию критично для выполнения.

## Модель «разговора» при выполнении

- Теперь общаются:
  - **virtual machine / JS engine** (движок) — выполняет код.
  - **scope manager** — выдаёт шарики (отвечает только «да»/«нет»).

## Пример выполнения

1. Строка 1: target reference на `teacher`. Спрашиваем глобальный (красный) scope: «есть `teacher`?» → да (объявлен при компиляции) → берём красный шарик и присваиваем ему значение `"Kyle"`.
2. Строки с объявлениями функций пропускаются (они скомпилированы).
3. Строка 13 (`otherClass()`): `otherClass` — это **source** позиция (значение из переменной извлекается, а не присваивается). Спрашиваем глобальный scope → да → получаем значение (ссылку на функцию).
   - Скобки `()` выполняют то, что извлекли. Если бы там было не функция (например, `null`/`undefined`), возникла бы **TypeError**.
4. Выполнение переходит в строку 4: target reference на `teacher` в синем scope → да → присваиваем `"Suzy"` (другая ячейка памяти, другой scope).
5. Строка 5: `console` — source. Внутри `otherClass` его нет → поднимаемся на уровень выше, в глобальный scope → `console` есть как **auto global** → получаем красный шарик, у него метод `log`.

## Ключевой механизм lexical scope

- Если переменная не найдена в текущем scope, поиск идёт на один уровень вверх (к внешнему scope).
- **TypeError** — значение найдено, но операция над его типом недопустима (например, вызов non-функции).
- Каждое обращение к переменной (и target, и source) требует процесса lookup (поиска).

## Главное

- При выполнении объявлений уже нет — есть только присваивания и обращения; цвета и позиции шариков определены ранее на компиляции.
- target = переменная получает значение, source = переменная отдаёт значение; различие критично для lookup.
- Lookup переменной: ищем в текущем scope, не нашли — поднимаемся на уровень выше.
- Вызов значения, которое не является функцией (`null`/`undefined`), даёт TypeError.
