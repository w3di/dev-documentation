# Решение упражнения по hoisting

## Подход

Каждую inline function expression проверяем: использует ли она окружающие лексические переменные?

- Если **нет** — функцию можно вынести в более внешний scope как standalone function declaration.
- Если **да** (closed over) — её приходится оставить внутри того scope, где доступна нужная переменная, но всё равно можно превратить в именованную function declaration внутри этого scope.

## Разбор по шагам

1. **Inline-функция, использующая `studentId`.** Замыкается на `studentId`, поэтому вынести как полностью отдельный helper нельзя — она остаётся внутри своего scope. Но её можно сделать именованной function declaration. Тогда место вызова читается чисто: `find` по совпадению ID → «найти запись студента по ID». Даже однострочные функции выигрывают в читаемости.
2. **Функция сортировки.** Ничего внутреннего не использует → выносится как standalone function и подставляется по имени. Становится яснее, что делает sort.
3. **`printRecord`.** По сути standalone — заменяется ссылкой по имени.
4. **`needToEnroll`** (inline filter в `paidStudentsToEnroll`). Не использует внутренних переменных → выносится наружу.
5. **`getStudentId`.** Ничего внутреннего не использует → выносится наружу.
6. **Фильтрующая функция в `remindUnpaid`.** Не использует внутренних переменных → выносится во внешний scope, вызывается по имени.

**Принцип:** scope легче анализировать, когда он плоский. Чем глубже вложенность, тем неожиданнее могут возникать closures. Поэтому функции выносят в максимально внешний scope.

## Финальная раскладка

1. Все вынесенные функции скопировать вниз файла (работает благодаря function hoisting).
2. Провести ASCII-разделитель:
   - выше линии — **исполняемый код**;
   - ниже линии — **детали реализации** (implementation detail).
3. При открытии файла сразу виден весь код, который будет выполняться.

## Главное

- Inline-функции без замыкания на локальные переменные выносятся наружу как именованные declarations; замкнутые остаются внутри своего scope, но становятся именованными.
- Замена inline-функций именами улучшает читаемость даже для однострочников: место вызова читается как описание действия.
- Function hoisting позволяет держать исполняемый код сверху, а реализацию — снизу; ASCII-линия визуально разделяет эти части.
- Hoisting можно использовать и во вред читаемости, и во благо — здесь показан полезный вариант.
