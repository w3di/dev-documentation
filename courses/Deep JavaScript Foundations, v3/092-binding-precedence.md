# Порядок приоритета привязки this (Binding Precedence)

## Проблема

- На одном call site может совпасть сразу несколько правил привязки `this`.
- Пример: `new workshop.ask.bind(...)` — одновременно есть `new`, контекстный объект и `.bind` (который под капотом использует `apply`). Совпадают три из четырёх правил.
- Так писать не рекомендуется, но это работает — значит, есть чёткий порядок приоритета.

## Порядок проверки правил

1. Функция вызвана с **new**? Если да — `this` указывает на **новый созданный объект**.
2. Функция вызвана через **call** или **apply** (а также `bind` как частный случай)? Если да — используется **указанный контекстный объект**.
3. Функция вызвана на **контекстном объекте** (например, `workshop.ask`)? Если да — используется этот объект.
4. Если ничего не подошло — **default binding**: global object, кроме strict mode (там `undefined`).

## Главное

- Всего 4 правила, проверяемые строго в этом порядке.
- Приоритет: `new` → `call`/`apply`/`bind` → контекстный объект → default.
- Этот порядок полностью и однозначно отвечает на вопрос, на что укажет `this`.
