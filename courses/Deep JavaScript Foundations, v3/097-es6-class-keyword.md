# Ключевое слово class (ES6)

## Что такое class

- **class** — синтаксический сахар поверх системы **prototype** (прототипов).
- Но это не «просто сахар»: у классов своя механика и своя сложность (super, приватные/публичные поля и методы, декораторы и т.д.) — «язык внутри языка».

## Синтаксис

```js
class Workshop {
  constructor() { /* ... */ }
  ask() { /* ... */ }
}
var deepJS = new Workshop();
deepJS.ask();
```

- Имя класса задаётся после `class`.
- Классы могут быть **statement** или **expression**, в т.ч. анонимными (анонимные не рекомендуются).
- Классы могут быть с `extends` или без.
- `constructor` — опционален.
- Между методами **не нужны запятые**.
- Создание экземпляра — `new Workshop()`, вызов метода работает с корректным `this`.

## Наследование и super

```js
class AnotherWorkshop extends Workshop {
  speakUp() { /* ... */ }
  ask(msg) { super.ask(msg); }  // обращение к методу родителя
}
```

- `extends` — наследование; методы родителя «наследуются» без переопределения.
- **super** — позволяет relative polymorphism (относительный полиморфизм): из child-класса обратиться к одноимённому методу parent-класса при **shadowing** (затенение метода).
- До ES6 не было эквивалента `super` — это расширение **за пределами** синтаксического сахара.

## Важно: this binding в классах не изменён

- Классы **не меняют** механику вызова функций и привязки `this`.
- Метод класса, переданный в `setTimeout`, **теряет** привязку `this` — авто-binding нет.
- Методы экземпляров классов ведут себя как любые обычные функции.

## Антипаттерн: hardbound/autobound методы

- Чтобы «зафиксировать» `this`, многие в `constructor` присваивают `this.ask = () => {...}` (arrow) или hardbound-функцию.
- Проблема: метод перестаёт быть на **prototype** и попадает на **instance**.
- Тогда каждый экземпляр получает **отдельную копию** всех функций.
- Дело не столько в производительности (движки справляются), сколько в **предательстве идеи классов**: смысл в том, что методы живут на прототипе и допускают динамизм `this`.
- В итоге получается «плохая, хрупкая версия module pattern», который в языке есть уже 20+ лет.

## Когда уместен class

- Class хорош для полиморфизма, многоуровневого наследования и `super`.
- Но большинство, фиксируя `this`, теряет всю динамическую гибкость и получает худший аналог module pattern.

## Главное

- `class` — сахар над prototype, но с собственной сложной механикой (super и др.).
- Методы класса не авто-биндятся: при передаче как callback теряют `this`.
- Фиксация `this` через arrow/bind в конструкторе перемещает методы с прототипа на экземпляр и ломает идею классов.
