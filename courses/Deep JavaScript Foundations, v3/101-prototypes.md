# Prototypes: копирование против связывания

## Откуда берутся объекты

- Объекты в программах создаются через **constructor call** — вызов функции с `new`.
- «Constructor call» не означает наличие отдельного «конструктора»; это просто вызов с `new`, конструирующий объект для привязки `this`.
- Часто говорят, что объект создаётся **«based on» (на основе)** прототипа конструктора. Именно с фразой «based on» автор не согласен.

## Теория классов: класс — это копирование

- Класс — абстрактный шаблон (**blueprint**, чертёж); instance — конкретная построенная вещь.
- Эта метафора неявно внушает: class-ориентированное программирование — это фундаментально **операция копирования**.
- Влияние Java/C++: большинство впервые увидело классы там, и их модель классов доминирует в сознании.

## Почему метафора подразумевает копирование

- Стёр стену на чертеже — в построенном здании стена не исчезнет.
- Поставил окно в здании — на чертеже оно не появится.
- Связь чертёж↔здание существовала лишь **в момент** постройки: характеристики были **скопированы**, после чего связь прекратилась.
- Вывод модели: instance — это **копия** поведения класса.

## Наследование — тоже копирование

- Метафора генетики: ребёнок получает **копию** ДНК родителя.
- После создания они независимы: перелом ноги ребёнка не ломает ногу родителя.
- Связь была копирующей **в момент создания**.
- Компиляторы/интерпретаторы часто **flatten** (уплощают) классы ради производительности: копируют ссылки на методы прямо в instance. Иерархию классов (**virtual table** из C++) держат только для relative polymorphism.

## JavaScript НЕ копирует — он связывает

- Корректное описание: constructor call создаёт объект **не «based on» прототип, а linked (связанный)** с прототипом.
- **Linking (связывание) и copying (копирование) — диаметрально противоположны**, а не «две стороны одной монеты».
- Они кардинально меняют ожидания от системы.

## Почему это критично

- Программа ломается, когда **ментальная модель расходится** с реальным поведением.
- Если думаешь «копирование», а система делает «связывание» — баги **обязательно** возникнут.
- Class-паттерн фундаментально про копирование, а JavaScript копий не делает — поэтому попытки заставить JS вести себя как class-язык (Java/C++) изначально не стыкуются.

## Главное

- Объекты создаются через constructor call (`new`); JS **связывает** объект с прототипом, а не копирует.
- Классическая модель классов (Java/C++) подразумевает копирование — это расходится с реальностью JS.
- Расхождение между моделью «copy» и реальным «link» — источник багов.
