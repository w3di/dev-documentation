# Lexical Scope: повторение (два прохода)

## Общая модель

- JS — не интерпретируемый построчно язык, а **two-pass processing** (двухпроходная обработка).
- Первый проход — компиляция/парсинг: проходим весь код, создаём план всех scope (вёдер) и помечаем все ссылки на идентификаторы как «цветные шарики».
- Второй проход — выполнение: используем информацию о цвете шарика и его ведре.

## Проход 1: компиляция (compiler ↔ scope manager)

- Для каждого formal declaration спрашиваем: «есть ли уже такой идентификатор в этом scope?»
  - Вопрос нужен, чтобы не создавать дубли: для одного scope шарик создаётся один раз, повторного создания нет.
- Пример (тот же, что разбирали):
  1. Строка 1: `teacher` → красный шарик в красном (глобальном) ведре.
  2. Строка 3: `otherClass` → красный шарик + новое синее ведро (функция создаёт scope).
  3. Строка 4: `teacher` внутри `otherClass` → «не слышали» (другое, синее ведро!) → синий шарик.
  4. Строка 8: `ask` → красный шарик + новое зелёное ведро.
  5. Строка 9: `question` → зелёный шарик.

## Проход 2: выполнение (engine ↔ scope manager)

1. Строка 1: target `teacher` → да → красный шарик, присваиваем значение.
2. Строка 13: source `otherClass` (не target → значит source) → да → красный шарик содержит ссылку на функцию (синий scope) → скобки вызывают её.
   - Если бы там была не функция — была бы TypeError (reference error — другое).
3. Строка 4: target `teacher` → синий шарик → присваиваем `"Suzy"`.
4. Строка 5: source `console` → в синем scope нет → поднимаемся в глобальный → да (предоставлен средой) → красный шарик, метод на объекте.
5. Строка 14: source `ask` → да → красный шарик (мы в глобальном scope) содержит функцию → вызов → зелёный scope.
   - Важно: функция имеет scope, но сама не является scope; шарик — это ссылка на функцию.
6. Строка 9: target `question` → зелёный шарик, присваиваем.
7. Строка 10: source `console` → находим в глобальном (как на строке 5); аргумент `question` — source → зелёный шарик → значение `"Why?"` передаётся → присваивается параметру.

## Главное

- Первый проход создаёт план всех scope и помечает идентификаторы «цветными шариками»; второй — выполняет, используя цвета и вёдра.
- Один и тот же вопрос «слышали ли об этом идентификаторе?» задаётся отдельно каждому scope — поэтому одноимённые переменные в разных scope независимы.
- Не найдя переменную в текущем scope, поиск поднимается на уровень вверх.
- Функция обладает scope, но сама scope не является; в шарике лежит ссылка на функцию.
