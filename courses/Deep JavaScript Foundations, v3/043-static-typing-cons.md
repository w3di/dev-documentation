# Минусы static typing (TypeScript / Flow)

## 1. Синтаксис поверх JavaScript / external standard

- TS/Flow вынуждены наслаивать синтаксис **поверх** JavaScript и определять **external standard**, а не стандарт JavaScript.
- Нет гарантии (и даже вероятности), что нынешний синтаксис TS/Flow окажется в гипотетическом будущем JavaScript. Типизация в JS — дело далёкого будущего: даже **stage-3 proposal** по типам отсутствует.
- Это создаёт **ecosystem lock-in**: выбор непортируемого синтаксиса и тулинга. JavaScript победил благодаря **ubiquity (вездесущности)**, а здесь мы замыкаемся в популярной, но менее вездесущей экосистеме.

## 2. Код-комментарии как «escape valve»

- Можно делать аннотации через **code comments** — тогда код запускается без инструмента (не полная привязка). Это плюс.
- Но почти никто так не делает: все используют inline-синтаксис → реальный lock-in сохраняется.

## 3. Требуется build process

- Использование инструментов требует **build process**, что повышает **barrier to entry**.
- Единственный способ обойтись без сборки — подход с code comments, но тогда нет никакой пользы от системы, поэтому так не делают.
- Build-процессы распространены, но новичкам приходится учить «весь DevOps» ещё до первой строки JavaScript. TypeScript, по сути, **навсегда привязан к build process** — плохо как barrier to entry.

## 4. Экспоненциальный рост сложности синтаксиса

- Базовые «наложенные» типы просты, но **generics**, **interfaces** и подобное быстро уводят код в стиль, **совсем не похожий на JavaScript** (по ощущению автора — на Haskell).
- Синтаксис разрастается в сложности экспоненциально (вложенные угловые скобки и т. п.).
- Продвинутые возможности резко поднимают barrier to entry: на проект с ними сложно нанять разработчика, не являющегося уже сильным TypeScript-разработчиком.

## 5. Static typing не в ДНК JavaScript

- Идея, что контейнеры (переменные, параметры, return, свойства) **обязаны всегда иметь ровно один тип**, чужда JavaScript.
- Для return-типа функции типизация бывает полезна, но типизировать **переменные** — не в ДНК языка.
- JavaScript (и любой динамический язык) — это **value typing** (типизация значений), а не **variable typing** (типизация переменных).
- Для автора это ощущается как «betrayal» — попытка переделать JavaScript в нечто иное, исходя из мнения, что текущий JavaScript «сломан» или недостаточен. Автор считает JavaScript отличным и «чинить» его не нужно.

## Вывод

- Есть big divide: с одной стороны — реальная польза тулинга для команд, с другой — серьёзные downsides.
- Поэтому обсуждение стоит расширять от конкретно TypeScript/Flow до общей идеи **type-aware linting**: сама идея полезна и важна, а TS/Flow — лишь два частных способа её реализации, не единственные.

## Главное

- Ключевые минусы: external standard и ecosystem lock-in; обязательный build process (barrier to entry); экспоненциальный рост сложности синтаксиса (generics/interfaces); static typing чуждо ДНК JavaScript (value typing, а не variable typing).
- Решение — мыслить шире, в терминах **type-aware linting**, где TS/Flow лишь одна из реализаций.
