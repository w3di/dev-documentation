# Понимание своих типов (итоги юнита)

## JavaScript имеет типовую систему

- Факт: у JavaScript есть **dynamic type system** — это полноценная типовая система, просто **динамическая**, не как у Java.
- Утверждение «в JavaScript нет типов» — неверно.
- Коэрсия в JS — это **value type conversions** (преобразования типов значений), а не variable typing. Также есть equality-сравнения с коэрсией.

## Критика стратегии избегания

- Преобладающий ответ на типовую систему JS — «избегать как можно большего и использовать только `===` для защиты».
- Это **неэффективная стратегия**. Системное избегание целого раздела языка **систематически порождает баги**.
- Проблема не в одном конкретном баге: сам настрой «мне не нужно понимать эту часть языка» — системный источник багов. Избегать понимания чего-либо в языке автор не рекомендует.

## Главное убеждение

- Нельзя писать качественные программы на JavaScript, **не понимая своих типов**.
- Код может работать, но не дотягивает до планки качества, если автор и читатели не понимают типы.
- Нужно менять структуру кода и использовать доступные механизмы, чтобы **сигнализировать о типах**.

## Про полный static type system

- Можно пойти до конца и взять TypeScript/Flow — это нормально и осмысленно для многих команд.
- Но автор считает это тоже формой **avoidance** (иного рода): «система типов JS безнадёжна, построим новую» — нездоровый подход.

## Рекомендация

- Типы JavaScript **не хуже** — их можно изучить и использовать, и это не намного сложнее.
- На деле выучить типовую систему JS (при правильном обучении) **проще**, чем все сложности static type system.
- Лучший подход — **принять типы JavaScript** и писать в стиле, который делает их очевидными.
- Даже если ничего не делать с `==`, а просто **думать о своих типах**, код станет лучше: лучше спроектирован, надёжнее, меньше багов.

## Главное

- JavaScript имеет полноценную **dynamic type system** (value typing с коэрсией); систематическое избегание типов через «`===` везде» порождает баги.
- Качественный JS невозможен без понимания типов; лучший путь — принять типы JS и писать в стиле, делающем их очевидными, что само по себе улучшает код.
- Полный переход на TS/Flow — допустим, но это тоже форма avoidance; изучить типы JS зачастую проще, чем осваивать static type system.
