# Fundamental Objects (фундаментальные объекты)

## Терминология

- **Fundamental objects** (фундаментальные объекты) — относительно новый термин спецификации.
- Раньше их называли **built-in objects** или **native functions**.
- Это «привинченная» к JavaScript объектная сторона, Java-подобные объектные обёртки для значений.

## Когда уместен new

- Эти фундаментальные объекты разумно создавать через `new`, если нужен объект соответствующего типа:

```
Object, Array, Function, Date, RegExp, Error
```

- Ключевой пример — **Date**: единственный способ создать дату — `new Date`, так как литерала даты в языке нет. Это, по сути, главная причина сохранять оператор `new`.

## String, Number, Boolean — НЕ через new

- **String**, **Number**, **Boolean** тоже можно вызвать с `new`, но так делать **не следует** — это создаёт «странный» объект-обёртку.
- Их нужно использовать **как функции** (не как конструкторы): в этой роли они приводят (**coercion**) любое значение к соответствующему примитивному типу.

```
String(myGPA)   // приводит значение к примитивной строке
```

- Это гораздо полезнее, чем конструирование объекта-обёртки.

## Главное

- Fundamental objects (ранее built-in objects / native functions): `Object, Array, Function, Date, RegExp, Error` — их уместно создавать через `new`.
- `Date` особенно: единственный способ создать дату — `new Date` (литерала нет).
- `String`, `Number`, `Boolean` никогда не использовать с `new` — только как функции для приведения к примитиву.
