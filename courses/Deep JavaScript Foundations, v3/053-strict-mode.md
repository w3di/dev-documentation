# Strict Mode

## Как включить

- Включается фрагментом `"use strict"` в начале scope.
- Лучше всего — в начале программы/файла, либо в начале функции.

```js
"use strict";
```

## Что меняется со scope

- Вся обработка та же, но при target-ссылке на необъявленную переменную, дойдя до глобального scope, вместо создания auto global возникает **ReferenceError**.
- Это именно то поведение, которого хочется всегда: «нет такого шарика — ошибка».

## ReferenceError vs TypeError

- **ReferenceError** — переменная не найдена (нельзя выдать шарик).
- **TypeError** — переменная найдена, но её текущее значение нельзя использовать так, как пытаемся (вызвать как функцию, обратиться к свойству `undefined`/`null` и т.п.).

## Где strict mode включён автоматически

- По умолчанию JS НЕ в strict mode (из-за обратной совместимости — иначе сломались бы старые программы). Нужно явно включать (opt-in).
- Транспайлеры (Babel и др.) почти всегда добавляют strict mode сами — транспилированный код почти наверняка strict.
- Внутри ES6 **class** и ES6 **module** strict mode подразумевается автоматически — писать `"use strict"` не нужно.

## Почему стоит использовать

- Strict mode — по сути будущее языка; всё больше конструкций (классы, модули) подразумевают его.
- Существует около десятилетия — пора переходить.
- Поведенческие различия (ещё с ES5): ряд операций, которые в non-strict тихо игнорировались, в strict дают ошибку.
  - Пример: присваивание к read-only свойству/переменной в non-strict молча не срабатывало; в strict — ошибка.

## Нюансы про новые фичи

- Прямых примеров синтаксиса, недоступного без strict mode, лектор не приводит, но различия в поведении (одно поведение разрешающее, другое запрещающее) возможны.
- В strict mode переменные всегда должны быть объявлены — нельзя авто-создавать их (включая случай в глобальном scope: всё равно ReferenceError).

## Главное

- Strict mode превращает обращение к необъявленной переменной в ReferenceError вместо создания auto global.
- ReferenceError = переменная не найдена; TypeError = найдена, но операция над её типом недопустима.
- JS не strict по умолчанию (нужен opt-in), но class и module включают strict mode автоматически.
