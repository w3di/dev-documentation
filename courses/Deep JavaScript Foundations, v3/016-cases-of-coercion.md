# Случаи coercion: где вы уже его используете

## Coercion неизбежен

- **Coercion** (приведение типов) — недооценённая и оклеветанная часть JavaScript, а не «зло».
- Совет «избегай coercion, всегда используй `===`» не работает: coercion происходит в коде постоянно, осознаёте вы это или нет.

## Number → String

### Template literals (ES6)
- При вставке не-строкового значения в template-строку оно неявно приводится к строке.

```js
`...${msg1}...`   // если msg1 — число, происходит implicit ToString
```

### Оператор `+`
- `+` перегружен (**operator overloading**): обычно числовая операция, но при участии строки предпочитает конкатенацию.
- Спецификация: если **хотя бы один** операнд — строка, `+` делает string concatenation, а второй операнд приводится через `ToString`.

```js
num + ""   // классический способ превратить число в строку
```

- На корректном числе (например, `16`) проблем нет, но у `ToString` есть corner cases на других значениях.

### Явные способы Number → String
- `[num].join("")` — спецификация `join` приводит элемент к строке (крайне неочевидно, не рекомендуется).
- `num.toString()` — на «этикетке» написано, что делает; но это всё ещё implicit coercion (вызов метода на примитиве — см. boxing).
- `String(num)` — предпочтительный явный способ (fundamental object **без** `new`).

## String → Number

- Данные из DOM/форм приходят строками; при числовых операциях это даёт ошибки.

```js
"16" + 1   // "161" (конкатенация), а не 17
```

### Способы String → Number
- Unary `+` — вызывает `ToNumber`:

```js
+"16"   // 16
+""     // 0  (пустая строка → 0, может быть нежелательно)
```

- `Number(x)` — предпочтительный явный способ; нет операции `ToNumber`, поэтому `Number()` — самый семантичный.
- Оператор `-` определён только для чисел (не перегружен для строк) → всегда вызывает `ToNumber`.

## Boolean coercion

- Проверка непустой строки в `if` — это тоже coercion (через `ToBoolean`).
- У Boolean coercion больше всего corner cases.

### Типичные ловушки
- Пустая строка → falsy; строка из одних пробелов → **truthy** (хотя для пользователя «пустая»).
- Использование числа как truthy/falsy («`length` ноль → false»): ломается на `NaN`.

### Явный Boolean
- `!!x` — двойное отрицание приводит к Boolean.
- `Boolean(x)` — предпочтительный явный способ.
- Вместо числового coercion лучше писать осмысленное условие: `while (length > 0)` вместо `while (length)` — защищает от части corner cases и яснее по смыслу.

## Личная позиция (Kyle Simpson)

- `null` и `undefined` стоит по возможности трактовать как неразличимые значения; Boolean coercion здесь полезен («задано или нет»).
- Для объектов/`null`/`undefined` implicit ToBoolean приемлем.
- Для строк и чисел implicit Boolean coercion «не окупается» из-за обилия corner cases — лучше быть явным.

## Главное

- Coercion уже работает в вашем коде: template literals, `+`, формы, `if` с не-Boolean.
- `+` предпочитает конкатенацию, если хоть один операнд — строка; `-` всегда приводит к числу.
- Предпочтительные явные приведения: `String(x)`, `Number(x)`, `Boolean(x)`.
- Boolean coercion полон corner cases (пробелы → truthy, `NaN`); используйте осмысленные сравнения вместо неявных.
