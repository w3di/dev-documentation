# TypeScript и Flow: контекст и преимущества

## Подход «знать свои типы»

- Цель — стиль кода, который делает **типы очевидными**. До сих пор это достигалось только средствами самого JavaScript (например, ограничением допустимых входных значений для сравнений).
- Более широкая категория, чем TypeScript/Flow, — **type-aware linting** (типо-зависимый линтинг).

## Про линтинг

- **Linter** — инструмент, применяющий «мнение» о коде, чтобы разработчик мог с ним согласиться или нет.
- Линтинг полезен, но только **конфигурируемый**: нет универсального «one size fits all».
- Решение о стиле должно приниматься командой демократически (**style guide**), а не диктоваться извне или одним «благожелательным диктатором».

## Отношение автора к TypeScript/Flow

- Автор рад, что они существуют, но сам не использует ни TypeScript, ни Flow.
- Уточнённая позиция: не «они решают проблемы, которых у меня нет», а «они решают реальную проблему способом, который, по его мнению, делает код **хуже**».
- Проблема реальна: кодить, ничего не зная о типах, — это плохо, и её надо решать. Разногласие — лишь в способе решения.

## Преимущества TypeScript и Flow

1. **Ловят type-related ошибки** — полезно для качества кода.
2. **Сообщают намерение о типах** (type intent), т. к. аннотации прямо в коде делают типы очевидными. Есть и режимы только с inference.
3. **IDE-интеграция / tooling feedback:** автодополнение, on-the-fly выводы и анализ типов прямо в IDE. У TypeScript интеграция с IDE лучше, чем у Flow (и лучше большинства проектов вообще).

## Оговорки (caveats)

1. **Inferencing — лишь best guess.** Вывод типов делается на compile time и не гарантирует, что произойдёт в runtime.
2. **Аннотации опциональны.** Без аннотации TypeScript по умолчанию подставляет тип **`any`** (если это не отключено), и пользы нет. Система **opt-in**: где не подключился — только догадка.
3. Это может давать **ложное чувство безопасности**, если использовать невнимательно.

## Главное

- Реальная проблема — кодинг без знания типов; TypeScript/Flow — один из способов её решить через type-aware linting.
- Их плюсы: ловля типовых ошибок, выражение type intent, мощная IDE-интеграция.
- Их минусы: inference — лишь best guess, аннотации опциональны (по умолчанию `any`), отсюда возможное ложное чувство безопасности; любое нетипизированное место = неопределённость.
