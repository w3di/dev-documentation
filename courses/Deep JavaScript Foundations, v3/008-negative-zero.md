# Отрицательный ноль (-0)

## Что это

- **-0** (negative zero) с точки зрения математики не существует, но существует в программировании и в **IEEE 754** (как и NaN).
- Это значение нуля с включённым **sign bit** (битом знака) — отрицательное представление нуля.

## Как JavaScript «прячет» -0

- На раннем этапе сочли, что разработчики не захотят -0, и стали маскировать его существование, из-за чего возникли странности:

```
trendRate = -0;
trendRate === -0;        // true
trendRate.toString();    // "0"  — знак потерян
(-0) === 0;              // true  — "лжёт"
-0 < 0;  // false;  -0 > 0;  // false
```

- `toString` «лжёт» (даёт `"0"`), `===` «лжёт» (`-0 === 0` → true), операторы `<` и `>` тоже «лгут».
- Урок (Getify): язык должен делать корректную вещь, а ответственность за разумное отображение пользователю — на разработчике. Язык не должен «перехитрять» разработчика (как и автоматическая вставка точек с запятой — ASI).

## Как проверить на -0

- До ES6 надёжного встроенного способа не было.
- С ES6 появилась **Object.is** — «учетверённое равенство», которое не лжёт:

```
Object.is(trendRate, -0);   // true только для -0
Object.is(NaN, NaN);        // true
```

- Есть и математический способ определить -0 (см. решение упражнения): `1 / -0 === -Infinity`.
- Для проверки NaN семантичнее `Number.isNaN`, но `Object.is` тоже умеет.

## Math.sign не помогает

- `Math.sign` должен бы определять знак, но возвращает `-0` и `0` (вместо `-1` и `1`) для нулей — поэтому для определения -0 непригоден.
- Можно написать «исправленную» версию sign: для не-нулей использовать `Math.sign`, а для нулей — `Object.is` для распознавания -0, чтобы вернуть `-1` при -0.

## Зачем нужен -0

- Полезен, когда одно числовое значение кодирует две сущности: абсолютное значение (например, скорость) и знак (направление).
- Пример автора: машинка на карте — при остановке (скорость 0) знак -0/+0 сохраняет последнее направление движения. Аналогично в играх и для трендов (например, падает или растёт акция, даже при нулевом значении).
- Это более консистентно, чем заводить отдельную переменную для направления при нуле.

## Главное

- -0 существует в IEEE 754: это ноль с битом знака.
- `===`, `<`, `>`, `toString` «лгут» про -0; надёжная проверка — `Object.is` (или приём `1/v === -Infinity`).
- `Math.sign` для нулей возвращает -0/0, поэтому для распознавания -0 не годится.
- -0 полезен, когда знак числа несёт направление, а абсолютное значение — величину.
