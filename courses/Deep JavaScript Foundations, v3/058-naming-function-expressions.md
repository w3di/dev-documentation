# Naming Function Expressions: три причины именовать

## Зачем именовать функции

- Именование (naming things) — классическая трудная задача в программировании, но усилие оправдано.
- Три причины, вместе образующие веский аргумент всегда использовать named function expressions.

## Причина 1: надёжная self-reference

- Имя создаёт надёжную **self-reference** (ссылку функции на саму себя изнутри).
- Полезно для:
  - рекурсии;
  - event handler, которому нужно отписать себя (unbind);
  - доступа к свойствам объекта-функции (`length`, `name` и т.д.).
- Старые хаки (`arguments.callee`) фактически deprecated; правильный способ — имя function expression.
- Имя в собственном scope read-only — это более надёжная self-reference, чем имя переменной во внешнем scope (которое не read-only и может быть переприсвоено).

## Причина 2: отлаживаемые stack traces

- Имя функции отображается в **stack trace** (трассировке стека).
- Анонимные функции в трассировке выглядят как «anonymous function» (особенно в минифицированном production-коде: `line 1, char 32712`) — бесполезно.
- Хорошее семантическое имя (например, `handleUserClick`, а не `foo`) делает код и трассировки отлаживаемыми.
- Иногда по именам и порядку функций в трассировке можно определить причину бага, не глядя в код.

## Причина 3: самодокументируемость

- Имя делает код **self-documenting** (самодокументируемым).
- У анонимной функции читателю приходится выводить (infer) назначение из тела функции и места вызова.
- Имя `handleUserClick` сразу и однозначно сообщает назначение — без чтения остального кода.

## Shadowing при совпадении имён

- Если имя function expression совпадает с именем внешней переменной — это shadowing, но это не считается проблемой.
- Обычно обе ссылки одновременно не нужны; если нужны — придётся дать разные имена.
- Иногда имя по назначению функции и имя переменной/свойства, куда она присваивается, должны различаться (разный смысл).

## Про name inference

- Анонимная функция, присвоенная переменной, может получить **inferred name** (выведенное имя) для stack trace — но только если нет сложного destructuring.
- Главная проблема: в ~99.9% случаев анонимные функции используются как **callbacks**, передаваемые inline в `.map`, `.then` и т.п.
- При передаче function expression в call-позицию имя вывести невозможно — name inference не работает.
- Чтобы получить выведенное имя, нужно присвоить переменной; но тогда проще сделать function declaration и не писать имя дважды.

## Практические рекомендации

- Предпочитать function declaration с именем; если нужен function expression — давать ему имя, как у declaration.
- Личное правило: function declaration, если функция длиннее трёх строк; для 1–3 строк — inline function expression; если функция вызывается многократно — declaration даже для одной строки.
- Анонимные функции используют по сути только чтобы «меньше печатать» — это не аргумент.
- Если не удаётся придумать имя — вероятно, функция слишком сложна и её нужно разбить на части.
- Приём автора: начинать с имени `TODO`, искать `TODO`-комментарии перед коммитом и доименовывать функции позже.

## Главное

- Три причины именовать function expressions: надёжная self-reference, отлаживаемые stack traces, самодокументируемость.
- Имя в собственном scope (read-only) — более надёжная self-reference, чем внешняя переменная.
- Name inference не работает для callback-ов, передаваемых inline — главная причина, по которой анонимные функции теряют имена.
- Цель кода — ясно сообщать намерение, а не быть удобным для набора; каждая функция имеет назначение, значит имеет имя.
