# Hoisting

## Hoisting — это метафора, а не реальный механизм

- До недавнего времени (последние год-два) слово «hoist» вообще не встречалось в спецификации JavaScript.
- **Hoisting** — не реальное поведение движка: движок не перемещает объявления.
- Это придуманная (англоязычная) языковая конвенция для обсуждения lexical scope, не думая о lexical scope явно.

## Почему hoisting не может существовать буквально

- Корректное объяснение требует двух проходов: сначала компилятор, затем исполнение. Людям удобнее одно-проходное объяснение, отсюда и hoisting.
- Hoisting описывают так: при входе в scope движок «магически заглядывает вперёд», находит все declarations и поднимает их наверх scope перед исполнением.
- Это не происходит: движок не переставляет `var` наверх.
- Доказательство: чтобы найти объявления дальше в блоке, нужно сложное обработка токенов до конца блока. JavaScript — non-regular язык, регулярные выражения не подходят.
- Такая «магическая обработка» называется **parsing** (парсинг). Найти объявления ниже можно только парсингом — значит, hoisting лишь сокращённое описание этого.

## Вред неправильного понимания

- На Stack Overflow «это из-за hoisting» часто даётся как ответ — и нередко неверно, что закрепляет заблуждения.
- Hoisting сам по себе не вреден, но без знания нюансов вводит в заблуждение.
- Поэтому сначала изучают реальный механизм (two-pass / lexical scope), а затем возвращаются к hoisting как к удобному сокращению — вооружившись обоими, не запутаешься.

## Function declaration vs function expression

- Function declarations обрабатываются в первом проходе и доступны раньше места объявления в scope.
- Function expression, присвоенное переменной, присваивается только на своей строке.

```js
foo();            // работает: function declaration
bar();            // TypeError: bar ещё undefined на этой строке

function foo() {}
var bar = function() {};
```

- **Важно:** при форме «функция присваивается переменной/свойству» все функции должны быть определены до вызова.

## Использование function hoisting на практике

- Функции hoist: они определяются на compile time и могут использоваться раньше места объявления.
- Это позволяет располагать исполняемый код вверху scope, а declarations функций — внизу (и в верхнем scope, и во вложенных).
- Выгода: открывая файл, читатель сразу видит исполняемый код, а не прокручивает тысячи строк функций.
- Часть разработчиков считает hoisting плохо спроектированной, «багованной» частью языка и поводом не считать JavaScript лексически scoped; оценка зависит от задачи — иногда hoisting вреден, иногда полезен.

## Главное

- Hoisting — метафора для lexical scope, а не реальное перемещение кода; на самом деле всё решается парсингом и двумя проходами.
- Function declarations доступны до объявления; function expressions — только после присваивания (иначе TypeError).
- Hoisting функций позволяет держать исполняемый код вверху, а объявления функций — внизу scope.
