# Corner cases coercion

## Corner cases есть у всех языков

- У любого языка есть type conversions, а значит — и corner cases, включая JavaScript.
- Нечестно использовать corner cases JS как аргумент против языка, делая вид, что у других языков (C++, Python) их нет.
- Спроектировать систему без corner cases невозможно. Правильный путь — изучить их и научиться обходить, а не делать «wat-видео».

## Числовые corner cases — корень зла

- Многие corner cases связаны с превращением falsy-значений в числа.
- Главный источник проблем: **пустая строка `""` → `0`**.
- `ToNumber` сначала срезает leading/trailing whitespace, поэтому строка из любых пробелов тоже → `0`.

```js
Number("")       // 0
Number("   ")    // 0
Number("\t\n")   // 0
```

- Если бы `""` приводилась к `NaN`, а не к `0`, большинство этих проблем исчезли бы.

## Falsy-объект: `new Boolean(false)`

- `new Boolean(false)` создаёт объект, который ведёт себя как **truthy**.
- Причина: при ToBoolean не делается `ToPrimitive` — просто проверяется, есть ли значение в falsy-списке. Объекта там нет → truthy.
- Ещё один довод никогда не использовать fundamental-объекты с `new`.

## Boolean → Number: опасность 1 и 0

- Неявное приведение Boolean к числу (`true` → `1`, `false` → `0`) — плохая идея.

### Пример «цепочки сравнений»

```js
1 < 2          // true
2 < 3          // true
1 < 2 < 3      // true — но это случайность!
```

- Что реально происходит: `1 < 2` → `true`; затем `true < 3` → `true` приводится к `1`, и `1 < 3` → `true`. Результат верен **по случайности**.

```js
3 > 2          // true
2 > 1          // true
3 > 2 > 1      // false!
```

- Здесь: `3 > 2` → `true`; `true > 1` → `1 > 1` → `false`.
- Сравнения по цепочке «работают» лишь из-за скрытого Boolean → Number; строить на этом программы нельзя.

## Главное

- Corner cases неизбежны в любом языке; их надо изучать, а не избегать весь механизм.
- Корень числовых проблем — `""` (и whitespace-строки) → `0`; в идеале было бы `NaN`.
- `new Boolean(false)` — truthy-объект, потому что ToBoolean не делает ToPrimitive.
- Неявное Boolean → Number (1/0) даёт обманчиво работающие цепочки сравнений — это случайность, а не «ум» JS.
