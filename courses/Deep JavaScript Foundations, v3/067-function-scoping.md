# Function scoping

## Проблема naming collision

- Переменная объявляется в начале программы и используется далее с расчётом на сохранение значения.
- Другой разработчик может позже вставить код, объявив переменную с тем же именем в том же scope.
- Перезапись переменной ломает использование ниже неочевидным образом — это **naming collision** (коллизия имён).
- `const` не решает проблему по сути: он лишь бросит ошибку, после чего разработчик заменит `const` на `var`.
- Корень проблемы — не возможность переприсваивания, а то, что две сущности используют одно имя в одном scope.

## Решение через function scope

- Чтобы избежать коллизии, переменные кладут в разные «buckets» — оборачивают функцией, создавая новый scope.
- Переменная внутри функции становится «другим marble» и не конфликтует с внешней.
- Недостаток: сама функция вводит имя (например, `anotherTeacher`) во внешний scope — коллизия лишь сдвигается на имя функции.

## Principle of least exposure

- **Principle of least exposure / least privilege** (принцип наименьшего раскрытия/привилегий): по умолчанию держать всё приватным, раскрывая только минимально необходимое.
- Это защитная позиция, решающая три проблемы:
  1. **Naming collisions** — скрытие уменьшает поверхность для коллизий имён.
  2. **Misuse** — скрытое нельзя случайно или намеренно использовать неправильно; всё открытое рано или поздно будет использовано.
  3. **Future refactoring** — самая важная и недооценённая: если деталь скрыта, её можно свободно рефакторить; открытое будет использовано чужим кодом, что свяжет руки при изменениях.

## Подготовка к IIFE

- Нужен способ создать scope функцией, но не загрязнить внешний scope именем.
- Вызов через переменную можно мыслить в два шага: (1) получить значение marble, (2) скобки `()` исполняют его.
- Обёртывание первого шага в скобки сохраняет работоспособность: `(fn)()` — сначала берётся значение, затем исполняется.

## Главное

- Naming collision — корневая проблема, решаемая через scope, а не через `const`.
- Principle of least exposure: всё приватно по умолчанию; защищает от коллизий, неправильного использования и связывает руки при рефакторинге.
- Простая обёртка функцией создаёт scope, но загрязняет внешний scope именем — нужен механизм без этого (IIFE).
