# Проверка типов операндов (validating operand types)

## Недооценённая возможность

- Помимо проверки присваиваний (static typing), TypeScript умеет сообщать, что некоторая **операция недопустима**.
- Именно отсюда у автора возникало **больше всего багов** — не из присваиваний, а из недопустимых операций.

## Пример

- TypeScript говорит: нельзя вычитать строку из числа — соответствующая настройка запрещает такую коэрсию.

```ts
var x: number = 42;
var y: string = "3";
x - y;   // ошибка: нельзя вычитать string из number
```

- Для автора это **реально полезная** помощь: хотелось бы линтер, который запрещает вычитать строку из числа.

## Пожелание автора

- Идеально: линтер, который проверяет **операции** (где сосредоточена бизнес-логика), но не навязывает все жалобы про static-type-присваивания.
- Хотелось бы механизм, **разрешающий часть коэрсий**: есть места, где коэрсия желательна, и места, где её надо избегать.
- По наблюдениям, TypeScript работает **«всё или ничего»** (opt-in целиком или нет). Хотелось бы больше нюансировки и конфигурации.

## Главное

- Проверка **типов операндов** (валидность операций) — недооценённая и очень полезная часть TypeScript; именно недопустимые операции — частый источник багов.
- Ограничение: TS «всё или ничего», не позволяет выборочно разрешать нужную коэрсию — автору не хватает конфигурируемости.
