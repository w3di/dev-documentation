# The Prototype Chain

## Нотация диаграммы

- Квадраты — объекты, кружки — функции.

## «Line zero»: окружение до старта программы

- Существует функция **Object** (capital O) — фундаментальная встроенная функция и одновременно namespace с утилитами (`Object.keys`, `Object.values` и др.).
- Существует важнейший объект **Object.prototype**, у которого нет собственного имени — на него ссылается свойство `prototype` функции `Object`.
  - На `Object.prototype` лежат `toString`, `valueOf` и другие фундаментальные утилиты.
  - Все non-primitives происходят напрямую от `Object.prototype`.
- Обратная ссылка: с `Object.prototype` на `Object` идёт свойство **constructor**.
  - В прототипной системе слово `constructor` не несёт реального смысла («не больше, чем fubar») — оно создано, чтобы создать видимость наличия классов.

## Разбор кода по строкам

### Строка 1: `function Workshop`

- Создаётся функция `Workshop`.
- Неявно создаётся объект **Workshop.prototype** (пустой, но важный) — ссылка идёт через свойство `prototype` функции.
- Обратная ссылка `Workshop.prototype.constructor` → `Workshop` (опять же ради видимости классов).
- Есть скрытая связь между `Workshop.prototype` и `Object.prototype` (пунктир) — детали позже.

### Строка 4: `Workshop.prototype.ask = ...`

- На объект `Workshop.prototype` добавляется свойство `ask` (то, что это функция, не важно).

### Строка 8: `var deepJS = new Workshop(...)`

Четыре действия `new`:

1. Создаётся новый пустой объект «из ниоткуда».
2. Этот объект **связывается** (скрытая пунктирная связь) с `Workshop.prototype`.
3. Вызывается `Workshop` с `this` = новый объект; строка 2 добавляет на него свойство `teacher`.
4. Функция не возвращает свой объект → `new` возвращает `this` (новый объект). Он именуется `deepJS`.

## Поиск по prototype chain

- Строка 11: `deepJS.ask()`. У `deepJS` **нет** метода `ask` (он не скопирован — модель копирования неверна).
- Работает за счёт внутренней связи — **prototype chain** (в спецификации `[[Prototype]]`).
- Механизм: при отсутствии свойства на объекте идём **на один уровень вверх** по цепочке к следующему объекту и спрашиваем там. `Workshop.prototype` имеет `ask` — берём оттуда.
- **Важно про this:** при вызове `ask` `this` указывает на `deepJS`, потому что **call site** — строка 11 (`deepJS.ask`). Откуда найден метод — не важно; `this` определяет call site.
- Для `reactJS.ask()` (строка 14) — то же: `this.teacher` обращается к `teacher` объекта `reactJS`.

## Вывод

- Один метод разделяется между потенциально бесконечным числом инстансов благодаря prototype linkage и this binding — мощная система.
- Прототипная система и `this` не плохи; ограничивающим является взгляд на них **только через призму классов** — система мощнее, чем class-паттерн.

## Главное

- В «line zero» уже существуют `Object`, `Object.prototype` и взаимные ссылки `prototype`/`constructor`.
- `new` создаёт объект, связанный с `Function.prototype`; методы не копируются в инстанс.
- Доступ к методу идёт вверх по prototype chain; `this` при этом определяется call site, а не местом нахождения метода.
