# NaN и проверка на NaN

## Что такое NaN

- **NaN** — формально «not a number», пришёл в JavaScript из спецификации **IEEE 754** (стандарт чисел).
- Лучшая ментальная модель: NaN — это **invalid number** (недопустимое число), специальное **sentinel value** (сигнальное значение), а не «не число».
- `typeof NaN` возвращает `"number"` — потому что NaN это именно недопустимое *число*. Трактовка «invalid number» снимает парадокс «typeof not-a-number = number».

## Как получается NaN

- Строки-представления чисел («38», «39») корректно ведут себя как числа.
- Если значение нельзя представить числом (например, `"n/a"`), при попытке математической операции получается NaN.
- **Важно**: число `0` НЕ является обозначением отсутствия числового значения — 0 это полноценное число. Единственное корректное значение для «нет валидного числа» — это NaN.

```
"38" - "n/a"   // NaN: "n/a" приводится к NaN, далее любая операция с NaN → NaN
```

- Оператор `-` определён только для чисел; нечисловой операнд приводится (**coercion**) к числу, и `"n/a"` превращается в NaN.
- **NaN распространяется (propagates)**: любая математическая операция с участием NaN даёт NaN.

## NaN не равен сам себе

- `NaN === NaN` возвращает `false`.
- Причина — не «прихоть» Брендана Эйха, а требование IEEE 754: NaN не равны друг другу.
- NaN — **единственное** значение в JavaScript, не обладающее **identity property** (не равно самому себе).
- `undefined === undefined` возвращает `true` (undefined равен себе).
- Вывод: оператор `===` «лжёт» в случае NaN, поэтому нужен отдельный способ проверки на NaN.

## isNaN vs Number.isNaN

- **isNaN** (исходная утилита) **приводит аргумент к числу** перед проверкой — это создаёт ложные срабатывания:

```
isNaN("my son's age")  // true — НЕВЕРНО: строка приводится к NaN, потом проверяется
```

- С ES6 появилась **Number.isNaN** — проверяет, является ли значение именно NaN, **без coercion**:

```
Number.isNaN("my son's age")  // false — корректно
Number.isNaN(NaN)             // true
```

## NaN как правильный сигнал «нет числа»

- Если функция должна вернуть число, но валидного числа нет, единственное осмысленное значение для сигнала — NaN (не `undefined`, `null`, `false` или `-1`).
- Историческое `-1` (например, в `indexOf`) — наследие C, где возвращались только не-IEEE числа; в JavaScript более уместен был бы NaN.

## Главное

- NaN — это «invalid number», его тип — `number` (по IEEE 754).
- NaN распространяется: любая математическая операция с NaN даёт NaN.
- NaN — единственное значение, не равное самому себе; `===` для NaN бесполезен.
- Для проверки используйте `Number.isNaN` (без coercion), а не устаревшую `isNaN`.
