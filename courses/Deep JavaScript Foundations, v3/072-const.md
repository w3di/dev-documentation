# const

## Позиция: const не «несёт свой вес»

- Распространённое мнение: следует использовать только `const` везде, где возможно, и даже не использовать `let`.
- Контраргумент: `const` **не carries its own weight** (выгода не оправдывает издержки).
- Выгода от `const` меньше, чем принято считать, а издержки (путаница) — больше.
- Поэтому `const` используется крайне избирательно, а не как замена всех объявлений.

## Главная издержка: путаница вокруг const

- Проблема не уникальна для JavaScript: добавление `const` путало программистов во всех языках (тысячи вопросов на Stack Overflow).
- Причина: «constant» интуитивно понимается как «то, что не меняется».
- На деле дизайнер языка имеет в виду **переменную, которую нельзя переприсвоить (reassign)** — это другое.

```js
const myTeacher = "Kyle";
myTeacher = "Suzy";        // ошибка: переприсваивание запрещено

const teachers = ["Kyle", "Suzy"];
teachers.push("Frank");     // ОК: мутация значения разрешена
```

- **Важно:** `const` запрещает переприсваивание переменной, но не мутацию значения. Массив/объект под `const` остаётся мутируемым.
- Читатель легко решит, что массив под `const` «не изменится», и запутается при его мутации.
- Java из-за этой путаницы убрала `const` и ввела `final`.

## Слабость семантической пользы

- `const` следует использовать в маленьких блоках; семантически он обещает «на остаток этого блока переменная не будет переприсвоена».
- Переприсваивание редко является источником багов.
- В маленьком блоке (3–5 строк) `const` в лучшем случае гарантирует отсутствие переприсваивания на следующие несколько строк — где его и так почти негде сделать из-за lexical scoping.
- `const` «делает вид», что решает большую проблему, но решает немногое — как ночник в детской: успокаивает, хотя монстров и так нет.

## Когда использовать const

- Только для значений, которые уже примитивны и потому immutable: **strings, numbers, booleans**.
- Как семантический placeholder для литералов: вместо «магического» `13` — именованная `const`.
- Хороший пример (из Q&A) — API URL: он не меняется в run time, объявляется один раз как `const customerApiUrl` и даёт смысловое имя строковому литералу.

## const и Object.freeze (из Q&A)

- `Object.freeze` — поверхностная (shallow) read-only блокировка свойств массива/объекта; делает значение «как бы» immutable (не глубоко).
- Не следует писать `const x = Object.freeze(...)`: это создаёт ложное впечатление, будто `const` связан с заморозкой. `const` оставляют только для примитивов.

## Итоговая рекомендация автора

- По умолчанию использовать `var`.
- `let` — там, где это помогает (естественная блочность).
- `const` — экономно, только с immutable примитивами.

## Главное

- `const` запрещает переприсваивание, но не мутацию значения — главный источник путаницы.
- Семантическая польза мала: в маленьком блоке он гарантирует немногое.
- Использовать `const` только для примитивов (string/number/boolean) как именованные placeholder'ы.
