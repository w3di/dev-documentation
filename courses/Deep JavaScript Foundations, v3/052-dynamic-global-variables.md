# Dynamic Global Variables (auto globals)

## Разбор строки с необъявленной переменной

- Продолжение примера: строка 5 — `topic = "React"` внутри `otherClass`, без `var`.
- Выполнение: target reference на `topic`.
  1. Спрашиваем scope `otherClass` (синий): «есть `topic`?» → нет.
  2. Поднимаемся в глобальный scope: «есть `topic`?» → нет.
- Логично было бы получить ошибку. Но в non-strict mode срабатывает историческая «плохая часть» JS.

## Auto global (автоглобал)

- **auto global** — если присваивать значение необъявленной переменной, и поиск дошёл до глобального scope, глобальный scope сам создаёт эту переменную.
- Вместо ошибки глобальный scope «любезно» создаёт **красный шарик** `topic` и возвращает его.
- Почему красный, а не синий: мы уже прошли мимо scope, где она могла бы быть объявлена, и обращаемся именно к глобальному scope — он и создаёт переменную.
- После строки 5 существует глобальная переменная `topic` со значением `"React"`.

## Отличие от обычного объявления

- Объявление на компиляции и динамическое создание в runtime — не одно и то же: есть разница в производительности и др.
- Но механически после создания это две одинаковые глобальные переменные.

## Важное предупреждение

- **Никогда** не создавайте глобалы автоматически таким способом.
- Всегда объявляйте переменные явно в нужном scope.
- Любое присваивание к переменной, необъявленной в доступных scope, создаёт auto global.

## Связь со strict mode

- Это поведение возможно только потому, что код работает в **non-strict mode** (иногда «sloppy mode»).
- В strict mode такого не происходит — следует использовать strict mode.

## Выполнение остатка примера

- Строка 11: source `teacher` → глобальный scope → значение `"Suzy"` (перезаписано на строке 4, это тот же шарик, не отдельная переменная).
- Строка 12: source `topic` → глобальный scope → значение `"React"` (существует, потому что `otherClass` создал его как auto global).

## Главное

- В non-strict mode присваивание необъявленной переменной создаёт переменную в глобальном scope (auto global) вместо ошибки.
- Это историческая ошибка дизайна JS; auto global всегда красный (глобальный), независимо от того, где было присваивание.
- Всегда объявляйте переменные явно; никогда не полагайтесь на auto globals.
