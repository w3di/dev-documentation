# Nested Scope (вложенные scope)

## Идея вложенности

- Scope могут быть вложены друг в друга: «ведро внутри ведра внутри ведра» — на любую глубину.

## Пример

```js
var teacher = "Kyle";              // 1

function otherClass() {            // 3 (blue)
    var topic = "Closure";         // 4 (blue marble)
    function ask(question) {       // 6 (blue marble; green scope)
        console.log(teacher, question);  // 7
    }
    ask("Why?");                   // 10
}

otherClass();                      // 13
ask("Still there?");               // 14
```

## Разбор шариков

1. Строка 1: `teacher` → красный шарик.
2. Строка 3: `otherClass` → красный шарик + синий scope.
3. Строка 4: `topic` → синий шарик (внутри синего scope).
4. Строка 6: `ask` → синий шарик (объявление функции создаёт идентификатор в **enclosing scope** — здесь это scope `otherClass`). Сама функция `ask` создаёт зелёный scope.
   - Важно: имя функции попадает в окружающий (enclosing) scope, а не в свой собственный.
5. Параметр `question` → зелёный шарик. Параметр формально создаёт идентификатор в scope функции, хотя `var` нет.

## Разрешение ссылок (строка 7)

- `teacher` на строке 7: в зелёном scope (`ask`) нет → поднимаемся → находим в синем scope → **синий шарик**.
- `question` на строке 7: → зелёный шарик (параметр `ask`).
- Поиск идёт по уровням вверх; можно подниматься сколь угодно глубоко (хоть 50 уровней).

## Значение question

- Строка 10: `ask("Why?")` — литерал `"Why?"` присваивается параметру `question` перед выполнением тела `ask`.
- Поэтому при чтении `question` на строке 7 значение — строка `"Why?"`.

## Строка 14: ReferenceError

- `ask("Still there?")` в глобальном scope: source reference на `ask` → глобальный scope «не слышал» → **ReferenceError**.
- Хотя `ask` существует в программе, он недоступен ни в одном scope, к которому есть доступ → это **undeclared** переменная.
- Отличие от auto globals: auto global возникает только при **target** (присваивании) необъявленной переменной в non-strict mode. **Source**-ссылка на необъявленную переменную ВСЕГДА даёт ReferenceError.
- Поэтому различие target/source критично (по крайней мере в non-strict mode; в strict обе ведут себя одинаково).

## Главное

- Имя функции создаётся в окружающем (enclosing) scope, а не внутри самой функции; параметры создают идентификаторы в scope функции.
- Разрешение ссылки идёт от текущего scope вверх по уровням до глобального.
- Source-ссылка на необъявленную переменную всегда даёт ReferenceError; auto global появляется только при target-ссылке в non-strict mode.
