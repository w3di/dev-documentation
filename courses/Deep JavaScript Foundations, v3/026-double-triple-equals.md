# `==` vs `===`: реальная разница

## Распространённый миф

- Общепринято: `==` проверяет только значение (**loose equality**), а `===` — значение **и** тип (**strict equality**).
- Это звучит хорошо, но **неверно**. И это не академическая придирка — неправильная модель приводит к ошибочным выводам.

## Что говорит спецификация

- Алгоритм `==` называется **Abstract Equality Comparison**.
- В самом начале алгоритма проверяются **типы** `x` и `y`.
- Значит, миф развенчан: `==` тоже проверяет типы. Оба оператора проверяют типы — но делают с этим разное.
- Источник истины — всегда спецификация; это алгоритм с `if`/`then`, переменными и операциями, понятный разработчику. Большинство JS-разработчиков никогда его не читали.

## Когда типы совпадают

- Если типы операндов **совпадают**, `==` и `===` ведут себя **абсолютно одинаково** — выполняется `===`.

```js
var x = "Frank";
var y = "Frank";
x == y    // true
x === y   // true  (типы совпали → делается тройное сравнение)
```

- Старайтесь, чтобы типы были очевидны и по возможности совпадали. Не делайте equality-сравнений, не зная типов.

## Что делает `===`

- `===` тоже проверяет типы: если типы **разные** → сразу `false`, ничего больше не проверяя (short-circuit).
- Если типы совпадают, `===` всё же «лжёт» в двух случаях:
  - `NaN` → `false` (NaN не равен сам себе);
  - `-0` → ведёт себя как равный `0` (`true`).
- Эти «лжи» происходят только при совпадающих типах.

## Реальная разница

- Настоящее отличие — **разрешать ли coercion**:
  - `===` — coercion **запрещён** (при разных типах сразу `false`).
  - `==` — coercion **разрешён**, когда типы разные.
- Иначе говоря: оба проверяют типы, но один (`===`) останавливается рано, а другой (`==`) — нет.

## Объекты: identity comparison

- Встроенное равенство JS — **не** структурное (не делает deep-проверку структуры), а **identity comparison** (сравнение ссылок).

```js
var workshop1 = { topic: null };
var workshop2 = { topic: null };
workshop1 == workshop2    // false
workshop1 === workshop2   // false  (разные объекты, разные ссылки)
```

- Два объекта с одинаковой структурой — всё равно разные объекты. `==` и `===` дадут одинаковый результат: `false`. `true` был бы только при одной и той же ссылке.

## Главное

- Миф «`==` сравнивает значение, `===` — значение и тип» неверен: оба проверяют типы.
- При совпадении типов `==` и `===` идентичны (выполняется `===`).
- Реальная разница: разрешён ли coercion. `===` запрещает (разные типы → `false`), `==` разрешает при разных типах.
- Равенство объектов — это identity (сравнение ссылок), не структурное сравнение.
