# Code Execution: завершение разбора выполнения

## Продолжение выполнения примера

1. Строка 14 (`ask()`): source reference на `ask`. Спрашиваем глобальный (красный) scope → да → красный шарик содержит функцию (зелёный scope), объявленную на строке 8. Скобки `()` вызывают функцию → переход в строку 9.
2. Строка 9: target reference на `question` в зелёном scope → да → берём зелёный шарик, присваиваем строку, не интересуясь прежним значением.
3. Строка 10: `console` — source, в зелёном scope нет → поднимаемся в глобальный, находим, у объекта есть метод `log`.
   - Перед вызовом `log` нужно вычислить аргумент: `question` в source-позиции → зелёный шарик → значение `"Why?"`.

## Аргументы и параметры

- Аргументы (то, что передаём) присваиваются параметрам (которые принимают).
- **parameter** (параметр) находится в позиции **target** (получает присваивание) — это как имя переменной, которой присваивают.
- Переменная в позиции аргумента (как `question` в `console.log(question)`) — это **source**.

## Итог по двум стадиям

- Стадия 1: определяем все scope, вёдра и шарики (компиляция).
- Стадия 2: используем эту информацию для выполнения кода.

## Главное

- Выполнение = повторяющийся lookup: для каждой ссылки определяем target/source и ищем шарик в текущем scope, поднимаясь вверх при необходимости.
- Аргументы присваиваются параметрам: аргумент — source, параметр — target.
- Вся работа движка делится на две стадии: разбор scope (компиляция) и выполнение по готовому плану.
