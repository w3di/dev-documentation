# Понимание своего кода через спецификацию

## Как читать спецификацию

- Спецификация описывает поведение в виде пронумерованного **алгоритмического формата** (по шагам).
- Разработчики ежедневно читают и пишут алгоритмы, поэтому такой формат доступен, хотя чтение спецификации требует усилий.
- Чтобы предсказывать поведение оператора (например, `++`) и избегать ошибок, нужно понять его алгоритм — другого надёжного способа нет.
- Весь курс по сути учит понимать алгоритмы — «ДНК JavaScript».

## Алгоритм postfix `++` из спецификации

- Берётся старое значение и над ним выполняется операция **ToNumber** (приведение к числу) — это **abstract operation** (абстрактная операция), которую спецификация описывает отдельно.
- Затем значение увеличивается на единицу, но возвращается исходное (уже приведённое к числу) значение.

Эквивалент на JavaScript:

```
function postIncrement(x) {
  x = Number(x);   // coercion к числу
  // сохранить x, обновить переменную на x + 1, вернуть исходный x
  return x;
}
```

## Где искать истину

- MDN не всегда корректна (в ней регулярно исправляют ошибки).
- Если наблюдаемое поведение не совпадает с прочитанным, единственный авторитетный источник — спецификация.

## Профессионализм против «угадывания»

- Многие разработчики фактически «профессиональные угадыватели»: код работает, но почему — неясно, он просто соответствует искусственно построенной ментальной модели.
- Аналогия: архитектор не говорит «надеюсь, стены устоят» — он знает, что делает. Так же и разработчик должен понимать свой код.

## Getify's Law #17

- **Getify's Law #17**: когда возникает расхождение между мозгом и компьютером — там в код входит баг.
- Большинство багов появляется именно из-за неверной ментальной модели, а не только из-за опечаток.

## Главное

- Спецификация написана как пошаговый алгоритм и доступна разработчикам при должном усилии.
- `++` в postfix сначала приводит значение через ToNumber, затем инкрементирует, возвращая приведённое исходное значение.
- Спецификация — главный источник истины, MDN и движок таковыми не являются.
- Баги входят в код там, где мысленная модель расходится с фактическим поведением (Getify's Law #17).
