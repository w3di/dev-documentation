# Dynamic scope

## Как работал бы dynamic scope

- В JavaScript dynamic scope отсутствует — рассмотрение чисто теоретическое.
- Если функция `ask` ссылается на переменную `teacher`, которой нет в её собственном scope:
  - при lexical scope она разрешалась бы по вложенности scope;
  - при dynamic scope язык не консультируется с лексической вложенностью, а спрашивает: **откуда была вызвана функция**.
- Переменная разрешается в scope места вызова (call site), а не места определения.

## Свойства dynamic scope

- Ссылки функции на переменные зависят от того, откуда она вызвана.
- Одна и та же функция, вызванная из 100 разных мест, может дать 100 разных результатов.
- Это даёт гибкость и переиспользование: одна функция работает в разных контекстах.
- Dynamic scope не «плохой» и не «странный» — просто непривычная модель; для тех, кто знает только её, lexical scope выглядел бы так же странно.

## Сопоставление

- Dynamic scope определяется условиями run time.
- Lexical scope определяется на author time.
- Ключевая пара противопоставлений: **fixed/predictable** (lexical) против **dynamic/flexible** (dynamic).
- В JavaScript нет dynamic scope, но есть механизм, дающий похожую гибкость (рассматривается позже — связан с `this`).

## Главное

- При dynamic scope переменные разрешаются по месту вызова функции, а не по месту её определения.
- Это даёт гибкость ценой предсказуемости; lexical scope — наоборот.
- В JavaScript dynamic scope нет, но аналогичную гибкость даёт механизм `this`.
