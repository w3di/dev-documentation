# Intentional coercion: осознанное приведение типов

## Нельзя избегать механизм из-за пары corner cases

- Corner cases — реальность, но решение не в том, чтобы отказаться от всего механизма coercion.
- Правильный подход: принять стиль кодирования, который делает типы и значения **явными и очевидными**.

## Стиль кода важнее, чем тип-система

- Можно использовать целые type-системы (например, **TypeScript**), но это не обязательно.
- Достаточно стиля кода, в котором типы операндов очевидны.
- Качественная JS-программа **обязана** обнимать coercion: типы в каждой операции должны быть понятны.

## Не злоупотребляйте полиморфизмом

- Не проектируйте polymorphic-функции, принимающие любой тип и делающие 15 разных вещей в зависимости от значения.
- Это порождает coercion-проблемы, которые потом «заклеивают» через `===`.
- Лучше: отдельная функция для чисел, отдельная для строк — или функция, явно принимающая только числа и строки (тогда известен ограниченный набор corner cases).

## Главный посыл

- Типы — это факт вашей программы; в вашей власти решать, насколько эти факты на вас влияют.
- Решение проблемы — **не** обязательно полная статическая типизация (Java/C++). Жёсткая типизация — лишь одна из реакций, и не необходимая.
- Систему типов JS можно изучить, использовать к месту и делать очевидной в коде.

## Type-система — сильная сторона JS

- Система типов JS — не слабость, а одно из сильнейших качеств, «unsung hero».
- Во многом благодаря ей JS стал первым по-настоящему **multi-paradigm** языком и таким повсеместным: он «съедобен» для множества разных задач.

## Главное

- Не избегайте coercion целиком — примите стиль, делающий типы очевидными.
- Сужайте полиморфизм функций, чтобы заранее знать набор возможных corner cases.
- Статическая типизация — не единственный и не обязательный ответ; систему типов JS стоит изучить и использовать осознанно.
