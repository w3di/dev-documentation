# Compilation and Scope: разбор вопросов

## Что выдаёт компилятор

- Компилятор создаёт **plan / roadmap** (план, «карту») для каждого scope: для синего ведра нужно создать идентификатор `teacher` и т.д.
- Выход компилятора — это план scope, «to-do список» для каждой области видимости. Это и есть исполняемый код.
- Реальной зарезервированной памяти компилятор НЕ создаёт — только план того, как зарезервировать память и создать шарики.

## Когда используется target/source

- Позиция target/source определяется на этапе компиляции, но используется только в runtime.
- Когда функция (например, `otherClass`) извлекается из переменной и вызывается, движок по плану создаёт всё синее ведро со всеми шариками, входит в него и выполняет.

## Пересоздание окружения при каждом вызове

- При каждом вызове функции окружение (environment) создаётся заново, «с нуля».
- Компилятор лишь хранит план: «вот так должно выглядеть зелёное ведро и его содержимое», но оно ещё не существует.
- При каждом выполнении функции план реализуется в памяти; по завершении всё содержимое уничтожается; при следующем вызове создаётся заново из того же плана.

## Метафора

- Выход компилятора — как **treasure map** (карта сокровищ) или плейсхолдер: план есть, но реальные сущности появляются только при выполнении.

## Главное

- Компилятор выдаёт лишь план (карту) scope, а не реальную память.
- Позиции target/source определяются при компиляции, применяются при выполнении.
- При каждом вызове функции её окружение создаётся из плана заново и уничтожается по завершении.
