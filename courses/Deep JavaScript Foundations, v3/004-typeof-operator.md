# Оператор typeof

## Назначение

- **typeof** — первый способ узнать «тип»/природу значения.
- Важно: запрос про тип *значения, находящегося в переменной сейчас*, а не про тип самой переменной.

```
var v;
typeof v;        // "undefined"
v = "1";  typeof v;  // "string"
v = 1;    typeof v;  // "number"
```

## typeof всегда возвращает строку

- Оператор **всегда** возвращает строку — это критично (важно для понимания coercion далее).
- Возвращаемые значения — короткий фиксированный список строк; среди них нет пустой строки и нет нестроковых значений вроде `null`/`undefined`.
- Частая ошибка в блогах: сравнение `typeof x == undefined` без кавычек — бессмысленно, так как typeof не может вернуть значение `undefined`, только строку `"undefined"`.

## undefined как значение

- **undefined** — значение по умолчанию: то, что есть, когда нет никакого другого значения.
- Тип `undefined` содержит ровно одно значение — `undefined`.
- Корректная трактовка: «значение в данный момент отсутствует», а не «значения ещё нет». Переменная может иметь значение, затем снова стать `undefined` — это не удаляет её.

## Особые случаи возврата typeof

- `typeof null` возвращает `"object"` — исторический **баг** (должно было быть `"null"`).
  - Историческая причина: в ES1 рекомендовалось сбрасывать обычные значения через `undefined`, а ссылки на объекты — через `null`.
  - Практическое следствие: при проверке `typeof x === "object"` нужно отдельно убедиться, что это не `null`.
- `typeof` для функции возвращает `"function"`, хотя function — не самостоятельный тип верхнего уровня (это удобное исключение).
- `typeof` для массива возвращает `"object"` (array — подтип объекта).

## Уточнение подтипов

- Эти исторические особенности нельзя исправить, не сломав существующий код — их нужно выучить и обходить.
- Для надёжной проверки массива есть **Array.isArray** — даёт точный ответ, массив это или нет.

## Главное

- typeof всегда возвращает строку из небольшого фиксированного списка — это делает результат предсказуемым.
- `typeof null === "object"` — исторический баг; при проверке объекта надо исключать null.
- `function` имеет свой результат `"function"`, а `array` отдаёт `"object"`.
- Для уточнения подтипов используются помощники вроде `Array.isArray`.
