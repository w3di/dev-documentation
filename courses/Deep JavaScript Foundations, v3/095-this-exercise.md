# Упражнение: this

## Суть задания

- Рефакторинг кода с **module pattern** на **namespace pattern**: методы лежат на объекте и обращаются к данным объекта через `this`.
- В файле `ex.js` есть фабричная функция `defineWorkshop()`, возвращающая объект `publicAPI` с внутренними данными (`currentEnrollment`, `studentRecords`).

## Что нужно сделать

1. Превратить `deepJS` из определения через функцию в **объектный литерал** со свойствами, ссылающимися на `currentEnrollment` и `studentRecords`.
2. Сделать все функции **публичными методами** этого объекта; ссылки на данные — через `this.`.
3. Убрать фабрику `defineWorkshop()`, заменив её объектом.

## Предупреждение про this binding

- В коде есть места, где передаются callback (например, в `.map`).
- При обычной лексической функции (как в module pattern) проблем с `this` нет.
- При переходе на методы с `this` возникает проблема привязки `this` в callback.
- Нужно использовать **hard-bound** ссылки (`.bind`) там, где это необходимо — но **не на всех** вызовах, а только где нужно.

> Решение — в файле `ex.fixed`.

## Главное

- Перевести module pattern в namespace pattern: данные на объекте, доступ через `this`.
- Применять `.bind` точечно — только для callback, теряющих привязку `this`, а не везде.
