# ES6 modules и Node.js

## История и проблема совместимости

- Раз module — важный паттерн, понадобилась первоклассная синтаксическая поддержка → в ES6 добавили **ES6 modules**.
- **Проблема процесса:** TC39 и Node.js не согласовали планы. Спецификация ES6 modules оказалась несовместима с Node.js, что выяснилось лишь спустя ~1,5 года.
- Несколько лет шли сложные обсуждения и компромиссы, т.к. **NPM** (крупнейший репозиторий кода) был несовместим со спецификацией.
- Один из спорных компромиссов: для использования ES6 modules в Node наряду с CommonJS нужно **другое расширение файла — `.mjs` вместо `.js`**.
- Поддержку вводят фазами; первая стабильная фаза ожидалась около Q1 2020 — спустя ~5 лет после выхода спецификации.

**Суть несовместимости:** Node хочет сохранить возможность старого `require` нового ES6-модуля и `import` старого CommonJS-модуля. По отдельности это терпимо, но при **циклических зависимостях** (один `require`-ит, другой `import`-ит) возникают тяжёлые corner cases, критичные для большой экосистемы Node.

## Формат ES6 module

- Открываете файл и просто пишете переменные и функции.
- Поскольку файл загружается как module, **по умолчанию всё private** — синтаксическая обёртка не нужна. Концептуально файл как бы обёрнут в функцию с приватным scope.
- Публичным делает ключевое слово **`export`**: что экспортировано — public, что нет — private.

```js
var teacher = "Kyle";
export function ask(question) {
    console.log(teacher, question);
}
```

## Ключевые свойства ES6 modules

1. **File-based:** один файл = один module. **Нельзя** держать более одного ES6 module в одном файле.
   - Приложение из 1000 модулей = 1000 отдельных файлов.
   - Без build-процесса в браузер пришлось бы грузить 1000 файлов (проблемы с производительностью).
   - На практике авторят в ES6 modules, затем компилируют в старый стиль и конкатенируют в один файл (bundle).
2. **Singletons:** сколько бы раз module ни импортировали, он выполняется **только один раз**; последующие импорты дают ссылку на тот же instance.
   - Чтобы создавать несколько instances, нужно экспортировать **factory function**.

## Главное

- ES6 modules долго имели проблемы совместимости с Node.js (отсюда расширение `.mjs`).
- В module-файле всё private по умолчанию; публичность задаётся через `export`.
- ES6 modules — **file-based** (один файл = один module) и **singletons** (выполняются один раз).
