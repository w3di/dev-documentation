# Явные let-блоки

## Сужение scope переменной

- Если переменная нужна лишь на несколько строк, её не следует помещать на верхний уровень scope функции.
- Вместо этого создают отдельный scope — открывают пару фигурных скобок именно для этих строк, и переменные не существуют в остальной части функции.
- Приём применим где угодно, в том числе внутри `if`.
- Это не нововведение: в других языках с block scoping так делают уже 30 лет — открывают `{}` и привязывают переменную к блоку.

```js
{
  let prefix, rest;
  // несколько строк, использующих prefix и rest
}
```

## Производительность

- Наблюдаемой разницы в производительности почти наверняка не будет.
- Теоретически возможны микроэффекты: garbage collector мог бы освободить переменную чуть раньше; уменьшается то, что доступно для closure.
- На практике эти различия не заметны — аргумент чисто о ясности кода.

## Стиль оформления

- Объявления (`let`) ставят на той же строке, что и открывающая скобка блока, чтобы сразу было ясно: переменные созданы для этого блока и существуют только ради него.
- Это избавляет читателя от поиска объявлений по всему scope.

## Рекомендация

- Чаще использовать явные let-блоки, максимально сужая scope переменных там, где это практично.

## Главное

- Переменную «на пару строк» оборачивают в отдельный блок `{}` с `let`, а не выносят на верх функции.
- Объявления пишут на одной строке с открывающей скобкой для наглядности.
- Выгода — ясность кода, а не производительность.
