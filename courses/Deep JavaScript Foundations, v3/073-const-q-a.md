# const: вопросы и ответы

## const только для строк и примитивов

- `const` используется только для примитивных immutable-значений: strings, numbers, booleans.
- И даже тогда — лишь когда значение служит семантическим placeholder вместо литерала, вставляемого в одном или нескольких местах.
- Не стоит оборачивать в `const` каждую строку ради самого факта использования `const`.
- Хороший пример — API URL: он почти наверняка не меняется в run time. Объявляется один раз в начале scope как `const customerApiUrl` и придаёт смысл строковому литералу.

## const и freeze для массивов/объектов

- Для массивов и объектов применяют `Object.freeze` — поверхностную (shallow) read-only блокировку всех свойств.
- Это делает значение «как бы» immutable, но не по-настоящему, поскольку заморозка не глубокая (не deep).
- Тем не менее не пишут `const x = Object.freeze(...)`: это создаёт у читателя ложное впечатление, будто `const` связан с заморозкой, а это не так.
- `const` оставляют исключительно для примитивных immutable-значений.

## Главное

- `const` — только для примитивов и только как семантический placeholder литерала (например, API URL).
- Для иммутабельности массивов/объектов используют `Object.freeze` (shallow), но не совмещают его с `const`.
