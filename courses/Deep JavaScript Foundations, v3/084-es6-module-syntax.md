# Синтаксис import в ES6 modules

Два основных стиля импорта (с вариациями).

## Named import

```js
import { ask } from "workshop.mjs";
// или для default:
import ask from "workshop.mjs";
```

- **Named import** импортирует **идентификаторы** прямо в текущий scope.
- В scope, где произошёл import, появляется идентификатор (`ask`), связанный с соответствующей функцией модуля.
- Это «Java-стиль» импорта: import буквально вносит идентификаторы в scope.
- Если экспортирован default, снаружи его имя — `default`, но при импорте ему можно дать своё имя.
- Представляет «новую школу» мышления о модулях.

## Namespace import

```js
import * as workshop from "workshop.mjs";
workshop.ask("...");
```

- **Namespace import** собирает всё содержимое модуля на один namespaced-объект (здесь `workshop`).
- Школа мышления: модули — это namespace-сущности.
- Этот стиль отражает то, как модули делались в JavaScript последние ~20 лет; автор предпочитает его.
- Namespace import добавили в спецификацию в последний момент.

Ни один из стилей не «правильнее» — это разные способы потребления модуля.

## Авторский подход автора

- Автор предпочитает писать модули в старом стиле — **revealing module pattern** (функция-обёртка), а не ES6-синтаксис, пока ситуация с Node не устаканится.
- Конкретно экспортирует модули как **UMD** (Universal Module Definition) — формат для взаимодействия между браузерами, module loaders и Node.

## Общий вывод о модулях

- Независимо от способа (синтаксис ES6 или старый revealing module pattern) применяется **один и тот же концепт**: организовать поведение в cohesive unit, спрятать данные, открыть минимально необходимый API.
- Внутри module можно использовать что угодно (хоть классы) — снаружи это всё равно module, который импортируют и используют.
- Module pattern останется надолго.
- Lexical scope — главный из трёх pillars языка: он фундаментально затрагивает всё остальное.

## Главное

- **Named import** вносит идентификаторы в scope; **namespace import** (`import * as`) собирает весь модуль на один объект.
- Оба стиля валидны — разница в мышлении (новая школа vs namespace-подход).
- Независимо от синтаксиса концепт module един: cohesive unit + сокрытие данных + минимальный API.
