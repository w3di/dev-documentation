# This и Prototypes: вопросы и ответы

## Можно ли перепривязать функцию, уже привязанную через bind

- Функция, к которой применили **bind**, становится *hard-bound* (жёстко привязанной) — её контекст `this` зафиксирован.
- Повторный вызов `.bind` на ней не переопределяет привязку.
- Единственный способ переопределить — вызов через ключевое слово **new**: это создаст новый объект и заменит `this` на него.
- Иначе перепривязать к другому объекту нельзя.

## Область видимости переменных внутри arrow function

- **Arrow functions** имеют полноценную лексическую (lexical) область видимости — как любые другие функции.
- Утверждение «у стрелочных функций нет scope» неверно: scope у них есть.
- Переменная, объявленная внутри стрелочной функции, ведёт себя как в обычной функции.
- Единственное отличие: обычные функции определяют собственный `this`, а стрелочные — нет.

## Зависит ли this в callback от того, как его вызывает higher-order function

- Значение `this` определяет только **call-site** (место вызова).
- Если передать функцию в `.map`, то именно способ её вызова внутри `.map` задаёт привязку `this`.
- Исключение — *hard-bound* функция: её жёсткая привязка имеет приоритет.
- Внутри `.map` вызов вида `cb()` не привязывает `this` к объекту.
- Поэтому все higher-order методы (`map`, `filter` и т.д.) полностью управляют контекстом `this` через способ вызова callback.

## Что происходит при установке `__proto__`

- `__proto__` (dunder proto) — технически и getter, и setter, но почти всегда используется только для чтения.
- Переписывать prototype chain объекта — в целом **anti-pattern**.
- С ES6 `__proto__` официально может выступать сеттером: перенаправлять prototype-связь объекта на другой объект.
- Альтернативный API: `Object.setPrototypeOf` — позволяет «перепаять» прототип любого объекта.
- На практике перепривязка prototype chain встречается крайне редко (~0.001% случаев), но в отдельных ситуациях может быть мощной и полезной.

## Есть ли у каждой функции объект prototype

- На диаграмме: функция — круг, её `.prototype` — квадрат.
- Обычные функции (declaration, expression, anonymous, named) **всегда** имеют `.prototype`.
- **Arrow functions** не имеют `.prototype`.
- Поэтому вызов `new` на стрелочной функции падает: она не constructor и не может быть сконструирована через `new`.

## Можно ли использовать super вне классов

- Ключевое слово **super** работает вне классов — при работе с объектами и их методами.
- Можно связать объекты через prototype-линковку и применять `super` внутри метода для обращения вверх по prototype chain.
- Важный нюанс: `super` привязывается **статически**, а не динамически.
- Чтобы его использовать, нужно создать object literal с методом, и в момент создания этот объект должен быть уже связан с целевым.
- Нельзя взять объект, поменять его прототип и ожидать, что `super` начнёт ссылаться на новый — привязка фиксируется при создании.
- `super` доступен в object literals только в форме **concise method** (краткой записи метода).

## Главное

- `this` в callback и методах определяется call-site; hard-bound функцию можно переопределить только через `new`.
- Arrow functions имеют lexical scope, но не имеют ни своего `this`, ни `.prototype` (нельзя вызвать `new`).
- `__proto__` (setter) и `Object.setPrototypeOf` позволяют менять prototype chain, но это anti-pattern.
- `super` вне классов привязывается статически и работает только в concise methods object literal.
