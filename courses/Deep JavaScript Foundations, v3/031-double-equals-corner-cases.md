# Corner Cases `==`: массив против собственного отрицания

## Знаменитый пример из «WAT»

- Пример: пустой массив оказывается **coercively equal** своему отрицанию.
- Конструкция вида `arr == !arr` подаётся как аргумент против JavaScript и против `==`.
- Это **ложная (искусственная) конструкция**: в реальном коде никто никогда не сравнивает значение с его собственным отрицанием.
- Найден сценарий, который не встречается в реальном коде, и на его основе объявлен «сломанным» весь механизм — это не рациональный аргумент.

## Разбор алгоритма для `arr == !arr`

Пусть есть массивы `workshop1Students` и `workshop2Students`. Сравнение `workshop1Students == !workshop2Students`:

1. `workshop2Students` — массив, он **truthy**, значит `!workshop2Students` → `false`.
2. Получаем сравнение: non-primitive (массив) vs primitive (`false`).
3. Массив приводится к примитиву (**ToPrimitive**) → пустая строка `""`.
4. Теперь `"" == false`: два примитива, но разных типов.
5. Алгоритм предпочитает number: `""` → `0`, `false` → `0`.
6. `0 == 0` → `true`.

- Алгоритм применён корректно; абсурден лишь сам входной случай, который в коде не возникает.

## Корректная альтернатива: `!=`

- Осмысленный код — это `workshop1Students != workshop2Students` (строка 8), а не `workshop1Students == !workshop2Students` (строка 4).
- `!=` — это отрицание coercive-равенства, а не сравнение с отрицанием значения. Это **совершенно разные вещи**.
- Поскольку оба операнда — массивы, `!=` фактически задаёт **identity-вопрос**: «это разные ссылки на массив?». Это валидная операция.
- В этом рациональном случае `==`/`!=` ведут себя **идентично** `===`/`!==` — разницы нет.

## Главное

- `arr == !arr` — искусственный пример, не встречающийся в реальном коде; алгоритм при нём работает по обычным правилам (ToPrimitive → `""`, prefer-number → `0`).
- Осмысленное сравнение массивов — `!=`/`==` как **identity-проверка**, и здесь нет разницы между double и triple equals.
