# Выбор между let и var

## Семантический аргумент за var

- Для переменной на уровне всего scope функции правильный сигнал читателю — `var`, а не `let` на верхнем уровне функции.
- `let` сигнализирует очень локальное использование переменной (в идеале на пару строк).
- Использование `let` на верхнем уровне функции убирает важную семантическую информацию о намерении (использовать переменную локально или повсюду).
- Аналогия: мало взять правильный инструмент (молоток для гвоздя) — нужно использовать его правильно. `let` для функционального scope «работает», но используется неверно.
- Естественно, что часть переменных не block-scoped: язык, разрешающий доступ к параметрам только на первой строке функции, был бы неудобен.

## Поведенческие причины использовать var

### Побег из непреднамеренного блока

- `let`/`const` block-scope себя внутри `try/catch`, хотя `try/catch` воспринимается как способ ловить исключения, а не как scope.
- Глобальная замена `var` → `let` сломала бы код, где переменная объявлена внутри `try` и используется после него.
- `var` цепляется к функциональному scope (благодаря hoisting) и «выбирается» из непреднамеренного блока.
- Альтернатива — объявить `var` снаружи `try` и присваивать в двух местах — хуже: чем дальше объявление от присваивания, тем сложнее понимать код.

### Повторное объявление в одном scope

- `var` можно использовать несколько раз в одном scope без ошибок; `let` — нельзя.
- Полезно для дизамбигуации: повторный `var id` в обеих ветках сигнализирует «в этом scope точно будет `id` со значением».
- В длинных функциях (100–200 строк) повторное объявление `var` рядом с дальним использованием показывает читателю, какому scope принадлежит переменная, без прокрутки вверх.
- **Важно:** повторный `var` не создаёт новую ячейку памяти — это один marble. На этапе компиляции второй `var` для уже известного имени становится no-op.

## ESLint

- Правило ESLint, запрещающее `var` (или требующее `let`), автор отключает.
- Инструмент, навязывающий своё мнение без возможности настройки, мешает коммуницировать намерение.

## Итоговая позиция

- `let` ≠ замена `var`; это `let` + `var`. В истории CS «x — это новый y» почти никогда не верно: новое дополняет, а не вытесняет старое.

## Главное

- `var` на уровне функции семантически сигнализирует «переменная для всего scope»; `let` — «локально на пару строк».
- `var` полезен поведенчески: выбирается из непреднамеренных блоков (`try/catch`) и допускает повторное объявление в одном scope.
- `let` и `var` сосуществуют; повторный `var` — это одна ячейка памяти (no-op при компиляции).
