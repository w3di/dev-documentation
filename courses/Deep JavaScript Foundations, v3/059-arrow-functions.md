# Arrow Functions

## Позиция автора

- **arrow functions** (стрелочные функции) появились в ES6.
- Главный аргумент против: arrow functions **анонимны**.
- Если не следует использовать анонимные function expressions, то логически не следует и arrow functions.
- Не стоит использовать arrow functions как универсальную замену всем функциям — только ради короткого синтаксиса.

## Про синтаксис

- Короткий синтаксис создавался не ради краткости — это лишь одна из характеристик, возможно даже не главная.
- Чем короче синтаксис, тем сложнее краевые случаи: у arrow function около 15 вариаций синтаксиса.

## Читаемость и назначение

```js
people.map(person => person.id);              // 1  анонимная стрелочная
const getId = person => person.id;            // 2  выведенное имя getId
people.map(getId);
function getId(person) { return person.id; }  // declaration: имя + меньше символов
```

- Чтобы понять, что делает arrow function (строка 1), нужно прочитать тело функции.
- Имя функции (например, `getPersonId`, `getDefaultPersonId`) сразу сообщает назначение без чтения кода.
- Даже если назначение «самоочевидно» — это всё равно вывод (inference) из кода, а не явно указанное назначение.

## Сравнение по длине

- Стрелочную функцию можно присвоить переменной (`getId`) и получить выведенное имя — но function declaration выходит даже короче по количеству символов.
- С `const` стрелочный вариант на пару символов длиннее declaration.
- Аргумент «более краткий код» не равен «более читаемый код».

## Promise chains

- При промис-цепочках функции часто передают inline.
- Лектор не любит promise chains за плохую читаемость («спагетти», как старый jQuery-код).
- Даже одностроку из такой цепочки он скорее вынес бы как function declaration и сослался на неё по имени, а не оставлял бы arrow function.

## Единственное исключение

- Есть одно-единственное исключение в пользу arrow functions — их **lexical `this`** поведение (рассматривается позже в курсе).
- Кроме этого случая, автор не рекомендует использовать arrow functions как общую замену функций.

## Главное

- Arrow functions анонимны → теряют преимущества именования (self-reference, stack trace, самодокументируемость).
- Краткость синтаксиса не означает лучшую читаемость; function declaration часто даже короче.
- Единственное оправданное применение arrow functions — их lexical `this` поведение.
