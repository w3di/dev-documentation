# Optimistic UI Updates (useOptimistic) — раздел Transitions & Deferred Values

## Пример Antisocial Network

- Блог-платформа (общаешься сам с собой). Использует реальный **JSON Placeholder API** (нужен интернет).
- Демонстрация проблемы: при **Network throttling 3G** после «Post» — долгое ожидание без обратной связи. Без индикатора рендеров кажется, что «интернет сломан», и пользователь начинает **rage clicking** (яростно кликать).
- Rage clicking — UX-проблема от отсутствия обратной связи (как и тормозящий поиск ранее). Интернет ускорить нельзя — «просто соврём пользователю» оптимистичным обновлением.

## useOptimistic

- Сигнатура похожа на `useReducer`:

```js
const [optimisticPosts, addOptimisticPost] = useOptimistic(
  posts,                       // реальное состояние
  (currentState, newPost) => { // reducer
    if (newPost.isPending) {
      return [newPost, ...currentState];   // временно показать сверху
    }
    return currentState.filter(/* убрать оптимистичный */);
  }
);
```

- Принимает: **текущее реальное состояние** (`posts`) и **функцию-редьюсер** `(currentState, newValue) => nextState`.
- Тип оптимистичного значения имеет флаг **`isPending`**.
- Важно: редьюсер **не мутирует** реальный `posts` — создаёт временную «оптимистичную» проекцию. React хранит копию реального состояния, поэтому при неудаче может **откатиться**; при успехе реальный пост и так попадёт в массив (поэтому оптимистичный фильтруется).

## handleCreatePost

```js
async function handleCreatePost(formData) {
  const optimisticPost = {
    id: crypto.randomUUID(),           // временный id
    title: formData.get('title'),
    body: formData.get('body'),
    userId: currentUserId,
    isPending: true,
  };

  addOptimisticPost(optimisticPost);    // показать сразу
  // ... await fetch(...) — создать на сервере
  // успех → реальный пост добавляется в posts
  // ошибка → bubble в error boundary, оптимистичный убирается
}
```

- Логика: пользователь жмёт Post → создаём пост, **какой ожидаем от сервера** → показываем немедленно (immediate dopamine hit) → ждём реальный ответ → согласуем реальность в тот же срок, что и раньше.
- Временный **id**: можно `crypto.randomUUID()` (современные браузеры), `Date.now()`, UUID-библиотека, счётчик — id не обязан совпадать с серверным (оптимистичный убирается фильтрацией по своему id).

## Обязательно: внутри transition

- `useOptimistic` должен вызываться внутри **transition или action**, иначе ошибка в консоли: *"An optimistic state update occurred outside a transition or action. To fix, move the update to an action, or wrap it in startTransition."*
- Причина: показ оптимистичного обновления — **не высокоприоритетная** работа относительно других рендеров. Оборачивание даёт также **pending state**.
- Достаточно обернуть функцию обновления в transition — получаешь `isPending`, можно показать faded-состояние (у поста есть свойство `isPending`).

## Итог

- Сетевой запрос быстрее не стал — но **UX ощущается отзывчивым**: пост появляется в состоянии «saving/sending», при резолве заменяется реальным.
- Оговорки: оптимистично обновлять стоит только то, что **обычно успешно** (для часто падающих операций — вредно). Делать всё оптимистичным или всё низкоприоритетным — не нужно; это инструмент для конкретных bottleneck'ов.
- Замечание про API: `useOptimistic` напоминает `useEffect` — описываешь, что должно произойти, и что сделать по завершении.

## Общий вывод раздела

- Самое тяжёлое и муторное в оптимизации React исторически — **push state down**. А «продвинутые» вещи (transitions, useOptimistic, Suspense) — это ~30 строк кода.
- Раньше «один тяжёлый bottleneck» был самой сложной проблемой; благодаря **Fiber** теперь решается легко.
- Простота этих API обманчива — за ней стоит сложная механика Fiber; понимание парадигм «под капотом» обязательно.

## Главное

- `useOptimistic(realState, reducer)` даёт оптимистичную проекцию состояния без мутации реального; при ошибке React откатывается к реальному.
- Создай временный пост с `isPending: true` и временным id, покажи сразу, согласуй с сервером по резолву.
- Вызывать **только внутри transition/action** (иначе ошибка); это же даёт pending-состояние для индикатора.
- Сеть не ускоряется — улучшается восприятие; применять к операциям, которые обычно успешны.
