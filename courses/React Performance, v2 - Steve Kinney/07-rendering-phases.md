# Rendering Phases (Фазы рендеринга)

## Напоминание: зачем virtual DOM

- Изменение реального DOM дорого: даже при добавлении одного CSS-класса браузер не знает, поменялся ли layout всей страницы, поэтому вынужден всё пересчитать.
- Базовая идея React: делать всё в памяти, в **virtual DOM** («фейковый» DOM, который можно править без последствий), а затем вычислить итоговые изменения и применить только их.

## Две фазы

- **Render phase** — вычисление, *что* означают изменения.
- **Commit phase** — применение изменений *к реальному DOM*.

## Две деревья в Fiber

- С React Fiber дерево не только разбито на мелкие куски «на конвейере» — существуют **два дерева**:
  1. **current tree** — то, что сейчас отражено в DOM.
  2. **work-in-progress tree** — то, что React в процессе строит.
- Смысл: если приходит что-то более важное и нужно бросить начатое, есть чистая копия (current), не «наполовину обновлённая», к которой можно вернуться. Fiber держит «бэкап», работает над копией и при необходимости откатывается.

## Цикл render phase (по шагам)

1. Взять следующий **fiber**.
2. Вызвать функцию «**begin work**» (название неважно) — вывести children, как в обычной модели React.
3. Если children есть — **спуститься (descend)**.
4. Если нет — «**complete work**» всплывает обратно вверх (bubble up), собирая по пути effects.
5. Периодически React делает паузу для проверки (см. ниже).

## Проверки и уступка управления (yielding)

- Примерно **каждые 5 миллисекунд** (а также перед каждым paint) React проверяет: «стоит ли уступить место другим задачам?». При дорогой операции может на секунду-две заблокироваться, но стремится проверяться регулярно.
- Эвристики проверки: что-то изменилось? пришло ли время? — это фактически **private APIs**, команда React может менять их в любой момент, поэтому важны не точные тайминги, а сам факт периодической проверки.
- Если пора уступить — React приостанавливается, возвращает «руль» браузеру (CSS-анимации и пр.), проверяет, не произошли ли другие state changes. Затем:
  - либо **продолжает** с места остановки,
  - либо «мир изменился» и начатое больше не имеет смысла → **начинает заново**.
- Философский момент: перезапуск — это формально потерянная работа, но *продолжать делать ставшее ненужным* — вот настоящая потеря работы.

## Главное

- Render phase вычисляет изменения, commit phase применяет их к DOM.
- Fiber держит два дерева: **current** (в DOM) и **work-in-progress** (строится) — это позволяет безопасно откатиться при прерывании.
- Render-цикл: взять fiber → begin work → вывести children → спуститься или всплыть с complete work, собирая effects.
- React уступает управление (~каждые 5 мс / перед paint), проверяя, продолжать ли; точные тайминги — приватные эвристики, важен сам факт проверки.
