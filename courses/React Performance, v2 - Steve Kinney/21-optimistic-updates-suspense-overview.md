# Optimistic Updates & Suspense (Overview) — раздел Transitions & Deferred Values

## Не только CPU тормозит

- Предыдущие приёмы решали медленный **клиентский рендеринг**. Но медленным бывает и **сервер / связь с ним**: сервер под нагрузкой или (чаще) у пользователя нестабильный интернет (метро и т.п.).

## Optimistic updates

- **Optimistic update** (оптимистичное обновление) — предположить, что операция **успешна**, и сразу отразить результат в UI, не дожидаясь ответа сервера. Если promise отклонится (reject, 429 и т.п.) — откатить и сообщить пользователю.
- Пример (Twitter web mobile): твит появлялся в ленте даже без интернета (service worker + optimistic updates); при неудаче — уведомление. Оптимизация перформанса дала ~25–50% больше твитов и engagement. Паттерн распространён в progressive web apps.
- Применять для операций, которые **скорее всего** удадутся — лучше, чем показывать loading и «мы не знаем».
- Пример (AI-чат): между Enter и ответом агента есть латентность, но пользователь хочет **сразу** видеть своё сообщение в окне; ответ модели можно подождать пару секунд.

### useOptimistic (React 19)

- Раньше — ручная пляска: loading/error states, вставка в DOM, при 429 искать элемент в массиве и удалять.
- В React 19 — хук **`useOptimistic`**, который берёт всю эту работу на себя.

## Suspense (связь с темой)

- Обычный поток: render phase → commit phase → `useEffect`.
- С **Suspense**: Fiber, проходя дерево, встречает **неразрешённый promise** → ставит паузу на этом месте, показывает **Suspense fallback** (loading-компонент). Когда promise резолвится — продолжает с этого узла вниз. React «помнит», что весь этот блок работы ждёт.

## Почему это «вариации одной темы»

- Optimistic update — это тоже **ожидание promise**: отправили запрос, оптимистично обновили DOM; при успехе (200/201) заменяем на реальное значение, при ошибке — откатываем.
- И transitions, и Suspense, и optimistic updates — про управление асинхронной/отложенной работой и про ощущение отзывчивости.
- Всё это можно сделать вручную, но новые хуки делают это значительно проще.

## Главное

- Медленным бывает не только CPU, но и сеть/сервер — отсюда optimistic updates и Suspense.
- **Optimistic update**: сразу показать ожидаемый результат, откатить при ошибке; в React 19 автоматизируется хуком `useOptimistic`.
- **Suspense**: Fiber приостанавливается на неразрешённом promise, показывает fallback, продолжает после резолва.
- Optimistic updates, Suspense и transitions — вариации одной идеи управления отложенной работой ради отзывчивости.
