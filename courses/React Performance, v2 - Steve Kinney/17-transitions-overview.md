# Transitions Overview — раздел Transitions & Deferred Values

## Где этот класс задач

- Предыдущие приёмы (push state down, memoization) — про «маленькие блокеры», которые встречаешь почти каждый день.
- Transitions — про другую категорию: **очевидная** проблема в одном конкретном месте, которая всех бесит («большой Snorlax, сидящий на трубе»). Такие инструменты нужны редко — раз в полгода, раз в год.
- Главная цель урока: построить **концептуальный фреймворк**, чтобы уметь опознать проблему, для которой это решение, — даже если детали потом пересматривать по заметкам.

## Связь с правилами

- Повтор: «не делать = быстрее».
- Новое в фокусе: **разделять urgent и non-urgent** (срочное и несрочное).
  - По умолчанию (с ранних дней) всё одного уровня приоритета.
  - Нельзя пометить что-то как «срочное» напрямую — можно пометить **несрочное**, и тогда срочное парадоксально выделяется само. Большинство действий пользователя срочны: сделал действие — хочет увидеть результат.
  - UX-нюанс: видео-буфер или статью ждать не хотим, а загрузку Gmail подождать готовы.

## Что такое transition

- **Transition** — способ сказать «это **не** срочно».
- Опирается на приоритизацию **React Fiber** и **lanes**: несрочное уходит в полосу низкого приоритета.
- Зачем: дорогие операции нельзя сделать мгновенными (можно ускорить, но предел есть; «сделать на сервере» часто пункт №53 в бэклоге другой команды). Поэтому делаем приложение **отзывчивым**:
  - ввод пользователя и его отражение — высокий приоритет;
  - если UI лагает, замирают анимации и hover — это бесит.
  - Цель: «walk and chew gum at the same time» — срочное вперёд, остальное может подождать.

## Два хука

- **useTransition / startTransition** — пометить работу как низкоприоритетную. Передаёшь функцию, внутри которой происходит переход.
- **useDeferredValue** — когда изменение значения триггерит дорогую операцию: держим актуальное значение для отображения (например, в input), а **отложенное (deferred)** значение запускает тяжёлую работу позже.

### Метафора (неточная, но как якорь)

- Как `useMemo` возвращает значение, а `useCallback` — функцию:
  - `useTransition`/`startTransition` дают возможность обернуть **действие** (функцию).
  - `useDeferredValue` работает с **значением**.

### Эвристика выбора

- **Контролируешь код** обновления → почти всегда `useTransition` (тянись за ним первым).
- **Не контролируешь код** (есть только значение, ограничения) → `useDeferredValue`.

## Главное

- Transitions решают редкую, но очевидную проблему «одного тяжёлого места», а не ежедневные мелочи.
- Суть — пометить работу как **non-urgent** (через Fiber/lanes), чтобы ввод пользователя оставался отзывчивым, пока дорогое выполняется в фоне.
- Два инструмента: `useTransition`/`startTransition` (оборачивает действие) и `useDeferredValue` (работает со значением).
- Эвристика: контролируешь код → `useTransition`; есть только значение → `useDeferredValue`.
