# Normalizing State — раздел Context / State (архивный курс v1)

> Дополнение из старого курса (archive). Темы нет в v2.

## Слой трансформации API

- Иметь **слой** между API-запросом и view: получил ответ → сразу преобразовал в нужную тебе структуру (независимо от того, что отдаёт API).
- Стандартная «опиния» этого слоя — **normalizing state** (нормализация состояния).

## Проблема ненормализованных данных

- Глубоко вложенные структуры (post → comments[] → user) ломают собственные оптимизации: любое изменение в глубине пересобирает всё снизу вверх → новые ссылки → каскад ре-рендеров.
- Добавление уникальных keys на входе — правильно, но это лишь часть; нужна более нормализованная структура.

## Нормализованная структура

Вместо массива объектов — **массив id + объект-словарь (lookup)**:

```js
{
  users: {
    ids: [1, 2, 3, 4],            // порядок/сортировка/список
    entities: {                   // данные по ключу
      1: { id: 1, name: '...' },
      2: { id: 2, name: '...' },
      // ...
    }
  }
}
```

- Список рендерится по `ids` (просто id, как keys в React). Данные достаются прямым доступом `entities[id]`.
- При редактировании имени item'а: список знает только id (`item 9`), а данные берёт из объекта по ключу. Удаление других элементов не влияет — **отделяет порядок/сортировку/состав списка от извлечения данных**.
- Это как работают keys в React: список не пересоздаётся целиком при изменении одного элемента.

## Инструменты

- Библиотека **normalizr** (без `e`, в духе интернета 10-летней давности) делает это для Redux — сейчас архивирована, но рабочая. Несложно реализовать и вручную.

## Зачем

- Иначе вся проделанная работа (ре-рендерить только при изменении объекта в памяти) обесценивается, если **любое** изменение пересоздаёт все объекты. Memoization не бесплатна — без нормализации либо нет эффекта, либо хуже.
- Инструменты профилирования помогают понять: технология работает как ожидалось, но «ожидаемое ≠ желаемое» — это две разные вещи.

## Главное

- Держать слой трансформации между API и view; нормализовать state.
- Нормализация = `ids` (список/порядок) + `entities` (словарь по ключу); список рендерится по id, данные достаются прямым доступом.
- Это отделяет состав/сортировку списка от данных и предотвращает каскадные ре-рендеры от пересборки вложенных структур.
- Можно вручную или через normalizr.
