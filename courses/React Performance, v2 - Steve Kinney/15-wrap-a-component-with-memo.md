# Wrap a Component with React.memo — раздел Memoization

## Оборачивание компонента

```js
import { memo } from 'react';

const CalculationCard = memo(function CalculationCard(props) {
  // ...
});
```

- `React.memo` берёт функцию-компонент и оборачивает в другую, которая делает проверку props **перед** вызовом. API снаружи тот же — «те же props на входе».
- Проверка каждый раз — хорошо, даже если ничего не изменилось (особенно если защищает от внесённого бага).

## Стабилизация функций родителя

- После memo карточки всё равно ре-рендерятся, потому что родитель передаёт **новые** `onUpdate`/`onDelete` каждый раз.
- Решение — `useCallback` + functional updater сеттера, чтобы убрать зависимость от внешнего значения:

```js
const updateCalculation = useCallback((id, value) => {
  setCalculations((previous) => /* ... используем previous ... */);
}, []);

const deleteCalculation = useCallback((id) => {
  setCalculations((previous) => previous.filter(/* ... */));
}, []);
```

- **Ключевой приём:** замена `setCalculations(calculations…)` на `setCalculations(previous => …)` убирает необходимость держать `calculations` в **closure scope**. Функция получает копию предыдущего значения как аргумент → нет внешних зависимостей → массив зависимостей пустой `[]` → функция referentially стабильна навсегда (как любой set-функция из `useState`).

## Нюансы

- Массив зависимостей должен быть **пустым массивом `[]`**, а не `undefined`: `undefined` ведёт себя иначе (по сути заставляет пересоздавать каждый раз — антипаттерн).
- Возвращаемое значение `useCallback` нужно присвоить переменной (`const updateCalculation = useCallback(...)`) — функция не может «висеть» сама по себе. Внутренние функции могут быть анонимными.

## Результат

- В Profiler — гораздо меньше «зелёного мигания». При добавлении новой карточки список меняется, новая появляется, но **существующий код карточек не выполняется**:
  - `onUpdate`/`onDelete` не зависят ни от чего (берут previous внутри функции) → статичны;
  - для каждой `CalculationCard` те же значения → ре-рендер пропускается.
- Если изменить значение конкретной карточки — ре-рендерится **только она** (её `useMemo` сломался из-за нового числа), остальные «выцветают» и полностью пропускаются.
- Большие куски работы не выполняются вообще («not doing stuff»). Маленькие тайминги в профайлере = потому что ничего не произошло (показано прошлое значение).

## Главное

- `React.memo(Component)` пропускает рендер при тех же props; работает только если props стабильны.
- Чтобы стабилизировать функции-обработчики из родителя — `useCallback` с пустыми зависимостями через functional updater `setState(prev => ...)`, убирая closure-зависимость.
- Зависимости — `[]`, а не `undefined`; результат `useCallback` обязательно присваивать переменной.
- Итог комбинации memo + useCallback + useMemo: ре-рендерится только реально изменившийся компонент, остальное пропускается целиком.
