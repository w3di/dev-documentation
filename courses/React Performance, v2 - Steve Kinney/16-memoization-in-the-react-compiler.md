# Memoization in the React Compiler — раздел Memoization

## Зачем компилятор

- Ручная memoization хрупка: забыл что-то в массиве зависимостей — баг. Но анализировать код умеет не только runtime — это умеет и **ESLint** (даёт squiggly line при пропущенной зависимости).
- **React compiler** делает то же автоматически: анализирует код и расставляет оптимизации за разработчика.

## Свойства React compiler

- На момент записи — **release candidate**, но уже в проде на Instagram.com.
- **Opt-in.** Не требует React 19: построен на примитивах **Fiber**, поэтому работает примерно с React 17+.
- Предполагает, что код следует **«правилам React»** — а в реальных кодовых базах есть места, где это не так. Зрелый подход — **инкрементальная** миграция (в репозитории есть guide).
- Аналогия со Svelte/Solid: они делают статический анализ на build time с самого начала. Цель — чтобы memoization стала тем, о чём не думаешь (если нет странных edge cases).

## Как это выглядит: playground.react.dev

- Компилятор импортирует хелпер `c` (из react-compiler-runtime; с Babel-плагином немного иначе). Разработчик пишет обычный React, **не зная** про useMemo/useCallback/React.memo — они появляются «за кулисами». Аналогия: bitwise-операции в lanes — внизу стека всё стрессовое, но это просто единицы и нули.

### Простейший компонент (без props)

- `c` создаёт массив на один слот. Если первый элемент — «sentinel» (ничего не изменилось), вернуть закэшированный JSX и больше не выполнять рендер.

### Компонент с props (например, `name`)

- Создаётся массив на два слота:
  1. Сравнить: первый элемент массива равен ли строке `name`?
  2. Если **не равен** — выполнить дочернюю функцию, сохранить результат в слот (`T0`) и обновить `name` в массиве.
  3. Если равен — вернуть сохранённый (второй элемент) JSX.
- Это механически похоже на `React.memo`, но **дешевле**: не вызывается функция-компаратор, не сравниваются объекты — просто хранится ссылка и сравниваются значения. «Очень чистые value checks».

## Поведение при «нарушении правил»

- Компилятор проверяет в основном **inputs/outputs**. Если он не понимает, что происходит (странный код, side effects) — у него два варианта: помочь (риск сделать неверно) или **bail** (не оптимизировать). Он выбирает bail.
- Опасность «умных хаков»: хак может решить один уникальный случай, но **отключить оптимизацию для всего поддерева** навсегда. Был ли хак быстрее — можно измерить инструментами.

## Подключение

- Подключается **Babel-плагин** (синтаксис в конфиге — массив внутри массива, как любит Babel; в Vite иначе). На build time прогоняет код через плагин, анализирует и расставляет оптимизации. Есть тонкие настройки opt-in/opt-out.
- Greenfield vs legacy: для нового проекта — включить везде; для legacy — включать прогрессивно, где безопасно.

### Директива `"use compiler"`

- Способ постепенного opt-in отдельных компонентов/файлов. Приём из эпохи ES5: строка-директива, которая **ничего не делает** в runtime и не ломает legacy-код, но инструмент (компилятор), который её ищет, видит строку и включает режим для этих компонентов.

## Осторожность

- Паттерн проторён (Svelte → Apple Music, React compiler → Instagram.com), но включать везде сразу рискованно — возможны непреднамеренные side effects. Лучше: включить точечно → оценить performance → расширять.
- Edge case почти всегда «вина приложения», а не компилятора: кто-то когда-то сделал странное, о чём не пожалел тогда, и это «выстрелило» годами позже (отсюда blameless postmortems).

## Почему всё равно учим хуки

- `useMemo`/`useCallback`/`React.memo` остаются актуальны: есть время и место для ручного применения, и нельзя мигрировать всё сразу (если не стартуешь новый проект завтра). Понимание механики нужно, чтобы доверять компилятору и отлаживать edge cases.
- Сгенерированный компилятором код менее читаем, но его и не нужно поддерживать вручную — JSX, TypeScript и минификация уже давно проходят через компиляторы, чей вывод мы не читаем.

## Главное

- React compiler автоматически расставляет memoization на build time через Babel-плагин; opt-in, работает с Fiber (React 17+), не требует React 19.
- Генерирует более дешёвую версию `React.memo`: хранит ссылки в слотах-массивах и сравнивает значения, без вызова компараторов и создания функций.
- При непонятном коде компилятор **bail**'ит (не оптимизирует); «умные хаки» могут отключить оптимизацию целого поддерева.
- Мигрировать инкрементально (директива `"use compiler"`, точечный opt-in); ручные хуки и понимание механики остаются нужны.
