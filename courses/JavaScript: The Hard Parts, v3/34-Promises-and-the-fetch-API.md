# Часть 34. Promises и fetch API

## Разбираемый код

```js
function display(data) {
  console.log(data);
}
const futureData = fetch("https://tiktok.com/will");
futureData.then(display);
console.log("me first");
```

- Цель: через промисы использовать сетевую фичу браузера (ярлык `fetch`), сходить по URL за последними видео, а полученные ссылки на видео затем отобразить.

## Объявление функции и переменной

1. Строка 1: объявляется функция `display` с параметром `data` (пока не вызывается, сохраняется целиком).
2. Левая часть следующей строки: объявляется константа `futureData`.
   - На этом этапе значение `futureData` — **uninitialized** (неинициализировано / undefined): результат правой части ещё неизвестен.

## Вызов fetch

- Правая часть — вызов `fetch` с URL (domain + path), например `tiktok.com/will`.
  - domain — адрес сервера; path — строка в конце, указывающая нужный участок сервера TikTok.
- `fetch` нельзя выполнять синхронно (ответ может идти долго и блокировать поток), значит он запускает фоновую работу в браузере, но и возвращает что-то в JS.
- Фича браузера здесь — **network** (сетевой запрос, обращение к интернету). Запускается network request, ему нужны URL/domain и path.
- HTTP-запрос (P = protocol) уходит в «штаб» TikTok с просьбой получить (get) информацию — список ссылок на видео.
  - По умолчанию `fetch` использует метод **get** (получить данные).
  - Вторым аргументом `fetch` можно настроить **post** — отправить данные на сервер (комментарий, описание, новое видео и т.п.).
- Всё это происходит на 0 мс, и ничего из этого — не в JavaScript.

## Объект Promise (второй «зубец»)

- На 0 мс данные ещё не пришли («физика не позволит»). У фоновой работы есть подпись complete: на 0 мс — нет; on completion — придут данные (список video URLs).
- `fetch` — two-pronged facade function (у `setTimeout` был один «зубец»): второй «зубец» немедленно возвращает в `futureData` новый объект **promise**.
- Promise-объект — placeholder для данных из фоновой работы; в нём же будет место для кода, который надо запустить на этих данных.
- У promise-объекта два (скрытых) свойства:
  1. **result** — сюда on completion попадут данные из фоновой работы; пока `undefined`.
  2. **fulfill reactions** (полное имя в спецификации — *promise fulfill reactions*) — пустой массив функций, которые надо запустить, когда данные придут; в эти функции автоматически передаётся значение `result` как аргумент.
- Всё это (объект, свойства, network request) создаётся пятью буквами `fetch`.

## Связь двух «зубцов»

- Два «зубца» имеют тесную связь (intimate bond): когда сетевой ответ от TikTok вернётся, данные попадут в `futureData.result` (технически это скрытое свойство — `[[...]]`).

## Метод .then

- Чтобы добавить функцию в массив `fulfill reactions`, есть метод **.then** на promise-объекте.
- `fulfill reactions` — скрытое свойство, напрямую через `.push` к нему не обратиться. Вместо этого:

```js
futureData.then(display);
```

- `.then` берёт переданную функцию (`display`) и кладёт её в скрытый массив `fulfill reactions`.
- Доступ к `.then` приходит через prototype chain (цепочку прототипов) — разбирается позже.

## Продолжение выполнения и приход данных

1. На 1 мс выполняется `console.log("me first")` → в консоль `me first`.
   - **Нюанс про console**: `console.log` тоже фича браузера, но его работа НЕ ставится в очередь и выполняется сразу там, где вызвана. Для dev tools важно видеть состояние приложения «вживую», поэтому вывод не откладывается до конца global-кода.
2. Пока шло объяснение, запрос к TikTok вернулся, скажем, на ~270 мс. Ответ приходит как HTTP-сообщение, браузер делает над ним обработку (на практике — JSON-объект); упрощённо — строка, например `"cute puppy"`.
3. На 270 мс работа complete. Значение уходит в `futureData.result` (скрытое свойство).
4. В этот момент есть функция, готовая к запуску (`display` из `fulfill reactions`).
5. На ~270 мс `display` добавляется в call stack; JS сам добавляет скобки И автоматически вставляет данные (`"cute puppy"`) в функцию как аргумент.
6. Новый execution context; параметр `data` получает `"cute puppy"`; `console.log(data)` выводит `cute puppy` → в консоль `cute puppy`.

## Главное

- `fetch` запускает в браузере network request (по умолчанию метод get; post — для отправки данных через второй аргумент) и одновременно возвращает в JS promise-объект как placeholder.
- promise-объект имеет скрытые свойства: `result` (заполнится данными on completion, изначально `undefined`) и `fulfill reactions` (массив функций для запуска по приходу данных).
- Метод `.then` кладёт функцию в `fulfill reactions`; по завершении JS автоматически вызывает её, передавая `result` как аргумент.
- `console.log` — исключение: его вывод не откладывается в очередь, а выполняется сразу, чтобы показывать состояние приложения вживую.
