# Часть 28. Повторение синхронного выполнения

## Что впереди (контекст)

- Темы дня: **Promises**, async и **event loop** (цикл событий).
- Promises — значимая фича ES6 (2015): делают код читабельнее, но «магичны», если не понимать их работу под капотом. Будут разобраны как изнутри, так и с управлением (вплоть до отмены/abort промисов).
- Асинхронное выполнение — архитектурная особенность, делающая возможными динамические веб-приложения.
- Event loop — механизм JavaScript для определения, что выполнять следующим (триаж). Для него понадобятся **microtask queue**, **callback queue** и web browser APIs/features.

## Модель выполнения JavaScript

- При старте создаётся новый **global execution context**.
- Прохождение кода строка за строкой — **thread of execution** (поток выполнения).
- JavaScript делает одну вещь за раз: поток выполнения один.
- Также есть **memory** (память) для хранения данных.

## Пошаговый разбор кода

```js
const num = 3;
function multiplyBy2(inputNumber) {
  const result = inputNumber * 2;
  return result;
}
const output = multiplyBy2(num);
const newOutput = multiplyBy2(10);
```

1. Объявляется константа `num` со значением `3`.
2. Объявляется функция `multiplyBy2` (в тело не заходим при объявлении).
3. Поток переходит к объявлению `output`; значение пока неизвестно — нужно выполнить работу.
4. Вызов `multiplyBy2(num)`, где `num` → `3`; вызов запускает создание нового execution context.

## Call stack

- Третий компонент модели выполнения — **call stack** (стек вызовов): отслеживает, какая функция выполняется сейчас, то есть где в потоке выполнения мы находимся.
- Call stack не определяет, какие данные доступны, — за это отвечает лексическая область видимости (lexical scoping) и замыкание (closure).
- `global` всегда внизу стека, пока выполняется JavaScript.
- При вызове `multiplyBy2(3)` он добавляется на верх стека.

## Выполнение первого вызова

1. В локальную память: **parameter** `inputNumber` = `3` (имя-плейсхолдер для входа), `3` — это **argument** (аргумент).
2. Объявляется `result` = `inputNumber * 2` = `6`.
3. `return` берёт значение `result` и возвращает в `output`.
4. Execution context уничтожается, снимается (pop) с call stack.
5. Наверху стека снова `global`, поток продолжается.

## Выполнение второго вызова

1. Объявляется `newOutput`; значение неизвестно — нужно выполнить работу. JavaScript никогда не оставляет строку незавершённой.
2. Вызов `multiplyBy2(10)` (видим скобки) → новый execution context, добавляется на стек.
3. `inputNumber` = `10`, `result` = `10 * 2` = `20`.
4. `return` возвращает `20` в глобальную константу `newOutput`; контекст снимается с call stack.

## Ключевые наблюдения

- Два вызова `multiplyBy2` НЕ выполняются одновременно.
- Следующая строка (`const newOutput`) НЕ выполняется до завершения первого вызова `multiplyBy2(num)`.
- В JavaScript-«земле» — одно действие за раз.

## Главное

- Модель синхронного выполнения: один thread of execution (строка за строкой), memory для данных, call stack для отслеживания текущей функции.
- `global` всегда на дне call stack; вызов функции кладёт новый execution context наверх, `return` снимает его.
- Поток выполнения один — всё строго по очереди, без параллелизма; строка не пропускается незавершённой.
- Это база для понимания дальнейших тем: Promises, async, event loop, microtask и callback queues.
