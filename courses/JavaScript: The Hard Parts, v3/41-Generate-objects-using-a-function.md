# Часть 41. Генерация объектов с помощью функции

## Проблема ручного создания
- Создавать каждый объект пользователя вручную, добавляя свойства по одному, — повторяющийся код.
- Нарушается принцип **DRY** (Don't Repeat Yourself — не повторяйся).
- Пользователей могут быть миллионы; вписывать данные вручную при каждом входе недопустимо.
- Работу, которую нужно делать многократно, оборачивают в функцию.

## Решение 1: функция userCreator
- Функция `userCreator` создаёт объекты с данными пользователя и нужной функциональностью.
- При вызове передаются аргументы (например, `Ari` и `3`), присваиваемые параметрам `name` и `score`.
- Внутри создаётся объект `newUser`, ему динамически назначаются свойства `name` и `score`, затем привязывается функция `increment`.
- Возвращается готовый объект.

## Пошаговое выполнение (первый вызов)
1. Объявляется функция `userCreator`, сохраняется в global memory (глобальной памяти).
2. Объявляется константа `userOne` (пока не инициализирована), вызывается `userCreator("Ari", 3)`.
3. Создаётся новый execution context.
4. В local memory (локальной памяти) сначала появляются связки параметр-аргумент: `name = "Ari"`, `score = 3`.
   - Важно: на этом этапе свойства объекта ещё не создаются; local memory — это хранилище данных функции, не объект.
5. Объявляется константа `newUser` — пустой объект.
6. Добавляется свойство (ключ) `name` со значением `"Ari"` (из local memory). Это присваивание (assignment): если ключа нет — он создаётся.
7. Добавляется свойство `score` = `3`.
8. Добавляется свойство `increment` — функция (method).
9. Оператор `return newUser` возвращает объект.
   - Метка `newUser` неважна; объект выходит в global и сохраняется в глобальную константу `userOne`.
- Результат: `userOne` с `name: "Ari"`, `score: 3`, `increment` (функция).

## Второй вызов
1. Вызывается `userCreator("J", 5)`, создаётся новый execution context.
2. В local memory: `name = "J"`, `score = 5`.
3. Объявляется `newUser` — пустой объект.
4. Создаются свойства `name = "J"`, `score = 5`, добавляется method `increment`.
   - Это новая, полностью сохранённая копия функции `increment` (нужна, чтобы и этот объект имел доступ к функциональности).
5. `return newUser` → выход в глобальную константу `user2`.
- Результат: `user2` с `name: "J"`, `score: 5`, `increment` (функция).

## Проверка вызова методов
- `userOne.increment()`:
  1. Ищем `userOne` — находим.
  2. Ищем `increment` — находим.
  3. Создаётся новый execution context, метод выполняется.
- Аналогично работает `user2.increment()`.

## Нюанс с closure
- В коде функции `increment` фигурирует `newUser`, но в global нет переменной `newUser`.
- Работает **closure** (замыкание) — «рюкзак» (backpack): функция `increment`, хотя сохранена на объекте, сохраняет доступ к окружению, где была создана (включая исходное имя `newUser`, который теперь стал `userOne`/`user2`).
- У каждого созданного пользователя — отдельный «рюкзак».

## Главное
- Повторяющееся создание объектов оборачивается в функцию (`userCreator`) ради соблюдения DRY.
- Функция в local memory заполняет параметры, создаёт `newUser`, назначает свойства и возвращает объект в глобальную константу.
- Каждый объект получает свою копию метода `increment`, и через closure метод сохраняет доступ к своему окружению.

> Проблема этого подхода (дублирование функций) разбирается в части 42.
