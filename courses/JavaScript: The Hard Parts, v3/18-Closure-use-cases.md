# Часть 18. Closure: практические применения

## Две способности функций благодаря closure
- Все функции при запуске получают свежую память (local memory в execution context) — мини-программу, которая каждый раз начинается заново. Это важно: функция не должна помнить предыдущие вызовы (запустив «умножить на 2» на 7, а затем на 10, не нужно тащить память о 7). Свежий старт — часть дизайна, модуляризация кода.
- Closure добавляет вторую способность: дать функции **специальное хранилище постоянных данных (persistent data)**. Это ключевой инструмент профессионального кода.

## Helper functions: «once»
- **once** (оncify) — обернуть функцию так, чтобы она выполнялась только один раз.
- Пример: «оncified» `multiplyBy2`: первый раз с 7 → 14; второй раз с 10 → «я уже запускалась», потому что проверяет флаг/counter в backpack.
- В backpack хранится `counter` (инкрементируется) или булев флаг `runBefore` (true/false). Применение: предотвратить повторный запуск win-функции в игре, чтобы пользователь не «выиграл» дважды.

## Memoization
- **memoization** (мемоизация) — кэширование результатов дорогих вычислений.
- Пример: функция `nthPrime`, считающая, скажем, 1.2-миллионное простое число, делает много вычислений.
- Решение: хранить пары «вход → результат» (1.2 млн → найденное простое число) в backpack функции.
- Логика: при первом вызове с 1.2 млн — в backpack ничего нет, считаем, сохраняем результат; при следующем вызове с тем же входом — берём готовый результат из backpack и сразу возвращаем.
- Всё это использует backpack/closure.

## Iterators и generators
- **iterators** (итераторы) позволяют не проходить список через `for`, а иметь функцию, которая при каждом запуске возвращает следующий элемент: первый запуск — нулевой элемент массива, следующий — следующий и т.д.
- Функция сама не помнит, на какой позиции остановилась, — позиция хранится в backpack. Iterators используют closure под капотом.
- **generators** (генераторы) ещё интереснее: позволяют приостановить выполнение функции на середине (например, пока не вернётся результат асинхронной работы / API), затем продолжить.
- Чтобы продолжить функцию, нужны её local memory и позиция строки в коде — и то и другое хранится в closure/backpack. Это позволяет «ставить функцию на паузу» и продолжать после асинхронной работы. (Детали — в курсе по async hard parts.)

## Module pattern
- **module pattern** позволяет иметь постоянные метки, не загрязняя global memory (без глобальных переменных-«поллюции»).
- Проблема: если хранить данные просто внутри функции, то при закрытии её execution context метка исчезает. Нужны «пожизненные» данные, но не в global.
- Ответ — backpack: функции с постоянной памятью, к которой можно обращаться, вызывая эти функции.
- Module pattern целиком построен на том, что функции имеют persistent memory.

## Асинхронный JavaScript: callbacks и promises
- Асинхронный JS (**callbacks**, **promises**) позволяет делать долгую работу, особенно API-вызовы — обращение к интернету, что и делает JavaScript главным языком веба.
- Когда данные возвращаются (например, последние треки Spotify или вирусные видео), мы хотим выполнить над ними код.
- Этот код может использовать и **другие данные**, помимо вернувшихся из API. Чтобы они оставались доступны, функция, которую мы запускаем, имеет backpack с данными из момента её определения.
- Поэтому при вызове функции (даже отложенном/асинхронном) эти данные всё ещё доступны.

## Главное
- Closure даёт функции постоянную приватную память (backpack), не нарушая принцип «свежей памяти при каждом запуске».
- Backpack лежит в основе ключевых паттернов: once, memoization, iterators/generators, module pattern и асинхронного кода (callbacks/promises).
- Во всех случаях суть одна: функция хранит и переиспользует данные между вызовами или удерживает данные из момента своего определения.
