# Часть 14. Closure: уточнения (Q&A)

## Повторение сути

- При определении `add1` внутри запуска `outer` сохраняется не только определение функции, но и скрытая ссылка на окружающую живую local memory (реальное `counter = 0`, а не текст).
- При `return` наружу определение уходит **вместе с backpack** в `newFunc`.
- При вызове `newFunc` поиск `counter`: local memory → backpack (находит и инкрементирует) → (global не нужен).
- backpack персистентен между вызовами; обычные функции получают **два вида памяти**: пересоздаваемую local memory и сохраняющийся приватный store, доступный только этой функции (не global).

## Возможный ручной доступ

- Гипотетически к данным backpack можно попробовать обратиться как `newFunc.backpack.counter`. [? Лектор помечает это как «maybe» — будет проверено далее.]

## Что попадает в backpack

- В backpack сохраняются **только те переменные, на которые функция реально ссылается** в своём теле.
- JavaScript на этапе **определения** (definition time) анализирует тело `add1`: какие идентификаторы/метки оно может использовать. Здесь — только `counter`.
- Если в `outer` объявить, например, `let anotherCounter = 5`, но не ссылаться на неё в `add1` — она в backpack **не** попадёт. Её нельзя достать ниоткуда (backpack доступен только через возвращённую функцию), поэтому такие неиспользуемые данные **garbage collected** (собираются сборщиком мусора — удаляются/забываются).
- Принцип: сохраняется только релевантное — то, от чего функция зависит извне (dependency на внешние данные → сохраняется ссылка на эту память).

## Вложенность и цепочки

- Если `outer` сам вызывается внутри других функций / возвращается на нескольких уровнях — backpack образует **цепочку (chain)** вверх. Ответ: да, работает по цепочке (стоит поэкспериментировать). [Тема продолжается.]

## Почему это мощно

- В чистом ядре JavaScript — «сделай это, потом это», а при выходе из функции всё внутри забывается (кроме return). Closure — исключение: возвращённая функция получает персистентный backpack.
- Особенно важно в асинхронности: если функция вызывается сильно позже (например, когда вернулись данные от API), её способность держать исходный backpack данных критична.
- На closure строится **module pattern**: иметь полезные метки (например, `result`) внутри функции, не загрязняя **global namespace** (глобальное пространство имён), причём данные сохраняются между вызовами через backpack. [Подробнее — далее.]

## Главное

- В backpack попадают только переменные, на которые функция ссылается; остальное — garbage collected.
- Состав backpack определяется на этапе определения функции (анализ тела).
- Closure доступен только через возвращённую функцию — это приватные персистентные данные.
- Closure — основа асинхронных callbacks и module pattern; backpack-цепочки работают по уровням вложенности.
