# Часть 15. Closure: scope и формальные термины

## Как хранится скрытая связь backpack
- Скрытая связь (link) с сохранёнными данными хранится как **hidden property** (скрытое свойство) на самой функции.
- В JavaScript-спецификации скрытые свойства обозначаются двойными квадратными скобками: `[[ ]]`.
- Это конкретное свойство называется `[[scope]]` — `[[scope]]`.
- В JavaScript существует множество таких скрытых связей; backpack — лишь одна из них.

## Что такое scope
- **scope** (область видимости) — это не что-то загадочное: на любой конкретной строке кода это ответ на вопрос «какие данные мне сейчас доступны».
- Внутри execution context доступны данные его local memory.
- Когда функция `add1` возвращается из `outer` и сохраняется в `newFunc`, у `newFunc` появляются дополнительные доступные данные через скрытое свойство `[[scope]]`.

## Формальные («умные») названия backpack
- Backpack — это сохранённое окружение данных. У него есть несколько формальных имён.
- **variable environment** (переменное окружение) — другое имя для local memory: данные/переменные вокруг функции в момент её сохранения.
- **closed over variable environment** (замкнутое переменное окружение, COVE) — то самое variable environment, на которое «закрыли крышку» и вытащили вместе с функцией.
- Самое точное название: **persistent lexically scoped referenced data** (постоянные данные, на которые ссылается lexical scope) — данные, которые: persistent (сохраняются), на которые ссылается свойство `[[scope]]`, по правилу lexical scope.

## Lexical scope против dynamic scope
- **lexical scope** (лексическая область видимости; синоним — static scope) — правило, по которому набор доступных функции данных определяется тем, **где функция была сохранена** (записана в коде), а не где её вызвали.
- «Lexical» означает «в порядке слов на странице»: `add1` сохранена внутри вызова `outer`, поэтому получает окружающие данные из момента сохранения.
- **dynamic scope** (динамическая область видимости) — противоположное правило: доступные данные определяются тем, **откуда функция вызвана**, а не где сохранена. JavaScript использует не его.
- При вызове `newFunc` функция имеет доступ к данным из момента её сохранения — то есть к её позиции в коде на момент сохранения.

## Разговорное название: closure
- Общепринятое разговорное имя для backpack — **closure** (замыкание).
- Лектор предпочитает термин backpack, потому что closure — перегруженный термин: им называют и общую концепцию, и саму ссылку, и хранимые данные.
- Тем не менее на практике говорят «put it in the closure», «use closure to give the function a persistent memory» — закрепить за функцией постоянную память за счёт того, что язык использует lexical scope.

## Главное
- Backpack хранится на функции как скрытое свойство `[[scope]]`; scope — это просто «какие данные доступны на данной строке».
- JavaScript использует **lexical (static) scope**: доступные данные определяются местом сохранения функции, а не местом её вызова (это было бы dynamic scope).
- Формальные имена backpack: variable environment, closed over variable environment, persistent lexically scoped referenced data; разговорное — **closure**.
