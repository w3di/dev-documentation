# Часть 39. Объектно-ориентированный JavaScript

## Зачем нужен OOP
- **Object-oriented programming (OOP)** (объектно-ориентированное программирование) — популярная парадигма для структурирования сложного кода.
- Раньше React был сильнее завязан на OOP; сейчас чаще используется функциональный стиль, но OOP остаётся мощной и значимой парадигмой в JS, библиотеках и собственном коде.
- В JS появились новые возможности (за последние годы), полнее эмулирующие OOP других языков.
- В отличие от языков с нативной поддержкой OOP, в JS он строится поверх иного механизма работы с данными и функциональностью — **prototype chain** (цепочка прототипов).
- Важно различать скрытое свойство `prototype` и сами prototype-объекты, чтобы избежать путаницы (особенно для пришедших из классических OOP-языков).
- Далее изучаются ключевые слова `new` и `class`, автоматизирующие работу с prototype chain, а также static, private и public поля.

## Суть программирования
- Программирование сводится к двум вещам: «делать код» (do code) и «сохранять данные» (save data).
- Пример — игра-викторина (quiz game): сохраняем данные двух пользователей и запускаем на них функции (например, увеличить счёт).
- «Делать со данными» может означать отправку по сети, отображение в UI, прибавление единицы — но это всегда действие над сохранёнными данными.

## Почему разработка сложна
- В большой кодовой базе (100 000+ строк) надо сохранять много сущностей: пользователей, админов, вопросы, результаты, таблицу лидеров, элементы представления и их данные/функциональность.
- Проблемы при простом хранении данных и функций по отдельности:
  - функциональность для изменения данных может оказаться где угодно среди тысяч строк;
  - трудно гарантировать, что функция применяется только к нужным данным.

## Объект как решение
- Нужна структура данных, хранящая данные и функциональность в одном «пакете» — это **object** (объект).
- Альтернатива из функциональной парадигмы — closure (замыкание): функции со связанными постоянными данными. Идея та же — держать данные и функциональность рядом.
- Функциональная и объектно-ориентированная парадигмы — две соперничающие парадигмы; здесь подход с объектами: данные и функциональность связаны внутри object.

## Три цели (в напряжении друг с другом)
1. Код легко осмысливать (easy to reason about) — данные и функция рядом, не искать по всей базе.
2. Легко добавлять новые функции/возможности (easy to add features).
3. Эффективность и производительность (efficient and performant) — не тратить лишнюю память.
- Эти цели могут конфликтовать: например, удобство осмысления (данные и функции рядом) может вредить производительности (лишняя память).
- Цель OOP-парадигмы — достичь всех трёх одновременно.

## Пример данных
- Хранятся user one и user two; имена Ari и J.
- Счёт Ari = 3, счёт J = 5.
- Нужная функциональность для каждого пользователя: increase score (увеличить счёт), а также (в реальности множество) decrease, log in, log out, display.
- Способ хранить данные и функциональность вместе — object.

## Главное
- OOP — парадигма структурирования сложного кода; в JS реализуется поверх prototype chain, а не нативно.
- Программирование = сохранять данные и выполнять над ними действия; объект объединяет данные и функциональность в одном пакете.
- OOP стремится одновременно к трём целям: лёгкость осмысления, лёгкость добавления возможностей и эффективность по памяти, которые находятся в напряжении.
