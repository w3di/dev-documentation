# Часть 21. ToBoolean coercion и сравнения

## Задача: проверить валидность ввода
- **ToBoolean** (приведение к true/false) — последняя из примитивных coercion.
- Нужно проверить, что пользователь ввёл валидное количество: **не 0 и не пустую строку**.
- Особенность интерфейса UI ↔ JavaScript runtime: часто на поле ввода висит listener, и при установке курсора в поле в `quantity` сначала попадает **пустая строка** `''`.
- Аналогия с реактивностью React: действие пользователя меняет state в JavaScript, а view обновляется (здесь — пустым значением).
- Не должно проходить submit, если: либо ничего не введено (пустая строка `''`), либо введён `0`. Оба случая нельзя пропускать как валидную покупку.

## Решение через ToBoolean в условии
- В условии можно положиться на **ToBoolean coercion**: передаём `quantity` напрямую в `if`, и значение приводится к булеву.
- **Важно:** для этого нужно, чтобы `quantity` была числом `0` или пустой строкой `''` (не строкой `'0'`) — то есть число `0` либо `''`.
- И `0`, и `''` являются **falsy** (приводятся к `false`).
```js
if (quantity) {
  // выполнится, только если quantity truthy
} else {
  // 0 или '' → falsy → сюда
}
```
- Достаточно одной проверки `if (quantity)`: не нужно явно сравнивать с `0` и с `''` по отдельности, потому что ToBoolean покрывает оба случая. Если `quantity` равна `0` или `''`, условие — `false`, и мы пропускаем `if`, идя к `console.log('add items')` (или наоборот, в зависимости от логики).

## Когда 0 и пустую строку нужно различать
- Для **donation** поведение должно отличаться: `0` — нормально (донат не делается, «no problem»), а пустая строка означает «пользователь ещё не решил» («do you want to donate?»). Их надо различать.
- Для `quantity` различать не нужно — и `0`, и `''` блокируют submit.

## Ловушка loose equality (`==`)
- Попытка явно проверить донат на ноль через **loose equality** (нестрогое равенство `==`):
```js
if (donation == 0) {
  // "no donation, no problem"
} else {
  // "want to donate?"
}
```
- **Проблема:** `==` запускает coercion. Пустая строка `''` тоже **coerces к `0`**, поэтому `'' == 0` → `true`.
- В итоге `else` («want to donate?») недостижим: и `0`, и `''` попадают в первую ветку. Сообщение «no donation, no problem» срабатывает даже когда пользователь ещё ничего не ввёл.
- **Важно:** даже оператор равенства `==` запускает **toNumber** coercion другой стороны, когда одна сторона — число `0`. Сравнение «одинаковы ли эти штуки?» неожиданно приводит типы перед сравнением.

## Решение: strict equality (`===`)
- **strict equality** (строгое равенство `===`) — единственный оператор, который сравнивает **ровно то, что видит**, и **не запускает никакой coercion**.
```js
if (donation === 0) {
  // "no donation, no problem"  ← только для числа 0
} else {
  // "want to donate?"          ← для пустой строки
}
```
- При `===` пустая строка `''` **не равна** числу `0`, поэтому достигается `else` («want to donate?»), а при реальном `0` — ветка «no problem».
- Логика: для relational или математических операторов coercion порой оправдана (хотим сравнивать/умножать числа). Но чтобы проверка равенства запускала сложную сеть приведений в зависимости от сторон — это «дико». Поэтому стандарт — `===`.

## Главное
- **ToBoolean**: `0` и `''` — falsy; одна проверка `if (quantity)` отсекает оба случая без явных сравнений.
- **Loose equality `==` опасна**: она запускает coercion, поэтому `'' == 0` → `true`, и различить `0` и пустую строку невозможно.
- **Strict equality `===`** не приводит типы и сравнивает значения как есть — используйте его как стандарт, чтобы избежать скрытых coercion.
