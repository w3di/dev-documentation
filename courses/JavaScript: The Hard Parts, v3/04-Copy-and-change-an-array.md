# Часть 4. Копирование и изменение массива (без мутации)

## Постановка задачи

```js
function copyArrayAndMultiplyBy2(array) {
  const output = [];
  for (let i = 0; i < array.length; i++) {
    output.push(array[i] * 2);
  }
  return output;
}
const myArray = [1, 2, 3];
const result = copyArrayAndMultiplyBy2(myArray);
```

- Внутри создаётся **новый** пустой output-массив; элементы input-массива по очереди умножаются на 2 и push-атся в output. Исходный массив не меняется. Возвращается заполненный output.

## Разбор выполнения

- При старте включаются три части: **global execution context** (память + один **single thread** — по одной операции за раз, построчно) и **call stack**.
  - Различие scope и execution context уточняется позже. [Тема продолжается.]
  - Намёк: позже будут способы делать несколько вещей одновременно (асинхронность), пока — строго один поток.
1. В global memory сохраняется функция (как «F-box» — весь текст кода + параметр как строка символов), затем `myArray = [1,2,3]`, затем `result` (uninitialized — функция ещё не вызвана).
2. Вызов создаёт execution context, добавляемый на call stack поверх `global`; внутри — local memory.
3. Сначала связывается параметр `array` ← аргумент `[1,2,3]`, затем объявляется `output = []`.
4. **for loop** (цикл) исполняет тело, пока `i < array.length`; `i` идёт 0, 1, 2 (при 3 тело не выполняется). Условие проверяется *до* тела.
5. Каждую итерацию: берётся `array[i]`, умножается на 2, push в output → `[2,4,6]`.
6. `return output` → значение возвращается в глобальную метку `result`.

## Почему важно не мутировать вход

- При передаче `myArray` в функцию передаётся **link** (ссылка) на исходный массив, определённый глобально, а не его копия.
- Поэтому критично создавать внутри **новый** пустой массив и копировать в него изменённые элементы — чтобы не менять входной массив.
- Цель — функции без **side effects** (побочных эффектов): последствий вне функции, не описанных её return-значением.
  - Изменение переданного массива = неожиданное воздействие на глобальные данные.
  - Хорошая функция: берёт input-массив, создаёт внутри новый, возвращает его; единственное последствие — return-значение.

## Замечания о for loop и операторах

- **for loop** — мощный, но неинтуитивный интерфейс к данным; позже вводятся **iterators** (итераторы) на основе closure, дающие следующий элемент при каждом вызове функции. [Тема продолжается.]
- Передать «кусочек функциональности» (например, `+3`) напрямую как аргумент нельзя. Технически можно взять строку и прогнать `eval`, превращающий её в код, но это очень рискованно.
- Чтобы обобщить функцию ещё и по выполняемой операции (multiply / divide / add — менялась лишь операция над элементом), нужно **обернуть функциональность в функцию**. Об этом — следующая часть.

## Главное

- Стандартный паттерн: создать внутри новый массив, не трогая входной.
- В функцию передаётся ссылка на исходный массив, поэтому мутация входа = side effect.
- Поведение функции должно полностью определяться её return-значением.
- Операцию/функциональность нельзя передать как данные — её нужно обернуть в функцию.
