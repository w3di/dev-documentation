# Часть 9. Pair programming как метод роста

## Зачем

- Ментальные модели и инструменты ценны лишь тогда, когда проверяются решением реальных задач.
- **Pair programming** (парное программирование) — эффективный способ роста: решать блокеры с партнёром, а не уходить «исследовать на 3 дня».

## Два инстинкта, которые нужно балансировать

- **Researcher** (исследователь) — берёт новую тему/keyword и закапывается в изучение каждой детали на дни. Само по себе не плохо.
- **Vibe coder** (раньше — «Stack Overflower») — «заставлю работать, не понимая почему», итеративно подбирает решение (раньше — копипаст со Stack Overflow, теперь — быстрее через ChatGPT).
- Оба — хорошие качества, но оба бывают **избеганием** того, что реально помогает: методичного, спокойного прохода по коду.

## Что реально помогает: методичный разбор

- Проговаривать код построчно, отслеживать шаги.
- Отслеживать **state** (состояние — данные, живущие в приложении) и то, что вызывается/выполняется в данный момент.
- В реальности runtime может быть не один: вызов API на другом сервере, lambda-функция на платформе с конфигурацией. Это всё равно отслеживание: где выполняется код и как данные идут через разные потоки и окружения.

## Роли в паре

- **Navigator** (штурман) — руки прочь от клавиатуры; описывает подход, *как* и *почему*, а не диктует код дословно.
  - При поломке не «дай я сам починю», а: «подозреваю, что произошло вот это», предложить нужный doc, точку в console / dev tools, или формулировку prompt для Copilot.
- **Driver** (водитель) — руки на клавиатуре; реализует подход.
- Работает и для мелких задач (тренировка баланса), и для сложных кодовых баз (разобрать поток, найти, что ломается).

## Связь с современной инженерией

- То, что в командах называют «vibe coding», на деле часто = очень явное определение целей, инженерных ограничений, того, что именно должно произойти, где лежат конфиги — это качественная **technical communication**.
- Этот навык всё важнее по мере эволюции инженерии.

## Главное

- Pair programming балансирует два инстинкта (researcher ↔ vibe coder) через явную проговариваемую коммуникацию.
- Ядро отладки — методичный построчный разбор, отслеживание state и того, что выполняется сейчас.
- Роли: navigator (описывает подход) и driver (реализует).
- Явное определение целей и ограничений = качественная technical communication, ключевой навык современного инженера.
