# Часть 16. Несколько независимых closure

## Исходная ситуация
- `outer` запустили, вернули определение `add1` в `newFunc`, прихватив backpack с живыми данными из момента сохранения `add1` внутри execution context вызова `outer`.
- `newFunc` запустили дважды: каждый раз искали `counter` в local memory, не находили, шли в backpack `newFunc` и инкрементировали (0 → 1, затем 1 → 2).
- После каждого запуска execution context `newFunc` снимался с call stack.

## Второй вызов outer создаёт новый backpack
- Ключевая точность: `anotherFunc` — это **не вызов `outer`** и не «второй вызов outer», а **возвращаемое значение (return value)** второго вызова `outer`.
- Эта точность критична при работе с функциями, возвращаемыми из других функций.

Пошагово, что происходит при втором вызове `outer`:
1. Объявляется константа `anotherFunc` (левая часть); что в ней будет — пока неизвестно.
2. Вызывается `outer` → создаётся **brand new execution context** (совершенно новый контекст исполнения), вызов `outer` кладётся на call stack.
3. Внутри `outer`: переменной `counter` присваивается 0.
4. Объявляется функция `add1`.
5. JavaScript сразу даёт `add1` скрытую связь через свойство `[[scope]]` (closure к `counter`) — ещё до возврата.
6. `return add1` — функция ищется, возвращается в глобальную константу `anotherFunc`.
7. Вместе с функцией наружу вытаскивается её **backpack** с `counter` со значением 0.
8. Execution context `outer` закрывается и снимается с call stack; возврат в global.

## Запуск anotherFunc
- `anotherFunc` запускается → новый execution context на call stack.
- Единственная строка: `counter++`. Сначала ищем `counter` локально — не находим, идём в backpack `anotherFunc`, находим `counter`, прибавляем 1.
- Первый запуск: 0 → 1. Второй запуск: 1 → 2.

## Два отдельных backpack
- Если логировать `counter` в конце каждого запуска: для `newFunc` — `1`, затем `2`; для `anotherFunc` — снова `1`, затем `2`.
- Причина: **два отдельных backpack**. Один создан первым вызовом `outer` (первый `add1`, первый `counter = 0`), второй — следующим вызовом `outer`. Они независимы и не делят состояние.

## Где определена counter — меняет всё
- **counter внутри `add1` (локально):** JavaScript всегда проверяет local memory первым. Тогда `counter = 0` пересоздаётся при каждом запуске, инкрементируется до 1, контекст уничтожается. Результат каждый раз — `1`, до backpack дело не доходит.
- **counter в global:** значение накапливается между всеми вызовами через global. Для четырёх запусков `newFunc`/`anotherFunc`: `1, 2, 3, 4`.
- **counter в `outer` (как в основном примере):** живёт в backpack возвращённой функции; каждый вызов `outer` даёт свой независимый backpack.

## Главное
- Каждый вызов `outer` возвращает функцию с **собственным новым backpack** — closure независимы и не делят состояние.
- Возвращаемая функция (`newFunc`, `anotherFunc`) — это return value вызова `outer`, а не сам вызов.
- Место объявления `counter` определяет поведение: local memory всегда проверяется первой, поэтому локальная `counter` «перекрывает» backpack и сбрасывается каждый запуск.
