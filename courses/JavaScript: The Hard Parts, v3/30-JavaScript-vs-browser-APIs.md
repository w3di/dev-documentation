# Часть 30. JavaScript против Browser APIs

## Архитектура: JS внутри браузера

- JavaScript не работает в изоляции — он встроен в web browser целиком.
- JavaScript-движок имеет 3 части: **memory**, **thread of execution** (single и synchronous, по одному делу за раз), **call stack**.
- Утверждение «JavaScript асинхронен» неточно: основной поток (main thread) синхронен, если не задействовано что-то извне.
- Всё, что ниже уровня JS-движка, — это **Web Browser APIs** (фичи браузера). I в API = interface: с ними мы взаимодействуем из JS, но выполняются они не в JS-движке.
- Среди фич браузера: DOM, timers, storage, network access (обращение к интернету). Доступ к ним — через несвязанные по имени ярлыки.

## Разбор кода с setTimeout

```js
function printHello() {
  console.log("hello");
}
setTimeout(printHello, 1000);
console.log("me first");
```

1. Строка 1: объявляется функция `printHello` — её код сохраняется в памяти JS (`F`). Мы в global.
2. Вызывается `setTimeout` — выглядит как обычная JS-функция, принимает callback.
   - Первый аргумент — функция `printHello` (передаётся её определение/ссылка, **без** скобок).
   - Второй аргумент — число миллисекунд задержки (по документации MDN). Здесь `1000`.
3. Последствия `setTimeout` — **не** в JavaScript, а в браузере (в land of the web browser).

## Запуск таймера в браузере

- В браузере запускается (spin up) **timer** — `setTimeout` это ярлык для фичи timer.
- Таймеру нужно: количество миллисекунд (1000) и функция для запуска по завершении (on completion).
  - Функция не копируется внутрь таймера — хранится ссылка на её определение в памяти JS.
- Время отслеживаем (зелёным) начиная с 0 мс.

## Прохождение по времени

1. На 0 мс таймер на 1000 мс ещё не завершён.
2. Вся работа JS на строке `setTimeout` закончена — задерживаться на ней не нужно. (Технически `setTimeout` возвращает ID таймера для управления им, но для нас это сейчас неважно.)
3. На ~1 мс выполняется `console.log("me first")` → в консоль попадает `me first`.
4. Глобальный код отработал; global execution context может быть снят (popped off). Но JS не закрывается, потому что в фоне ещё что-то отслеживается.
5. На 1000 мс таймер завершается. По завершении нужно выполнить `printHello`.
   - Чтобы функция выполнилась, к ней добавляются скобки (parens) — JS добавляет их сам, мы их не писали.
   - Функция добавляется в **call stack**, создаётся новый execution context.
6. На 1000 мс выполняется `console.log("hello")` → в консоль попадает `hello`.

## Итог по модели

- Добавлена новая часть архитектуры: web browser features, которые можно запустить (spin up / kick off) через facade function.
- Facade function выглядит как JS-функция, вызывается со скобками, принимает аргументы, но делает работу в браузере, а не в JS.
- Здесь `setTimeout` запускает таймер на 1000 мс, сохраняет ссылку на код для запуска по завершении и отсчитывает время в фоне.
- Тем временем JS в своём единственном потоке доходит до `console.log("me first")` и выполняет его сразу.
- Через 1000 мс таймер завершается, функция `printHello` готова вернуться в JS; для запуска она кладётся в call stack, создаётся новый execution context, выполняется `console.log("hello")`.

## Главное

- JavaScript-движок (memory, single synchronous thread, call stack) живёт внутри браузера; всё «ниже» — Web Browser APIs, выполняемые вне JS.
- `setTimeout` — facade function: в JS почти ничего не делает, а запускает в браузере timer с указанием задержки и функции on completion (ссылка, без скобок).
- Пока таймер отсчитывает в фоне, синхронный JS-поток продолжает выполнять остальной код (`me first` печатается раньше `hello`).
- По завершении фоновой работы функция помещается в call stack (JS сам добавляет скобки) и выполняется.
