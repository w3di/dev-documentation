# Часть 13. Эксперимент: closure и «рюкзак» (backpack)

## Код

```js
function outer() {
  let counter = 0;
  function add1() { counter++; }
  return add1;
}
const newFunc = outer();
newFunc();
newFunc();
```

- Теперь `add1` не вызывается внутри `outer`, а **возвращается** наружу — и вызывается в global под именем `newFunc`. Так функция запускается **не там, где определена**.

## Разбор выполнения

1. global memory: объявлен `outer`. `newFunc` — uninitialized.
2. `outer()` → execution context (на call stack). В local memory: `counter = 0`, объявлена `add1`.
3. `return add1` — возвращается определение функции (FKA `add1`) в глобальную метку `newFunc`. Контекст `outer` закрывается, pop со стека.
4. `newFunc()` → новый execution context, новая local memory. Строка `counter++`:
   - ищем `counter` в local memory `newFunc` — нет;
   - по логике call stack дальше шёл бы `global` — там тоже нет.
5. Здесь обычная логика «провалилась бы»: функция ссылается на данные, которых нет ни в local, ни в global.

## Решение: скрытая привязка к данным (backpack)

- В момент **определения** `add1` внутри запуска `outer` сохранилось не только определение функции, но и **скрытая связь (live bond) с окружающими данными** — живой local memory.
- При `return` наружу вернулось определение **вместе с этими данными «на спине»** функции. Неформальное название — **backpack** («рюкзак»); официально это **closure** (замыкание). [Иногда называют closed-over variable environment / C.O.V.E. или scope — далее.]
- В backpack попадает **реальное** значение: не «counter будет 0», а конкретное сохранённое `counter = 0` из памяти.
- `newFunc` теперь = определение функции + прикреплённый **живой персистентный** store данных. Он доступен **только** внутри запуска `newFunc` (можно назвать **private data** — приватные данные).

## Порядок поиска (scope chain с backpack)

- При `counter++` JavaScript ищет `counter`:
  1. local memory текущего вызова `newFunc` → нет;
  2. **backpack** функции `newFunc` → есть `counter` → прибавляем 1 (стало 1);
  3. (до global дело не доходит — backpack «перехватывает» раньше).

## Персистентность между вызовами

- Второй `newFunc()`: новая (пустая) local memory; `counter++` снова не находит в local → идёт в backpack, где `counter` уже = 1 → инкремент до 2.
- backpack устанавливается при сохранении функции в `newFunc` и **сохраняется (persists)** между вызовами, в отличие от local memory, которая каждый раз создаётся заново и стирается.
- Итог: у обычной функции появляются **два вида памяти** — временная local memory (на каждый запуск) и персистентный приватный store (backpack), доступный только этой функции.

## Про термин «lexical»

- Термин для механизма содержит слово **lexical** (лексический): от того, *где в коде ты написал/сохранил* функцию, а не где её запустил.
- Поэтому связь привязана к месту определения функции. Осторожно: дело не в самих фигурных скобках как тексте, а в том, что при *выполнении* кода `counter = 0` сохраняется в памяти живым, и в этот момент возникает live bond к окружающим данным.

## Главное

- Возврат функции наружу прикрепляет к ней backpack — closure: живой персистентный store окружающих данных с момента её определения.
- При поиске переменной порядок: local memory → backpack → global.
- backpack сохраняется между вызовами (персистентная приватная память), local memory — нет.
- Доступ к данным определяется **местом определения** функции (lexical scope), а не местом вызова.
