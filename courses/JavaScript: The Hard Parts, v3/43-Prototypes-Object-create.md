# Часть 43. Prototypes и Object.create

## Цель подхода

- Цель: иметь возможность вызывать `user1.increment` и `user2.increment`, чтобы запускать функциональность на нужных данных конкретного пользователя.
- При этом нельзя держать копию функции `increment` на каждом объекте (`user1`, `user2`, ..., `user700`). Нужна **одна** сохранённая версия функции.
- Решение: объекты создаются через **Object.create** (встроенная функция, создающая объект со скрытой ссылкой на другой объект), а доступ к общей функции обеспечивает **prototype chain** (цепочка прототипов — механизм, по которому JS ищет недостающее свойство в связанном объекте).
- Объект без функции на самом себе всё равно автоматически знает, куда пойти искать эту функцию.

## Разбор кода solution 2

```js
function userCreator(name, score) {
  const newUser = Object.create(userFunctionStore);
  newUser.name = name;
  newUser.score = score;
  return newUser;
}

const userFunctionStore = {
  increment: function () { this.score++; },
  login: function () { console.log("Logged in"); }
};

const user1 = userCreator("Ari", 3);
const user2 = userCreator("J", 5);
```

- `userCreator` — обычное определение функции.
- `userFunctionStore` — это объект (несмотря на вид), внутри хранятся методы-функции `increment` и `login`.
- `user1` — пока неизвестно что хранить, нужно вызвать `userCreator` с аргументами `"Ari"` и `3`.

## Выполнение userCreator("Ari", 3)

1. Создаётся новый execution context, новый local memory.
2. Сначала идёт только argument-parameter assignment: параметры `name` и `score` получают аргументы `"Ari"` и `3`. Это просто данные в local memory, **не объект** (частая ошибка).
3. Объявляется метка `newUser`, ей присваивается результат вызова `Object.create`, в который передан `userFunctionStore`.
4. `Object.create` возвращает **пустой объект** (empty object). Не «уже заполненный» — именно пустой.
5. Этот пустой объект каким-то образом получит связь (bond) с `userFunctionStore` — пока неизвестно как.
6. Вручную добавляются свойства: `newUser.name = "Ari"`, `newUser.score = 3`. Передача аргументов сама по себе НЕ кладёт их на объект — их нужно присвоить явно.
7. `return newUser` — объект целиком уходит в глобальную метку `user1`.

- Объект `user1` имеет `name: "Ari"`, `score: 3` и скрытую ссылку вверх на `userFunctionStore`. Execution context закрывается, снимается с call stack.
- Аналогично для `user2 = userCreator("J", 5)`: новый execution context, новый вызов `Object.create`, новый объект со скрытой связью на `userFunctionStore`.

## Замыкание и Object.create

- Возвращаемые объекты НЕ несут с собой замыкание (closure) с локальными данными `userCreator`, потому что на них нет функции, объявленной внутри. Именно наличие функции удерживает замыкание с окружающими данными.
- Нельзя написать `return Object.create(userFunctionStore)` напрямую: тогда негде было бы добавить свойства `name` и `score`.

## Lookup при вызове user1.increment

1. `user1` ищется в global memory — найдено.
2. Ищется свойство `increment`: это не `name`, не `score` — на самом объекте нет.
3. JS не «паникует» (нет ошибки): он идёт по скрытой ссылке вверх.

## Скрытое свойство prototype

- При создании через `Object.create` объекты получают не просто пустой объект, а скрытое свойство — ссылку вверх на `userFunctionStore`.
- Имя этого скрытого свойства — **prototype** (в спецификации обозначается как `[[Prototype]]` — в двойных квадратных скобках). Раньше называлось иначе.
- Скрытое свойство недоступно напрямую и не видно при переборе свойств объекта. В консоли его можно раскрыть стрелкой вниз.
- Связь устанавливается в момент создания объекта, когда `userFunctionStore` передаётся в `Object.create`.

## Завершение lookup

1. Не найдя `increment` на `user1`, JS идёт по `[[Prototype]]`-ссылке на `userFunctionStore`.
2. Там находит `increment` и запускает его — создаётся новый execution context.

## Проблема: на каком объекте работает increment

- Одна сохранённая версия `increment` должна работать на `user1`, `user2`, `user400` и т.д. Функция заранее не знает, на каком объекте её вызвали.
- Термины «копия» и **instance** (экземпляр) лектор избегает: точнее «одна сохранённая версия функции в памяти».
- Нужно нечто в local memory, что автоматически укажет на объект, на котором запущена функция.

## Implicit parameter this

- В local memory автоматически появляется **implicit parameter** (неявный параметр) — `this`, без объявления вручную.
- `this` всегда указывает на объект слева от точки, на котором запущена функция.
  - При `user1.increment()` → `this` = `user1`.
  - При `user2.increment()` → `this` = `user2`.
- Код метода написан через `this`: `this.score++`.

## Как this находит данные

1. `this.score++` для `user1.increment()` вычисляется как `user1.score++`.
2. Метод `increment` ищет `user1` в своём local memory — не находит (это не плохо).
3. Находит `user1` в global, на нём ищет свойство `score`.
4. Прибавляет 1: `score` становится 4.

## Главное

- **Object.create** создаёт пустой объект со скрытой связью **[[Prototype]]** на переданный объект; это база для **prototype chain**.
- При обращении к отсутствующему свойству JS не падает, а идёт вверх по prototype chain и находит общий метод в одном месте (`userFunctionStore`).
- Общий метод узнаёт свой целевой объект через **implicit parameter this**, который указывает на объект слева от точки в момент вызова.
- Аргументы, переданные в функцию, не попадают на объект автоматически — свойства нужно присваивать вручную.
