# Часть 51. Private instance fields

## Проблема публичных свойств
- Публичные свойства можно менять напрямую из любого места: `user1.score++` сработает без вызова `user1.increment()`.
- В больших кодовых базах (100 000 строк) это опасно: другой разработчик может случайно изменить значение в обход предусмотренного механизма.
- Цель — заставить менять `score` только через метод `increment`, по предсказуемому паттерну.

## Что такое private instance field
- **private instance field** (приватное поле экземпляра) — данные, доступные и видимые только методам, выполняемым на этом объекте.
- Их нельзя прочитать или изменить извне: попытка `user1.score++` из global кода даст ошибку.

## #-syntax
- Приватное поле объявляется через **#-syntax** (символ `#`, «hashtag»/«number symbol») перед именем.
- В скрытой секции fields класса задаётся приватное поле, например `#score`.
- Внутри constructor оно доступно как `this.#score` и устанавливается там же.

```js
class UserCreator {
  #score;
  constructor(name, score) {
    this.name = name;
    this.#score = score;
  }
  increment() { this.#score++; }
}

const user1 = new UserCreator('Ari', 3);
user1.increment();
```

## Где хранится #score
- При создании `user1` поле `#score` добавляется НЕ к обычным свойствам объекта, а в отдельную скрытую, недоступную секцию — **private element properties** (приватные свойства элемента).
- Доступ к ним возможен только из методов, определённых в составе класса (constructor и методов класса).
- Снаружи объекта (`user1.#score` или `user1.score`) доступа нет — будет ошибка.

## Пошаговый разбор: user1.increment()
1. `user1` находится в global memory.
2. На объекте `increment` нет — поиск идёт по prototype chain через скрытую ссылку proto в `prototype`, где найдены `increment` (и `login`).
3. `increment` запускается в новом execution context. Код: `this.#score++`.
4. В local memory `this` = то, что слева от точки, то есть `user1`.
5. Так как обращение идёт изнутри метода того же класса, ошибки нет: происходит прямой доступ к скрытой приватной секции, и `score` увеличивается с 3 до 4.

## Важные нюансы
- Это не syntactic sugar, а реальное изменение поведения JavaScript «под капотом».
- В обычном выполняемом коде приватные данные недоступны снаружи.
- Технически в Chrome DevTools приватные данные видны (чтобы разработчик понимал, что хранится) и даже изменяемы там, но в обычном JavaScript-коде так делать нельзя.

## Главное
- **private instance field** объявляется через `#` и хранится в отдельной скрытой секции private element properties, недоступной извне объекта.
- Доступ к приватному полю есть только у методов, определённых в классе (через `this.#имя`).
- Это реальное изменение под капотом, а не syntactic sugar; обеспечивает контроль над тем, как меняются данные объекта.
- Снаружи `user1.#score` приводит к ошибке; в DevTools данные видимы для отладки.
