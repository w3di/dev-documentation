# Часть 29. Обзор асинхронного кода

## Проблема синхронности

- JavaScript — **single-threaded** (один поток исполнения): одна команда за раз.
- Код выполняется **synchronously** (синхронно): каждая строка по порядку, без перескоков. Это предсказуемо.
- Но представим задачу, которая обращается к серверу TikTok за ссылками на видео: сервер не на нашем компьютере, ответ может идти 100–300 мс (а в масштабах вычислений — дольше, чем весь остальной код приложения).
- Ждать ответа нельзя пассивно: пока ждём, никакой другой код выполняться не сможет — поток заблокирован.
- При этом данные нужны: получив их, мы хотим, например, отобразить видео.

## Блокирующий код

- Медленная функция блокирует дальнейшее выполнение, потому что поток один.

```js
function getVideos() {
  // уходит к TikTok за видео, ~350 мс
}
function displayVideos(data) {
  // отображает видео, когда данные пришли
}
getVideos();
displayVideos(data);
console.log("I want to run");
```

- `console.log("I want to run")` не может выполниться раньше, пока ждём видео, — поток один.

## Попытка отложить через setTimeout

- **setTimeout** (встроенная функция-таймер) откладывает запуск функции на заданное число миллисекунд.

```js
function printHello() {
  console.log("hello");
}
setTimeout(printHello, 1000);
console.log("me first");
```

- По «обычной» модели JS ожидался бы порядок: сначала `hello` (после ожидания 1000 мс на этой строке), затем `me first`.
- Фактически порядок другой: сначала `me first`, потом `hello`.
- Даже при задержке `0` миллисекунд:

```js
setTimeout(printHello, 0);
console.log("me first");
```

- Всё равно сначала выводится `me first`, затем `hello`. Привычная модель JS здесь не работает — нужны новые компоненты.

## Чего недостаточно в «чистом» JS

- Ядро JavaScript-движка имеет 3 части:
  1. **thread of execution** (поток исполнения) — один, проходит код построчно.
  2. **memory** (память) — она же variable environment / state; данные приложения в данный момент.
  3. **call stack** — отслеживает, какая функция выполняется сейчас.
- Этого набора недостаточно для асинхронности. Нужно добавить новые компоненты.

## Новые компоненты (вне JavaScript)

- **Web/Browser APIs** (в Node — background features / Node APIs).
- **Promises**.
- **event loop** (цикл событий).
- **callback queue** (она же task queue — очередь обратных вызовов / задач).
- **microtask queue** (очередь микрозадач).
- Эти части находятся не в JavaScript, а во внешней системе. JavaScript не работает в изоляции — он работает в браузере (web browser) или в среде Node.

## Возможности браузера, которых нет в самом JS

- **DOM** (Document Object Model) — большой объект, описывающий содержимое веб-страницы; позволяет взаимодействовать со страницей из JS.
- **console** — даже консоль и dev tools не входят в JavaScript.
- Таймеры: `setTimeout`, `setInterval`.
- Сетевой доступ (обращение к интернету).
- IndexedDB, local storage, service workers, webcam.
- Ни одна из этих возможностей не реализована в самом JavaScript.

## Facade functions (функции-фасады)

- JS даёт «ярлыки» (labels) для доступа к этим внешним возможностям.
- Лектор называет их **facade functions** (функции-фасады): выглядят как обычные JS-функции, но на деле лишь запускают работу вне JavaScript — в браузере.
- Имена ярлыков в JS часто не совпадают с официальными именами возможностей. Уточнять — на MDN:
  - DOM → `document`
  - console → `console` (метод `.log`)
  - сеть: раньше `XHR` (**XMLHttpRequest**), теперь **fetch API** (через `fetch`)
  - таймеры → `setTimeout`, `setInterval`
- Через **abort signal** можно тоже запустить таймер и, например, прервать (abort) запрос `fetch`, если результат не пришёл к заданному времени.

## Расширение модели

- Систему расширяем: к JavaScript добавляем уровень web browser features.
- В JS появляется код, который сам по себе делает мало, но запускает работу целиком вне JavaScript — внутри браузера.

## Главное

- JavaScript — single-threaded и synchronous; долгие операции блокируют единственный поток, поэтому нужна асинхронность.
- Асинхронность обеспечивается компонентами вне JS: Web/Browser APIs, callback queue, event loop, microtask queue, Promises.
- Facade functions (`setTimeout`, `fetch`, `console.log` и др.) выглядят как JS-функции, но запускают работу в браузере; их JS-ярлыки часто отличаются от официальных имён (искать на MDN).
- `setTimeout(fn, 0)` не запускает функцию сразу — это первое доказательство, что прежней модели JS недостаточно.
