# Часть 27. Symbols и metaprogramming

## Больше контроля: аргумент hint

- Когда движок запускает функцию из `@@toPrimitive`, он не только добавляет скобки (вызывает функцию), но и автоматически передаёт в неё информацию о режиме приведения.
- Для ToNumber движок вставляет строку `"number"`, для ToString — строку `"string"`.
- Параметр принято называть **hint** (подсказка), но имя любое.

```js
function coerce(hint) {
  if (hint === "number") {
    return 105;
  }
  if (hint === "string") {
    return "user";
  }
}
```

- Режим зависит от оператора над объектом: математика/унарный `+` → `hint === "number"`; строковый контекст (например, шаблонный литерал) → `hint === "string"`.
- В локальную память функции `hint` попадает как соответствующая строка; на её основе пишется условная логика и возвращаются разные значения для number и string.

## Symbols

- **Symbol** — фича ES6 для добавления **semi-hidden** (полускрытых) свойств объектам.
- Это **labels** (метки) — уникальные идентификаторы. Как любая метка на объекте, символ уникален и сам по себе является уникальным значением.
- Их нельзя вписать напрямую, поэтому они не перезапишут существующий код разработчиков.

## Зачем именно скрытый тип, а не строка

- Если бы фичу сделали обычным строковым свойством `toPrimitive`, то у всех, у кого уже была функция/свойство `toPrimitive`, JavaScript внезапно начал бы его использовать — неожиданное поведение и поломка кода.
- `@@toPrimitive` не перезапишет существующее строковое `toPrimitive` разработчика.
- Язык с 30-летней историей может вносить в основном **non-breaking backwards-compatible** изменения. Решение — новый тип данных, не конфликтующий с прежними.

## Свойства Symbols

- При переборе свойств объекта обычные свойства видны, а символы — нет (отдельно перебираются именно символы). Код, выводящий все элементы объекта, случайно не заденет символьные свойства.
- JavaScript использует символы для доступа к внутренним («under the hood») возможностям языка.

## Well-known symbols

- Встроенные символы, которые JavaScript «знает» и куда сам смотрит, называются **well-known symbols** (общеизвестные символы; по сути — «известные языку»).
- Они открывают **metaprogramming** (метапрограммирование — управление поведением самого языка):
  - ручной контроль ToPrimitive (number, string и default — когда оператор не задаёт ни number, ни string);
  - изменение работы iterator;
  - влияние на async-возможности;
  - влияние на поведение классов.
- Можно создавать и собственные символы (редко в прикладном коде, часто — в библиотеках).
- Всё это с обратной совместимостью за счёт полускрытости: чужое одноимённое свойство не начнёт использоваться для мета-поведения.

## Итог по контролю coercion

- Теперь известно, как вручную управлять приведением примитивов (ToNumber, ToString, ToBoolean) и полным пайплайном object-to-primitive.
- Это даёт и **гибкость** (польза от того, что данные могут приводиться при использовании), и **предсказуемость** (явное, контролируемое приведение).
- На практике часто всё равно нужно проверять экспериментом, какая именно coercion сработала: каждый вызов API и каждый оператор её запускает.
- По умолчанию стоит выбирать явный контроль: явный вызов `Number()` для данных из DOM (чтобы не остаться с DOM-строкой), явное управление приведением object-to-primitive.

## Связь с TypeScript

- TypeScript популярен, потому что автоматизирует многие из этих правил и контроль, убирая непредсказуемость.
- Но понимание coercion «под капотом» остаётся ключевым для эффективной работы с JavaScript (и для ответов на каверзные вопросы на собеседованиях).

## Главное

- Функция в `@@toPrimitive` получает аргумент **hint** (`"number"`/`"string"`/`"default"`), по которому можно вернуть разные значения.
- **Symbols** (ES6) — уникальные полускрытые метки; их нельзя вписать напрямую, они не видны при обычном переборе и не ломают существующий код.
- **Well-known symbols** известны движку и открывают metaprogramming: контроль coercion, итераторов, async, классов — с обратной совместимостью.
- Цель — явный, предсказуемый контроль над повсеместной coercion; TypeScript автоматизирует это, но понимать механизм всё равно необходимо.
