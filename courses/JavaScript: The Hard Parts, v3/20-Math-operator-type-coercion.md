# Часть 20. Type coercion у разных операторов

## Relational-операторы тоже запускают toNumber
- Добавим лимит количества:
```js
let max = 10;
function onSubmit() {
  total = price * quantity;     // 7 * '3' → toNumber → 21
  if (quantity < max) { /* ... */ }
}
```
- **relational operator** (оператор сравнения) `<` («меньше») вычисляется в `true`, если левая сторона меньше правой.
- При `quantity < max`: `quantity` — строка `'3'`, `max` — число 10. «Строка `'3'` меньше 10?» само по себе бессмысленно.
- Оператор `<` запускает **toNumber**: `'3'` → `3`, `10` остаётся `10`. Получаем `3 < 10` → `true`.
- Вывод: relational-операторы тоже запускают **toNumber coercion**.

## Оператор `+` ведёт себя иначе
- Добавим донат (donation), приходящий из DOM как строка `'10'`:
```js
let donation = '10';
function onSubmit() {
  total = price * quantity + donation;
}
```
- Порядок действий (BODMAS / PEMDAS — приоритет умножения над сложением):
  1. `price * quantity` → `7 * '3'` → toNumber → `21`.
  2. `21 + '10'` — здесь **toNumber не запускается**.
- **Важно:** если хотя бы одна сторона `+` — строка, JavaScript запускает **toString** (приведение к строке), а не toNumber.
- `21` приводится к строке `'21'`, `'10'` уже строка; `'21' + '10'` даёт **string concatenation** (конкатенацию строк) → `'2110'`, а не число.
- Результат `'2110'` вместо ожидаемого `31` — печально известное поведение.

## Правило по операторам
- Большинство математических операторов — `-` (минус), `*` (умножение), `/` (деление), `%` (**modulo**, остаток от деления), `**` (**exponent**, возведение в степень) — **всегда запускают toNumber**.
- `+` делает «честную» математику, **только если обе стороны уже числа**; если хотя бы одна — строка, запускается **toString** и происходит конкатенация.
- Какая coercion сработает, зависит от данных в позиции операнда в данный момент — это **сильно недоспецифицировано** (underspecified): в отличие от функции (или TypeScript), нет синтаксической спецификации входов/выходов, поведение зависит от потока данных. Это делает код непредсказуемым.

## Ручное управление coercion
Чтобы сделать поведение предсказуемым, приведение типов запускают **вручную**.

**Гарантировать число (toNumber):**
1. **unary operator** (унарный плюс) — поставить `+` перед значением: `+price`, `+quantity`, `+donation`.
2. Либо вызвать встроенную функцию `Number(...)`.

**Гарантировать строку (toString):**
1. **string literal / template** — обернуть значение в шаблонный литерал: `` `${value}` `` (доллар, фигурные скобки, бэктики).
2. Либо вызвать функцию `String(...)`.

Пример с ручным toNumber:
```js
total = +price * +quantity + +donation;
```
- `+price` → 7 (без изменений), `+quantity` → число `3`, `+donation` → число `10`.
- Теперь: `7 * 3 = 21`, затем `21 + 10 = 31`.
- Вместо строки `'2110'` в `total` попадает число `31`.
- Суть: мы перестаём полагаться на оператор, который одновременно делает математику и предварительно запускает скрытое действие (type coercion), и берём контроль на себя.

## Главное
- `-`, `*`, `/`, `%`, `**` всегда запускают **toNumber**; `+` запускает **toString** (конкатенацию), если хотя бы одна сторона — строка.
- Автоматическая coercion недоспецифицирована и зависит от данных в рантайме — это источник непредсказуемых багов.
- Берите контроль вручную: `+x` или `Number(x)` для числа; `` `${x}` `` или `String(x)` для строки.
