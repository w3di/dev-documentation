# Часть 52. Private static fields

## Что такое private static field
- **private static field** (приватное статическое поле) — приватные данные, хранящиеся прямо на `UserCreator` (на объектной части function + object combo), а не на отдельных создаваемых объектах.
- Объявляется как `static #count = 0` в наборе приватных свойств класса.
- Доступ есть только изнутри кода, связанного с `UserCreator` (например, из constructor), но НЕ из global.
- `UserCreator.#count` из global кода — ошибка/недоступно.

```js
class UserCreator {
  static #count = 0;
  constructor(name, score) {
    if (UserCreator.#count >= 2) {
      throw new Error('maximum number of users has been reached');
    }
    this.name = name;
    this.score = score;
    UserCreator.#count++;
  }
  increment() { this.score++; }
}

const user1 = new UserCreator('Ari', 3);
const user2 = new UserCreator('J', 5);
const user3 = new UserCreator('Tam', 9); // throws
```

## Назначение
- Это разделяемые (shared) данные для всех объектов класса, которые нельзя случайно изменить извне.
- Пример: ограничение максимального числа создаваемых пользователей.

## static и однократная инициализация
- Благодаря ключевому слову `static` значение `#count = 0` устанавливается на классе один раз — при определении класса, а не при каждом вызове.
- При повторных вызовах `new UserCreator(...)` запускается только функциональная часть (constructor), а не объявление класса, поэтому `#count` не сбрасывается в 0.
- Это типичная «ловушка» (gotcha): вызов `UserCreator(...)` — это запуск только constructor, а не всего класса.

## Пошаговый разбор третьего вызова: new UserCreator('Tam', 9)
1. В global memory объявляется `user3`, ожидает возвращаемое значение.
2. Создаётся новый execution context для запуска constructor (функциональной части combo).
3. В local memory: `name = 'Tam'`, `score = 9`.
4. the new keyword создаёт пустой объект `this`.
5. Устанавливается скрытая ссылка proto объекта на `UserCreator.prototype` (объект, куда class положил `increment`).
6. fields для отдельных объектов здесь нет (используется static — поле прикреплено к классу в целом).
7. Первая строка тела constructor — проверка `UserCreator.#count >= 2`. Доступ к приватному полю есть, так как код выполняется внутри constructor.
8. `#count` на этот момент равен 2 (увеличивался при создании `user1` и `user2`). 2 >= 2 — истина.
9. Бросается ошибка: «maximum number of users has been reached». Объект `user3` не создаётся полностью.

## Важные нюансы
- `UserCreator.#count` из global недоступен — это новая возможность JavaScript (приватные данные).
- Перезаписать `prototype` напрямую всё ещё можно, но shared private данные, защищённые через приватные поля класса, перезаписать извне нельзя.

## Итоговые выводы курса по OOP в JavaScript
- JavaScript «под капотом» — **prototypal language** (язык на основе прототипов): доступ к чужим объектам/функциям/методам идёт через скрытое свойство proto и prototype chain.
- На этой прототипной основе язык воссоздаёт возможности классических object-oriented языков: доступ к общим методам, private data, shared private data, static fields.
- Эти возможности не ведут себя «под капотом» так, как в классических OOP-языках, и потому могут вести себя иначе и на поверхности — без понимания механики они дают сбои (частая тема жёстких интервью-вопросов).
- the new keyword и class были первыми инструментами, автоматизирующими прототипную работу (создание объекта, связывание с общими функциями, возврат объекта).
- Новые field-возможности (private/public, static/instance) дают **encapsulation** (инкапсуляцию): данные и функциональность связаны вместе и недоступны извне — это структурированный, устойчивый код.

## Главное
- **private static field** (`static #имя`) хранит приватные shared-данные прямо на классе; инициализируется один раз при определении класса, недоступно из global.
- Вызов `new UserCreator(...)` запускает только constructor, поэтому static-поле не переинициализируется — типичная ловушка.
- Приватные static-данные защищены от случайного изменения извне и удобны для общей логики (например, лимита числа объектов).
- Все OOP-возможности JavaScript — надстройка над прототипной природой языка; их корректное использование требует понимания prototype chain.
