# Часть 45. Arrow functions и ключевое слово this

## Контекст примера

- `increment` теперь объявляет внутри функцию `addOne` и вызывает её. Цель — показать, что произойдёт с `this` внутри вложенной функции.

## Lookup user2.increment

1. `user2` ищется в global — найдено.
2. `increment` на `user2` нет → не паникуем → идём по proto-ссылке.
3. Proto указывает на `userFunctionStore`, там находится `increment`.
4. Запускается `increment` — новый execution context.

- Лектор называет скрытую ссылку «proto reference», чтобы отличать от объекта по имени `prototype` (ещё одна ловушка именования).

## Выполнение increment

1. В local memory объявляется функция `addOne`.
2. Появляется implicit parameter `this`, установленный в объект слева от точки — `user2`.
3. Вызывается `addOne()` — новый (вложенный) execution context.
4. В `addOne` исполняется `this.score++`.

## Проблема: this в обычной вложенной функции

- Ожидается, что `this` внутри `addOne` будет `user2`. На деле — нет.
- При обычном вызове функции (не как метода через точку) `this` указывает на бесполезный объект **window** (глобальный объект).
- Тогда `score` создалось бы динамически на `window` как `undefined`, и `++` потребовал бы type coercion — нежелательное поведение.
- Правило JS строгое: `this` присваивается тому, что слева от точки при вызове функции. У `addOne()` слева от точки ничего нет, поэтому `this` по умолчанию = global (window).

## Старый хак: that = this

```js
increment: function () {
  var that = this;
  function addOne() {
    that.score++;
  }
  addOne();
}
```

- Внутри `increment` объявляли `that = this`, а во вложенной функции писали `that.score++`.
- `that` есть в замыкании, указывает на `this` внешней функции (т.е. `user2`).
- Один из крупнейших «хаков», давших JS дурную славу. Сейчас не нужен.

## Решение: arrow function

```js
increment: function () {
  const addOne = () => {
    this.score++;
  };
  addOne();
}
```

- **arrow function** (стрелочная функция) — другой способ объявления функции; по исполнению такой же, но имеет специфическое последствие для `this`.
- `this` стрелочной функции определяется не по месту вызова (не «слева от точки»), а по месту определения — это поведение похоже на **lexical scoping** (лексическая область видимости): `addOne` теперь лексически привязана.
- Стрелочная функция держит **lexical this** — значение `this` из той области, где функция была определена.

## Как работает this в arrow function

1. `addOne` определена внутри `increment`, где `this` уже автоматически установлен в объект слева от точки — `user2`.
2. При вызове `addOne()` её `this` берётся из места определения = `user2` (а не window).
3. `this.score++` вычисляется как `user2.score++`.
4. `user2` ищется в local — нет, нет — находится в global; `score` инкрементируется до 6.

- Для `user1.increment()` аналогично: `this` в `increment` = `user1`, стрелочная `addOne` наследует этот `this`, `user1.score++` даёт 5.

## Когда применять arrow functions

- Сильная причина использовать стрелочные функции — внутри методов, общих для многих объектов.
- Для самого метода это поведение не нужно (если бы метод сам был стрелочным, поведение изменилось бы нежелательно).
- Но для функции, вызываемой ВНУТРИ метода (не как метод объекта, а просто `addOne()`), стрелочный синтаксис гарантирует правильный `this`.

## Оценка solution 2 (prototype chain)

- Объекты получают доступ к функциям без копирования их на каждый объект (`user1`, `user2`, `user400`...). Решение полностью рабочее и изящное.
- Минус — многословность: каждый раз вручную создавать объект, делать `Object.create` для bond с function store, возвращать объект. В других языках это делается автоматически.
- В объектно-ориентированной парадигме мыслят данными и функциональностью, обёрнутыми в объект, даже для единственного экземпляра (например, игровое поле).
- Solution 2 — полноценное, не сломанное решение, но **не стандартное**. (тема продолжается)

## Главное

- При обычном вызове функции `this` указывает на глобальный объект **window**, что внутри методов бесполезно и опасно.
- **arrow function** фиксирует **lexical this** — берёт `this` из места определения, а не из места вызова.
- Стрелочные функции — современная замена старому хаку `that = this`; их применяют для вложенных функций внутри общих методов.
- Solution 2 на prototype chain работает полностью, но многословно и не является стандартным подходом.
