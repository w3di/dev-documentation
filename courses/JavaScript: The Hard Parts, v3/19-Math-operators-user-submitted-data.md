# Часть 19. Математические операторы и данные от пользователя

## Что разбираем
- **type coercion** (приведение типов) — одна из самых неоднозначных частей JavaScript, но это **дизайнерская фича, а не ошибка**: язык не работает в изоляции, он живёт в веб-браузере и должен гибко принимать данные неожиданных типов.
- Попутно используется **Symbol** для **metaprogramming** (метапрограммирование — управление внутренними механизмами самого языка) и контроля над coercion-пайплайнами (тема продолжается далее).
- Понимание coercion опирается на различие **primitives** (примитивы — обрабатываются by value, лежат в stack) и **objects** (объекты — by reference, лежат в heap).

## Операторы как «диспетчеры действий»
- **operator** (оператор) — это, по сути, аналог функции, но «перевёрнутый»: функция действует на то, что внутри скобок, а оператор действует на **operands** (операнды) — то, что стоит рядом с ним на строке.
- Точнее операторы называют **action dispatchers** (диспетчеры действий), а не функциями: они запускают работу — математику или, что важно, type coercion.
- В выражении `price * quantity`: `*` — operator (умножение), `price` и `quantity` — operands; оператор диспетчеризует действие «умножь их».

## Базовый пример без пользователя
```js
const price = 7;
const quantity = 3;
const total = price * quantity; // 21
```
- Здесь `*` диспетчеризует встроенное в язык умножение; `7 * 3` вычисляется в `21` и сохраняется в `total`.

## Данные от пользователя приходят как строка
- Чтобы пользователь сам вводил количество, делаем веб-страницу с полем ввода и кнопкой submit. (Детали DOM — в UI hard parts; здесь фокус на JavaScript.)
- Значение из поля достаётся так:
```js
let quantity; // изначально без значения, используем let
// при submit:
quantity = document.getElementById('q').value;
```
- **Важно:** хотя пользователь ввёл число 3, в JavaScript оно приходит как **строка** `'3'`, а не как число `3`.

## Функция onSubmit и проблема coercion
```js
function onSubmit() {
  total = price * quantity; // price = 7, quantity = '3'
}
```
- `onSubmit` навешивается обработчиком (handler) на click-событие кнопки submit и запускается при клике (создаётся новый execution context).
- Внутри: `total = price * quantity`, где `price` — число 7, а `quantity` — строка `'3'`.
- **Важно:** `'3'` — это строка, не число. Она ничем не лучше буквы `A` или `'A3'`: символ `3` в строке не является числовым значением, над которым можно делать математику.
- В «строгом» языке `число * строка` было бы ошибкой.

## toNumber coercion спасает ситуацию
- JavaScript с самого начала проектировался как язык-посредник между двумя средами: DOM (где число 3 пришло как строка `'3'`) и JavaScript-логикой.
- Как только движок видит **math operator** (`*`) и одну сторону число, а другую — строку, он запускает **type coercion**.
- Запускается **toNumber** (приведение к числу): строка `'3'` превращается в число `3`, число `7` уже число.
- Получается `7 * 3 = 21`, результат сохраняется в `total` — без ошибки, через обычное умножение.

## Главное
- Данные из DOM (от пользователя) приходят в JavaScript как **строки**, даже если выглядят как числа.
- **operator** — это «диспетчер действия» над соседними operands; математический оператор при несовпадении типов запускает **type coercion**.
- Умножение строки `'3'` на число автоматически запускает **toNumber**, приводя `'3'` к числу `3`; это дизайнерская фича для работы на границе DOM ↔ JavaScript.
