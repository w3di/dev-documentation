# Часть 32. Event loop

## Что проверяет JavaScript

- Нужен механизм, который проверяет:
  1. Пуст ли call stack?
  2. Завершился ли весь глобальный код?
  3. Есть ли что-то в callback queue?
- Этот механизм — **event loop** (цикл событий). Он сидит между очередью и call stack.

## Как работает event loop

- Перед запуском каждого кусочка кода event loop в цикле непрерывно проверяет одно и то же: пуст ли call stack, завершён ли весь global-код, есть ли что-то в callback queue.
- Пример на коде из прошлой части:
  1. Пока в call stack `blockForOneSec` — call stack не пуст, callback queue ждёт.
  2. По завершении `blockForOneSec` event loop НЕ выпускает очередь: остался ещё global-код (`console.log("me first")` и т.д.).
  3. Только когда выполнен последний `console.log("me first")`, call stack пуст и весь global-код завершён.
  4. `printHello` ждала в очереди с самого начала (она сразу завершилась и была поставлена в очередь). Теперь event loop видит, что условия выполнены, выводит её из очереди (dequeue) и кладёт в call stack — функция выполняется.

## Условия для запуска из очереди (строго)

- Функция из callback queue попадёт в call stack только когда:
  1. call stack полностью пуст, И
  2. весь глобальный код завершён.

## Сводка расширенной модели

- От базовой модели (synchronous-исполнение построчно + memory + call stack) перешли к расширенной:
  - добавлен пакет инструментов — web browser features (в Node — Node background features);
  - возможность запускать их из JS через facade functions: они вызываются со скобками, принимают аргументы; имена фич на MDN часто отличаются от JS-ярлыков;
  - правила и структуры для возврата результата фоновой работы в JS, ради предсказуемости.
- Когда фоновая работа завершена, связанная функция (триггерящая JS-код в единственном потоке) ставится в callback queue, чтобы не «приземлиться» в произвольный момент.
- event loop на каждом «тике» проверяет, можно ли что-то запустить из callback queue: только при пустом call stack и завершённом глобальном коде.

## Замечание про Node

- event loop проверяет именно callback queue; могут быть и другие очереди (намёк на microtask queue).
- В Node очередей может быть несколько (несколько разных очередей) — деталь, разбираемая в «Node, the hard parts».

## Главное

- event loop — механизм, который непрерывно проверяет: пуст ли call stack, завершён ли весь global-код, есть ли задачи в callback queue.
- Только при пустом call stack и полностью отработавшем глобальном коде event loop переносит функцию из очереди в call stack.
- Функция могла стоять в очереди готовой с самого начала, но ждёт выполнения этих условий — это и обеспечивает предсказуемость.
- В Node очередей может быть несколько (тема Node).
