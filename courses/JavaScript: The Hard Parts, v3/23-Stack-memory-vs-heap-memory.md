# Часть 23. Stack memory против heap memory

## Постановка задачи

- Демо: фича аутентификации. В браузере пользователь вводит имя и ID, нажимает submit.
- В глобальной памяти: `userStored` — объект `{ name: "Will", ID: 105 }`; `userSubmitted` — объект с пока неизвестными значениями; функция `onSubmit`.
- ID, пришедший из DOM как строка `"105"`, сразу приводится к числу `105` (например, унарным `+` или вызовом `Number()`).
- `onSubmit` вызывается при клике (не в момент объявления), создаёт новый execution context, где сравниваются `userSubmitted` и `userStored`.

## Проблема сравнения объектов

- При `userSubmitted == userStored` результат `false`, хотя содержимое выглядит одинаково.
- Переход на `===` (строгое равенство, без coercion) — тоже `false`.
- Причина: нужно различать хранение **by value** (по значению) и **by reference** (по ссылке).

## Primitive против non-primitive

- **Primitive** (примитивы: число `7`, строка `"3"`, `true` и т.п.) хранятся напрямую там, где объявлены. Условно это **stack memory** — но в JavaScript явно не определяется, просто «хранится напрямую».
- **Объекты** (non-primitive) могут объединять много примитивов и быть любого размера. Они хранятся не напрямую, а в **heap memory** (куча — большая гибкая область памяти).
- В переменной JavaScript хранит не сам объект, а **reference/pointer** (ссылка/указатель) — адрес позиции объекта в heap.

## Как это работает

- При объявлении `userStored` объект `{ name: "Will", ID: 105 }` уходит в heap; в памяти переменной остаётся лишь ссылка на позицию (условно `1001`).
- То же с `userSubmitted` (условно `1002`).
- JavaScript не даёт явного доступа к heap; объект доступен только через адрес (как почтовый индекс).
- В некоторых других языках с указателями можно делать **pointer math** (арифметику над адресами) — вычислять позиции в памяти, свободное место и т.п. В JavaScript этого нет.

## Что именно сравнивается

- При `==` и `===` сравниваются не содержимое объектов, а **pointers/references/addresses**.
- Сравнивается `1002 === 1001`? — то есть одна ли это позиция в памяти. Ответ — нет, поэтому `false`.

## Копирование по ссылке

```js
const anotherLink = userStored;
```

- Это НЕ копия и НЕ резервная копия объекта — копируется только адрес (ссылка на ту же позицию в heap).
- После присваивания `anotherLink === userStored` → `true`, потому что это одна и та же позиция в памяти.

## Следствия

- Встроенного способа сравнить содержимое объектов в JavaScript нет — при вычислении доступна только ссылка.
- Чтобы сравнить содержимое, нужно вручную обойти свойства (`name`, `ID`), вытащить их в память и сравнивать там.
- **Deep comparison** (глубокое сравнение) и **deep clone / deep copy** (глубокое клонирование) приходится реализовывать вручную, рекурсивно — неизвестно, сколько уровней вложенности у объекта.
- Гибкость heap осмысленна именно потому, что объекты могут содержать множество вложенных объектов.

## Функции тоже в heap

- Функции — первоклассные объекты, поэтому тоже хранятся в heap, а в памяти лежит ссылка на них.
- Когда функция «передавалась by reference» в другую функцию, передавалась именно ссылка на функцию, а не сама функция.
- В диаграммах это обычно не выделяют, так как чаще не влияет на результат; критично становится при сравнении объектов.

## Связь с Date

- Постановка следующей темы: вызов функции `Date` возвращает объект с timestamp «сейчас» в скрытом свойстве. Можно было бы предотвратить двойной клик submit (например, запретить повторную отправку в течение 1–2 секунд), но сравнивать такие объекты-таймстемпы напрямую нельзя — тема продолжается.

## Главное

- Примитивы хранятся by value (условно stack), объекты — by reference в heap; в переменной лежит pointer.
- `==`/`===` для объектов сравнивают адреса (references), а не содержимое — поэтому одинаковые на вид объекты не равны.
- Присваивание объекта копирует ссылку, а не данные; deep copy и deep comparison делаются вручную.
- Функции — тоже объекты в heap, передаются по ссылке.
