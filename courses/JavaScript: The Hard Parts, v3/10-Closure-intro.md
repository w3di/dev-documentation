# Часть 10. Closure: введение

## Где используется closure

- **closure** (замыкание — способность функции «помнить» данные из места своего рождения) возникает при **возврате функции из другой функции** — вторая грань higher-order functions (не только приём функции на вход, но и возврат).
- На closure построено множество практик и паттернов:
  - **once** — ограничивает, сколько раз функцию можно вызвать.
  - **memoize** (мемоизация) — сохраняет результат тяжёлых вычислений, чтобы не повторять уже сделанную работу.
  - **module pattern** (паттерн модулей) и встроенные модули JavaScript.
  - **iterators** (итераторы) — функция, возвращающая при каждом вызове следующий элемент массива (альтернатива for loop).
  - **partial application** (частичное применение) — важная часть functional programming.
  - Работа **асинхронности**: асинхронный callback при отложенном вызове должен иметь нужные данные — это обеспечивает closure. [Тема продолжается в разделе асинхронности.]

## Отправная точка: обычное поведение функции

- При каждом вызове функции создаётся новый execution context со своей временной **local memory** — только для данных внутри этого запуска.
- По завершении всё внутри удаляется, кроме **return**-значения. Следующий вызов начинается «с чистого листа» — прошлый запуск не запоминается.
- Это и нужно для предсказуемости: у чистой функции (**pure** — без side effects) единственное последствие — её return-значение; внутренняя работа замкнута внутри функции.

## Идея closure

- local memory иначе называют **variable environment** (окружение переменных) — данные, доступные «вокруг» внутри функции; синоним сиюминутных данных приложения — **state** (состояние).
- Обычно по завершении функции local memory удаляется (кроме return). 
- Вопрос: что, если функция могла бы удерживать «живые» данные **между** вызовами — не только временную, но и **persistent memory** (постоянную память), причём доступную только изнутри этой функции?
- Это позволило бы менять поведение функции: например, разрешить запуск только один раз (counter уже = 1 → больше не запускать) — всё «привязано» к функции.
- Всё начинается с возврата функции из другой функции. [Механика — в следующей части.]

## Главное

- closure появляется при возврате функции из функции.
- На нём держатся once, memoize, module pattern, iterators, partial application и асинхронность.
- Обычно local memory временна и стирается после возврата (кроме return-значения).
- closure даёт функции постоянную приватную память, сохраняемую между вызовами.
