# Часть 2. Call stack и хранение функций в памяти

## Как функция хранится в памяти

- Функция сохраняется в памяти один раз (define / declare), а использовать (use) её можно сколько угодно раз — ограничение лишь объём памяти.
- Детали хранения разбираются в разделе type coercion: часть данных хранится **напрямую** в памяти, а часть — как **references** (ссылки, по «pointer» — указателю) на другое место в памяти. Это может менять поведение.
- Пока это не имеет последствий, функция условно показывается «сохранённой прямо здесь». [? Последствия проявятся позже — тема продолжается в type coercion.]

## Зачем нужен call stack

- При запуске файла создаётся **global execution context** (глобальный контекст) — он включается автоматически, как только стартует JavaScript (аналог `main` в других языках, но вызывать его явно не нужно).
- При вызове функции создаётся свой execution context (thread + memory). После завершения нужно знать, куда вернуться.
- JavaScript не «знает» этого автоматически — нужен механизм отслеживания: какая функция выполняется сейчас и куда вернуться после.
- Этот механизм — **call stack** (стек вызовов): структура данных типа **stack** (стек), где важен только самый верхний элемент — то, что выполняется в данный момент. По завершении элемент снимается (**pop**).

## Три ключевые части runtime

- **Thread of execution** — выполнять код (do code).
- **Memory** — хранить данные (save stuff).
- **Call stack** — отслеживать, какая функция выполняется (keep track of what's being run).
- Всё остальное в языке — надстройки над этими тремя частями или смежно с ними.

## Работа call stack на примере

1. При старте JavaScript на дно стека помещается `global` — он лежит там, пока выполняется глобальный код.
2. Вызов `multiplyBy2(3)` → на стек добавляется `multiplyBy2` (с входом 3); теперь это верх стека → именно она выполняется.
3. По выходу из функции (по ключевому слову `return`) она **pop**-ается со стека. JavaScript не ищет, куда идти — просто смотрит, что теперь наверху стека (`global`), и продолжает там.
4. Второй вызов `multiplyBy2(10)` снова добавляет элемент на стек, `return` снимает его → возврат к `global`.

## Когда снимается global

- `global` снимается только когда код JavaScript завершён **и** не осталось ничего, что могло бы быть запущено позже.
- Намёк: бывают вещи, которые могут «вернуться» и запуститься позже — это ведёт к теме асинхронности. [Тема продолжается далее.]

## Главное

- Функция объявляется один раз, вызывается многократно; объявление лишь сохраняет код.
- Call stack отслеживает текущую выполняемую функцию: важен только верхний элемент, по `return` он pop-ается.
- Три опоры runtime: thread of execution, memory, call stack.
- `global` всегда на дне стека и снимается только по полному завершению программы.
