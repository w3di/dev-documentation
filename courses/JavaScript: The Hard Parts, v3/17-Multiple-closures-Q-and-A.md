# Часть 17. Несколько closure: вопросы и ответы

## Сброс counter или новый scope?
- Вопрос: при повторном вызове `outer` `counter` устанавливается в 0 — это «сброс» того же значения или новый scope?
- Ответ: каждый вызов `outer` — это **новый execution context**, в котором `counter` определяется заново как 0.
- В первом вызове `outer` обычно execution context (вместе с `counter = 0`) был бы полностью удалён. Но он не забывается, потому что наружу вернулась функция, которая удержала `counter = 0` в своём backpack.

## outer не имеет памяти между запусками
- **`outer` — обычная функция без backpack.** У неё нет памяти между запусками: каждый раз она просто создаёт `counter = 0` внутри и делает свою работу.
- Если бы `outer` завершилась без возврата функции, её `counter = 0` был бы навсегда забыт.
- `newFunc` и `anotherFunc` **никак не связаны** с `outer` после возврата: они не «ссылаются обратно» на `outer`, между ними нет постоянной связи и нет «сброса между вызовами».
- `newFunc` / `anotherFunc` — это возвращённые версии `add1` (из первого и второго запусков `outer` соответственно), к которым приклеен живой `counter = 0` в мини-памяти.
- При запуске `newFunc` его local memory каждый раз очищается, но persistent memory (backpack) сохраняется.

## Управление памятью и garbage collection
- Вопрос: освобождается ли память backpack?
- Пока живы метки `newFunc` / `anotherFunc`, их backpack существует.
- Если переприсвоить, например, `anotherFunc = null`, то в какой-то момент сработает **garbage collection** (сборка мусора) и данные будут удалены.

## Backpack и «утечки памяти»
- Содержимое backpack не очень видно явно из кода: нельзя просто обратиться к `anotherFunc.scope`. Посмотреть можно в **Chrome dev tools** (развернуть функцию и посмотреть её backpack).
- Это **не настоящая утечка памяти**: настоящий **memory leak** — это данные, к которым уже нельзя обратиться, но которые всё ещё занимают место.
- В backpack по определению можно обратиться к данным (запустив функцию), иначе JavaScript их бы туда не положил.
- JavaScript делает оптимизацию: в backpack попадают **только те данные, на которые функция реально ссылается**; остальное удаляется. Так что инадвертентной утечки быть не может.
- Возможен лишь «разговорный» вариант: разработчик не осознаёт, как много данных лежит в backpack (но это проблема, возможная и в других случаях).

## Немедленный вызов и module pattern
- Поскольку `outer` возвращает функцию, можно сразу вызвать её ещё одними скобками: `outer()()`.
- Именно так работают традиционные **module pattern** (паттерны модулей): функцию немедленно вызывают (immediately invoke), создавая постоянное и приватное пространство памяти для всего кода внутри модуля.
- Идея: иметь функцию-инициализатор, разворачивающую всё состояние (state), внутри которой определена функция с основной работой; это функция-обёртка для постоянного использования — суть module pattern.

## Главное
- `outer` — обычная функция без памяти между запусками; постоянную память имеют только возвращаемые из неё функции через свой backpack.
- В backpack JavaScript кладёт только реально используемые данные, поэтому это не утечка памяти; данные освобождаются garbage collection после потери ссылки (например, `= null`).
- Возможность немедленно вызвать возвращённую функцию (`outer()()`) лежит в основе **module pattern** — приватного постоянного пространства памяти.
