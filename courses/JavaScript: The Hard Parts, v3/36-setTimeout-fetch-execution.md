# Часть 36. Полное выполнение setTimeout и fetch

## Постановка задачи
- Цель — проследить правила, по которым данные асинхронной работы возвращаются обратно в JavaScript после завершения фоновой работы.
- В примере объединены два стиля: «старая школа» (**setTimeout** с callback) и «новая школа» (**fetch** с двумя последствиями — Promise и работа в web browser).
- Функция, привязанная к **Promise** для отображения данных, не может попасть на **call stack** напрямую — нужны правила/очередь.

## Компоненты системы
- **JavaScript land** (земля JavaScript): thread of execution (поток выполнения), memory (память), call stack.
- **Web browser land** (земля браузера): web browser features / APIs (возможности и API браузера).
- **callback queue** (очередь callback-функций) — часть системы.
- **event loop** (цикл событий) — проверяет: пуста ли call stack, завершён ли глобальный код; если да, перемещает функции из очереди на call stack.
- **server** (сервер) на стороне TikTok — компьютер, подключённый к интернету, готовый принимать запросы.
- **console** (консоль).

## Объявление функций
1. Объявляется функция `display` — код целиком кладётся в память, тело не вычисляется до вызова.
2. Объявляется функция `printHello`.
3. Объявляется функция `blockFor300ms` — выполняет долгий цикл (~300 мс), блокирующий единственный поток JavaScript напрямую (не фоновая работа).

## Вызов setTimeout
- Вызывается `setTimeout(printHello, 0)`.
- В JavaScript ничего интересного не выполняется — тело функции не исполняется.
- В web browser создаётся фоновая возможность — **timer** (таймер).
- Таймеру нужны: функция для вызова в конце (`printHello`) и время ожидания в миллисекундах (здесь 0).
- На завершении таймер вызовет `printHello` обратно в JavaScript: передаётся ссылка (reference) на функцию `printHello` в памяти.
- Таймер на 0 мс завершается сразу, поэтому `printHello` попадает не на call stack, а в **callback queue** (на отметке ~0 мс).

## Вызов fetch
- Слева объявляется `const futureData`, справа вызывается `fetch` с аргументом-строкой, содержащей домен и маршрут (route).
- `fetch` делает два главных дела (two-pronged — «двузубое» последствие):

### Последствие 1: работа в web browser
- Запускается сетевой запрос (network request) через возможность браузера.
- Передаётся домен и маршрут; неявно отправляется **GET**-запрос.
- На ~1 мс уходит HTTP-сообщение на сервер TikTok с запросом данных по пути `/will`.
- На отметке 1 мс работа ещё не завершена.

### Последствие 2: Promise object в JavaScript
- Создаётся **Promise object** (объект-обещание), сохраняемый в `futureData`.
- На нём есть скрытые свойства:
  - `value` — пока `undefined`;
  - `onFulfilled` (точнее, fulfill reactions) — пустой массив для функций, которые автоматически запустятся, когда `value` обновится.
- Сетевой запрос в браузере хранит ссылку на этот объект, созданный одновременно из двузубого `fetch`.
- Немедленный результат вызова `fetch` — «живой» объект (Promise), а не фоновая работа.
- На завершении фоновой работы `futureData.value` будет обновлено данными от TikTok.

## Привязка функции через .then
- Как только `value` заполнится реальными данными, любые функции из `onFulfilled` вызовутся автоматически, их входом станут эти данные.
- В скрытое свойство-массив нельзя пушить напрямую — используется встроенный метод `futureData.then`.
- Вызывается `.then(display)` — функция `display` (с параметром-заготовкой `data`) добавляется в массив `onFulfilled`.
- Ключевой момент: `display` сейчас НЕ запускается; она лишь сохраняется в массив, чтобы выполниться позже автоматически.
- Слово `then` вводит в заблуждение: точнее было бы `addThisFunctionToRunLater` — оно лишь добавляет функцию на выполнение позже, а не «прямо сейчас».

## Главное
- `fetch` имеет два последствия: сетевой запрос в браузере и создание Promise object в JavaScript (со скрытыми `value` и `onFulfilled`).
- `setTimeout` ставит callback в callback queue по завершении таймера; `.then` лишь добавляет функцию в массив `onFulfilled` Promise object, не запуская её.
- Функции из `onFulfilled` запускаются автоматически при обновлении `value`, и им автоматически передаются полученные данные.
