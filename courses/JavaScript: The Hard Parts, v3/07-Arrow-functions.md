# Часть 7. Arrow functions и встроенный map

## Четыре версии одной функции

- Современный стиль — **arrow function** (стрелочная функция). Та же `multiplyBy2` проходит 4 эквивалентных версии — от тяжёлого синтаксиса до компактного:

```js
// 1) function keyword
function multiplyBy2(input) { return input * 2; }

// 2) arrow + тело с return
const multiplyBy2 = (input) => { return input * 2; };

// 3) неявный возврат (один return → без {} и без return)
const multiplyBy2 = (input) => input * 2;

// 4) один параметр → можно без скобок
const multiplyBy2 = input => input * 2;
```

- Все версии сохраняют в памяти одно и то же определение функции и выполняются одинаково: вызов создаёт execution context, `input` ← аргумент, возвращается `input * 2`.
- Версия 3 опускает `{}` и `return`: при единственном return JavaScript автоматически вставит return и вернёт `input * 2`.
- Аргумент за использование `function`: ключевое слово ясно сигналит «это сохраняемый код», тогда как arrow-стиль (особенно как анонимная функция) часто *ошибочно* читают как выполнение кода прямо на месте. Это лишь сохранение определения, не выполнение.

## Нюанс arrow functions на будущее

- Стрелочные функции имеют отличие в **implicit parameter assignment** — на что указывает ключевое слово `this`. У arrow functions поведение `this` иное и удобное: при вызове функции внутри другой функции `this` ссылается на нужный объект, а не на глобальный. Подробнее — позже. [Тема продолжается.]

## Анонимная передача и map

- callback можно передать напрямую без имени — **anonymous function** (анонимная функция, «без имени»). Близко к стилю lambda в Python.
- Встроенный аналог `copyArrayAndManipulate` — метод **map**, один из важнейших в программировании:
  - берёт данные, применяет операцию к каждому элементу, возвращает новый массив; исходные данные не меняет.
  - типичное применение: превратить список данных (песни, твиты) в список UI-элементов, не меняя сами данные.

```js
const result = [1, 2, 3].map(input => input * 2); // [2, 4, 6]
```

- Через **dot notation** (точечную нотацию) массив `[1,2,3]` неявно вставляется как данные, над которыми работает map. Внутри происходит то же, что в самописном варианте; map доступен всем массивам через **prototype chain** (цепочку прототипов — разбирается позже).
- Различать: самописный `map` (переименованный `copyArrayAndManipulate`) и встроенный `.map`. Список встроенных методов массива — в документации (MDN).

## О производительности и читаемости

- Микро-различия (сохранять ли функцию в константу или передавать напрямую) практически не влияют на производительность.
- Главный «бутылочный горлышко» и ценность — время разработчика и команды, поэтому приоритет — **legibility и readability** (понятность и читаемость) кода.

## Замечания о стиле

- Отдельное именованное определение функции лучше показывает её поведение (полезно для коммуникации).
- В functional programming часто цепочкой передают задачи напрямую (анонимно) — компактно, но может скрывать происходящее.
- arrow functions и встроенные методы массива «прихорашивают» код, не меняя его работы под капотом.

## Главное

- 4 версии записи функции эквивалентны; arrow — лишь синтаксический сахар (кроме поведения `this`, о чём позже).
- arrow-стиль легко спутать с выполнением на месте — это всё ещё лишь сохранение определения.
- map — встроенный неизменяющий HOF: применяет callback к каждому элементу, возвращает новый массив.
- Читаемость кода важнее микро-оптимизаций производительности.
