# Часть 38. Microtask queue — вопросы и ответы

## Проблемы Promise
- Большинство разработчиков не понимают, как Promise работает «под капотом».
- Распространённая ошибка: считать, что функция `display` запускается в момент передачи в `then`. На деле:
  1. `fetch` настраивает фоновую работу;
  2. в JavaScript сохраняется объект (Promise), связанный с этой работой;
  3. к нему привязывается функция, которая запустится только по завершении фоновой работы;
  4. её аргумент автоматически заполняется полученными данными.
- Из-за непонимания этого отладка Promise тяжела, и разработчики проваливают технические интервью.

## Преимущества Promise-стиля
- Более чистый и читаемый код в псевдосинхронном стиле.
- В отличие от `setTimeout` (где функция передаётся внутрь и «уезжает» на потом), здесь функция тоже отложена, но передаётся после слова `then`.
- Удобная обработка ошибок.

## Обработка ошибок: reject reactions и .catch
- Если вместо `"cute puppy"` вернётся ошибка (нет ответа сервера, нет доступа к видео), Promise-стиль даёт инструмент её обработки.
- На Promise object есть ещё один скрытый массив — **reject reactions** (реакции на отклонение).
- В него привязываются функции, которые запустятся при возврате ошибки и присвоении её свойству `value`/`result`.
- При ошибке автоматически вызывается не массив fulfilled, а массив rejected.
- Привязка к этому массиву — не через `.then`, а через `.catch` (передаётся функция, которая автоматически запустится с ошибкой).

## Сводка правил выполнения асинхронного кода
1. Promise-отложенные функции хранятся в **microtask queue**, callback из старых средств (например, `setTimeout`) — в **callback queue**.
2. По завершении web browser API функции попадают в соответствующие очереди.
3. Функция добавляется на call stack (запускается) только когда call stack пуст и весь глобальный код выполнен — за этим постоянно следит **event loop**.
4. Функции из microtask queue приоритетнее функций из callback queue.

## Бонус: прерывание fetch через abort signal
- Возможность прерывать (abort) фоновую задачу `fetch` появилась в 2017 г.; вариант на основе таймаута (**abort signal timeout**) — в 2022 г.
- Применяется, когда не нужно ждать ответа (например, сервер может никогда не ответить).

### Как это работает
- Вторым аргументом в `fetch` можно передать объект. У него может быть свойство метода (GET/POST), но здесь используется свойство `signal`.
- Объявляется `signal` = результат вызова встроенного `AbortSignal.timeout(...)`.
- Этот вызов двузубый (two-pronged): в JavaScript возвращает объект со свойствами (НЕ скрытыми, видимыми):
  - `aborted` — изначально `false`;
  - `reason` — изначально `undefined`.
- Этот объект передаётся в `fetch` и меняет поведение сетевого запроса.

### Последствия объявления signal
1. Создаётся объект в JavaScript (с `aborted`/`reason`).
2. В фоне (web browser) запускается **timer** (например, на 200 мс).
- При передаче объекта в `fetch` создаётся связь (bond) между фоновым сетевым запросом и этим таймером: если таймер завершится, сетевая работа отменяется и возвращается ошибка.

### Пример с таймаутом
- В исходном примере ответ пришёл на 270 мс. Но с таймером на 200 мс на ~201 мс таймер завершился бы.
- Это отменило бы сетевой запрос, вернув ошибку (timeout error) вместо `"cute puppy"`.
- Ошибка попала бы в `result`, и вызвались бы НЕ функции массива fulfilled, а функции массива reject (привязанные через `.catch`).
- Свойство `aborted` стало бы `true`, `reason` — `timeout error`.

## Итог: неблокирующие приложения
- Promise, web APIs, callback queue, microtask queue и event loop вместе позволяют строить неблокирующие (non-blocking) приложения.
- Можно продолжать выполнять код (`blockFor300ms`, `console.log("me first")`) сразу после запуска фоновых задач, не дожидаясь их завершения.
- Так как момент завершения фоновой работы (особенно сетевой) непредсказуем, JavaScript сам запускает функцию по завершении: не пишут «жди здесь данные», не пытаются угадать время, не ставят скобки вручную.
- При возврате в JavaScript скобки добавляются автоматически, а данные вставляются в аргумент.
- Это основа современного веба: «однопоточность» — это один поток в JavaScript плюс большой объём фоновой работы за кулисами.

## Главное
- На Promise object два скрытых массива: fulfill reactions (через `.then`) и reject reactions (через `.catch`); при ошибке выполняются только reject reactions.
- `AbortSignal.timeout(...)` создаёт объект-сигнал и фоновый таймер; передача его в `fetch` отменяет сетевой запрос по истечении таймера и возвращает ошибку.
- Promise + web APIs + очереди + event loop дают неблокирующие приложения; JavaScript автоматически запускает отложенные функции и подставляет в них данные.
