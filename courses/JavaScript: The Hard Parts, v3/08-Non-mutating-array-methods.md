# Часть 8. Неизменяющие (non-mutating) методы массива

## Контекст: не менять входные данные

- `copyArrayAndManipulate` и встроенный `map` возвращают **новый** массив, не меняя исходный.

```js
const myArray = [1, 2, 3];
const result = myArray.map(x => x * 2); // result = [2,4,6], myArray = [1,2,3]
```

- Это важно: функция не должна иметь последствий вне своего явного output. Изменение входных данных — это side effect, не описанный в определении функции.

## Проблема: старые мутирующие методы

- Некоторые встроенные методы массива (с первых дней JS) меняют (**mutate**) сам массив, на котором вызваны: **reverse**, **sort**, **splice**.
- Это называют «преступлением»: при волне изменений ES6 (2015) их оставили мутирующими ради совместимости.
- Пример (всё применяется к одному `array1`, мутируя его):

```js
const array1 = [1, 2, 3];
array1.reverse();      // array1 → [3,2,1]
array1.splice(1, 1, 6);// array1 → [3,6,1] (на позиции 1 заменить 1 элемент на 6)
array1.sort();         // array1 → [1,3,6]
```

- `reverse()` не возвращает новый перевёрнутый массив для присваивания — он мутирует входной.
- `splice` принимает позицию и число изменяемых элементов и заменяет их.
- Почему это плохо: для UI данные часто берут, чтобы показать их (например, в обратном порядке), но не чтобы менять сами данные. В UI-окружении особенно нельзя менять underlying data.

## Решение: новые non-mutating методы

- Добавлены неизменяющие аналоги: **toReversed**, **toSpliced**, **toSorted** (ES2023). Внутри они создают новый массив с изменёнными элементами — как `copyArrayAndManipulate`.

```js
const array2 = [1, 2, 3];
const reversed = array2.toReversed();    // [3,2,1], array2 не тронут
const spliced  = array2.toSpliced(1,1,6);// [1,6,3], array2 не тронут
const sorted   = array2.toSorted();      // [1,2,3], array2 не тронут
```

- Их можно **chain** (сцеплять): каждый возвращает новый массив, исходный `array2` остаётся неизменным.

## Прочие современные методы массива (обзор)

- Смысл — не зубрить список фич, а видеть, что JS постоянно добавляет HOF, не мутирующие вход. Подробности — в документации по мере надобности.
- **flat** (ES2019) — «разворачивает» вложенный массив на один уровень; не мутирует:

```js
[1, 2, [1, 2, 2]].flat(); // [1,2,1,2,2]
```

  - аргумент **depth** (глубина) задаёт, сколько слоёв разворачивать (по умолчанию 1); можно передать `Infinity` для любой глубины.
- **findLastIndex** — ищет с конца; принимает callback, возвращающий true/false, и отдаёт индекс последнего подходящего элемента:

```js
[1,2,1,2,2].findLastIndex(el => el === 2); // 4
```

- **groupBy** — популярна в SQL; по callback группирует элементы. Каждая возвращённая callback-метка становится ключом в объекте-результате, а соответствующие значения — массивом под этим ключом (например, even / odd). Не мутирует вход.

## Главное

- Старые `reverse`, `sort`, `splice` мутируют исходный массив — это нежелательный side effect, особенно в UI.
- Новые `toReversed`, `toSpliced`, `toSorted` возвращают новый массив и сцепляются без мутации.
- `flat`, `findLastIndex`, `groupBy` и др. — примеры продолжающегося добавления неизменяющих HOF.
- Базовая модель массивных методов: создать новый массив, применить инструкции к каждому элементу, вернуть новый массив.
