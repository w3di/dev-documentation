# Часть 47. Рефакторинг userCreator с ключевым словом new

## Объявление функции userCreator

```js
function userCreator(name, score) {
  this.name = name;
  this.score = score;
}
userCreator.prototype.increment = function () { this.score++; };

const user1 = new userCreator("Ari", 3);
```

- Объявляется функция `userCreator` — это **function-object combo** (функция-объект): одновременно функция и объект.
- У этого объекта по умолчанию есть свойство **prototype** — большой пустой объект.
- Любая объявленная функция автоматически: и функция, и объект; у её объектной части автоматически есть свойство `prototype` (пустой объект).
- Это не скрытое `[[Prototype]]`. Скрытое свойство (proto) есть и у самого объекта `prototype`, и так далее по цепочке вверх до `Object.prototype`, чей proto равен `null` (protos all the way down).

## Заполнение userCreator.prototype

1. Ищется `userCreator` — найдено.
2. Через точку обращаемся к объектной части (а не функциональной — у неё были бы скобки).
3. Находим свойство `prototype` — это пустой объект.
4. Ищем на нём свойство `increment` — нет → JS его создаёт (JS либо находит свойство, либо создаёт).
5. Присваиваем `increment` функцию с телом `this.score++`.

- Результат тот же, что раньше с `userFunctionStore`, но объект-хранилище предоставлен JS автоматически — это `userCreator.prototype`.

## Вызов new userCreator("Ari", 3)

- Слева объявляется константа `user1`. Значение пока неизвестно — вызывается `userCreator` с обычными скобками и аргументами `"Ari"`, `3`, но с ключевым словом **new** впереди.
- Создаётся новый execution context.

### Шаг 1 — argument/parameter setup

1. В local memory: параметр `name` = `"Ari"`, параметр `score` = `3`.
2. Передача аргументов не добавляет их на объект — это просто данные в local memory.

### Шаг 2 — автоматическое создание объекта (делает new)

1. `new` автоматически создаёт в памяти большой пустой объект.
2. Метка для доступа к нему — `this` (implicit parameter). Здесь `this` ссылается на авто-созданный объект (в отличие от прежнего смысла «объект слева от точки»).

### Шаг 3 — автоматическая установка proto-ссылки (делает new)

1. Объект создан автоматически, поэтому bond вручную не делается.
2. `new` автоматически устанавливает скрытую proto-ссылку объекта на объектную форму функции `userCreator`, на её свойство `prototype` (тот самый объект с `increment`).

### Шаг 4 — ручное присвоение свойств

1. К авто-созданному объекту обращаемся через метку `this`.
2. `this.name = name` — создаётся свойство `name` со значением `"Ari"`.
3. `this.score = score` — создаётся свойство `score` со значением `3`.

### Шаг 5 — автоматический возврат (делает new)

1. Явного `return` в функции нет.
2. `new` автоматически возвращает объект `this`.
3. Объект сохраняется в `user1`: `name: "Ari"`, `score: 3`, скрытая proto-ссылка на store функций.

- Всё «синее» (создание объекта, proto-ссылка, возврат) делает `new`; разработчик не выбирает это.

## Lookup user1.increment

1. `user1` ищется в global — найдено.
2. `increment` на свойствах `user1` нет → не паникуем.
3. Идём по скрытой proto-ссылке вверх — на объектную форму `userCreator`, на её свойство `prototype` (объект).
4. Находим `increment` — создаётся новый execution context.
5. В local memory `this` автоматически = объект слева от точки = `user1`.
6. `this.score++` = `user1.score++`, значение инкрементируется на 1.

## Итог рефакторинга

- Внутри `userCreator` не нужно создавать объект (`new` сделал это, доступ через `this`) и не нужно возвращать объект (`new` вернул).
- Единственное, что делается вручную, — присвоение аргументов на объект.
- Не нужен отдельный `userFunctionStore`: общие функции кладутся в готовый `userCreator.prototype`, где JS автоматически делает bond для объектов из `new`-вызова.
- Можно добавить и `login` туда же — `user1` получит доступ и к `increment`, и к `login`. Под капотом ничего не изменилось по сравнению с solution 2.

## Главное

- `new` внутри одного вызова делает: создаёт пустой объект, привязывает его скрытую proto-ссылку к `userCreator.prototype`, возвращает объект.
- Авто-созданный объект адресуется через **this**; свойства на него присваиваются вручную (`this.name`, `this.score`).
- Общие методы кладутся в **prototype property** функции-конструктора (`userCreator.prototype`) — туда JS автоматически направляет lookup объектов.
- Код становится компактным, но механика та же, что и при ручном `Object.create` (solution 2).
