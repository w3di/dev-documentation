# Структура проекта — файловые конвенции Next.js

> Next.js использует **файловую систему как маршрутизатор**: папки определяют сегменты URL,
> а специальные файлы (`page.tsx`, `layout.tsx`, `error.tsx`) определяют UI для каждого
> сегмента. Понимание файловых конвенций — основа работы с App Router.

## 1. Верхнеуровневые папки

| Папка | Назначение |
|-------|-----------|
| `app/` | App Router — рекомендуется для Next.js 13+ |
| `pages/` | Pages Router — устоявшийся, но уступает `app/` |
| `public/` | Статические ресурсы, доступные по URL (`/favicon.ico`, `/images/logo.png`) |
| `src/` | Необязательная обёртка для исходников (`src/app/`, `src/pages/`) |

## 3. Файлы маршрутизации

Специальные файлы в сегментах маршрутов `app/`:

| Файл | Назначение |
|------|-----------|
| `layout.tsx` | Общий каркас, оборачивает дочерние сегменты. Сохраняет состояние при навигации |
| `page.tsx` | Страница — публичный маршрут. Без `page.tsx` сегмент не является маршрутом |
| `loading.tsx` | Скелет загрузки (React Suspense boundary) |
| `error.tsx` | Локальная error boundary |
| `global-error.tsx` | Глобальная error boundary на корне (должна содержать `<html>` и `<body>`) |
| `not-found.tsx` | UI для 404 |
| `route.ts` | API endpoint (Route Handler) — **не может** быть в одном сегменте с `page.tsx` |
| `template.tsx` | Как `layout`, но **пересоздаётся** при каждой навигации (сбрасывает состояние) |
| `default.tsx` | Fallback для параллельных маршрутов |

## 4. Динамические маршруты

| Синтаксис | Пример URL | `params` |
|-----------|-----------|----------|
| `[slug]` | `/blog/hello` | `{ slug: 'hello' }` |
| `[...slug]` | `/blog/a/b/c` | `{ slug: ['a', 'b', 'c'] }` |
| `[[...slug]]` | `/blog` или `/blog/a/b` | `{ slug: undefined }` или `{ slug: ['a', 'b'] }` |

- `[slug]` — один параметр.
- `[...slug]` — **catch-all**: захват всех оставшихся сегментов (обязателен минимум один).
- `[[...slug]]` — **optional catch-all**: как catch-all, но маршрут без параметров тоже работает.

## 5. Группы маршрутов и приватные папки

### Группы маршрутов `(groupName)`

Не влияют на URL — только для организации:

```
app/
├── (marketing)/
│   ├── layout.tsx     ← layout только для marketing
│   ├── about/page.tsx   → /about
│   └── blog/page.tsx    → /blog
├── (admin)/
│   ├── layout.tsx     ← layout только для admin
│   └── dashboard/page.tsx → /dashboard
```

Можно создать **несколько root layouts** через группы маршрутов.

### Приватные папки `_folderName`

Исключаются из маршрутизации. Для внутренних файлов:

```
app/
├── _components/      ← не маршрут
│   └── Header.tsx
├── _lib/             ← не маршрут
│   └── utils.ts
└── page.tsx          → /
```

**Важно**: даже без `_` файлы в `app/` не становятся маршрутами без `page.tsx` или `route.ts` в сегменте.

## 6. Параллельные и перехватываемые маршруты

### Параллельные маршруты `@slot`

Именованные слоты, рендерящиеся одновременно в layout:

```
app/
├── layout.tsx         ← принимает @analytics и @team
├── @analytics/
│   └── page.tsx
├── @team/
│   └── page.tsx
└── page.tsx
```

```tsx
// app/layout.tsx
export default function Layout({ children, analytics, team }) {
  return (
    <>
      {children}
      {analytics}
      {team}
    </>
  )
}
```

### Перехватываемые маршруты

| Конвенция | Описание |
|-----------|----------|
| `(.)folder` | Перехват на том же уровне |
| `(..)folder` | Перехват родителя |
| `(..)(..)folder` | Два уровня выше |
| `(...)folder` | Перехват от корня |

Типичный кейс: модальное окно поверх списка без смены URL.

## 7. Иерархия специальных компонентов

Порядок рендера в пределах одного сегмента:

```
layout.tsx
  └── template.tsx
        └── error.tsx (ErrorBoundary)
              └── loading.tsx (Suspense)
                    └── not-found.tsx (ErrorBoundary)
                          └── page.tsx | layout.tsx (вложенный)
```

Компоненты каждого вложенного сегмента **рекурсивно вставляются** внутрь компонентов родительского сегмента.

## 9. Колокация и организация кода

Маршрут становится публичным **только при наличии** `page.tsx` или `route.ts` в сегменте. Это значит:

- Компоненты, утилиты, тесты, стили можно хранить **рядом с маршрутом** в `app/`.
- Они не станут маршрутами автоматически.

```
app/dashboard/
├── page.tsx           ← маршрут /dashboard
├── _components/
│   └── Chart.tsx      ← не маршрут
├── utils.ts           ← не маршрут
└── chart.test.ts      ← не маршрут
```

### Использование `src/`

Изолирует исходники от конфигурации в корне:

```
├── src/
│   ├── app/
│   ├── lib/
│   └── middleware.ts
├── next.config.js
├── package.json
└── tsconfig.json
```

## 10. Рекомендации

- **Используйте `app/`** (App Router) для новых проектов.
- **Группы маршрутов** `(group)` — для организации без влияния на URL.
- **Приватные папки** `_folder` — для явного отделения от маршрутизации.
- **Колокация** — держите компоненты и утилиты рядом с маршрутами, которые их используют.
- Рассмотрите **`src/`** для чистого разделения исходников и конфигурации.
- Параллельные и перехватываемые маршруты — для сложных UI-паттернов (модальные окна, split-view).
- `template.tsx` вместо `layout.tsx` — когда нужен сброс состояния при навигации.
