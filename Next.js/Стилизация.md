# Стилизация в Next.js — подходы к CSS и управление стилями

> Next.js поддерживает несколько способов стилизации: Tailwind CSS, CSS Modules, Global CSS, Sass, CSS-in-JS и inline-стили. Выбор подхода зависит от масштаба проекта, требований к scoping и совместимости с Server Components.

## 1. CSS Modules

CSS Modules обеспечивают локальный scoping стилей, генерируя уникальные имена классов. Это исключает конфликты имён между компонентами.

Файл должен иметь расширение `.module.css`:

```css
/* app/blog/blog.module.css */
.blog {
  padding: 24px;
}
```

Импорт в компоненте:

```tsx
// app/blog/page.tsx
import styles from './blog.module.css'

export default function Page() {
  return <main className={styles.blog}>Контент блога</main>
}
```

**Ключевые особенности:**

- Каждый класс преобразуется в уникальный идентификатор (например, `.blog_abc123`)
- Работает и в Server Components, и в Client Components
- Поддерживает композицию через `composes`
- Можно комбинировать с [Sass](#5-sass) через расширение `.module.scss`

## 2. Global CSS

Глобальные стили применяются ко всему приложению. Создайте файл `app/globals.css` и импортируйте его в [[Layouts и Pages|root layout]]:

```css
/* app/globals.css */
body {
  padding: 20px 20px 60px;
  max-width: 680px;
  margin: 0 auto;
}
```

```tsx
// app/layout.tsx
import './globals.css'

export default function RootLayout({ children }: { children: React.ReactNode }) {
  return (
    <html lang="ru">
      <body>{children}</body>
    </html>
  )
}
```

> **Важно:** глобальные стили можно импортировать в любом layout, page или component внутри `app/`. Однако Next.js использует React Suspense для интеграции стилей и **не удаляет стили при навигации между маршрутами**, что может приводить к конфликтам. Рекомендуется использовать глобальные стили только для действительно глобального CSS (base-стили Tailwind), а для компонентов -- CSS Modules или Tailwind.

**Внешние стили** (из npm-пакетов) также импортируются напрямую:

```tsx
import 'bootstrap/dist/css/bootstrap.css'
```

## 3. Tailwind CSS

Utility-first CSS фреймворк, рекомендуемый Next.js для большинства задач стилизации.

### Установка

```bash
npm install -D tailwindcss @tailwindcss/postcss
```

### Конфигурация PostCSS

```js
// postcss.config.mjs
export default {
  plugins: {
    '@tailwindcss/postcss': {},
  },
}
```

### Подключение в globals.css

```css
/* app/globals.css */
@import 'tailwindcss';
```

### Импорт в root layout

```tsx
// app/layout.tsx
import './globals.css'

export default function RootLayout({ children }: { children: React.ReactNode }) {
  return (
    <html lang="ru">
      <body>{children}</body>
    </html>
  )
}
```

### Использование utility-классов

```tsx
export default function Page() {
  return (
    <main className="flex min-h-screen flex-col items-center justify-between p-24">
      <h1 className="text-4xl font-bold">Next.js + Tailwind</h1>
    </main>
  )
}
```

**Best practices для Tailwind в Next.js:**

- Используйте Tailwind для большинства стилей компонентов
- Держите глобальные стили минимальными (base-стили)
- Интегрируйте шрифты через CSS-переменные (см. [[Fonts]])
- Для Tailwind v3 используйте `tailwind.config.js` с `content` массивом

## 4. CSS-in-JS

CSS-in-JS библиотеки **работают только в Client Components** в App Router. Server Components не поддерживают runtime CSS-in-JS.

### Поддерживаемые библиотеки

`styled-components`, `styled-jsx`, `@mui/material`, `chakra-ui`, `vanilla-extract`, `pandacss`, `stylex`, `tamagui`, `kuma-ui`, `tss-react`.

> `emotion` -- в процессе поддержки.

### Паттерн Style Registry

Настройка CSS-in-JS в App Router требует трёх шагов:

1. **Style Registry** -- собирает все CSS-правила при рендере
2. **`useServerInsertedHTML`** -- инжектирует правила перед контентом
3. **Client Component-обёртка** -- оборачивает приложение при SSR

### Пример: styled-components

Включите в `next.config.js`:

```js
// next.config.js
module.exports = {
  compiler: {
    styledComponents: true,
  },
}
```

Создайте registry:

```tsx
// lib/registry.tsx
'use client'

import React, { useState } from 'react'
import { useServerInsertedHTML } from 'next/navigation'
import { ServerStyleSheet, StyleSheetManager } from 'styled-components'

export default function StyledComponentsRegistry({
  children,
}: {
  children: React.ReactNode
}) {
  const [styledComponentsStyleSheet] = useState(() => new ServerStyleSheet())

  useServerInsertedHTML(() => {
    const styles = styledComponentsStyleSheet.getStyleElement()
    styledComponentsStyleSheet.instance.clearTag()
    return <>{styles}</>
  })

  if (typeof window !== 'undefined') return <>{children}</>

  return (
    <StyleSheetManager sheet={styledComponentsStyleSheet.instance}>
      {children}
    </StyleSheetManager>
  )
}
```

Оберните root layout:

```tsx
// app/layout.tsx
import StyledComponentsRegistry from './lib/registry'

export default function RootLayout({ children }: { children: React.ReactNode }) {
  return (
    <html>
      <body>
        <StyledComponentsRegistry>{children}</StyledComponentsRegistry>
      </body>
    </html>
  )
}
```

> При SSR стили извлекаются в глобальный registry и вставляются в `<head>`. При стриминге стили каждого chunk собираются и добавляются к существующим. После гидратации `styled-components` работает как обычно.

## 5. Sass

Next.js имеет встроенную поддержку Sass (`.scss` и `.sass`) после установки пакета.

### Установка

```bash
npm install --save-dev sass
```

### Конфигурация sassOptions

```ts
// next.config.ts
import type { NextConfig } from 'next'

const nextConfig: NextConfig = {
  sassOptions: {
    additionalData: `$var: red;`,
  },
}

export default nextConfig
```

Можно указать альтернативную реализацию:

```ts
sassOptions: {
  implementation: 'sass-embedded',
}
```

### Sass-переменные в CSS Modules

```scss
// app/variables.module.scss
$primary-color: #64ff00;

:export {
  primaryColor: $primary-color;
}
```

```tsx
// app/page.tsx
import variables from './variables.module.scss'

export default function Page() {
  return <h1 style={{ color: variables.primaryColor }}>Hello!</h1>
}
```

> `.scss` -- расширение SCSS-синтаксиса (надмножество CSS), `.sass` -- индентированный синтаксис. Рекомендуется `.scss` для начинающих.

## 6. PostCSS

Next.js использует PostCSS для обработки CSS. Конфигурация задаётся в `postcss.config.mjs` в корне проекта.

### Кастомная конфигурация

```js
// postcss.config.mjs
export default {
  plugins: {
    '@tailwindcss/postcss': {},
    autoprefixer: {},
    'postcss-nested': {},
  },
}
```

**Важно:** при наличии файла `postcss.config.mjs` Next.js использует **только** указанные в нём плагины, отключая дефолтные. Убедитесь, что включили все нужные плагины.

## 7. Inline стили

Применяются через атрибут `style` напрямую к элементу:

```tsx
export default function Page() {
  return <h1 style={{ color: 'red', fontSize: '2rem' }}>Заголовок</h1>
}
```

**Когда использовать:** динамические стили из переменных/состояния, одноразовые стили, значения из API.

**Когда не использовать:** повторяющиеся стили, псевдоклассы/медиа-запросы (не поддерживаются), сложные анимации.

## 8. Сводная таблица -- сравнение подходов

| Подход | Scoping | Server Components | Типизация | Runtime | Рекомендация |
|---|---|---|---|---|---|
| **CSS Modules** | Локальный | Да | Да (через typed-css-modules) | Нет | Компонентные стили |
| **Global CSS** | Глобальный | Да | Нет | Нет | Base-стили, reset |
| **Tailwind CSS** | Utility | Да | Нет | Нет | Основной подход |
| **CSS-in-JS** | Локальный | Нет (только Client) | Да | Да | Динамические стили |
| **Sass** | Модульный/глобальный | Да | Нет | Нет | Сложная логика стилей |
| **PostCSS** | Зависит от плагинов | Да | Нет | Нет | Кастомная обработка |
| **Inline** | Инлайн | Да | Да (CSSProperties) | Нет | Динамические одноразовые стили |

### Порядок и мерж CSS

Next.js оптимизирует CSS при production-сборке, автоматически объединяя стили в минифицированные `.css`-файлы. Порядок CSS зависит от **порядка импорта** в коде.

**Рекомендации по предсказуемому порядку:**

- Содержите CSS-импорты в одном entry-файле
- Импортируйте глобальные стили и Tailwind в корне приложения
- Используйте единообразные имена для CSS Modules (`<name>.module.css`)
- Отключите автосортировку импортов (ESLint `sort-imports`)

> В development (`next dev`) CSS обновляется мгновенно через Fast Refresh. В production (`next build`) CSS автоматически разбивается на минифицированные chunks. CSS работает даже при отключённом JavaScript в production.
