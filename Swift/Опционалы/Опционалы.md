## Optional как enum

`Optional` — это обычный generic enum в стандартной библиотеке:

```swift
@frozen
enum Optional<Wrapped> {
    case none
    case some(Wrapped)
}

// Следующие записи эквивалентны:
let a: Optional<Int> = .some(42)
let b: Int? = 42
let c: Int? = nil  // .none
```

`nil` в Swift — это **не нулевой указатель** (как в C) и **не отдельный тип** (как `null`/`undefined` в JS). Это литерал, обозначающий `.none` для любого `Optional<T>`.

## Optional Binding

### if let

```swift
let name: String? = "Alice"

if let unwrapped = name {
    print("Hello, \(unwrapped)")  // "Hello, Alice"
}

// Swift 5.7+ — shorthand (shadowing)
if let name {
    print("Hello, \(name)")  // используется unwrapped name
}
```

### guard let

```swift
func greet(_ name: String?) {
    guard let name else {
        print("No name provided")
        return  // ОБЯЗАТЕЛЬНО выход из scope
    }

    // name гарантированно non-optional дальше
    print("Hello, \(name)")
}
```

### while let

```swift
let numbers = [1, 2, 3]
var iterator = numbers.makeIterator()

while let value = iterator.next() {
    print(value)  // 1, 2, 3
}

// Чтение строк
while let line = readLine() {
    print("Read: \(line)")
}
```

### Множественный binding

```swift
let first: String? = "John"
let last: String? = "Doe"
let age: Int? = 30

if let first, let last, let age, age >= 18 {
    print("\(first) \(last), age \(age)")
}

// Эквивалент с guard
guard let first, let last, let age else { return }
```

## Optional Chaining

Безопасный доступ к свойствам, методам и subscripts через цепочку `?`:

```swift
class Address {
    var street: String?
}

class Person {
    var address: Address?
}

let person: Person? = Person()
person?.address = Address()
person?.address?.street = "Main St"

// Вся цепочка возвращает Optional
let street: String? = person?.address?.street  // "Main St"

// Если любое звено nil — вся цепочка возвращает nil
let nobody: Person? = nil
let noStreet = nobody?.address?.street  // nil (даже не пытается идти дальше)

// С вызовом метода
let count: Int? = person?.address?.street?.count  // 7

// С subscript
let dict: [String: [Int]]? = ["key": [1, 2, 3]]
let value = dict?["key"]?[0]  // Optional(1)
```

## Nil Coalescing

Оператор `??` предоставляет значение по умолчанию:

```swift
let name: String? = nil
let displayName = name ?? "Anonymous"  // "Anonymous"

// Цепочка
let primary: String? = nil
let secondary: String? = nil
let fallback = primary ?? secondary ?? "default"  // "default"

// Правый операнд вычисляется лениво (только если левый == nil)
let value = cache[key] ?? expensiveComputation()

// Тип результата — non-optional T (если правый операнд — T)
let x: Int? = 42
let y: Int = x ?? 0  // Int, не Int?
```

## Force Unwrapping

Оператор `!` извлекает значение или вызывает **runtime crash**:

```swift
let name: String? = "Alice"
print(name!)  // "Alice"

let empty: String? = nil
// print(empty!)  // Fatal error: Unexpectedly found nil while unwrapping
```

### Когда допустимо:
- В тестах
- Когда `nil` означает ошибку программиста (assertion)
- После проверки (но лучше использовать binding)

```swift
// Лучше не так:
if name != nil {
    print(name!)  // Плохо — лучше if let
}

// А так:
if let name {
    print(name)
}
```

## Implicitly Unwrapped Optionals

`Type!` — optional, который автоматически unwrap'ится при использовании:

```swift
var label: String! = "Hello"
let text: String = label  // автоматический unwrap, без !
// Но если label == nil → crash

// Основное применение:
// 1. IBOutlet в UIKit (инициализируется после init)
// 2. Двухфазная инициализация
class ViewController {
    var button: UIButton!  // будет установлен в viewDidLoad

    func viewDidLoad() {
        button = UIButton()
        button.setTitle("Tap", for: .normal)  // не нужно писать button!
    }
}
```

> **Правило:** Избегай IUO кроме случаев, когда значение гарантированно будет установлено перед использованием и не может быть задано в `init`.

## Optional map и flatMap

`Optional` поддерживает функциональные трансформации:

### map

```swift
let number: Int? = 42
let string = number.map { String($0) }  // Optional("42")

let none: Int? = nil
let result = none.map { String($0) }    // nil (замыкание не вызывается)

// Эквивалент:
// if let n = number { return String(n) } else { return nil }
```

### flatMap

```swift
let input: String? = "42"
let parsed = input.flatMap { Int($0) }  // Optional(42)

let bad: String? = "abc"
let failed = bad.flatMap { Int($0) }    // nil (Int("abc") возвращает nil)

// Разница: map вложил бы Optional в Optional
let withMap = input.map { Int($0) }     // Optional(Optional(42)) — Int??
let withFlatMap = input.flatMap { Int($0) }  // Optional(42) — Int?
```

### Цепочки

```swift
struct User {
    var email: String?
}

func findUser(id: Int) -> User? { /* ... */ }

let domain = findUser(id: 1)
    .flatMap { $0.email }
    .flatMap { $0.split(separator: "@").last }
    .map { String($0) }
// Optional<String> — домен email или nil
```

## Паттерны

### Early return с guard

```swift
func process(data: Data?) throws -> Result {
    guard let data else {
        throw ProcessingError.noData
    }
    // data гарантированно non-nil дальше
    return try parse(data)
}
```

### Conditional assignment

```swift
var config: Config?

// Установить только если nil
config = config ?? Config.default

// Или через if
if config == nil {
    config = loadConfig()
}
```

### Optional в switch

```swift
let value: Int? = 42

switch value {
case .some(let x) where x > 0:
    print("Positive: \(x)")
case .some(let x):
    print("Non-positive: \(x)")
case .none:
    print("nil")
}

// Shorthand
switch value {
case let x? where x > 0:   // x? — это .some(x)
    print("Positive: \(x)")
case let x?:
    print("Non-positive: \(x)")
case nil:
    print("nil")
}
```

### Коллекция опционалов

```swift
let numbers: [Int?] = [1, nil, 3, nil, 5]

// compactMap убирает nil
let nonNil = numbers.compactMap { $0 }  // [1, 3, 5]

// for case let — фильтрация при итерации
for case let number? in numbers {
    print(number)  // 1, 3, 5
}
```

## Внутреннее представление

### Payload optimization

Компилятор Swift **оптимизирует** размер Optional для определённых типов:

```swift
// Bool — 1 байт, Bool? — тоже 1 байт!
// false = 0x00, true = 0x01, nil = 0x02
MemoryLayout<Bool>.size    // 1
MemoryLayout<Bool?>.size   // 1

// Ссылочные типы — nil = нулевой указатель
// Указатель 8 байт, Optional<AnyObject> — тоже 8 байт
MemoryLayout<AnyObject>.size    // 8
MemoryLayout<AnyObject?>.size   // 8

// Int — 8 байт, Int? — 9 байт (нет spare bits)
MemoryLayout<Int>.size    // 8
MemoryLayout<Int?>.size   // 9

// Вложенные optionals
MemoryLayout<Int?>.size    // 9
MemoryLayout<Int??>.size   // 10 (дополнительный tag byte)
```

### Spare bit optimization

Для типов, у которых есть **невалидные битовые паттерны**, компилятор использует их для представления `nil`:

- **Ссылочные типы** — нулевой указатель = nil
- **Bool** — значения 0 и 1 заняты, 2 = nil
- **Enum** — если есть свободные tag-значения

Для типов без spare bits (как `Int`) добавляется дополнительный **tag byte**.

### Multi-payload enum

```swift
// Optional<Optional<Int>> — три состояния:
// .some(.some(value)) — есть значение
// .some(.none)        — внутренний nil
// .none               — внешний nil

let a: Int?? = 42     // .some(.some(42))
let b: Int?? = nil    // .none
let c: Int?? = .some(nil)  // .some(.none)

// a, b и c — три разных значения!
```

## Сравнение с JS

| Аспект | Swift Optional | JavaScript null/undefined |
|--------|---------------|--------------------------|
| Тип | `Optional<T>` (generic enum) | Два отдельных типа: `null`, `undefined` |
| Проверка | `if let`, `guard let`, pattern matching | `if (x != null)`, `x ?? default` |
| Chaining | `a?.b?.c` | `a?.b?.c` (ES2020) |
| Default | `a ?? b` | `a ?? b` (ES2020) |
| Force | `a!` (crash if nil) | Нет аналога |
| Type safety | Компилятор заставляет обрабатывать nil | Ничего не заставляет |
| Nested | `Int??` — валидный тип | `null` внутри `null` бессмысленно |
| Map/FlatMap | `optional.map { }` | Нет нативного |

> **Ключевое отличие:** В Swift `Optional` — часть системы типов. Компилятор **не даст** использовать `String?` там, где ожидается `String`. В JS `null` может появиться где угодно, и TypeScript лишь частично решает эту проблему.
