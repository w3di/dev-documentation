## Классы как ссылочные типы

В Swift единственный **нативный** ссылочный тип — это `class`. При присваивании и передаче копируется **ссылка**, а не данные:

```swift
class Person {
    var name: String
    init(name: String) { self.name = name }
}

let alice = Person(name: "Alice")
let ref = alice           // ref и alice указывают на ОДИН объект
ref.name = "Bob"
print(alice.name)         // "Bob" — мутация через ref видна через alice
```

> **Сравнение с JS:** В JavaScript все объекты и массивы — ссылочные. В Swift только `class` (и замыкания) — ссылочные. `struct`, `enum`, tuples — значимые.

## Reference Counting

Swift использует **ARC (Automatic Reference Counting)** — компилятор вставляет `retain` и `release` в нужных местах:

```swift
class Node {
    var value: Int
    init(value: Int) { self.value = value }
    deinit { print("Node \(value) deallocated") }
}

var a: Node? = Node(value: 1)  // refcount = 1
var b = a                       // refcount = 2
a = nil                         // refcount = 1
b = nil                         // refcount = 0 → deinit → "Node 1 deallocated"
```

### Три вида ссылок

| Тип | Ключевое слово | Увеличивает refcount? | nil при деаллокации? |
|-----|---------------|----------------------|---------------------|
| Strong | (по умолчанию) | Да | — |
| Weak | `weak` | Нет | Да (автоматически) |
| Unowned | `unowned` | Нет | Нет (crash при доступе) |

```swift
class Owner {
    var pet: Pet?
    deinit { print("Owner deinit") }
}

class Pet {
    weak var owner: Owner?    // weak — разрывает retain cycle
    deinit { print("Pet deinit") }
}

var owner: Owner? = Owner()
var pet: Pet? = Pet()
owner?.pet = pet
pet?.owner = owner

owner = nil  // Owner deinit (pet.owner автоматически стал nil)
pet = nil    // Pet deinit
```

### Unowned

```swift
class Customer {
    var card: CreditCard?
    deinit { print("Customer deinit") }
}

class CreditCard {
    unowned let customer: Customer  // гарантируем, что customer живёт дольше
    init(customer: Customer) { self.customer = customer }
    deinit { print("Card deinit") }
}

var john: Customer? = Customer()
john?.card = CreditCard(customer: john!)
john = nil  // Customer deinit, Card deinit
```

> **Правило:** Используй `weak` когда время жизни объекта неизвестно. Используй `unowned` когда гарантируешь, что ссылаемый объект живёт дольше или столько же.

## Identity vs Equality

```swift
class Foo: Equatable {
    var value: Int
    init(_ value: Int) { self.value = value }

    static func == (lhs: Foo, rhs: Foo) -> Bool {
        lhs.value == rhs.value
    }
}

let a = Foo(42)
let b = Foo(42)
let c = a

a == b   // true  — равенство по значению (Equatable)
a === b  // false — разные объекты в памяти
a === c  // true  — один и тот же объект
```

| Оператор | Что сравнивает | Аналог в JS |
|----------|---------------|-------------|
| `==` | Значения (Equatable) | `==` (с оговорками) |
| `===` | Идентичность (один объект) | `===` для объектов |
| `!==` | Не идентичны | `!==` |

## Heap allocation и ARC overhead

Каждый объект класса имеет **header** (16 байт на 64-bit):

```
┌─────────────────────┐
│  Metadata pointer    │  8 байт — указатель на type metadata (V-table, type info)
│  Reference count     │  8 байт — strong RC + weak RC + flags
├─────────────────────┤
│  Stored properties   │  N байт
└─────────────────────┘
```

### Затраты ARC

- Каждый `retain` — атомарный инкремент (atomic increment)
- Каждый `release` — атомарный декремент + проверка на 0
- Атомарные операции дороже обычных из-за memory barriers

### Оптимизации компилятора

- **Retain/release coalescing** — убирает парные retain/release
- **Owned parameter convention** — передаёт ownership без retain
- **Guaranteed parameter convention** — заимствование без retain/release

## Class-bound protocols

```swift
protocol Delegate: AnyObject {  // только классы могут подписаться
    func didUpdate()
}

class Controller {
    weak var delegate: Delegate?  // weak возможен только для AnyObject-протоколов
}
```

Без `AnyObject` нельзя сделать `weak var delegate: SomeProtocol?` — компилятор не знает, будет ли это ссылочный тип.

## ObjectIdentifier

Уникальный идентификатор для экземпляров классов и метатипов:

```swift
class Service {}

let a = Service()
let b = Service()

let idA = ObjectIdentifier(a)
let idB = ObjectIdentifier(b)

print(idA == idB)  // false
print(idA)         // ObjectIdentifier(0x600000c04b40)

// Для метатипов
let typeId = ObjectIdentifier(Service.self)
```

Используется для создания `Dictionary` с ключами-объектами без `Hashable`.

## Existential containers

Когда значимый тип хранится через протокол, Swift использует **existential container**:

```swift
protocol Drawable {
    func draw()
}

struct Circle: Drawable {
    var radius: Double
    func draw() { print("Circle r=\(radius)") }
}

let shape: any Drawable = Circle(radius: 5)
```

Структура existential container (40 байт):

```
┌──────────────────────────┐
│  Inline buffer (24 байт) │  Для маленьких значений (≤ 3 words)
│  или указатель на heap   │  Для больших значений
├──────────────────────────┤
│  Metadata pointer        │  8 байт — тип конкретного значения
├──────────────────────────┤
│  Witness table pointer   │  8 байт — таблица реализаций протокола
└──────────────────────────┘
```

- Если тип ≤ 24 байт — хранится **inline** (без heap allocation)
- Если > 24 байт — аллокация на heap, в buffer хранится указатель

### Opaque types (some) вместо existential

```swift
// Existential — dynamic dispatch, возможна heap-аллокация
func makeShape() -> any Drawable { Circle(radius: 5) }

// Opaque — static dispatch, нет overhead
func makeShape() -> some Drawable { Circle(radius: 5) }
```

## Class vs Struct — когда что

### Используй struct когда:
- Данные — это **значение** (координата, цвет, конфигурация)
- Нужна **value semantics** (предсказуемое копирование)
- Нет необходимости в наследовании
- Нужна **thread safety** без синхронизации

### Используй class когда:
- Нужна **identity** (два объекта с одинаковыми полями — разные сущности)
- Нужно **наследование**
- Нужен **shared mutable state** (один объект, много ссылок)
- Interop с Objective-C (`NSObject`)
- Нужен **deinit** для cleanup

```swift
// struct — значение
struct Color {
    var r, g, b, a: Double
}

// class — identity, shared state
class DatabaseConnection {
    private var handle: OpaquePointer?

    func query(_ sql: String) -> [Row] { /* ... */ }

    deinit {
        // закрыть соединение
    }
}
```

## deinit

Деинициализатор вызывается **автоматически** когда reference count достигает 0:

```swift
class FileHandle {
    let path: String

    init(path: String) {
        self.path = path
        print("Opened \(path)")
    }

    deinit {
        print("Closed \(path)")
        // освобождение ресурсов
    }
}

do {
    let file = FileHandle(path: "/tmp/data")
    // использование file
}  // deinit вызывается здесь (ARC знает, что file больше не используется)
```

- `deinit` доступен **только для классов** (struct деаллоцируется при выходе из scope без deinit)
- Нельзя вызвать `deinit` вручную
- В `deinit` доступны все свойства экземпляра
- `deinit` наследуется и вызывается по цепочке (subclass → superclass)

## Unmanaged

`Unmanaged` используется для работы с C API, когда ARC не управляет временем жизни:

```swift
import CoreFoundation

// Получение объекта без передачи ownership
let unmanaged: Unmanaged<CFString> = someCFunction()
let str = unmanaged.takeUnretainedValue()  // +0 (не увеличивает RC)

// Получение объекта с передачей ownership
let owned = unmanaged.takeRetainedValue()  // +1 → ARC берёт управление

// Передача Swift-объекта в C-callback как void*
class Context { var data = 42 }
let ctx = Context()
let ptr = Unmanaged.passRetained(ctx).toOpaque()     // +1, → UnsafeMutableRawPointer
// ... позже в callback ...
let restored = Unmanaged<Context>.fromOpaque(ptr).takeRetainedValue()  // -1
```

## Сравнение с JavaScript

| Аспект | Swift (class) | JavaScript (object) |
|--------|--------------|-------------------|
| Управление памятью | ARC (compile-time) | GC (runtime, tracing) |
| Деструктор | `deinit` (детерминированный) | Нет (FinalizationRegistry — не гарантирован) |
| Weak references | `weak var` (автоматический nil) | `WeakRef` (ручная проверка) |
| Identity check | `===` | `===` (для объектов) |
| Наследование | Классическое (`class A: B`) | Прототипное (`__proto__`) |
| Value types | `struct` (нативная поддержка) | Нет (объекты всегда ссылочные) |
