## Closure expression syntax

Замыкание в Swift -- это самодостаточный блок кода, который может быть передан и использован как значение. Замыкания аналогичны лямбдам в других языках, но с рядом синтаксических сокращений.

### Полный синтаксис

```swift
let multiply: (Int, Int) -> Int = { (a: Int, b: Int) -> Int in
    return a * b
}
```

### Последовательное упрощение

Swift предлагает несколько уровней синтаксического сахара:

```swift
let numbers = [5, 2, 8, 1, 9]

// 1. Полная форма
let sorted1 = numbers.sorted(by: { (a: Int, b: Int) -> Bool in
    return a < b
})

// 2. Вывод типов из контекста
let sorted2 = numbers.sorted(by: { a, b in
    return a < b
})

// 3. Неявный return для однострочных замыканий
let sorted3 = numbers.sorted(by: { a, b in a < b })

// 4. Shorthand argument names ($0, $1, ...)
let sorted4 = numbers.sorted(by: { $0 < $1 })

// 5. Operator function (оператор < уже является функцией (Int, Int) -> Bool)
let sorted5 = numbers.sorted(by: <)
```

> **Компилятор:** Все пять форм генерируют идентичный SIL-код. Синтаксический сахар полностью разрешается на этапе type-checking, до генерации промежуточного представления.

## Trailing closures

### Одиночный trailing closure

Если замыкание -- последний аргумент функции, его можно вынести за скобки:

```swift
func performAnimation(
    duration: TimeInterval,
    animations: () -> Void
) {
    // ...
    animations()
}

// Trailing closure syntax
performAnimation(duration: 0.3) {
    print("Animating...")
}
```

### Множественные trailing closures (Swift 5.3+)

```swift
func animate(
    withDuration duration: TimeInterval,
    animations: @escaping () -> Void,
    completion: @escaping (Bool) -> Void
) {
    // ...
}

// Множественные trailing closures
animate(withDuration: 0.5) {
    // animations
    print("Animating")
} completion: { finished in
    print("Finished: \(finished)")
}
```

Практический пример с SwiftUI-стилем API:

```swift
// SwiftUI активно использует множественные trailing closures
func buildUI(
    header: () -> String,
    content: () -> [String],
    footer: () -> String
) -> String {
    "\(header())\n\(content().joined(separator: "\n"))\n\(footer())"
}

let page = buildUI {
    "=== Header ==="
} content: {
    ["Line 1", "Line 2", "Line 3"]
} footer: {
    "=== Footer ==="
}
```

> **Дизайн-принцип:** Trailing closures делают код визуально похожим на DSL. Это фундамент SwiftUI result builders, где замыкания используются для описания UI-иерархии.

## Захват значений

Замыкания захватывают переменные и константы из окружающего контекста. По умолчанию захват происходит **по ссылке** -- замыкание и внешний код разделяют одну и ту же переменную.

### Захват по ссылке (по умолчанию)

```swift
func makeCounter() -> () -> Int {
    var count = 0
    return {
        count += 1  // Захватывает count по ссылке
        return count
    }
}

let counter = makeCounter()
counter() // 1
counter() // 2
counter() // 3

// Два замыкания разделяют один и тот же count
let counter2 = makeCounter() // Новый count
counter2() // 1 (независимый счетчик)
```

### Capture list -- явное управление захватом

Capture list позволяет захватить **копию значения** на момент создания замыкания:

```swift
func createClosures() -> [() -> Int] {
    var value = 0
    var closures: [() -> Int] = []

    for i in 1...3 {
        value = i

        // Без capture list: все замыкания видят ОДНУ переменную value
        // closures.append { value }

        // С capture list: каждое замыкание захватывает КОПИЮ
        closures.append { [value] in value }
    }

    return closures
}

let fns = createClosures()
fns[0]() // 1
fns[1]() // 2
fns[2]() // 3
```

### Capture list с несколькими переменными

```swift
class DataManager {
    var data: [String] = []
    var lastUpdate = Date()

    func scheduleRefresh() -> () -> Void {
        return { [weak self, data = self.data.count] in
            // self -- weak reference
            // data -- копия Int на момент создания
            guard let self else { return }
            print("Had \(data) items, now \(self.data.count)")
        }
    }
}
```

> **SIL-уровень:** Захват по ссылке реализуется через `alloc_box` -- heap-allocated контейнер, содержащий захваченное значение. Замыкание хранит strong reference на этот box. При захвате по значению (capture list) значение копируется в context object замыкания напрямую.

## @escaping vs non-escaping

### Non-escaping (по умолчанию)

Замыкание **non-escaping**, если его время жизни не превышает время вызова функции. Это значение по умолчанию с Swift 3:

```swift
func performOperation(_ operation: () -> Int) -> Int {
    // operation -- non-escaping
    // Гарантировано: operation не переживет performOperation()
    return operation()
}

// Компилятор может:
// 1. Аллоцировать контекст замыкания на стеке
// 2. Не делать retain/release захваченных объектов
// 3. Не требовать explicit self в замыкании
```

### @escaping

Замыкание **escaping**, если оно может быть вызвано после завершения функции:

```swift
class TaskManager {
    private var pendingTasks: [() -> Void] = []

    func addTask(_ task: @escaping () -> Void) {
        // task сохраняется в массив -- escapes из функции
        pendingTasks.append(task)
    }

    func executeTasks() {
        pendingTasks.forEach { $0() }
        pendingTasks.removeAll()
    }
}
```

### Почему это важно

```swift
class ViewController {
    var name = "Main"

    func setupNonEscaping() {
        performOperation {
            // Non-escaping: self не нужен
            print(name) // OK
        }
    }

    func setupEscaping() {
        let manager = TaskManager()
        manager.addTask { [weak self] in
            // @escaping: обязателен explicit self
            // Рекомендуется weak self для предотвращения retain cycle
            guard let self else { return }
            print(self.name)
        }
    }
}
```

### @escaping и оптимизации

```swift
// Non-escaping преимущества:
// 1. Stack allocation контекста (вместо heap)
// 2. Нет ARC overhead для захваченных переменных
// 3. Компилятор может инлайнить замыкание
// 4. Нет необходимости в явном self

// @escaping стоимость:
// 1. Heap allocation для контекста
// 2. ARC retain/release для захваченных объектов
// 3. Potential retain cycles
// 4. Обязательный explicit self
```

> **Правило:** Всегда предпочитайте non-escaping, если нет необходимости сохранять замыкание. Компилятор сам проверит -- если вы попытаетесь сохранить non-escaping замыкание, получите ошибку компиляции.

## @autoclosure

`@autoclosure` автоматически оборачивает выражение в замыкание. Это позволяет отложить вычисление (lazy evaluation) без синтаксического шума:

```swift
func logIfNeeded(
    _ condition: Bool,
    message: @autoclosure () -> String,
    file: String = #file,
    line: Int = #line
) {
    guard condition else { return }
    // message() вызывается ТОЛЬКО если condition == true
    print("[\(file):\(line)] \(message())")
}

// Вызов выглядит как обычная передача значения
logIfNeeded(isDebug, message: "User data: \(expensiveSerialize(userData))")
// expensiveSerialize вызовется ТОЛЬКО если isDebug == true
```

### Стандартные примеры из stdlib

```swift
// assert использует @autoclosure для обоих параметров
// В release builds ни condition, ни message не вычисляются
assert(array.count > 0, "Array must not be empty: \(array)")

// Nil coalescing оператор ?? использует @autoclosure для default value
let value = optionalDict["key"] ?? expensiveDefault()
// expensiveDefault() вызовется только если optionalDict["key"] == nil
```

### Комбинация @autoclosure и @escaping

```swift
class LazyProperty<T> {
    private var computation: (() -> T)?
    private var cachedValue: T?

    init(_ computation: @autoclosure @escaping () -> T) {
        self.computation = computation
    }

    var value: T {
        if let cached = cachedValue { return cached }
        let result = computation!()
        cachedValue = result
        computation = nil  // Освобождаем замыкание
        return result
    }
}

let lazy = LazyProperty(expensiveComputation())
// expensiveComputation() ещё НЕ вызвана
// Вызовется при первом обращении к lazy.value
```

## Capture semantics: strong, weak, unowned

### Strong capture (по умолчанию)

```swift
class Service {
    let name: String
    init(name: String) { self.name = name }
    deinit { print("\(name) deinitialized") }
}

func example() {
    let service = Service(name: "API")
    let closure = {
        // Strong capture: service retain count +1
        print(service.name)
    }
    closure()
    // service освободится когда И переменная, И замыкание выйдут из scope
}
```

### Weak capture

```swift
class NetworkController {
    var onDataReceived: ((Data) -> Void)?

    func fetchData() {
        URLSession.shared.dataTask(with: url) { [weak self] data, _, _ in
            guard let self else {
                print("Controller was deallocated")
                return
            }
            // self гарантированно жив в этом блоке
            self.processData(data)
        }.resume()
    }

    private func processData(_ data: Data?) { }
}
```

### Unowned capture

`unowned` -- как `weak`, но без Optional обертки. Используется когда **гарантировано**, что объект жив на момент вызова замыкания:

```swift
class Customer {
    let name: String
    var card: CreditCard?

    init(name: String) { self.name = name }
    deinit { print("\(name) deinitialized") }
}

class CreditCard {
    let number: String
    unowned let owner: Customer  // Карта не переживет владельца

    lazy var displayInfo: () -> String = { [unowned self] in
        // Безопасно: замыкание принадлежит self, self -> card -> closure
        // Если card существует, то и self (owner) существует
        "\(self.number) owned by \(self.owner.name)"
    }

    init(number: String, owner: Customer) {
        self.number = number
        self.owner = owner
    }
}
```

### Таблица сравнения

```
+-----------+------------------+------------------+---------------------+
| Тип       | Reference count  | Optional?        | Crash при dealloc?  |
+-----------+------------------+------------------+---------------------+
| strong    | +1               | Нет              | Нет                 |
| weak      | Не меняет        | Да (T?)          | Нет (становится nil)|
| unowned   | Не меняет        | Нет (T)          | Да! (dangling ptr)  |
+-----------+------------------+------------------+---------------------+
```

> **Когда что использовать:**
> - `strong` -- когда замыкание должно удерживать объект (e.g., анимации)
> - `weak` -- когда объект может быть деаллоцирован (e.g., UI callbacks, сетевые запросы)
> - `unowned` -- когда 100% уверены, что объект переживет замыкание (e.g., parent-child relationships)

## Retain cycles с замыканиями

### Классический retain cycle

```swift
class ViewModel {
    var name = "ViewModel"
    var onUpdate: (() -> Void)?

    func setup() {
        // RETAIN CYCLE:
        // self -> onUpdate (strong)
        // onUpdate -> self (strong, через захват)
        onUpdate = {
            print(self.name) // Strong capture self!
        }
    }

    deinit { print("ViewModel deinitialized") } // Никогда не вызовется!
}

var vm: ViewModel? = ViewModel()
vm?.setup()
vm = nil // Memory leak! deinit не вызовется
```

### Исправление через capture list

```swift
class ViewModel {
    var name = "ViewModel"
    var onUpdate: (() -> Void)?

    func setup() {
        // Вариант 1: weak self
        onUpdate = { [weak self] in
            guard let self else { return }
            print(self.name)
        }

        // Вариант 2: unowned self (если уверены в lifecycle)
        onUpdate = { [unowned self] in
            print(self.name)
        }
    }

    deinit { print("ViewModel deinitialized") } // Теперь вызовется
}
```

### Сложный retain cycle через цепочку

```swift
class Parent {
    var child: Child?
    deinit { print("Parent deinitialized") }
}

class Child {
    var parent: Parent
    var onAction: (() -> Void)?

    init(parent: Parent) {
        self.parent = parent
    }

    func configure() {
        // Цикл: Parent -> Child -> onAction -> Parent (через parent)
        onAction = { [weak parent = self.parent] in
            guard let parent else { return }
            print("Parent exists: \(parent)")
        }
    }

    deinit { print("Child deinitialized") }
}
```

### Диагностика retain cycles

```swift
// 1. Проверка через deinit
class Tracked {
    let id: String
    init(id: String) { self.id = id }
    deinit { print("Tracked \(id) freed") }
}

// 2. Xcode Memory Graph Debugger (Product -> Profile -> Leaks)

// 3. Паттерн: weak-strong dance
func fetchData(completion: @escaping (Data?) -> Void) {
    networkCall { [weak self] data in
        guard let self else { return }
        // self теперь strong reference, но только на время блока
        self.process(data)
        self.updateUI()
        completion(data)
    }
}
```

## Closure как reference type

Замыкания -- это **reference types**. Присвоение замыкания другой переменной не создает копию, а создает ещё одну ссылку на тот же объект:

```swift
func makeIncrementer(step: Int) -> () -> Int {
    var total = 0
    return {
        total += step
        return total
    }
}

let incrementByTwo = makeIncrementer(step: 2)
let alsoIncrementByTwo = incrementByTwo // Та же ссылка!

incrementByTwo()       // 2
alsoIncrementByTwo()   // 4 (не 2! -- разделяют один total)
incrementByTwo()       // 6
```

> **Внутри:** Замыкание -- это heap-allocated объект, управляемый ARC. Он содержит указатель на функцию (code pointer) и контекст (context pointer) с захваченными значениями. Retain/release работает так же, как для классов.

```swift
// Проверка: замыкания -- reference types, но НЕ поддерживают ===
let a = { 42 }
let b = a
// a === b  // Ошибка: === не определен для замыканий
// Это by design -- identity comparison замыканий не имеет смысла
```

## Оптимизации: inlining замыканий

### Automatic inlining

Компилятор агрессивно инлайнит замыкания, особенно non-escaping:

```swift
// До оптимизации:
let result = numbers.map { $0 * 2 }.filter { $0 > 5 }

// После inlining + fusion:
// Компилятор может объединить map и filter в один проход,
// устранив промежуточный массив

// Эквивалент оптимизированного кода:
var result: [Int] = []
for n in numbers {
    let mapped = n * 2
    if mapped > 5 {
        result.append(mapped)
    }
}
```

### Guaranteed optimization для стандартных HOF

```swift
// С флагом -O компилятор:

// 1. Инлайнит замыкание в forEach/map/filter/reduce
// 2. Устраняет heap allocation для non-escaping замыканий
// 3. Специализирует generic-параметры
// 4. Разворачивает простые циклы (loop unrolling)

let sum = [1, 2, 3, 4, 5].reduce(0, +)
// Оптимизируется до: let sum = 15 (constant folding)
```

### withoutActuallyEscaping

Иногда нужно передать non-escaping замыкание в API, требующий @escaping, зная, что замыкание на самом деле не escapes:

```swift
func performWithBothAPIs(
    using closure: () -> Void
) {
    withoutActuallyEscaping(closure) { escapableClosure in
        // escapableClosure имеет тип @escaping () -> Void
        // но мы гарантируем, что оно не переживет этот блок
        someAPIRequiringEscaping(escapableClosure)
    }
}
```

## Thin vs thick closures в SIL

На уровне SIL (Swift Intermediate Language) различаются два вида замыканий:

### Thin closure (без контекста)

```swift
// Thin closure -- просто указатель на функцию, без context pointer
// Размер: 1 machine word

// Пример: глобальная функция или статический метод
func globalAdd(_ a: Int, _ b: Int) -> Int { a + b }

// В SIL: @convention(thin) (Int, Int) -> Int
// Нет захваченных переменных -> нет context -> thin
```

### Thick closure (с контекстом)

```swift
// Thick closure -- пара (function pointer, context pointer)
// Размер: 2 machine words

func makeAdder(_ base: Int) -> (Int) -> Int {
    return { x in base + x } // Захватывает base
}

// В SIL: @convention(thick) (Int) -> Int
// Context содержит захваченный base
// Структура в памяти:
// +------------------+
// | function pointer | -> код замыкания
// | context pointer  | -> heap-allocated box { refcount, base: Int }
// +------------------+
```

### Reabstraction thunks

Когда Swift конвертирует между разными calling conventions, он создает **thunk** -- маленькую промежуточную функцию:

```swift
// Функция ожидает thick closure:
func apply(_ f: (Int) -> Int, to x: Int) -> Int { f(x) }

// Передаем thin function:
func double(_ x: Int) -> Int { x * 2 }

apply(double, to: 5)
// Компилятор создает reabstraction thunk:
// thin -> thick conversion (оборачивает thin в thick с nil-контекстом)
```

> **Производительность:** Reabstraction thunks добавляют один уровень indirect call. При -O компилятор обычно инлайнит и thunk, и саму функцию, устраняя overhead. Но в debug-сборках thunks видны в стек-трейсах.

## Partial application

### Curried-стиль через вложенные замыкания

```swift
func multiply(by factor: Int) -> (Int) -> Int {
    return { value in value * factor }
}

let double = multiply(by: 2)
let triple = multiply(by: 3)

double(5)  // 10
triple(5)  // 15

// Композиция
let values = [1, 2, 3, 4, 5]
values.map(double) // [2, 4, 6, 8, 10]
```

### Partial application методов

```swift
struct Formatter {
    let prefix: String

    func format(_ value: String) -> String {
        "\(prefix): \(value)"
    }
}

let fmt = Formatter(prefix: "LOG")

// Method reference -- partial application с привязкой self
let logFormatter: (String) -> String = fmt.format
logFormatter("Hello") // "LOG: Hello"

// Unbound method reference (тип включает Self)
let unboundFormat: (Formatter) -> (String) -> String = Formatter.format
unboundFormat(fmt)("Hello") // "LOG: Hello"
```

### Практический пример: конфигурируемые пайплайны

```swift
func pipe<A, B, C>(
    _ f: @escaping (A) -> B,
    _ g: @escaping (B) -> C
) -> (A) -> C {
    return { a in g(f(a)) }
}

let processString = pipe(
    { (s: String) in s.trimmingCharacters(in: .whitespaces) },
    { $0.lowercased() }
)

processString("  HELLO WORLD  ") // "hello world"
```

## Сравнение с JavaScript

### Базовый синтаксис

```swift
// Swift closure
let greet = { (name: String) -> String in
    "Hello, \(name)!"
}

// Swift shorthand
let greetShort: (String) -> String = { "Hello, \($0)!" }
```

```javascript
// JavaScript arrow function
const greet = (name) => `Hello, ${name}!`;

// JavaScript traditional function expression
const greetTraditional = function(name) {
    return `Hello, ${name}!`;
};
```

### Ключевые различия

| Аспект | Swift Closures | JS Callbacks/Arrow Functions |
|--------|---------------|------------------------------|
| Типизация | Статическая, выводится или явная | Динамическая |
| Захват | По ссылке (по умолчанию), capture list для контроля | Всегда по ссылке (lexical scoping) |
| Escaping | Явное разделение @escaping / non-escaping | Все "escaping" по умолчанию |
| Memory | ARC, ручное управление циклами | GC, автоматическая очистка |
| this/self | Захватывает self, нужен explicit self в @escaping | Arrow: лексический this. Function: динамический this |
| Reference type | Да | Да |
| Retain cycles | Возможны, нужны weak/unowned | Нет (GC разрывает циклы) |

### Захват переменных: классическая ловушка

```swift
// Swift -- с capture list можно захватить копию
var functions: [() -> Int] = []
for i in 0..<3 {
    functions.append { [i] in i } // Захват копии
}
functions.map { $0() } // [0, 1, 2]
```

```javascript
// JavaScript -- классическая ловушка с var
var functions = [];
for (var i = 0; i < 3; i++) {
    functions.push(() => i); // Все ссылаются на одну переменную
}
functions.map(f => f()); // [3, 3, 3]

// Исправление через let (block scoping) или IIFE
for (let i = 0; i < 3; i++) {
    functions.push(() => i); // let создает новую binding на каждой итерации
}
```

### Управление памятью

```swift
// Swift: нужно явно управлять retain cycles
class ViewModel {
    var handler: (() -> Void)?

    func setup() {
        handler = { [weak self] in
            self?.doSomething() // weak self предотвращает cycle
        }
    }
}
```

```javascript
// JavaScript: GC справляется автоматически
class ViewModel {
    setup() {
        this.handler = () => {
            this.doSomething(); // Нет проблем с циклами
        };
    }
}
// Но: замыкания могут удерживать большие scope в памяти дольше ожидаемого
```

### Async паттерны

```swift
// Swift: structured concurrency заменяет callback hell
func fetchUser() async throws -> User {
    let data = try await URLSession.shared.data(from: url)
    return try JSONDecoder().decode(User.self, from: data.0)
}
```

```javascript
// JavaScript: async/await тоже решает callback hell
async function fetchUser() {
    const response = await fetch(url);
    return await response.json();
}
```

> **Принципиальное различие:** В Swift @escaping -- это compile-time гарантия, позволяющая оптимизировать non-escaping замыкания (stack allocation, отсутствие ARC). В JavaScript все замыкания потенциально escaping, и GC берет на себя управление жизненным циклом. Подход Swift дает лучшую производительность ценой сложности (explicit self, capture lists, retain cycle awareness).
