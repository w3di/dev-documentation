## Объявление функций

Функция в Swift объявляется ключевым словом `func`. На уровне компилятора каждая функция превращается в SIL (Swift Intermediate Language), а затем в LLVM IR. Компилятор различает **свободные функции**, **методы** (привязанные к типу) и **замыкания** -- все они в итоге представлены как указатели на код, но с разным calling convention.

```swift
func greet(name: String) -> String {
    return "Hello, \(name)!"
}

// Вызов
let message = greet(name: "Swift")
```

Функция без возвращаемого значения на самом деле возвращает `Void` (тайпалиас для пустого кортежа `()`):

```swift
func logEvent(message: String) {
    print(message)
}
// Сигнатура: (String) -> Void  (эквивалент (String) -> ())
```

> **Компилятор:** На уровне SIL функция представляется как `sil @$s...greet... : $@convention(method) (@guaranteed String) -> @owned String`. Каждая функция получает mangled name, кодирующий модуль, имя, типы параметров и возвращаемого значения.

## Параметры: внешние и внутренние имена

Swift использует систему **argument labels** (внешние имена) и **parameter names** (внутренние имена). Это уникальная особенность, унаследованная от Objective-C, которая делает вызовы самодокументируемыми.

```swift
// 'for' -- argument label (внешнее имя)
// 'person' -- parameter name (внутреннее имя)
func greet(for person: String, from city: String) -> String {
    return "Hello, \(person) from \(city)!"
}

greet(for: "Alice", from: "Moscow")
```

### Подавление внешнего имени

Символ `_` убирает argument label:

```swift
func multiply(_ a: Int, _ b: Int) -> Int {
    return a * b
}

multiply(3, 5) // без меток
```

### Важный нюанс: argument labels -- часть сигнатуры

Argument labels являются частью **идентичности** функции. Две функции с одинаковыми типами параметров, но разными labels -- это разные функции:

```swift
func move(to point: CGPoint) { }
func move(from point: CGPoint) { }
// Это две разные функции, перегрузка по argument label
```

На уровне mangled name labels кодируются в имя символа, поэтому линкер их различает.

## Значения по умолчанию

Параметры могут иметь значения по умолчанию. Компилятор генерирует **отдельную thunk-функцию** для каждого параметра со значением по умолчанию (`default argument generator`), которая вызывается в месте вызова, если аргумент не передан.

```swift
func connect(
    to host: String,
    port: Int = 443,
    timeout: TimeInterval = 30.0,
    useTLS: Bool = true
) {
    print("Connecting to \(host):\(port), TLS: \(useTLS), timeout: \(timeout)s")
}

connect(to: "api.example.com")
connect(to: "api.example.com", port: 8080)
connect(to: "api.example.com", port: 80, useTLS: false)
```

> **Внутренний механизм:** Для каждого значения по умолчанию компилятор создает функцию вида `default argument N of connect(to:port:timeout:useTLS:)`. Это означает, что значение по умолчанию вычисляется **в месте вызова**, а не в месте определения. Следствие: значение по умолчанию может использовать выражения, зависящие от контекста вызывающей стороны.

```swift
// Значение по умолчанию -- выражение, вычисляемое при вызове
func log(
    message: String,
    file: String = #file,
    line: Int = #line,
    function: String = #function
) {
    print("[\(file):\(line)] \(function): \(message)")
}
```

## Variadic параметры

Variadic параметры принимают ноль или более значений одного типа. Внутри функции они представлены как `Array<T>`.

```swift
func average(_ numbers: Double...) -> Double {
    guard !numbers.isEmpty else { return 0 }
    let sum = numbers.reduce(0, +)
    return sum / Double(numbers.count)
}

average(1.0, 2.0, 3.0, 4.0) // 2.5
```

Начиная с Swift 5.4, допускается **несколько variadic параметров** в одной функции:

```swift
func zip(letters: Character..., numbers: Int...) -> [(Character, Int)] {
    Array(Swift.zip(letters, numbers))
}

zip(letters: "a", "b", "c", numbers: 1, 2, 3)
// [("a", 1), ("b", 2), ("c", 3)]
```

> **Производительность:** Variadic параметры приводят к аллокации массива на куче при вызове. Если performance-critical, предпочтительнее принимать `some Collection` или конкретный `Array` -- это позволяет передать уже существующий буфер без дополнительной аллокации.

## inout параметры

`inout` реализует семантику **copy-in copy-out** (также называемую call-by-value-result). Значение копируется в функцию, модифицируется, и результат копируется обратно. Это **не** передача по ссылке, хотя компилятор **может** оптимизировать до pass-by-reference, если это безопасно.

```swift
func increment(_ value: inout Int, by amount: Int = 1) {
    value += amount
}

var counter = 10
increment(&counter, by: 5) // counter == 15
```

### Copy-in copy-out семантика в деталях

```swift
struct Matrix {
    var data: [[Double]]

    mutating func scale(by factor: Double) {
        for i in data.indices {
            for j in data[i].indices {
                data[i][j] *= factor
            }
        }
    }
}

func transform(_ matrix: inout Matrix) {
    // 1. Значение matrix КОПИРУЕТСЯ из вызывающего контекста
    // 2. Функция работает с локальной копией
    matrix.scale(by: 2.0)
    // 3. По завершении результат КОПИРУЕТСЯ обратно
}
```

### Оптимизация до pass-by-reference

На уровне SIL, `inout` параметр передается как `*T` (указатель). Компилятор применяет **exclusivity enforcement** -- гарантирует, что никакой другой код не имеет доступа к той же памяти во время исполнения функции. Это позволяет безопасно использовать pass-by-reference:

```swift
// На уровне SIL:
// %0 : $*Int  -- передается как указатель
// Exclusivity enforcement гарантирует, что никто другой
// не читает/пишет в эту память одновременно

func swap<T>(_ a: inout T, _ b: inout T) {
    let temp = a
    a = b
    b = temp
}

var x = 1, y = 2
swap(&x, &y) // Работает: разные адреса

var arr = [1, 2, 3]
// swap(&arr[0], &arr[1]) // Ошибка exclusivity enforcement!
// arr.swapAt(0, 1)       // Правильный способ
```

> **Важно:** Нельзя передать одну и ту же переменную как два `inout` параметра -- это нарушение exclusivity rule и приведет к runtime crash (или compile-time error, если компилятор может это обнаружить).

## Возвращаемые значения и кортежи

### Один результат

```swift
func factorial(_ n: Int) -> Int {
    n <= 1 ? 1 : n * factorial(n - 1)
}
```

### Множественные результаты через кортежи

```swift
func minMax(of array: [Int]) -> (min: Int, max: Int)? {
    guard let first = array.first else { return nil }

    var currentMin = first
    var currentMax = first

    for value in array.dropFirst() {
        currentMin = min(currentMin, value)
        currentMax = max(currentMax, value)
    }

    return (min: currentMin, max: currentMax)
}

if let result = minMax(of: [3, 1, 4, 1, 5, 9]) {
    print("Min: \(result.min), Max: \(result.max)")
}
```

### Opaque return types (some Protocol)

```swift
func makeCollection() -> some Collection {
    [1, 2, 3, 4, 5]
}
// Конкретный тип скрыт, но компилятор знает его
// Это позволяет менять реализацию без изменения API
```

### Результат Never

```swift
func fatalError(_ message: String) -> Never {
    // Функция никогда не возвращает управление
    preconditionFailure(message)
}
// Never -- bottom type, подтип любого типа
// Компилятор использует это для проверки полноты switch/if
```

## Функции как first-class citizens

Функции в Swift -- это значения первого класса. Каждая функция имеет тип, может быть присвоена переменной, передана как аргумент или возвращена из другой функции.

```swift
// Тип функции: (Int, Int) -> Int
func add(_ a: Int, _ b: Int) -> Int { a + b }
func multiply(_ a: Int, _ b: Int) -> Int { a * b }

// Присвоение переменной
var operation: (Int, Int) -> Int = add
operation(3, 4) // 7

operation = multiply
operation(3, 4) // 12
```

### Функции высшего порядка

```swift
func apply(
    _ f: (Int, Int) -> Int,
    to a: Int,
    and b: Int
) -> Int {
    f(a, b)
}

apply(add, to: 10, and: 20)      // 30
apply(multiply, to: 10, and: 20) // 200
```

### Функция, возвращающая функцию

```swift
func makeMultiplier(factor: Int) -> (Int) -> Int {
    func multiplier(_ value: Int) -> Int {
        value * factor // захватывает factor из enclosing scope
    }
    return multiplier
}

let triple = makeMultiplier(factor: 3)
triple(10) // 30
```

> **Внутренняя реализация:** Когда функция используется как значение, компилятор представляет её как **thick function pointer** -- пару (указатель на код, указатель на контекст). Контекст хранит захваченные переменные. Если захвата нет, контекст равен `nil`, и это **thin function**.

## @discardableResult

По умолчанию Swift выдает предупреждение, если результат функции не используется. `@discardableResult` подавляет это предупреждение:

```swift
@discardableResult
func insert(_ element: String, into array: inout [String]) -> Int {
    array.append(element)
    return array.count
}

var items: [String] = []
insert("item1", into: &items)         // OK, результат можно не использовать
let count = insert("item2", into: &items) // Можно и использовать
```

Типичное применение -- builder pattern, fluent API:

```swift
class QueryBuilder {
    private var conditions: [String] = []

    @discardableResult
    func whereClause(_ condition: String) -> QueryBuilder {
        conditions.append(condition)
        return self
    }

    @discardableResult
    func orderBy(_ field: String) -> QueryBuilder {
        // ...
        return self
    }

    func build() -> String {
        "SELECT * WHERE \(conditions.joined(separator: " AND "))"
    }
}

// Fluent API
let query = QueryBuilder()
    .whereClause("age > 18")
    .whereClause("active = true")
    .orderBy("name")
    .build()
```

## Вложенные функции

Вложенные функции (nested functions) определяются внутри тела другой функции. Они имеют доступ к переменным enclosing scope и невидимы извне.

```swift
func chooseStepFunction(backward: Bool) -> (Int) -> Int {
    func stepForward(_ input: Int) -> Int { input + 1 }
    func stepBackward(_ input: Int) -> Int { input - 1 }

    return backward ? stepBackward : stepForward
}

var currentValue = 4
let moveToZero = chooseStepFunction(backward: currentValue > 0)

while currentValue != 0 {
    currentValue = moveToZero(currentValue)
}
```

### Вложенные функции и захват контекста

```swift
func makeCounter(startingAt initial: Int = 0) -> () -> Int {
    var count = initial

    func increment() -> Int {
        count += 1  // Захватывает 'count' по ссылке
        return count
    }

    return increment
}

let counter = makeCounter()
counter() // 1
counter() // 2
counter() // 3
```

> **SIL-уровень:** Вложенная функция, захватывающая переменные, превращается в замыкание. Компилятор аллоцирует box для захваченных переменных на куче (alloc_box в SIL). Если компилятор может доказать, что замыкание не escapes, он может продвинуть аллокацию на стек (stack promotion optimization).

## Функции-дженерики

Дженерик-функции позволяют писать обобщенный код с параметрами типа:

```swift
func findIndex<T: Equatable>(of target: T, in array: [T]) -> Int? {
    for (index, element) in array.enumerated() {
        if element == target {
            return index
        }
    }
    return nil
}

findIndex(of: 42, in: [1, 2, 42, 99])     // Optional(2)
findIndex(of: "cat", in: ["dog", "cat"])   // Optional(1)
```

### Where-clause для сложных ограничений

```swift
func merge<S1: Sequence, S2: Sequence>(
    _ first: S1,
    _ second: S2
) -> [S1.Element]
where S1.Element == S2.Element, S1.Element: Comparable {
    (Array(first) + Array(second)).sorted()
}

merge([3, 1, 4], [2, 7, 5]) // [1, 2, 3, 4, 5, 7]
```

### some и any -- opaque vs existential

```swift
// Opaque type (some) -- конкретный тип, известный компилятору
func makeSequence() -> some Sequence<Int> {
    [1, 2, 3]
}

// Existential type (any) -- box с vtable, стирание типа
func processSequence(_ seq: any Sequence<Int>) {
    for item in seq {
        print(item)
    }
}
```

> **Производительность:** `some` позволяет статическую диспетчеризацию (компилятор знает конкретный тип), а `any` требует динамическую (через existential container с witness table). Разница может быть 2-10x в hot loops.

## @inlinable и @usableFromInline

Эти атрибуты управляют видимостью тела функции для оптимизатора **через границы модулей**.

### @inlinable

Делает тело функции доступным для инлайнинга в другие модули:

```swift
// В модуле MathUtils
@inlinable
public func square(_ x: Int) -> Int {
    x * x
}

// В клиентском модуле компилятор может заинлайнить тело square,
// даже несмотря на то, что оно в другом модуле
```

### @usableFromInline

Делает internal-объявление видимым для `@inlinable` функций без изменения уровня доступа:

```swift
@usableFromInline
internal struct InternalState {
    @usableFromInline var value: Int

    @usableFromInline
    init(value: Int) {
        self.value = value
    }
}

@inlinable
public func createState() -> Int {
    let state = InternalState(value: 42)
    return state.value
}
```

### Когда использовать

```swift
// Хорошо для @inlinable:
// - Простые, стабильные функции (математика, аксессоры)
// - Performance-critical функции в библиотечном коде
// - Функции из stdlib, используемые повсеместно

// Плохо для @inlinable:
// - Функции с нестабильной реализацией (тело станет частью ABI)
// - Функции с побочными эффектами, зависящими от версии
// - Функции, использующие private API
```

> **Важный компромисс:** `@inlinable` делает тело функции частью **публичного ABI**. Изменение тела @inlinable функции -- это ABI-breaking change. Клиентский код, скомпилированный со старой версией, будет использовать заинлайненную старую версию.

## Calling convention в Swift

### swiftcall (по умолчанию)

Swift использует собственный calling convention, оптимизированный для Swift-типов:

```swift
// swiftcall особенности:
// - До 4 параметров передаются в регистрах (на ARM64)
// - Возвращаемые значения тоже через регистры (до 4 слов)
// - self передается в специальном регистре
// - Error возвращается в отдельном регистре (не через стек)
// - Гарантии ownership (owned, guaranteed, inout)

func process(a: Int, b: Int, c: Int, d: Int) -> Int {
    // a, b, c, d передаются через регистры x0-x3 (ARM64)
    // Результат возвращается через x0
    a + b + c + d
}
```

### @convention(c) -- C calling convention

```swift
// Функция, совместимая с C ABI
let cFunction: @convention(c) (Int32, Int32) -> Int32 = { a, b in
    a + b
}

// Типичное использование -- callback для C API
import Darwin

let handler: @convention(c) (Int32) -> Void = { signal in
    print("Received signal: \(signal)")
}
signal(SIGINT, handler)
```

### @convention(block) -- Objective-C block

```swift
// Objective-C compatible block
let block: @convention(block) (NSString) -> NSString = { str in
    "Hello, \(str)!" as NSString
}
```

### Сравнение convention

```
+-------------------+------------------+-----------------------+
| Convention        | Контекст (self)  | Использование         |
+-------------------+------------------+-----------------------+
| @convention(swift) | thick (с контекстом) | По умолчанию     |
| @convention(c)     | нет контекста    | C interop             |
| @convention(block)  | Obj-C block     | Obj-C interop          |
| @convention(thin)  | нет контекста    | SIL-уровень           |
| @convention(method)| self параметр   | Методы типов          |
+-------------------+------------------+-----------------------+
```

## Оптимизации компилятора

### Специализация дженериков

Компилятор создает **специализированные версии** дженерик-функций для конкретных типов:

```swift
// Исходная дженерик-функция
func sum<T: Numeric>(_ array: [T]) -> T {
    array.reduce(.zero, +)
}

// При компиляции с -O компилятор может создать:
// - sum<Int>() -- специализированная для Int
// - sum<Double>() -- специализированная для Double
// Каждая версия использует нативные инструкции для конкретного типа
// вместо вызовов через witness table
```

Специализация особенно важна для generic-контейнеров:

```swift
// Без специализации:
// Array<T>.append() -> вызов через witness table для каждой операции
// С специализацией для Array<Int>:
// Прямые операции с памятью, SIMD-инструкции, автовекторизация

// Можно подсказать компилятору через @_specialize
@_specialize(where T == Int)
@_specialize(where T == Double)
func dotProduct<T: Numeric>(_ a: [T], _ b: [T]) -> T {
    zip(a, b).reduce(.zero) { $0 + $1.0 * $1.1 }
}
```

### Девиртуализация

Замена динамической диспетчеризации на статический вызов:

```swift
class Shape {
    func area() -> Double { 0 }
}

final class Circle: Shape {
    let radius: Double
    init(radius: Double) { self.radius = radius }
    override func area() -> Double { .pi * radius * radius }
}

// 'final' позволяет девиртуализацию:
// Вместо: vtable lookup -> indirect call
// Получаем: direct call -> возможен inlining

let circle = Circle(radius: 5.0)
circle.area() // Компилятор знает точный тип -> прямой вызов
```

### Другие оптимизации

```swift
// 1. Dead code elimination
func unusedBranch(_ x: Int) -> Int {
    if false { return expensiveComputation() } // Удаляется
    return x + 1
}

// 2. Constant folding
let result = 3 * 7 + 2 // Вычисляется в compile-time -> 23

// 3. Stack promotion
// Если компилятор может доказать, что замыкание не escapes,
// захваченные переменные аллоцируются на стеке, а не на куче

func localOperation() {
    var sum = 0
    [1, 2, 3].forEach { sum += $0 } // Замыкание non-escaping
    // -> 'sum' остается на стеке
    print(sum)
}
```

## Сравнение с JavaScript

### Объявление

```swift
// Swift
func greet(name: String) -> String {
    "Hello, \(name)!"
}
```

```javascript
// JavaScript
function greet(name) {
    return `Hello, ${name}!`;
}
```

### Ключевые различия

| Аспект | Swift | JavaScript |
|--------|-------|------------|
| Типизация параметров | Статическая, обязательная | Динамическая, нет проверки |
| Argument labels | Да (`greet(name:)`) | Нет |
| Перегрузка | Да, по типам и labels | Нет (последнее объявление перезаписывает) |
| Значения по умолчанию | Вычисляются в месте вызова | Вычисляются при вызове (ES6+) |
| Variadic | `Int...` -> `[Int]` | `...args` (rest parameters) |
| inout | Явная семантика copy-in copy-out | Нет аналога (объекты по ссылке) |
| Hoisting | Нет | Да (function declaration) |
| this/self | Явный контекст, нет rebinding | Динамический this, bind/call/apply |
| Closures | Reference type, ARC | Reference type, GC |
| Generic | Мономорфизация + witness tables | Нет (TypeScript -- erasure) |

### Variadic: Swift vs JavaScript

```swift
// Swift -- типизированный variadic
func sum(_ numbers: Int...) -> Int {
    numbers.reduce(0, +)
}
```

```javascript
// JavaScript -- rest parameters (нетипизированный)
function sum(...numbers) {
    return numbers.reduce((a, b) => a + b, 0);
}
```

### Функции высшего порядка

```swift
// Swift
let numbers = [1, 2, 3, 4, 5]
let doubled = numbers.map { $0 * 2 }
let evens = numbers.filter { $0 % 2 == 0 }
let sum = numbers.reduce(0, +) // оператор + как функция
```

```javascript
// JavaScript
const numbers = [1, 2, 3, 4, 5];
const doubled = numbers.map(x => x * 2);
const evens = numbers.filter(x => x % 2 === 0);
const sum = numbers.reduce((a, b) => a + b, 0);
```

### inout vs JavaScript reference semantics

```swift
// Swift -- явная семантика, компилятор проверяет exclusivity
func increment(_ value: inout Int) {
    value += 1
}
var x = 10
increment(&x) // Явный & показывает, что x будет изменен
```

```javascript
// JavaScript -- нет inout, объекты по ссылке, примитивы по значению
function increment(obj) {
    obj.value += 1; // Мутация через ссылку, неявно
}
let x = { value: 10 };
increment(x); // x.value === 11, но это не очевидно из вызова
```

> **Ключевое различие в дизайне:** Swift стремится к **явности** и **безопасности** -- argument labels, обязательные типы, `&` для inout, exclusivity enforcement. JavaScript стремится к **гибкости** и **краткости** -- динамические типы, неявная передача по ссылке, hoisting, flexible this.
