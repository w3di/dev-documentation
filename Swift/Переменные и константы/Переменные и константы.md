## var vs let

В Swift переменные объявляются через `var` (mutable), а константы -- через `let` (immutable). Это фундаментальное различие, определяющее не только семантику кода, но и возможности оптимизации компилятора.

### Базовый синтаксис

```swift
var mutableValue = 42        // можно изменять
let immutableValue = 42      // нельзя изменять после инициализации

mutableValue = 100           // OK
// immutableValue = 100      // Ошибка компиляции: Cannot assign to value: 'immutableValue' is a 'let' constant
```

### Семантика let для значимых и ссылочных типов

Ключевое различие: `let` для значимого типа (struct, enum, tuple) делает всю структуру неизменяемой. Для ссылочного типа (class) `let` фиксирует только ссылку, но не свойства объекта.

```swift
struct Point {
    var x: Double
    var y: Double
}

let point = Point(x: 1.0, y: 2.0)
// point.x = 3.0  // Ошибка: нельзя модифицировать свойства константной структуры

class ViewModel {
    var title: String = "Hello"
}

let viewModel = ViewModel()
viewModel.title = "World"    // OK: изменяем свойство, не ссылку
// viewModel = ViewModel()   // Ошибка: нельзя переназначить ссылку
```

### Deferred initialization

`let` поддерживает отложенную инициализацию -- значение может быть присвоено позже, но ровно один раз. Компилятор использует definite initialization analysis для проверки корректности:

```swift
let result: Int

if condition {
    result = computeA()
} else {
    result = computeB()
}

print(result) // Компилятор гарантирует, что result инициализирован
```

### SIL-уровень: var vs let

На уровне SIL (Swift Intermediate Language) `let` и `var` имеют разное представление. Для `let` компилятор генерирует `alloc_stack` с аннотацией `[let]`, что позволяет последующим проходам оптимизации исключить проверки мутабельности:

```
// SIL для let x = 42
%0 = integer_literal $Builtin.Int64, 42
%1 = struct $Int (%0 : $Builtin.Int64)
debug_value %1 : $Int, let, name "x"

// SIL для var x = 42
%0 = alloc_stack $Int, var, name "x"
%1 = integer_literal $Builtin.Int64, 42
%2 = struct $Int (%1 : $Builtin.Int64)
store %2 to %0 : $*Int
```

Для `let` значение хранится в SSA-регистре (Static Single Assignment), тогда как `var` требует аллокации на стеке и операции `store`/`load`.

### Почему let предпочтительнее

1. **Семантическая ясность** -- намерение разработчика очевидно
2. **Оптимизации компилятора** -- компилятор может инлайнить значения, исключать redundant loads, применять constant propagation
3. **Thread safety** -- неизменяемые значения inherently thread-safe
4. **Copy elision** -- компилятор может избежать копирования для `let` значений

```swift
// Компилятор может заменить на константу при оптимизации -O
let multiplier = 3.14159
let result = value * multiplier  // multiplier инлайнится
```

## Type inference и type annotation

### Type inference

Swift обладает мощной системой вывода типов, основанной на constraint-based type inference (система ограничений Hindley-Milner с расширениями). Компилятор создает систему type constraints и решает её для определения типов:

```swift
let integer = 42                // Int (по умолчанию для целых литералов)
let double = 3.14               // Double (по умолчанию для дробных литералов)
let string = "Hello"            // String
let boolean = true              // Bool
let array = [1, 2, 3]           // [Int]
let dictionary = ["a": 1]       // [String: Int]
let tuple = (1, "hello")        // (Int, String)
```

### Литеральные протоколы

Вывод типов для литералов работает через литеральные протоколы. Целочисленный литерал `42` может стать любым типом, реализующим `ExpressibleByIntegerLiteral`:

```swift
let a = 42                       // Int (дефолтный тип для IntegerLiteralType)
let b: Double = 42               // Double (через ExpressibleByIntegerLiteral)
let c: Float = 42                // Float
let d: Int8 = 42                 // Int8
let e: UInt64 = 42               // UInt64

// Кастомный тип с поддержкой литералов
struct Meters: ExpressibleByIntegerLiteral {
    let value: Double

    init(integerLiteral value: IntegerLiteralType) {
        self.value = Double(value)
    }
}

let distance: Meters = 100      // Meters(value: 100.0)
```

### Type annotation

Явная аннотация типа используется, когда: вывод типов неоднозначен, нужен конкретный подтип, или для документирования API:

```swift
// Необходимо: тип неочевиден
let data: Data = .init()
let view: some View = Text("Hello")

// Необходимо: нужен конкретный подтип
let smallNumber: Int8 = 42
let float: Float = 3.14

// Необходимо: пустые коллекции
let emptyArray: [String] = []
let emptyDict: [String: Int] = [:]

// Протокольный тип
let sequence: any Sequence<Int> = [1, 2, 3]
```

### Влияние на время компиляции

Сложные выражения с type inference могут существенно замедлять компиляцию. Constraint solver работает экспоненциально в худшем случае:

```swift
// ПЛОХО: экспоненциальный рост времени компиляции
let result = dict["a"]?.map { $0 + 1 }.flatMap { compute($0) }?.filter { $0 > threshold } ?? defaultValue

// ЛУЧШЕ: разбить на шаги с явными типами
let mapped: [Int]? = dict["a"]?.map { $0 + 1 }
let computed: [Int]? = mapped.flatMap { compute($0) }
let filtered: [Int]? = computed?.filter { $0 > threshold }
let result: [Int] = filtered ?? defaultValue
```

### Bidirectional type inference

Swift поддерживает двунаправленный вывод типов -- контекст использования влияет на тип выражения:

```swift
// Тип замыкания выводится из контекста
let numbers = [1, 2, 3, 4, 5]
let filtered = numbers.filter { $0 > 3 }  // $0 выводится как Int

// Enum member inference
enum Direction { case north, south, east, west }
let dir: Direction = .north  // .north выводится из контекста типа

// Тип результата определяет перегрузку
func compute() -> Int { return 42 }
func compute() -> String { return "42" }
let value: Int = compute()     // вызывается версия для Int
```

## Stored properties vs computed properties

### Stored properties

Stored properties хранят значение в памяти экземпляра. Каждый экземпляр получает собственную копию хранимого свойства, и эта копия размещается в layout структуры/класса:

```swift
struct Rectangle {
    var width: Double   // stored property (8 байт)
    var height: Double  // stored property (8 байт)
}
// Размер Rectangle: 16 байт (два Double)

print(MemoryLayout<Rectangle>.size)       // 16
print(MemoryLayout<Rectangle>.stride)     // 16
print(MemoryLayout<Rectangle>.alignment)  // 8
```

### Computed properties

Computed properties не хранят значение, а вычисляют его при каждом доступе. Они не занимают места в memory layout типа:

```swift
struct Rectangle {
    var width: Double
    var height: Double

    // Read-only computed property
    var area: Double {
        return width * height
    }

    // Read-write computed property
    var perimeter: Double {
        get {
            return 2 * (width + height)
        }
        set {
            // newValue -- неявный параметр
            let scale = newValue / perimeter
            width *= scale
            height *= scale
        }
    }
}

print(MemoryLayout<Rectangle>.size) // 16 (computed properties не занимают места)
```

### Computed properties с кастомным именем newValue

```swift
struct Temperature {
    var celsius: Double

    var fahrenheit: Double {
        get {
            return celsius * 9 / 5 + 32
        }
        set(newFahrenheit) {  // кастомное имя
            celsius = (newFahrenheit - 32) * 5 / 9
        }
    }
}
```

### SIL-представление computed properties

На уровне SIL computed property превращается в пару функций getter/setter. При использовании `@inlinable` или в пределах модуля с Whole Module Optimization компилятор может инлайнить getter, что делает computed property столь же эффективным, как хранимое:

```swift
// При WMO компилятор может оптимизировать:
let rect = Rectangle(width: 10, height: 20)
let a = rect.area  // инлайнится в: 10.0 * 20.0 = 200.0 (constant folding)
```

### Key path для свойств

```swift
struct User {
    var name: String
    var age: Int

    var isAdult: Bool {
        return age >= 18
    }
}

// WritableKeyPath для stored var property
let nameKeyPath: WritableKeyPath<User, String> = \User.name

// KeyPath (read-only) для computed property
let isAdultKeyPath: KeyPath<User, Bool> = \User.isAdult

var user = User(name: "Alice", age: 25)
user[keyPath: nameKeyPath] = "Bob"
print(user[keyPath: isAdultKeyPath]) // true
```

## lazy переменные

### Основы lazy

`lazy` свойства инициализируются только при первом обращении. Они полезны для тяжелых вычислений или зависимостей, которые не нужны сразу:

```swift
class DataProcessor {
    lazy var heavyResource: HeavyResource = {
        print("Initializing heavy resource...")
        return HeavyResource()
    }()

    // Простая форма без замыкания
    lazy var formatter = DateFormatter()

    // lazy может зависеть от self (в отличие от stored property с default value)
    lazy var description: String = "Processor: \(self.name)"

    var name: String

    init(name: String) {
        self.name = name
        // heavyResource НЕ инициализируется здесь
    }
}
```

### Ограничения lazy

```swift
struct Config {
    // lazy может быть только var, не let
    lazy var settings: [String: Any] = loadSettings()

    // lazy не может быть computed property
    // lazy var computed: Int { return 42 }  // Ошибка

    // lazy не может иметь property observers
    // lazy var observed: Int = 0 { didSet { } }  // Ошибка

    private func loadSettings() -> [String: Any] {
        return [:]
    }
}
```

### Внутреннее устройство lazy

Под капотом `lazy` реализован как `Optional`, начинающийся со значения `.none`. При первом обращении выполняется инициализатор, результат сохраняется, и последующие обращения возвращают сохраненное значение:

```swift
// Концептуально lazy var x: Int = computeX() эквивалентно:
private var _x: Int?

var x: Int {
    mutating get {
        if _x == nil {
            _x = computeX()
        }
        return _x!
    }
}
```

Именно поэтому доступ к `lazy` свойству является `mutating` операцией. Для структур это означает, что `lazy` свойство нельзя прочитать через `let`:

```swift
struct LazyStruct {
    lazy var value: Int = 42
}

let instance = LazyStruct()
// print(instance.value)  // Ошибка: Cannot use mutating getter on immutable value
```

### Thread safety lazy свойств

**`lazy` свойства не являются thread-safe.** Если два потока одновременно обращаются к неинициализированному lazy свойству, инициализатор может быть вызван дважды:

```swift
class UnsafeLazy {
    lazy var resource: Resource = Resource()  // НЕ thread-safe!
}

// Thread-safe альтернативы:
class SafeLazy {
    // Вариант 1: dispatch_once через глобальную/статическую переменную
    static let shared = SafeLazy()  // гарантированно thread-safe

    // Вариант 2: ручная синхронизация
    private var _cache: Resource?
    private let lock = NSLock()

    var cache: Resource {
        lock.lock()
        defer { lock.unlock() }
        if _cache == nil {
            _cache = Resource()
        }
        return _cache!
    }

    // Вариант 3: actor (Swift Concurrency)
    // Перемещение lazy свойства в actor
}
```

### lazy и память

Из-за внутреннего представления через Optional, `lazy` свойство может занимать больше памяти, чем обычное stored property. Для типов, где Optional не может использовать spare bits (оптимизацию внутреннего представления), добавляется дополнительный байт для тега:

```swift
struct WithLazy {
    lazy var value: Double = 0.0  // Optional<Double> = 9 байт (8 + 1 tag)
}

struct WithoutLazy {
    var value: Double = 0.0      // Double = 8 байт
}

print(MemoryLayout<WithLazy>.size)    // 9
print(MemoryLayout<WithoutLazy>.size) // 8
```

## Property observers

### willSet и didSet

Property observers позволяют реагировать на изменения хранимых свойств. `willSet` вызывается перед изменением, `didSet` -- после:

```swift
class StepCounter {
    var totalSteps: Int = 0 {
        willSet(newTotalSteps) {
            print("About to set totalSteps to \(newTotalSteps)")
            // Здесь totalSteps ещё имеет старое значение
        }
        didSet {
            if totalSteps > oldValue {
                print("Added \(totalSteps - oldValue) steps")
            }
            // Здесь totalSteps уже имеет новое значение
        }
    }
}

let counter = StepCounter()
counter.totalSteps = 200
// About to set totalSteps to 200
// Added 200 steps
```

### Порядок вызова

```swift
class Account {
    var balance: Double = 0.0 {
        willSet {
            print("1. willSet: \(balance) -> \(newValue)")
        }
        didSet {
            print("2. didSet: \(oldValue) -> \(balance)")
            if balance < 0 {
                balance = 0  // didSet НЕ вызывается рекурсивно при изменении в didSet
                print("3. Balance corrected to \(balance)")
            }
        }
    }
}
```

### Observers для наследуемых свойств

Подклассы могут добавлять observers к свойствам суперкласса, включая computed properties:

```swift
class Base {
    var value: Int {
        get { return _value }
        set { _value = newValue }
    }
    private var _value: Int = 0
}

class Derived: Base {
    override var value: Int {
        willSet {
            print("Derived willSet: \(newValue)")
        }
        didSet {
            print("Derived didSet: \(oldValue) -> \(value)")
        }
    }
}
```

### Observers и инициализация

Property observers **не вызываются** при инициализации свойства в `init`. Это предотвращает вызов observers до полной инициализации объекта:

```swift
class ViewController {
    var title: String = "" {
        didSet {
            updateUI()  // Не вызывается при init
        }
    }

    init(title: String) {
        self.title = title  // didSet НЕ вызывается
    }

    // Если нужно вызвать observer при init:
    init(titleWithObserver: String) {
        defer { self.title = titleWithObserver }  // Хак: didSet ВЫЗЫВАЕТСЯ
    }

    func updateUI() { /* ... */ }
}
```

### SIL-представление property observers

На уровне SIL property observer реализуется через setter, содержащий вызовы willSet и didSet функций. Компилятор генерирует три функции: getter, setter и modify корутину:

```
// Упрощенный SIL для свойства с observers:
sil @setter : $@convention(method) (Int, @inout MyType) -> () {
    // 1. Загрузить старое значение
    // 2. Вызвать willSet(newValue)
    // 3. Записать новое значение
    // 4. Вызвать didSet(oldValue)
}
```

### Property Wrapper как альтернатива observers

Для сложной логики наблюдения property wrappers часто предпочтительнее:

```swift
@propertyWrapper
struct Clamped<Value: Comparable> {
    var wrappedValue: Value {
        didSet {
            wrappedValue = min(max(wrappedValue, range.lowerBound), range.upperBound)
        }
    }
    let range: ClosedRange<Value>

    init(wrappedValue: Value, _ range: ClosedRange<Value>) {
        self.range = range
        self.wrappedValue = min(max(wrappedValue, range.lowerBound), range.upperBound)
    }
}

struct Player {
    @Clamped(0...100) var health: Int = 100
    @Clamped(0...999) var score: Int = 0
}

var player = Player()
player.health = 150  // clamped to 100
player.health = -10  // clamped to 0
```

## Static и class свойства

### Static свойства

`static` свойства принадлежат типу, а не экземпляру. Они существуют в единственном экземпляре и инициализируются лениво при первом обращении (thread-safe, используя dispatch_once под капотом):

```swift
struct AppConfig {
    static let version = "2.1.0"
    static let buildNumber = 142
    static var isDebug = false

    // Static computed property
    static var fullVersion: String {
        return "\(version) (\(buildNumber))"
    }

    // Static stored property с инициализатором
    static let defaultHeaders: [String: String] = {
        var headers = ["Content-Type": "application/json"]
        #if DEBUG
        headers["X-Debug"] = "true"
        #endif
        return headers
    }()
}

// Доступ через тип
print(AppConfig.version)      // "2.1.0"
print(AppConfig.fullVersion)  // "2.1.0 (142)"
```

### class vs static для классов

`class` свойства (только computed) могут быть переопределены в подклассах. `static` -- не могут:

```swift
class Animal {
    // static нельзя override
    static var species: String {
        return "Unknown"
    }

    // class можно override
    class var sound: String {
        return "..."
    }

    // static stored property (эквивалент class final)
    static let kingdom = "Animalia"
}

class Dog: Animal {
    // override static var species  // Ошибка!

    override class var sound: String {
        return "Woof!"
    }
}

print(Dog.sound)    // "Woof!"
print(Dog.kingdom)  // "Animalia" (наследуется)
```

### Singleton pattern

Static свойства -- стандартный способ реализации синглтона:

```swift
class NetworkManager {
    static let shared = NetworkManager()

    private init() {
        // private init предотвращает создание дополнительных экземпляров
    }

    func request(_ url: URL) async throws -> Data {
        // ...
        return Data()
    }
}

// Thread-safe доступ
let manager = NetworkManager.shared
```

### Метатипы и static dispatch

Статические свойства используют static dispatch (прямой вызов), что делает их быстрее, чем виртуальный dispatch для instance properties:

```swift
protocol Configurable {
    static var defaultConfig: Self { get }
}

struct Theme: Configurable {
    var primaryColor: String
    var fontSize: Int

    static var defaultConfig: Theme {
        return Theme(primaryColor: "#007AFF", fontSize: 16)
    }
}

// При вызове через protocol -- witness table dispatch
// При вызове через конкретный тип -- static dispatch (инлайнится)
let theme = Theme.defaultConfig
```

## Глобальные и локальные переменные

### Глобальные переменные

Глобальные переменные в Swift инициализируются лениво при первом обращении, аналогично `static` свойствам. Это инициализация thread-safe (реализована через `swift_once`):

```swift
// Глобальная переменная -- lazy + thread-safe по умолчанию
let globalConfig = loadConfiguration()
var globalCache: [String: Any] = [:]

func loadConfiguration() -> Configuration {
    print("Loading configuration...")  // Вызывается один раз при первом обращении
    return Configuration()
}
```

### Локальные переменные

Локальные переменные размещаются на стеке и не требуют thread safety (стек принадлежит конкретному потоку):

```swift
func processData(_ data: [Int]) -> Int {
    var sum = 0              // Stack allocation
    let count = data.count   // Stack allocation

    for value in data {
        let doubled = value * 2  // Stack allocation, оптимизируется в регистр
        sum += doubled
    }

    return sum
}
```

### Capture семантика

Когда локальная переменная захватывается замыканием, она может быть "promoted" со стека в heap:

```swift
func makeCounter() -> () -> Int {
    var count = 0  // Изначально на стеке, но...

    return {
        count += 1  // ...count захвачен, перемещается в heap (box allocation)
        return count
    }
}

let counter = makeCounter()
print(counter())  // 1
print(counter())  // 2

// На уровне SIL:
// %box = alloc_box ${ var Int }  // Heap allocation для захваченной переменной
```

### Разница в SIL между локальными и захваченными переменными

```swift
func example() {
    var local = 42          // alloc_stack -- стек
    var captured = 42       // alloc_box -- куча (если захвачен замыканием)

    let closure = {
        captured += 1
    }

    local += 1              // Быстрый доступ к стеку
    closure()               // Доступ через указатель на heap
}
```

## Thread safety переменных

### Проблемы конкурентного доступа

Swift не обеспечивает автоматическую thread safety для изменяемых переменных. Data race -- это одновременный неатомарный доступ к памяти, где хотя бы один доступ является записью:

```swift
// НЕБЕЗОПАСНО: data race
var sharedCounter = 0

DispatchQueue.concurrentPerform(iterations: 1000) { _ in
    sharedCounter += 1  // Data race! Результат непредсказуем
}
```

### Механизмы синхронизации

```swift
// 1. DispatchQueue (serial)
class ThreadSafeCounter {
    private var _value = 0
    private let queue = DispatchQueue(label: "counter.queue")

    var value: Int {
        return queue.sync { _value }
    }

    func increment() {
        queue.sync { _value += 1 }
    }
}

// 2. NSLock
class LockCounter {
    private var _value = 0
    private let lock = NSLock()

    var value: Int {
        lock.lock()
        defer { lock.unlock() }
        return _value
    }

    func increment() {
        lock.lock()
        defer { lock.unlock() }
        _value += 1
    }
}

// 3. os_unfair_lock (более производительный, чем NSLock)
import os

class UnfairLockCounter {
    private var _value = 0
    private let lock = OSAllocatedUnfairLock()

    var value: Int {
        lock.withLock { _value }
    }

    func increment() {
        lock.withLock { _value += 1 }
    }
}
```

### Swift Concurrency: Actor

Actors -- встроенный в язык механизм обеспечения thread safety:

```swift
actor Counter {
    private(set) var value = 0

    func increment() {
        value += 1  // Гарантированно безопасно -- actor isolation
    }

    func reset() {
        value = 0
    }
}

// Все обращения к actor -- асинхронные (кроме изолированного контекста)
let counter = Counter()
await counter.increment()
print(await counter.value)

// nonisolated свойства не защищены actor
actor Service {
    let id: UUID = UUID()           // let -- immutable, доступ без await
    nonisolated let name: String    // Явно nonisolated

    var mutableState: Int = 0       // Защищено actor isolation

    init(name: String) {
        self.name = name
    }
}
```

### Sendable и переменные

Протокол `Sendable` гарантирует безопасность передачи значений между потоками:

```swift
// Значимые типы без изменяемого shared state -- автоматически Sendable
struct Point: Sendable {
    let x: Double
    let y: Double
}

// Классы -- Sendable только если все свойства let и Sendable
final class ImmutableConfig: Sendable {
    let apiKey: String
    let timeout: TimeInterval

    init(apiKey: String, timeout: TimeInterval) {
        self.apiKey = apiKey
        self.timeout = timeout
    }
}

// @unchecked Sendable -- ручная гарантия thread safety
final class ThreadSafeCache: @unchecked Sendable {
    private var storage: [String: Any] = [:]
    private let lock = NSLock()

    func set(_ value: Any, forKey key: String) {
        lock.withLock { storage[key] = value }
    }

    func get(_ key: String) -> Any? {
        lock.withLock { storage[key] }
    }
}
```

## Оптимизации компилятора

### Copy-on-Write (COW)

Стандартные коллекции Swift (Array, Dictionary, Set, String) используют COW-семантику. Данные копируются только при мутации, если существует более одной ссылки:

```swift
var array1 = [1, 2, 3, 4, 5]
var array2 = array1  // НЕТ копирования -- оба указывают на один буфер

// Проверка уникальности ссылки
print(array1.withUnsafeBufferPointer { $0.baseAddress! })
print(array2.withUnsafeBufferPointer { $0.baseAddress! })
// Оба адреса одинаковы!

array2.append(6)  // Мутация -> копирование буфера (COW)
// Теперь адреса различаются
```

### Реализация кастомного COW

```swift
final class StorageRef<T> {
    var value: T
    init(_ value: T) { self.value = value }
}

struct COWContainer<T> {
    private var storage: StorageRef<T>

    init(_ value: T) {
        storage = StorageRef(value)
    }

    var value: T {
        get { storage.value }
        set {
            // isKnownUniquelyReferenced -- ключ к COW оптимизации
            if !isKnownUniquelyReferenced(&storage) {
                storage = StorageRef(newValue)
            } else {
                storage.value = newValue
            }
        }
    }
}
```

### Stack allocation

Компилятор Swift предпочитает размещать значения на стеке, когда это возможно. Stack allocation -- это инкремент указателя стека (практически бесплатно):

```swift
// Stack allocated
func compute() {
    let point = Point(x: 1.0, y: 2.0)        // Stack: 16 байт
    var numbers: (Int, Int, Int) = (1, 2, 3)  // Stack: 24 байта
    let flag = true                            // Stack: 1 байт (или регистр)
}

// Heap allocated
func createObject() {
    let object = MyClass()  // Heap: malloc + reference counting overhead
}
```

### Escape analysis и stack promotion

Компилятор анализирует, "убегает" ли значение из функции. Если нет -- даже ссылочные типы могут быть размещены на стеке:

```swift
// При -O компилятор может разместить на стеке:
func processLocally() {
    let temp = NSMutableArray()  // Может быть stack-promoted
    temp.add(42)
    print(temp.count)
    // temp не убегает из функции
}

// Не может быть stack-promoted:
func processAndReturn() -> NSMutableArray {
    let temp = NSMutableArray()
    temp.add(42)
    return temp  // temp убегает -> heap allocation обязательна
}
```

### Whole Module Optimization (WMO)

При WMO компилятор видит весь модуль и может применять агрессивные оптимизации:

```swift
// file1.swift
struct Point {
    var x: Double
    var y: Double
}

// file2.swift
func distance(_ p1: Point, _ p2: Point) -> Double {
    let dx = p1.x - p2.x
    let dy = p1.y - p2.y
    return (dx * dx + dy * dy).squareRoot()
}

// При WMO:
// 1. Point может быть инлайнен (известен layout)
// 2. distance() может быть инлайнен
// 3. Промежуточные переменные dx, dy оптимизируются в регистры
// 4. Dead code elimination для неиспользуемых свойств
```

### Оптимизация let vs var

```swift
// let позволяет компилятору:
let constant = 42

// 1. Constant propagation -- подставить 42 в места использования
// 2. Dead store elimination -- не хранить значение вовсе
// 3. Inlining -- инлайнить computed properties

// var препятствует некоторым оптимизациям:
var variable = 42

// Компилятор не может гарантировать, что variable не изменится,
// поэтому должен загружать значение при каждом использовании
```

## Сравнение с JavaScript

### var, let, const: Swift vs JavaScript

| Характеристика | Swift `var` | Swift `let` | JS `var` | JS `let` | JS `const` |
|---|---|---|---|---|---|
| Мутабельность | Mutable | Immutable | Mutable | Mutable | Binding immutable* |
| Область видимости | Block | Block | Function | Block | Block |
| Hoisting | Нет | Нет | Да (undefined) | Нет (TDZ) | Нет (TDZ) |
| Повторное объявление | Нет | Нет | Да | Нет | Нет |
| Тип | Статический | Статический | Динамический | Динамический | Динамический |
| Инициализация | Обязательна | Обязательна | Опционально | Опционально | Обязательна |

*`const` в JS фиксирует только binding, не содержимое объекта.

### Ключевые различия

```swift
// Swift let -- глубокая иммутабельность для value types
let point = Point(x: 1, y: 2)
// point.x = 3  // Ошибка! Вся структура неизменяема
```

```javascript
// JS const -- только привязка
const point = { x: 1, y: 2 };
point.x = 3;  // OK! Мутация свойств разрешена
// point = {};  // Ошибка! Нельзя переприсвоить

// JS var -- function-scoped + hoisting
console.log(x);  // undefined (hoisted)
var x = 42;

// JS let -- block-scoped + TDZ
// console.log(y);  // ReferenceError (TDZ)
let y = 42;
```

### Type safety

```swift
// Swift: статическая типизация -- ошибки на этапе компиляции
var count: Int = 42
// count = "hello"  // Ошибка компиляции

// Type inference не означает динамическую типизацию
var inferred = 42    // Тип Int зафиксирован навсегда
// inferred = "hello"  // Ошибка компиляции
```

```javascript
// JavaScript: динамическая типизация -- ошибки в рантайме
let count = 42;
count = "hello";  // OK -- тип может меняться
count = [];       // OK
```

### Property observers аналоги

```javascript
// JavaScript: Proxy для аналога property observers
const handler = {
    set(target, prop, value) {
        console.log(`Setting ${prop} from ${target[prop]} to ${value}`);
        target[prop] = value;
        return true;
    }
};

const obj = new Proxy({ name: "Alice" }, handler);
obj.name = "Bob";  // "Setting name from Alice to Bob"

// JavaScript: Object.defineProperty
Object.defineProperty(obj, 'age', {
    get() { return this._age; },
    set(value) {
        if (value < 0) throw new Error("Invalid age");
        this._age = value;
    }
});
```

```swift
// Swift: встроенные property observers -- более лаконичны
class Person {
    var name: String = "Alice" {
        didSet {
            print("Setting name from \(oldValue) to \(name)")
        }
    }

    var age: Int = 0 {
        willSet {
            precondition(newValue >= 0, "Invalid age")
        }
    }
}
```

## Итого: Best practices

1. **Предпочитайте `let`** -- используйте `var` только когда значение действительно должно меняться
2. **Type inference** -- используйте, когда тип очевиден; добавляйте аннотации для API и неочевидных случаев
3. **Computed properties** -- для производных значений; stored -- для независимых данных
4. **lazy** -- для тяжелых инициализаций, но помните о thread safety
5. **Property observers** -- для побочных эффектов при изменении; property wrappers -- для переиспользуемой логики
6. **static** -- для type-level данных; `class` -- только для переопределяемых computed properties
7. **Thread safety** -- используйте actors в новом коде, locks для legacy; никогда не полагайтесь на "само работает"
8. **Профилируйте** -- включайте WMO, проверяйте stack vs heap allocation через Instruments (Allocations)
