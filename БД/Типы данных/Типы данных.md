# Типы данных

В SQL каждый столбец в таблице должен иметь определенный тип данных, указывающий на то, какая информация может храниться в этом столбце.

Тип данных столбца определяет:
- Какие операции можно выполнять с данными в этом столбце
- Сколько места требуется для хранения данных
- Как данные хранятся внутри

## Строковые типы данных

Строковый тип данных является наиболее используемым. Благодаря ему в базе данных хранятся как текстовые, так и различные двоичные данные (например, картинки).

### CHARACTER, VARCHAR, TEXT

| Тип | Описание | Диапазон символов |
|-----|----------|-------------------|
| `CHAR(n)` | Текстовые строки фиксированной длины. Дополняется пробелами до указанной длины. | Длина от 1 до 10,485,760 |
| `VARCHAR(n)` | Текстовые строки переменной длины с ограничением. | Длина от 1 до 10,485,760 |
| `TEXT` | Текстовые строки неограниченной переменной длины. | Практически неограниченная длина (до 1 ГБ) |

### CHAR(n)

Фиксированная длина:
- Если строка короче указанной длины, она дополняется пробелами
- Всегда занимает n байт памяти

```sql
CREATE TABLE Example (
    code CHAR(5)
);

INSERT INTO Example (code) VALUES ('ABC');
```

Значение `'ABC'` будет сохранено как `'ABC  '` (с двумя пробелами).

### VARCHAR(n)

Переменная длина с ограничением:
- Хранит только фактические символы
- Не дополняется пробелами
- Занимает столько памяти, сколько нужно для хранения данных (плюс небольшой overhead)

```sql
CREATE TABLE Users (
    username VARCHAR(50),
    email VARCHAR(255)
);

INSERT INTO Users (username, email)
VALUES ('john_doe', 'john@example.com');
```

### TEXT

Неограниченная переменная длина:
- Может хранить текст практически любой длины (до 1 ГБ)
- Не требует указания максимальной длины
- Идеален для хранения больших текстов

```sql
CREATE TABLE Articles (
    title VARCHAR(255),
    content TEXT
);

INSERT INTO Articles (title, content)
VALUES ('Article Title', 'Very long article content...');
```

### Рекомендации по выбору строкового типа

Используйте `CHAR(n)`:
- Когда длина данных фиксирована (коды стран, почтовые индексы)
- Когда все значения имеют одинаковую длину

Используйте `VARCHAR(n)`:
- Когда длина данных переменная, но имеет логическое ограничение
- Для имен пользователей, email адресов, названий
- Когда нужна валидация максимальной длины

Используйте `TEXT`:
- Для больших текстов без ограничения длины
- Для описаний, статей, комментариев
- Когда максимальная длина неизвестна или не имеет значения

В PostgreSQL тип `TEXT` предпочтительнее `VARCHAR` без ограничения длины, так как они имеют одинаковую производительность.

Вместо:

```sql
CREATE TABLE Posts (
    content VARCHAR
);
```

Лучше использовать:

```sql
CREATE TABLE Posts (
    content TEXT
);
```

### Производительность строковых типов

Все три типа (`CHAR`, `VARCHAR`, `TEXT`) имеют схожую производительность в PostgreSQL:
- Нет значительной разницы в скорости операций чтения/записи
- Основное различие -- в способе хранения и валидации данных
- `CHAR` может быть менее эффективным из-за дополнения пробелами

```sql
CREATE TABLE Products (
    sku CHAR(10),
    name VARCHAR(255) NOT NULL,
    description TEXT,
    category VARCHAR(50)
);

INSERT INTO Products (sku, name, description, category)
VALUES
    ('PROD000001', 'Laptop', 'High-performance laptop with...', 'Electronics'),
    ('PROD000002', 'Mouse', 'Wireless optical mouse', 'Accessories');
```

## Числовые типы данных

Числовые данные разделяются на точные и приближенные, на целые и вещественные.

### Целые числа

| Тип | Объем памяти | Диапазон |
|-----|--------------|----------|
| `SMALLINT` | 2 байта | от -32768 до 32767 |
| `INT` / `INTEGER` (синонимы) | 4 байта | от -2147483648 до 2147483647 |
| `BIGINT` | 8 байт | от -9223372036854775808 до 9223372036854775807 |

```sql
CREATE TABLE Products (
    id INTEGER,
    quantity SMALLINT,
    views_count BIGINT
);
```

Рекомендации:
- Используйте `SMALLINT` для небольших целых чисел (возраст, количество товара)
- Используйте `INTEGER` для стандартных целых чисел (ID, счетчики)
- Используйте `BIGINT` для больших чисел (счетчики просмотров, большие ID)

### Автоинкрементные типы (SERIAL)

| Тип | Объем памяти | Диапазон |
|-----|--------------|----------|
| `SMALLSERIAL` | 2 байта | от 1 до 32767 |
| `SERIAL` | 4 байта | от 1 до 2147483647 |
| `BIGSERIAL` | 8 байт | от 1 до 9223372036854775807 |

Типы `SERIAL` являются псевдотипами для создания автоинкрементных столбцов. `SERIAL` эквивалентен `INTEGER` с автоматически создаваемой последовательностью.

```sql
CREATE TABLE Users (
    id SERIAL PRIMARY KEY,
    username VARCHAR(50)
);

-- При добавлении записи поле id генерируется автоматически
INSERT INTO Users (username) VALUES ('john_doe');
```

Рекомендации:
- Используйте `SERIAL` для первичных ключей в большинстве таблиц
- Используйте `BIGSERIAL` если ожидается очень большое количество записей (миллиарды)
- Используйте `SMALLSERIAL` только если точно знаете, что записей будет меньше 32767

### Точные вещественные числа (NUMERIC / DECIMAL)

| Тип | Точность | Диапазон |
|-----|----------|----------|
| `DECIMAL[(precision, scale)]` / `NUMERIC[(precision, scale)]` (синонимы) | Пользовательская | До 131072 цифр до десятичной точки и до 16383 цифр после |

Тип `NUMERIC` хранит точное вещественное значение данных. Используется, когда точность является критически важной, например при хранении финансовых данных.

Параметры:
- `precision` -- общее количество значащих цифр
- `scale` -- количество цифр после десятичной точки

```sql
CREATE TABLE Users (
    id SERIAL PRIMARY KEY,
    name VARCHAR(255),
    salary NUMERIC(10, 2)
);

-- salary может хранить числа с максимум 10 цифрами, 2 из которых после точки
-- Диапазон: от -99999999.99 до 99999999.99
INSERT INTO Users (name, salary) VALUES
    ('Alice', 75000.50),
    ('Bob', 125000.75),
    ('Charlie', 999999.99);
```

Рекомендации:
- Всегда используйте `NUMERIC` или `DECIMAL` для денежных значений
- Никогда не используйте типы с плавающей точкой для денег
- Указывайте точность явно: `NUMERIC(10, 2)` вместо просто `NUMERIC`

### Приближенные числа (с плавающей точкой)

| Тип | Объем памяти | Точность | Диапазон |
|-----|--------------|----------|----------|
| `REAL` | 4 байта | 6 знаков | от 1E-37 до 1E+37 |
| `DOUBLE PRECISION` | 8 байтов | 15 знаков | от 1E-307 до 1E+308 |

Типы с плавающей точкой используются для приближенных вычислений.

PostgreSQL также поддерживает специальные значения:
- `Infinity` -- положительная бесконечность
- `-Infinity` -- отрицательная бесконечность
- `NaN` -- не число (Not a Number)

```sql
CREATE TABLE Measurements (
    id SERIAL PRIMARY KEY,
    temperature REAL,
    precise_value DOUBLE PRECISION
);

INSERT INTO Measurements (temperature, precise_value) VALUES
    (36.6, 3.14159265358979),
    ('Infinity', 'NaN');
```

Рекомендации:
- Используйте для научных вычислений, где не требуется абсолютная точность
- НЕ используйте для финансовых данных
- Используйте `REAL` когда достаточно 6 знаков точности
- Используйте `DOUBLE PRECISION` когда нужна более высокая точность

### Сравнение: целые vs автоинкрементные

```sql
-- Обычное целое число
CREATE TABLE Products (
    id INTEGER PRIMARY KEY,
    name VARCHAR(255)
);

-- Автоинкрементное поле
CREATE TABLE Products (
    id SERIAL PRIMARY KEY,
    name VARCHAR(255)
);
```

### Сравнение: точные vs приближенные

```sql
-- Точные (для финансов)
CREATE TABLE Orders (
    id SERIAL PRIMARY KEY,
    total_amount NUMERIC(10, 2)
);

-- Приближенные (для научных расчетов)
CREATE TABLE Experiments (
    id SERIAL PRIMARY KEY,
    measurement DOUBLE PRECISION
);
```

### Комплексный пример с числовыми типами

```sql
CREATE TABLE Products (
    id SERIAL PRIMARY KEY,
    name VARCHAR(255) NOT NULL,
    price NUMERIC(10, 2) NOT NULL,
    quantity SMALLINT DEFAULT 0,
    weight REAL,
    views_count BIGINT DEFAULT 0,
    rating DOUBLE PRECISION
);

INSERT INTO Products (name, price, quantity, weight, rating) VALUES
    ('Laptop', 1299.99, 15, 2.5, 4.7),
    ('Mouse', 29.99, 150, 0.1, 4.3),
    ('Keyboard', 89.99, 50, 0.8, 4.5);
```

## Числовые функции и операции

Создание числовых данных в SQL: можно ввести число как литерал, получить из столбца таблицы или сгенерировать путем вычислений.

При вычислениях можно использовать стандартные арифметические операции (+, -, *, /) и изменять приоритеты вычислений с помощью скобок.

```sql
SELECT 2 * ((22 - 16) / (2 + 1)) AS calc_example;
```

### Математические функции

| Функция | Описание |
|---------|----------|
| `POWER(num, power)` | Число в указанной степени |
| `SQRT(num)` | Квадратный корень числа |
| `LOG(base, num)` | Логарифм числа по указанному основанию |
| `EXP(num)` | e в степени num |
| `SIN(num)` | Синус числа |
| `COS(num)` | Косинус числа |
| `TAN(num)` | Тангенс числа |

### Округление чисел

**CEIL и FLOOR** -- округление к ближайшему целому. CEIL -- в большую сторону, FLOOR -- в меньшую.

```sql
SELECT CEIL(69.69) AS ceiling, FLOOR(69.69) AS floor;
-- CEIL = 70, FLOOR = 69
```

**ROUND** -- округление к ближайшему целому. Если десятичная часть >= 0.5, округляет вверх.

```sql
SELECT ROUND(69.499), ROUND(69.5), ROUND(69.501);
-- 69, 70, 70
```

ROUND позволяет округлять до указанного количества знаков после запятой:

```sql
SELECT ROUND(69.7171, 1), ROUND(69.7171, 2), ROUND(69.7171, 3);
-- 69.7, 69.72, 69.717
```

Второй аргумент может быть отрицательным -- цифры слева от точки становятся нулями:

```sql
SELECT ROUND(1691.7, -1), ROUND(1691.7, -2), ROUND(1691.7, -3);
-- 1690, 1700, 2000
```

**TRUNC** -- аналогична ROUND, но вместо округления просто отбрасывает ненужные цифры:

```sql
SELECT TRUNC(69.7979, 1), TRUNC(69.7979, 2), TRUNC(69.7979, 3);
-- 69.7, 69.79, 69.797

SELECT TRUNC(69.7979, -1);
-- 60
```

### Работа со знаковыми числами

**SIGN** -- возвращает -1 для отрицательных, 0 для нуля и 1 для положительных:

```sql
SELECT SIGN(-69), SIGN(0), SIGN(69);
-- -1, 0, 1
```

**ABS** -- возвращает абсолютное значение числа:

```sql
SELECT ABS(-69), ABS(0), ABS(69);
-- 69, 0, 69
```

## Логический тип (BOOLEAN)

Используется для хранения логических значений.

Допустимые значения:
- `TRUE` (или `true`, `'t'`, `'yes'`, `'on'`, `'1'`)
- `FALSE` (или `false`, `'f'`, `'no'`, `'off'`, `'0'`)
- `NULL`

```sql
CREATE TABLE Products (
    id SERIAL PRIMARY KEY,
    name VARCHAR(255),
    is_available BOOLEAN DEFAULT TRUE,
    is_featured BOOLEAN DEFAULT FALSE
);

INSERT INTO Products (name, is_available, is_featured) VALUES
    ('Laptop', TRUE, TRUE),
    ('Old Phone', FALSE, FALSE);

SELECT * FROM Products WHERE is_available = TRUE;
-- Или короткая запись:
SELECT * FROM Products WHERE is_available;
```

## Дата и время

Временные данные являются наиболее сложными в SQL из-за множества способов задания, наличия временных зон и неочевидности вычислений.

### Типы данных для даты и времени

| Тип | Описание | Диапазон значений | Размер |
|-----|----------|-------------------|--------|
| `DATE` | Дата в виде ГГГГ-ММ-ДД. Например, `2022-12-05` | от 4713 BC до 5874897 AD | 4 байта |
| `TIME` | Время в формате ЧЧ:ММ:СС. Например, `14:30:45` | от 00:00:00 до 24:00:00 | 8 байт |
| `TIMESTAMP` | Дата и время без часового пояса. Например, `2022-12-05 10:37:22` | от 4713 BC до 294276 AD | 8 байт |
| `TIMESTAMPTZ` | Дата и время с часовым поясом. Например, `2022-12-05 10:37:22+03` | от 4713 BC до 294276 AD | 8 байт |
| `INTERVAL` | Интервал времени. Например, `1 year 2 months 3 days 4 hours` | от -178000000 лет до 178000000 лет | 16 байт |

### Отличие TIMESTAMP и TIMESTAMPTZ

**TIMESTAMP** (TIMESTAMP WITHOUT TIME ZONE) -- хранит дату и время без информации о часовом поясе. PostgreSQL не знает, в каком часовом поясе была записана дата, и не производит никаких преобразований.

```sql
CREATE TABLE timestamp_table (timestamp_field TIMESTAMP);
SET timezone = 'UTC';
INSERT INTO timestamp_table VALUES('2022-06-16 16:37:23');
SET timezone = 'Europe/Moscow';
SELECT * FROM timestamp_table;
-- Результат: 2022-06-16 16:37:23 (значение не изменилось)
```

**TIMESTAMPTZ** (TIMESTAMP WITH TIME ZONE) -- хранит дату и время с информацией о часовом поясе. PostgreSQL автоматически преобразует время в UTC для хранения и обратно в локальный часовой пояс при выводе.

```sql
CREATE TABLE timestamptz_table (timestamptz_field TIMESTAMPTZ);
SET timezone = 'UTC';
INSERT INTO timestamptz_table VALUES('2022-06-16 16:37:23');
SET timezone = 'Europe/Moscow';
SELECT * FROM timestamptz_table;
-- Результат: 2022-06-16 19:37:23+03 (время автоматически скорректировано)
```

Рекомендации:
- Используйте `TIMESTAMP` -- когда часовой пояс не важен, для локальных событий, когда все данные в одном часовом поясе
- Используйте `TIMESTAMPTZ` -- для глобальных приложений, для логов и аудита, в большинстве случаев (предпочтительный тип)

### INTERVAL

Тип `INTERVAL` используется для хранения периодов времени -- промежутки в годах, месяцах, днях, часах, минутах и секундах.

```sql
SELECT '1 year 2 months 3 days 4 hours 5 minutes 6 seconds'::INTERVAL;
SELECT '2 weeks'::INTERVAL;
SELECT '90 minutes'::INTERVAL;
```

Использование с арифметическими операциями:

```sql
SELECT NOW() + INTERVAL '1 day';
SELECT NOW() - INTERVAL '3 hours';
SELECT NOW() + INTERVAL '2 weeks 3 days';
```

Пример:

```sql
CREATE TABLE Tasks (
    id SERIAL PRIMARY KEY,
    name VARCHAR(255),
    created_at TIMESTAMPTZ DEFAULT NOW(),
    duration INTERVAL
);

INSERT INTO Tasks (name, duration) VALUES
    ('Task 1', '2 hours'),
    ('Task 2', '1 day 3 hours'),
    ('Task 3', '30 minutes');

SELECT name, created_at + duration AS deadline
FROM Tasks;
```

### Способы задания значений даты и времени

Значения могут быть заданы в различных форматах:

| Формат | Пример |
|--------|--------|
| ISO 8601 дата и время | `'YYYY-MM-DD HH:MM:SS'` |
| С часовым поясом | `'YYYY-MM-DD HH:MM:SS+TZ'` |
| Только дата | `'YYYY-MM-DD'` |
| Только время | `'HH:MM:SS'` |

```sql
CREATE TABLE date_table (
    date_field DATE,
    time_field TIME,
    timestamp_field TIMESTAMP,
    timestamptz_field TIMESTAMPTZ
);

INSERT INTO date_table VALUES(
    '2022-06-16',
    '16:37:23',
    '2022-06-16 16:37:23',
    '2022-06-16 16:37:23+03'
);
```

Строковое представление и CAST:

```sql
SELECT  CAST('2022-06-16 16:37:23' AS TIMESTAMP) AS timestamp_1,
        CAST('2014/02/22 16:37:22' AS TIMESTAMP) AS timestamp_2,
        CAST('20220616163723' AS TIMESTAMP) AS timestamp_3,
        CAST('2021-02-12' AS DATE) AS date_1,
        CAST('16:23:13' AS TIME) AS time_1;
```

При указании даты допускается использовать любой знак пунктуации в качестве разделителя или задавать дату без разделителя, слитно.

### Часовые пояса

В качестве точки отсчета времени используется UTC (Coordinated Universal Time). Все остальные часовые пояса описываются количеством часов сдвига от UTC.

Часовой пояс может задаваться:
- глобально для базы данных
- для конкретного пользователя
- для текущей пользовательской сессии

```sql
ALTER DATABASE mydb SET timezone = 'Europe/Moscow';
ALTER USER myuser SET timezone = 'Europe/Moscow';
SET TIME ZONE 'Europe/Moscow';
SET TIME ZONE '+03:00';
```

Проверка текущего часового пояса:

```sql
SHOW timezone;
```

## Функции даты и времени

### Получение текущей даты и времени

```sql
SELECT NOW();              -- текущая дата и время с часовым поясом
SELECT CURRENT_DATE;       -- текущая дата
SELECT CURRENT_TIME;       -- текущее время
SELECT CURRENT_TIMESTAMP;  -- текущая дата и время (аналог NOW())
```

### EXTRACT -- извлечение компонентов даты

```sql
EXTRACT(YEAR FROM date)    -- год
EXTRACT(MONTH FROM date)   -- месяц (от 1 до 12)
EXTRACT(DAY FROM date)     -- день (от 1 до 31)
EXTRACT(HOUR FROM time)    -- час (от 0 до 23)
EXTRACT(MINUTE FROM time)  -- минуты (от 0 до 59)
```

### TO_DATE -- парсинг даты из строки

Если строка не соответствует стандартному формату, используется функция TO_DATE:

```sql
SELECT TO_DATE('November 13, 1998', 'Month DD, YYYY') AS date;
```

### AGE -- определение возраста / разницы между датами

Неправильный подход -- вычисление разницы годов (не учитывает, был ли день рождения в этом году):

```sql
SELECT EXTRACT(YEAR FROM NOW()) - EXTRACT(YEAR FROM TIMESTAMP '2003-07-03 14:10:26');
```

Неправильный подход -- разница дней, деленная на 365 (не учитывает високосные годы):

```sql
SELECT FLOOR(EXTRACT(DAY FROM NOW() - TIMESTAMP '2003-07-03 14:10:26') / 365);
```

Правильный подход -- использование функции AGE:

```sql
SELECT EXTRACT(YEAR FROM AGE(NOW(), TIMESTAMP '2003-07-03 14:10:26'));
```

Функция AGE вычисляет точный интервал между двумя датами.

### Комплексный пример с датами

```sql
CREATE TABLE Events (
    id SERIAL PRIMARY KEY,
    name VARCHAR(255) NOT NULL,
    event_date DATE,
    event_time TIME,
    created_at TIMESTAMP DEFAULT NOW(),
    scheduled_at TIMESTAMPTZ,
    duration INTERVAL
);

INSERT INTO Events (name, event_date, event_time, scheduled_at, duration) VALUES
    ('Meeting', '2024-01-15', '10:00:00', '2024-01-15 10:00:00+00', '2 hours'),
    ('Conference', '2024-02-20', '09:00:00', '2024-02-20 09:00:00+00', '1 day'),
    ('Workshop', '2024-03-10', '14:30:00', '2024-03-10 14:30:00+00', '3 hours 30 minutes');

SELECT
    name,
    event_date,
    event_time,
    scheduled_at,
    scheduled_at + duration AS end_time
FROM Events;
```

## JSON и JSONB

PostgreSQL предоставляет два типа для хранения JSON-данных: `JSON` и `JSONB`.

### Отличие JSON и JSONB

| Характеристика | JSON | JSONB |
|----------------|------|-------|
| Хранение | Текстовая копия входных данных | Разобранный бинарный формат |
| Скорость записи | Быстрее (нет парсинга) | Медленнее (парсинг при записи) |
| Скорость чтения/запросов | Медленнее (парсинг при каждом чтении) | Быстрее |
| Индексирование | Не поддерживает | Поддерживает GIN-индексы |
| Порядок ключей | Сохраняется | Не гарантирован |
| Дубликаты ключей | Сохраняются | Последний ключ перезаписывает |

В большинстве случаев рекомендуется использовать `JSONB`.

### Создание и вставка

```sql
CREATE TABLE Products (
    id SERIAL PRIMARY KEY,
    name VARCHAR(255),
    metadata JSONB
);

INSERT INTO Products (name, metadata) VALUES
    ('Laptop', '{"brand": "Dell", "ram": 16, "ssd": true}'),
    ('Phone', '{"brand": "Apple", "model": "iPhone 15", "colors": ["black", "white"]}');
```

### Операторы доступа к данным

```sql
-- Получение значения по ключу (как JSON)
SELECT metadata -> 'brand' FROM Products;
-- "Dell"

-- Получение значения по ключу (как текст)
SELECT metadata ->> 'brand' FROM Products;
-- Dell

-- Получение вложенного значения по пути
SELECT metadata #> '{colors, 0}' FROM Products WHERE name = 'Phone';
-- "black"

-- Проверка наличия ключа
SELECT * FROM Products WHERE metadata ? 'ram';

-- Проверка вхождения
SELECT * FROM Products WHERE metadata @> '{"brand": "Dell"}';
```

### Индексирование JSONB

```sql
-- GIN-индекс для эффективного поиска по JSONB
CREATE INDEX idx_products_metadata ON Products USING GIN (metadata);

-- Индекс на конкретный путь
CREATE INDEX idx_products_brand ON Products ((metadata ->> 'brand'));
```

### Функции для работы с JSONB

```sql
-- Получение всех ключей
SELECT jsonb_object_keys(metadata) FROM Products WHERE id = 1;

-- Преобразование строки в набор пар ключ-значение
SELECT * FROM jsonb_each('{"brand": "Dell", "ram": 16}');

-- Объединение JSONB-объектов
SELECT '{"a": 1}'::jsonb || '{"b": 2}'::jsonb;
-- {"a": 1, "b": 2}

-- Удаление ключа
SELECT '{"a": 1, "b": 2}'::jsonb - 'a';
-- {"b": 2}

-- Построение JSON из записи
SELECT jsonb_build_object('name', 'Laptop', 'price', 999);
-- {"name": "Laptop", "price": 999}
```

## Массивы (Array)

PostgreSQL поддерживает столбцы-массивы -- возможность хранить несколько значений одного типа в одном столбце.

### Объявление и вставка

```sql
CREATE TABLE Articles (
    id SERIAL PRIMARY KEY,
    title VARCHAR(255),
    tags TEXT[],
    scores INTEGER[]
);

INSERT INTO Articles (title, tags, scores) VALUES
    ('PostgreSQL Guide', ARRAY['database', 'sql', 'postgres'], ARRAY[95, 88, 92]),
    ('React Hooks', '{"react", "hooks", "frontend"}', '{90, 85}');
```

Два синтаксиса для литералов массивов: `ARRAY[...]` и `'{...}'`.

### Доступ к элементам

```sql
-- Индексация начинается с 1
SELECT tags[1] FROM Articles;
-- database

-- Срез массива
SELECT tags[1:2] FROM Articles;
-- {database, sql}

-- Длина массива
SELECT array_length(tags, 1) FROM Articles;
```

### Поиск по массиву

```sql
-- Проверка наличия элемента
SELECT * FROM Articles WHERE 'react' = ANY(tags);

-- Проверка наличия всех элементов
SELECT * FROM Articles WHERE tags @> ARRAY['sql', 'postgres'];

-- Проверка пересечения
SELECT * FROM Articles WHERE tags && ARRAY['react', 'vue'];
```

### Функции для работы с массивами

```sql
-- Добавление элемента
SELECT array_append(ARRAY[1, 2, 3], 4);
-- {1, 2, 3, 4}

-- Удаление элемента
SELECT array_remove(ARRAY[1, 2, 3, 2], 2);
-- {1, 3}

-- Объединение массивов
SELECT array_cat(ARRAY[1, 2], ARRAY[3, 4]);
-- {1, 2, 3, 4}

-- Превращение массива в строки (unnest)
SELECT unnest(ARRAY['a', 'b', 'c']);
-- a
-- b
-- c

-- GIN-индекс для массивов
CREATE INDEX idx_articles_tags ON Articles USING GIN (tags);
```

## Преобразование типов (CAST)

Когда выполняются операции со значениями с разными типами данных, СУБД пытается выполнить преобразование и привести используемые значения к нужному типу.

```sql
SELECT '50' > 49 AS comparison_1, '50' > 51 AS comparison_2;
-- СУБД автоматически конвертирует строковое значение в числовое для сравнения
```

Но не все преобразования СУБД может сделать автоматически, и тогда необходимо делать явное преобразование типов.

### Синтаксис

В PostgreSQL два способа явного преобразования:

```sql
-- Функция CAST
CAST(значение AS тип_для_конвертации);

-- Оператор :: (специфичен для PostgreSQL)
значение::тип_для_конвертации;
```

```sql
SELECT CAST(12005.6 AS NUMERIC) AS cast_example, 12005.4::NUMERIC AS operator_example;
```

### Типы для конвертации

| Целевой тип | Описание | Пример |
|-------------|----------|--------|
| `DATE` | Формат "YYYY-MM-DD" | `CAST('2024-01-15' AS DATE)` |
| `TIMESTAMP` | Формат "YYYY-MM-DD hh:mm:ss" | `CAST('2024-01-15 10:30:00' AS TIMESTAMP)` |
| `TIME` | Формат "hh:mm:ss" | `CAST('10:30:00' AS TIME)` |
| `NUMERIC[(M,D)]` | Число с точностью M и масштабом D | `CAST(123.456 AS NUMERIC(10,2))` |
| `VARCHAR[(N)]` | Строка с макс. длиной N | `CAST(123 AS VARCHAR(10))` |
| `INTEGER` | Целое число | `CAST('42' AS INTEGER)` |
| `BIGINT` | Большое целое число | `CAST('999999999999' AS BIGINT)` |
| `BOOLEAN` | Логический тип | `CAST(1 AS BOOLEAN)` |
| `TEXT` | Текстовый тип | `CAST(123 AS TEXT)` |

### Ошибки конвертации

Если формат не соответствует целевому типу, PostgreSQL вернет ошибку:

```sql
SELECT CAST('SQL Academy' AS TIMESTAMP) AS invalid_cast;
-- ERROR: invalid input syntax for type timestamp
```

### Примеры преобразований

```sql
-- Число в строку
SELECT 42::TEXT;

-- Строка в число
SELECT '123'::INTEGER;

-- Число в дату (через строку)
SELECT '2024-01-15'::DATE;

-- NUMERIC в INTEGER (отбрасывание дробной части)
SELECT 99.9::INTEGER;
-- 100 (округление)

-- BOOLEAN
SELECT 1::BOOLEAN;  -- true
SELECT 0::BOOLEAN;  -- false
```

## Рекомендации по выбору типов данных

- Учитывайте возможный диапазон значений, которые будут храниться в каждом столбце
- Выбирайте тип данных, соответствующий этому диапазону
- Не используйте избыточно большие типы данных
- Для строк с фиксированной длиной используйте `CHAR`, для переменной -- `VARCHAR`
- Для больших текстов используйте `TEXT`
- Для денежных значений используйте `NUMERIC` или `DECIMAL` вместо типов с плавающей точкой
- Для хранения структурированных данных без фиксированной схемы используйте `JSONB`
- Для списков однотипных значений рассмотрите массивы

```sql
CREATE TABLE Products (
    id SERIAL PRIMARY KEY,
    name VARCHAR(255) NOT NULL,
    description TEXT,
    price NUMERIC(10, 2) NOT NULL,
    quantity INTEGER NOT NULL DEFAULT 0,
    is_available BOOLEAN DEFAULT TRUE,
    tags TEXT[],
    metadata JSONB,
    created_at TIMESTAMPTZ DEFAULT NOW()
);
```
