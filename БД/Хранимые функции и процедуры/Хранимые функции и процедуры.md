## Хранимые функции и процедуры

Хранимые функции и процедуры -- мощные инструменты PostgreSQL, позволяющие инкапсулировать бизнес-логику непосредственно в базе данных. Они обеспечивают переиспользование кода, централизацию логики и повышение производительности.

---

## Хранимые функции

Хранимая функция -- это именованный блок SQL-кода, который принимает параметры, выполняет вычисления и всегда возвращает значение определённого типа.

### Общая структура

```sql
CREATE OR REPLACE FUNCTION имя_функции(параметр1 ТИП, параметр2 ТИП, ...)
RETURNS тип_возвращаемого_значения
LANGUAGE plpgsql
AS $$
BEGIN
    -- логика функции
    RETURN результат_вычислений;
END;
$$;
```

Ключевые элементы:
- `LANGUAGE plpgsql` -- указывает, что функция написана на языке PL/pgSQL (процедурном языке PostgreSQL)
- `AS $$ ... $$` -- долларовое квотирование, способ обрамления тела функции. Позволяет избежать экранирования символов внутри функции
- `RETURNS` -- указывает тип возвращаемого значения

### Простой пример

Функция для определения, является ли человек совершеннолетним:

```sql
CREATE OR REPLACE FUNCTION is_adult(birth_date DATE)
RETURNS BOOLEAN
LANGUAGE plpgsql
AS $$
BEGIN
    RETURN EXTRACT(YEAR FROM AGE(CURRENT_DATE, birth_date)) >= 18;
END;
$$;
```

Использование:

```sql
SELECT
    is_adult('2010-05-15') AS child_status,
    is_adult('2000-03-20') AS adult_status;
```

### Использование в запросах

Функции можно использовать в любых частях SQL-запросов: `SELECT`, `WHERE`, `ORDER BY`, `HAVING`:

```sql
SELECT
    first_name,
    last_name,
    birthday,
    is_adult(birthday) AS is_adult
FROM Student
WHERE is_adult(birthday) = TRUE
LIMIT 5;
```

### Функции с запросами к базе данных

Хранимые функции могут выполнять SQL-запросы внутри себя:

```sql
CREATE OR REPLACE FUNCTION get_student_lessons_count(student_id INT, target_date DATE)
RETURNS INT
LANGUAGE plpgsql
AS $$
DECLARE
    lessons_count INT;
BEGIN
    SELECT COUNT(*) INTO lessons_count
    FROM Schedule s
    INNER JOIN Student_in_class sic ON s.class = sic.class
    WHERE sic.student = student_id
      AND s.date = target_date;

    RETURN lessons_count;
END;
$$;
```

Использование:

```sql
SELECT get_student_lessons_count(1, '2019-09-01') AS lessons_today;
```

### Функции, возвращающие множество строк

```sql
CREATE OR REPLACE FUNCTION get_active_users()
RETURNS TABLE(id INT, name VARCHAR, email VARCHAR)
LANGUAGE plpgsql
AS $$
BEGIN
    RETURN QUERY
    SELECT u.id, u.name, u.email
    FROM Users u
    WHERE u.status = 'active';
END;
$$;
```

Использование:

```sql
SELECT * FROM get_active_users();
```

### Управление функциями

Просмотр существующих функций:

```sql
SELECT routine_name, routine_type
FROM information_schema.routines
WHERE routine_type = 'FUNCTION' AND routine_schema = 'public';
```

Удаление функции:

```sql
DROP FUNCTION IF EXISTS is_adult(DATE);
```

### Преимущества хранимых функций

- Переиспользуемость кода
- Централизация бизнес-логики
- Возможность использования в любых SQL-запросах
- Консистентность вычислений во всём приложении

## Хранимые процедуры

Хранимые процедуры -- это программные блоки, которые выполняют определённую последовательность действий в базе данных. В отличие от функций, процедуры не возвращают значение и вызываются командой `CALL`.

### Общая структура

```sql
CREATE OR REPLACE PROCEDURE имя_процедуры(параметр1 ТИП, параметр2 ТИП, ...)
LANGUAGE plpgsql
AS $$
BEGIN
    -- логика процедуры
END;
$$;
```

### Пример

Процедура для обновления информации о студенте:

```sql
CREATE OR REPLACE PROCEDURE update_student_info(
    student_id INT,
    new_first_name VARCHAR(50),
    new_last_name VARCHAR(50)
)
LANGUAGE plpgsql
AS $$
BEGIN
    UPDATE Student
    SET first_name = new_first_name,
        last_name = new_last_name
    WHERE id = student_id;
END;
$$;
```

Вызов:

```sql
CALL update_student_info(1, 'Alexander', 'Smirnov');
```

### Процедуры с управлением транзакциями

Ключевое преимущество процедур перед функциями -- возможность управления транзакциями внутри:

```sql
CREATE OR REPLACE PROCEDURE transfer_funds(
    from_id INT,
    to_id INT,
    amount NUMERIC
)
LANGUAGE plpgsql
AS $$
BEGIN
    UPDATE accounts SET balance = balance - amount WHERE user_id = from_id;
    UPDATE accounts SET balance = balance + amount WHERE user_id = to_id;
    COMMIT;
END;
$$;
```

### Отличия от функций

```
Характеристика      | Функция (FUNCTION)           | Процедура (PROCEDURE)
--------------------|------------------------------|-------------------------
Возвращает значение | Да (RETURNS)                 | Нет
Вызов               | SELECT, WHERE и т.д.         | CALL
Транзакции внутри   | Нет (COMMIT/ROLLBACK нельзя) | Да (COMMIT/ROLLBACK можно)
Использование в SQL | Да                           | Нет
Назначение          | Вычисления, преобразования    | Бизнес-логика, изменение данных
```

### Управление процедурами

Просмотр:

```sql
SELECT routine_name, routine_type
FROM information_schema.routines
WHERE routine_type = 'PROCEDURE' AND routine_schema = 'public';
```

Удаление:

```sql
DROP PROCEDURE IF EXISTS update_student_info(INT, VARCHAR, VARCHAR);
```

## PL/pgSQL -- язык процедур

PL/pgSQL (Procedural Language/PostgreSQL) -- процедурный язык PostgreSQL, расширяющий SQL возможностями переменных, условий, циклов и обработки ошибок.

### Переменные и типы

Все переменные объявляются в блоке `DECLARE` до начала тела (до `BEGIN`). Объявлять переменные внутри тела нельзя.

```sql
DECLARE
    user_name VARCHAR(100);
    user_age INT := 0;             -- значение по умолчанию
    total NUMERIC(10, 2);
    is_active BOOLEAN DEFAULT true; -- альтернативный синтаксис
    created TIMESTAMP := NOW();
```

#### %TYPE

Тип переменной берётся из типа столбца таблицы. Если тип столбца изменится, переменная автоматически подстроится.

```sql
DECLARE
    user_email Users.email%TYPE;
    order_amount Orders.total_amount%TYPE;
```

#### %ROWTYPE

Переменная, содержащая целую строку таблицы:

```sql
DECLARE
    user_row Users%ROWTYPE;
BEGIN
    SELECT * INTO user_row FROM Users WHERE id = 1;
    RAISE NOTICE 'Name: %, Email: %', user_row.name, user_row.email;
END;
```

#### RECORD

Универсальный тип для хранения строки любой структуры (определяется при присвоении):

```sql
DECLARE
    rec RECORD;
BEGIN
    SELECT * INTO rec FROM Users WHERE id = 1;
    RAISE NOTICE 'Name: %', rec.name;
END;
```

#### SELECT ... INTO

Сохранение результата запроса в переменную:

```sql
SELECT COUNT(*) INTO lessons_count
FROM Schedule s
WHERE s.date = target_date;
```

### Операторы управления потоком

#### IF / ELSIF / ELSE

```sql
IF условие THEN
    -- код при истинном условии
ELSIF другое_условие THEN
    -- код для альтернативного условия
ELSE
    -- код по умолчанию
END IF;
```

Пример:

```sql
CREATE OR REPLACE FUNCTION categorize_student_by_age(student_id INT)
RETURNS VARCHAR(20)
LANGUAGE plpgsql
AS $$
DECLARE
    student_age INT;
    category VARCHAR(20);
BEGIN
    SELECT EXTRACT(YEAR FROM AGE(CURRENT_DATE, birthday))
    INTO student_age
    FROM Student
    WHERE id = student_id;

    IF student_age < 18 THEN
        category := 'Несовершеннолетний';
    ELSIF student_age BETWEEN 18 AND 25 THEN
        category := 'Молодой';
    ELSE
        category := 'Взрослый';
    END IF;

    RETURN category;
END;
$$;
```

#### CASE

Более элегантный способ обработки множественных условий:

```sql
CASE
    WHEN условие1 THEN результат1
    WHEN условие2 THEN результат2
    ELSE результат_по_умолчанию
END CASE;
```

Также можно использовать CASE как выражение с присвоением:

```sql
category := CASE
    WHEN student_age < 18 THEN 'Несовершеннолетний'
    WHEN student_age BETWEEN 18 AND 25 THEN 'Молодой'
    ELSE 'Взрослый'
END;
```

#### LOOP (простой цикл)

Бесконечный цикл, прерывается через `EXIT`:

```sql
LOOP
    -- код
    EXIT WHEN i > 10;
    i := i + 1;
END LOOP;
```

#### WHILE

Цикл с предусловием:

```sql
WHILE условие LOOP
    -- код
END LOOP;
```

Пример:

```sql
CREATE OR REPLACE PROCEDURE create_test_subjects(count_subjects INT)
LANGUAGE plpgsql
AS $$
DECLARE
    i INT := 1;
    subject_id INT := 20;
BEGIN
    WHILE i <= count_subjects LOOP
        INSERT INTO Subject (id, name)
        VALUES (subject_id + i, 'Test Subject ' || i);

        i := i + 1;
    END LOOP;

    RAISE NOTICE 'Создано % тестовых предметов', count_subjects;
END;
$$;
```

#### FOR

Цикл по диапазону:

```sql
FOR i IN 1..10 LOOP
    RAISE NOTICE 'Итерация: %', i;
END LOOP;

-- Обратный порядок
FOR i IN REVERSE 10..1 LOOP
    RAISE NOTICE 'Обратная итерация: %', i;
END LOOP;
```

Цикл по результату запроса:

```sql
FOR rec IN SELECT * FROM Users WHERE status = 'active' LOOP
    RAISE NOTICE 'User: %', rec.name;
END LOOP;
```

#### FOREACH (для массивов)

```sql
DECLARE
    arr INT[] := ARRAY[1, 2, 3, 4, 5];
    elem INT;
BEGIN
    FOREACH elem IN ARRAY arr LOOP
        RAISE NOTICE 'Element: %', elem;
    END LOOP;
END;
```

### Обработка ошибок

#### EXCEPTION

Блок обработки исключений позволяет перехватывать ошибки и реагировать на них:

```sql
BEGIN
    -- код, который может вызвать ошибку
EXCEPTION
    WHEN условие THEN
        -- обработка ошибки
END;
```

Пример:

```sql
CREATE OR REPLACE FUNCTION safe_divide(a NUMERIC, b NUMERIC)
RETURNS NUMERIC
LANGUAGE plpgsql
AS $$
BEGIN
    RETURN a / b;
EXCEPTION
    WHEN division_by_zero THEN
        RAISE NOTICE 'Деление на ноль! Возвращаю 0.';
        RETURN 0;
    WHEN OTHERS THEN
        RAISE NOTICE 'Неизвестная ошибка: %', SQLERRM;
        RETURN NULL;
END;
$$;
```

Основные условия ошибок:
- `division_by_zero` -- деление на ноль
- `unique_violation` -- нарушение уникальности
- `foreign_key_violation` -- нарушение внешнего ключа
- `not_null_violation` -- нарушение NOT NULL
- `check_violation` -- нарушение CHECK
- `no_data_found` -- данные не найдены
- `OTHERS` -- все остальные ошибки

Переменные внутри EXCEPTION:
- `SQLERRM` -- текст сообщения об ошибке
- `SQLSTATE` -- код ошибки (5 символов)

#### RAISE

Оператор для вывода сообщений и генерации ошибок:

```sql
-- Информационное сообщение (не прерывает выполнение)
RAISE NOTICE 'Обработано % записей', counter;

-- Предупреждение
RAISE WARNING 'Данные могут быть устаревшими';

-- Ошибка (прерывает выполнение, откатывает транзакцию)
RAISE EXCEPTION 'Пользователь с id=% не найден', user_id;

-- Ошибка с кодом
RAISE EXCEPTION 'Недостаточно средств'
    USING ERRCODE = 'P0001',
          HINT = 'Пополните баланс перед переводом';
```

Уровни сообщений:
- `DEBUG` -- отладочная информация
- `LOG` -- информация для логирования
- `NOTICE` -- информационное сообщение (по умолчанию выводится клиенту)
- `WARNING` -- предупреждение
- `EXCEPTION` -- ошибка (прерывает выполнение)

## Триггеры

Триггер -- это функция, которая автоматически выполняется при определённых событиях на таблице (INSERT, UPDATE, DELETE). Триггеры используются для автоматизации действий и обеспечения целостности данных.

### CREATE TRIGGER

```sql
CREATE TRIGGER имя_триггера
{BEFORE | AFTER | INSTEAD OF} {INSERT | UPDATE | DELETE}
ON имя_таблицы
[FOR EACH ROW | FOR EACH STATEMENT]
EXECUTE FUNCTION имя_функции();
```

- `BEFORE` -- выполняется до операции (можно изменить данные)
- `AFTER` -- выполняется после операции (данные уже записаны)
- `INSTEAD OF` -- выполняется вместо операции (используется для представлений)
- `FOR EACH ROW` -- срабатывает для каждой строки
- `FOR EACH STATEMENT` -- срабатывает один раз на всю операцию

### Триггерные функции

Триггерная функция всегда возвращает тип `TRIGGER` и не принимает аргументов:

```sql
CREATE OR REPLACE FUNCTION имя_функции()
RETURNS TRIGGER
LANGUAGE plpgsql
AS $$
BEGIN
    -- логика
    RETURN NEW; -- или RETURN OLD, или RETURN NULL
END;
$$;
```

Специальные переменные внутри триггерной функции:
- `NEW` -- новая строка (для INSERT и UPDATE). Содержит данные после изменения
- `OLD` -- старая строка (для UPDATE и DELETE). Содержит данные до изменения
- `TG_OP` -- тип операции: 'INSERT', 'UPDATE', 'DELETE'
- `TG_TABLE_NAME` -- имя таблицы, на которой сработал триггер
- `TG_WHEN` -- 'BEFORE' или 'AFTER'

Возвращаемое значение (для BEFORE ROW):
- `RETURN NEW` -- продолжить операцию с (возможно, изменёнными) данными
- `RETURN OLD` -- продолжить операцию со старыми данными
- `RETURN NULL` -- отменить операцию для текущей строки

### Примеры использования

#### Автоматическое обновление updated_at

```sql
CREATE OR REPLACE FUNCTION update_modified_column()
RETURNS TRIGGER
LANGUAGE plpgsql
AS $$
BEGIN
    NEW.updated_at := NOW();
    RETURN NEW;
END;
$$;

CREATE TRIGGER trigger_update_timestamp
    BEFORE UPDATE ON Users
    FOR EACH ROW
    EXECUTE FUNCTION update_modified_column();
```

Теперь при любом `UPDATE` на таблицу `Users` столбец `updated_at` будет автоматически обновлён.

#### Аудит изменений (логирование)

```sql
CREATE TABLE audit_log (
    id SERIAL PRIMARY KEY,
    table_name TEXT,
    operation TEXT,
    old_data JSONB,
    new_data JSONB,
    changed_at TIMESTAMP DEFAULT NOW(),
    changed_by TEXT DEFAULT current_user
);

CREATE OR REPLACE FUNCTION log_changes()
RETURNS TRIGGER
LANGUAGE plpgsql
AS $$
BEGIN
    IF TG_OP = 'INSERT' THEN
        INSERT INTO audit_log (table_name, operation, new_data)
        VALUES (TG_TABLE_NAME, 'INSERT', row_to_json(NEW)::JSONB);
        RETURN NEW;
    ELSIF TG_OP = 'UPDATE' THEN
        INSERT INTO audit_log (table_name, operation, old_data, new_data)
        VALUES (TG_TABLE_NAME, 'UPDATE', row_to_json(OLD)::JSONB, row_to_json(NEW)::JSONB);
        RETURN NEW;
    ELSIF TG_OP = 'DELETE' THEN
        INSERT INTO audit_log (table_name, operation, old_data)
        VALUES (TG_TABLE_NAME, 'DELETE', row_to_json(OLD)::JSONB);
        RETURN OLD;
    END IF;
END;
$$;

CREATE TRIGGER trigger_users_audit
    AFTER INSERT OR UPDATE OR DELETE ON Users
    FOR EACH ROW
    EXECUTE FUNCTION log_changes();
```

#### Валидация данных перед вставкой

```sql
CREATE OR REPLACE FUNCTION validate_email()
RETURNS TRIGGER
LANGUAGE plpgsql
AS $$
BEGIN
    IF NEW.email !~ '^[A-Za-z0-9._%+-]+@[A-Za-z0-9.-]+\.[A-Za-z]{2,}$' THEN
        RAISE EXCEPTION 'Некорректный email: %', NEW.email;
    END IF;

    NEW.email := LOWER(NEW.email);
    RETURN NEW;
END;
$$;

CREATE TRIGGER trigger_validate_email
    BEFORE INSERT OR UPDATE ON Users
    FOR EACH ROW
    EXECUTE FUNCTION validate_email();
```

#### Мягкое удаление (soft delete)

```sql
CREATE OR REPLACE FUNCTION soft_delete()
RETURNS TRIGGER
LANGUAGE plpgsql
AS $$
BEGIN
    UPDATE Users SET deleted_at = NOW() WHERE id = OLD.id;
    RETURN NULL; -- отменяем настоящее удаление
END;
$$;

CREATE TRIGGER trigger_soft_delete
    BEFORE DELETE ON Users
    FOR EACH ROW
    EXECUTE FUNCTION soft_delete();
```

### Управление триггерами

Просмотр триггеров на таблице:

```sql
SELECT trigger_name, event_manipulation, action_timing
FROM information_schema.triggers
WHERE event_object_table = 'users';
```

Удаление триггера:

```sql
DROP TRIGGER IF EXISTS trigger_update_timestamp ON Users;
```

Временное отключение/включение:

```sql
ALTER TABLE Users DISABLE TRIGGER trigger_update_timestamp;
ALTER TABLE Users ENABLE TRIGGER trigger_update_timestamp;

-- Отключить все триггеры на таблице
ALTER TABLE Users DISABLE TRIGGER ALL;
```

## Запланированные события (pg_cron)

В реальных приложениях часто возникает необходимость выполнять действия автоматически по расписанию: очищать старые записи, обновлять статистику, формировать отчёты.

В PostgreSQL для этого используется расширение `pg_cron`, позволяющее планировать SQL-команды с использованием синтаксиса cron.

### Включение

```sql
CREATE EXTENSION IF NOT EXISTS pg_cron;
```

Важно: расширение `pg_cron` может требовать прав суперпользователя. В облачных сервисах (AWS RDS, Azure) оно может быть уже предустановлено.

### Создание задачи

```sql
SELECT cron.schedule(
    'cleanup_old_logs',
    '0 3 * * *',
    'DELETE FROM logs WHERE created_at < NOW() - INTERVAL ''30 days'''
);
```

Это событие выполняется каждый день в 3:00 и удаляет записи логов старше 30 дней.

### Формат cron расписания

```
* * * * *
| | | | |
| | | | +--- День недели (0-7, где 0 и 7 = воскресенье)
| | | +----- Месяц (1-12)
| | +------- День месяца (1-31)
| +--------- Час (0-23)
+----------- Минута (0-59)
```

Примеры:
- `'*/5 * * * *'` -- каждые 5 минут
- `'0 * * * *'` -- каждый час
- `'0 0 * * *'` -- каждый день в полночь
- `'0 0 * * 0'` -- каждое воскресенье в полночь
- `'0 9 1 * *'` -- первого числа каждого месяца в 9:00

### Периодическая задача

```sql
SELECT cron.schedule(
    'update_statistics_hourly',
    '0 * * * *',
    $$
    UPDATE product_stats SET
        total_sales = (SELECT SUM(amount) FROM orders WHERE product_id = product_stats.product_id),
        last_updated = NOW()
    $$
);
```

### Просмотр задач

```sql
-- Все запланированные задачи
SELECT * FROM cron.job;

-- История выполнения
SELECT * FROM cron.job_run_details
ORDER BY start_time DESC
LIMIT 10;
```

### Управление задачами

Удаление:

```sql
SELECT cron.unschedule('cleanup_old_logs');
-- или по ID
SELECT cron.unschedule(42);
```

Изменение: нельзя изменить существующую задачу напрямую. Нужно удалить старую и создать новую:

```sql
SELECT cron.unschedule('cleanup_old_logs');
SELECT cron.schedule(
    'cleanup_old_logs',
    '0 */2 * * *',
    'DELETE FROM logs WHERE created_at < NOW() - INTERVAL ''30 days'''
);
```

### Важные моменты

- Задачи выполняются по временной зоне PostgreSQL (`SHOW timezone;`)
- Минимальная точность -- 1 минута
- Все выполнения сохраняются в `cron.job_run_details`
- `pg_cron` проверяет расписание каждую секунду
