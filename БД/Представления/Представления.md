## Представления (VIEW)

Хорошо спроектированные приложения обычно предоставляют открытый интерфейс, скрывая детали реализации, что позволяет вносить изменения в дизайн без влияния на конечных пользователей.

При разработке базы данных можно достичь аналогичного результата, закрывая таблицы и предоставляя доступ к данным только через набор представлений.

---

## Что такое VIEW

Представление -- объект базы данных, являющийся результатом выполнения запроса к базе данных, определённого с помощью оператора `SELECT`, в момент обращения к представлению.

Представления иногда называют "виртуальными таблицами". Представление для пользователя выглядит как таблица, но фактически не хранит данных, а извлекает их из других таблиц в момент обращения.

Ключевые особенности:
- Представление не хранит данные
- Данные извлекаются из основных таблиц при каждом обращении
- Представления не кэшируют результаты выборки
- Если данные в основной таблице меняются, пользователь получает актуальные данные при обращении к представлению

Зачем нужны:
- Упрощение сложных запросов
- Обеспечение безопасности (сокрытие конфиденциальных столбцов)
- Стандартизация доступа к данным
- Создание уровня абстракции между пользователями и базовыми таблицами

---

## Создание и удаление VIEW

### CREATE VIEW

Общий синтаксис:

```sql
CREATE [OR REPLACE] VIEW имя_представления [(имена_полей)]
AS select_выражение;
```

Пример -- представление, скрывающее email пользователей:

```sql
CREATE VIEW ViewUsers AS
    SELECT id,
           name,
           CONCAT(SUBSTR(email, 1, 2), '****', RIGHT(email, 4)) AS email
FROM Users;
```

Использование:

```sql
SELECT * FROM ViewUsers;
```

Результат:

```
id    name                email
1     Bruce Willis        ba****.com
2     George Clooney      te****.com
3     Kevin Costner       me****.com
```

Представление в SQL-запросе выглядит и используется как обычная таблица.

### CREATE OR REPLACE VIEW

Изменение существующего представления без его удаления:

```sql
CREATE OR REPLACE VIEW ViewUsers AS
    SELECT id,
           name,
           CONCAT(LEFT(email, 3), '***', RIGHT(email, 4)) AS email
FROM Users;
```

`OR REPLACE`:
- Если представление с таким именем уже существует, старое будет заменено новым
- Если не существует, будет создано новое
- Без `OR REPLACE` при попытке создать представление с существующим именем возникнет ошибка

Ограничение: при замене нельзя изменять список столбцов (порядок, типы, количество). Для этого нужно сначала удалить представление и создать заново.

### DROP VIEW

Удаление представления:

```sql
DROP VIEW ViewUsers;
```

Безопасное удаление (без ошибки, если представление не существует):

```sql
DROP VIEW IF EXISTS ViewUsers;
```

Удаление с каскадом (удаляет зависимые объекты):

```sql
DROP VIEW IF EXISTS ViewUsers CASCADE;
```

### Просмотр информации о представлении

Для просмотра столбцов представления:

```sql
SELECT column_name, data_type, is_nullable
FROM information_schema.columns
WHERE table_name = 'viewusers';
```

Для просмотра определения представления:

```sql
SELECT definition
FROM pg_views
WHERE viewname = 'viewusers';
```

## Обновляемые представления (Updatable Views)

По умолчанию не все представления позволяют выполнять операции `INSERT`, `UPDATE`, `DELETE`. PostgreSQL автоматически делает представление обновляемым, если оно удовлетворяет определённым условиям.

### Условия обновляемости

Представление является автоматически обновляемым, если:
- В `FROM` указана ровно одна таблица (или другое обновляемое представление)
- Нет `WITH`, `DISTINCT`, `GROUP BY`, `HAVING`, `LIMIT`, `OFFSET` в определении
- Нет `UNION`, `INTERSECT`, `EXCEPT`
- Нет агрегатных функций, оконных функций, функций, возвращающих множество
- Столбцы представления напрямую ссылаются на столбцы базовой таблицы (не вычисляемые)

### Пример обновляемого представления

```sql
CREATE VIEW ActiveUsers AS
SELECT id, name, email, status
FROM Users
WHERE status = 'active';

-- INSERT через представление
INSERT INTO ActiveUsers (name, email, status)
VALUES ('New User', 'new@example.com', 'active');

-- UPDATE через представление
UPDATE ActiveUsers SET name = 'Updated Name' WHERE id = 1;

-- DELETE через представление
DELETE FROM ActiveUsers WHERE id = 1;
```

### WITH CHECK OPTION

Для предотвращения вставки строк, которые не будут видны через представление:

```sql
CREATE VIEW ActiveUsers AS
SELECT id, name, email, status
FROM Users
WHERE status = 'active'
WITH CHECK OPTION;
```

Теперь при попытке вставить строку с `status != 'active'` возникнет ошибка:

```sql
INSERT INTO ActiveUsers (name, email, status)
VALUES ('User', 'user@example.com', 'inactive');
-- ERROR: new row violates check option for view "activeusers"
```

## Материализованные представления (MATERIALIZED VIEW)

Материализованные представления физически хранят результат запроса на диске. Это кэшированный результат, который не обновляется автоматически.

### Создание

```sql
CREATE MATERIALIZED VIEW MonthlyStats AS
SELECT
    DATE_TRUNC('month', order_date) AS month,
    COUNT(*) AS orders_count,
    SUM(total_amount) AS total_revenue
FROM Orders
GROUP BY DATE_TRUNC('month', order_date);
```

### Обновление данных

Данные в материализованном представлении не обновляются автоматически. Обновление выполняется вручную:

```sql
-- Полное обновление (блокирует чтение на время обновления)
REFRESH MATERIALIZED VIEW MonthlyStats;

-- Параллельное обновление (не блокирует чтение, но требует UNIQUE INDEX)
REFRESH MATERIALIZED VIEW CONCURRENTLY MonthlyStats;
```

Для использования `CONCURRENTLY` необходим уникальный индекс:

```sql
CREATE UNIQUE INDEX idx_monthly_stats ON MonthlyStats (month);
REFRESH MATERIALIZED VIEW CONCURRENTLY MonthlyStats;
```

### Автоматическое обновление

Материализованные представления можно обновлять по расписанию с помощью `pg_cron`:

```sql
SELECT cron.schedule(
    'refresh_monthly_stats',
    '0 * * * *',
    'REFRESH MATERIALIZED VIEW CONCURRENTLY MonthlyStats'
);
```

### Удаление

```sql
DROP MATERIALIZED VIEW IF EXISTS MonthlyStats;
```

## VIEW vs MATERIALIZED VIEW

```
Характеристика          | VIEW                    | MATERIALIZED VIEW
------------------------|-------------------------|---------------------------
Хранение данных         | Не хранит               | Хранит физически
Актуальность            | Всегда актуальные       | Может быть устаревшей
Скорость чтения         | Зависит от запроса       | Быстрое (данные готовы)
Дисковое пространство   | Не занимает              | Занимает
Обновление              | Автоматическое           | Ручное (REFRESH)
INSERT/UPDATE/DELETE     | Возможен (при условиях)  | Невозможен
Индексы                 | Нельзя создать           | Можно создать
```

Когда использовать VIEW:
- Данные должны быть всегда актуальными
- Запрос быстрый или выполняется редко
- Нужна абстракция для безопасности
- Нужна возможность записи через представление

Когда использовать MATERIALIZED VIEW:
- Сложный и тяжёлый запрос
- Данные меняются редко или допустима небольшая задержка
- Частые обращения к одним и тем же агрегированным данным
- Отчёты и аналитические дашборды

## Примеры использования

### Упрощение сложных запросов

```sql
CREATE VIEW ActiveOrders AS
SELECT
    o.id,
    o.order_date,
    u.name AS customer_name,
    u.email,
    SUM(oi.quantity * oi.price) AS total_amount
FROM Orders o
JOIN Users u ON o.user_id = u.id
JOIN OrderItems oi ON o.id = oi.order_id
WHERE o.status = 'active'
GROUP BY o.id, o.order_date, u.name, u.email;
```

Вместо написания сложного запроса каждый раз:

```sql
SELECT * FROM ActiveOrders;
```

### Обеспечение безопасности

```sql
CREATE VIEW PublicUsers AS
SELECT id, name, country
FROM Users;
```

Это представление скрывает конфиденциальные данные (email, телефон, адрес) от пользователей, которым не нужен полный доступ.

### Представление для отчётов

```sql
CREATE VIEW SalesReport AS
SELECT
    p.name AS product_name,
    c.name AS category_name,
    COUNT(oi.id) AS times_ordered,
    SUM(oi.quantity) AS total_quantity,
    SUM(oi.quantity * oi.price) AS total_revenue
FROM Products p
JOIN Categories c ON p.category_id = c.id
JOIN OrderItems oi ON p.id = oi.product_id
GROUP BY p.name, c.name;
```

### Упрощение JOIN

```sql
CREATE VIEW ProductsWithCategories AS
SELECT
    p.id,
    p.name AS product_name,
    p.price,
    c.name AS category_name
FROM Products p
LEFT JOIN Categories c ON p.category_id = c.id;
```

### Материализованное представление для аналитики

```sql
CREATE MATERIALIZED VIEW DailyRevenue AS
SELECT
    DATE(order_date) AS day,
    COUNT(*) AS orders,
    SUM(total_amount) AS revenue,
    AVG(total_amount) AS avg_order
FROM Orders
WHERE status = 'completed'
GROUP BY DATE(order_date);

CREATE UNIQUE INDEX idx_daily_revenue ON DailyRevenue (day);
```

Обновление каждый час:

```sql
REFRESH MATERIALIZED VIEW CONCURRENTLY DailyRevenue;
```

---

## Ограничения представлений

- Обычные представления могут снижать производительность для очень сложных запросов
- Не все представления могут быть обновляемыми
- Изменения в структуре базовых таблиц могут нарушить работу представлений
- Материализованные представления требуют ручного обновления и дополнительного дискового пространства
