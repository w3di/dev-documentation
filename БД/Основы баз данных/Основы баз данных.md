# Основы баз данных

## Что такое база данных и СУБД

**База данных (БД)** -- набор данных, организованных в структурированном виде для эффективного хранения, поиска и обработки.

**СУБД (система управления базами данных)** -- программное обеспечение для доступа к данным, их создания, изменения и удаления. СУБД обеспечивает:
- многопользовательский доступ
- целостность данных
- резервное копирование и восстановление
- управление транзакциями
- контроль доступа и безопасность

Примеры СУБД: PostgreSQL, MySQL, SQLite, Oracle, Microsoft SQL Server, MongoDB.

## Типы баз данных

### Реляционные БД (RDBMS)

Данные хранятся в таблицах со строками и столбцами. Таблицы связаны между собой через ключи.

Особенности:
- Строгая типизация данных
- Одно значение на пересечении строки и столбца
- Столбцы имеют имя и тип
- Порядок столбцов фиксирован при создании
- Таблица может быть пустой, но должна иметь хотя бы один столбец
- Результат запроса -- таблица

Примеры: PostgreSQL, MySQL, Oracle, SQL Server.

### Key-value БД

Данные хранятся как пары ключ-значение, где ключ -- уникальный идентификатор. Обеспечивают высокую скорость чтения/записи по ключу.

Примеры: Redis, Memcached, Amazon DynamoDB.

### Документоориентированные БД

Данные хранятся в виде документов, похожих на JSON. Каждый документ может иметь произвольную структуру, что обеспечивает гибкость схемы.

Примеры: MongoDB, CouchDB, Firebase Firestore.

### Графовые БД

Данные представлены в виде узлов (nodes) и связей (edges) между ними. Оптимальны для моделирования сложных взаимосвязей -- социальные сети, рекомендательные системы.

Примеры: Neo4j, Amazon Neptune, ArangoDB.

### Колоночные БД

Данные хранятся по столбцам, а не по строкам. Эффективны для аналитических запросов, работающих с большими объемами данных по отдельным колонкам.

Примеры: ClickHouse, Apache Cassandra, Amazon Redshift.

## Реляционная модель

Реляционная модель -- математическая модель данных, основанная на теории множеств. Основные понятия:

**Отношение (Relation)** -- таблица с данными. Формально -- подмножество декартова произведения доменов.

**Кортеж (Tuple)** -- одна строка таблицы, набор значений атрибутов.

**Атрибут (Attribute)** -- столбец таблицы, имеющий имя и тип данных.

**Домен (Domain)** -- множество допустимых значений для атрибута. Например, домен "возраст" -- целые числа от 0 до 150.

**Схема отношения** -- набор атрибутов с их типами, описывающий структуру таблицы.

| Термин реляционной модели | Эквивалент в SQL |
|---------------------------|------------------|
| Отношение                 | Таблица (TABLE)  |
| Кортеж                    | Строка (ROW)     |
| Атрибут                   | Столбец (COLUMN) |
| Домен                     | Тип данных       |

## Структура таблицы реляционных БД

Таблица состоит из:
- **строк** (записи, кортежи) -- каждая строка представляет одну сущность
- **столбцов** (поля, атрибуты) -- каждый столбец описывает одно свойство сущности

```sql
CREATE TABLE Employees (
    id SERIAL PRIMARY KEY,       -- столбец: уникальный идентификатор
    name VARCHAR(100) NOT NULL,  -- столбец: имя сотрудника
    department VARCHAR(50),      -- столбец: отдел
    salary NUMERIC(10, 2)        -- столбец: зарплата
);
```

## Первичный ключ (PRIMARY KEY)

Поле или набор полей, однозначно определяющий запись в таблице.

Свойства:
- Уникален для каждой строки
- Не может содержать NULL
- Таблица может иметь только один первичный ключ
- Необязателен -- целостность может обеспечиваться на уровне приложения

```sql
-- Простой первичный ключ
CREATE TABLE Users (
    id SERIAL PRIMARY KEY,
    username VARCHAR(50)
);

-- Составной первичный ключ
CREATE TABLE OrderItems (
    order_id INT,
    product_id INT,
    quantity INT,
    PRIMARY KEY (order_id, product_id)
);
```

## Внешний ключ (FOREIGN KEY)

Поле или набор полей в одной таблице, ссылающееся на первичный ключ другой таблицы.

- Таблица с внешним ключом -- **дочерняя**
- Таблица с первичным ключом -- **родительская**
- Внешний ключ гарантирует, что значение существует в родительской таблице
- Необязателен

```sql
CREATE TABLE Departments (
    id SERIAL PRIMARY KEY,
    name VARCHAR(100) NOT NULL
);

CREATE TABLE Employees (
    id SERIAL PRIMARY KEY,
    name VARCHAR(100) NOT NULL,
    department_id INT,
    FOREIGN KEY (department_id) REFERENCES Departments(id)
);
```

## ACID свойства транзакций

ACID -- набор свойств, гарантирующих надежную обработку транзакций в БД:

**Atomicity (Атомарность)** -- транзакция выполняется полностью или не выполняется вовсе. Если одна из операций внутри транзакции завершается ошибкой, все изменения откатываются.

**Consistency (Согласованность)** -- транзакция переводит БД из одного корректного состояния в другое. Все ограничения и правила целостности данных соблюдаются.

**Isolation (Изолированность)** -- параллельные транзакции не влияют друг на друга. Промежуточные результаты транзакции не видны другим транзакциям.

**Durability (Долговечность)** -- после успешного завершения транзакции данные сохраняются даже при сбое системы.

```sql
BEGIN;
    UPDATE Accounts SET balance = balance - 500 WHERE id = 1;
    UPDATE Accounts SET balance = balance + 500 WHERE id = 2;
COMMIT;
-- Либо обе операции выполнятся, либо ни одна (Atomicity)
```

## SQL как язык

**SQL (Structured Query Language)** -- язык структурированных запросов для работы с реляционными базами данных. SQL делится на несколько подмножеств:

### DDL -- Data Definition Language (Язык определения данных)

Операторы для создания и изменения структуры БД:

| Оператор | Описание |
|----------|----------|
| `CREATE` | Создание объекта (база данных, таблица, индекс, представление) |
| `ALTER`  | Изменение структуры объекта |
| `DROP`   | Удаление объекта |
| `TRUNCATE` | Быстрое удаление всех данных из таблицы |

```sql
CREATE TABLE Products (id SERIAL PRIMARY KEY, name VARCHAR(255));
ALTER TABLE Products ADD COLUMN price NUMERIC(10, 2);
DROP TABLE Products;
```

### DML -- Data Manipulation Language (Язык манипулирования данными)

Операторы для работы с данными:

| Оператор | Описание |
|----------|----------|
| `SELECT` | Выборка данных |
| `INSERT` | Добавление данных |
| `UPDATE` | Обновление данных |
| `DELETE` | Удаление данных |

```sql
INSERT INTO Products (name, price) VALUES ('Laptop', 999.99);
SELECT * FROM Products WHERE price > 500;
UPDATE Products SET price = 899.99 WHERE name = 'Laptop';
DELETE FROM Products WHERE name = 'Laptop';
```

### DCL -- Data Control Language (Язык управления доступом)

Операторы для управления правами доступа:

| Оператор | Описание |
|----------|----------|
| `GRANT`  | Предоставление прав |
| `REVOKE` | Отзыв прав |

```sql
GRANT SELECT, INSERT ON Products TO app_user;
REVOKE DELETE ON Products FROM app_user;
```

### TCL -- Transaction Control Language (Язык управления транзакциями)

Операторы для управления транзакциями:

| Оператор | Описание |
|----------|----------|
| `BEGIN` / `START TRANSACTION` | Начало транзакции |
| `COMMIT`    | Подтверждение транзакции |
| `ROLLBACK`  | Откат транзакции |
| `SAVEPOINT` | Создание точки сохранения внутри транзакции |

```sql
BEGIN;
    INSERT INTO Orders (user_id, total) VALUES (1, 150.00);
    SAVEPOINT order_created;
    INSERT INTO OrderItems (order_id, product_id) VALUES (1, 5);
    -- Если ошибка в деталях, можно откатить только к точке сохранения
    ROLLBACK TO order_created;
COMMIT;
```
