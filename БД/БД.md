## Ключевые концепции

### Реляционная модель

Реляционная модель -- математическая основа для работы с данными, предложенная Эдгаром Коддом в 1970 году. Данные представляются в виде отношений (таблиц), где каждая строка (кортеж) -- уникальная запись, а каждый столбец (атрибут) -- свойство сущности с определённым доменом (типом). Связи между таблицами устанавливаются через ключи: primary key однозначно идентифицирует строку, а foreign key ссылается на primary key другой таблицы.

### ACID

Набор свойств, гарантирующих надёжность транзакций в базе данных:

- **Atomicity (атомарность)** -- транзакция выполняется целиком или не выполняется вообще
- **Consistency (согласованность)** -- транзакция переводит данные из одного корректного состояния в другое
- **Isolation (изоляция)** -- параллельные транзакции не влияют друг на друга
- **Durability (долговечность)** -- результат завершённой транзакции сохраняется даже при сбое системы

### Нормализация

Процесс организации данных в таблицах для устранения избыточности и аномалий (вставки, обновления, удаления). Основные нормальные формы:

- **1NF** -- атомарные значения, нет повторяющихся групп
- **2NF** -- нет частичных зависимостей от составного ключа
- **3NF** -- нет транзитивных зависимостей от ключа
- **BCNF** -- каждый детерминант является кандидатным ключом

Денормализация применяется осознанно для повышения производительности чтения за счёт допущения контролируемой избыточности.

### Индексы

Дополнительные структуры данных, ускоряющие поиск строк по определённым столбцам. Основные типы в PostgreSQL:

- **B-tree** -- универсальный индекс для операций сравнения и сортировки (используется по умолчанию)
- **Hash** -- только для операций равенства
- **GIN** -- для полнотекстового поиска, массивов и JSONB
- **GiST** -- для геометрических и диапазонных данных
- **BRIN** -- для больших таблиц с естественным порядком данных

Наличие индекса не гарантирует его использование -- решение принимает планировщик на основе статистики и стоимости.

### Транзакции и MVCC

PostgreSQL реализует изоляцию транзакций через MVCC (Multi-Version Concurrency Control) -- механизм, при котором каждая транзакция видит свой согласованный снимок данных. Обновление строки создаёт новую версию, а старая помечается как неактуальная. Это позволяет читателям не блокировать писателей и наоборот.

Уровни изоляции в PostgreSQL:

- **Read Committed** -- транзакция видит только зафиксированные данные на момент выполнения каждого оператора
- **Repeatable Read** -- транзакция видит снимок данных на момент начала первого оператора
- **Serializable** -- полная сериализация, гарантирующая результат как при последовательном выполнении
