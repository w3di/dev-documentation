## Принципы состояния

Состояние — «память» компонента между рендерами. Ключевые принципы:

- **Однонаправленный поток данных** — данные текут сверху вниз через props, обратная связь — через колбэки
- **Иммутабельность** — состояние не мутируется напрямую, а заменяется новым значением
- **Минимальность** — храните только то, что нельзя вычислить из других данных

```
┌──────────┐   props    ┌──────────┐   props    ┌──────────┐
│  Parent   │ ────────► │  Child A  │ ────────► │ Grandchild│
│  (state)  │           │           │           │           │
│           │ ◄──────── │           │ ◄──────── │           │
└──────────┘  callback  └──────────┘  callback  └──────────┘
```

## State как снимок (Snapshot)

Каждый рендер «замораживает» значения state на момент вызова. `setState` не меняет текущую переменную — она запланирует новый рендер с новым значением.

```jsx
function Timer() {
  const [count, setCount] = useState(0);

  function handleClick() {
    setCount(count + 1);
    // count всё ещё 0 здесь — это снимок текущего рендера
    setTimeout(() => {
      alert(count); // Покажет 0, а не 1 — замыкание захватило снимок
    }, 3000);
  }

  return <button onClick={handleClick}>Счёт: {count}</button>;
}
```

## Очередь обновлений

React **группирует** (batches) обновления и обрабатывает их в очереди:

```jsx
function Counter() {
  const [count, setCount] = useState(0);

  function handleClick() {
    // ❌ Все три используют один снимок count = 0
    setCount(count + 1); // → 1
    setCount(count + 1); // → 1 (не 2!)
    setCount(count + 1); // → 1 (не 3!)
  }

  function handleClickCorrect() {
    // ✅ Updater functions — каждая получает актуальное значение
    setCount(c => c + 1); // 0 → 1
    setCount(c => c + 1); // 1 → 2
    setCount(c => c + 1); // 2 → 3
  }
}
```

React обрабатывает очередь обновлений по порядку: каждая updater-функция получает результат предыдущей.

## Выбор структуры состояния

### Принципы

1. **Группируйте связанные значения** — если два значения всегда обновляются вместе, объедините их
2. **Избегайте дублирования** — вычисляйте производные данные, не храните
3. **Избегайте глубокой вложенности** — нормализуйте (flatten)
4. **Не зеркальте props в state** — используйте props напрямую
5. **Избегайте избыточного состояния** — computed values не нужно хранить

```jsx
// ❌ Плохо: дублирование и избыточность
const [items, setItems] = useState([]);
const [selectedItem, setSelectedItem] = useState(null); // копия объекта из items
const [itemCount, setItemCount] = useState(0);           // можно вычислить

// ✅ Хорошо: минимальное состояние
const [items, setItems] = useState([]);
const [selectedId, setSelectedId] = useState(null);       // храним только ID
const selectedItem = items.find(i => i.id === selectedId); // вычисляем
const itemCount = items.length;                            // вычисляем
```

```jsx
// ❌ Плохо: глубокая вложенность
const [tree, setTree] = useState({
  id: 1, children: [{ id: 2, children: [{ id: 3 }] }]
});

// ✅ Хорошо: нормализованная структура
const [nodes, setNodes] = useState({
  1: { id: 1, childIds: [2] },
  2: { id: 2, childIds: [3] },
  3: { id: 3, childIds: [] },
});
```

## Обновление объектов в состоянии

Состояние нельзя мутировать — нужно создавать новый объект:

```jsx
const [person, setPerson] = useState({ name: 'Анна', age: 25, address: { city: 'Москва' } });

// ❌ Мутация — React не узнает об изменении
person.name = 'Мария';

// ✅ Spread — создание нового объекта
setPerson({ ...person, name: 'Мария' });

// ✅ Обновление вложенного объекта
setPerson({
  ...person,
  address: { ...person.address, city: 'Санкт-Петербург' }
});
```

### Immer — удобная «мутация»

```jsx
import { useImmerState } from 'use-immer';

const [person, updatePerson] = useImmerState({ name: 'Анна', address: { city: 'Москва' } });

updatePerson(draft => {
  draft.address.city = 'Казань'; // «мутация» — Immer создаст новый объект автоматически
});
```

## Обновление массивов в состоянии

| Операция | Мутирующий метод ❌ | Немутирующая альтернатива ✅ |
|---|---|---|
| Добавление | `push`, `unshift` | `[...arr, item]`, `[item, ...arr]` |
| Удаление | `splice`, `pop`, `shift` | `filter`, `slice` |
| Замена | `splice`, `arr[i] = x` | `map` |
| Сортировка | `sort`, `reverse` | `toSorted`, `toReversed` или копия |

```jsx
const [todos, setTodos] = useState([]);

// Добавление
setTodos([...todos, { id: nextId++, text: 'Новая задача' }]);

// Удаление
setTodos(todos.filter(t => t.id !== idToRemove));

// Замена
setTodos(todos.map(t => t.id === id ? { ...t, done: true } : t));

// Сортировка (создать копию перед sort)
setTodos([...todos].sort((a, b) => a.text.localeCompare(b.text)));
// Или (ES2023):
setTodos(todos.toSorted((a, b) => a.text.localeCompare(b.text)));
```

## Поднятие состояния (Lifting State Up)

Когда два компонента должны синхронизировать данные — поднимите state в ближайшего общего родителя:

```jsx
function Parent() {
  const [value, setValue] = useState('');

  return (
    <>
      <InputA value={value} onChange={setValue} />
      <InputB value={value} onChange={setValue} />
    </>
  );
}

function InputA({ value, onChange }) {
  return <input value={value} onChange={e => onChange(e.target.value)} />;
}
```

Паттерн: дочерний компонент становится **контролируемым** — state управляется родителем через props.

## Сохранение и сброс состояния

React сохраняет state компонента, пока он **остаётся на той же позиции в дереве UI**.

```jsx
// ✅ State сохраняется — тот же компонент на той же позиции
{isPlayerA ? <Counter person="A" /> : <Counter person="B" />}
// React видит <Counter> на той же позиции → state сохраняется!

// ✅ Принудительный сброс через key
{isPlayerA
  ? <Counter key="A" person="A" />
  : <Counter key="B" person="B" />
}
// Разные key → React считает это разными компонентами → state сбрасывается
```

Правила:
- **Тот же тип + та же позиция** → state сохраняется
- **Разный тип** на той же позиции → state сбрасывается, поддерево удаляется
- **Тот же тип + разный key** → state сбрасывается

## Масштабирование: useReducer + useContext

Для сложной логики состояния: reducer для логики, Context для передачи вглубь дерева:

```jsx
const TodosContext = createContext(null);
const TodosDispatchContext = createContext(null);

function TodosProvider({ children }) {
  const [todos, dispatch] = useReducer(todosReducer, []);

  return (
    <TodosContext value={todos}>
      <TodosDispatchContext value={dispatch}>
        {children}
      </TodosDispatchContext>
    </TodosContext>
  );
}

// Любой дочерний компонент:
function AddTodo() {
  const dispatch = use(TodosDispatchContext);
  return <button onClick={() => dispatch({ type: 'add', text: 'Новая' })}>+</button>;
}
```

### Когда useState vs useReducer

| Критерий | useState | useReducer |
|---|---|---|
| Простое значение | ✅ | Излишне |
| Несколько связанных полей | Громоздко | ✅ |
| Сложные переходы состояний | Запутанно | ✅ |
| Тестирование логики | В компоненте | Reducer тестируется отдельно |
| Передача через Context | setValue | dispatch (стабильная ссылка) |

## Внешние менеджеры состояния

Когда Context + useReducer становится недостаточно (производительность, DevTools, middleware):

| Библиотека | Подход | Размер | Особенности |
|---|---|---|---|
| Redux Toolkit | Единый store, actions/reducers | ~11 KB | DevTools, middleware, широкая экосистема |
| Zustand | Минималистичный store | ~1 KB | Простой API, без boilerplate |
| Jotai | Атомарное состояние | ~3 KB | Bottom-up, атомы как примитивы |
| Valtio | Proxy-based | ~3 KB | Мутабельный API, proxy-подписки |
| Recoil | Атомы + селекторы | ~20 KB | От Meta, граф зависимостей |

```jsx
// Zustand — пример
import { create } from 'zustand';

const useStore = create((set) => ({
  count: 0,
  increment: () => set(state => ({ count: state.count + 1 })),
}));

function Counter() {
  const count = useStore(state => state.count);
  const increment = useStore(state => state.increment);
  return <button onClick={increment}>{count}</button>;
}
```

Для подписки на внешние store из React используйте `useSyncExternalStore`:

```jsx
import { useSyncExternalStore } from 'react';

const width = useSyncExternalStore(
  (callback) => {
    window.addEventListener('resize', callback);
    return () => window.removeEventListener('resize', callback);
  },
  () => window.innerWidth,
  () => 1024 // SSR fallback
);
```
