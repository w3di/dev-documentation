# Производительность и оптимизация React-приложений

> Производительность React-приложения определяется не скоростью виртуального DOM,
> а умением разработчика минимизировать **количество и глубину** ненужных перерисовок.
> React перерисовывает компоненты агрессивно — по умолчанию каждый дочерний компонент
> рендерится заново при рендере родителя, даже если его props не изменились.

## 1. Когда React перерисовывает компоненты

### 1.1 Четыре триггера ререндера

| Триггер | Механизм | Можно ли предотвратить? |
|---|---|---|
| Изменение state | `setState` / `dispatch` | Нет — это основной контракт React |
| Изменение props | Родитель передал новые props | `React.memo` |
| Ререндер родителя | Родитель перерисовался — все дети рендерятся заново | `React.memo`, composition |
| Изменение контекста | `Context.Provider` получил новый `value` | Разделение контекстов, мемоизация |

### 1.2 Каскад ререндеров

```
setState() в компоненте A
       │
       ▼
┌──── App (A) ─── Re-render ──────────────────────────────────────┐
│                                                                   │
│  ┌── Header (B) ── Re-render ──────────────────────────────┐     │
│  │   ┌── Logo (D) ── Re-render ─┐                         │     │
│  │   └──────────────────────────┘                         │     │
│  │   ┌── NavMenu (E) ── Re-render ──────────────────┐     │     │
│  │   │   ┌── NavItem × N ── Re-render ─┐           │     │     │
│  │   │   └─────────────────────────────┘           │     │     │
│  │   └─────────────────────────────────────────────┘     │     │
│  └─────────────────────────────────────────────────────────┘     │
│                                                                   │
│  ┌── Main (C) ── Re-render ────────────────────────────────┐     │
│  │   ┌── Sidebar (F) ── Re-render ─┐                      │     │
│  │   └─────────────────────────────┘                      │     │
│  │   ┌── Content (G) ── Re-render ─┐                      │     │
│  │   └─────────────────────────────┘                      │     │
│  └─────────────────────────────────────────────────────────┘     │
└───────────────────────────────────────────────────────────────────┘

Все компоненты B, C, D, E, F, G перерисовались,
даже если их props не изменились.
```

**Ключевое понимание**: React **не сравнивает props по умолчанию**. Если родитель
рендерится — все его дочерние компоненты рендерятся безусловно. Сравнение props
включается явно через `React.memo`.

## 2. React.memo — мемоизация компонентов

`React.memo` — HOC, который оборачивает функциональный компонент и пропускает
ререндер, если props не изменились (по умолчанию — shallow comparison).

### 2.1 Базовое использование

```jsx
const ExpensiveChart = React.memo(function ExpensiveChart({ data, title }) {
  console.log('ExpensiveChart render'); // Не вызовется при ререндере родителя,
                                         // если data и title не изменились
  return (
    <div>
      <h2>{title}</h2>
      <svg>{/* тяжёлая отрисовка графика */}</svg>
    </div>
  );
});
```

### 2.2 Кастомная функция сравнения

Shallow comparison не работает для сложных объектов. Второй аргумент `React.memo` —
функция `arePropsEqual(prevProps, nextProps)`, возвращающая `true`, если ререндер
**не нужен** (обратная логика `shouldComponentUpdate`).

```jsx
const UserCard = React.memo(
  function UserCard({ user, onSelect }) {
    return (
      <div onClick={() => onSelect(user.id)}>
        <img src={user.avatar} alt={user.name} />
        <h3>{user.name}</h3>
        <p>{user.email}</p>
      </div>
    );
  },
  (prevProps, nextProps) => {
    // true → НЕ перерисовывать (props считаются равными)
    return (
      prevProps.user.id === nextProps.user.id &&
      prevProps.user.name === nextProps.user.name &&
      prevProps.user.avatar === nextProps.user.avatar &&
      prevProps.onSelect === nextProps.onSelect
    );
  }
);
```

### 2.3 Когда React.memo не помогает

| Ситуация | Причина | Решение |
|---|---|---|
| Inline-объект в props | `style={{ color: 'red' }}` — новый объект каждый render | `useMemo` для объекта |
| Inline-функция в props | `onClick={() => handleClick(id)}` — новая ссылка | `useCallback` |
| Children как JSX | `<Wrapper><Child /></Wrapper>` — новый ReactElement | Composition pattern |
| Частое изменение props | Props реально меняются на каждый render | Memo бесполезен — лишний overhead |

## 3. useMemo и useCallback — мемоизация значений и функций

### 3.1 useMemo — мемоизация вычислений

Возвращает мемоизированное **значение**. Пересчитывает только при изменении зависимостей.

```jsx
function ProductList({ products, filterTerm }) {
  // Без useMemo: фильтрация происходит на КАЖДЫЙ рендер
  // С useMemo: только при изменении products или filterTerm
  const filtered = useMemo(() => {
    return products.filter((p) =>
      p.name.toLowerCase().includes(filterTerm.toLowerCase())
    );
  }, [products, filterTerm]);

  const stats = useMemo(() => ({
    total: filtered.length,
    avgPrice: filtered.reduce((s, p) => s + p.price, 0) / filtered.length,
  }), [filtered]);

  return (
    <div>
      <Stats data={stats} />
      {filtered.map((p) => <ProductCard key={p.id} product={p} />)}
    </div>
  );
}
```

### 3.2 useCallback — мемоизация функций

Возвращает мемоизированную **функцию**. Критичен при передаче callback'ов
в `React.memo`-компоненты — без `useCallback` ссылка на функцию меняется при каждом рендере.

```jsx
function TodoApp() {
  const [todos, setTodos] = useState([]);

  // Без useCallback: новая функция на каждый render → React.memo на TodoItem бесполезен
  const handleToggle = useCallback((id) => {
    setTodos((prev) =>
      prev.map((t) => (t.id === id ? { ...t, done: !t.done } : t))
    );
  }, []); // [] — функция не зависит от внешних переменных

  const handleDelete = useCallback((id) => {
    setTodos((prev) => prev.filter((t) => t.id !== id));
  }, []);

  return todos.map((todo) => (
    <TodoItem
      key={todo.id}
      todo={todo}
      onToggle={handleToggle}
      onDelete={handleDelete}
    />
  ));
}

const TodoItem = React.memo(function TodoItem({ todo, onToggle, onDelete }) {
  return (
    <li>
      <span onClick={() => onToggle(todo.id)}>{todo.text}</span>
      <button onClick={() => onDelete(todo.id)}>Удалить</button>
    </li>
  );
});
```

## 4. Оптимизация контекста

### 4.1 Проблема: любое изменение value перерисовывает всех потребителей

Когда `Provider` получает новый объект `value`, **все компоненты**, вызывающие
`useContext(MyContext)`, перерисовываются — даже если они используют лишь часть контекста.

### 4.2 Стратегия: разделение контекстов

```jsx
// ДО: единый контекст — изменение theme перерисовывает потребителей user
const AppContext = React.createContext();

// ПОСЛЕ: разделённые контексты — изменение theme не затрагивает потребителей user
const ThemeContext = React.createContext();
const UserContext = React.createContext();

function AppProvider({ children }) {
  const [theme, setTheme] = useState('light');
  const [user, setUser] = useState(null);

  // Мемоизация value — предотвращает ререндер при рендере AppProvider
  const themeValue = useMemo(() => ({ theme, setTheme }), [theme]);
  const userValue = useMemo(() => ({ user, setUser }), [user]);

  return (
    <ThemeContext.Provider value={themeValue}>
      <UserContext.Provider value={userValue}>
        {children}
      </UserContext.Provider>
    </ThemeContext.Provider>
  );
}

// Потребители подписываются только на нужный контекст
function ThemeToggle() {
  const { theme, setTheme } = useContext(ThemeContext);
  // Не перерисовывается при изменении user
  return (
    <button onClick={() => setTheme(theme === 'light' ? 'dark' : 'light')}>
      Тема: {theme}
    </button>
  );
}
```

### 4.3 Паттерн: разделение state и dispatch

```jsx
const StateContext = React.createContext();
const DispatchContext = React.createContext();

function AppProvider({ children }) {
  const [state, dispatch] = useReducer(reducer, initialState);
  return (
    <DispatchContext.Provider value={dispatch}>
      <StateContext.Provider value={state}>
        {children}
      </StateContext.Provider>
    </DispatchContext.Provider>
  );
}

// Компоненты, которые только отправляют действия, не рендерятся при изменении state
function AddButton() {
  const dispatch = useContext(DispatchContext); // dispatch стабилен — useReducer гарантирует
  return <button onClick={() => dispatch({ type: 'ADD' })}>Добавить</button>;
}
```

## 5. Composition pattern — избегание ререндеров

### 5.1 Children as props

Когда дочерний JSX передаётся как `children` (или любой prop), он **создаётся
в родительском компоненте**. Если родитель не перерисовывается — `children` сохраняет
ту же ссылку, и дочерний компонент не рендерится.

```jsx
// ПРОБЛЕМА: MovingDot рендерит ExpensiveTree на каждое движение мыши
function MovingDotBad() {
  const [position, setPosition] = useState({ x: 0, y: 0 });

  return (
    <div onMouseMove={(e) => setPosition({ x: e.clientX, y: e.clientY })}>
      <Dot position={position} />
      <ExpensiveTree /> {/* Рендерится на каждое движение мыши */}
    </div>
  );
}

// РЕШЕНИЕ: поднять ExpensiveTree выше, передать как children
function MovingDotWrapper({ children }) {
  const [position, setPosition] = useState({ x: 0, y: 0 });

  return (
    <div onMouseMove={(e) => setPosition({ x: e.clientX, y: e.clientY })}>
      <Dot position={position} />
      {children} {/* Ссылка на children не меняется — ExpensiveTree НЕ рендерится */}
    </div>
  );
}

// Использование:
function App() {
  return (
    <MovingDotWrapper>
      <ExpensiveTree />
    </MovingDotWrapper>
  );
}
```

### 5.2 Почему это работает

```
App рендерится → создаёт <ExpensiveTree /> (ReactElement)
       │
       ▼ передаёт как children в MovingDotWrapper
       │
MovingDotWrapper рендерится (setState) → children — та же ссылка
       │
       ▼ React видит: children === prevChildren → пропускает ререндер
```

## 6. Виртуализация списков

При рендеринге длинных списков (тысячи элементов) React создаёт DOM-узел для каждого.
Виртуализация рендерит **только видимые элементы**, значительно снижая нагрузку на DOM.

```jsx
import { FixedSizeList } from 'react-window';

function VirtualizedUserList({ users }) {
  const Row = ({ index, style }) => (
    <div style={style} className="user-row">
      <img src={users[index].avatar} alt="" />
      <span>{users[index].name}</span>
      <span>{users[index].email}</span>
    </div>
  );

  return (
    <FixedSizeList
      height={600}           // Высота контейнера (px)
      width="100%"
      itemCount={users.length} // Общее количество элементов
      itemSize={72}           // Высота одного элемента (px)
      overscanCount={5}       // Дополнительные элементы за пределами viewport
    >
      {Row}
    </FixedSizeList>
  );
}
```

| Библиотека | Размер (gzip) | Динамическая высота | Бесконечная прокрутка |
|---|---|---|---|
| `react-window` | ~6 KB | `VariableSizeList` | Через `react-window-infinite-loader` |
| `react-virtuoso` | ~16 KB | Встроена | Встроена |
| `@tanstack/react-virtual` | ~5 KB | Встроена | Ручная реализация |

## 7. Code Splitting — React.lazy и Suspense

`React.lazy` позволяет загружать компоненты **по требованию**, разделяя бандл на чанки.
Используется совместно с `Suspense` для отображения fallback во время загрузки.

```jsx
import { lazy, Suspense } from 'react';

// Динамический import — webpack/vite создаёт отдельный чанк
const AdminPanel = lazy(() => import('./AdminPanel'));
const Analytics = lazy(() => import('./Analytics'));

function App() {
  const [tab, setTab] = useState('home');

  return (
    <div>
      <nav>
        <button onClick={() => setTab('home')}>Главная</button>
        <button onClick={() => setTab('admin')}>Админка</button>
        <button onClick={() => setTab('analytics')}>Аналитика</button>
      </nav>

      <Suspense fallback={<Skeleton />}>
        {tab === 'home' && <Home />}
        {tab === 'admin' && <AdminPanel />}
        {tab === 'analytics' && <Analytics />}
      </Suspense>
    </div>
  );
}
```

## 8. React Compiler — автоматическая мемоизация

React Compiler (ранее React Forget) — компилятор, который автоматически добавляет
`useMemo` и `useCallback` на этапе сборки. Анализирует компоненты и определяет,
какие значения и функции можно мемоизировать.

### 8.1 Что делает компилятор

| Аспект | До компилятора | После компилятора |
|---|---|---|
| Мемоизация | Ручная: `useMemo`, `useCallback`, `React.memo` | Автоматическая на уровне AST |
| JSX-элементы | Создаются заново каждый render | Мемоизируются при неизменных props |
| Объекты/массивы | Новая ссылка каждый render | Кэшируются при неизменных deps |
| Обратная совместимость | — | Полная — результат идентичен ручной мемоизации |

### 8.2 Правила для совместимости

React Compiler предполагает, что компоненты следуют **Rules of React**:
- Компоненты и хуки — чистые функции (идемпотентные)
- Props и state — иммутабельны
- Возвращаемые значения и аргументы хуков — иммутабельны
- Значения, переданные в JSX, не мутируются после создания

Нарушение этих правил приводит к тому, что компилятор **пропускает** компонент
или генерирует некорректный код.

## 9. Concurrent Features для UX

### 9.1 useTransition — несрочные обновления

Помечает обновление state как **transition** — React может прервать его рендер
ради более срочных обновлений (пользовательский ввод).

```jsx
function SearchPage() {
  const [query, setQuery] = useState('');
  const [results, setResults] = useState([]);
  const [isPending, startTransition] = useTransition();

  const handleChange = (e) => {
    const value = e.target.value;
    setQuery(value); // Срочное: обновить input мгновенно

    startTransition(() => {
      // Несрочное: фильтрация может быть прервана
      setResults(filterHugeDataset(value));
    });
  };

  return (
    <div>
      <input value={query} onChange={handleChange} />
      <div style={{ opacity: isPending ? 0.6 : 1 }}>
        <ResultsList results={results} />
      </div>
    </div>
  );
}
```

### 9.2 useDeferredValue — отложенное значение

Аналог `useTransition`, но для **значений**, а не для обновлений state.
React показывает старое значение, пока новое рендерится в фоне.

```jsx
function SearchResults({ query }) {
  // deferredQuery обновляется с задержкой — не блокирует input
  const deferredQuery = useDeferredValue(query);
  const isStale = query !== deferredQuery;

  const results = useMemo(
    () => filterHugeDataset(deferredQuery),
    [deferredQuery]
  );

  return (
    <div style={{ opacity: isStale ? 0.7 : 1 }}>
      {results.map((r) => <ResultItem key={r.id} data={r} />)}
    </div>
  );
}
```

## 10. Профилирование: React DevTools

### 10.1 Profiler API

React предоставляет компонент `<Profiler>` для программного замера производительности
рендеринга.

```jsx
import { Profiler } from 'react';

function onRenderCallback(
  id,           // "Navigation" — идентификатор профилируемого дерева
  phase,        // "mount" | "update" | "nested-update"
  actualDuration, // Время рендеринга поддерева (мс)
  baseDuration,   // Время полного рендеринга без мемоизации (мс)
  startTime,      // Timestamp начала рендеринга
  commitTime      // Timestamp коммита
) {
  // Отправка метрик в систему мониторинга
  analytics.track('react_render', {
    component: id,
    phase,
    duration: actualDuration,
    timestamp: commitTime,
  });
}

function App() {
  return (
    <Profiler id="Navigation" onRender={onRenderCallback}>
      <Navigation />
    </Profiler>
  );
}
```

### 10.2 React DevTools Flamegraph

| Цвет в Flamegraph | Значение |
|---|---|
| Серый | Компонент не рендерился в этом коммите |
| Голубой/Зелёный | Быстрый рендер |
| Жёлтый | Средний рендер |
| Красный | Долгий рендер — кандидат на оптимизацию |

### 10.3 Сводная таблица техник оптимизации

| Техника | Когда применять | Стоимость | Эффект |
|---|---|---|---|
| `React.memo` | Дорогие компоненты с редко меняющимися props | Shallow compare на каждый render | Предотвращает ререндер поддерева |
| `useMemo` | Тяжёлые вычисления | Сравнение deps | Кэширует результат |
| `useCallback` | Callback в `React.memo`-компоненты | Сравнение deps | Стабильная ссылка на функцию |
| Composition | Изоляция state от дочерних компонентов | Нулевая | Предотвращает каскад |
| Виртуализация | Списки > 100 элементов | Сложность реализации | Рендерит только видимое |
| Code Splitting | Крупные страницы, редко посещаемые маршруты | Дополнительные HTTP-запросы | Уменьшает начальный бандл |
| `useTransition` | Несрочные обновления state | Минимальная | UI остаётся отзывчивым |
| `useDeferredValue` | Тяжёлый рендеринг зависимый от props | Минимальная | Показывает stale данные |
| React Compiler | Вся кодовая база | Настройка сборки | Автоматическая мемоизация |
| Разделение Context | Контексты с частыми обновлениями | Архитектурная | Изолирует подписчиков |

## 11. Специальные хуки производительности

### 11.1 useId — стабильный идентификатор

Генерирует уникальный ID, стабильный между сервером и клиентом. Предотвращает
hydration mismatch, который возникает при использовании `Math.random()` или счётчиков.

```jsx
function FormField({ label }) {
  const id = useId();
  return (
    <div>
      <label htmlFor={id}>{label}</label>
      <input id={id} />
    </div>
  );
}
```

### 11.2 useSyncExternalStore — подписка на внешние хранилища

Безопасная подписка на внешние источники данных (Redux store, browser API)
с поддержкой Concurrent Mode. Предотвращает **tearing** — ситуацию, когда
разные части UI показывают данные из разных «снимков» store.

```jsx
function useWindowWidth() {
  return useSyncExternalStore(
    (onStoreChange) => {
      window.addEventListener('resize', onStoreChange);
      return () => window.removeEventListener('resize', onStoreChange);
    },
    () => window.innerWidth,          // getSnapshot (client)
    () => 1024                        // getServerSnapshot (SSR)
  );
}
```

## 12. Web Vitals и React

| Метрика | Расшифровка | Как React влияет | Оптимизация |
|---|---|---|---|
| **LCP** (Largest Contentful Paint) | Время отрисовки крупнейшего элемента | SSR/SSG уменьшают LCP; Code Splitting увеличивает, если lazy-компонент — LCP-элемент | `<Suspense>` с preload, SSR streaming |
| **INP** (Interaction to Next Paint) | Задержка от взаимодействия до визуального отклика | Долгий рендер блокирует main thread | `useTransition`, виртуализация, React Compiler |
| **CLS** (Cumulative Layout Shift) | Смещения макета при загрузке | Lazy-загрузка без placeholder вызывает сдвиг | Skeleton UI, `width`/`height` на медиа |
| **FCP** (First Contentful Paint) | Первая отрисовка контента | CSR показывает пустой `<div id="root">` | SSR, streaming, progressive hydration |
| **TTFB** (Time to First Byte) | Время до первого байта ответа | Server Components и streaming ускоряют TTFB | Edge Runtime, кэширование |
