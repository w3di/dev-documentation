# Формы в React — полное руководство

> Формы — одна из ключевых точек взаимодействия пользователя с приложением.
> React предлагает два фундаментально различных подхода к управлению данными форм:
> **controlled** (управляемые) и **uncontrolled** (неуправляемые) компоненты.
> Выбор подхода определяет архитектуру обработки ввода, валидации и отправки.

## 1. Controlled Components

В controlled-компоненте React является **единственным источником истины** для значения
элемента формы. Значение хранится в state компонента, а изменения обрабатываются через
`onChange`. DOM-элемент всегда отражает текущий state.

### 1.1 Принцип работы

```
Пользователь вводит символ
       │
       ▼
onChange → event.target.value
       │
       ▼
setState(newValue)
       │
       ▼
Re-render → input.value = state
       │
       ▼
DOM обновлён — отображает новое значение
```

### 1.2 Базовый пример

```jsx
function LoginForm() {
  const [email, setEmail] = useState('');
  const [password, setPassword] = useState('');
  const [errors, setErrors] = useState({});

  const validate = () => {
    const newErrors = {};
    if (!email.includes('@')) newErrors.email = 'Некорректный email';
    if (password.length < 8) newErrors.password = 'Минимум 8 символов';
    setErrors(newErrors);
    return Object.keys(newErrors).length === 0;
  };

  const handleSubmit = (e) => {
    e.preventDefault();
    if (validate()) {
      submitToAPI({ email, password });
    }
  };

  return (
    <form onSubmit={handleSubmit}>
      <div>
        <input
          type="email"
          value={email}
          onChange={(e) => setEmail(e.target.value)}
          className={errors.email ? 'input-error' : ''}
        />
        {errors.email && <span className="error">{errors.email}</span>}
      </div>
      <div>
        <input
          type="password"
          value={password}
          onChange={(e) => setPassword(e.target.value)}
        />
        {errors.password && <span className="error">{errors.password}</span>}
      </div>
      <button type="submit">Войти</button>
    </form>
  );
}
```

### 1.3 Особенности разных элементов

| Элемент | Атрибут значения | Событие | Особенность |
|---|---|---|---|
| `<input type="text">` | `value` | `onChange` | `e.target.value` — строка |
| `<textarea>` | `value` | `onChange` | В React — `value`, не `children` |
| `<select>` | `value` | `onChange` | Значение на `<select>`, не `selected` на `<option>` |
| `<input type="checkbox">` | `checked` | `onChange` | `e.target.checked` — boolean |
| `<input type="radio">` | `checked` | `onChange` | Группировка по `name` |

## 2. Uncontrolled Components

В uncontrolled-компоненте DOM сам хранит значение элемента. React обращается к нему
через `ref` при необходимости (обычно при отправке). Начальное значение задаётся
атрибутом `defaultValue` (не `value`).

```jsx
function SearchForm() {
  const inputRef = useRef(null);
  const selectRef = useRef(null);

  const handleSubmit = (e) => {
    e.preventDefault();
    // Значения читаются из DOM в момент отправки
    const query = inputRef.current.value;
    const category = selectRef.current.value;
    performSearch({ query, category });
  };

  return (
    <form onSubmit={handleSubmit}>
      <input
        ref={inputRef}
        type="text"
        defaultValue=""
        placeholder="Поиск..."
      />
      <select ref={selectRef} defaultValue="all">
        <option value="all">Все категории</option>
        <option value="articles">Статьи</option>
        <option value="products">Товары</option>
      </select>
      <button type="submit">Найти</button>
    </form>
  );
}
```

## 3. Сравнение подходов

| Критерий | Controlled | Uncontrolled |
|---|---|---|
| Источник истины | React state | DOM |
| Доступ к значению | Мгновенный (из state) | Через `ref.current.value` |
| Валидация на лету | Да — при каждом `onChange` | Затруднена — только при submit |
| Условный рендеринг | Да — зависит от текущего значения | Ограничен |
| Производительность | Re-render на каждый keystroke | Без re-render при вводе |
| Начальное значение | `value={state}` | `defaultValue="..."` |
| Интеграция со сторонними библиотеками | Сложнее — требуется синхронизация | Проще — DOM управляет собой |
| Файловый `<input>` | Невозможен (read-only `value`) | Единственный вариант |

**Рекомендация React**: использовать controlled-компоненты в большинстве случаев.
Uncontrolled оправданы для простых форм, файлового ввода и интеграции с не-React кодом.

## 4. Обработка событий форм

### 4.1 SyntheticEvent

React оборачивает нативные DOM-события в `SyntheticEvent` — кроссбраузерную обёртку
с единым API. Для форм ключевые события:

| Событие | Когда срабатывает | Типичное использование |
|---|---|---|
| `onChange` | При каждом изменении значения | Обновление state |
| `onSubmit` | При отправке формы | Валидация и отправка данных |
| `onBlur` | При потере фокуса | Валидация отдельного поля |
| `onFocus` | При получении фокуса | Показ подсказок |
| `onInput` | При каждом вводе (аналог нативного) | Редко — `onChange` предпочтительнее |

### 4.2 preventDefault и отправка

```jsx
function ContactForm() {
  const [formData, setFormData] = useState({ name: '', message: '' });
  const [submitting, setSubmitting] = useState(false);

  const handleSubmit = async (e) => {
    e.preventDefault(); // Предотвращаем перезагрузку страницы
    setSubmitting(true);
    try {
      await fetch('/api/contact', {
        method: 'POST',
        headers: { 'Content-Type': 'application/json' },
        body: JSON.stringify(formData),
      });
      setFormData({ name: '', message: '' }); // Сброс формы
    } finally {
      setSubmitting(false);
    }
  };

  return (
    <form onSubmit={handleSubmit}>
      {/* поля формы */}
      <button type="submit" disabled={submitting}>
        {submitting ? 'Отправка...' : 'Отправить'}
      </button>
    </form>
  );
}
```

## 5. Многопольные формы — единый обработчик

Вместо создания отдельного обработчика для каждого поля используется паттерн
с атрибутом `name` и **вычисляемым именем свойства** (`[e.target.name]`).

```jsx
function RegistrationForm() {
  const [formData, setFormData] = useState({
    firstName: '',
    lastName: '',
    email: '',
    role: 'user',
    agreeToTerms: false,
  });

  // Единый обработчик для всех полей
  const handleChange = (e) => {
    const { name, value, type, checked } = e.target;
    setFormData((prev) => ({
      ...prev,
      [name]: type === 'checkbox' ? checked : value,
    }));
  };

  const handleSubmit = (e) => {
    e.preventDefault();
    console.log('Данные формы:', formData);
  };

  return (
    <form onSubmit={handleSubmit}>
      <input name="firstName" value={formData.firstName} onChange={handleChange} />
      <input name="lastName" value={formData.lastName} onChange={handleChange} />
      <input name="email" type="email" value={formData.email} onChange={handleChange} />

      <select name="role" value={formData.role} onChange={handleChange}>
        <option value="user">Пользователь</option>
        <option value="admin">Администратор</option>
      </select>

      <label>
        <input
          name="agreeToTerms"
          type="checkbox"
          checked={formData.agreeToTerms}
          onChange={handleChange}
        />
        Согласен с условиями
      </label>

      <button type="submit" disabled={!formData.agreeToTerms}>
        Зарегистрироваться
      </button>
    </form>
  );
}
```

## 6. Валидация форм

### 6.1 Три уровня валидации

| Уровень | Механизм | Плюсы | Минусы |
|---|---|---|---|
| Встроенная HTML | `required`, `pattern`, `minLength`, `type="email"` | Нулевой JS-код, нативные подсказки | Неконсистентный UX, сложно стилизовать |
| Кастомная React | Ручная проверка в `onChange` / `onBlur` / `onSubmit` | Полный контроль | Boilerplate, ручная обработка ошибок |
| Библиотечная | React Hook Form, Formik, Zod, Yup | Декларативные схемы, мало кода | Размер бандла, кривая обучения |

### 6.2 Кастомная валидация с onBlur

```jsx
function ValidatedInput({ label, name, value, onChange, validate }) {
  const [error, setError] = useState(null);
  const [touched, setTouched] = useState(false);

  const handleBlur = () => {
    setTouched(true);
    const errorMessage = validate(value);
    setError(errorMessage);
  };

  return (
    <div className="field">
      <label>{label}</label>
      <input
        name={name}
        value={value}
        onChange={onChange}
        onBlur={handleBlur}
        aria-invalid={touched && !!error}
        aria-describedby={error ? `${name}-error` : undefined}
      />
      {touched && error && (
        <span id={`${name}-error`} role="alert" className="error">
          {error}
        </span>
      )}
    </div>
  );
}
```

## 7. Файловые input

Файловый `<input type="file">` — **всегда uncontrolled**, поскольку его `value`
доступен только для чтения по соображениям безопасности. React не может программно
устанавливать выбранные файлы.

```jsx
function FileUpload() {
  const fileInputRef = useRef(null);
  const [selectedFiles, setSelectedFiles] = useState([]);

  const handleFileChange = (e) => {
    const files = Array.from(e.target.files);
    setSelectedFiles(files);
  };

  const handleUpload = async () => {
    const formData = new FormData();
    selectedFiles.forEach((file) => formData.append('files', file));

    await fetch('/api/upload', { method: 'POST', body: formData });
    // Сброс input — через ref, т. к. value read-only для file
    fileInputRef.current.value = '';
    setSelectedFiles([]);
  };

  return (
    <div>
      <input
        ref={fileInputRef}
        type="file"
        multiple
        accept="image/*,.pdf"
        onChange={handleFileChange}
      />
      {selectedFiles.length > 0 && (
        <ul>
          {selectedFiles.map((f) => (
            <li key={f.name}>{f.name} — {(f.size / 1024).toFixed(1)} KB</li>
          ))}
        </ul>
      )}
      <button onClick={handleUpload} disabled={selectedFiles.length === 0}>
        Загрузить
      </button>
    </div>
  );
}
```

## 8. React 19: Actions и useActionState

React 19 вводит концепцию **Actions** — функций, которые обрабатывают отправку формы.
`useActionState` (ранее `useFormState` из `react-dom`) управляет состоянием формы
на основе результата действия.

### 8.1 Server Action + useActionState

```jsx
// actions.js (Server Action — директива 'use server')
'use server';

export async function createUser(prevState, formData) {
  const name = formData.get('name');
  const email = formData.get('email');

  // Серверная валидация
  if (!email.includes('@')) {
    return { error: 'Некорректный email', success: false };
  }

  await db.users.create({ name, email });
  return { error: null, success: true };
}
```

```jsx
// CreateUserForm.jsx
'use client';

import { useActionState } from 'react';
import { createUser } from './actions';

function CreateUserForm() {
  const [state, formAction, isPending] = useActionState(createUser, {
    error: null,
    success: false,
  });

  return (
    <form action={formAction}>
      <input name="name" placeholder="Имя" required />
      <input name="email" type="email" placeholder="Email" required />

      {state.error && <p className="error">{state.error}</p>}
      {state.success && <p className="success">Пользователь создан</p>}

      <button type="submit" disabled={isPending}>
        {isPending ? 'Создание...' : 'Создать'}
      </button>
    </form>
  );
}
```

### 8.2 Преимущества Actions

- Форма работает **до загрузки JavaScript** (progressive enhancement)
- Server Actions выполняются на сервере — клиент не видит логику
- `isPending` — встроенное отслеживание состояния загрузки
- Автоматическая сериализация `FormData`

## 9. React 19: useFormStatus

Хук `useFormStatus` из `react-dom` предоставляет информацию о статусе родительской
формы (`<form>`). Должен вызываться в **дочернем компоненте** формы.

```jsx
import { useFormStatus } from 'react-dom';

function SubmitButton() {
  const { pending, data, method, action } = useFormStatus();

  return (
    <button type="submit" disabled={pending}>
      {pending ? (
        <>
          <Spinner size="sm" /> Отправка...
        </>
      ) : (
        'Отправить'
      )}
    </button>
  );
}

// Использование — SubmitButton ВНУТРИ <form>
function FeedbackForm({ submitAction }) {
  return (
    <form action={submitAction}>
      <textarea name="feedback" required />
      <SubmitButton /> {/* Получает статус родительской формы */}
    </form>
  );
}
```

| Свойство | Тип | Описание |
|---|---|---|
| `pending` | `boolean` | `true` во время выполнения action |
| `data` | `FormData \| null` | Данные отправляемой формы |
| `method` | `string` | HTTP-метод (`"get"` или `"post"`) |
| `action` | `function \| string` | Ссылка на action формы |

## 10. Библиотеки форм

### 10.1 React Hook Form — минимальные re-render'ы

React Hook Form использует **uncontrolled-подход** с `ref` внутри, что даёт
минимальное количество перерисовок. Значения извлекаются из DOM через `register`.

```jsx
import { useForm } from 'react-hook-form';
import { zodResolver } from '@hookform/resolvers/zod';
import { z } from 'zod';

// Zod-схема для валидации
const schema = z.object({
  username: z.string().min(3, 'Минимум 3 символа'),
  email: z.string().email('Некорректный email'),
  age: z.coerce.number().min(18, 'Минимум 18 лет'),
});

function ProfileForm() {
  const {
    register,
    handleSubmit,
    formState: { errors, isSubmitting },
  } = useForm({
    resolver: zodResolver(schema),
    defaultValues: { username: '', email: '', age: '' },
  });

  const onSubmit = async (data) => {
    // data уже типизирован и провалидирован через Zod
    await saveProfile(data);
  };

  return (
    <form onSubmit={handleSubmit(onSubmit)}>
      <input {...register('username')} placeholder="Имя пользователя" />
      {errors.username && <span>{errors.username.message}</span>}

      <input {...register('email')} placeholder="Email" />
      {errors.email && <span>{errors.email.message}</span>}

      <input {...register('age')} type="number" placeholder="Возраст" />
      {errors.age && <span>{errors.age.message}</span>}

      <button type="submit" disabled={isSubmitting}>
        Сохранить
      </button>
    </form>
  );
}
```

### 10.2 Сравнение библиотек

| Критерий | React Hook Form | Formik | Тандем Zod + RHF |
|---|---|---|---|
| Подход | Uncontrolled (ref) | Controlled (state) | Uncontrolled + схема |
| Re-render'ы | Минимальные | На каждое изменение | Минимальные |
| Размер (gzip) | ~9 KB | ~13 KB | ~9 KB + ~14 KB (Zod) |
| TypeScript | Отличная типизация | Хорошая | Инферринг типов из схемы |
| Валидация | Встроенная + resolvers | Yup, ручная | Zod-схемы |
| API | `register`, `handleSubmit` | `<Field>`, `<Form>` | `zodResolver` |

## 11. Производительность форм

### 11.1 Проблема: useState на каждый keystroke

В controlled-подходе `setState` вызывается на **каждый символ**. Для формы с 20 полями
это означает перерисовку всего компонента формы на каждый keystroke.

### 11.2 Стратегии оптимизации

| Стратегия | Описание | Когда использовать |
|---|---|---|
| Изоляция полей | Каждое поле — отдельный компонент с `React.memo` | Формы > 10 полей |
| Uncontrolled + ref | Нет re-render при вводе | Простые формы без динамических правил |
| React Hook Form | Uncontrolled внутри, API controlled | Средние и большие формы |
| Debounced state | `useState` обновляется с задержкой | Поля поиска с API-запросами |
| `useTransition` | Помечает обновление как несрочное | Тяжёлые фильтрации при вводе |

```jsx
// Пример: изоляция поля для предотвращения каскадного ререндера
const IsolatedField = React.memo(function IsolatedField({ name, value, onChange }) {
  console.log(`render: ${name}`); // Рендер только при изменении СВОЕГО value
  return <input name={name} value={value} onChange={onChange} />;
});

function OptimizedForm() {
  const [fields, setFields] = useState({ a: '', b: '', c: '' });

  const handleChange = useCallback((e) => {
    const { name, value } = e.target;
    setFields((prev) => ({ ...prev, [name]: value }));
  }, []);

  return (
    <form>
      {Object.keys(fields).map((key) => (
        <IsolatedField
          key={key}
          name={key}
          value={fields[key]}
          onChange={handleChange}
        />
      ))}
    </form>
  );
}
```
