# Жизненный цикл компонента — полное руководство

> Каждый React-компонент проходит через три фазы существования: **монтирование** (mounting),
> **обновление** (updating) и **размонтирование** (unmounting). Понимание порядка вызова
> методов жизненного цикла — фундамент для корректной работы с побочными эффектами,
> подписками и оптимизацией рендеринга.

## 1. Концепция жизненного цикла

Жизненный цикл компонента — это последовательность этапов, которые компонент проходит
от момента создания до удаления из DOM. React разделяет эти этапы на две внутренние фазы:

| Фаза | Описание | Может быть прервана? |
|---|---|---|
| **Render phase** | React вызывает `render()`, вычисляет VDOM-дифф. Чистая фаза — без побочных эффектов | Да (Concurrent Mode) |
| **Commit phase** | React применяет изменения к реальному DOM, вызывает lifecycle-методы и эффекты | Нет — синхронна |

Это разделение критично: методы **Render-фазы** (`constructor`, `render`, `getDerivedStateFromProps`,
`shouldComponentUpdate`) не должны содержать побочных эффектов, поскольку в Concurrent Mode
React может вызвать их многократно и прервать без завершения.

## 2. Жизненный цикл классового компонента

### 2.1 Полная карта методов

```
MOUNTING                    UPDATING                         UNMOUNTING
────────                    ────────                         ──────────
constructor()               getDerivedStateFromProps()        componentWillUnmount()
     │                           │
     ▼                           ▼
getDerivedStateFromProps()  shouldComponentUpdate()
     │                           │
     ▼                           ▼ (если true)
render()                    render()
     │                           │
     ▼                           ▼
componentDidMount()         getSnapshotBeforeUpdate()
                                 │
                                 ▼
                            componentDidUpdate()

ERROR HANDLING
──────────────
static getDerivedStateFromError()   ← Render phase
componentDidCatch()                 ← Commit phase
```

## 3. Mounting — фаза монтирования

### 3.1 constructor(props)

Вызывается **один раз** перед монтированием. Единственное место, где допустимо прямое
присвоение `this.state`. Вызов `super(props)` обязателен перед обращением к `this`.

```jsx
class UserProfile extends React.Component {
  constructor(props) {
    super(props);
    // Прямая инициализация state — единственное место без setState
    this.state = {
      isLoading: true,
      userData: null,
      error: null,
    };
    // Привязка контекста — альтернатива: class fields + arrow functions
    this.handleRetry = this.handleRetry.bind(this);
  }

  handleRetry() {
    this.setState({ isLoading: true, error: null });
    this.fetchUser();
  }
}
```

### 3.2 static getDerivedStateFromProps(props, state)

Статический метод — не имеет доступа к `this`. Вызывается **перед каждым рендером**
(и при монтировании, и при обновлении). Возвращает объект для обновления state
или `null`, если обновление не требуется.

```jsx
class FilteredList extends React.Component {
  state = { prevItems: [], filteredItems: [] };

  static getDerivedStateFromProps(props, state) {
    // Пересчитываем только при изменении входных данных
    if (props.items !== state.prevItems) {
      return {
        prevItems: props.items,
        filteredItems: props.items.filter((item) => item.active),
      };
    }
    return null; // state не изменяется
  }

  render() {
    return this.state.filteredItems.map((item) => (
      <div key={item.id}>{item.name}</div>
    ));
  }
}
```

### 3.3 render()

Чистая функция. Должна возвращать JSX, `null`, `false`, строку, число, портал
или массив элементов. **Запрещены** побочные эффекты, `setState`, подписки.

### 3.4 componentDidMount()

Вызывается **один раз** после того, как компонент вставлен в DOM. Это место для:
- HTTP-запросов и подписок
- Интеграции с DOM API (`addEventListener`, сторонние библиотеки)
- Вызовов `setState` (вызовет повторный рендер до отрисовки на экране)

```jsx
class DataFetcher extends React.Component {
  state = { data: null, loading: true };

  async componentDidMount() {
    try {
      const response = await fetch(`/api/users/${this.props.userId}`);
      const data = await response.json();
      this.setState({ data, loading: false });
    } catch (error) {
      this.setState({ error, loading: false });
    }
  }

  componentWillUnmount() {
    // AbortController для отмены запросов — см. раздел Unmounting
  }

  render() {
    if (this.state.loading) return <Spinner />;
    return <UserCard user={this.state.data} />;
  }
}
```

## 4. Updating — фаза обновления

Обновление происходит при изменении `props`, вызове `setState()` или `forceUpdate()`.

### 4.1 shouldComponentUpdate(nextProps, nextState)

Возвращает `boolean`. По умолчанию — `true`. Позволяет предотвратить рендер,
если обновление не затрагивает визуальное представление. `React.PureComponent`
реализует shallow comparison автоматически.

```jsx
class HeavyList extends React.Component {
  shouldComponentUpdate(nextProps, nextState) {
    // Рендерим только при реальном изменении данных
    return (
      nextProps.items !== this.props.items ||
      nextState.sortOrder !== this.state.sortOrder
    );
  }

  render() {
    const sorted = [...this.props.items].sort(comparator(this.state.sortOrder));
    return sorted.map((item) => <Row key={item.id} data={item} />);
  }
}
```

### 4.2 getSnapshotBeforeUpdate(prevProps, prevState)

Вызывается **после render**, но **до применения изменений к DOM**. Возвращаемое значение
передаётся третьим аргументом в `componentDidUpdate`. Используется для захвата информации
о DOM (позиция скролла, размеры элемента) перед обновлением.

```jsx
class ChatWindow extends React.Component {
  chatRef = React.createRef();

  getSnapshotBeforeUpdate(prevProps) {
    // Запоминаем позицию скролла перед добавлением новых сообщений
    if (prevProps.messages.length < this.props.messages.length) {
      const chat = this.chatRef.current;
      return chat.scrollHeight - chat.scrollTop;
    }
    return null;
  }

  componentDidUpdate(prevProps, prevState, snapshot) {
    // Восстанавливаем позицию скролла после обновления DOM
    if (snapshot !== null) {
      const chat = this.chatRef.current;
      chat.scrollTop = chat.scrollHeight - snapshot;
    }
  }

  render() {
    return (
      <div ref={this.chatRef} className="chat-window">
        {this.props.messages.map((msg) => (
          <Message key={msg.id} data={msg} />
        ))}
      </div>
    );
  }
}
```

## 5. Unmounting — фаза размонтирования

### 5.1 componentWillUnmount()

Вызывается непосредственно перед удалением компонента из DOM. Место для очистки:
- Отмена HTTP-запросов (`AbortController`)
- Удаление подписок и слушателей событий
- Очистка таймеров (`clearInterval`, `clearTimeout`)
- Отмена анимаций

```jsx
class RealTimeChart extends React.Component {
  controller = new AbortController();

  componentDidMount() {
    this.ws = new WebSocket('wss://api.example.com/feed');
    this.ws.onmessage = (event) => {
      this.setState({ data: JSON.parse(event.data) });
    };
    this.intervalId = setInterval(() => this.syncData(), 30000);
  }

  componentWillUnmount() {
    // Критично: без очистки — утечки памяти и обновление unmounted-компонента
    this.ws.close();
    this.controller.abort();
    clearInterval(this.intervalId);
  }
}
```

## 6. Error Boundaries — перехват ошибок

Error Boundaries доступны **только в классовых компонентах**. Перехватывают ошибки
в дочернем дереве во время рендеринга, lifecycle-методов и конструкторов.

| Метод | Фаза | Назначение |
|---|---|---|
| `static getDerivedStateFromError(error)` | Render | Обновить state для показа fallback UI |
| `componentDidCatch(error, errorInfo)` | Commit | Логирование, отправка в Sentry и т. д. |

**Не перехватывают**: ошибки в обработчиках событий, асинхронном коде, SSR, в самом Error Boundary.

```jsx
class ErrorBoundary extends React.Component {
  state = { hasError: false, error: null };

  static getDerivedStateFromError(error) {
    // Render phase — обновляем state для fallback UI
    return { hasError: true, error };
  }

  componentDidCatch(error, errorInfo) {
    // Commit phase — побочные эффекты разрешены
    logErrorToService(error, errorInfo.componentStack);
  }

  render() {
    if (this.state.hasError) {
      return <FallbackUI error={this.state.error} />;
    }
    return this.props.children;
  }
}

// Использование:
<ErrorBoundary>
  <UserDashboard />
</ErrorBoundary>
```

## 7. Маппинг lifecycle → хуки

### 7.1 Полная таблица соответствия

| Классовый метод | Хуки (функциональные компоненты) | Примечания |
|---|---|---|
| `constructor` | `useState`, `useRef` | Инициализация state — через начальное значение `useState` |
| `getDerivedStateFromProps` | `useState` + условие в теле компонента | Вычислить новый state до рендера на основе props |
| `shouldComponentUpdate` | `React.memo(Component, compareFn)` | Мемоизация на уровне компонента |
| `render` | Тело функции (return JSX) | Функциональный компонент — это и есть `render` |
| `componentDidMount` | `useEffect(fn, [])` | Пустой массив зависимостей — один раз после mount |
| `componentDidUpdate` | `useEffect(fn, [deps])` | Вызывается после каждого рендера при изменении deps |
| `componentWillUnmount` | `useEffect(() => cleanup, [])` | Функция очистки из `useEffect` |
| `getSnapshotBeforeUpdate` | Нет прямого аналога | Используют `useRef` + `useLayoutEffect` |
| `componentDidCatch` | Нет аналога в хуках | Error Boundaries — только классы (React 19: нет изменений) |
| `getDerivedStateFromError` | Нет аналога в хуках | Error Boundaries — только классы |

### 7.2 componentDidMount → useEffect

```jsx
// Классовый компонент
class UserList extends React.Component {
  state = { users: [], loading: true };

  componentDidMount() {
    fetch('/api/users')
      .then((res) => res.json())
      .then((users) => this.setState({ users, loading: false }));
  }

  render() {
    if (this.state.loading) return <Spinner />;
    return this.state.users.map((u) => <UserCard key={u.id} user={u} />);
  }
}

// Функциональный эквивалент
function UserList() {
  const [users, setUsers] = useState([]);
  const [loading, setLoading] = useState(true);

  useEffect(() => {
    let cancelled = false;
    fetch('/api/users')
      .then((res) => res.json())
      .then((data) => {
        if (!cancelled) {
          setUsers(data);
          setLoading(false);
        }
      });
    return () => { cancelled = true; }; // cleanup — аналог componentWillUnmount
  }, []); // [] — вызов один раз, как componentDidMount

  if (loading) return <Spinner />;
  return users.map((u) => <UserCard key={u.id} user={u} />);
}
```

### 7.3 getDerivedStateFromProps → useState в теле компонента

```jsx
function FilteredList({ items }) {
  const [prevItems, setPrevItems] = useState(items);
  const [filtered, setFiltered] = useState(() => items.filter((i) => i.active));

  // Паттерн «derived state» — вычисление до рендера
  if (items !== prevItems) {
    setPrevItems(items);
    setFiltered(items.filter((i) => i.active));
  }

  return filtered.map((item) => <div key={item.id}>{item.name}</div>);
}
```

## 8. Порядок выполнения хуков при рендеринге

### 8.1 Последовательность вызовов

```
Функциональный компонент — порядок выполнения при MOUNT:
───────────────────────────────────────────────────────
1. Вызов функции компонента (тело)
   ├── useState() — инициализация state
   ├── useRef() — создание ref
   ├── useMemo() — вычисление мемоизированного значения
   └── return JSX
2. React применяет изменения к DOM (commit)
3. useLayoutEffect(fn, []) — СИНХРОННО после DOM-мутации, ДО отрисовки
4. Браузер отрисовывает экран (paint)
5. useEffect(fn, []) — АСИНХРОННО после отрисовки

При UPDATE:
───────────
1. Вызов функции компонента (тело)
   ├── useState() — возвращает текущий state
   ├── useMemo() — пересчитывает при изменении deps
   └── return JSX
2. React применяет изменения к DOM (commit)
3. useLayoutEffect cleanup (предыдущий) → useLayoutEffect(fn)
4. Браузер отрисовывает экран (paint)
5. useEffect cleanup (предыдущий) → useEffect(fn)
```

### 8.2 useLayoutEffect vs useEffect

| Характеристика | `useEffect` | `useLayoutEffect` |
|---|---|---|
| Когда вызывается | После paint (асинхронно) | После DOM-мутации, до paint (синхронно) |
| Блокирует ли отрисовку | Нет | Да |
| Использование | Запросы, подписки, аналитика | Измерение DOM, синхронные визуальные корректировки |
| Аналог в классах | `componentDidMount` / `componentDidUpdate` | `componentDidMount` / `componentDidUpdate` (ближе) |

## 9. StrictMode и двойной вызов

В режиме разработки (`development`) `<React.StrictMode>` намеренно вызывает определённые
функции **дважды**, чтобы обнаружить побочные эффекты в Render-фазе.

### 9.1 Что вызывается дважды

| Что | Двойной вызов? | Причина |
|---|---|---|
| Тело функционального компонента | Да | Проверка чистоты render |
| Инициализатор `useState` / `useReducer` | Да | Проверка идемпотентности |
| `useMemo` callback | Да | Проверка чистоты |
| `useEffect` setup + cleanup | Да (mount → unmount → mount) | Проверка корректной очистки |
| Event handlers | Нет | Не входят в render phase |

```jsx
function Counter() {
  // В StrictMode: этот console.log выведется ДВАЖДЫ при каждом рендере
  console.log('render');

  const [count, setCount] = useState(() => {
    console.log('init state'); // Тоже дважды в dev
    return 0;
  });

  useEffect(() => {
    console.log('effect mount');
    return () => console.log('effect cleanup');
    // Dev: mount → cleanup → mount (три вызова)
  }, []);

  return <button onClick={() => setCount((c) => c + 1)}>{count}</button>;
}
```

### 9.2 Зачем это нужно

React готовит компоненты к Concurrent Mode и Offscreen API, где компоненты могут
монтироваться и размонтироваться многократно без участия пользователя. Двойной вызов
в `StrictMode` гарантирует, что:
- `useEffect` cleanup корректно отменяет подписки
- Нет утечек ресурсов при повторном монтировании
- Рендер не зависит от побочных эффектов

## 10. Диаграммы жизненного цикла

### 10.1 Классовый компонент — полный цикл

```
┌─────────────────────────────── MOUNTING ────────────────────────────────┐
│                                                                         │
│  constructor(props)                                                     │
│       │                                                                 │
│       ▼                                                                 │
│  static getDerivedStateFromProps(props, state)                          │
│       │                                                                 │
│       ▼                                                                 │
│  render()                                         ◄── Render Phase      │
│       │                                               (чистая, без      │
│       ▼                                                side effects)    │
│  ═══════════════ DOM обновлён ══════════════════                        │
│       │                                                                 │
│       ▼                                                                 │
│  componentDidMount()                              ◄── Commit Phase      │
│                                                       (side effects OK) │
└─────────────────────────────────────────────────────────────────────────┘
         │
         │  setState() / new props / forceUpdate()
         ▼
┌─────────────────────────────── UPDATING ────────────────────────────────┐
│                                                                         │
│  static getDerivedStateFromProps(props, state)                          │
│       │                                                                 │
│       ▼                                                                 │
│  shouldComponentUpdate(nextProps, nextState)    → false → СТОП          │
│       │ true                                                            │
│       ▼                                                                 │
│  render()                                         ◄── Render Phase      │
│       │                                                                 │
│       ▼                                                                 │
│  getSnapshotBeforeUpdate(prevProps, prevState)                          │
│       │                                                                 │
│       ▼                                                                 │
│  ═══════════════ DOM обновлён ══════════════════                        │
│       │                                                                 │
│       ▼                                                                 │
│  componentDidUpdate(prevProps, prevState, snapshot) ◄── Commit Phase    │
│                                                                         │
└─────────────────────────────────────────────────────────────────────────┘
         │
         │  Компонент удаляется из дерева
         ▼
┌─────────────────────────────── UNMOUNTING ───────────────────────────────┐
│                                                                          │
│  componentWillUnmount()                            ◄── Commit Phase      │
│  (очистка подписок, таймеров, отмена запросов)                           │
│                                                                          │
└──────────────────────────────────────────────────────────────────────────┘
```

### 10.2 Функциональный компонент — порядок хуков

```
┌────────────────────── РЕНДЕРИНГ (каждый цикл) ──────────────────────────┐
│                                                                          │
│  Вызов функции компонента                                                │
│       │                                                                  │
│       ├── useState / useReducer   → возврат текущего state               │
│       ├── useRef                  → возврат текущего ref                  │
│       ├── useContext              → чтение контекста                      │
│       ├── useMemo(fn, deps)       → мемоизированное значение             │
│       ├── useCallback(fn, deps)   → мемоизированная функция              │
│       └── return JSX                                                     │
│                                                                          │
│  ════════════════ React commit: DOM обновлён ═══════════════             │
│       │                                                                  │
│       ▼                                                                  │
│  useLayoutEffect cleanup (пред.) → useLayoutEffect(fn)  ◄── ДО paint    │
│       │                                                                  │
│       ▼                                                                  │
│  ════════════════ Браузер paint ═════════════════════════                 │
│       │                                                                  │
│       ▼                                                                  │
│  useEffect cleanup (пред.) → useEffect(fn)              ◄── ПОСЛЕ paint │
│                                                                          │
└──────────────────────────────────────────────────────────────────────────┘
```
