## Iteration Protocol

JavaScript определяет два протокола: **iterable protocol** и **iterator protocol**. Их разделение --- принципиальное архитектурное решение: один объект описывает *способность* перебираться, другой --- конкретное *состояние* перебора.

### Iterable protocol

Объект является *iterable*, если у него определён метод `Symbol.iterator`, который возвращает *iterator*.

```js
const iterable = {
  [Symbol.iterator]() {
    let i = 0;
    return {
      next() {
        return i < 3 ? { value: i++, done: false } : { value: undefined, done: true };
      }
    };
  }
};

for (const v of iterable) console.log(v); // 0, 1, 2
```

### Iterator protocol

Объект является *iterator*, если у него есть метод `next()`, возвращающий `{ value, done }`. Опционально --- `return()` и `throw()`.

### Почему протокол разделён

Разделение позволяет создавать **несколько независимых курсоров** по одной коллекции. Каждый вызов `[Symbol.iterator]()` порождает новый iterator со своим состоянием:

```js
const arr = [1, 2, 3];
const it1 = arr[Symbol.iterator]();
const it2 = arr[Symbol.iterator]();

it1.next(); // { value: 1, done: false }
it2.next(); // { value: 1, done: false } --- независимый курсор
it1.next(); // { value: 2, done: false }
```

### Lazy evaluation

Итераторы вычисляют значения **по требованию** (pull-based). Значение не существует, пока не вызван `next()`. Это фундаментально отличается от массива, где все элементы уже в памяти:

```js
function* naturalNumbers() {
  let n = 1;
  while (true) yield n++;
}

// Бесконечная последовательность --- но памяти потребляет O(1)
const it = naturalNumbers();
it.next(); // { value: 1, done: false }
it.next(); // { value: 2, done: false }
```

### Протокол `return()` и ранний выход

Когда `for...of` прерывается (`break`, `throw`, `return`), движок вызывает `iterator.return()`, давая итератору шанс освободить ресурсы:

```js
function* readLines(file) {
  const handle = openFile(file);
  try {
    while (true) yield handle.readLine();
  } finally {
    handle.close(); // Вызовется при break из for...of
  }
}
```

## Встроенные итерируемые объекты

### Кто итерируем

| Тип | `Symbol.iterator` | Что итерирует |
|---|---|---|
| `Array` | Да | Элементы по индексу |
| `String` | Да | Unicode code points (не code units!) |
| `Map` | Да | Пары `[key, value]` в порядке вставки |
| `Set` | Да | Значения в порядке вставки |
| `TypedArray` | Да | Числовые элементы |
| `arguments` | Да | Аргументы функции |
| `NodeList` | Да | DOM-узлы |
| Генераторы | Да | `yield`-значения |

### String и Unicode

`String` итерирует **code points**, а не code units. Это критично для emoji и символов за пределами BMP:

```js
const emoji = '😀';
emoji.length;          // 2 (два code units --- surrogate pair)
[...emoji].length;     // 1 (один code point)

for (const char of '𝒜BC') {
  console.log(char);   // '𝒜', 'B', 'C' --- корректно разбивает surrogate pairs
}
```

### Кто НЕ итерируем

**Обычный `Object` не итерируем.** Это осознанное решение: у объектов нет гарантированного порядка свойств (хотя де-факто спецификация ES2015+ его определяет). Для обхода объектов используют `Object.keys()`, `Object.values()`, `Object.entries()` --- они возвращают массивы (которые итерируемы):

```js
const obj = { a: 1, b: 2 };

// TypeError: obj is not iterable
// for (const v of obj) {}

// Корректные подходы:
for (const [k, v] of Object.entries(obj)) {
  console.log(k, v);
}
```

### Где используется iterable protocol

Протокол потребляется не только `for...of`, но и: деструктуризацией (`const [a, b] = iterable`), spread (`[...iterable]`), `Array.from()`, `new Map()`, `new Set()`, `Promise.all()`, `yield*`.

## `for...of` vs `for...in`

### `for...of`

Работает через `Symbol.iterator`. Перебирает **значения**. Используется для любых iterable:

```js
const arr = ['a', 'b', 'c'];
for (const value of arr) {
  console.log(value); // 'a', 'b', 'c'
}
```

### `for...in`

Перебирает **enumerable string-keyed свойства**, включая унаследованные через прототипную цепочку:

```js
const parent = { inherited: true };
const child = Object.create(parent);
child.own = 42;

for (const key in child) {
  console.log(key); // 'own', 'inherited' --- включая прототип!
}
```

### Критические различия

| Аспект | `for...of` | `for...in` |
|---|---|---|
| Протокол | `Symbol.iterator` | Enumerable properties |
| Прототипы | Не затрагивает | Включает inherited |
| Массивы | Значения | Индексы (строки!) + кастомные свойства |
| Объекты | TypeError (если нет итератора) | Работает |
| Performance | Оптимизирован для коллекций | Медленнее из-за property lookup chain |

### Почему `for...in` опасен для массивов

```js
const arr = [10, 20, 30];
arr.custom = 'oops';

for (const i in arr) {
  console.log(i); // '0', '1', '2', 'custom' --- строковые ключи + кастомные свойства
}

for (const v of arr) {
  console.log(v); // 10, 20, 30 --- только значения
}
```

## Кастомные итераторы

### Базовый iterable объект

```js
class Range {
  constructor(start, end, step = 1) {
    this.start = start;
    this.end = end;
    this.step = step;
  }

  [Symbol.iterator]() {
    let current = this.start;
    const { end, step } = this;

    return {
      next() {
        if (current <= end) {
          const value = current;
          current += step;
          return { value, done: false };
        }
        return { value: undefined, done: true };
      }
    };
  }
}

console.log([...new Range(1, 10, 2)]); // [1, 3, 5, 7, 9]
```

### Бесконечные итераторы

```js
function createFibonacci() {
  return {
    [Symbol.iterator]() {
      let a = 0, b = 1;
      return {
        next() {
          [a, b] = [b, a + b];
          return { value: a, done: false }; // Никогда done: true
        }
      };
    }
  };
}

// Безопасно с деструктуризацией или take-подобными утилитами
const [f1, f2, f3, f4, f5] = createFibonacci(); // 1, 1, 2, 3, 5
```

### Iterator как iterable (return `this`)

Часто итератор одновременно является iterable --- для этого он возвращает `this` из `[Symbol.iterator]()`. Все встроенные итераторы (Array Iterator, Map Iterator и т.д.) следуют этому паттерну:

```js
const arr = [1, 2, 3];
const it = arr[Symbol.iterator]();

// it сам iterable --- можно передать в for...of
console.log(it[Symbol.iterator]() === it); // true

for (const v of it) {
  console.log(v); // 1, 2, 3
}
```

Это полезно для «одноразовых» итераторов: один и тот же объект --- и iterable, и iterator. Но при этом нельзя создать два независимых курсора.

### Stateful iterator с `return()`

```js
class DatabaseCursor {
  constructor(query) {
    this.query = query;
    this.connection = null;
  }

  [Symbol.iterator]() {
    this.connection = db.connect();
    const cursor = this.connection.execute(this.query);

    return {
      next() {
        const row = cursor.fetchOne();
        return row ? { value: row, done: false } : { value: undefined, done: true };
      },
      return() {
        // Вызывается при break/throw --- критично для cleanup
        this.connection?.close();
        return { value: undefined, done: true };
      },
      [Symbol.iterator]() { return this; }
    };
  }
}
```

## Генераторы глубоко

### Базовый синтаксис

`function*` объявляет генераторную функцию. `yield` приостанавливает выполнение и возвращает значение. Вызов генераторной функции возвращает iterator (не выполняет тело):

```js
function* countdown(n) {
  while (n > 0) {
    yield n--;
  }
}

const gen = countdown(3);
gen.next(); // { value: 3, done: false }
gen.next(); // { value: 2, done: false }
gen.next(); // { value: 1, done: false }
gen.next(); // { value: undefined, done: true }
```

### `yield*` --- делегирование

`yield*` передаёт управление другому iterable. Это не просто синтаксический сахар --- `yield*` пробрасывает `next()`, `return()` и `throw()` во вложенный итератор:

```js
function* inner() {
  yield 'a';
  yield 'b';
  return 'inner_result'; // return-значение становится результатом yield*
}

function* outer() {
  const result = yield* inner(); // 'a', 'b'
  console.log(result);           // 'inner_result'
  yield 'c';
}

console.log([...outer()]); // ['a', 'b', 'c'] --- return-значение inner НЕ попадает в spread
```

### Двунаправленная коммуникация

Значение, переданное в `next(val)`, становится результатом выражения `yield`:

```js
function* conversation() {
  const name = yield 'Как тебя зовут?';
  const age = yield `Привет, ${name}! Сколько тебе лет?`;
  return `${name}, ${age} лет`;
}

const gen = conversation();
console.log(gen.next());           // { value: 'Как тебя зовут?', done: false }
console.log(gen.next('Алиса'));    // { value: 'Привет, Алиса! Сколько тебе лет?', done: false }
console.log(gen.next(25));         // { value: 'Алиса, 25 лет', done: true }
```

**Важный нюанс:** первый `next()` всегда вызывается без аргумента --- переданное значение будет проигнорировано, потому что ещё нет `yield`-выражения, которому можно присвоить значение.

### `return()` и `throw()`

```js
function* gen() {
  try {
    yield 1;
    yield 2;
    yield 3;
  } finally {
    console.log('cleanup');
  }
}

const it = gen();
it.next();     // { value: 1, done: false }
it.return(42); // cleanup, { value: 42, done: true } --- принудительное завершение
it.next();     // { value: undefined, done: true } --- генератор завершён

// throw() --- инъекция ошибки в точку yield
const it2 = gen();
it2.next();
it2.throw(new Error('fail')); // cleanup, Error: fail
```

### Генератор как coroutine

Генераторы реализуют **cooperative multitasking**. Выполнение приостанавливается на `yield` и возобновляется извне. Это делает их идеальными для управления потоком исполнения:

```js
function* task(name) {
  console.log(`${name}: шаг 1`);
  yield;
  console.log(`${name}: шаг 2`);
  yield;
  console.log(`${name}: шаг 3`);
}

// Простой кооперативный планировщик
function scheduler(tasks) {
  const iterators = tasks.map(t => t());
  let active = [...iterators];

  while (active.length > 0) {
    active = active.filter(it => !it.next().done);
  }
}

scheduler([() => task('A'), () => task('B')]);
// A: шаг 1, B: шаг 1, A: шаг 2, B: шаг 2, A: шаг 3, B: шаг 3
```

## Async iterators и generators

### `Symbol.asyncIterator` и `for await...of`

Async iteration protocol --- аналог sync, но `next()` возвращает `Promise<{ value, done }>`:

```js
const asyncIterable = {
  [Symbol.asyncIterator]() {
    let i = 0;
    return {
      async next() {
        if (i < 3) {
          await new Promise(r => setTimeout(r, 100));
          return { value: i++, done: false };
        }
        return { value: undefined, done: true };
      }
    };
  }
};

(async () => {
  for await (const v of asyncIterable) {
    console.log(v); // 0, 1, 2 --- с задержкой 100ms между значениями
  }
})();
```

### Async generators

`async function*` --- наиболее мощный инструмент для работы с асинхронными потоками данных:

```js
async function* fetchPages(url) {
  let nextUrl = url;
  while (nextUrl) {
    const response = await fetch(nextUrl);
    const data = await response.json();
    yield* data.items;                   // yield каждый элемент страницы
    nextUrl = data.pagination?.nextUrl;  // переход на следующую страницу
  }
}

// Потребление --- элегантный for await...of
for await (const item of fetchPages('/api/users?page=1')) {
  console.log(item);
  if (shouldStop(item)) break; // return() корректно прервёт генератор
}
```

### Практический кейс: обработка stream

```js
async function* parseNDJSON(readableStream) {
  const reader = readableStream.getReader();
  const decoder = new TextDecoder();
  let buffer = '';

  try {
    while (true) {
      const { done, value } = await reader.read();
      if (done) break;

      buffer += decoder.decode(value, { stream: true });
      const lines = buffer.split('\n');
      buffer = lines.pop(); // Неполная строка остаётся в буфере

      for (const line of lines) {
        if (line.trim()) yield JSON.parse(line);
      }
    }

    if (buffer.trim()) yield JSON.parse(buffer);
  } finally {
    reader.releaseLock();
  }
}
```

### Отличия async от sync итераторов

| Аспект | Sync | Async |
|---|---|---|
| Symbol | `Symbol.iterator` | `Symbol.asyncIterator` |
| `next()` возвращает | `{ value, done }` | `Promise<{ value, done }>` |
| Цикл | `for...of` | `for await...of` |
| `yield` | Синхронное значение | Можно `await` внутри |
| Spread | `[...iterable]` | Не поддерживается напрямую |
| Backpressure | Отсутствует (sync) | Естественный --- `await` блокирует чтение |

## Продвинутые паттерны

### Pipeline через генераторы

Генераторы позволяют строить ленивые конвейеры обработки данных --- аналог UNIX pipes:

```js
function* map(iterable, fn) {
  for (const item of iterable) yield fn(item);
}

function* filter(iterable, predicate) {
  for (const item of iterable) {
    if (predicate(item)) yield item;
  }
}

function* take(iterable, n) {
  let count = 0;
  for (const item of iterable) {
    if (count++ >= n) return;
    yield item;
  }
}

function* range(start, end) {
  for (let i = start; i <= end; i++) yield i;
}

// Pipeline: первые 5 чётных квадратов из 1..1000000
const result = [
  ...take(
    filter(
      map(range(1, 1_000_000), x => x * x),
      x => x % 2 === 0
    ),
    5
  )
];
// [4, 16, 36, 64, 100] --- вычислено лениво, без промежуточных массивов
```

### Lazy collections

```js
class LazyCollection {
  constructor(source) {
    this.source = source;
  }

  *[Symbol.iterator]() {
    yield* this.source;
  }

  map(fn) {
    const source = this.source;
    return new LazyCollection(function* () {
      for (const item of source) yield fn(item);
    }());
  }

  filter(fn) {
    const source = this.source;
    return new LazyCollection(function* () {
      for (const item of source) {
        if (fn(item)) yield item;
      }
    }());
  }

  take(n) {
    const source = this.source;
    return new LazyCollection(function* () {
      let count = 0;
      for (const item of source) {
        if (count++ >= n) return;
        yield item;
      }
    }());
  }

  toArray() {
    return [...this];
  }
}

const result = new LazyCollection(range(1, Infinity))
  .map(x => x * x)
  .filter(x => x % 2 === 0)
  .take(5)
  .toArray();
// [4, 16, 36, 64, 100]
```

### Cancellable generators

```js
function* cancellable(genFn) {
  const controller = { cancelled: false };

  const gen = genFn(controller);

  try {
    let result = gen.next();
    while (!result.done) {
      if (controller.cancelled) {
        gen.return(); // Принудительное завершение
        return;
      }
      yield result.value;
      result = gen.next();
    }
  } finally {
    // Cleanup
  }
}
```

### Генератор как state machine

```js
function* trafficLight() {
  while (true) {
    yield 'green';
    yield 'yellow';
    yield 'red';
  }
}

function* connectionStateMachine() {
  while (true) {
    console.log('DISCONNECTED');
    const connectCmd = yield 'disconnected';
    if (connectCmd !== 'connect') continue;

    console.log('CONNECTING...');
    const result = yield 'connecting';

    if (result === 'success') {
      console.log('CONNECTED');
      let cmd;
      while ((cmd = yield 'connected') !== 'disconnect') {
        // Обработка команд в состоянии connected
      }
    } else {
      console.log('CONNECTION FAILED');
      yield 'error';
    }
  }
}

const conn = connectionStateMachine();
conn.next();               // DISCONNECTED -> { value: 'disconnected' }
conn.next('connect');      // CONNECTING... -> { value: 'connecting' }
conn.next('success');      // CONNECTED    -> { value: 'connected' }
conn.next('send data');    // (обработка)  -> { value: 'connected' }
conn.next('disconnect');   // DISCONNECTED -> { value: 'disconnected' }
```

### Pull-based vs Push-based streams

**Pull-based** (итераторы): потребитель запрашивает данные через `next()`. Потребитель контролирует темп.

**Push-based** (Observable, EventEmitter): источник отправляет данные когда они появляются. Источник контролирует темп.

```js
// Pull-based --- потребитель тянет данные
function* pullStream() {
  let i = 0;
  while (true) {
    yield i++; // Ждёт пока потребитель вызовет next()
  }
}

// Push-based --- источник толкает данные
function pushStream(callback) {
  let i = 0;
  setInterval(() => callback(i++), 100); // Не ждёт готовности потребителя
}
```

Async iterators занимают **промежуточное положение**: они pull-based по интерфейсу (`for await...of` запрашивает следующее значение), но внутри могут ждать push-based источники (events, WebSocket). Это даёт **естественный backpressure**: следующее значение не запрашивается, пока текущее не обработано.

```js
// Превращение push-based потока в pull-based async итератор
async function* fromEvent(emitter, event) {
  const queue = [];
  let resolve;

  emitter.on(event, (data) => {
    if (resolve) {
      resolve({ value: data, done: false });
      resolve = null;
    } else {
      queue.push(data);
    }
  });

  try {
    while (true) {
      if (queue.length > 0) {
        yield queue.shift();
      } else {
        yield await new Promise(r => { resolve = r; }).then(v => v.value);
      }
    }
  } finally {
    emitter.removeAllListeners(event);
  }
}
```
