## Классы как синтаксический сахар

Классы в JavaScript — это **не новая модель наследования**, а синтаксическая обёртка над существующим прототипным механизмом. Однако называть их "просто сахаром" некорректно — между `class` и `function`-конструктором есть принципиальные отличия на уровне спецификации ECMAScript.

### Что происходит под капотом

Когда движок встречает `class`-декларацию, он создаёт функцию-объект с внутренним слотом `[[IsClassConstructor]]: true`. Этот слот определяет критическое поведение:

- **`[[Construct]]`** — класс может быть вызван через `new`. Вызов `[[Construct]]` аллоцирует новый объект, привязывает прототип, вызывает тело конструктора.
- **`[[Call]]`** — при вызове без `new` выбрасывает `TypeError`. У обычных функций-конструкторов `[[Call]]` работает нормально.

```js
class Foo {}
function Bar() {}

Bar();       // OK — [[Call]] отрабатывает, this === globalThis (sloppy) или undefined (strict)
Foo();       // TypeError: Class constructor Foo cannot be invoked without 'new'
```

### Ключевые отличия от function constructor

| Аспект | `function` constructor | `class` |
|---|---|---|
| Вызов без `new` | Работает (баг-prone) | `TypeError` |
| Strict mode | Только если задан явно | Всегда strict |
| Enumerable methods | `prototype` методы enumerable | Методы **non-enumerable** |
| Hoisting | Hoisted (можно вызвать до объявления) | TDZ — `ReferenceError` до объявления |
| `prototype` property | writable | **non-writable** (нельзя переназначить) |

```js
// Hoisting / TDZ
const a = new A(); // ReferenceError — A в Temporal Dead Zone
class A {}

const b = new B(); // OK — function declaration hoisted
function B() {}
```

### Non-enumerable методы: почему это важно

Когда вы определяете метод в `class`, он попадает в `prototype` с `enumerable: false`. Это соответствует поведению встроенных методов (`Array.prototype.map`, `Object.prototype.toString`) и предотвращает их появление в `for...in` и `Object.keys()`.

```js
class User {
  greet() { return 'hi'; }
}

// Эквивалент через function constructor:
function UserOld() {}
Object.defineProperty(UserOld.prototype, 'greet', {
  value() { return 'hi'; },
  writable: true,
  configurable: true,
  enumerable: false   // <--- class делает это автоматически
});
```

Если написать `UserOld.prototype.greet = function() {}`, метод будет `enumerable: true` — это ломает `for...in`, `JSON.stringify` при обходе прототипов и паттерны вроде `Object.assign`.

## `constructor`

### Implicit vs explicit constructor

Если `constructor` не определён явно, класс получает **implicit constructor**. Для базового класса это эквивалент пустого `constructor() {}`, для derived-класса — `constructor(...args) { super(...args); }`.

```js
class Base {}
// Неявно: constructor() {}

class Child extends Base {}
// Неявно: constructor(...args) { super(...args); }
```

### Return из конструктора

Поведение `return` в конструкторе определено спецификацией `[[Construct]]`:

- **Возврат объекта** — `new` вернёт этот объект вместо `this`. Прототипная цепочка при этом **не наследуется** автоматически.
- **Возврат примитива** — значение игнорируется, `new` возвращает `this`.

```js
class Sneaky {
  constructor() {
    this.real = true;
    return { fake: true }; // Объект — заменяет this
  }
}
const s = new Sneaky();
console.log(s.real);  // undefined
console.log(s.fake);  // true
console.log(s instanceof Sneaky); // false — прототип подменённого объекта не Sneaky.prototype

class Honest {
  constructor() {
    this.real = true;
    return 42; // Примитив — игнорируется
  }
}
const h = new Honest();
console.log(h.real); // true — this возвращён как обычно
```

### Derived class constructor и обязательный `super()` до `this`

В derived-классе (с `extends`) `this` не существует до вызова `super()`. Это обусловлено спецификацией — аллокацию объекта выполняет **базовый** конструктор. Derived-конструктор получает `this` только после того, как `super()` вернёт управление.

Под капотом: у derived-конструктора внутренний слот `[[ConstructorKind]]` имеет значение `"derived"` (вместо `"base"`). При входе в `[[Construct]]` для derived-класса движок **не создаёт** `this`-binding — среда выполнения (`Environment Record`) имеет неинициализированный `this`.

```js
class Animal {
  constructor(name) {
    this.name = name;
  }
}

class Dog extends Animal {
  constructor(name, breed) {
    // console.log(this); // ReferenceError — this ещё не инициализирован
    super(name);          // Аллоцирует this через базовый конструктор
    this.breed = breed;   // Теперь this доступен
  }
}
```

**Edge case** — если derived-конструктор не вызывает `super()` и пытается обратиться к `this` или завершиться без `return`:

```js
class Broken extends Animal {
  constructor() {
    // Нет super() и нет return объекта
  }
}
new Broken(); // ReferenceError: Must call super constructor in derived class
              // before accessing 'this' or returning from derived constructor
```

Но если вернуть объект явно — `super()` не нужен:

```js
class Weird extends Animal {
  constructor() {
    return { injected: true }; // Работает без super()
  }
}
```

## `extends` и `super`

### `[[HomeObject]]` — как `super` знает, где искать

Ключевой механизм `super` — внутренний слот `[[HomeObject]]`, который привязывается к методу **при определении** (а не при вызове). Этот слот указывает на объект, в `prototype` которого был определён метод. `super.method()` разрешается как `Object.getPrototypeOf([[HomeObject]]).method`.

```js
class A {
  greet() { return 'A'; }
}

class B extends A {
  greet() {
    // [[HomeObject]] этого метода === B.prototype
    // super.greet() === Object.getPrototypeOf(B.prototype).greet() === A.prototype.greet()
    return super.greet() + ' -> B';
  }
}

new B().greet(); // "A -> B"
```

**Критически важно**: `[[HomeObject]]` не меняется при переприсвоении метода другому объекту. Это может привести к неожиданному поведению:

```js
class C {
  greet() { return 'C'; }
}

class D extends C {
  greet() { return super.greet() + ' -> D'; }
}

const obj = { greet: D.prototype.greet };
// obj.greet() всё ещё вызовет super.greet() относительно B.prototype,
// а не относительно obj — потому что [[HomeObject]] закреплён
```

### `super` в статических методах

Для статических методов `[[HomeObject]]` — сам класс (не `prototype`). `super` в статическом методе обращается к статическим методам родителя:

```js
class Parent {
  static create() { return new this(); }
}

class Child extends Parent {
  static create() {
    console.log('Child.create');
    return super.create(); // Parent.create(), но this === Child
  }
}

Child.create(); // "Child.create", возвращает экземпляр Child
```

### `super` property access vs `super()` call

- **`super()`** — вызов конструктора родителя. Допустим **только** внутри `constructor` derived-класса.
- **`super.prop`** / **`super.method()`** — обращение к свойствам/методам прототипа `[[HomeObject]]`. Допустим в любом методе (instance и static).

```js
class Base {
  constructor() { this.x = 1; }
  getX() { return this.x; }
}

class Derived extends Base {
  test() {
    // super() здесь — SyntaxError (не в конструкторе)
    return super.getX(); // OK — property access
  }
}
```

### `extends` с выражениями

`extends` принимает **любое выражение**, которое возвращает конструктор (или `null`). Это открывает путь к динамическому наследованию:

```js
function getBase(type) {
  return type === 'array' ? Array : Object;
}

class MyCollection extends getBase('array') {
  first() { return this[0]; }
}

const c = new MyCollection(1, 2, 3);
c.first(); // 1 — мы унаследовали Array
```

`extends null` создаёт класс без `Object.prototype` в цепочке прототипов. Однако использовать его нетривиально — конструктор по умолчанию вызовет `super()`, а `null` не конструктор:

```js
class NullProto extends null {
  constructor() {
    // super() — TypeError, потому что null не функция
    return Object.create(new.target.prototype);
  }
}
Object.getPrototypeOf(NullProto.prototype); // null — нет Object.prototype
```

## Приватные поля и методы (`#`)

### Hard private vs WeakMap-based private

До появления `#`-синтаксиса приватность эмулировалась через `WeakMap`:

```js
const _secret = new WeakMap();

class OldWay {
  constructor(val) {
    _secret.set(this, val);
  }
  getSecret() {
    return _secret.get(this);
  }
}
```

Нативные приватные поля (`#`) — это **hard private**. Они не существуют в прототипе, не доступны через `Reflect`, `Object.getOwnPropertyNames`, `Object.keys`, `Proxy` traps. Они хранятся во внутренних слотах экземпляра и проверяются через **brand check** — проверку принадлежности объекта к классу.

```js
class Vault {
  #data;
  #secret;

  constructor(data, secret) {
    this.#data = data;
    this.#secret = secret;
  }

  getData() { return this.#data; }

  static extract(vault) {
    return vault.#secret; // OK — brand check пройден, если vault — экземпляр Vault
  }
}

const v = new Vault('open', 'hidden');
// v.#secret;             // SyntaxError — за пределами класса
// Vault.extract({});     // TypeError — brand check не пройден
Vault.extract(v);         // "hidden"
```

### Brand check

Brand check — это проверка, имеет ли объект конкретный приватный слот. Попытка обратиться к `#field` у объекта, который не является экземпляром данного класса, выбрасывает `TypeError`:

```js
class Token {
  #id;
  constructor(id) { this.#id = id; }

  static isToken(obj) {
    try {
      obj.#id; // Brand check — если #id не существует, TypeError
      return true;
    } catch {
      return false;
    }
  }
}

Token.isToken(new Token(1));  // true
Token.isToken({ id: 1 });     // false
```

Начиная с ES2022, есть более чистый способ — оператор `in` для приватных полей:

```js
class Token {
  #id;
  static isToken(obj) {
    return #id in obj; // Ergonomic brand check
  }
}
```

### Ограничения

- **Нет динамического доступа**: `this['#field']` — это обращение к публичному свойству с именем `"#field"`, а не к приватному полю. Приватные поля доступны **только** через точку: `this.#field`.
- **Нет reflection**: `Object.getOwnPropertyNames()`, `Reflect.ownKeys()`, `Object.getOwnPropertyDescriptors()` — ни один механизм не видит приватные поля.
- **Наследование**: приватные поля **не наследуются**. Подкласс не может обратиться к `#field` родителя напрямую — только через публичные/protected-методы родителя.

```js
class Parent {
  #value = 42;
  getValue() { return this.#value; }
}

class Child extends Parent {
  test() {
    // return this.#value; // SyntaxError — #value принадлежит Parent, не Child
    return this.getValue(); // OK — через публичный метод
  }
}
```

### Приватные методы и accessors

```js
class Account {
  #balance = 0;

  get #formattedBalance() {
    return `$${this.#balance.toFixed(2)}`;
  }

  #validate(amount) {
    if (amount <= 0) throw new RangeError('Amount must be positive');
    if (amount > this.#balance) throw new RangeError('Insufficient funds');
  }

  deposit(amount) {
    if (amount <= 0) throw new RangeError('Amount must be positive');
    this.#balance += amount;
  }

  withdraw(amount) {
    this.#validate(amount);
    this.#balance -= amount;
    return this.#formattedBalance;
  }
}
```

## Статические блоки (`static {}`)

Статические блоки инициализации (`static initialization blocks`, Stage 4, ES2022) позволяют выполнять произвольный код при определении класса. Это решает проблему инициализации сложных статических свойств, которые зависят друг от друга или требуют try/catch.

### Базовое использование

```js
class Config {
  static host;
  static port;

  static {
    try {
      const data = JSON.parse(localStorage.getItem('config') ?? '{}');
      Config.host = data.host ?? 'localhost';
      Config.port = data.port ?? 3000;
    } catch {
      Config.host = 'localhost';
      Config.port = 3000;
    }
  }
}
```

### Доступ к приватным полям

Статический блок выполняется **в контексте класса** и имеет доступ к приватным полям и методам. Это единственный легальный способ "экспортировать" доступ к приватным полям наружу (например, для тестирования или friend-классов):

```js
let getPrivateField;

class Secret {
  #value;

  constructor(v) {
    this.#value = v;
  }

  static {
    // "Friend access" — контролируемая утечка приватности
    getPrivateField = (instance) => instance.#value;
  }
}

const s = new Secret(42);
getPrivateField(s); // 42 — доступ к #value извне класса
```

### Порядок выполнения

Статические блоки выполняются **в порядке объявления**, чередуясь с инициализаторами статических полей:

```js
class Order {
  static a = console.log('field a');
  static { console.log('block 1'); }
  static b = console.log('field b');
  static { console.log('block 2'); }
}
// Вывод:
// field a
// block 1
// field b
// block 2
```

### Несколько static блоков

Класс может содержать **несколько** статических блоков. Каждый имеет свою область видимости, но все работают в контексте класса:

```js
class Registry {
  static #items = new Map();
  static #frozen = false;

  static {
    // Первый блок — инициализация из внешнего источника
    for (const [k, v] of Object.entries(globalDefaults)) {
      Registry.#items.set(k, v);
    }
  }

  static {
    // Второй блок — заморозка после инициализации
    Registry.#frozen = true;
  }
}
```

## Property descriptors в классах

### Методы класса — non-enumerable

Все методы, определённые в теле класса, устанавливаются через `Object.defineProperty` с `enumerable: false`. Это касается как instance-методов (на `prototype`), так и статических методов (на самом классе).

```js
class Example {
  instanceMethod() {}
  static staticMethod() {}
}

const protoDesc = Object.getOwnPropertyDescriptor(Example.prototype, 'instanceMethod');
// { value: [Function], writable: true, enumerable: false, configurable: true }

const staticDesc = Object.getOwnPropertyDescriptor(Example, 'staticMethod');
// { value: [Function], writable: true, enumerable: false, configurable: true }
```

### Почему это критично

`for...in` обходит **enumerable** собственные и наследуемые свойства. Если методы были бы `enumerable`, они появлялись бы в цикле `for...in`:

```js
function OldStyle() { this.data = 1; }
OldStyle.prototype.method = function() {}; // enumerable: true

for (const key in new OldStyle()) {
  console.log(key); // "data", "method" — метод протёк в цикл
}

class NewStyle {
  constructor() { this.data = 1; }
  method() {}
}

for (const key in new NewStyle()) {
  console.log(key); // "data" — только данные, методы скрыты
}
```

### `Object.getOwnPropertyDescriptors()` и классы

При клонировании объектов или миксинах важно использовать `Object.getOwnPropertyDescriptors` для сохранения дескрипторов:

```js
class Source {
  get computed() { return 42; }
}

// Неправильно — getter потеряется, скопируется только значение:
const broken = Object.assign({}, Source.prototype);
// broken.computed === 42, но это уже не getter

// Правильно — сохраняет getter:
const correct = Object.create(
  Object.getPrototypeOf(Source.prototype),
  Object.getOwnPropertyDescriptors(Source.prototype)
);
```

### Свойства в конструкторе vs class fields

Class fields (объявленные в теле класса) создаются на экземпляре с `enumerable: true`, `writable: true`, `configurable: true` — как обычное присваивание в конструкторе:

```js
class Data {
  x = 10;          // class field — enumerable: true
  method() {}      // prototype method — enumerable: false
}

const d = new Data();
Object.keys(d);    // ["x"] — class field виден
```

## Mixins pattern

JavaScript не поддерживает множественное наследование, но миксины реализуются через **функции-обёртки**, возвращающие class expression.

### Базовый паттерн

```js
const Serializable = (Base) => class extends Base {
  serialize() {
    return JSON.stringify(this);
  }

  static deserialize(json) {
    return Object.assign(new this(), JSON.parse(json));
  }
};

const Validatable = (Base) => class extends Base {
  validate() {
    for (const [key, rules] of Object.entries(this.constructor.rules || {})) {
      for (const rule of rules) {
        if (!rule.check(this[key])) {
          throw new Error(`Validation failed for ${key}: ${rule.message}`);
        }
      }
    }
    return true;
  }
};

class User extends Serializable(Validatable(Object)) {
  static rules = {
    name: [{ check: (v) => v?.length > 0, message: 'Name required' }]
  };

  constructor(name) {
    super();
    this.name = name;
  }
}

const u = new User('Alice');
u.validate();                         // true
const json = u.serialize();           // '{"name":"Alice"}'
User.deserialize(json);               // User { name: "Alice" }
```

### Проблема diamond inheritance

Когда два миксина наследуют общий базовый миксин, методы из общего предка дублируются в цепочке прототипов:

```js
const A = (Base) => class extends Base {
  hello() { return 'A'; }
};

const B = (Base) => class extends A(Base) {
  world() { return 'B'; }
};

const C = (Base) => class extends A(Base) {
  foo() { return 'C'; }
};

// A появляется в цепочке прототипов дважды
class D extends B(C(Object)) {}
```

**Решение** — использовать `deduplication` паттерн:

```js
const appliedMixins = new WeakMap();

function mixin(mixinFn) {
  return (Base) => {
    const applied = appliedMixins.get(Base) || new Set();
    if (applied.has(mixinFn)) return Base; // Уже применён
    const result = mixinFn(Base);
    appliedMixins.set(result, new Set([...applied, mixinFn]));
    return result;
  };
}

const SafeA = mixin((Base) => class extends Base {
  hello() { return 'A'; }
});
```

### `Symbol.hasInstance` для корректного `instanceof`

По умолчанию `instanceof` проверяет цепочку прототипов, что не работает с миксинами (экземпляр проверяется против функции-обёртки, а не результирующего класса). `Symbol.hasInstance` позволяет переопределить поведение:

```js
const Loggable = (Base) => {
  class LoggableMixin extends Base {
    log(msg) { console.log(`[${this.constructor.name}] ${msg}`); }
  }

  // Позволяет проверять: instance instanceof Loggable
  // Невозможно напрямую, но можно добавить на функцию-обёртку
  return LoggableMixin;
};

// Паттерн с Symbol.hasInstance:
function createMixin(mixinFactory) {
  const instances = new WeakSet();

  function apply(Base) {
    const Mixed = mixinFactory(Base);
    const originalConstructor = Mixed.prototype.constructor;
    const origNew = Mixed;

    // Оборачиваем для трекинга экземпляров
    const wrapper = class extends Mixed {
      constructor(...args) {
        super(...args);
        instances.add(this);
      }
    };

    Object.defineProperty(apply, Symbol.hasInstance, {
      value: (instance) => instances.has(instance)
    });

    return wrapper;
  }

  return apply;
}

const Loggable2 = createMixin((Base) => class extends Base {
  log(msg) { console.log(msg); }
});

class App extends Loggable2(Object) {}
const app = new App();
console.log(app instanceof Loggable2); // true
```

## Abstract class pattern

JavaScript не имеет ключевого слова `abstract`, но паттерн реализуется через `new.target`:

```js
class AbstractShape {
  constructor() {
    if (new.target === AbstractShape) {
      throw new TypeError('Cannot instantiate abstract class AbstractShape directly');
    }
  }

  // "Абстрактный метод" — выбросит ошибку, если не переопределён
  area() {
    throw new Error(`${this.constructor.name} must implement area()`);
  }

  // Конкретный метод — доступен всем наследникам
  toString() {
    return `${this.constructor.name}(area=${this.area()})`;
  }
}

class Circle extends AbstractShape {
  #radius;
  constructor(radius) {
    super();
    this.#radius = radius;
  }
  area() {
    return Math.PI * this.#radius ** 2;
  }
}

new Circle(5).toString();  // "Circle(area=78.53981633974483)"
new AbstractShape();       // TypeError: Cannot instantiate abstract class
```

### Продвинутая версия: валидация интерфейса в конструкторе

```js
class AbstractRepository {
  constructor() {
    if (new.target === AbstractRepository) {
      throw new TypeError('Abstract class');
    }

    // Проверяем, что подкласс реализовал все обязательные методы
    const required = ['findById', 'save', 'delete'];
    for (const method of required) {
      if (typeof this[method] !== 'function') {
        throw new TypeError(
          `${new.target.name} must implement method ${method}()`
        );
      }
    }
  }
}

class UserRepository extends AbstractRepository {
  findById(id) { /* ... */ }
  save(entity) { /* ... */ }
  // Забыли delete() — TypeError при инстанциировании
}

new UserRepository();
// TypeError: UserRepository must implement method delete()
```

### `new.target` в деталях

`new.target` — мета-свойство, доступное внутри функций и конструкторов. При вызове через `new` оно указывает на конструктор, который был вызван **изначально** (даже если мы находимся в базовом конструкторе, вызванном через `super()`):

```js
class Base {
  constructor() {
    console.log(new.target.name);
  }
}

class Derived extends Base {}

new Base();    // "Base"
new Derived(); // "Derived" — new.target указывает на Derived, не на Base
```

## Наследование built-in классов

### `extends Array`

```js
class TypedArray extends Array {
  #type;

  constructor(type, ...items) {
    super(...items);
    this.#type = type;
    // Валидация типов
    for (const item of this) {
      if (typeof item !== type) {
        throw new TypeError(`Expected ${type}, got ${typeof item}`);
      }
    }
  }

  push(...items) {
    for (const item of items) {
      if (typeof item !== this.#type) {
        throw new TypeError(`Expected ${this.#type}, got ${typeof item}`);
      }
    }
    return super.push(...items);
  }
}

const nums = new TypedArray('number', 1, 2, 3);
nums.push(4);       // OK
nums.push('five');  // TypeError
```

### `extends Error`

Наследование от `Error` важно для custom error classes. До ES6 это было проблематично — `Error` внутри конструктора не устанавливал `stack` trace корректно. С `class` всё работает:

```js
class HttpError extends Error {
  constructor(statusCode, message, options) {
    super(message, options); // options.cause — ES2022
    this.name = 'HttpError';
    this.statusCode = statusCode;
  }

  get isClientError() {
    return this.statusCode >= 400 && this.statusCode < 500;
  }
}

class NotFoundError extends HttpError {
  constructor(resource, options) {
    super(404, `${resource} not found`, options);
    this.name = 'NotFoundError';
  }
}

try {
  throw new NotFoundError('User', { cause: new Error('DB lookup failed') });
} catch (e) {
  console.log(e.name);       // "NotFoundError"
  console.log(e.message);    // "User not found"
  console.log(e.statusCode); // 404
  console.log(e.stack);      // Корректный stack trace
  console.log(e.cause);      // Error: DB lookup failed
}
```

### `Symbol.species`

`Symbol.species` определяет конструктор, который используется при создании производных объектов (например, при вызове `.map()`, `.filter()`, `.slice()` на наследнике `Array`).

**Проблема**: без `Symbol.species` методы-трансформации (`map`, `filter`) возвращают экземпляр **подкласса**, что может быть нежелательно или вызывать ошибки:

```js
class PowerArray extends Array {
  #power;
  constructor(power, ...items) {
    super(...items);
    this.#power = power;
  }

  // Без Symbol.species:
  // const filtered = new PowerArray(2, 1, 2, 3).filter(x => x > 1);
  // filtered — это PowerArray, но #power === undefined (конструктор вызван иначе)
}
```

**Решение**: переопределить `Symbol.species`, чтобы производные методы возвращали базовый `Array`:

```js
class SafePowerArray extends Array {
  #power;
  constructor(power, ...items) {
    super(...items);
    this.#power = power;
  }

  static get [Symbol.species]() {
    return Array; // map(), filter() и т.д. будут возвращать обычный Array
  }

  pow() {
    return this.map(x => x ** this.#power);
    // Вернёт Array, не SafePowerArray
  }
}
```

**Примечание**: `Symbol.species` поддерживается в `Array`, `Map`, `Set`, `RegExp`, `Promise`, `ArrayBuffer`, `TypedArray`. Для `Map` и `Set` он влияет на результат, например, `.filter()` (если реализован подклассом).

### `extends Map`

```js
class DefaultMap extends Map {
  #factory;

  constructor(factory, entries) {
    super(entries);
    this.#factory = factory;
  }

  get(key) {
    if (!this.has(key)) {
      this.set(key, this.#factory(key));
    }
    return super.get(key);
  }
}

const counter = new DefaultMap(() => 0);
counter.set('a', counter.get('a') + 1);
counter.get('a'); // 1
counter.get('b'); // 0 — автоматически создано
```

## Performance

### Hidden classes (V8: Maps)

V8 присваивает каждому объекту **hidden class** (внутренне называется `Map`, не путать с `Map` из JS). Hidden class описывает форму объекта: набор свойств, их типы, смещения в памяти. Объекты одной "формы" разделяют один hidden class, что позволяет V8 кешировать обращения к свойствам (inline caches).

```js
class Point {
  constructor(x, y) {
    this.x = x; // Transition: Map0 -> Map1 (добавлено x)
    this.y = y; // Transition: Map1 -> Map2 (добавлено y)
  }
}

// Все экземпляры Point проходят одинаковые transitions:
const p1 = new Point(1, 2); // Map2
const p2 = new Point(3, 4); // Map2 — тот же hidden class
```

### Monomorphic vs polymorphic vs megamorphic

Inline caches (IC) при обращении к свойствам объектов имеют несколько состояний:

- **Monomorphic** — все объекты в данной точке кода имеют один hidden class. Самый быстрый путь — одно сравнение и прямой доступ по offset.
- **Polymorphic** — 2-4 hidden class. V8 проверяет каждый по цепочке. Ощутимо медленнее.
- **Megamorphic** — 5+ hidden class. V8 переходит к generic dictionary lookup. Катастрофическая деоптимизация.

```js
function getX(obj) {
  return obj.x; // IC здесь
}

class A { constructor() { this.x = 1; } }
class B { constructor() { this.x = 2; } }
class C { constructor() { this.x = 3; } }
class D { constructor() { this.x = 4; } }
class E { constructor() { this.x = 5; } }

// Monomorphic — быстро
for (let i = 0; i < 10000; i++) getX(new A());

// Polymorphic — медленнее
for (let i = 0; i < 10000; i++) getX(i % 2 ? new A() : new B());

// Megamorphic — значительно медленнее
const classes = [A, B, C, D, E];
for (let i = 0; i < 10000; i++) getX(new classes[i % 5]());
```

### Динамическое добавление свойств — деоптимизация

Каждое добавление свойства вне конструктора создаёт новый hidden class transition. Если объекты одного "класса" имеют разные наборы свойств, они получают **разные** hidden class — и код становится polymorphic/megamorphic.

```js
// ПЛОХО — разные hidden class для разных экземпляров
class Bad {
  constructor(options) {
    this.name = options.name;
    if (options.age) this.age = options.age;       // Не у всех будет age
    if (options.email) this.email = options.email;  // Не у всех будет email
  }
}

// ХОРОШО — одинаковый hidden class для всех экземпляров
class Good {
  constructor(options) {
    this.name = options.name;
    this.age = options.age ?? null;      // Всегда присутствует
    this.email = options.email ?? null;  // Всегда присутствует
  }
}
```

### Порядок инициализации свойств

V8 создаёт цепочку transitions на основе **порядка** добавления свойств. Если в двух местах кода свойства добавляются в разном порядке — hidden class не совпадут:

```js
// Разный порядок — разные hidden class
const obj1 = {};
obj1.a = 1;
obj1.b = 2;
// Transition chain: {} -> {a} -> {a, b}

const obj2 = {};
obj2.b = 2;
obj2.a = 1;
// Transition chain: {} -> {b} -> {b, a}

// obj1 и obj2 имеют РАЗНЫЕ hidden class, хотя ключи и значения идентичны
```

**Класс решает эту проблему**: все экземпляры одного класса гарантированно инициализируют свойства в одном порядке (порядке объявления в конструкторе и class fields).

### Class fields vs constructor assignment

Class fields инициализируются **до** тела конструктора, в порядке объявления. Это гарантирует предсказуемый hidden class:

```js
class Optimized {
  x = 0;   // Инициализируется первым
  y = 0;   // Инициализируется вторым
  z = 0;   // Инициализируется третьим

  constructor(x, y, z) {
    // К этому моменту x, y, z уже существуют на объекте
    // Простое переприсвоение НЕ создаёт новый hidden class transition
    this.x = x;
    this.y = y;
    this.z = z;
  }
}
```

### Советы для production

1. **Избегать `delete`** на свойствах объектов — это переводит объект в "dictionary mode" (slow properties), разрушая hidden class. Вместо этого присваивайте `undefined` или `null`.
2. **Не добавлять свойства после конструктора** — определяйте все свойства в конструкторе или как class fields.
3. **Использовать class fields** для предсказуемой формы объекта.
4. **Сохранять мономорфизм** — функции должны работать с объектами одной формы. Если нужно обрабатывать разные типы — используйте явный `switch` или перегрузку, а не полиморфные вызовы.
5. **Не менять прототип после создания** — `Object.setPrototypeOf()` инвалидирует inline caches по всему движку.

```js
// ПЛОХО — delete ломает hidden class
const user = new User('Alice');
delete user.temporaryField;

// ХОРОШО — сохраняет hidden class
const user2 = new User('Alice');
user2.temporaryField = undefined;
```
