## Внутреннее представление

### UTF-16: code units vs code points

JavaScript использует **UTF-16** для внутреннего представления строк. Каждый символ занимает один или два **code unit** (16-битных значения). Символы из Basic Multilingual Plane (BMP, U+0000 — U+FFFF) представлены одним code unit. Символы за пределами BMP (U+10000 и выше) — двумя code units, образующими **суррогатную пару**.

```js
const latin = "A";           // U+0041 — один code unit
const cyrillic = "Я";        // U+042F — один code unit (BMP)
const emoji = "😀";          // U+1F600 — два code units (суррогатная пара)

console.log(latin.length);    // 1
console.log(cyrillic.length); // 1
console.log(emoji.length);    // 2 — .length считает CODE UNITS, не символы!
```

### Суррогатные пары

Символы за пределами BMP кодируются парой: **high surrogate** (U+D800 — U+DBFF) + **low surrogate** (U+DC00 — U+DFFF):

```js
const rocket = "🚀"; // U+1F680

console.log(rocket.charCodeAt(0)); // 55357 (0xD83D) — high surrogate
console.log(rocket.charCodeAt(1)); // 56960 (0xDE80) — low surrogate

// Правильный способ получить code point:
console.log(rocket.codePointAt(0)); // 128640 (0x1F680) — полный code point

// Создание символа из code point:
console.log(String.fromCodePoint(0x1F680)); // "🚀"

// Старый метод НЕ работает с суррогатными парами:
console.log(String.fromCharCode(0x1F680)); // Некорректный символ
```

### Итерация с учётом code points

Оператор `for...of` и spread-оператор корректно обрабатывают суррогатные пары:

```js
const text = "Hi 😀👋";

// НЕПРАВИЛЬНО — посимвольный доступ через индекс
for (let i = 0; i < text.length; i++) {
  console.log(text[i]); // "H", "i", " ", "\uD83D", "\uDE00", "\uD83D", "\uDC4B"
  // Суррогатные пары разорваны!
}

// ПРАВИЛЬНО — for...of итерирует по code points
for (const char of text) {
  console.log(char); // "H", "i", " ", "😀", "👋"
}

// ПРАВИЛЬНО — spread для подсчёта символов
console.log([...text].length); // 5, не 7
```

### Графемные кластеры — ещё один уровень сложности

Даже code points не всегда соответствуют «видимым символам». Некоторые графемы состоят из нескольких code points:

```js
const flag = "🇷🇺"; // Флаг России — два Regional Indicator symbols

console.log(flag.length);       // 4 (две суррогатные пары)
console.log([...flag].length);  // 2 (два code points: 🇷 + 🇺)
// Визуально — 1 символ (графемный кластер)

const accented = "é";  // Может быть 1 code point (U+00E9) или 2 (e + U+0301 combining accent)
console.log("é".length);              // 1 или 2 — зависит от формы
console.log("e\u0301".length);        // 2
console.log("é" === "e\u0301");       // false!
console.log("é".normalize() === "e\u0301".normalize()); // true — NFC нормализация
```

## Иммутабельность

### Строки неизменяемы

В JavaScript строки являются **примитивами** и **не могут быть изменены** после создания. Любая операция над строкой возвращает **новую** строку:

```js
let str = "hello";
str[0] = "H";       // Молча проигнорировано (TypeError в strict mode)
console.log(str);    // "hello" — не изменилась

// Каждая операция создаёт новую строку
let result = str.toUpperCase(); // Новый объект строки "HELLO"
console.log(str);    // "hello" — оригинал не затронут
```

### String Interning в V8

V8 применяет **string interning** (дедупликацию) для строк: одинаковые строковые литералы могут указывать на один и тот же участок памяти:

```js
const a = "hello";
const b = "hello";
// V8 внутренне: a и b указывают на ОДИН объект в памяти (internalized string)

// Это работает и для конкатенации литералов:
const c = "hel" + "lo"; // V8 выполнит constant folding на этапе компиляции → "hello"
```

Interning автоматически применяется к строковым литералам и свойствам объектов. Для динамически созданных строк interning не гарантирован.

### Rope Strings (ConsString) в V8

При конкатенации V8 **не всегда** создаёт новую строку сразу. Вместо этого создаётся **ConsString** — узел дерева, хранящий ссылки на две исходные строки:

```js
let result = "";
for (let i = 0; i < 1000; i++) {
  result += "a"; // V8 создаёт дерево ConsString
}
// Внутренне: ConsString("", ConsString("a", ConsString("a", ...)))
// Физическая строка создаётся (flattening) только когда нужен доступ к содержимому
```

```
ConsString структура:

       ConsString
      /          \
  "hello"    ConsString
            /          \
        " "        "world"

→ При flattening → "hello world"
```

Flattening происходит при:
- Доступе к символу по индексу (`str[i]`)
- Передаче строки в native API
- Вызове методов, требующих последовательного доступа

## Template Literals

### Базовое использование

```js
const name = "Alice";
const age = 30;

// Интерполяция и многострочность
const message = `Привет, ${name}!
Вам ${age} ${age === 1 ? "год" : "лет"}.`;
```

### Tagged Templates

Tagged template — это **вызов функции** с особым синтаксисом. Функция-тег получает массив строковых литералов и подставленные значения:

```js
function tag(strings, ...values) {
  console.log(strings); // ["Hello, ", "! Age: ", ""]
  console.log(values);  // ["Alice", 30]
  return strings.reduce((result, str, i) => {
    return result + str + (values[i] !== undefined ? values[i] : "");
  }, "");
}

const name = "Alice";
const age = 30;
const result = tag`Hello, ${name}! Age: ${age}`;
```

Свойство `strings.raw` содержит строки **без обработки** escape-последовательностей:

```js
function showRaw(strings) {
  console.log(strings[0]);     // "Line1\nLine2" — escape обработан
  console.log(strings.raw[0]); // "Line1\\nLine2" — raw, без обработки
}

showRaw`Line1\nLine2`;
```

### `String.raw`

Встроенный тег, возвращающий raw-строку:

```js
const path = String.raw`C:\Users\new\test`; // "C:\\Users\\new\\test" — \ не escape
console.log(path); // C:\Users\new\test
```

### Практические кастомные теги

**SQL escaping:**

```js
function sql(strings, ...values) {
  const escaped = values.map((val) => {
    if (typeof val === "string") return `'${val.replace(/'/g, "''")}'`;
    if (val === null) return "NULL";
    return String(val);
  });
  return strings.reduce((q, str, i) => q + str + (escaped[i] || ""), "");
}

const userInput = "Robert'; DROP TABLE users; --";
const query = sql`SELECT * FROM users WHERE name = ${userInput}`;
// SELECT * FROM users WHERE name = 'Robert''; DROP TABLE users; --'
```

**HTML sanitization:**

```js
function html(strings, ...values) {
  const escape = (str) =>
    String(str)
      .replace(/&/g, "&amp;")
      .replace(/</g, "&lt;")
      .replace(/>/g, "&gt;")
      .replace(/"/g, "&quot;");

  return strings.reduce((result, str, i) => {
    return result + str + (values[i] !== undefined ? escape(values[i]) : "");
  }, "");
}

const userInput = '<script>alert("XSS")</script>';
const safe = html`<div>${userInput}</div>`;
// <div>&lt;script&gt;alert(&quot;XSS&quot;)&lt;/script&gt;</div>
```

**i18n:**

```js
function i18n(strings, ...values) {
  const key = strings.join("{}");
  const template = translations[currentLocale]?.[key] || key;
  return values.reduce((result, val, i) => result.replace("{}", val), template);
}

const count = 5;
const message = i18n`You have ${count} messages`;
```

## Методы строк

### `at()` — доступ по индексу с поддержкой отрицательных значений

```js
const str = "Hello";

console.log(str.at(0));   // "H"
console.log(str.at(-1));  // "o" — последний символ
console.log(str.at(-2));  // "l"
console.log(str[str.length - 1]); // "o" — старый способ
```

### `slice()` vs `substring()` vs `substr()`

```js
const str = "Hello, World!";

// slice(start, end) — поддерживает отрицательные индексы
str.slice(7, 12);   // "World"
str.slice(-6, -1);  // "World"
str.slice(-6);      // "World!"

// substring(start, end) — НЕ поддерживает отрицательные, меняет местами если start > end
str.substring(7, 12); // "World"
str.substring(12, 7); // "World" — аргументы поменялись местами
str.substring(-3);    // "Hello, World!" — отрицательное стало 0

// substr(start, length) — DEPRECATED, не используйте
str.substr(7, 5);     // "World"
```

**Рекомендация:** всегда используйте `slice()` — он предсказуем и поддерживает отрицательные индексы.

### Padding и Trimming

```js
// padStart / padEnd — дополнение до заданной длины
"42".padStart(5, "0");    // "00042"
"hi".padEnd(10, ".");     // "hi........"
"hello".padStart(3);      // "hello" — уже длиннее, без изменений

// trim / trimStart / trimEnd
"  hello  ".trim();       // "hello"
"  hello  ".trimStart();  // "hello  "
"  hello  ".trimEnd();    // "  hello"
```

### Поиск и проверка

```js
const str = "JavaScript is awesome";

str.startsWith("Java");       // true
str.startsWith("Script", 4);  // true — с позиции 4
str.endsWith("awesome");      // true
str.endsWith("is", 16);       // true — проверяет среди первых 16 символов
str.includes("Script");       // true
str.includes("script");       // false — регистрозависимо
```

### `repeat()` и `replaceAll()`

```js
"abc".repeat(3);              // "abcabcabc"
"abc".repeat(0);              // ""

// replaceAll — замена ВСЕХ вхождений
"a-b-c".replaceAll("-", "_"); // "a_b_c"
"aabaa".replaceAll("aa", "x"); // "xbx" — не перекрывающиеся

// С regex — ОБЯЗАТЕЛЬНО флаг g
"a1b2c3".replaceAll(/\d/g, "X"); // "aXbXcX"
// "a1b2".replaceAll(/\d/, "X"); // TypeError — нужен флаг g
```

### `normalize()` — Unicode нормализация

Четыре формы нормализации:

```js
const e1 = "\u00e9";        // é (precomposed, NFC)
const e2 = "e\u0301";       // é (decomposed, e + combining accent)

console.log(e1 === e2);                          // false
console.log(e1.normalize("NFC") === e2.normalize("NFC"));   // true
console.log(e1.normalize("NFD") === e2.normalize("NFD"));   // true

// NFC  — Canonical Decomposition + Canonical Composition (по умолчанию)
// NFD  — Canonical Decomposition
// NFKC — Compatibility Decomposition + Canonical Composition
// NFKD — Compatibility Decomposition

// NFKC/NFKD «схлопывают» совместимые символы:
"ﬁ".normalize("NFKC"); // "fi" — лигатура разложена
"①".normalize("NFKD"); // "1" — circled digit → обычная цифра
```

## Intl и locale

### `localeCompare()` и `Intl.Collator`

Стандартное сравнение строк (`<`, `>`) сравнивает code units. Для корректной сортировки по языковым правилам нужен `localeCompare`:

```js
const words = ["яблоко", "апельсин", "банан", "Арбуз"];

// Code unit сортировка — неправильная
words.sort(); // ["Арбуз", "апельсин", "банан", "яблоко"] — заглавные отдельно

// Locale-aware сортировка
words.sort((a, b) => a.localeCompare(b, "ru"));
// ["апельсин", "Арбуз", "банан", "яблоко"]
```

Для массовой сортировки `Intl.Collator` **значительно быстрее**, чем повторные вызовы `localeCompare`:

```js
const collator = new Intl.Collator("ru", {
  sensitivity: "base",  // игнорировать регистр и диакритику
  numeric: true,        // "file2" < "file10"
});

const files = ["file10", "file2", "file1", "file20"];
files.sort(collator.compare);
// ["file1", "file2", "file10", "file20"]
```

Опции `sensitivity`:
- `"base"` — A = a = Á = á
- `"accent"` — A = a, Á ≠ a
- `"case"` — A ≠ a, Á = A
- `"variant"` — все различия значимы (по умолчанию)

### `toLocaleLowerCase()` / `toLocaleUpperCase()`

Для некоторых языков стандартный `toLowerCase()` недостаточен:

```js
// Турецкий язык: I → ı (не i)
"I".toLowerCase();                   // "i" — неправильно для турецкого
"I".toLocaleLowerCase("tr");         // "ı" — правильно

// Немецкий: ß → SS при uppercase
"straße".toLocaleUpperCase("de");    // "STRASSE"
```

### `Intl.Segmenter` — итерация по графемам

`Intl.Segmenter` позволяет корректно разбивать строки на **графемные кластеры**, слова или предложения:

```js
const segmenter = new Intl.Segmenter("ru", { granularity: "grapheme" });

const text = "Привет 👨‍👩‍👧‍👦!";

// Emoji "семья" — один графемный кластер, но 7 code points (25 code units!)
console.log(text.length);          // 30+ code units
console.log([...text].length);     // 9+ code points

const segments = [...segmenter.segment(text)];
console.log(segments.length);      // 9 — правильное число графем
segments.forEach((s) => console.log(s.segment));
// "П", "р", "и", "в", "е", "т", " ", "👨‍👩‍👧‍👦", "!"
```

```js
// Сегментация по словам
const wordSegmenter = new Intl.Segmenter("ru", { granularity: "word" });
const words = [...wordSegmenter.segment("Привет, мир!")]
  .filter((s) => s.isWordLike)
  .map((s) => s.segment);

console.log(words); // ["Привет", "мир"]
```

## Performance

### Конкатенация: `+` vs template literals vs `Array.join()`

```js
// Тест 1: простая конкатенация двух строк — практически идентичны
const a = "hello";
const b = "world";

const r1 = a + " " + b;        // V8: быстро, ConsString
const r2 = `${a} ${b}`;        // V8: компилируется в ту же операцию
const r3 = [a, " ", b].join(""); // Медленнее — создание массива + join
```

```js
// Тест 2: конкатенация в цикле
function concatPlus(n) {
  let result = "";
  for (let i = 0; i < n; i++) {
    result += "a"; // V8 создаёт ConsString дерево
  }
  return result;
}

function concatJoin(n) {
  const parts = [];
  for (let i = 0; i < n; i++) {
    parts.push("a"); // Собираем в массив
  }
  return parts.join(""); // Одна аллокация финальной строки
}
```

**Для небольших строк (< 1000):** `+` и template literals примерно одинаковы и обычно быстрее `join()`.

**Для больших строк (> 10 000):** `Array.join()` может быть быстрее, так как избегает глубоких деревьев `ConsString`. Но V8 оптимизирует `+=` через ConsString flattening, поэтому разница не так велика, как в ранних движках.

### Rope Strings Optimization в V8

V8 использует несколько внутренних типов строк:

```
SeqString        — обычная последовательная строка (один буфер)
ConsString       — конкатенация (ссылки на две строки)
SlicedString     — подстрока (ссылка на родительскую строку + offset + length)
ThinString       — интернализированная строка (ссылка на canonical version)
ExternalString   — строка, хранящаяся во внешней памяти (например, из C++)
```

```js
const base = "Hello, World!";
const sub = base.slice(0, 5); // SlicedString — НЕ копирует данные
// sub хранит ссылку на base + offset 0 + length 5

const concat = "foo" + "bar"; // ConsString (или SeqString при constant folding)
```

### String Deduplication

V8 может дедуплицировать строки во время garbage collection (аналогично Java String Deduplication):

```js
// Если множество объектов содержат одинаковые строки:
const users = Array.from({ length: 10000 }, () => ({
  role: "admin", // V8 может дедуплицировать — все указывают на одну строку
}));
```

Для **интернализации** строк вручную можно использовать `Map` или `Set` как пул:

```js
const stringPool = new Map();

function intern(str) {
  if (stringPool.has(str)) return stringPool.get(str);
  stringPool.set(str, str);
  return str;
}

// Все объекты будут ссылаться на ОДНУ строку в памяти
const role = intern("admin");
```

### Сравнение строк

```js
// === для строк — O(n) в худшем случае, но:
// 1. Если строки интернализированы — O(1) сравнение указателей
// 2. Если длины различаются — O(1) ранний выход

const a = "x".repeat(1_000_000);
const b = "x".repeat(1_000_000);

a === b; // O(n) — посимвольное сравнение (разные объекты в памяти)

const c = "hello";
const d = "hello";
c === d; // O(1) — оба интернализированы, сравнение указателей
```
