## Операторы сравнения

### Abstract Equality (`==`) -- алгоритм пошагово

Оператор `==` выполняет **Abstract Equality Comparison** (спецификация ECMA-262, секция 7.2.14). Если типы операндов различаются, происходит неявное приведение типов.

Алгоритм (упрощённо):

1. Если типы одинаковы -- используется `===` (Strict Equality).
2. `null == undefined` -> `true` (и наоборот). Больше ни с чем `null` и `undefined` не равны.
3. Если один операнд -- `Number`, а другой -- `String`, строка приводится к `Number` через `ToNumber`.
4. Если один операнд -- `Boolean`, он приводится к `Number` (`true -> 1`, `false -> 0`), затем сравнение повторяется.
5. Если один операнд -- `Object`, а другой -- примитив, объект приводится через `ToPrimitive` (вызывается `[Symbol.toPrimitive]('number')`, затем `valueOf()`, затем `toString()`).

```js
// Шаг 2: null и undefined
null == undefined;   // true
null == 0;           // false (null НЕ приводится к 0 при ==)
null == '';          // false

// Шаг 3: String -> Number
'5' == 5;            // true, ToNumber('5') === 5
'' == 0;             // true, ToNumber('') === 0

// Шаг 4: Boolean -> Number, затем повтор
true == '1';         // true -> 1, '1' -> 1, 1 === 1
false == '';         // false -> 0, '' -> 0, 0 === 0
false == [];         // false -> 0, [] -> '' -> 0, true!

// Шаг 5: ToPrimitive
[1] == 1;            // [1].toString() -> '1' -> 1
({}) == '[object Object]'; // true
```

**Ловушка с `ToPrimitive`:**

```js
const obj = {
  [Symbol.toPrimitive](hint) {
    console.log(`hint: ${hint}`);
    return hint === 'number' ? 42 : 'hello';
  }
};

obj == 42;    // hint: "number", true (== передаёт hint "number" для ToPrimitive —
              // на самом деле hint "default", который ведёт себя как "number")
`${obj}`;     // hint: "string", "hello"
```

### Strict Equality (`===`)

Никакого приведения типов. Если типы различны -- сразу `false`.

```js
5 === '5';       // false
null === undefined; // false
NaN === NaN;     // false (!!!)
-0 === +0;       // true  (!!!)
```

Два особых случая `===` важно помнить: `NaN` не равен самому себе, а `-0` равен `+0`.

### `Object.is()` -- SameValue

`Object.is()` реализует алгоритм **SameValue** -- самое строгое сравнение в языке:

```js
Object.is(NaN, NaN);   // true  (в отличие от ===)
Object.is(-0, +0);     // false (в отличие от ===)
Object.is(0, -0);      // false
Object.is(null, null);  // true
```

**Когда использовать:** утилитарные функции, полифиллы, внутренние алгоритмы (например, `Map` использует SameValueZero -- как SameValue, но `-0 === +0`).

### Сводная таблица

| Выражение | `==` | `===` | `Object.is()` |
|-----------|------|-------|----------------|
| `NaN, NaN` | `false` | `false` | `true` |
| `-0, +0` | `true` | `true` | `false` |
| `null, undefined` | `true` | `false` | `false` |
| `'', 0` | `true` | `false` | `false` |

## Логические операторы

### `&&`, `||`, `!` возвращают значения, а не boolean

Критически важное понимание: `&&` и `||` возвращают **один из операндов**, а не `true`/`false`.

```js
// || возвращает ПЕРВОЕ truthy значение или ПОСЛЕДНЕЕ значение
0 || '' || null || 'hello' || 42;  // 'hello'
0 || '' || null || undefined;       // undefined (последнее)

// && возвращает ПЕРВОЕ falsy значение или ПОСЛЕДНЕЕ значение
1 && 'hello' && [] && 42;   // 42 (последнее, все truthy)
1 && '' && 42;               // '' (первое falsy)
```

### Short-circuit evaluation

```js
// && не вычисляет правую часть если левая — falsy
false && expensiveOperation(); // expensiveOperation НЕ вызывается

// || не вычисляет правую часть если левая — truthy
true || expensiveOperation();  // expensiveOperation НЕ вызывается

// Идиома: guard
user && user.profile && user.profile.name; // до optional chaining
```

### Nullish Coalescing `??` vs `||`

`||` считает "пустыми" все **falsy** значения: `0`, `''`, `false`, `null`, `undefined`, `NaN`.
`??` считает "пустыми" только `null` и `undefined`.

```js
const port = config.port || 3000;
// Если config.port === 0 — получим 3000 (баг!)

const port = config.port ?? 3000;
// Если config.port === 0 — получим 0 (правильно)

const name = input ?? 'Anonymous';  // '' сохранится как пустая строка
const name = input || 'Anonymous';  // '' заменится на 'Anonymous'
```

**Нельзя смешивать `??` с `&&`/`||` без скобок:**

```js
// SyntaxError: Unexpected token '??'
a || b ?? c;

// Нужно явно указать приоритет
(a || b) ?? c;
a || (b ?? c);
```

### Logical Assignment (`&&=`, `||=`, `??=`)

Введены в ES2021. Каждый совмещает логический оператор с присваиванием.

```js
// ||= присваивает если текущее значение falsy
let title = '';
title ||= 'Untitled'; // 'Untitled'

// ??= присваивает если текущее значение null/undefined
let count = 0;
count ??= 10; // 0 (не перезаписано!)

// &&= присваивает если текущее значение truthy
let user = { name: 'Alice' };
user &&= { ...user, logged: true }; // { name: 'Alice', logged: true }

let user2 = null;
user2 &&= { logged: true }; // null (не перезаписано)
```

**Важно:** `x ??= y` -- это НЕ `x = x ?? y`. Если `x` уже не `null`/`undefined`, присваивание вообще не происходит (setter не вызывается). Это short-circuit на уровне присваивания.

```js
const obj = {
  get value() { return this._value; },
  set value(v) { console.log('SET!'); this._value = v; }
};
obj._value = 42;
obj.value ??= 100; // setter НЕ вызывается, потому что 42 !== null/undefined
```

## Optional Chaining

### Три формы

```js
// 1. Property access
const name = user?.profile?.name;

// 2. Method call
const result = obj.method?.();

// 3. Bracket notation
const value = obj?.[dynamicKey];
const item = arr?.[0];
```

### Short-circuiting

Если левая часть `?.` равна `null` или `undefined`, **вся остальная цепочка не вычисляется**, и возвращается `undefined`:

```js
const x = null?.foo.bar.baz(); // undefined
// .foo, .bar, .baz() — ничего из этого не выполняется!

// Побочные эффекты не происходят:
let called = false;
const result = null?.[getKey(called = true)];
console.log(called); // false
```

### Ограничения

**Нельзя использовать для записи (left-hand side):**

```js
user?.name = 'Alice'; // SyntaxError!

// Правильно:
if (user) {
  user.name = 'Alice';
}
```

**`delete` работает с `?.`:**

```js
delete user?.name; // OK, вернёт true если user == null
```

### `?.` и вызов метода

```js
const obj = {
  greet() { return 'hello'; }
};

obj.greet?.();  // 'hello'
obj.farewell?.(); // undefined (не TypeError!)

// Типичный паттерн — callback:
function process(data, onComplete) {
  // ...
  onComplete?.(result); // вызываем только если передан
}
```

## typeof и instanceof

### `typeof`

```js
typeof 42;          // 'number'
typeof 'hello';     // 'string'
typeof true;        // 'boolean'
typeof undefined;   // 'undefined'
typeof Symbol();    // 'symbol'
typeof 42n;         // 'bigint'
typeof null;        // 'object'  <-- исторический баг с JS 1.0
typeof {};          // 'object'
typeof [];          // 'object'  <-- массив тоже 'object'!
typeof function(){};// 'function' <-- единственный callable отличается
```

**Почему `typeof null === 'object'`:** в первой реализации JS (1995) значения хранились как пара (type tag, value). Объекты имели tag `0`. `null` был представлен как null pointer (`0x00`), и его tag тоже читался как `0`, то есть "object". Это баг, который невозможно исправить из-за обратной совместимости.

**`typeof` и TDZ (Temporal Dead Zone):**

```js
typeof undeclaredVar;  // 'undefined' (не ReferenceError!)
typeof letBeforeInit;  // ReferenceError! (let/const в TDZ)
let letBeforeInit = 1;
```

### `instanceof`

Проверяет, есть ли `Constructor.prototype` в цепочке прототипов объекта.

```js
class Animal {}
class Dog extends Animal {}

const d = new Dog();
d instanceof Dog;    // true
d instanceof Animal; // true
d instanceof Object; // true
```

**Кастомизация через `Symbol.hasInstance`:**

```js
class Even {
  static [Symbol.hasInstance](num) {
    return typeof num === 'number' && num % 2 === 0;
  }
}

4 instanceof Even;  // true
3 instanceof Even;  // false
```

**Проблема с разными realm (iframe, vm):**

```js
// iframe.contentWindow.Array !== window.Array
const arr = iframe.contentWindow.eval('[]');
arr instanceof Array;       // false! (разные конструкторы Array)
Array.isArray(arr);          // true  (работает across realms)
```

**Альтернативы `instanceof`:**

```js
// Array
Array.isArray(value);

// Duck typing
function isPromiseLike(obj) {
  return obj && typeof obj.then === 'function';
}

// Symbol.toStringTag
Object.prototype.toString.call(value); // '[object Array]', '[object Map]', ...
```

## Spread и Rest

### Spread в массивах

```js
const a = [1, 2, 3];
const b = [0, ...a, 4]; // [0, 1, 2, 3, 4]

// Shallow copy
const copy = [...a];
copy === a; // false (новый массив)
copy[0] === a[0]; // true (элементы — те же ссылки для объектов)
```

### Spread в объектах

```js
const defaults = { theme: 'light', lang: 'en', debug: false };
const userPrefs = { theme: 'dark', fontSize: 14 };

// Порядок merge: последний побеждает
const config = { ...defaults, ...userPrefs };
// { theme: 'dark', lang: 'en', debug: false, fontSize: 14 }

// Эквивалентно Object.assign({}, defaults, userPrefs), но создаёт новый объект
```

**Shallow copy -- вложенные объекты НЕ копируются:**

```js
const original = { a: 1, nested: { b: 2 } };
const clone = { ...original };
clone.nested.b = 99;
console.log(original.nested.b); // 99 (та же ссылка!)
```

### Rest в деструктуризации

```js
const { id, ...rest } = { id: 1, name: 'Alice', age: 30 };
// id === 1, rest === { name: 'Alice', age: 30 }

const [first, ...remaining] = [1, 2, 3, 4];
// first === 1, remaining === [2, 3, 4]
```

### Rest параметры функций

```js
function sum(...numbers) {
  return numbers.reduce((acc, n) => acc + n, 0);
}
sum(1, 2, 3); // 6

// Rest должен быть последним
function f(a, b, ...rest) {} // OK
function f(...rest, a) {}    // SyntaxError!
```

### Spread работает только с итерируемыми объектами (для массивов)

```js
// Массивы, строки, Set, Map — итерируемые
[...'hello'];        // ['h', 'e', 'l', 'l', 'o']
[...new Set([1,2,2,3])]; // [1, 2, 3]

// Обычные объекты — НЕ итерируемые (spread в массив не работает)
[...{ a: 1 }];       // TypeError: object is not iterable

// Но spread в объект работает для ЛЮБОГО объекта:
({ ...{ a: 1 } });   // { a: 1 }
```

**Spread для вызова функции:**

```js
const args = [1, 2, 3];
Math.max(...args); // 3  (вместо Math.max.apply(null, args))
```

## Побитовые операторы

Все побитовые операторы (кроме `>>>`) работают с 32-битными **знаковыми** целыми (int32). Операнды приводятся через `ToInt32`.

### Базовые операторы

```js
// AND — оба бита должны быть 1
5 & 3;    // 0101 & 0011 = 0001 = 1

// OR — хотя бы один бит 1
5 | 3;    // 0101 | 0011 = 0111 = 7

// XOR — биты различаются
5 ^ 3;    // 0101 ^ 0011 = 0110 = 6

// NOT — инверсия всех бит (результат: -(x+1))
~5;       // -6
~-1;      // 0

// Left shift
5 << 1;   // 0101 << 1 = 1010 = 10 (умножение на 2)

// Signed right shift (сохраняет знак)
-8 >> 2;  // -2

// Unsigned right shift (заполняет нулями)
-1 >>> 0; // 4294967295 (0xFFFFFFFF, max uint32)
```

### Практическое применение

**Флаги и битовые маски (система прав):**

```js
const READ    = 0b0001; // 1
const WRITE   = 0b0010; // 2
const EXECUTE = 0b0100; // 4
const ADMIN   = 0b1000; // 8

let permissions = READ | WRITE; // 0b0011 = 3

// Проверка: имеет ли право
(permissions & READ) !== 0;     // true
(permissions & EXECUTE) !== 0;  // false

// Добавить право
permissions |= EXECUTE;  // 0b0111 = 7

// Убрать право
permissions &= ~WRITE;   // 0b0101 = 5

// Переключить (toggle)
permissions ^= ADMIN;    // 0b1101 = 13
```

**Быстрые математические трюки:**

```js
// ~~x — быстрый Math.trunc() для чисел в диапазоне int32
~~4.9;    // 4
~~-4.9;   // -4

// | 0 — аналогично
4.9 | 0;  // 4

// Проверка чётности
n & 1;    // 0 если чётное, 1 если нечётное

// Умножение/деление на степени двойки
x << 3;   // x * 8
x >> 2;   // Math.trunc(x / 4) для положительных

// Swap без временной переменной (XOR swap)
a ^= b; b ^= a; a ^= b;
```

**Внимание:** `~~x` и `| 0` обрезают число до 32 бит. Для чисел больше `2^31 - 1` или меньше `-2^31` результат будет неверным:

```js
~~2147483648;    // -2147483648 (overflow!)
~~NaN;           // 0
~~Infinity;      // 0
```

### `BigInt` и побитовые

`BigInt` поддерживает побитовые операторы, но **нельзя смешивать** `BigInt` и `Number`:

```js
5n & 3n;  // 1n
5n | 3n;  // 7n
~5n;      // -6n

5n & 3;   // TypeError: Cannot mix BigInt and other types
```

## Оператор `in`

### Проверка свойств (включая прототипы)

```js
const obj = { a: 1, b: undefined };

'a' in obj;       // true
'b' in obj;       // true  (свойство существует, даже если значение undefined!)
'c' in obj;       // false

'toString' in obj; // true (из прототипа Object.prototype)
```

**Отличие от проверки через `obj.prop !== undefined`:**

```js
const obj = { key: undefined };
obj.key !== undefined;  // false (думаем, свойства нет)
'key' in obj;           // true  (свойство есть!)

// Для проверки собственных свойств:
obj.hasOwnProperty('key');            // true
Object.prototype.hasOwnProperty.call(obj, 'key'); // безопаснее
Object.hasOwn(obj, 'key');            // ES2022, рекомендуется
```

### `in` с массивами -- проверяет ИНДЕКСЫ, не значения

```js
const arr = [10, 20, 30];

0 in arr;    // true  (индекс 0 существует)
3 in arr;    // false (индекса 3 нет)
10 in arr;   // false (нет индекса 10, 10 — это значение!)

// Разреженные массивы
const sparse = [1, , 3]; // элемент с индексом 1 отсутствует
1 in sparse; // false!
```

### Private field brand check (ES2022)

```js
class Color {
  #value;
  constructor(v) { this.#value = v; }

  static isColor(obj) {
    // Brand check: проверяет наличие приватного поля
    return #value in obj;
  }
}

Color.isColor(new Color('red')); // true
Color.isColor({ value: 'red' }); // false
```

Это единственный способ проверить наличие приватного поля извне — попытка обратиться к `obj.#value` вне класса вызывает `SyntaxError`.

## Comma, void, delete

### Comma operator

Вычисляет оба операнда слева направо и возвращает **значение правого**.

```js
const x = (1, 2, 3); // 3

// В циклах for:
for (let i = 0, j = 10; i < j; i++, j--) {
  console.log(i, j);
}

// В стрелочных функциях (сомнительная практика):
const tap = (x) => (console.log(x), x);
tap(42); // логирует 42, возвращает 42
```

**Внимание:** запятая в `let a = 1, b = 2` -- это НЕ comma operator, это часть синтаксиса объявления переменных.

### `void`

Вычисляет выражение и возвращает `undefined`.

```js
void 0;          // undefined
void 'hello';   // undefined
void fn();       // вызывает fn(), возвращает undefined

// Зачем?
// 1. Гарантированный undefined (до ES5 window.undefined можно было перезаписать)
void 0 === undefined; // true всегда

// 2. IIFE без присваивания
void function() {
  // ...
}();

// 3. В href для предотвращения навигации (устаревшее)
// <a href="javascript:void(0)">Click</a>

// 4. Подавление возврата значения в стрелочных функциях
const sideEffect = () => void doSomething();
// Вернёт undefined, даже если doSomething возвращает что-то
```

### `delete`

Удаляет свойство из объекта. Возвращает `true` при успешном удалении или если свойства не существовало, `false` если свойство non-configurable.

```js
const obj = { a: 1, b: 2 };
delete obj.a;  // true
obj;           // { b: 2 }

// Non-configurable свойства
delete Math.PI;    // false (strict mode: TypeError)

// Нельзя удалить переменные
let x = 1;
delete x;          // false (strict mode: SyntaxError)
```

**Deoptimization в V8 (скрытые классы / hidden classes):**

Когда V8 оптимизирует объект, он создаёт **hidden class** (внутреннюю "форму" или "shape"). `delete` меняет shape объекта и переключает его в **dictionary mode** (медленный доступ к свойствам):

```js
function createUser(name, age) {
  const user = { name, age, email: '' };
  delete user.email; // V8 переключает объект в slow mode!
  return user;
}

// Лучше:
function createUser(name, age) {
  return { name, age }; // не добавляем email вообще
  // или:
  return { name, age, email: undefined }; // undefined вместо delete
}
```

**`delete` возвращает `true` для несуществующих свойств:**

```js
const obj = {};
delete obj.nonexistent; // true (свойства и так нет, "удаление" успешно)
```

**`delete` и массивы -- создаёт дырки:**

```js
const arr = [1, 2, 3];
delete arr[1];
console.log(arr);       // [1, empty, 3]
console.log(arr.length); // 3 (длина НЕ меняется!)
1 in arr;                // false

// Используйте splice для "правильного" удаления:
arr.splice(1, 1);       // [1, 3], length === 2
```

## Приоритет операторов (ключевые моменты)

Запоминать всю таблицу приоритетов нет смысла -- используйте скобки для ясности. Но некоторые моменты важны:

```js
// ?? имеет ОЧЕНЬ низкий приоритет
a + b ?? c;  // (a + b) ?? c, не a + (b ?? c)

// ?. имеет высокий приоритет
a?.b.c;      // (a?.b).c — если a === null, дальше TypeError!
// Правильно: a?.b?.c

// typeof имеет приоритет выше сравнения
typeof x === 'string'; // (typeof x) === 'string' — правильно парсится

// Присваивание правоассоциативно
a = b = c = 5; // a = (b = (c = 5))
```
