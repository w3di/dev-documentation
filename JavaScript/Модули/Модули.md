## ES Modules vs CommonJS

### Фундаментальное различие: статический vs динамический

**ES Modules (ESM)** анализируются **статически на этапе парсинга**, до выполнения кода. Движок строит полный граф зависимостей ещё до того, как выполнится первая строка.

**CommonJS (CJS)** — `require()` это обычная функция, которая выполняется **в рантайме**. Зависимости разрешаются в момент вызова `require()`.

```js
// ESM — статический импорт: движок знает зависимости до выполнения
import { readFile } from 'node:fs/promises';

// CJS — динамический: require выполняется как обычный вызов функции
const { readFile } = require('fs/promises');

// CJS позволяет условный require — ESM статический import так не может
if (process.env.NODE_ENV === 'test') {
  const mock = require('./mock'); // работает в CJS
}

// В ESM для условной загрузки используется dynamic import():
let mock;
if (process.env.NODE_ENV === 'test') {
  mock = await import('./mock.js'); // dynamic import — runtime
}
```

### `import` hoisting

Все декларации `import` **поднимаются** в начало модуля. Независимо от того, где вы их написали, они выполняются первыми:

```js
console.log('start');      // (2) — выполняется после импорта
import { value } from './mod.js'; // (1) — hoisted, выполняется первым
console.log(value);        // (3)

// Эквивалентно:
import { value } from './mod.js';
console.log('start');
console.log(value);
```

### Live bindings vs Value copy

Это **критически важное** различие:

```js
// === counter.mjs (ESM) ===
export let count = 0;
export function increment() { count++; }

// === main.mjs (ESM) ===
import { count, increment } from './counter.mjs';
console.log(count);   // 0
increment();
console.log(count);   // 1 — live binding! Мы видим изменение

// =========================================

// === counter.cjs (CommonJS) ===
let count = 0;
function increment() { count++; }
module.exports = { count, increment };

// === main.cjs (CommonJS) ===
const { count, increment } = require('./counter.cjs');
console.log(count);   // 0
increment();
console.log(count);   // 0 — копия значения! Изменение в модуле не видно

// Чтобы обойти в CJS, нужен getter или объект-обёртка:
// module.exports = { get count() { return count; }, increment };
```

В ESM `import` создаёт **привязку (binding)** к переменной в экспортирующем модуле — как ссылка на ячейку памяти. В CJS `require` копирует **значения** свойств `module.exports` в момент вызова.

### Tree-shaking возможен только с ESM

Поскольку ESM-импорты статические, бандлеры (webpack, Rollup, esbuild) могут определить на этапе сборки, какие экспорты **реально используются**, и удалить мёртвый код:

```js
// utils.mjs
export function used() { return 42; }
export function unused() { return 'мёртвый код'; }

// main.mjs
import { used } from './utils.mjs';
console.log(used());
// Бандлер удалит unused() из финального бандла

// С CJS tree-shaking невозможен:
const utils = require('./utils');
// Бандлер не может гарантировать, что utils.unused не вызывается
// где-то через динамический доступ: utils[someVariable]
```

### `this` в модулях

```js
// ESM: this на верхнем уровне === undefined
console.log(this); // undefined

// CJS: this на верхнем уровне === module.exports
console.log(this === module.exports); // true (в начале файла)
```

### Strict mode

ESM **всегда** выполняется в strict mode. Не нужно писать `'use strict'`. CJS по умолчанию выполняется в sloppy mode.

## Named vs Default exports

### Почему `named exports` лучше для tree-shaking

Named exports позволяют бандлеру точно знать, **что именно импортируется**:

```js
// math.mjs
export function add(a, b) { return a + b; }
export function subtract(a, b) { return a - b; }
export function multiply(a, b) { return a * b; }

// main.mjs — бандлер видит, что нужен только add
import { add } from './math.mjs';

// С default export — бандлер получает весь объект
// math-default.mjs
export default {
  add(a, b) { return a + b; },
  subtract(a, b) { return a - b; },
  multiply(a, b) { return a * b; },
};

// main.mjs — бандлер не может определить, какие методы используются
import math from './math-default.mjs';
math.add(1, 2); // бандлер не может удалить subtract и multiply
```

### `export { x as default }`

`default export` — это, по сути, named export с именем `default`:

```js
function myFunc() {}

// Эти два варианта полностью эквивалентны:
export default myFunc;
export { myFunc as default };

// При импорте:
import myFunc from './mod.js';
// Это сахар для:
import { default as myFunc } from './mod.js';
```

### Re-exports

Переэкспорт позволяет создавать «агрегирующие» модули:

```js
// Именованный реэкспорт
export { foo, bar } from './mod-a.js';

// Реэкспорт с переименованием
export { foo as renamedFoo } from './mod-a.js';

// Реэкспорт всех named exports (НЕ включает default!)
export * from './mod-b.js';

// Реэкспорт default
export { default } from './mod-c.js';

// Реэкспорт default как named
export { default as ModC } from './mod-c.js';

// Реэкспорт всего, включая default (ES2020):
export * as ns from './mod-d.js';
// Создаёт namespace: import { ns } from '...' — ns.default, ns.foo, etc.
```

Важное поведение `export *`: если два модуля экспортируют одно и то же имя, возникает **неявный конфликт** — ни один из них не будет реэкспортирован (без ошибки!):

```js
// a.js: export const x = 1;
// b.js: export const x = 2;

// barrel.js
export * from './a.js';
export * from './b.js';

// main.js
import { x } from './barrel.js'; // SyntaxError: ambiguous star export 'x'
```

### Namespace import

```js
import * as utils from './utils.mjs';

// utils — это Module Namespace Object
// Он frozen (Object.isFrozen(utils) === true), но значения — live bindings
utils.count; // live binding — обновляется при изменении в модуле
utils.foo = 1; // TypeError: Cannot assign to read only property

// typeof utils === 'object'
// utils[Symbol.toStringTag] === 'Module'
```

## Dynamic import()

### Основы

`import()` — это **оператор** (не функция), который возвращает `Promise<Module>`:

```js
// Возвращает Promise, который резолвится в Module Namespace Object
const module = await import('./heavy-module.js');
module.default;    // default export
module.namedExport; // named export
```

### Code splitting

Dynamic import — основа для разделения кода (code splitting) в бандлерах:

```js
// Webpack создаёт отдельный chunk для каждого dynamic import
const routes = {
  '/dashboard': () => import('./pages/Dashboard.js'),
  '/settings': () => import('./pages/Settings.js'),
  '/profile': () => import('./pages/Profile.js'),
};

async function navigate(path) {
  const loader = routes[path];
  if (!loader) {
    const { NotFound } = await import('./pages/NotFound.js');
    return render(NotFound);
  }
  const page = await loader();
  render(page.default);
}
```

### Conditional loading

```js
// Загрузка полифилла только если нужен
if (!globalThis.structuredClone) {
  const { default: polyfill } = await import('structured-clone-polyfill');
  globalThis.structuredClone = polyfill;
}

// Загрузка зависимости только для определённой платформы
const os = await import('node:os');
let fsModule;
if (os.platform() === 'win32') {
  fsModule = await import('./fs-windows.js');
} else {
  fsModule = await import('./fs-posix.js');
}
```

### `import.meta`

Объект `import.meta` содержит метаданные о текущем модуле:

```js
// import.meta.url — URL текущего модуля (всегда file:// или https://)
console.log(import.meta.url);
// Node.js: file:///Users/dev/project/src/app.mjs
// Браузер: https://example.com/js/app.mjs

// Получение __dirname и __filename в ESM (аналоги CJS):
import { fileURLToPath } from 'node:url';
import { dirname } from 'node:path';

const __filename = fileURLToPath(import.meta.url);
const __dirname = dirname(__filename);

// import.meta.resolve() — разрешает спецификатор модуля в полный URL
const resolvedPath = import.meta.resolve('./config.json');
// 'file:///Users/dev/project/src/config.json'

// import.meta.resolve() для bare specifiers
const lodashPath = import.meta.resolve('lodash');
// Разрешит путь по алгоритму Node.js module resolution
```

### Top-level await (ES2022)

Позволяет использовать `await` на верхнем уровне ESM-модуля, **без оборачивания в `async` функцию**:

```js
// config.mjs
const response = await fetch('/api/config');
export const config = await response.json();

// main.mjs
import { config } from './config.mjs';
// Этот модуль не начнёт выполняться, пока config.mjs полностью не завершится
// (включая все его await)
console.log(config.apiUrl);
```

Top-level await **блокирует** выполнение всех модулей, которые зависят от данного. Используйте осторожно — это может замедлить начальную загрузку:

```js
// slow.mjs
await new Promise(r => setTimeout(r, 5000)); // 5 секунд
export const ready = true;

// main.mjs
import { ready } from './slow.mjs'; // будет ждать 5 секунд!
```

Движок оптимизирует: модули, **не зависящие** от модуля с top-level await, выполняются параллельно.

## Module resolution

### Типы спецификаторов

```js
// 1. Relative specifiers — начинаются с ./ или ../
import { x } from './utils.js';
import { y } from '../lib/helpers.js';

// 2. Absolute specifiers — полный URL
import { z } from 'file:///opt/lib/mod.js';
import { w } from 'https://cdn.example.com/lib.js';

// 3. Bare specifiers — имя пакета (требуют resolution algorithm)
import { v } from 'lodash-es';
import { readFile } from 'node:fs/promises';  // node: протокол для built-in модулей
```

В браузерах bare specifiers **не работают** без Import Maps. Node.js разрешает их через `node_modules`.

### Import Maps (браузер)

Позволяют браузеру понимать bare specifiers:

```html
<script type="importmap">
{
  "imports": {
    "lodash": "https://cdn.skypack.dev/lodash-es",
    "react": "https://esm.sh/react@18",
    "@app/": "./src/",
    "#internal/": "./src/internal/"
  },
  "scopes": {
    "/vendor/": {
      "lodash": "https://cdn.skypack.dev/lodash-es@3"
    }
  }
}
</script>

<script type="module">
  // Теперь работают bare specifiers:
  import _ from 'lodash';
  import { useState } from 'react';
  import { api } from '@app/services/api.js';
</script>
```

### `package.json` `exports` field

Поле `exports` (Node.js 12.11+) заменяет `main` и предоставляет **encapsulation** — потребители не могут импортировать внутренние файлы:

```json
{
  "name": "my-lib",
  "type": "module",
  "exports": {
    ".": {
      "import": "./dist/esm/index.js",
      "require": "./dist/cjs/index.cjs",
      "types": "./dist/types/index.d.ts"
    },
    "./utils": {
      "import": "./dist/esm/utils.js",
      "require": "./dist/cjs/utils.cjs"
    },
    "./package.json": "./package.json"
  }
}
```

```js
import { something } from 'my-lib';        // -> ./dist/esm/index.js
import { helper } from 'my-lib/utils';     // -> ./dist/esm/utils.js
import { internal } from 'my-lib/src/foo'; // ERROR — не описано в exports!
```

**Conditional exports** — разные точки входа для разных условий:

```json
{
  "exports": {
    ".": {
      "node": {
        "import": "./dist/node-esm.js",
        "require": "./dist/node-cjs.cjs"
      },
      "browser": "./dist/browser.js",
      "default": "./dist/index.js"
    }
  }
}
```

### `"type": "module"` в `package.json`

Определяет, как Node.js интерпретирует `.js` файлы в пакете:

```json
// package.json
{ "type": "module" }
// Теперь все .js файлы — ESM
// Для CJS используйте расширение .cjs

{ "type": "commonjs" } // или отсутствие поля
// Все .js файлы — CJS
// Для ESM используйте расширение .mjs
```

Расширения `.mjs` и `.cjs` **всегда** имеют приоритет над `"type"` и работают однозначно.

## Циклические зависимости

### Как ESM обрабатывает циклы

Благодаря **live bindings** ESM корректно работает с циклическими зависимостями. Модули проходят три фазы: **Construction** (парсинг, построение графа), **Instantiation** (выделение памяти для bindings), **Evaluation** (выполнение кода):

```js
// === a.mjs ===
import { b } from './b.mjs';
export const a = 'A';
console.log('a.mjs:', b); // 'B' — к этому моменту b.mjs уже выполнился

// === b.mjs ===
import { a } from './a.mjs';
export const b = 'B';
console.log('b.mjs:', a); // undefined! a.mjs ещё не выполнился до этой строки
```

Порядок выполнения (depth-first, post-order):
1. Начинаем с `a.mjs`
2. `a.mjs` импортирует `b.mjs` — идём в `b.mjs`
3. `b.mjs` импортирует `a.mjs` — цикл обнаружен, используем **текущее состояние bindings** из `a.mjs`
4. Выполняется тело `b.mjs`: `a` ещё не инициализирована (`undefined` для `const` до TDZ, а точнее `TDZ` ошибка если обращение до `export const`)
5. Возвращаемся к выполнению `a.mjs`: `b` уже инициализирована

**Важный нюанс с `let`/`const` и TDZ:**

```js
// === a.mjs ===
import { getB } from './b.mjs';
export const a = 'A';
console.log(getB()); // 'B' — вызов после инициализации b, работает

// === b.mjs ===
import { a } from './a.mjs';
export const b = 'B';
export function getB() { return b; } // function declaration поднимается
console.log(a); // ReferenceError! a ещё в TDZ
```

### Как CJS ломается при циклах

CommonJS при обнаружении цикла возвращает **частично заполненный** `module.exports`:

```js
// === a.cjs ===
console.log('a.cjs начал загрузку');
exports.done = false;
const b = require('./b.cjs'); // идём в b.cjs
console.log('в a.cjs, b.done =', b.done); // true
exports.done = true;
console.log('a.cjs завершил загрузку');

// === b.cjs ===
console.log('b.cjs начал загрузку');
exports.done = false;
const a = require('./a.cjs'); // цикл! Получаем ЧАСТИЧНЫЙ exports из a.cjs
console.log('в b.cjs, a.done =', a.done); // false — a.cjs ещё не дошёл до exports.done = true
exports.done = true;
console.log('b.cjs завершил загрузку');

// Вывод:
// a.cjs начал загрузку
// b.cjs начал загрузку
// в b.cjs, a.done = false    <-- получили неполные exports
// b.cjs завершил загрузку
// в a.cjs, b.done = true
// a.cjs завершил загрузку
```

### Как избегать циклических зависимостей

```js
// 1. Выделить общий код в третий модуль
// Вместо A <-> B:
// A -> C <- B

// 2. Dependency Injection
// Вместо прямого импорта, передавать зависимость как параметр:
// a.mjs
export function createA(b) {
  return { doSomething: () => b.help() };
}

// 3. Lazy import через dynamic import()
// a.mjs
export async function doWork() {
  const { helper } = await import('./b.mjs'); // разрывает цикл на этапе парсинга
  return helper();
}

// 4. Медиатор / Event Bus
// Вместо прямых вызовов между модулями, общение через центральный EventEmitter
```

## Module evaluation

### Модули выполняются один раз и кэшируются

При повторном `import` одного модуля из разных мест код **не выполняется повторно**. Движок хранит результат в **Module Map**:

```js
// counter.mjs
console.log('counter.mjs evaluated');  // выведется ОДИН раз
let count = 0;
export function increment() { return ++count; }

// a.mjs
import { increment } from './counter.mjs'; // первый импорт — evaluation
console.log(increment()); // 1

// b.mjs
import { increment } from './counter.mjs'; // повторный — из кэша
console.log(increment()); // 2 (не 1! — состояние общее)

// main.mjs
import './a.mjs';
import './b.mjs';
// Лог: "counter.mjs evaluated" (только один раз)
// Лог: 1
// Лог: 2
```

### Module Map

**Module Map** — это внутренняя структура (per-realm), которая сопоставляет **URL модуля** с его Module Record. Ключ — полный разрешённый URL:

```js
// Это ДВА разных модуля в Module Map (разные URL):
import './utils.js';
import './Utils.js'; // на case-sensitive FS — другой файл и другой entry

// Это ОДИН модуль (один URL после resolution):
import './utils.js';
import '../src/utils.js'; // если резолвится в тот же абсолютный путь — кэш
```

В CJS аналог — `require.cache`, но его **можно очищать**:

```js
// CJS: можно сбросить кэш (используется в тестах, но это хак)
delete require.cache[require.resolve('./module.cjs')];
const fresh = require('./module.cjs'); // re-evaluation

// ESM: Module Map недоступен для пользовательского кода
// Единственный способ «перезагрузить» — добавить query string:
const m1 = await import('./mod.js?v=1');
const m2 = await import('./mod.js?v=2'); // другой URL = другой entry в Module Map
```

### Порядок выполнения: depth-first post-order

```js
// main.mjs
import './a.mjs';
import './b.mjs';

// a.mjs
import './c.mjs';
console.log('a');

// b.mjs
import './c.mjs';
console.log('b');

// c.mjs
console.log('c');

// Порядок выполнения (depth-first, post-order):
// 1. main.mjs начинает, встречает import './a.mjs'
// 2. a.mjs начинает, встречает import './c.mjs'
// 3. c.mjs выполняется: "c"
// 4. a.mjs продолжает: "a"
// 5. main.mjs встречает import './b.mjs'
// 6. b.mjs начинает, встречает import './c.mjs' — уже в кэше, пропускаем
// 7. b.mjs продолжает: "b"
// Итог: c, a, b
```

### Side effects в модулях

Код на верхнем уровне модуля — это **side effect**. Бандлеры по умолчанию считают все модули имеющими side effects:

```js
// side-effect модуль — изменяет глобальное состояние при импорте
import './polyfill.js'; // добавляет методы к прототипам
import './analytics.js'; // инициализирует трекинг

// package.json: sideEffects field для tree-shaking
{
  "sideEffects": false  // НИЧЕГО в пакете не имеет side effects — можно смело удалять неиспользуемое
}

{
  "sideEffects": [
    "*.css",           // CSS-импорты — всегда side effect
    "./src/polyfill.js" // этот файл имеет side effects, остальные — нет
  ]
}
```

## Паттерны

### Barrel files (index.js re-exports)

Barrel — файл, который реэкспортирует из нескольких модулей, предоставляя единую точку входа:

```js
// components/index.js (barrel)
export { Button } from './Button.js';
export { Input } from './Input.js';
export { Modal } from './Modal.js';
export { Dropdown } from './Dropdown.js';
export { Table } from './Table.js';

// Использование — удобный импорт:
import { Button, Input } from './components';

// Без barrel — каждый компонент импортируется отдельно:
import { Button } from './components/Button.js';
import { Input } from './components/Input.js';
```

### Проблемы barrel files с tree-shaking

```js
// components/index.js
export { Button } from './Button.js';       // 2 KB
export { DataGrid } from './DataGrid.js';   // 200 KB с зависимостями

// page.js — нужен только Button
import { Button } from './components';

// ПРОБЛЕМА: бандлер загружает index.js, который импортирует ВСЕ модули.
// Если DataGrid.js имеет side effects при импорте (например, регистрирует
// глобальные обработчики), бандлер не может его удалить.

// Даже без side effects, barrel замедляет dev-сервер:
// Vite/webpack-dev-server должны распарсить ВСЕ модули,
// на которые ссылается barrel, чтобы найти нужный экспорт.
```

**Решения:**

```js
// 1. Прямые импорты в production-критичном коде
```

### Lazy initialization в модулях

Модуль выполняется при первом импорте. Для тяжёлой инициализации можно откладывать:

```js
// ПРОБЛЕМА: тяжёлая инициализация при импорте
// db.mjs
import { createPool } from 'mysql2/promise';
export const pool = createPool({  // создаётся СРАЗУ при первом import
  host: 'localhost',
  database: 'app',
});

// РЕШЕНИЕ: lazy initialization
// db.mjs
import { createPool } from 'mysql2/promise';

let pool;
export function getPool() {
  if (!pool) {
    pool = createPool({
      host: 'localhost',
      database: 'app',
    });
  }
  return pool;
}

// Или через class с lazy getter:
class Database {
  #pool;

  get pool() {
    if (!this.#pool) {
      this.#pool = createPool({ host: 'localhost', database: 'app' });
    }
    return this.#pool;
  }
}

export const db = new Database();
```

### Module-level state (singleton pattern)

Поскольку модули кэшируются, переменные на верхнем уровне модуля образуют **singleton**:

```js
// store.mjs — module-level state = singleton
const state = new Map();

export function get(key) {
  return state.get(key);
}

export function set(key, value) {
  state.set(key, value);
}

// Любой модуль, который импортирует store.mjs, работает с ТЕМ ЖЕ Map.
// Это удобно, но создаёт проблемы при тестировании — состояние «протекает» между тестами.
```

```js
// Singleton через class (более явный):
// logger.mjs
class Logger {
  #level = 'info';
  #transports = [];

  setLevel(level) { this.#level = level; }
  addTransport(transport) { this.#transports.push(transport); }

  log(level, message) {
    if (this.#shouldLog(level)) {
      for (const transport of this.#transports) {
        transport.write({ level, message, timestamp: Date.now() });
      }
    }
  }

  #shouldLog(level) {
    const levels = ['debug', 'info', 'warn', 'error'];
    return levels.indexOf(level) >= levels.indexOf(this.#level);
  }
}

// Один экземпляр на всё приложение
export const logger = new Logger();

// Для тестируемости — экспортируем и класс:
export { Logger };
```

### Проблемы singleton-модулей при тестировании

```js
// Решение: фабрика + singleton обёртка
// store.mjs
export function createStore(initialState = {}) {
  const state = { ...initialState };
  return {
    get(key) { return state[key]; },
    set(key, value) { state[key] = value; },
    clear() { for (const key in state) delete state[key]; },
  };
}

// Singleton для production:
export const store = createStore();

// В тестах — создаём свежий экземпляр:
// store.test.mjs
import { createStore } from './store.mjs';

let store;
beforeEach(() => {
  store = createStore(); // чистое состояние для каждого теста
});
```

### Условный экспорт для Node.js и браузера

```js
// crypto.mjs — универсальный модуль
let cryptoImpl;

if (typeof globalThis.crypto !== 'undefined') {
  // Браузер или Node.js 19+
  cryptoImpl = globalThis.crypto;
} else {
  // Node.js < 19
  const { webcrypto } = await import('node:crypto');
  cryptoImpl = webcrypto;
}

export function randomUUID() {
  return cryptoImpl.randomUUID();
}

export async function hash(data) {
  const encoded = new TextEncoder().encode(data);
  const buffer = await cryptoImpl.subtle.digest('SHA-256', encoded);
  return Array.from(new Uint8Array(buffer))
    .map(b => b.toString(16).padStart(2, '0'))
    .join('');
}
```

### Import assertions / attributes (ES2025)

Синтаксис для указания типа импортируемого ресурса:

```js
// Import Attributes (бывшие Import Assertions)
import config from './config.json' with { type: 'json' };
import styles from './styles.css' with { type: 'css' };

// Dynamic import с attributes
const data = await import('./data.json', { with: { type: 'json' } });

// Это позволяет движку:
// 1. Проверить MIME-тип ответа (безопасность)
// 2. Выбрать правильный парсер (JSON, CSS, etc.)
```
