## Number

### IEEE 754 Double Precision — внутреннее представление

Все числа в JavaScript представлены в формате `IEEE 754 double-precision 64-bit float`. Каждое число занимает ровно 64 бита:

| Компонент | Биты | Описание |
|-----------|------|----------|
| Sign bit | 1 бит (бит 63) | `0` — положительное, `1` — отрицательное |
| Exponent | 11 бит (биты 52–62) | Смещённая экспонента (bias = 1023) |
| Mantissa (Significand) | 52 бита (биты 0–51) | Дробная часть мантиссы (целая `1.` подразумевается) |

Формула нормализованного числа:

```
(-1)^sign × 2^(exponent - 1023) × 1.mantissa
```

**Денормализованные числа** (denormalized / subnormal) — когда все 11 бит экспоненты равны `0`. В этом случае подразумеваемая единица перед мантиссой отсутствует, формула:

```
(-1)^sign × 2^(-1022) × 0.mantissa
```

Это позволяет представить числа, близкие к нулю, с постепенной потерей точности (gradual underflow), вместо резкого прыжка в ноль:

```javascript
console.log(Number.MIN_VALUE);        // 5e-324 — минимальное положительное денормализованное число
console.log(Number.MIN_VALUE / 2);    // 0 — underflow, дальше уже нельзя
console.log(5e-324 > 0);             // true — оно больше нуля, но едва-едва
```

**Специальные значения** кодируются через экспоненту `11111111111` (все единицы, т.е. 2047):
- Мантисса = 0 → `±Infinity`
- Мантисса ≠ 0 → `NaN`

### V8 Smi Optimization

V8 оптимизирует целые числа в диапазоне **-2^31 .. 2^31-1** (на 64-bit платформах: -2^31 .. 2^31-1 для Smi, хотя внутренне Smi может быть 31-bit на 32-bit платформах) через **tagged pointers** — Smi (Small Integer).

```javascript
// Smi — число хранится прямо в указателе, без heap allocation
let x = 42;          // Smi: 42 << 1 | 0 (tag bit = 0 означает Smi)

// HeapNumber — число на куче, требует allocation
let y = 3.14;        // HeapNumber: объект в heap, содержащий 64-bit float
let z = 2 ** 31;     // HeapNumber: 2147483648 выходит за Smi-диапазон
```

Почему это важно:
- **Smi** не аллоцируется в куче — нет GC-давления, быстрая арифметика
- **HeapNumber** — отдельный объект, требует allocation/deallocation
- Переход из Smi в HeapNumber (и обратно) — hidden cost при выходе из диапазона

```javascript
// Плохо для производительности: Smi -> HeapNumber -> Smi в горячем цикле
function badLoop() {
  let sum = 0;
  for (let i = 0; i < 1000000; i++) {
    sum += 0.1; // HeapNumber на каждой итерации
  }
  return sum;
}

// Лучше: оставаться в Smi-диапазоне когда возможно
function goodLoop() {
  let sum = 0;
  for (let i = 0; i < 1000000; i++) {
    sum += 1; // Smi всю дорогу (пока sum < 2^31)
  }
  return sum;
}
```

### `MAX_SAFE_INTEGER`, `MIN_SAFE_INTEGER`, `EPSILON`

```javascript
console.log(Number.MAX_SAFE_INTEGER);  // 9007199254740991 (2^53 - 1)
console.log(Number.MIN_SAFE_INTEGER);  // -9007199254740991 (-(2^53 - 1))
console.log(Number.EPSILON);           // 2.220446049250313e-16 (2^-52)
```

**Safe integer** — целое число, которое точно представимо в `double`. За пределами `±2^53-1` целые числа начинают "прыгать":

```javascript
console.log(9007199254740991);       // 9007199254740991 — OK
console.log(9007199254740992);       // 9007199254740992 — ещё OK (2^53 представимо)
console.log(9007199254740993);       // 9007199254740992 — ПОТЕРЯ! Округлено вниз
console.log(9007199254740994);       // 9007199254740994 — OK (чётное)
console.log(9007199254740995);       // 9007199254740996 — ПОТЕРЯ! Округлено вверх

// Поэтому:
console.log(9007199254740992 === 9007199254740993); // true (!!)
```

`Number.EPSILON` — разница между `1` и следующим представимым числом. Используется для сравнения с плавающей точкой:

```javascript
function almostEqual(a, b) {
  return Math.abs(a - b) < Number.EPSILON;
}

console.log(almostEqual(0.1 + 0.2, 0.3)); // true

// Но EPSILON работает ТОЛЬКО для чисел вблизи 1.
// Для больших чисел нужен относительный epsilon:
function relativelyEqual(a, b, tolerance = Number.EPSILON) {
  const diff = Math.abs(a - b);
  const max = Math.max(Math.abs(a), Math.abs(b));
  return diff <= tolerance * max;
}
```

### 0.1 + 0.2 !== 0.3 — ПОЧЕМУ

Число `0.1` в двоичной системе — бесконечная периодическая дробь (аналогично `1/3 = 0.333...` в десятичной):

```
0.1 (десятичная) = 0.0001100110011001100110011... (двоичная, бесконечная)
```

При записи в 52-bit мантиссу дробь обрезается, возникает ошибка округления:

```javascript
// Реальные значения, хранящиеся в памяти:
console.log(0.1.toPrecision(20)); // "0.10000000000000000555"
console.log(0.2.toPrecision(20)); // "0.20000000000000001110"
console.log(0.3.toPrecision(20)); // "0.29999999999999998890"

// При сложении ошибки складываются:
console.log((0.1 + 0.2).toPrecision(20)); // "0.30000000000000004441"

// А 0.3 хранится как:
console.log((0.3).toPrecision(20));         // "0.29999999999999998890"

// Разница:
console.log(0.1 + 0.2 - 0.3);  // 5.551115123125783e-17
console.log(0.1 + 0.2 === 0.3); // false
```

Решения:
```javascript
// 1. Сравнение с EPSILON (для чисел около 1)
Math.abs(0.1 + 0.2 - 0.3) < Number.EPSILON; // true

// 2. Работа в целых числах (центы вместо долларов)
const price = 199; // $1.99 хранится как 199 центов
const tax = 15;    // 15 центов
const total = (price + tax) / 100; // 2.14 — точный результат

// 3. Умножить, сложить, разделить
Math.round((0.1 + 0.2) * 10) / 10 === 0.3; // true
```

### +0 и -0

IEEE 754 определяет два нуля: положительный и отрицательный.

```javascript
console.log(+0 === -0);           // true — оператор === не различает
console.log(Object.is(+0, -0));   // false — Object.is различает

// Как получить -0
console.log(-0);                   // -0
console.log(0 * -1);              // -0
console.log(0 / -1);              // -0
console.log(-Number.MIN_VALUE / Infinity); // -0

// Как определить -0
console.log(1 / +0);  // Infinity
console.log(1 / -0);  // -Infinity — вот так различаем

function isNegativeZero(x) {
  return x === 0 && 1 / x === -Infinity;
}

// Или просто:
Object.is(x, -0);
```

Зачем нужен `-0` на практике:
```javascript
// Направление движения: объект остановился, но "ехал" влево
let velocity = -0.5;
velocity += 0.5; // -0 — сохраняет информацию о направлении

// Math.sign() понимает -0:
Math.sign(-0); // -0
```

### NaN (Not a Number)

`NaN` — единственное значение в JavaScript, которое не равно самому себе:

```javascript
console.log(NaN === NaN);         // false
console.log(NaN !== NaN);         // true
console.log(typeof NaN);          // "number" — ирония

// Как получить NaN
console.log(0 / 0);               // NaN
console.log(Infinity - Infinity);  // NaN
console.log(Math.sqrt(-1));        // NaN
console.log(parseInt("hello"));    // NaN
console.log(undefined + 1);       // NaN
console.log("abc" * 2);           // NaN
```

**`Number.isNaN()` vs `isNaN()`** — критически важное отличие:

```javascript
// isNaN() — СНАЧАЛА приводит к числу через ToNumber(), ПОТОМ проверяет
isNaN("hello");      // true — "hello" → NaN → true
isNaN("123");        // false — "123" → 123 → false
isNaN(undefined);    // true — undefined → NaN → true
isNaN({});           // true — {} → NaN → true

// Number.isNaN() — НЕ приводит тип, проверяет СТРОГО
Number.isNaN("hello");    // false — "hello" не является NaN
Number.isNaN(undefined);  // false — undefined не является NaN
Number.isNaN(NaN);        // true — единственный случай

// Полифил Number.isNaN:
function myIsNaN(value) {
  return value !== value; // NaN — единственное значение, неравное самому себе
}
```

`NaN` заразен — любая арифметическая операция с `NaN` даёт `NaN`:

```javascript
console.log(NaN + 1);      // NaN
console.log(NaN * 100);    // NaN
console.log(NaN > 0);      // false
console.log(NaN < 0);      // false
console.log(NaN === 0);    // false
// NaN не больше, не меньше и не равен НИЧЕМУ, включая себя
```

### Infinity

```javascript
console.log(1 / 0);               // Infinity
console.log(-1 / 0);              // -Infinity
console.log(Number.POSITIVE_INFINITY); // Infinity
console.log(Number.NEGATIVE_INFINITY); // -Infinity

// Арифметика с Infinity
console.log(Infinity + Infinity);  // Infinity
console.log(Infinity - Infinity);  // NaN
console.log(Infinity * -1);       // -Infinity
console.log(Infinity / Infinity); // NaN
console.log(1 / Infinity);        // 0
console.log(-1 / Infinity);       // -0
```

**`Number.isFinite()` vs `isFinite()`**:

```javascript
// isFinite() — сначала ToNumber(), потом проверка
isFinite("42");       // true — "42" → 42 → true
isFinite("hello");    // false — "hello" → NaN → false
isFinite(null);       // true — null → 0 → true (!)
isFinite("");         // true — "" → 0 → true (!)

// Number.isFinite() — строгая проверка без приведения
Number.isFinite("42");    // false — строка, не число
Number.isFinite(null);    // false
Number.isFinite(42);      // true
Number.isFinite(Infinity); // false
Number.isFinite(NaN);     // false
```

### parseInt() gotchas

```javascript
// parseInt(0.0000005) === 5 — ПОЧЕМУ?!
console.log(parseInt(0.0000005)); // 5

// Разгадка: parseInt сначала преобразует аргумент в строку!
console.log(String(0.0000005));   // "5e-7"
// А затем парсит строку "5e-7" до первого нечислового символа → 5

// То же для больших чисел:
console.log(parseInt(1000000000000000000000)); // 1
console.log(String(1000000000000000000000));    // "1e+21" → parseInt → 1

// ВСЕГДА передавайте radix!
console.log(parseInt("010"));      // 10 (в современных движках), но раньше было 8 (octal)
console.log(parseInt("010", 10));  // 10 — явно десятичная
console.log(parseInt("0x10"));     // 16 — определяет hex автоматически
console.log(parseInt("0x10", 10)); // 0 — принудительно десятичная, останавливается на "x"

// Ещё gotcha: parseInt с Array.prototype.map
console.log(["1", "2", "3"].map(parseInt));
// [1, NaN, NaN]
// Потому что map передаёт (element, index, array):
// parseInt("1", 0) → 1 (radix 0 трактуется как 10)
// parseInt("2", 1) → NaN (radix 1 невалиден)
// parseInt("3", 2) → NaN ("3" не существует в двоичной)

// Решение:
["1", "2", "3"].map(Number);             // [1, 2, 3]
["1", "2", "3"].map(s => parseInt(s, 10)); // [1, 2, 3]
```

### Побитовые операции: конвертация в 32-bit signed int

Все побитовые операторы (`|`, `&`, `^`, `~`, `<<`, `>>`, `>>>`) конвертируют операнды в **32-bit signed integer** (кроме `>>>` — unsigned):

```javascript
// Потеря данных при больших числах:
console.log(2 ** 40 | 0);        // 0 — число не влезает в int32!
console.log(2 ** 31 | 0);        // -2147483648 — переполнение в отрицательное (sign bit)
console.log((2 ** 31 - 1) | 0);  // 2147483647 — максимум int32

// Трюк для Math.trunc() через побитовый OR:
console.log(3.7 | 0);   // 3
console.log(-3.7 | 0);  // -3
// НО: сломается для чисел > 2^31-1 или < -2^31:
console.log(2147483648.5 | 0); // -2147483648 — НЕВЕРНО!

// ~~ (double NOT) — ещё один трюк для truncation:
console.log(~~3.7);   // 3
console.log(~~-3.7);  // -3
// Те же ограничения по диапазону int32

// >>> 0 — конвертация в uint32:
console.log(-1 >>> 0);           // 4294967295 (0xFFFFFFFF)
console.log((-1 >>> 0).toString(16)); // "ffffffff"
```

### `Number.isInteger()`, `Number.isSafeInteger()`

```javascript
console.log(Number.isInteger(42));      // true
console.log(Number.isInteger(42.0));    // true — 42.0 === 42 в IEEE 754
console.log(Number.isInteger(42.5));    // false
console.log(Number.isInteger("42"));    // false — без приведения типа
console.log(Number.isInteger(Infinity)); // false
console.log(Number.isInteger(NaN));     // false

console.log(Number.isSafeInteger(42));                    // true
console.log(Number.isSafeInteger(9007199254740991));      // true (MAX_SAFE_INTEGER)
console.log(Number.isSafeInteger(9007199254740992));      // false (2^53, уже unsafe)
console.log(Number.isSafeInteger(3.0));                   // true (целое)
console.log(Number.isSafeInteger(3.1));                   // false (не целое)
```

### `toFixed()` и банкирское округление

```javascript
// toFixed() возвращает СТРОКУ!
console.log(typeof (1.5).toFixed(0));  // "string"

// Банкирское округление (round half to even) — поведение НЕ гарантировано спецификацией,
// но многие движки его используют:
console.log((0.5).toFixed(0));   // "0" — округляет к чётному (банкирское)
console.log((1.5).toFixed(0));   // "2" — округляет к чётному
console.log((2.5).toFixed(0));   // "2" — округляет к чётному (!)
console.log((3.5).toFixed(0));   // "4" — округляет к чётному

// Но: из-за IEEE 754 ошибок результат может быть неожиданным:
console.log((1.255).toFixed(2)); // "1.25" — не "1.26"!
console.log(1.255.toPrecision(20)); // "1.2549999999999999822" — вот почему

// Надёжное округление:
function roundToFixed(num, decimals) {
  const factor = 10 ** decimals;
  return (Math.round(num * factor) / factor).toFixed(decimals);
}
console.log(roundToFixed(1.255, 2)); // "1.26"
```

## String

### V8 String Representations

V8 хранит строки не как единый массив символов, а использует несколько внутренних представлений для оптимизации:

| Тип | Описание | Когда используется |
|-----|----------|--------------------|
| `SeqString` | Плоский массив символов (one-byte или two-byte) | Литералы, результаты `.slice()` при flatten |
| `ConsString` | "Rope" — дерево из двух частей (left + right) | Конкатенация `a + b` (ленивая, без копирования) |
| `SlicedString` | Ссылка на родительскую строку + offset + length | `.substring()`, `.slice()` (zero-copy) |
| `ThinString` | Обёртка, указывающая на интернализированную строку | После интернализации (deduplication) |

```javascript
// ConsString: V8 НЕ копирует при конкатенации — создаёт дерево
let s = "hello";
s = s + " " + "world"; // ConsString { left: "hello", right: ConsString { left: " ", right: "world" } }

// SlicedString: .slice() не копирует — указывает на оригинал
const original = "Hello, World!";
const slice = original.slice(7); // SlicedString → указывает на original, offset=7

// При обращении к символам или сравнении V8 "выравнивает" (flatten) строку в SeqString
```

### UTF-16: `code units` vs `code points`, суррогатные пары

JavaScript строки — это последовательности **16-bit code units** (UTF-16), а не Unicode code points:

```javascript
// BMP-символы (U+0000..U+FFFF): один code unit = один code point
console.log("A".length);     // 1
console.log("Ж".length);     // 1

// Символы за пределами BMP (U+10000+): два code units = суррогатная пара
console.log("😀".length);    // 2 (!!)
console.log("𝕳".length);     // 2 (Mathematical Double-Struck H, U+1D573)

// Суррогатная пара для 😀 (U+1F600):
// High surrogate: 0xD83D, Low surrogate: 0xDE00
console.log("😀".charCodeAt(0).toString(16)); // "d83d"
console.log("😀".charCodeAt(1).toString(16)); // "de00"

// Проблемы:
console.log("😀"[0]);             // "\uD83D" — сломанный high surrogate
console.log("😀"[1]);             // "\uDE00" — сломанный low surrogate
console.log("😀".split(""));      // ["\uD83D", "\uDE00"] — разорвали пару!
```

### `codePointAt()` vs `charCodeAt()`, `String.fromCodePoint()` vs `fromCharCode()`

```javascript
// charCodeAt() — возвращает code UNIT (16 bit)
console.log("😀".charCodeAt(0));  // 55357 (0xD83D) — high surrogate
console.log("😀".charCodeAt(1));  // 56832 (0xDE00) — low surrogate

// codePointAt() — возвращает полный code POINT
console.log("😀".codePointAt(0)); // 128512 (0x1F600) — полный code point!
console.log("😀".codePointAt(1)); // 56832 — low surrogate (индекс всё ещё по code units)

// Итерация по code points (а не code units):
for (const char of "Hello 😀🌍") {
  console.log(char); // Каждый символ целиком, включая emoji
}

// Spread тоже работает по code points:
console.log([..."😀🌍"]);         // ["😀", "🌍"] — правильно!
console.log([..."😀🌍"].length);  // 2 — правильно!

// Создание строк:
console.log(String.fromCharCode(0xD83D, 0xDE00)); // "😀" — нужна суррогатная пара
console.log(String.fromCodePoint(0x1F600));         // "😀" — один code point
```

### String Interning в V8

V8 **интернализирует** (deduplicates) идентичные строки для экономии памяти. Все строковые литералы в исходном коде автоматически интернализируются:

```javascript
// Литералы интернализируются — одна копия в памяти
const a = "hello";
const b = "hello";
// a и b указывают на один и тот же объект в памяти (V8 internal)

// Динамически созданные строки могут быть интернализированы
// при использовании как ключ объекта:
const obj = {};
const key = ["hel", "lo"].join(""); // "hello" — динамическая
obj[key] = 1; // V8 интернализирует "hello" для использования как ключ
```

### Иммутабельность и performance

Строки в JavaScript **иммутабельны** — любая "модификация" создаёт новую строку:

```javascript
let s = "hello";
s[0] = "H";          // Не работает (молча в sloppy mode, TypeError в strict)
console.log(s);       // "hello" — не изменилась

// Конкатенация в цикле — классическая ловушка производительности:
// ПЛОХО: O(n²) по памяти и времени (без оптимизаций)
let result = "";
for (let i = 0; i < 100000; i++) {
  result += "x"; // V8 оптимизирует через ConsString, но flatten будет дорогим
}

// ЛУЧШЕ: собираем массив, потом join
const parts = [];
for (let i = 0; i < 100000; i++) {
  parts.push("x");
}
const result2 = parts.join(""); // Одна аллокация результата

// В РЕАЛЬНОСТИ: V8 хорошо оптимизирует += через ConsString rope,
// но join() всё равно предпочтительнее для очень больших строк,
// т.к. flatten rope-дерева может вызвать stack overflow при глубоком дереве
```

### Template Literals и Tagged Templates

```javascript
// Базовые template literals
const name = "мир";
const greeting = `Привет, ${name}!`; // "Привет, мир!"

// Многострочность:
const multiline = `
  строка 1
  строка 2
`; // Сохраняет переводы строк и отступы!

// Tagged templates — мощнейший паттерн:
function sql(strings, ...values) {
  // strings — массив "статических" частей (frozen!)
  // values — массив интерполированных значений
  let query = "";
  const params = [];

  strings.forEach((str, i) => {
    query += str;
    if (i < values.length) {
      query += `$${i + 1}`;
      params.push(values[i]);
    }
  });

  return { query, params };
}

const userId = 42;
const status = "active";
const { query, params } = sql`SELECT * FROM users WHERE id = ${userId} AND status = ${status}`;
// query: "SELECT * FROM users WHERE id = $1 AND status = $2"
// params: [42, "active"]

// Tagged template получает .raw версию (без escape-последовательностей):
function raw(strings) {
  return strings.raw[0];
}
console.log(raw`Hello\nWorld`);  // "Hello\\nWorld" — raw, без перевода строки
console.log(String.raw`Hello\n`); // "Hello\\n" — встроенный аналог
```

### Ключевые методы строк


### `isWellFormed()`, `toWellFormed()` (ES2024)

Строки с "осиротевшими" суррогатами (lone surrogates) — невалидный UTF-16:

## BigInt

### Создание и литералы

```javascript
// Литерал — суффикс n
const a = 123n;
const b = 0xFFn;          // 255n (hex)
const c = 0o77n;          // 63n (octal)
const d = 0b1010n;        // 10n (binary)

// Функция BigInt()
const e = BigInt("123");  // 123n — из строки
const f = BigInt(123);    // 123n — из числа
const g = BigInt("0xff"); // 255n — hex строка тоже работает

// Edge cases при создании:
BigInt(1.5);         // RangeError: The number 1.5 is not safe to convert to a BigInt
BigInt(NaN);         // RangeError
BigInt(Infinity);    // RangeError
BigInt("1.5");       // SyntaxError: Cannot convert 1.5 to a BigInt
BigInt("");          // SyntaxError в большинстве движков
BigInt("  123  ");   // 123n — пробелы по краям допускаются
```

### Невозможность смешивания с `Number`

```javascript
// TypeError при смешивании в арифметике:
1n + 1;       // TypeError: Cannot mix BigInt and other types
1n * 2;       // TypeError
1n < 2;       // true — СРАВНЕНИЕ работает!

// Явное приведение:
BigInt(1) + 1n;      // 2n
Number(1n) + 1;      // 2

// ОСТОРОЖНО: потеря при конвертации
Number(9007199254740993n); // 9007199254740992 — потеря точности!
// Для безопасной конвертации проверяйте:
function safeToNumber(big) {
  if (big > BigInt(Number.MAX_SAFE_INTEGER) || big < BigInt(Number.MIN_SAFE_INTEGER)) {
    throw new RangeError("BigInt value exceeds safe integer range");
  }
  return Number(big);
}
```

### Сравнение и равенство

```javascript
// Строгое равенство: разные типы → false
console.log(0n === 0);   // false
console.log(1n === 1);   // false

// Нестрогое равенство: с приведением типов → true
console.log(0n == 0);    // true
console.log(1n == 1);    // true

// Сравнение операторами работает между BigInt и Number:
console.log(1n < 2);     // true
console.log(2n > 1);     // true
console.log(2n >= 2);    // true

// Сортировка смешанных массивов:
const mixed = [4n, 6, -12n, 10, 4, 0, 0n];
mixed.sort(); // [-12n, 0, 0n, 10, 4n, 4, 6] — лексикографическая (сломано)
mixed.sort((a, b) => (a < b ? -1 : a > b ? 1 : 0)); // корректно
// [-12n, 0, 0n, 4, 4n, 6, 10]

// Boolean context:
console.log(Boolean(0n));  // false — falsy!
console.log(Boolean(1n));  // true
if (0n) { /* не выполнится */ }
```

### Performance

`BigInt` **значительно медленнее** `Number`:

```javascript

// Каждая арифметическая операция создаёт новый объект на куче

// Бенчмарк (концептуальный):
// Number: ~1x (базовая скорость)
// BigInt для малых значений: ~5-20x медленнее
// BigInt для больших значений (>64 bit): ~50-100x медленнее

// - Криптография

```

### JSON и сериализация

```javascript

  typeof value === "bigint" ? value.toString() : value
);
// '{"value":"1"}'

};
```

### Логические операторы возвращают операнд, а не `boolean`

```javascript
// && возвращает ПЕРВЫЙ falsy или ПОСЛЕДНИЙ truthy

console.log(null ?? "fallback");  // "fallback"
console.log(undefined ?? "fb");   // "fb"

// Частая ошибка — || вместо ?? для значений, которые могут быть 0 или "":

  // return config.port ?? 3000;
```

### `Symbol.for()` / `Symbol.keyFor()` — глобальный реестр

#### `Symbol.iterator` и `Symbol.asyncIterator`

```javascript
// Symbol.iterator — делает объект iterable (for...of, spread, destructuring)
const range = {
  from: 1,
  to: 5,
  [Symbol.iterator]() {
    let current = this.from;
    const last = this.to;
    return {
      next() {
        return current <= last
          ? { value: current++, done: false }
          : { done: true };
      }
    };
  }
};

console.log([...range]);      // [1, 2, 3, 4, 5]
for (const n of range) { }    // 1, 2, 3, 4, 5

  from: 1,
  to: 3,
  [Symbol.asyncIterator]() {
    let current = this.from;
    const last = this.to;
    return {
      async next() {

        return current <= last
          ? { value: current++, done: false }
          : { done: true };
      }
    };
  }
};

// for await (const n of asyncRange) { console.log(n); }
```

```javascript
// Управляет приведением объекта к примитиву
// hint: "number", "string", "default"

  currency: "USD",
  [Symbol.toPrimitive](hint) {
    switch (hint) {
      case "number":  return this.amount;         // +money, Number(money)
```

### Soft Private через `Symbol` vs Hard Private `#`

```javascript
// Symbol — "soft private": скрыто от обычного перечисления, но доступно через Reflect
const _balance = Symbol("balance");

class BankAccount {
  constructor(amount) {
    this[_balance] = amount;
  }

  getBalance() {
    return this[_balance];
  }
}

const acc = new BankAccount(1000);
console.log(acc.getBalance());                        // 1000
console.log(acc[_balance]);                            // 1000 — доступно, если есть символ
console.log(Object.getOwnPropertySymbols(acc));       // [Symbol(balance)] — можно найти!
console.log(acc[Object.getOwnPropertySymbols(acc)[0]]); // 1000 — обход "приватности"

// # — "hard private": истинная приватность на уровне спецификации
class SecureAccount {
  #balance;

  constructor(amount) {
    this.#balance = amount;
  }

  getBalance() {
    return this.#balance;
  }
}

const sacc = new SecureAccount(1000);
console.log(sacc.getBalance());     // 1000
// sacc.#balance;                    // SyntaxError — недоступно извне
// Нет способа обратиться к #balance извне класса — даже через Reflect
```

## Null и Undefined

### `typeof null === "object"` — исторический баг

```javascript
console.log(typeof null); // "object" — не "null"!
```

Это баг из первой реализации JavaScript (1995, Brendan Eich). В первом движке значения хранились как `(type tag, value)`. Type tags были 32-bit:
- `000` — object
- `001` — int
- `010` — double
- `100` — string
- `110` — boolean

`null` был представлен как **NULL-указатель** (`0x00`), и его type tag — `000`, что совпадает с `object`. Этот баг был зафиксирован в спецификации ECMAScript и никогда не будет исправлен из-за обратной совместимости.

```javascript
// Правильная проверка на null:
const value = null;

// Плохо:
typeof value === "object"; // true, но не отличает от реальных объектов

// Хорошо:
value === null; // true — строгое сравнение с null
```

### Семантика: `null` vs `undefined`

```javascript
// undefined — значение НЕ БЫЛО ЗАДАНО (отсутствие значения "по умолчанию")
let x;                           // undefined — переменная объявлена, не инициализирована
const obj = {};
console.log(obj.missing);       // undefined — свойство не существует
function f() {}
console.log(f());                // undefined — нет return
function g(a, b) { return b; }
console.log(g(1));               // undefined — аргумент не передан

// null — значение ЯВНО УСТАНОВЛЕНО как "пусто" (намеренное отсутствие)
const user = {
  name: "Alice",
  middleName: null,  // мы ЗНАЕМ, что отчества нет — это явный выбор
  // lastName отсутствует → undefined при обращении
};

console.log(user.middleName);   // null — явно задано
console.log(user.lastName);     // undefined — не задано
```

### `Object.create(null)` — объект без прототипа

```javascript
// Обычный объект наследует от Object.prototype:
const regular = {};
console.log(regular.toString);    // [Function: toString]
console.log(regular.hasOwnProperty); // [Function: hasOwnProperty]

// Object.create(null) — "чистый словарь" без прототипа:
const dict = Object.create(null);
console.log(dict.toString);       // undefined — нет прототипа!

// Зачем: безопасное хранилище ключ-значение без конфликтов с прототипом
dict["__proto__"] = "safe";       // просто ключ, не меняет прототип
dict["toString"] = "safe";        // просто ключ, не конфликтует с Object.prototype.toString
dict["constructor"] = "safe";     // просто ключ

// Используется в: Map-подобных структурах, конфигах, AST node metadata
// Или просто используйте Map:
const map = new Map();
```

### `undefined` не зарезервировано в non-strict mode

```javascript
// В non-strict mode undefined — это СВОЙСТВО глобального объекта, а не keyword!
// Его МОЖНО было перезаписать (до ES5):
// undefined = 42; // Работало в старых движках!

// Даже в modern JS можно shadowing в локальном скоупе:
(function() {
  var undefined = 42; // Это работает! (не strict mode)
  console.log(undefined); // 42 (!)
})();

// void 0 — гарантированно возвращает undefined
console.log(void 0);           // undefined — всегда
console.log(void "anything");  // undefined — void отбрасывает результат

// В strict mode:
// "use strict";
// var undefined = 42; // TypeError

// В современном коде void 0 почти не нужен благодаря strict mode и ESM (всегда strict),
// но встречается в минифицированном коде (void 0 короче undefined)
```

### `typeof` для необъявленных переменных — safety guard

```javascript
// Обращение к необъявленной переменной — ReferenceError:
// console.log(notDeclared); // ReferenceError: notDeclared is not defined

// НО typeof для необъявленной переменной — НЕ ошибка:
console.log(typeof notDeclared); // "undefined" — безопасная проверка

// Практическое применение:
if (typeof window !== "undefined") {
  // Мы в браузере
}

if (typeof process !== "undefined" && process.versions?.node) {
  // Мы в Node.js
}

// Альтернатива через globalThis (ES2020):
const isBrowser = globalThis.window !== undefined;
```

### Default Parameters: `undefined` vs `null`

```javascript
// Default parameters срабатывают ТОЛЬКО для undefined, НЕ для null:
function greet(name = "World") {
  return `Hello, ${name}!`;
}

console.log(greet());          // "Hello, World!" — undefined → default
console.log(greet(undefined)); // "Hello, World!" — undefined → default
console.log(greet(null));      // "Hello, null!" — null НЕ триггерит default!
console.log(greet(""));        // "Hello, !" — "" НЕ триггерит default
console.log(greet(0));         // "Hello, 0!" — 0 НЕ триггерит default
```

### Destructuring Defaults

```javascript
// Те же правила: default срабатывает только для undefined
const { a = 5 } = { a: undefined };
console.log(a); // 5 — default сработал

const { b = 5 } = { b: null };
console.log(b); // null — default НЕ сработал!

const { c = 5 } = { c: 0 };
console.log(c); // 0 — default НЕ сработал

const { d = 5 } = {};
console.log(d); // 5 — свойство отсутствует → undefined → default

// Вложенный destructuring с defaults:
const { user: { name = "Anonymous" } = {} } = {};
console.log(name); // "Anonymous"

// Осторожно с null во вложенных:
// const { user: { name = "Anon" } = {} } = { user: null };
// TypeError: Cannot destructure property 'name' of null
```

### JSON: поведение с `null` и `undefined`

```javascript
// JSON.stringify() — undefined и null ведут себя по-разному:

// В объектах: undefined ПРОПУСКАЕТСЯ
console.log(JSON.stringify({ a: 1, b: undefined, c: null }));
// '{"a":1,"c":null}' — b исчез!

// В массивах: undefined → null
console.log(JSON.stringify([1, undefined, null, 3]));
// '[1,null,null,3]' — undefined стал null

// Как значение верхнего уровня:
console.log(JSON.stringify(undefined)); // undefined (не строка!)
console.log(JSON.stringify(null));      // "null"

// Функции и Symbol тоже пропускаются:
console.log(JSON.stringify({ fn: () => {}, sym: Symbol() }));
// '{}'

// JSON.parse("null"):
console.log(JSON.parse("null")); // null
// JSON.parse("undefined"); // SyntaxError — undefined не валидный JSON
```

### Optional Chaining `?.` и Nullish Coalescing `??`

```javascript
// ?. — останавливает цепочку при null или undefined (не при других falsy!)
const user = {
  address: {
    street: "Main St"
  }
};

console.log(user.address?.street);      // "Main St"
console.log(user.profile?.avatar);      // undefined — profile не существует
console.log(user.profile?.avatar?.url); // undefined — short-circuit при первом null/undefined

// Работает с методами и индексами:
const arr = null;
console.log(arr?.[0]);       // undefined
console.log(arr?.length);    // undefined

const obj = { fn: null };
console.log(obj.fn?.());     // undefined (не TypeError!)

// ?? — nullish coalescing, дефолт ТОЛЬКО для null/undefined
console.log(null ?? "default");      // "default"
console.log(undefined ?? "default"); // "default"
console.log(0 ?? "default");        // 0 — ноль НЕ nullish
console.log("" ?? "default");       // "" — пустая строка НЕ nullish
console.log(false ?? "default");    // false — false НЕ nullish

// Комбинация:
const config = null;
const port = config?.server?.port ?? 3000;
console.log(port); // 3000

// ??= (nullish assignment, ES2021):
let a = null;
a ??= 42;       // a = 42 (было null)
let b = 0;
b ??= 42;       // b = 0 (0 не nullish)

// Нельзя комбинировать ?? с || или && без скобок:
// null ?? true || false; // SyntaxError!
(null ?? true) || false;  // true — OK
null ?? (true || false);  // true — OK
```

## Общее для всех примитивов

### Autoboxing (Wrapper Objects)

Когда мы вызываем метод на примитиве, JavaScript временно оборачивает его в объект-обёртку:

```javascript
// Как работает "abc".toUpperCase():
// 1. Создаётся временный new String("abc")
// 2. Вызывается .toUpperCase() на обёртке
// 3. Возвращается результат "ABC" (примитив)
// 4. Временный объект уничтожается (в теории)

// На практике V8 ОПТИМИЗИРУЕТ autoboxing — объект-обёртка часто НЕ создаётся.
// JIT-компилятор инлайнит методы строк/чисел напрямую.

// Но обёртки и примитивы — разные вещи:
const strPrim = "hello";
const strObj = new String("hello");

console.log(typeof strPrim);         // "string"
console.log(typeof strObj);          // "object"
console.log(strPrim === strObj);     // false
console.log(strPrim == strObj);      // true (с приведением)

// Присвоение свойства примитиву — молча теряется:
const s = "hello";
s.myProp = 42;           // В non-strict: создаётся на временной обёртке, потом обёртка GC'd
console.log(s.myProp);   // undefined
// В strict mode: TypeError

// Обёртки для каждого типа:
// String("abc"), Number(42), Boolean(true), Symbol(), BigInt(1n)
// null и undefined НЕ имеют обёрток — вызов метода на них = TypeError
```

### Спецификация: алгоритм `ToObject()`

Алгоритм `ToObject()` вызывается неявно при обращении к свойствам примитивов:

| Тип | Результат |
|-----|-----------|
| `undefined` | TypeError |
| `null` | TypeError |
| `boolean` | `new Boolean(value)` |
| `number` | `new Number(value)` |
| `string` | `new String(value)` |
| `symbol` | `Object(symbol)` |
| `bigint` | `Object(bigint)` |
| `object` | без изменений |

```javascript
// Явный вызов через Object():
console.log(Object("hello")); // String {"hello"} — обёртка
console.log(Object(42));      // Number {42} — обёртка
console.log(Object(true));    // Boolean {true} — обёртка

// null и undefined бросают TypeError при доступе к свойствам:
// null.toString();      // TypeError: Cannot read properties of null
// undefined.toString(); // TypeError: Cannot read properties of undefined

// Но Object(null) и Object(undefined) — пустой объект (НЕ TypeError):
console.log(Object(null));      // {} — пустой объект, не обёртка
console.log(Object(undefined)); // {} — пустой объект, не обёртка
```

### Copy-by-Value: как V8 хранит примитивы

Примитивы копируются **по значению** при присвоении и передаче в функции:

```javascript
let a = 42;
let b = a;  // КОПИЯ значения
b = 100;
console.log(a); // 42 — не изменилось

let s1 = "hello";
let s2 = s1; // Копия ссылки на интернализированную строку (оптимизация),
              // но семантически — по значению
s2 = "world";
console.log(s1); // "hello" — не изменилось
```

Внутреннее представление в V8:

```
Smi (Small Integer):
  Значение хранится ПРЯМО в указателе (tagged pointer):
  [ value (31 bits) | 0 ]  ← tag bit 0 означает Smi
  Нет heap allocation, нет GC overhead.

HeapNumber (float):
  Указатель на объект в куче:
  pointer → [ Map | 64-bit IEEE 754 value ]
  Heap allocation, подвержен GC.

String:
  pointer → [ Map | hash | length | chars... ]
  Или ConsString: pointer → [ Map | left-ptr | right-ptr ]
  Интернализированные строки разделяют один объект.

Boolean:
  V8 использует singleton-объекты для true/false (oddball).
  Нет отдельных аллокаций для каждого boolean.

null, undefined:
  Тоже oddball singletons — один объект на весь runtime.
```

### Comparisons: `NaN`, `-0`, `Object.is()` vs `===`

```javascript
// === (strict equality) — почти всегда достаточен, но имеет 2 edge case:

// Edge case 1: NaN
console.log(NaN === NaN);           // false — единственное значение неравное себе
console.log(Object.is(NaN, NaN));   // true  — Object.is "исправляет" это

// Edge case 2: +0 и -0
console.log(+0 === -0);             // true  — оператор === не различает
console.log(Object.is(+0, -0));     // false — Object.is различает

// Во всех остальных случаях Object.is() === ===:
console.log(Object.is(1, 1));         // true
console.log(Object.is("a", "a"));     // true
console.log(Object.is(null, null));    // true
console.log(Object.is(1, "1"));       // false (нет приведения типов)

// Таблица сравнений:
//                  ===       Object.is()    ==
// NaN, NaN        false     true           false
// +0, -0          true      false          true
// null, undefined  false     false          true (!)
// 1, "1"          false     false          true (!)

// SameValueZero (используется в Map, Set, includes):
// Как Object.is(), но +0 === -0:
console.log(new Set([+0, -0]).size);      // 1 — +0 и -0 считаются одинаковыми
console.log([NaN].includes(NaN));          // true — NaN находит NaN!
console.log([NaN].indexOf(NaN));           // -1 — indexOf использует ===, не находит NaN

// Полифил Object.is:
function objectIs(x, y) {
  if (x === y) {
    // Отличаем +0 от -0: 1/+0 = Infinity, 1/-0 = -Infinity
    return x !== 0 || 1 / x === 1 / y;
  }
  // Отличаем NaN: единственное значение неравное себе
  return x !== x && y !== y;
}
```
