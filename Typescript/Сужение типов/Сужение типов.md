> (сужать) тип переменной внутри условных блоков кода. Это основа безопасной работы
> с union-типами и ключевой элемент системы типов TypeScript.

## 1. Что такое сужение типов (Type Narrowing)

### 1.1 Control Flow Analysis (CFA)

TypeScript-компилятор выполняет **Control Flow Analysis** — анализ потока управления,
который отслеживает, как тип переменной изменяется по мере прохождения через условные
конструкции (`if`, `switch`, тернарный оператор, циклы).

CFA строит внутренний **граф потока управления** (Control Flow Graph, CFG), где каждый
узел — это блок кода, а рёбра — возможные переходы. На каждом узле компилятор вычисляет
множество допустимых типов переменной.

```ts
function process(value: string | number | boolean) {
  // Здесь value: string | number | boolean

  if (typeof value === "string") {
    // CFA сузил: value: string
    console.log(value.toUpperCase());
    return;
  }

  // После return string исключён: value: number | boolean

  if (typeof value === "number") {
    // CFA сузил: value: number
    console.log(value.toFixed(2));
    return;
  }

  // Единственный оставшийся тип: value: boolean
  console.log(value ? "yes" : "no");
}
```

### 1.2 Граф сужения типов

Компилятор строит **type narrowing graph** — дерево решений, определяющее тип
в каждой точке программы:

```
process(value: string | number | boolean)
│
├── if (typeof value === "string") ──► true ──► value: string ──► return
│                                      false ▼
│                               value: number | boolean
│
├── if (typeof value === "number") ──► true ──► value: number ──► return
│                                      false ▼
│                               value: boolean
│
└── value: boolean
```

### 1.3 Assignments и CFA

CFA учитывает **присваивания** — после присваивания тип переменной пересчитывается:

```ts
let x: string | number;

x = "hello";
// x: string (CFA сузил на основе присваивания)
console.log(x.toUpperCase());

x = 42;
// x: number (тип пересчитан)
console.log(x.toFixed(2));
```

**Важно:** CFA работает **только в пределах одной функции**. Если переменная
передаётся в callback, компилятор теряет информацию о сужении, потому что callback
может быть вызван в произвольный момент.

```ts
let value: string | number = "hello";

// Тут value: string
setTimeout(() => {
  // Компилятор НЕ гарантирует, что value всё ещё string
  // value: string | number
}, 0);

value = 42; // переприсваивание после объявления callback
```

## 2. `typeof` guards

### 2.1 Поддерживаемые типы

Оператор `typeof` в JavaScript возвращает одну из следующих строк. TypeScript
использует этот факт для сужения:

| `typeof` результат | Сужает до типа TypeScript | Пример значений                       |
| ------------------- | ------------------------- | ------------------------------------- |
| `"string"`          | `string`                  | `"hello"`, `""`                       |
| `"number"`          | `number`                  | `42`, `NaN`, `Infinity`               |
| `"boolean"`         | `boolean`                 | `true`, `false`                       |
| `"symbol"`          | `symbol`                  | `Symbol("id")`                        |
| `"bigint"`          | `bigint`                  | `9007199254740991n`                   |
| `"undefined"`       | `undefined`               | `undefined`                           |
| `"function"`        | `Function`                | `() => {}`, `function() {}`           |
| `"object"`          | `object` (включая `null`) | `{}`, `[]`, `null`, `new Date()`      |

### 2.2 Базовый пример

```ts
function formatValue(value: string | number | boolean): string {
  if (typeof value === "string") {
    // value: string — доступны все строковые методы
    return value.trim().toLowerCase();
  }

  if (typeof value === "number") {
    // value: number — доступны числовые методы
    return value.toFixed(2);
  }

  // value: boolean — единственный оставшийся тип
  return value ? "true" : "false";
}
```

### 2.3 Ловушка: `typeof null === "object"`

Это историческая ошибка JavaScript, сохранённая для обратной совместимости.
TypeScript **знает** об этом — `typeof` guard с `"object"` **не исключает** `null`:

```ts
function handle(value: string | object | null) {
  if (typeof value === "object") {
    // value: object | null — null НЕ исключён!
    // value.toString(); // Ошибка! Object is possibly 'null'

    if (value !== null) {
      // value: object — теперь безопасно
      console.log(value.toString());
    }
  }
}
```

### 2.4 Негативное сужение

`typeof` работает и в ветке `else` — исключая тип из union:

```ts
function process(input: string | number | string[]) {
  if (typeof input !== "string") {
    // input: number | string[] — string исключён
    if (typeof input !== "number") {
      // input: string[] — остался только массив
      console.log(input.join(", "));
    }
  }
}
```

## 3. Truthiness narrowing

### 3.1 Truthy/falsy проверки

TypeScript сужает типы при проверке значения на truthiness. Все значения в JavaScript
делятся на **falsy** (`false`, `0`, `-0`, `0n`, `""`, `null`, `undefined`, `NaN`)
и **truthy** (все остальные).

```ts
function printName(name: string | null | undefined) {
  if (name) {
    // name: string — null и undefined исключены
    console.log(name.toUpperCase());
  } else {
    // name: string | null | undefined
    // Пустая строка "" тоже попадёт сюда!
    console.log("No name provided");
  }
}
```

### 3.2 Ограничение: ложные срабатывания

**Критически важно:** truthiness narrowing не различает `null`/`undefined` и «ложные»
значения примитивов (`0`, `""`, `NaN`, `false`). Это частый источник багов:

```ts
function processCount(count: number | undefined) {
  if (count) {
    // count: number — НО: 0 также отфильтрован!
    // Если count === 0, мы ошибочно его пропустим
    console.log(`Count: ${count}`);
  }

  // Правильный подход:
  if (count !== undefined) {
    // count: number — включая 0
    console.log(`Count: ${count}`);
  }
}
```

### 3.3 Паттерн двойного отрицания `!!`

Двойное отрицание приводит значение к boolean. TypeScript понимает этот паттерн:

```ts
function filterTruthy(values: (string | null | undefined)[]): string[] {
  // Boolean как функция-фильтр — TypeScript сужает тип элементов
  return values.filter(Boolean) as string[];

  // Эквивалент с !!:
  // return values.filter(v => !!v) as string[];
}
```

### 3.4 Сужение с логическими операторами

```ts
function greet(name?: string) {
  // Логическое И: правая часть выполнится только если name truthy
  name && console.log(name.toUpperCase()); // name: string в правой части

  // Nullish coalescing: сужает только null | undefined
  const displayName = name ?? "Anonymous";
  // displayName: string — undefined исключён через ??
}
```

## 4. Equality narrowing

### 4.1 Строгое равенство (`===`, `!==`)

При сравнении с конкретным значением TypeScript сужает тип до литерального:

```ts
function handle(status: "success" | "error" | "pending") {
  if (status === "success") {
    // status: "success" — литеральный тип
    console.log("Completed!");
  } else {
    // status: "error" | "pending" — "success" исключён
  }
}
```

### 4.2 Сравнение двух переменных

Когда две переменные с разными union-типами сравниваются через `===`, TypeScript
вычисляет их **пересечение**:

```ts
function compare(a: string | number, b: string | boolean) {
  if (a === b) {
    // Единственный общий тип — string
    // a: string, b: string
    console.log(a.toUpperCase(), b.toLowerCase());
  }
}
```

### 4.3 Нестрогое равенство и `== null`

Оператор `==` в JavaScript приводит типы. TypeScript использует это **специфично**
для проверки `null` и `undefined`:

```ts
function process(value: string | null | undefined) {
  if (value == null) {
    // value: null | undefined
    // == null ловит И null, И undefined — это идиоматический паттерн
    return;
  }

  // value: string — оба null и undefined исключены
  console.log(value.trim());
}

// Обратное: != null исключает оба
function format(input: number | null | undefined) {
  if (input != null) {
    // input: number — null и undefined исключены одной проверкой
    return input.toFixed(2);
  }
  return "N/A";
}
```

**Важно:** паттерн `== null` (нестрогое сравнение) — это один из немногих случаев,
когда `==` предпочтительнее `===` в TypeScript, потому что он проверяет
одновременно `null` и `undefined`.

### 4.4 Сравнение с литералами и `switch`

```ts
type Direction = "north" | "south" | "east" | "west";

function move(dir: Direction) {
  switch (dir) {
    case "north":
      // dir: "north"
      break;
    case "south":
      // dir: "south"
      break;
    default:
      // dir: "east" | "west"
      break;
  }
}
```

## 5. `instanceof` narrowing

### 5.1 Принцип работы

Оператор `instanceof` проверяет, присутствует ли `Constructor.prototype` в цепочке
прототипов объекта. TypeScript использует это для сужения до конкретного класса:

```ts
class ApiError extends Error {
  statusCode: number;

  constructor(message: string, statusCode: number) {
    super(message);
    this.statusCode = statusCode;
  }
}

class ValidationError extends Error {
  fields: string[];

  constructor(message: string, fields: string[]) {
    super(message);
    this.fields = fields;
  }
}

function handleError(error: Error) {
  if (error instanceof ApiError) {
    // error: ApiError — доступен statusCode
    console.log(`API Error ${error.statusCode}: ${error.message}`);
  } else if (error instanceof ValidationError) {
    // error: ValidationError — доступен fields
    console.log(`Validation: ${error.fields.join(", ")}`);
  } else {
    // error: Error — базовый тип
    console.log(error.message);
  }
}
```

### 5.2 Работа с встроенными типами

```ts
function processValue(value: Date | RegExp | string) {
  if (value instanceof Date) {
    // value: Date
    console.log(value.getFullYear());
  } else if (value instanceof RegExp) {
    // value: RegExp
    console.log(value.source);
  } else {
    // value: string
    console.log(value.toUpperCase());
  }
}
```

### 5.3 Ограничение: `instanceof` не работает с интерфейсами

**Критически важный момент:** интерфейсы TypeScript не существуют в runtime — они
полностью стираются при компиляции. Поэтому `instanceof` невозможно применить
к интерфейсу:

```ts
interface Serializable {
  serialize(): string;
}

function process(obj: Serializable | string) {
  // if (obj instanceof Serializable) {} // Ошибка!
  // 'Serializable' only refers to a type, but is being used as a value here

  // Решение — использовать 'in' оператор или type guard:
  if (typeof obj === "string") {
    console.log(obj);
  } else {
    console.log(obj.serialize());
  }
}
```

## 6. `in` operator narrowing

### 6.1 Проверка наличия свойства

Оператор `in` проверяет, существует ли свойство в объекте (включая цепочку прототипов).
TypeScript использует это для сужения union-типов:

```ts
interface Fish {
  swim: () => void;
}

interface Bird {
  fly: () => void;
}

function move(animal: Fish | Bird) {
  if ("swim" in animal) {
    // animal: Fish — TypeScript знает, что swim есть только у Fish
    animal.swim();
  } else {
    // animal: Bird — swim отсутствует, значит это Bird
    animal.fly();
  }
}
```

### 6.2 Сужение с опциональными свойствами

Когда свойство присутствует в **обоих** типах (пусть и опционально), сужение работает
иначе:

```ts
interface Human {
  swim?: () => void;
  speak: () => void;
}

interface Fish {
  swim: () => void;
}

function interact(entity: Human | Fish) {
  if ("swim" in entity) {
    // entity: Human | Fish — оба типа МОГУТ иметь swim
    // Human имеет swim как опциональное свойство
  }

  if ("speak" in entity) {
    // entity: Human — speak есть только у Human
    entity.speak();
  }
}
```

### 6.3 Ловушка: унаследованные свойства

Оператор `in` проверяет **всю цепочку прототипов**, что может привести к неожиданным
результатам:

```ts
interface WithToString {
  toString(): string;
  customProp: number;
}

interface Simple {
  value: string;
}

function check(obj: WithToString | Simple) {
  if ("toString" in obj) {
    // obj: WithToString | Simple — toString есть у ВСЕХ объектов!
    // Сужение не произошло, потому что toString унаследован от Object.prototype
  }

  if ("customProp" in obj) {
    // obj: WithToString — customProp уникален для WithToString
    console.log(obj.customProp);
  }
}
```

### 6.4 Паттерн для API-ответов

```ts
interface SuccessResponse {
  data: unknown;
  status: "ok";
}

interface ErrorResponse {
  error: string;
  code: number;
}

function handleResponse(res: SuccessResponse | ErrorResponse) {
  if ("data" in res) {
    // res: SuccessResponse
    console.log("Success:", res.data);
  } else {
    // res: ErrorResponse
    console.log(`Error ${res.code}: ${res.error}`);
  }
}
```

## 7. Discriminated Unions (Дискриминантные объединения)

### 7.1 Концепция

**Discriminated Union** (размеченное объединение) — паттерн, при котором каждый
член union-типа имеет общее **литеральное** свойство (дискриминант), позволяющее
однозначно идентифицировать конкретный тип.

Требования к дискриминанту:
- Свойство должно быть **литерального типа** (`string literal`, `number literal`, `boolean literal`)
- Свойство должно быть **не опциональным**
- Свойство должно присутствовать во **всех** членах union

```ts
interface Circle {
  kind: "circle";    // дискриминант
  radius: number;
}

interface Rectangle {
  kind: "rectangle"; // дискриминант
  width: number;
  height: number;
}

interface Triangle {
  kind: "triangle";  // дискриминант
  base: number;
  height: number;
}

type Shape = Circle | Rectangle | Triangle;

function area(shape: Shape): number {
  switch (shape.kind) {
    case "circle":
      // shape: Circle
      return Math.PI * shape.radius ** 2;
    case "rectangle":
      // shape: Rectangle
      return shape.width * shape.height;
    case "triangle":
      // shape: Triangle
      return (shape.base * shape.height) / 2;
  }
}
```

### 7.2 Множественные дискриминанты

Можно использовать **несколько** свойств как дискриминанты для более точного сужения:

```ts
interface HttpSuccess {
  status: "success";
  method: "GET" | "POST";
  data: unknown;
}

interface HttpRedirect {
  status: "redirect";
  method: "GET";
  location: string;
}

interface HttpError {
  status: "error";
  method: "GET" | "POST" | "DELETE";
  code: number;
  message: string;
}

type HttpResponse = HttpSuccess | HttpRedirect | HttpError;

function handle(res: HttpResponse) {
  if (res.status === "success" && res.method === "POST") {
    // res: HttpSuccess, res.method: "POST"
    console.log("POST success:", res.data);
  }
}
```

### 7.3 Redux actions — классический пример

```ts
interface FetchStart {
  type: "FETCH_START";
}

interface FetchSuccess {
  type: "FETCH_SUCCESS";
  payload: { items: string[]; total: number };
}

interface FetchError {
  type: "FETCH_ERROR";
  error: string;
}

type FetchAction = FetchStart | FetchSuccess | FetchError;

interface State {
  loading: boolean;
  items: string[];
  error: string | null;
}

function reducer(state: State, action: FetchAction): State {
  switch (action.type) {
    case "FETCH_START":
      // action: FetchStart
      return { ...state, loading: true, error: null };
    case "FETCH_SUCCESS":
      // action: FetchSuccess — payload доступен
      return { ...state, loading: false, items: action.payload.items };
    case "FETCH_ERROR":
      // action: FetchError — error доступен
      return { ...state, loading: false, error: action.error };
  }
}
```

### 7.4 Паттерн конечного автомата (State Machine)

```ts
type ConnectionState =
  | { status: "disconnected" }
  | { status: "connecting"; attempt: number }
  | { status: "connected"; socket: WebSocket }
  | { status: "error"; error: Error; retryAfter: number };

function renderStatus(state: ConnectionState): string {
  switch (state.status) {
    case "disconnected":
      return "Offline";
    case "connecting":
      return `Connecting (attempt ${state.attempt})...`;
    case "connected":
      return `Online (${state.socket.url})`;
    case "error":
      return `Error: ${state.error.message}. Retry in ${state.retryAfter}s`;
  }
}
```

## 8. Пользовательские type guards (`is`)

### 8.1 Type predicate функции

Когда встроенных механизмов сужения недостаточно, можно создать **пользовательский
type guard** — функцию, возвращающую `value is Type`:

```ts
interface Cat {
  meow(): void;
  purr(): void;
}

interface Dog {
  bark(): void;
  fetch(): void;
}

// Type predicate: возвращаемый тип "animal is Cat"
function isCat(animal: Cat | Dog): animal is Cat {
  return "meow" in animal;
}

function interact(animal: Cat | Dog) {
  if (isCat(animal)) {
    // animal: Cat — TypeScript доверяет нашей проверке
    animal.purr();
  } else {
    // animal: Dog — автоматическое сужение в else
    animal.bark();
  }
}
```

### 8.2 Type guard для фильтрации массивов

Одно из самых полезных применений — типизированная фильтрация:

```ts
function isNonNull<T>(value: T | null | undefined): value is T {
  return value != null;
}

const mixed: (string | null | undefined)[] = ["hello", null, "world", undefined];

// Без type guard: filtered имеет тип (string | null | undefined)[]
const wrong = mixed.filter(v => v != null);

// С type guard: filtered имеет тип string[]
const filtered = mixed.filter(isNonNull);
// filtered: string[] — точный тип!
```

### 8.3 Assertion functions (`asserts`)

TypeScript 3.7 добавил **assertion functions** — функции, которые бросают исключение,
если условие не выполнено, и сужают тип после вызова:

```ts
// asserts value is Type — сужает тип ИЛИ бросает ошибку
function assertIsString(value: unknown): asserts value is string {
  if (typeof value !== "string") {
    throw new Error(`Expected string, got ${typeof value}`);
  }
}

function process(input: unknown) {
  assertIsString(input);
  // После вызова: input: string — TypeScript верит assertion
  console.log(input.toUpperCase());
}

// asserts condition — аналог Node.js assert
function assert(condition: unknown, msg?: string): asserts condition {
  if (!condition) {
    throw new Error(msg ?? "Assertion failed");
  }
}

function divide(a: number, b: number | null) {
  assert(b !== null, "Divisor must not be null");
  // b: number — null исключён assertion-ом
  return a / b;
}
```

### 8.4 Когда что использовать

| Механизм                    | Когда применять                                                      |
| --------------------------- | -------------------------------------------------------------------- |
| `value is Type`             | Проверка в условии, фильтрация массивов, переиспользуемые проверки   |
| `asserts value is Type`     | Валидация на входе функции, guard clauses, fail-fast паттерн         |
| `asserts condition`         | Проверка инвариантов, контрактное программирование                    |

**Важно:** TypeScript **не проверяет** корректность реализации type guard. Если функция
объявляет `value is Cat`, но внутри проверяет неправильно — компилятор не предупредит.
Ответственность за корректность лежит на разработчике.

## 9. `satisfies` оператор

### 9.1 Проблема, которую решает `satisfies`

До TypeScript 4.9 существовал выбор: либо аннотировать тип (и потерять литеральные
типы), либо не аннотировать (и потерять проверку):

```ts
type Color = "red" | "green" | "blue";
type ColorMap = Record<string, Color | Color[]>;

// Вариант 1: аннотация типа — теряем информацию о ключах
const palette1: ColorMap = {
  primary: "red",
  secondary: ["green", "blue"],
};
// palette1.primary имеет тип Color | Color[] — неизвестно, что это string!

// Вариант 2: без аннотации — нет проверки на Color
const palette2 = {
  primary: "red",
  secondary: ["green", "blue"],
  accent: "yellow", // Ошибка не обнаружена!
};
```

### 9.2 Решение: `satisfies`

Оператор `satisfies` (TS 4.9+) проверяет совместимость с типом, **не расширяя** его:

```ts
type Color = "red" | "green" | "blue";
type ColorMap = Record<string, Color | Color[]>;

const palette = {
  primary: "red",
  secondary: ["green", "blue"],
  // accent: "yellow", // Ошибка! "yellow" не входит в Color
} satisfies ColorMap;

// palette.primary: "red" — литеральный тип сохранён!
// palette.secondary: ("green" | "blue")[] — массив конкретных цветов

// Методы строки доступны без приведения:
const upper = palette.primary.toUpperCase(); // OK: palette.primary — string
```

### 9.3 `satisfies` vs аннотация типа

| Аспект                  | `const x: Type = ...`          | `const x = ... satisfies Type`         |
| ----------------------- | ------------------------------ | -------------------------------------- |
| Проверка совместимости  | Да                             | Да                                     |
| Тип переменной          | Расширяется до `Type`          | Сохраняется выведенный (узкий) тип     |
| Литеральные типы        | Теряются                       | Сохраняются                            |
| Автодополнение ключей   | По `Type`                      | По фактическим ключам объекта          |
| Excess property check   | Да                             | Да                                     |

### 9.4 Практические применения

```ts
// Конфигурация с проверкой типов и сохранением литералов
interface RouteConfig {
  path: string;
  method: "GET" | "POST" | "PUT" | "DELETE";
  auth: boolean;
}

const routes = {
  getUsers: { path: "/users", method: "GET", auth: true },
  createUser: { path: "/users", method: "POST", auth: true },
  health: { path: "/health", method: "GET", auth: false },
} satisfies Record<string, RouteConfig>;

// routes.getUsers.method: "GET" — не просто string, а литерал!
// routes.health.auth: false — не просто boolean, а литерал false!

// Совмещение с as const для максимальной точности:
const config = {
  port: 3000,
  host: "localhost",
} as const satisfies { port: number; host: string };
// config.port: 3000 (readonly литерал)
```

## 10. Exhaustiveness checking

### 10.1 Тип `never` как индикатор полноты

Когда все варианты union-типа обработаны, TypeScript сужает остаток до `never` —
типа, не имеющего значений. Это можно использовать для **проверки полноты обработки**:

```ts
type Shape = Circle | Rectangle | Triangle;

function area(shape: Shape): number {
  switch (shape.kind) {
    case "circle":
      return Math.PI * shape.radius ** 2;
    case "rectangle":
      return shape.width * shape.height;
    case "triangle":
      return (shape.base * shape.height) / 2;
    default:
      // shape: never — если все варианты обработаны
      const _exhaustive: never = shape;
      return _exhaustive;
  }
}
```

Если добавить новый вариант в `Shape` (например, `Pentagon`), но забыть обработать
его в `switch` — компилятор выдаст ошибку на строке `const _exhaustive: never = shape`,
потому что `shape` будет иметь тип `Pentagon`, который нельзя присвоить `never`.

### 10.2 Паттерн `assertNever`

Вынесение проверки в переиспользуемую функцию:

```ts
function assertNever(value: never, message?: string): never {
  throw new Error(message ?? `Unexpected value: ${JSON.stringify(value)}`);
}

type PaymentMethod = "card" | "paypal" | "crypto" | "bank_transfer";

function processPayment(method: PaymentMethod): string {
  switch (method) {
    case "card":
      return "Processing card payment...";
    case "paypal":
      return "Redirecting to PayPal...";
    case "crypto":
      return "Generating wallet address...";
    case "bank_transfer":
      return "Generating bank details...";
    default:
      // Если забыли case — ошибка компиляции
      return assertNever(method);
  }
}
```

### 10.3 Почему exhaustiveness checking критичен

**Без exhaustiveness checking** добавление нового варианта в union может привести
к тихим ошибкам в runtime:

```ts
// 1. Разработчик добавляет "bank_transfer" в PaymentMethod
// 2. Без exhaustiveness checking код компилируется без ошибок
// 3. В runtime processPayment("bank_transfer") возвращает undefined
// 4. Баг обнаруживается только в production

// С exhaustiveness checking:
// 1. Разработчик добавляет "bank_transfer" в PaymentMethod
// 2. Компилятор СРАЗУ показывает ошибки во всех switch/if по этому типу
// 3. Разработчик добавляет обработку ДО деплоя
```

### 10.4 Exhaustiveness в if/else цепочках

Паттерн работает не только в `switch`, но и в цепочках `if/else`:

```ts
type LogLevel = "debug" | "info" | "warn" | "error";

function logColor(level: LogLevel): string {
  if (level === "debug") return "\x1b[36m";   // cyan
  if (level === "info")  return "\x1b[32m";   // green
  if (level === "warn")  return "\x1b[33m";   // yellow
  if (level === "error") return "\x1b[31m";   // red

  // level: never — все варианты покрыты
  return assertNever(level);
}
```

### 10.5 Сводная таблица механизмов сужения

| Механизм                    | Работает в runtime | Сужает интерфейсы | Exhaustiveness |
| --------------------------- | ------------------ | ----------------- | -------------- |
| `typeof`                    | Да                 | Нет               | Нет            |
| Truthiness (`if (x)`)       | Да                 | Нет               | Нет            |
| `===` / `!==`               | Да                 | Нет               | Нет            |
| `instanceof`                | Да                 | Нет               | Нет            |
| `in`                        | Да                 | Да                | Нет            |
| Discriminated Unions        | Да                 | Да                | Да             |
| Type guards (`is`)          | Да                 | Да                | Нет            |
| `asserts`                   | Да                 | Да                | Нет            |
| `satisfies`                 | Нет (compile-time) | —                 | —              |
| `never` exhaustiveness      | Опционально        | Да                | Да             |
