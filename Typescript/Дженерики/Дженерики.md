# Дженерики (Generics) — полное руководство

> Дженерики — механизм **параметрического полиморфизма** в TypeScript.
> Они позволяют писать код, абстрагированный от конкретных типов, сохраняя
> полную типобезопасность. Без дженериков — выбор между дублированием и `any`.

## 1. Основы дженериков

### 1.1 Зачем нужны дженерики

Без дженериков функция теряет связь между входом и выходом:

```ts
function identity(value: any): any { return value; }
const a = identity("hello"); // a: any — информация потеряна

function identity<T>(value: T): T { return value; }
const b = identity("hello"); // b: "hello" — литеральный тип сохранён
```

**Ключевой принцип**: дженерик — **переменная уровня типов**. `T` объявляется при определении, конкретный тип подставляется при использовании.

### 1.2 Синтаксис type parameter

```ts
// Функция — параметр перед аргументами
function map<T, U>(arr: T[], fn: (item: T) => U): U[] { return arr.map(fn); }

// Стрелочная функция — <T,> с запятой для JSX-совместимости
const toArray = <T,>(value: T): T[] => [value];

// Интерфейс и класс — параметр после имени
interface Repository<T> {
  getById(id: string): Promise<T>;
  save(entity: T): Promise<void>;
}

class Stack<T> {
  private items: T[] = [];
  push(item: T): void { this.items.push(item); }
  pop(): T | undefined { return this.items.pop(); }
}

const nums = new Stack<number>();
nums.push(42);
nums.push("x"); // Error: 'string' is not assignable to 'number'
```

### 1.3 Когда дженерик нужен, а когда нет

| Ситуация | Решение | Причина |
|----------|---------|---------|
| Связь вход-выход | Дженерик | Тип результата зависит от аргумента |
| Связь между аргументами | Дженерик | Аргументы должны быть совместимы |
| Нет зависимости | `unknown` | Дженерик избыточен |
| Коллекция однотипных элементов | Дженерик | Тип элемента параметризуется |

**Правило**: если `T` используется **один раз** в сигнатуре — замените на `unknown`:

```ts
function bad<T>(value: T): void { console.log(value); }   // T один раз
function good(value: unknown): void { console.log(value); } // лучше
```

## 2. Ограничения (Constraints)

### 2.1 Базовый синтаксис `T extends U`

Без ограничения TS считает `T` эквивалентным `unknown` — свойства недоступны:

```ts
function getLength<T>(value: T): number { return value.length; } // Error

function getLength<T extends { length: number }>(value: T): number {
  return value.length; // OK — TS знает, что у T есть length
}

getLength("hello");   // OK
getLength([1, 2, 3]); // OK
getLength(42);         // Error: number не имеет length
```

### 2.2 Ограничение через `keyof`

```ts
function getProp<T, K extends keyof T>(obj: T, key: K): T[K] {
  return obj[key];
}

const user = { name: "Alice", age: 30 };
getProp(user, "name");    // string
getProp(user, "missing"); // Error: '"missing"' not assignable to '"name" | "age"'
```

**Важно**: `T[K]` — **indexed access type**, возвращает точный тип свойства `K`.

### 2.3 Множественные ограничения и bounded polymorphism

```ts
interface Serializable { serialize(): string; }
interface Identifiable { id: string; }

// Пересечение: T реализует оба интерфейса
function save<T extends Serializable & Identifiable>(entity: T): void {
  console.log(`Saving ${entity.id}: ${entity.serialize()}`);
}

// Bounded polymorphism: один параметр ограничен другим
function assign<T extends object, U extends Partial<T>>(target: T, source: U): T & U {
  return Object.assign(target, source);
}
```

### 2.4 Ошибка: избыточные ограничения

```ts
// Плохо: дженерик не даёт преимущества
function process<T extends string[]>(items: T): void { /* ... */ }
// Лучше:
function process(items: string[]): void { /* ... */ }

// Дженерик оправдан при сохранении подтипа:
function first<T extends readonly unknown[]>(arr: T): T[0] { return arr[0]; }
const f = first([1, "hello", true] as const); // f: 1
```

## 3. Значения по умолчанию (Default Type Parameters)

### 3.1 Синтаксис

```ts
interface Container<T = string> { value: T; }

const a: Container = { value: "hello" };        // T = string (default)
const b: Container<number> = { value: 42 };     // T = number (явно)

type ApiResponse<TData = unknown, TError = Error> = {
  data: TData | null;
  error: TError | null;
};
```

### 3.2 Правила порядка

Параметры с default **должны** стоять после обязательных:

```ts
interface Cache<T, TKey = string> {       // OK
  get(key: TKey): T | undefined;
}
// interface Bad<T = string, U> { }       // Error: required after optional
```

### 3.3 Приоритет: вывод vs default

Выведенный из аргументов тип **всегда** побеждает значение по умолчанию:

```ts
function createState<T = string>(initial: T) {
  let state = initial;
  return { get: () => state, set: (v: T) => { state = v; } };
}
const counter = createState(0); // T = number, default игнорируется
counter.set("x"); // Error: string не assignable к number
```

Default должен удовлетворять constraint:

```ts
interface Component<T extends Element = HTMLElement> { render(): T; } // OK
// interface Bad<T extends Element = string> { }  // Error
```

| Сценарий | Результат |
|----------|-----------|
| Явно указан тип | Используется указанный |
| Выводится из аргументов | Выведенный, default игнорируется |
| Нет ни явного, ни вывода | Используется default |
| Default нарушает constraint | Ошибка компиляции |

## 4. Вывод типов дженериков (Generic Inference)

### 4.1 Вывод из аргументов

TS выводит параметры из фактических аргументов через алгоритм унификации:

```ts
function merge<T, U>(a: T, b: U): T & U { return { ...a, ...b }; }
const m = merge({ name: "Alice" }, { age: 30 }); // { name: string } & { age: number }
```

### 4.2 Множественные inference sites

Когда `T` встречается в нескольких позициях, TS ищет **best common type**:

```ts
function choose<T>(a: T, b: T): T { return Math.random() > 0.5 ? a : b; }
choose(1, 2);       // T = number
choose(1, "hello"); // T = string | number
```

### 4.3 Контекстная типизация из коллбэков

```ts
declare function transform<T, U>(value: T, fn: (input: T) => U): U;
const len = transform("hello", (input) => input.length);
// T = string (из "hello"), U = number (из return), input: string
```

### 4.4 Провал вывода и partial inference

```ts
function createMap<K, V>(): Map<K, V> { return new Map(); }
const m1 = createMap();                // Map<unknown, unknown>
const m2 = createMap<string, number>(); // OK, ручное указание

// Partial inference невозможна: createMap<string>() — Error
// Решение: каррирование
function createMapFor<K>() {
  return <V>(): Map<K, V> => new Map();
}
const m3 = createMapFor<string>()<number>(); // Map<string, number>
```

### 4.5 Сохранение литеральных типов

```ts
function literal<T extends string>(value: T): T { return value; }
const a = literal("hello"); // "hello", не string

function tuple<T extends readonly unknown[]>(...args: T): T { return args; }
const t = tuple("hello", 42, true); // readonly ["hello", 42, true]
```

### 4.6 `const` type parameters (TS 5.0)

Модификатор `const` перед type parameter заставляет TS выводить **литеральные типы** для аргументов — без необходимости писать `as const` на стороне вызова:

```ts
// Без const — выводится широкий тип
function routes<T extends readonly string[]>(paths: T): T { return paths; }
const r1 = routes(["home", "about"]); // type: string[]

// С const — выводится литеральный кортеж
function routes<const T extends readonly string[]>(paths: T): T { return paths; }
const r2 = routes(["home", "about"]); // type: readonly ["home", "about"]
```

Работает с любыми литеральными типами — строки, числа, объекты:

```ts
function config<const T extends Record<string, unknown>>(cfg: T): T { return cfg; }
const c = config({ retries: 3, env: "prod" });
// type: { readonly retries: 3; readonly env: "prod" }
```

**Когда использовать**: когда нужно сохранить точные литеральные типы аргументов — маршруты, конфигурации, константные массивы.

### 4.7 `NoInfer<T>` (TS 5.4)

Утилитарный тип `NoInfer<T>` запрещает вывод типа из определённой позиции. TS будет выводить `T` только из **других** позиций, а обёрнутая в `NoInfer` — станет проверкой:

```ts
// Без NoInfer — TS выводит S из обеих позиций, допуская невалидное значение
function createFSM<S extends string>(config: {
  initial: S;
  states: S[];
}) {}
createFSM({ initial: "unknown", states: ["idle", "loading"] }); // OK — S = "unknown" | "idle" | "loading"

// С NoInfer — initial не участвует в выводе, а проверяется
function createFSM<S extends string>(config: {
  initial: NoInfer<S>;
  states: S[];
}) {}
createFSM({ initial: "unknown", states: ["idle", "loading"] }); // Error: "unknown" not assignable to "idle" | "loading"
createFSM({ initial: "idle", states: ["idle", "loading"] });    // OK
```

Ещё пример — приоритет вывода в функции с default-значением:

```ts
function highlight<T extends string>(items: T[], preferred: NoInfer<T>): T {
  return items.includes(preferred) ? preferred : items[0];
}
highlight(["red", "green", "blue"], "red");    // OK
highlight(["red", "green", "blue"], "yellow"); // Error
```

**Когда использовать**: когда один аргумент должен **зависеть** от типа другого, а не влиять на его вывод.

## 5. Условные типы (Conditional Types)

### 5.1 Базовый синтаксис

Тернарный оператор уровня типов — `T extends U ? X : Y`:

```ts
type IsString<T> = T extends string ? true : false;
type A = IsString<"hello">; // true
type B = IsString<42>;      // false
```

### 5.2 Дистрибутивные условные типы

При передаче union в голый параметр тип **распределяется** по членам:

```ts
type ToArray<T> = T extends unknown ? T[] : never;
type R = ToArray<string | number>; // string[] | number[]
// Без дистрибуции было бы (string | number)[]
```

### 5.3 Отключение дистрибуции через `[T] extends [U]`

```ts
type ToArrayNonDist<T> = [T] extends [unknown] ? T[] : never;
type R = ToArrayNonDist<string | number>; // (string | number)[]

// Проверка на never — обязательно через кортеж
type IsNever<T> = [T] extends [never] ? true : false;
type A = IsNever<never>;  // true

// Без кортежа дистрибуция по пустому union даёт never:
type Bad<T> = T extends never ? true : false;
type B = Bad<never>; // never (!) — не true
```

### 5.4 Вложенные условные типы и практические паттерны

```ts
type TypeName<T> =
  T extends string ? "string" :
  T extends number ? "number" :
  T extends boolean ? "boolean" :
  T extends Function ? "function" : "object";

type ElementOf<T> = T extends readonly (infer E)[] ? E : never;
type UnwrapPromise<T> = T extends Promise<infer U> ? UnwrapPromise<U> : T;

type A = UnwrapPromise<Promise<Promise<string>>>; // string
type B = ElementOf<readonly [1, 2, 3]>;           // 1 | 2 | 3
```

## 6. Ключевое слово `infer`

### 6.1 Вывод типа внутри conditional type

`infer` объявляет переменную типа, заполняемую при проверке `extends`:

```ts
type ReturnOf<T> = T extends (...args: any[]) => infer R ? R : never;
type A = ReturnOf<() => string>;           // string
type B = ReturnOf<(x: number) => boolean>; // boolean

type ParamsOf<T> = T extends (...args: infer P) => any ? P : never;
type C = ParamsOf<(a: string, b: number) => void>; // [string, number]
```

### 6.2 Вывод элементов кортежа

```ts
type Head<T extends readonly unknown[]> =
  T extends readonly [infer F, ...unknown[]] ? F : never;
type Last<T extends readonly unknown[]> =
  T extends readonly [...unknown[], infer L] ? L : never;
type Tail<T extends readonly unknown[]> =
  T extends readonly [unknown, ...infer R] ? R : never;

type A = Head<[1, 2, 3]>; // 1
type B = Last<[1, 2, 3]>; // 3
type C = Tail<[1, 2, 3]>; // [2, 3]
```

### 6.3 Вывод из шаблонных строковых типов

```ts
type Split<T extends string> =
  T extends `${infer H}/${infer R}` ? [H, ...Split<R>] : [T];
type A = Split<"api/users/123">; // ["api", "users", "123"]

type RouteParams<T extends string> =
  T extends `${string}:${infer P}/${infer R}` ? P | RouteParams<R>
  : T extends `${string}:${infer P}` ? P : never;
type B = RouteParams<"/users/:id/posts/:postId">; // "id" | "postId"
```

### 6.4 Ковариантные и контравариантные позиции

```ts
// Ковариантная (свойства) — даёт union
type Cov<T> = T extends { a: infer U; b: infer U } ? U : never;
type A = Cov<{ a: string; b: number }>; // string | number

// Контравариантная (параметры функций) — даёт intersection
type Contra<T> = T extends {
  a: (x: infer U) => void; b: (x: infer U) => void;
} ? U : never;
type B = Contra<{
  a: (x: { name: string }) => void;
  b: (x: { age: number }) => void;
}>; // { name: string } & { age: number }
```

| Позиция | Вариантность | Результат |
|---------|-------------|-----------|
| Свойство, return type | Ковариантная | `A \| B` |
| Параметр функции | Контравариантная | `A & B` |

## 7. Mapped Types

### 7.1 Базовый синтаксис и модификаторы

```ts
type MyReadonly<T> = { readonly [K in keyof T]: T[K] };
type MyPartial<T> = { [K in keyof T]?: T[K] };
type Mutable<T> = { -readonly [K in keyof T]: T[K] };
type Required<T> = { [K in keyof T]-?: T[K] };
```

### 7.2 Переименование ключей с `as` (Key Remapping)

```ts
type Getters<T> = {
  [K in keyof T as `get${Capitalize<string & K>}`]: () => T[K];
};
type PG = Getters<{ name: string; age: number }>;
// { getName: () => string; getAge: () => number }

// Фильтрация: never исключает ключ
type OnlyStrings<T> = {
  [K in keyof T as T[K] extends string ? K : never]: T[K];
};

// Комбинация: хэндлеры событий
type Handlers<T> = {
  [K in keyof T as K extends string ? `on${Capitalize<K>}Change` : never]:
    (newVal: T[K], oldVal: T[K]) => void;
};
```

### 7.3 Рекурсивные mapped types

```ts
type DeepReadonly<T> = T extends Function ? T
  : T extends object ? { readonly [K in keyof T]: DeepReadonly<T[K]> } : T;

type DeepPartial<T> = T extends Function ? T
  : T extends object ? { [K in keyof T]?: DeepPartial<T[K]> } : T;

interface Config { server: { host: string; ssl: { enabled: boolean } } }
declare function merge(base: Config, patch: DeepPartial<Config>): Config;
merge(cfg, { server: { ssl: { enabled: true } } }); // OK — все поля опциональны
```

### 7.4 Mapped type над discriminated union

```ts
type ActionMap<T extends { type: string }> = {
  [K in T["type"]]: Extract<T, { type: K }>;
};
type Actions = { type: "inc"; n: number } | { type: "reset" };
type M = ActionMap<Actions>;
// { inc: { type: "inc"; n: number }; reset: { type: "reset" } }
```

## 8. Дженерики в практике

### 8.1 Типобезопасная система событий

```ts
interface EventMap {
  "user:login": { userId: string; ts: number };
  "user:logout": { userId: string };
  "error": { message: string; code: number };
}

class TypedEmitter<T extends Record<string, unknown>> {
  private ls = new Map<keyof T, Set<Function>>();

  on<K extends keyof T>(ev: K, fn: (p: T[K]) => void): () => void {
    if (!this.ls.has(ev)) this.ls.set(ev, new Set());
    this.ls.get(ev)!.add(fn);
    return () => { this.ls.get(ev)?.delete(fn); };
  }

  emit<K extends keyof T>(ev: K, payload: T[K]): void {
    this.ls.get(ev)?.forEach(fn => fn(payload));
  }
}

const bus = new TypedEmitter<EventMap>();
bus.on("user:login", (p) => console.log(p.userId)); // payload типизирован
bus.emit("user:login", { userId: "1" });              // Error: нет ts
```

### 8.2 Типобезопасный API-клиент

```ts
interface Endpoints {
  "GET /users": { res: User[]; query: { page: number; limit: number } };
  "POST /users": { res: User; body: CreateUserDto };
  "GET /users/:id": { res: User; params: { id: string } };
}

type Opts<K extends keyof Endpoints> =
  (Endpoints[K] extends { params: infer P } ? { params: P } : {}) &
  (Endpoints[K] extends { query: infer Q } ? { query: Q } : {}) &
  (Endpoints[K] extends { body: infer B } ? { body: B } : {});

class Api {
  request<K extends keyof Endpoints>(ep: K, opts: Opts<K>): Promise<Endpoints[K]["res"]> {
    return {} as any;
  }
}

const api = new Api();
await api.request("GET /users", { query: { page: 1, limit: 10 } }); // User[]
await api.request("GET /users/:id", { params: { id: "1" } });        // User
```

### 8.3 Builder с отслеживанием состояния

```ts
class QB<S extends Record<string, unknown> = {}> {
  private cfg: Record<string, unknown> = {};

  from<T extends string>(t: T): QB<S & { table: T }> {
    this.cfg.table = t;
    return this as any;
  }

  where(c: string): QB<S & { where: true }> {
    ((this.cfg.conds ??= []) as string[]).push(c);
    return this as any;
  }

  execute(this: QB<S & { table: string }>): string {
    return `SELECT * FROM ${this.cfg.table}`;
  }
}

new QB().from("users").where("age > 18").execute(); // OK
// new QB().execute(); // Error — table не задан
```

### 8.4 Generic React-компоненты и хуки

```ts
interface ListProps<T> {
  items: T[];
  renderItem: (item: T, i: number) => React.ReactNode;
  keyExtractor: (item: T) => string;
  onItemClick?: (item: T) => void;
}

function List<T>({ items, renderItem, keyExtractor, onItemClick }: ListProps<T>) {
  return (
    <ul>{items.map((item, i) => (
      <li key={keyExtractor(item)} onClick={() => onItemClick?.(item)}>
        {renderItem(item, i)}
      </li>
    ))}</ul>
  );
}

// T = User выведен из items
<List items={users} renderItem={(u) => <span>{u.name}</span>} keyExtractor={(u) => u.id} />

function useForm<T extends Record<string, unknown>>(init: T) {
  const [vals, setVals] = React.useState(init);
  const set = <K extends keyof T>(k: K, v: T[K]) =>
    setVals(p => ({ ...p, [k]: v }));
  return { vals, set } as const;
}

const f = useForm({ name: "", age: 0 });
f.set("name", "Alice"); // OK
f.set("age", "old");    // Error: string не assignable к number
f.set("xxx", true);     // Error: "xxx" не существует
```

## 9. Аннотации вариантности `in`/`out` (TS 4.7)

### 9.1 Зачем нужны аннотации вариантности

По умолчанию TS определяет вариантность type parameter **структурно**, анализируя все позиции, в которых он используется. Это может быть медленно для сложных типов и иногда приводит к неожиданным результатам. Аннотации `in`/`out` позволяют **явно** указать вариантность, давая два преимущества:

- **Проверка корректности**: компилятор убедится, что параметр используется только в допустимых позициях.
- **Производительность**: TS пропускает структурный анализ вариантности, ускоряя проверку типов.

### 9.2 Синтаксис

| Аннотация | Вариантность | Позиция использования |
|-----------|-------------|----------------------|
| `out T` | Ковариантная | Только на выходе (return type, свойства) |
| `in T` | Контравариантная | Только на входе (параметры функций) |
| `in out T` | Инвариантная | И на входе, и на выходе |

```ts
// Ковариантный — T только на выходе (производит значения)
interface Producer<out T> {
  get(): T;
}

// Контравариантный — T только на входе (потребляет значения)
interface Consumer<in T> {
  accept(value: T): void;
}

// Инвариантный — T и на входе, и на выходе
interface Storage<in out T> {
  get(): T;
  set(value: T): void;
}
```

### 9.3 Как это влияет на совместимость типов

```ts
// Producer<Dog> assignable к Producer<Animal> — ковариантность
declare let animalProducer: Producer<Animal>;
declare let dogProducer: Producer<Dog>;
animalProducer = dogProducer; // OK — Dog extends Animal

// Consumer<Animal> assignable к Consumer<Dog> — контравариантность
declare let animalConsumer: Consumer<Animal>;
declare let dogConsumer: Consumer<Dog>;
dogConsumer = animalConsumer; // OK — Animal «шире» Dog

// Storage<Dog> НЕ assignable к Storage<Animal> — инвариантность
declare let animalStorage: Storage<Animal>;
declare let dogStorage: Storage<Dog>;
animalStorage = dogStorage; // Error
dogStorage = animalStorage; // Error
```

### 9.4 Ошибка при неправильном использовании

Если аннотация не соответствует фактическому использованию, TS выдаёт ошибку:

```ts
interface Broken<out T> {
  consume(value: T): void; // Error: T используется во входной позиции, но помечен как out
}
```

**Когда использовать**: в библиотечном коде со сложными иерархиями типов, где важна и корректность, и скорость компиляции. Для простых дженериков аннотации необязательны — TS справится сам.
