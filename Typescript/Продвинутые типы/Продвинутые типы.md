# Продвинутые типы TypeScript

> Система типов TypeScript тьюринг-полна: она способна выполнять произвольные вычисления
> на уровне типов. Продвинутые типы позволяют строить **type-safe** абстракции, где
> невозможные состояния непредставимы.

## 1. Template Literal Types

Template literal types конструируют строковые типы через шаблонную интерполяцию. Компилятор **раскрывает** каждую комбинацию union-типов внутри шаблона, формируя итоговый union.

```typescript
type Greeting = `Hello, ${string}`;  // любая строка "Hello, ..."
type Version = `v${number}`;         // "v1", "v2.5" и т.д.

// Декартово произведение union-типов
type Color = "red" | "blue" | "green";
type Size = "sm" | "md" | "lg";
type CSSClass = `${Color}-${Size}`;
// "red-sm" | "red-md" | "red-lg" | "blue-sm" | ... (9 комбинаций)

type Padding = `${number}${"px" | "rem" | "em"}`;
const p: Padding = "16px";   // OK
```

### Встроенные string manipulation types

| Тип                | Описание                        | Пример                              |
| ------------------ | ------------------------------- | ------------------------------------ |
| `Uppercase<S>`     | Все символы в верхний регистр   | `Uppercase<"hello">` → `"HELLO"`    |
| `Lowercase<S>`     | Все символы в нижний регистр    | `Lowercase<"HELLO">` → `"hello"`    |
| `Capitalize<S>`    | Первый символ в верхний регистр | `Capitalize<"hello">` → `"Hello"`   |
| `Uncapitalize<S>`  | Первый символ в нижний регистр  | `Uncapitalize<"Hello">` → `"hello"` |

```typescript
// Генерация event-handler имён
type EventName<T extends string> = `on${Capitalize<T>}`;
type ClickHandler = EventName<"click">;     // "onClick"
type Getter<T extends string> = `get${Capitalize<T>}`;
type NameGetter = Getter<"name">;           // "getName"
```

### Сложные паттерны: маршруты, CSS

```typescript
// Рекурсивный парсинг route-параметров
type ExtractParams<T extends string> =
  T extends `${string}:${infer Param}/${infer Rest}`
    ? Param | ExtractParams<Rest>
    : T extends `${string}:${infer Param}` ? Param : never;

type RouteParams = ExtractParams<"/api/:version/users/:userId">;
// "version" | "userId"

// CSS вендорные префиксы
type Vendor = "-webkit-" | "-moz-" | "";
type CSSProp = "transform" | "transition";
type PrefixedCSS = `${Vendor}${CSSProp}`;
// "transform" | "-webkit-transform" | "-moz-transform" | "transition" | ...
```

**Важно:** декартово произведение растёт экспоненциально. Union из 100+ членов в шаблоне приведёт к ошибке `Expression produces a union type that is too complex to represent`.

## 2. Variadic Tuple Types

Variadic tuple types (TS 4.0+) описывают **кортежи переменной длины** через spread `...T` на уровне типов. Это позволяет типизировать `concat`, `push`, `unshift` без потери информации о типах.

### Spread в кортежах и извлечение элементов

```typescript
type Head<T extends readonly unknown[]> =
  T extends readonly [infer H, ...unknown[]] ? H : never;

type Tail<T extends readonly unknown[]> =
  T extends readonly [unknown, ...infer R] ? R : never;

type Last<T extends readonly unknown[]> =
  T extends readonly [...infer _, infer L] ? L : never;

type A = Head<[1, 2, 3]>;   // 1
type B = Tail<[1, 2, 3]>;   // [2, 3]
type C = Last<[1, 2, 3]>;   // 3
```

### Typed concat и push

```typescript
type Concat<A extends readonly unknown[], B extends readonly unknown[]> = [...A, ...B];
type Push<T extends readonly unknown[], V> = [...T, V];
type Unshift<T extends readonly unknown[], V> = [V, ...T];

type R1 = Concat<[1, 2], [3, 4]>;   // [1, 2, 3, 4]
type R2 = Push<[1, 2], 3>;          // [1, 2, 3]
type R3 = Unshift<[1, 2], 0>;       // [0, 1, 2]
```

### Практическое применение: типизированный partial apply

```typescript
declare function bindFirst<A, B extends readonly unknown[], R>(
  fn: (a: A, ...rest: B) => R, a: A
): (...rest: B) => R;

function greet(name: string, age: number, city: string): string {
  return `${name}, ${age}, ${city}`;
}
const greetAlice = bindFirst(greet, "Alice");
// (age: number, city: string) => string

// Labeled tuple elements — улучшают подсказки IDE
type Range = [start: number, end: number];
type Entry = [key: string, ...values: number[]];
```

**Важно:** spread `...T` может стоять в любой позиции кортежа, но только **один** spread допустим.

## 3. `keyof` и Indexed Access Types

Оператор `keyof` извлекает union ключей типа. Indexed access `T[K]` читает тип по ключу. Вместе они — основа mapped types и type-safe доступа к свойствам.

```typescript
interface User {
  id: number;
  name: string;
  email: string;
  isAdmin: boolean;
}

type UserKeys = keyof User;  // "id" | "name" | "email" | "isAdmin"

// С index signature: string | number (obj[0] === obj["0"])
type DictKeys = keyof { [key: string]: unknown };  // string | number
```

### Indexed Access `T[K]`, вложенные обращения, `T[number]`

```typescript
type UserName = User["name"];                // string
type UserIdOrEmail = User["id" | "email"];   // number | string
type UserValues = User[keyof User];          // number | string | boolean

interface Config {
  db: { host: string; port: number; creds: { user: string; pass: string } };
}
type DBHost = Config["db"]["host"];             // string
type Password = Config["db"]["creds"]["pass"];  // string

// T[number] — тип элементов массива
const roles = ["admin", "editor", "viewer"] as const;
type Role = (typeof roles)[number];   // "admin" | "editor" | "viewer"

type Tuple = [string, number, boolean];
type TupleEl = Tuple[number];   // string | number | boolean
```

### Type-safe property accessor

```typescript
function getProperty<T, K extends keyof T>(obj: T, key: K): T[K] {
  return obj[key];
}
const user: User = { id: 1, name: "Alice", email: "a@b.com", isAdmin: true };
const name = getProperty(user, "name");   // string (не union!)
// getProperty(user, "age");               // Error: '"age"' not assignable to keyof User
```

| Выражение         | Результат                 | Описание                     |
| ------------------ | ------------------------ | ---------------------------- |
| `keyof T`          | union ключей             | Все ключи типа T            |
| `T[K]`             | тип значения по ключу    | Indexed access               |
| `T[keyof T]`       | union всех типов значений| Все возможные значения       |
| `T[number]`        | тип элементов массива    | Для массивов и кортежей      |
| `keyof T & string` | только строковые ключи   | Исключает number и symbol    |

## 4. `const` Type Parameters (TS 5.0+)

Модификатор `const` для type-параметра выводит **литеральные типы** и `readonly`-кортежи без `as const` на стороне вызывающего кода.

### Проблема и решение

```typescript
// Без const — TypeScript расширяет типы
function routes1<T extends readonly string[]>(paths: T): T { return paths; }
const r1 = routes1(["home", "about"]);  // string[]  — литералы потеряны

// С const — литеральные типы автоматически
function routes2<const T extends readonly string[]>(paths: T): T { return paths; }
const r2 = routes2(["home", "about"]);  // readonly ["home", "about"]

function defineConfig<const T extends Record<string, unknown>>(config: T): T {
  return config;
}
const cfg = defineConfig({ port: 3000, host: "localhost" });
// { port: 3000; host: "localhost" }
// Свойства НЕ становятся readonly — const type parameter выводит
// литеральные типы (3000, "localhost") вместо расширенных (number, string).
// Для readonly-свойств объекта по-прежнему нужен `as const` на стороне вызова.
```

### Сравнение с `as const`

| Аспект              | `as const` (caller)        | `<const T>` (callee)        |
| ------------------- | -------------------------- | --------------------------- |
| Кто контролирует    | Вызывающий код             | Автор функции/библиотеки    |
| DX                  | Нужно помнить `as const`   | Работает автоматически      |
| Применимость        | Любое выражение            | Только type-параметры       |
| Глубина             | Рекурсивно `readonly`      | Верхний уровень параметра   |
| Совместимость       | TS 3.4+                   | TS 5.0+                    |

```typescript
// Type-safe builder
function select<const T extends readonly string[]>(columns: T) {
  return {
    from<const U extends string>(table: U) {
      return { columns, table } as { columns: T; table: U };
    },
  };
}
const query = select(["id", "name"]).from("users");
// { columns: readonly ["id", "name"]; table: "users" }
```

**Важно:** `<const T>` не делает значения immutable в runtime — это исключительно compile-time механизм.

## 5. `satisfies` operator (TS 4.9+)

Оператор `satisfies` проверяет совместимость с типом, **не расширяя** тип переменной. Сохраняется узкий (narrow) тип при гарантии корректности структуры.

### Проблема и решение

```typescript
type ColorMap = Record<string, [number, number, number] | string>;

// Аннотация — теряем узкие типы
const colors1: ColorMap = { red: [255, 0, 0], green: "#00ff00" };
colors1.red.map(x => x * 2);   // Error! red может быть string | tuple

// satisfies — проверка + сохранение узкого типа
const colors = {
  red: [255, 0, 0],
  green: "#00ff00",
} satisfies ColorMap;

colors.red.map(x => x * 2);     // OK! red — это [number, number, number]
colors.green.toUpperCase();       // OK! green — это string
```

| Подход                       | Проверка типа | Узкий тип | Автодополнение |
| ---------------------------- | ------------- | --------- | -------------- |
| `const x: T = ...`          | Да            | Нет       | Да             |
| `const x = ...`             | Нет           | Да        | Нет            |
| `const x = ... satisfies T` | Да            | Да        | Да             |

### Практические use-cases

```typescript
// Exhaustive check через Record
type Route = "home" | "about" | "contact";
const handlers = {
  home: () => "Welcome",
  about: () => "About us",
  contact: () => "Contact",
} satisfies Record<Route, () => string>;
// Если забыть route — ошибка компиляции

// satisfies + as const — максимально узкие типы
const palette = {
  primary: "#3b82f6",
  danger: "#ef4444",
} as const satisfies Record<string, `#${string}`>;
// palette.primary — тип "#3b82f6" (литерал)
```

**Важно:** `satisfies` не создаёт новый тип и не влияет на runtime — это чисто compile-time проверка.

## 6. Рекурсивные типы

Рекурсивные типы — type aliases, ссылающиеся сами на себя. Они описывают древовидные структуры, вложенные объекты произвольной глубины и type-level вычисления.

### JSON type

```typescript
type JSONValue =
  | string | number | boolean | null
  | JSONValue[]
  | { [key: string]: JSONValue };

const data: JSONValue = {
  users: [{ name: "Alice", age: 30, hobbies: ["reading"] }],
  meta: { total: 1, page: null },
};
```

### DeepPartial, DeepReadonly, DeepRequired

```typescript
type DeepPartial<T> = T extends object
  ? { [K in keyof T]?: DeepPartial<T[K]> }
  : T;

type DeepReadonly<T> = T extends object
  ? { readonly [K in keyof T]: DeepReadonly<T[K]> }
  : T;

type DeepRequired<T> = T extends object
  ? { [K in keyof T]-?: DeepRequired<T[K]> }
  : T;

interface Settings {
  ui: { theme: { primary: string; secondary: string }; sidebar: boolean };
}

type P = DeepPartial<Settings>;   // все поля на всех уровнях необязательны
type R = DeepReadonly<Settings>;  // frozen.ui.theme.primary = "red" → Error
```

### Flatten и рекурсивные conditional types

```typescript
type Flatten<T> = T extends readonly (infer U)[] ? Flatten<U> : T;
type A = Flatten<number[][][]>;   // number

// Подсчёт длины строки на уровне типов
type StringLength<S extends string, Acc extends unknown[] = []> =
  S extends `${infer _}${infer Rest}`
    ? StringLength<Rest, [...Acc, unknown]>
    : Acc["length"];
type Len = StringLength<"Hello">;   // 5

// Reverse строки
type Reverse<S extends string> =
  S extends `${infer First}${infer Rest}` ? `${Reverse<Rest>}${First}` : S;
type Rev = Reverse<"abcd">;   // "dcba"
```

**Важно:** глубина рекурсии типов зависит от формы рекурсии:
- **Обычные рекурсивные типы** ограничены ~50 уровнями вложенности.
- **Tail-call оптимизация (TS 4.5+):** если conditional type рекурсивно возвращает себя в хвостовой позиции (т.е. результат `extends` — непосредственно рекурсивный вызов без обёрток вроде `[...X]`), TypeScript применяет tail-call elimination и допускает ~1000 уровней.

Пример tail-рекурсивного типа (до ~1000 уровней):
```typescript
type StringLength<S extends string, Acc extends unknown[] = []> =
  S extends `${infer _}${infer Rest}`
    ? StringLength<Rest, [...Acc, unknown]>  // хвостовая позиция
    : Acc["length"];
```

При превышении лимита: `Type instantiation is excessively deep and possibly infinite`.

## 7. Типы-шаблоны для паттерн-матчинга

Conditional types + template literal types + `infer` формируют инструмент паттерн-матчинга: извлечение частей строк, разбор маршрутов, трансформация ключей.

### Извлечение частей строки

```typescript
type Split<S extends string, D extends string> =
  S extends `${infer Head}${D}${infer Tail}` ? [Head, ...Split<Tail, D>] : [S];
type Parts = Split<"a.b.c.d", ".">;    // ["a", "b", "c", "d"]

type TrimLeft<S extends string> = S extends ` ${infer R}` ? TrimLeft<R> : S;
type TrimRight<S extends string> = S extends `${infer R} ` ? TrimRight<R> : S;
type Trim<S extends string> = TrimLeft<TrimRight<S>>;
type T = Trim<"  hello  ">;   // "hello"
```

### Парсинг route с полной типизацией

```typescript
type Prettify<T> = { [K in keyof T]: T[K] } & {};

type ParseRoute<T extends string> =
  T extends `${string}:${infer Param}/${infer Rest}`
    ? { [K in Param]: string } & ParseRoute<`/${Rest}`>
    : T extends `${string}:${infer Param}` ? { [K in Param]: string } : {};

type Params = Prettify<ParseRoute<"/api/:version/users/:userId">>;
// { version: string; userId: string }

declare function createRoute<const T extends string>(
  path: T, handler: (params: Prettify<ParseRoute<T>>) => void
): void;

createRoute("/users/:id", (params) => {
  params.id;      // OK, string
  // params.name; // Error: Property 'name' does not exist
});
```

### CamelCase → kebab-case конвертация

```typescript
type CamelToKebab<S extends string> =
  S extends `${infer H}${infer T}`
    ? H extends Uppercase<H>
      ? `-${Lowercase<H>}${CamelToKebab<T>}`
      : `${H}${CamelToKebab<T>}`
    : S;

type K = CamelToKebab<"backgroundColor">;   // "background-color"

// Трансформация ключей объекта
type CamelToKebabKeys<T> = {
  [K in keyof T as K extends string ? CamelToKebab<K> : K]: T[K];
};

type CSSStyle = CamelToKebabKeys<{ backgroundColor: string; fontSize: number }>;
// { "background-color": string; "font-size": number }
```

**Важно:** паттерн-матчинг строк на уровне типов увеличивает время компиляции. Для библиотек тестируйте с `tsc --diagnostics`.

## 8. `infer` в продвинутых сценариях

Ключевое слово `infer` объявляет переменную типа внутри `extends`-клаузы conditional type. Продвинутые паттерны: множественные позиции, ковариантный/контравариантный вывод, извлечение сложных структур.

### Множественные позиции infer

```typescript
type FnParts<T> = T extends (...args: infer A) => infer R
  ? { args: A; return: R } : never;

type P = FnParts<(name: string, age: number) => boolean>;
// { args: [name: string, age: number]; return: boolean }

type MapParts<T> = T extends Map<infer K, infer V>
  ? { key: K; value: V } : never;
type M = MapParts<Map<string, number>>;  // { key: string; value: number }
```

### Ковариантная vs контравариантная позиция

```typescript
// Ковариантная (return) — результат: union
type CoInfer<T> = T extends { a: infer U; b: infer U } ? U : never;
type C1 = CoInfer<{ a: string; b: number }>;   // string | number

// Контравариантная (параметры функций) — результат: intersection
type ContraInfer<T> =
  T extends { a: (x: infer U) => void; b: (x: infer U) => void } ? U : never;
type C2 = ContraInfer<{
  a: (x: { name: string }) => void; b: (x: { age: number }) => void;
}>;  // { name: string } & { age: number }
```

### UnionToIntersection

```typescript
// Используем контравариантность для превращения union в intersection
type UnionToIntersection<U> =
  (U extends unknown ? (x: U) => void : never) extends (x: infer I) => void
    ? I : never;

type R = UnionToIntersection<{ a: 1 } | { b: 2 } | { c: 3 }>;
// { a: 1 } & { b: 2 } & { c: 3 }
```

### Constrained infer (TS 4.7+) и template literals

```typescript
// Извлечение числового литерала из строки
type ToNumber<T extends string> =
  T extends `${infer N extends number}` ? N : never;
type Num = ToNumber<"42">;   // 42 (число, не string!)

// Извлечение домена из email
type ExtractDomain<T extends string> =
  T extends `${string}@${infer D}` ? D : never;
type D = ExtractDomain<"user@example.com">;   // "example.com"
```

**Важно:** `infer X extends Type` ограничивает выводимый тип до подтипа `Type`, позволяя извлекать числовые литералы, булевы значения и другие узкие типы.

## 9. Branded Types (Номинативная типизация)

TypeScript использует **структурную** типизацию: совместимость определяется структурой. Branded types симулируют **номинативную** типизацию, добавляя уникальную метку (brand) для предотвращения смешивания семантически различных типов.

### Проблема и Brand pattern

```typescript
// Без brand — опасное смешивание
type UserId = number;
type OrderId = number;
function getUser(id: UserId): void {}
const orderId: OrderId = 42;
getUser(orderId);   // OK для компилятора, но логическая ошибка!

// Brand pattern
type Brand<T, B extends string> = T & { readonly __brand: B };
type SafeUserId = Brand<number, "UserId">;
type SafeOrderId = Brand<number, "OrderId">;

const uid = 1 as SafeUserId;
const oid = 2 as SafeOrderId;
getUser(uid);   // OK
// getUser(oid); // Error! OrderId не совместим с UserId
```

### Валидация на границах

```typescript
type Email = Brand<string, "Email">;

function toEmail(value: string): Email {
  if (!/^[^\s@]+@[^\s@]+\.[^\s@]+$/.test(value)) throw new Error(`Invalid email`);
  return value as Email;
}

function sendEmail(to: Email, subject: string): void { /* ... */ }
// sendEmail("raw-string", "hi");             // Error! string !== Email
sendEmail(toEmail("user@example.com"), "hi"); // OK — валидировано
```

### Type-safe ID для доменных моделей

```typescript
type EntityId<T extends string> = Brand<string, `${T}Id`>;
type UserId = EntityId<"User">;
type ProductId = EntityId<"Product">;

interface User { id: UserId; name: string; favorites: ProductId[] }
function findProduct(id: ProductId): Product | null { return null; }

const user: User = { id: "u-1" as UserId, name: "Alice", favorites: ["p-1" as ProductId] };
findProduct(user.favorites[0]);   // OK
// findProduct(user.id);           // Error! UserId !== ProductId

// Утилита для снятия brand
type Unbrand<T> = T extends Brand<infer U, string> ? U : T;
type Raw = Unbrand<UserId>;   // string (базовый тип без brand)
```

**Важно:** brand-свойство (`__brand`) существует **только на уровне типов**. В runtime объект остаётся обычным `number` или `string` — никаких затрат памяти.

---

> **Итог.** Template literal types, variadic tuples, recursive types, `infer`, `satisfies`,
> `const` type parameters и branded types — фундамент type-safe библиотек, где ошибки
> обнаруживаются до запуска программы.
