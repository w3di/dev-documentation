# Утилитарные типы TypeScript — полное руководство

> Утилитарные типы (`Utility Types`) — это набор встроенных generic-типов,
> предоставляемых TypeScript «из коробки». Каждый из них реализован через
> **mapped types**, **conditional types** и ключевое слово **`infer`**.
> Понимание их внутренней реализации позволяет не только использовать готовые
> утилиты, но и создавать собственные на уровне библиотеки типов.

## 1. Типы трансформации объектов — Partial, Required, Readonly

Три фундаментальных утилитарных типа, построенных на **mapped types** — механизме итерации по ключам типа с модификацией модификаторов свойств (`?` и `readonly`).

### 1.1 `Partial<T>`

Делает **все** свойства типа `T` опциональными.

**Внутренняя реализация:**

```typescript
type Partial<T> = {
  [P in keyof T]?: T[P];
};
```

Mapped type итерирует по каждому ключу `P` из `keyof T` и добавляет модификатор `?`, превращая свойство в опциональное. Значение `T[P]` (indexed access type) сохраняется без изменений.

**Практический пример — обновление сущности:**

```typescript
interface User {
  id: number;
  name: string;
  email: string;
  role: "admin" | "user";
}

// Функция обновления принимает только те поля, которые нужно изменить
function updateUser(id: number, updates: Partial<User>): User {
  const existing = getUserById(id);
  return { ...existing, ...updates };
}

// Можно передать любое подмножество свойств
updateUser(1, { name: "Иван" });           // OK
updateUser(1, { email: "a@b.com", role: "admin" }); // OK
updateUser(1, {});                          // OK — пустой объект тоже валиден
```

**Важно:** `Partial` работает только на первом уровне вложенности. Вложенные объекты остаются обязательными. Для глубокой опциональности нужен кастомный `DeepPartial<T>` (см. раздел 9).

### 1.2 `Required<T>`

Обратная операция к `Partial` — делает **все** свойства обязательными, удаляя модификатор `?`.

**Внутренняя реализация:**

```typescript
type Required<T> = {
  [P in keyof T]-?: T[P];
};
```

Ключевой синтаксис — **`-?`** (mapping modifier removal). Знак `-` перед `?` означает «удалить опциональность». Аналогично существует `+?` (добавить), но `+` можно опустить — он подразумевается по умолчанию.

**Практический пример — валидация конфигурации:**

```typescript
interface AppConfig {
  apiUrl?: string;
  timeout?: number;
  retries?: number;
  debug?: boolean;
}

// После загрузки и валидации конфигурация должна быть полной
function loadConfig(partial: AppConfig): Required<AppConfig> {
  return {
    apiUrl: partial.apiUrl ?? "https://api.example.com",
    timeout: partial.timeout ?? 5000,
    retries: partial.retries ?? 3,
    debug: partial.debug ?? false,
  };
}

const config: Required<AppConfig> = loadConfig({ debug: true });
config.apiUrl;   // string — гарантированно есть, не string | undefined
config.timeout;  // number — гарантированно есть
```

### 1.3 `Readonly<T>`

Делает все свойства доступными только для чтения.

**Внутренняя реализация:**

```typescript
type Readonly<T> = {
  readonly [P in keyof T]: T[P];
};
```

Mapped type добавляет модификатор `readonly` к каждому свойству. Попытка присвоения вызовет ошибку компиляции.

**Практический пример — иммутабельное состояние:**

```typescript
interface State {
  count: number;
  items: string[];
}

function createStore(initial: State) {
  let state: Readonly<State> = initial;

  return {
    getState(): Readonly<State> {
      return state;
    },
    // Обновление только через замену всего объекта
    setState(next: State) {
      state = next;
    },
  };
}

const store = createStore({ count: 0, items: [] });
const s = store.getState();
s.count = 5;  // Error: Cannot assign to 'count' because it is a read-only property
```

**Важно:** `Readonly` — это **поверхностная** защита. `s.items.push("x")` скомпилируется без ошибок, потому что сам массив не заморожен — заморожена только ссылка на него. Для глубокой неизменяемости нужен `DeepReadonly<T>` (раздел 9).

**Снятие `readonly`** возможно через mapped type с `-readonly`:

```typescript
type Mutable<T> = {
  -readonly [P in keyof T]: T[P];
};
```

### Сводная таблица трансформаций

| Утилита | Модификатор | Реализация | Эффект |
|---|---|---|---|
| `Partial<T>` | `+?` | `[P in keyof T]?: T[P]` | Все свойства опциональны |
| `Required<T>` | `-?` | `[P in keyof T]-?: T[P]` | Все свойства обязательны |
| `Readonly<T>` | `+readonly` | `readonly [P in keyof T]: T[P]` | Все свойства только для чтения |

## 2. Типы выборки свойств — Pick, Omit, Record

Эти утилиты управляют **набором ключей** объектного типа: выбирают подмножество, исключают ключи или создают тип с заданными ключами.

### 2.1 `Pick<T, K>`

Создаёт тип, содержащий только свойства `T`, ключи которых перечислены в `K`.

**Внутренняя реализация:**

```typescript
type Pick<T, K extends keyof T> = {
  [P in K]: T[P];
};
```

Constraint `K extends keyof T` гарантирует, что переданные ключи реально существуют в типе `T`. Mapped type итерирует не по `keyof T`, а по подмножеству `K`.

**Практический пример — DTO для API:**

```typescript
interface User {
  id: number;
  name: string;
  email: string;
  passwordHash: string;
  createdAt: Date;
}

// Публичный профиль — только безопасные поля
type PublicProfile = Pick<User, "id" | "name">;
// { id: number; name: string }

// Ответ API на обновление
type UserUpdateResponse = Pick<User, "id" | "name" | "email">;
// { id: number; name: string; email: string }

function toPublicProfile(user: User): PublicProfile {
  return { id: user.id, name: user.name };
}
```

### 2.2 `Omit<T, K>`

Создаёт тип из `T`, исключая свойства с ключами из `K`. Логическая противоположность `Pick`.

**Внутренняя реализация:**

```typescript
type Omit<T, K extends keyof any> = Pick<T, Exclude<keyof T, K>>;
```

`Omit` — это **композиция** двух утилит: сначала `Exclude` отфильтровывает из `keyof T` ключи, входящие в `K`, затем `Pick` выбирает оставшиеся свойства.

**Практический пример — создание сущности без auto-generated полей:**

```typescript
interface Article {
  id: number;
  title: string;
  body: string;
  authorId: number;
  createdAt: Date;
  updatedAt: Date;
}

// При создании id и временные метки генерируются автоматически
type CreateArticleDTO = Omit<Article, "id" | "createdAt" | "updatedAt">;
// { title: string; body: string; authorId: number }

function createArticle(data: CreateArticleDTO): Article {
  return {
    ...data,
    id: generateId(),
    createdAt: new Date(),
    updatedAt: new Date(),
  };
}
```

**Gotcha:** в отличие от `Pick`, `Omit` **не проверяет строго** существование ключей. Constraint `K extends keyof any` (эквивалент `K extends string | number | symbol`) позволяет передать любой строковый литерал:

```typescript
type T = Omit<User, "nonExistentField">; // Без ошибки!
type U = Pick<User, "nonExistentField">; // Error: Type '"nonExistentField"' is not assignable
```

Это сделано намеренно — `Omit` часто используется в generic-контекстах, где ключи могут не совпадать. Но это может скрывать опечатки.

### 2.3 `Record<K, T>`

Создаёт объектный тип, где все ключи из `K` имеют тип значения `T`.

**Внутренняя реализация:**

```typescript
type Record<K extends keyof any, T> = {
  [P in K]: T;
};
```

В отличие от `Pick` и `Omit`, `Record` не принимает исходный тип для трансформации — он **создаёт** тип с нуля.

**Практические примеры:**

```typescript
// Словарь с фиксированными ключами
type RolePermissions = Record<"admin" | "editor" | "viewer", boolean>;
// { admin: boolean; editor: boolean; viewer: boolean }

// Индексированная коллекция
type UserCache = Record<string, User>;

// Маппинг статусов на конфигурацию
type StatusConfig = Record<
  "active" | "inactive" | "banned",
  { color: string; label: string; icon: string }
>;

const statusConfig: StatusConfig = {
  active:   { color: "green",  label: "Активен",     icon: "check" },
  inactive: { color: "gray",   label: "Неактивен",   icon: "pause" },
  banned:   { color: "red",    label: "Заблокирован", icon: "block" },
};
```

**`Record` vs index signature:**

```typescript
// Index signature — любой строковый ключ
type A = { [key: string]: number };

// Record<string, number> — семантически идентичен
type B = Record<string, number>;

// Но Record с union-литералом требует ВСЕ ключи
type C = Record<"x" | "y", number>;
const c: C = { x: 1 };       // Error: Property 'y' is missing
const c2: C = { x: 1, y: 2 }; // OK
```

## 3. Типы фильтрации Union — Exclude, Extract, NonNullable

Эти утилиты работают с **union types** и используют механизм **distributive conditional types** — условный тип, который автоматически распределяется по членам union.

### Как работает дистрибутивность

Когда conditional type `T extends U ? X : Y` получает union в качестве `T`, TypeScript применяет условие к **каждому члену** union отдельно:

```typescript
// Для T = A | B | C:
// (A extends U ? X : Y) | (B extends U ? X : Y) | (C extends U ? X : Y)
```

Дистрибутивность срабатывает только когда проверяемый тип — это **naked type parameter** (голый параметр типа, не обёрнутый ни в какую конструкцию).

### 3.1 `Exclude<UnionType, ExcludedMembers>`

Удаляет из union те члены, которые assignable к `ExcludedMembers`.

**Внутренняя реализация:**

```typescript
type Exclude<T, U> = T extends U ? never : T;
```

Для каждого члена `T`: если он extends `U`, возвращаем `never` (член исключается из union), иначе оставляем как есть.

```typescript
type T = Exclude<"a" | "b" | "c", "a" | "c">;
// Дистрибуция:
//   "a" extends "a" | "c" ? never : "a"  →  never
//   "b" extends "a" | "c" ? never : "b"  →  "b"
//   "c" extends "a" | "c" ? never : "c"  →  never
// Результат: never | "b" | never  →  "b"
```

**Практический пример:**

```typescript
type AllEvents = "click" | "scroll" | "mouseover" | "keydown" | "keyup";
type MouseEvents = "click" | "scroll" | "mouseover";

// Только клавиатурные события
type KeyboardEvents = Exclude<AllEvents, MouseEvents>;
// "keydown" | "keyup"
```

### 3.2 `Extract<Type, Union>`

Оставляет в union только те члены, которые assignable к `Union`. Противоположность `Exclude`.

**Внутренняя реализация:**

```typescript
type Extract<T, U> = T extends U ? T : never;
```

Логика зеркальна: если член extends `U` — оставляем, иначе — `never`.

```typescript
type T = Extract<string | number | boolean, string | boolean>;
// string | boolean

// Полезно для фильтрации discriminated union
type Shape =
  | { kind: "circle"; radius: number }
  | { kind: "rect"; width: number; height: number }
  | { kind: "triangle"; base: number; height: number };

type RectOrTriangle = Extract<Shape, { kind: "rect" } | { kind: "triangle" }>;
// { kind: "rect"; ... } | { kind: "triangle"; ... }
```

### 3.3 `NonNullable<T>`

Удаляет `null` и `undefined` из типа.

**Внутренняя реализация:**

```typescript
type NonNullable<T> = T & {};
```

**Важно:** начиная с TypeScript 4.8, реализация `NonNullable` была изменена с `T extends null | undefined ? never : T` на `T & {}`. Пересечение с пустым объектным типом `{}` отсекает `null` и `undefined`, потому что `null & {}` и `undefined & {}` сводятся к `never`. При этом все остальные типы (включая строки, числа, объекты) пересекаются с `{}` без изменений.

```typescript
type A = NonNullable<string | null | undefined>;  // string
type B = NonNullable<number | null>;               // number
type C = NonNullable<null | undefined>;             // never

// Практическое применение — безопасное обращение к nullable значениям
function processValue(value: string | null | undefined): string {
  const safe: NonNullable<typeof value> = value!;
  return safe.toUpperCase(); // OK — тип гарантированно string
}
```

## 4. Типы для функций — Parameters, ReturnType, ConstructorParameters, InstanceType

Эти утилиты используют **conditional types с `infer`** для извлечения частей сигнатуры функции. Ключевое слово `infer` объявляет type variable внутри `extends` clause, позволяя TypeScript **вывести** тип из позиции.

### 4.1 `Parameters<T>`

Извлекает типы параметров функции в виде кортежа (tuple).

**Внутренняя реализация:**

```typescript
type Parameters<T extends (...args: any) => any> =
  T extends (...args: infer P) => any ? P : never;
```

`infer P` стоит в позиции параметров функции — TypeScript выводит тип аргументов.

```typescript
type Fn = (a: string, b: number, c?: boolean) => void;
type P = Parameters<Fn>;  // [a: string, b: number, c?: boolean]

// Доступ к отдельным параметрам
type First = P[0];   // string
type Second = P[1];  // number

// Практика — типизация враппера
function debounce<T extends (...args: any[]) => any>(
  fn: T,
  delay: number
): (...args: Parameters<T>) => void {
  let timer: ReturnType<typeof setTimeout>;
  return (...args) => {
    clearTimeout(timer);
    timer = setTimeout(() => fn(...args), delay);
  };
}
```

### 4.2 `ReturnType<T>`

Извлекает тип возвращаемого значения функции.

**Внутренняя реализация:**

```typescript
type ReturnType<T extends (...args: any) => any> =
  T extends (...args: any) => infer R ? R : any;
```

`infer R` стоит в позиции возвращаемого типа.

```typescript
function fetchUser() {
  return { id: 1, name: "Иван", role: "admin" as const };
}

type UserData = ReturnType<typeof fetchUser>;
// { id: number; name: string; role: "admin" }

// Полезно когда функция возвращает сложный тип, и вы не хотите дублировать его
type ApiResponse = ReturnType<typeof fetch>;  // Promise<Response>
```

### 4.3 `ConstructorParameters<T>`

Извлекает параметры конструктора класса.

**Внутренняя реализация:**

```typescript
type ConstructorParameters<T extends abstract new (...args: any) => any> =
  T extends abstract new (...args: infer P) => any ? P : never;
```

Отличие от `Parameters` — `new` keyword в сигнатуре и `abstract` для поддержки абстрактных классов.

```typescript
class HttpClient {
  constructor(
    public baseUrl: string,
    public timeout: number,
    public headers?: Record<string, string>
  ) {}
}

type HttpClientArgs = ConstructorParameters<typeof HttpClient>;
// [baseUrl: string, timeout: number, headers?: Record<string, string>]

// Фабрика для создания экземпляров
function createInstance<T extends new (...args: any[]) => any>(
  Ctor: T,
  ...args: ConstructorParameters<T>
): InstanceType<T> {
  return new Ctor(...args);
}

const client = createInstance(HttpClient, "https://api.example.com", 5000);
// тип: HttpClient
```

### 4.4 `InstanceType<T>`

Извлекает тип экземпляра, создаваемого конструктором.

**Внутренняя реализация:**

```typescript
type InstanceType<T extends abstract new (...args: any) => any> =
  T extends abstract new (...args: any) => infer R ? R : any;
```

`infer R` стоит в позиции возвращаемого типа конструктора.

```typescript
abstract class BaseModel {
  abstract tableName: string;
}

class UserModel extends BaseModel {
  tableName = "users";
  name: string = "";
}

type UserInstance = InstanceType<typeof UserModel>;  // UserModel

// Полезно в generic-фабриках и DI-контейнерах
function resolve<T extends abstract new (...args: any) => any>(
  token: T
): InstanceType<T> {
  return container.get(token);
}
```

## 5. Типы для `this` — ThisParameterType, OmitThisParameter, ThisType

Эти утилиты работают с параметром `this`, который TypeScript позволяет объявлять как **фиктивный первый параметр** функции.

### 5.1 `ThisParameterType<T>`

Извлекает тип параметра `this` из сигнатуры функции. Если `this` не объявлен, возвращает `unknown`.

**Внутренняя реализация:**

```typescript
type ThisParameterType<T> =
  T extends (this: infer U, ...args: never) => any ? U : unknown;
```

```typescript
function greet(this: { name: string }, greeting: string): string {
  return `${greeting}, ${this.name}!`;
}

type ThisCtx = ThisParameterType<typeof greet>;  // { name: string }

// Если this не объявлен
function plain(x: number): void {}
type NoThis = ThisParameterType<typeof plain>;  // unknown
```

### 5.2 `OmitThisParameter<T>`

Создаёт тип функции без параметра `this`.

**Внутренняя реализация:**

```typescript
type OmitThisParameter<T> =
  unknown extends ThisParameterType<T>
    ? T
    : T extends (...args: infer A) => infer R
      ? (...args: A) => R
      : T;
```

Логика: если `ThisParameterType<T>` равен `unknown` (нет явного `this`), возвращаем `T` без изменений. Иначе — конструируем новую сигнатуру только с `args` и `return`.

```typescript
function onClick(this: HTMLButtonElement, event: MouseEvent): void {
  this.disabled = true;
  console.log(event.type);
}

type BoundHandler = OmitThisParameter<typeof onClick>;
// (event: MouseEvent) => void

// Полезно при передаче метода как callback с bind
const button = document.querySelector("button")!;
const handler: BoundHandler = onClick.bind(button);
button.addEventListener("click", handler);
```

### 5.3 `ThisType<T>`

Особый **маркерный тип** — он не трансформирует тип, а служит подсказкой компилятору о том, каким будет `this` внутри объектного литерала. Работает **только** при включённом `noImplicitThis`.

**Внутренняя реализация:**

```typescript
interface ThisType<T> {}
```

Реализация пуста — вся магия в компиляторе. Когда TypeScript видит `ThisType<T>` в пересечении с типом объекта, он устанавливает контекстный тип `this` для всех методов.

```typescript
type ObjectDescriptor<D, M> = {
  data?: D;
  methods?: M & ThisType<D & M>;  // this внутри methods — это D & M
};

function makeObject<D, M>(desc: ObjectDescriptor<D, M>): D & M {
  const data: object = desc.data || {};
  const methods: object = desc.methods || {};
  return { ...data, ...methods } as D & M;
}

const obj = makeObject({
  data: { x: 0, y: 0 },
  methods: {
    moveBy(dx: number, dy: number) {
      this.x += dx;  // OK — this.x: number (из data)
      this.y += dy;  // OK — this.y: number (из data)
    },
  },
});

obj.moveBy(5, 5);  // OK
obj.x;             // 5
```

## 6. Типы строковых манипуляций — Uppercase, Lowercase, Capitalize, Uncapitalize

Эти четыре утилиты — единственные **intrinsic types** в TypeScript. Они реализованы непосредственно в коде компилятора (`checker.ts`) на TypeScript и **не могут быть воспроизведены** через пользовательские типы. Нативный порт компилятора на Go (tsgo, анонсированный в рамках TypeScript 7.0) также реализует эти типы, но в оригинальном компиляторе нет ни C++, ни Go — только TypeScript.

### Реализация в компиляторе

В исходном коде TypeScript (файл `checker.ts`) эти типы обрабатываются специальной веткой:

```typescript
// Внутри компилятора (упрощённо):
// Если тип — intrinsic string mapping type, применяем трансформацию:
// "uppercase" → toUpperCase()
// "lowercase" → toLowerCase()
// "capitalize" → первый символ toUpperCase()
// "uncapitalize" → первый символ toLowerCase()
```

### Примеры использования

```typescript
type U = Uppercase<"hello">;      // "HELLO"
type L = Lowercase<"HELLO">;      // "hello"
type C = Capitalize<"hello">;     // "Hello"
type UC = Uncapitalize<"Hello">;  // "hello"

// Работают с union — дистрибутивно
type Events = "click" | "scroll" | "keydown";
type UpperEvents = Uppercase<Events>;
// "CLICK" | "SCROLL" | "KEYDOWN"

// Работают с template literal types
type EventHandler<T extends string> = `on${Capitalize<T>}`;
type Handlers = EventHandler<Events>;
// "onClick" | "onScroll" | "onKeydown"
```

### Практический пример — типизированная система событий

```typescript
type DOMEvents = "click" | "focus" | "blur" | "input" | "change";

// Генерация имён обработчиков: onClick, onFocus, ...
type HandlerName<E extends string> = `on${Capitalize<E>}`;

// Генерация типа объекта с обработчиками
type EventHandlers = {
  [E in DOMEvents as HandlerName<E>]?: (event: Event) => void;
};
// {
//   onClick?: (event: Event) => void;
//   onFocus?: (event: Event) => void;
//   onBlur?: (event: Event) => void;
//   onInput?: (event: Event) => void;
//   onChange?: (event: Event) => void;
// }
```

**Важно:** intrinsic типы работают только со **строковыми литеральными типами**. Для `string` (нелитерального) они возвращают `string`:

```typescript
type T = Uppercase<string>;  // string (не "UNKNOWN_STRING")
```

## 7. Awaited — рекурсивное разворачивание Promise

`Awaited<T>` извлекает тип значения, которое будет получено при `await`. Рекурсивно разворачивает вложенные `Promise` и поддерживает `Thenable`-объекты.

### Внутренняя реализация

```typescript
type Awaited<T> =
  T extends null | undefined
    ? T  // null и undefined возвращаются как есть
    : T extends object & { then(onfulfilled: infer F, ...args: infer _): any }
      ? F extends (value: infer V, ...args: infer _) => any
        ? Awaited<V>  // Рекурсивное разворачивание
        : never
      : T;  // Не thenable — возвращаем как есть
```

Логика по шагам:
1. Если `T` — `null` или `undefined`, возвращаем как есть (они не thenable).
2. Если `T` — объект с методом `then`, извлекаем тип первого аргумента `onfulfilled`.
3. Из колбэка `onfulfilled` извлекаем тип его первого параметра `V` (resolved value).
4. Рекурсивно применяем `Awaited` к `V` — это разворачивает вложенные промисы.
5. Если `T` — не thenable, возвращаем `T` без изменений.

### Примеры

```typescript
type A = Awaited<Promise<string>>;              // string
type B = Awaited<Promise<Promise<number>>>;     // number (рекурсия!)
type C = Awaited<string>;                       // string (не Promise)
type D = Awaited<boolean | Promise<number>>;    // boolean | number

// Работает с Thenable (не обязательно Promise)
interface CustomThenable {
  then(onFulfilled: (value: number) => void): void;
}
type E = Awaited<CustomThenable>;               // number
```

**Практический пример — типизация Promise.all:**

```typescript
// Упрощённая типизация Promise.all использует Awaited
declare function promiseAll<T extends readonly unknown[]>(
  values: [...T]
): Promise<{ -readonly [P in keyof T]: Awaited<T[P]> }>;

const result = await promiseAll([
  Promise.resolve(42),
  Promise.resolve("hello"),
  true,
] as const);
// тип: [number, string, true]
```

## 8. NoInfer — предотвращение вывода типов

`NoInfer<T>` (добавлен в TypeScript 5.4) блокирует позицию параметра как **inference site** — TypeScript не будет выводить generic тип из этой позиции.

### Внутренняя реализация

```typescript
// Intrinsic type — реализован в компиляторе
type NoInfer<T> = intrinsic;
```

`NoInfer` — это intrinsic тип, как и строковые манипуляции. На уровне системы типов он ведёт себя как identity (`NoInfer<T> = T`), но компилятор помечает позицию как non-inferrable.

### Проблема, которую решает NoInfer

```typescript
// БЕЗ NoInfer — тип выводится из ОБОИХ аргументов
function createFSM<S extends string>(
  initial: S,
  states: S[]
): void {}

// TypeScript выводит S из обоих позиций и объединяет:
createFSM("idle", ["idle", "running", "typo"]);
// S = "idle" | "running" | "typo" — опечатка «typo» не вызывает ошибку!
```

```typescript
// С NoInfer — тип выводится ТОЛЬКО из initial
function createFSM<S extends string>(
  initial: S,
  states: NoInfer<S>[]
): void {}

createFSM("idle", ["idle", "running", "typo"]);
// Error: Type '"typo"' is not assignable to type '"idle"'
// S выведен ТОЛЬКО из "idle", и "typo" не прошёл проверку
```

### Практический пример — значения по умолчанию

```typescript
function getOrDefault<T>(value: T | undefined, defaultValue: NoInfer<T>): T {
  return value ?? defaultValue;
}

// Тип T выводится ТОЛЬКО из первого аргумента
getOrDefault<number>(undefined, "hello");
// Error: Argument of type 'string' is not assignable to parameter of type 'number'
// Без NoInfer тип T был бы number | string
```

## 9. Кастомные утилитарные типы

Встроенные утилиты покрывают базовые сценарии. Для продвинутых задач необходимы кастомные типы, построенные на тех же примитивах: mapped types, conditional types и `infer`.

### 9.1 `DeepPartial<T>`

Рекурсивно делает все свойства опциональными, включая вложенные объекты.

```typescript
type DeepPartial<T> = T extends object
  ? { [P in keyof T]?: DeepPartial<T[P]> }
  : T;
```

```typescript
interface Config {
  server: {
    host: string;
    port: number;
    ssl: { cert: string; key: string };
  };
  logging: { level: string; file: string };
}

// Можно передать любой фрагмент на любой глубине вложенности
const override: DeepPartial<Config> = {
  server: { ssl: { cert: "/new/cert.pem" } },
};
```

### 9.2 `DeepReadonly<T>`

Рекурсивно делает все свойства и вложенные объекты readonly.

```typescript
type DeepReadonly<T> = T extends (infer U)[]
  ? ReadonlyArray<DeepReadonly<U>>
  : T extends object
    ? { readonly [P in keyof T]: DeepReadonly<T[P]> }
    : T;
```

```typescript
const config: DeepReadonly<Config> = {
  server: { host: "localhost", port: 3000, ssl: { cert: "a", key: "b" } },
  logging: { level: "info", file: "app.log" },
};

config.server.port = 8080;        // Error: Cannot assign to 'port'
config.server.ssl.cert = "new";   // Error: Cannot assign to 'cert'
```

### 9.3 `Mutable<T>`

Снимает `readonly` со всех свойств — противоположность `Readonly`.

```typescript
type Mutable<T> = {
  -readonly [P in keyof T]: T[P];
};
```

```typescript
interface FrozenUser {
  readonly id: number;
  readonly name: string;
}

type EditableUser = Mutable<FrozenUser>;
// { id: number; name: string } — без readonly
```

### 9.4 `PickByType<T, V>`

Выбирает из объектного типа только те свойства, значения которых assignable к `V`.

```typescript
type PickByType<T, V> = {
  [P in keyof T as T[P] extends V ? P : never]: T[P];
};
```

Здесь используется **key remapping** (`as` clause в mapped type) — если условие не выполнено, ключ маппится в `never` и исключается.

```typescript
interface Mixed {
  id: number;
  name: string;
  active: boolean;
  count: number;
  label: string;
}

type StringProps = PickByType<Mixed, string>;
// { name: string; label: string }

type NumberProps = PickByType<Mixed, number>;
// { id: number; count: number }
```

### 9.5 `RequiredKeys<T>` и `OptionalKeys<T>`

Извлекают union ключей, которые являются обязательными или опциональными.

```typescript
type RequiredKeys<T> = {
  [K in keyof T]-?: {} extends Pick<T, K> ? never : K;
}[keyof T];

type OptionalKeys<T> = {
  [K in keyof T]-?: {} extends Pick<T, K> ? K : never;
}[keyof T];
```

Трюк: `{} extends Pick<T, K>` проверяет, можно ли присвоить пустой объект типу `Pick<T, K>`. Если свойство `K` опциональное, `Pick<T, K>` — это `{ K?: V }`, и пустой объект `{}` ему assignable. Если обязательное — нет.

```typescript
interface Form {
  name: string;
  email: string;
  phone?: string;
  bio?: string;
}

type R = RequiredKeys<Form>;  // "name" | "email"
type O = OptionalKeys<Form>;  // "phone" | "bio"
```

### 9.6 `Prettify<T>`

«Раскрывает» пересечения и mapped types в плоский объектный тип для удобства чтения в IDE.

```typescript
type Prettify<T> = {
  [K in keyof T]: T[K];
} & {};
```

Mapped type пересоздаёт тип свойство за свойством, а `& {}` заставляет TypeScript отобразить результат как единый объектный тип вместо пересечения.

```typescript
type A = { id: number } & { name: string } & { role: "admin" };
// При наведении IDE покажет: { id: number } & { name: string } & { role: "admin" }

type B = Prettify<A>;
// При наведении IDE покажет: { id: number; name: string; role: "admin" }
```

### Сводная таблица кастомных утилит

| Утилита | Назначение | Ключевой механизм |
|---|---|---|
| `DeepPartial<T>` | Рекурсивная опциональность | Рекурсивный mapped type |
| `DeepReadonly<T>` | Рекурсивная неизменяемость | Рекурсивный mapped type + массивы |
| `Mutable<T>` | Снятие readonly | `-readonly` modifier |
| `PickByType<T, V>` | Фильтрация свойств по типу значения | Key remapping (`as`) |
| `RequiredKeys<T>` | Извлечение обязательных ключей | `{} extends Pick<T, K>` |
| `OptionalKeys<T>` | Извлечение опциональных ключей | `{} extends Pick<T, K>` |
| `Prettify<T>` | Раскрытие пересечений | Re-mapped type + `& {}` |
