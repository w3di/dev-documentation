# Декораторы в TypeScript

> Декораторы --- это специальные функции, применяемые к классам, методам, свойствам и параметрам
> для декларативной модификации их поведения. Они позволяют реализовать cross-cutting concerns
> (логирование, валидацию, авторизацию, DI) без загрязнения бизнес-логики.

## 1. Что такое декораторы

### 1.1 Концепция

Декоратор --- это **функция**, которая принимает цель декорирования (класс, метод, свойство или параметр) и может модифицировать или заменить её. Синтаксически декоратор применяется с помощью символа `@` перед объявлением:

```ts
@sealed
class BugReport {
  @validate
  title: string;

  @log
  getReport(@inject logger: Logger): string {
    return this.title;
  }
}
```

Декораторы реализуют паттерн **Decorator Pattern** из GoF, но на уровне языка, а не через ручное оборачивание объектов. Это даёт декларативный, читаемый код.

### 1.2 История: TC39 Proposal vs Legacy

Существуют **две принципиально разные** реализации декораторов:

| Аспект | Legacy (experimental) | TC39 Stage 3 |
|---|---|---|
| Флаг tsconfig | `"experimentalDecorators": true` | Не требуется (TS 5.0+) |
| Статус | Устаревший, не станет стандартом | Будет частью ECMAScript |
| API | `(target, key, descriptor)` | `(value, context)` |
| Поддержка | TypeScript, Babel (legacy plugin) | TypeScript 5.0+, Babel 2023+ |
| Декораторы параметров | Поддерживаются | **Не поддерживаются** |
| `reflect-metadata` | Широко используется | Не требуется |

### 1.3 Включение декораторов

Для **legacy** декораторов в `tsconfig.json`:

```json
{
  "compilerOptions": {
    "target": "ES2016",
    "experimentalDecorators": true,
    "emitDecoratorMetadata": true   // опционально, для reflect-metadata
  }
}
```

Для **TC39 Stage 3** декораторов достаточно TypeScript 5.0+ без дополнительных флагов. Компилятор автоматически различает два формата по наличию или отсутствию флага `experimentalDecorators`.

**Важно:** `emitDecoratorMetadata` работает **только** с `experimentalDecorators` и генерирует метаданные типов через `Reflect.metadata`. В TC39-версии этого механизма нет --- вместо него используется `context.metadata`.

## 2. Декораторы классов (Class Decorators)

### 2.1 Сигнатура (Legacy)

Декоратор класса получает **конструктор** класса как единственный аргумент. Может вернуть новый конструктор, заменяющий исходный.

```ts
type ClassDecorator = <TFunction extends Function>(
  target: TFunction
) => TFunction | void;
```

### 2.2 Модификация конструктора

Классический паттерн --- расширение класса через возврат нового конструктора:

```ts
function Timestamped<T extends { new (...args: any[]): {} }>(Base: T) {
  return class extends Base {
    createdAt = new Date();
    updatedAt = new Date();
  };
}

@Timestamped
class Order {
  constructor(public id: number) {}
}

const order = new Order(1);
// order.createdAt --- Date  (добавлено декоратором)
// order.updatedAt --- Date  (добавлено декоратором)
```

**Обратите внимание:** при замене конструктора TypeScript **не обновляет** тип автоматически. Чтобы типы были корректны, необходимо использовать interface merging или declare:

```ts
interface Order {
  createdAt: Date;
  updatedAt: Date;
}
```

### 2.3 Sealing класса

Запрет расширения и модификации прототипа:

```ts
function sealed(constructor: Function): void {
  Object.seal(constructor);
  Object.seal(constructor.prototype);
}

@sealed
class Singleton {
  private static instance: Singleton;
  static getInstance(): Singleton {
    return this.instance ??= new Singleton();
  }
}

// Object.defineProperty(Singleton.prototype, 'hack', { value: 42 });
// TypeError: Cannot define property hack, object is not extensible
```

### 2.4 Добавление метаданных

Декораторы часто используются для аннотации классов метаданными, которые считываются позже (ORM, DI-контейнеры):

```ts
const ENTITY_METADATA = Symbol('entity');

function Entity(tableName: string) {
  return function (constructor: Function) {
    Reflect.defineMetadata(ENTITY_METADATA, { tableName }, constructor);
  };
}

@Entity('users')
class User {
  id!: number;
  name!: string;
}

// Позже при инициализации ORM:
const meta = Reflect.getMetadata(ENTITY_METADATA, User);
// { tableName: 'users' }
```

## 3. Декораторы методов (Method Decorators)

### 3.1 Сигнатура (Legacy)

Декоратор метода получает три аргумента и может модифицировать `PropertyDescriptor`:

```ts
type MethodDecorator = <T>(
  target: Object,              // прототип класса (или конструктор для static)
  propertyKey: string | symbol,// имя метода
  descriptor: TypedPropertyDescriptor<T>
) => TypedPropertyDescriptor<T> | void;
```

Параметр `target` --- это `ClassName.prototype` для instance-методов и сам конструктор для `static`-методов. Это критически важно для понимания того, к чему вы привязываете логику.

### 3.2 Логирование вызовов

Наиболее распространённый паттерн --- оборачивание метода:

```ts
function Log(
  target: Object,
  propertyKey: string,
  descriptor: PropertyDescriptor
): void {
  const original = descriptor.value;

  descriptor.value = function (this: any, ...args: any[]) {
    console.log(`[CALL] ${propertyKey}(${args.map(a => JSON.stringify(a)).join(', ')})`);
    const start = performance.now();
    const result = original.apply(this, args);
    const duration = performance.now() - start;
    console.log(`[RETURN] ${propertyKey} -> ${JSON.stringify(result)} (${duration.toFixed(2)}ms)`);
    return result;
  };
}

class MathService {
  @Log
  factorial(n: number): number {
    return n <= 1 ? 1 : n * this.factorial(n - 1);
  }
}

const svc = new MathService();
svc.factorial(5);
// [CALL] factorial(5)
// [CALL] factorial(4)  ... рекурсивные вызовы тоже логируются
// [RETURN] factorial -> 120 (0.12ms)
```

### 3.3 Memoization

Кэширование результатов чистых функций:

```ts
function Memoize(
  target: Object,
  propertyKey: string,
  descriptor: PropertyDescriptor
): void {
  const original = descriptor.value;
  const cache = new Map<string, any>();

  descriptor.value = function (this: any, ...args: any[]) {
    const key = JSON.stringify(args);
    if (cache.has(key)) return cache.get(key);
    const result = original.apply(this, args);
    cache.set(key, result);
    return result;
  };
}

class FibService {
  @Memoize
  fib(n: number): number {
    if (n <= 1) return n;
    return this.fib(n - 1) + this.fib(n - 2);
  }
}
```

### 3.4 Throttle / Debounce

Управление частотой вызовов через `PropertyDescriptor`:

```ts
function Throttle(ms: number) {
  return function (
    target: Object,
    propertyKey: string,
    descriptor: PropertyDescriptor
  ): void {
    const original = descriptor.value;
    let lastCall = 0;

    descriptor.value = function (this: any, ...args: any[]) {
      const now = Date.now();
      if (now - lastCall < ms) return;
      lastCall = now;
      return original.apply(this, args);
    };
  };
}

class SearchController {
  @Throttle(300)
  onInput(query: string): void {
    console.log(`Searching: ${query}`);
  }
}
```

### 3.5 Манипуляция PropertyDescriptor

Декоратор может модифицировать любое поле дескриптора:

```ts
function Readonly(
  target: Object,
  propertyKey: string,
  descriptor: PropertyDescriptor
): void {
  descriptor.writable = false;
}

function NonEnumerable(
  target: Object,
  propertyKey: string,
  descriptor: PropertyDescriptor
): void {
  descriptor.enumerable = false;
}

class Config {
  @Readonly
  getVersion(): string {
    return '1.0.0';
  }

  @NonEnumerable
  getInternalState(): object {
    return { debug: true };
  }
}
```

## 4. Декораторы свойств (Property Decorators)

### 4.1 Сигнатура (Legacy)

Декоратор свойства получает **два** аргумента. В отличие от декоратора метода, `PropertyDescriptor` **не передаётся** и не может быть возвращён:

```ts
type PropertyDecorator = (
  target: Object,               // прототип класса
  propertyKey: string | symbol  // имя свойства
) => void;
```

**Почему нет descriptor?** На момент вызова декоратора свойства класс ещё не инстанциирован. Свойства экземпляра создаются в конструкторе (или через field initializer), а не на прототипе. Поэтому у движка нет `PropertyDescriptor`, который можно было бы передать.

### 4.2 Аннотация метаданными

Основное применение --- сохранение метаданных для последующей обработки:

```ts
import 'reflect-metadata';

const COLUMN_KEY = Symbol('column');

interface ColumnOptions {
  name?: string;
  type: 'varchar' | 'int' | 'boolean' | 'timestamp';
  nullable?: boolean;
}

function Column(options: ColumnOptions): PropertyDecorator {
  return (target, propertyKey) => {
    const columns: Map<string | symbol, ColumnOptions> =
      Reflect.getMetadata(COLUMN_KEY, target) ?? new Map();
    columns.set(propertyKey, options);
    Reflect.defineMetadata(COLUMN_KEY, columns, target);
  };
}

class UserEntity {
  @Column({ type: 'int' })
  id!: number;

  @Column({ type: 'varchar', nullable: false })
  email!: string;

  @Column({ type: 'timestamp', nullable: true })
  deletedAt?: Date;
}

// Получение метаданных:
const columns = Reflect.getMetadata(COLUMN_KEY, UserEntity.prototype);
// Map { 'id' => { type: 'int' }, 'email' => { ... }, 'deletedAt' => { ... } }
```

### 4.3 Паттерн валидации

Декоратор свойства может перехватить доступ через `Object.defineProperty` в конструкторе:

```ts
function Min(minValue: number): PropertyDecorator {
  return (target, propertyKey) => {
    const PRIVATE = Symbol(String(propertyKey));

    Object.defineProperty(target, propertyKey, {
      get() {
        return this[PRIVATE];
      },
      set(value: number) {
        if (value < minValue) {
          throw new RangeError(
            `${String(propertyKey)} must be >= ${minValue}, got ${value}`
          );
        }
        this[PRIVATE] = value;
      },
      enumerable: true,
      configurable: true,
    });
  };
}

class Product {
  @Min(0)
  price!: number;

  @Min(1)
  quantity!: number;
}

const p = new Product();
p.price = 100;    // OK
p.price = -5;     // RangeError: price must be >= 0, got -5
```

**Важно:** этот трюк модифицирует **прототип**, что означает, что getter/setter будет общим для всех экземпляров. Данные хранятся в `this[PRIVATE]`, поэтому каждый экземпляр имеет собственное значение.

## 5. Декораторы параметров (Parameter Decorators)

### 5.1 Сигнатура (Legacy)

Декоратор параметра получает три аргумента:

```ts
type ParameterDecorator = (
  target: Object,               // прототип класса
  propertyKey: string | symbol, // имя метода (undefined для конструктора)
  parameterIndex: number        // индекс параметра (0-based)
) => void;
```

Декоратор параметра **не может** напрямую изменить поведение --- он может только **аннотировать** параметр метаданными. Реальная логика реализуется в паре с декоратором метода.

### 5.2 Использование с reflect-metadata

Стандартный паттерн --- запись индексов декорированных параметров в метаданные:

```ts
import 'reflect-metadata';

const INJECT_KEY = Symbol('inject');

function Inject(token: string): ParameterDecorator {
  return (target, propertyKey, parameterIndex) => {
    const existing: { index: number; token: string }[] =
      Reflect.getOwnMetadata(INJECT_KEY, target, propertyKey!) ?? [];
    existing.push({ index: parameterIndex, token });
    Reflect.defineMetadata(INJECT_KEY, existing, target, propertyKey!);
  };
}

class OrderService {
  constructor(
    @Inject('UserRepository') private userRepo: any,
    @Inject('Logger') private logger: any
  ) {}
}

const injections = Reflect.getOwnMetadata(INJECT_KEY, OrderService);
// [{ index: 0, token: 'UserRepository' }, { index: 1, token: 'Logger' }]
```

### 5.3 Паттерн Dependency Injection

Полный пример DI-контейнера с декораторами параметров:

```ts
const container = new Map<string, any>();
const INJECT_META = Symbol('inject');

function Injectable(constructor: Function): void {
  // Считываем аннотации параметров и резолвим зависимости
  const injections: { index: number; token: string }[] =
    Reflect.getOwnMetadata(INJECT_META, constructor) ?? [];

  const sortedDeps = injections
    .sort((a, b) => a.index - b.index)
    .map(dep => {
      const resolved = container.get(dep.token);
      if (!resolved) throw new Error(`Dependency "${dep.token}" not registered`);
      return resolved;
    });

  // Регистрируем фабрику
  container.set(constructor.name, new (constructor as any)(...sortedDeps));
}

// Регистрация зависимостей
container.set('Logger', { log: console.log });
container.set('UserRepository', { findAll: () => [] });

@Injectable
class OrderService {
  constructor(
    @Inject('Logger') private logger: any,
    @Inject('UserRepository') private userRepo: any
  ) {}
}

const service = container.get('OrderService'); // полностью собранный экземпляр
```

**Важно:** В TC39 Stage 3 декораторы параметров **не поддерживаются**. Фреймворки (NestJS, Angular) используют legacy-декораторы или переходят на альтернативные подходы (token-based DI через декораторы свойств).

## 6. Фабрики декораторов (Decorator Factories)

### 6.1 Концепция

Фабрика декоратора --- это функция, которая **возвращает** декоратор. Она позволяет параметризировать декораторы:

```ts
// Простой декоратор (без параметров):
function sealed(constructor: Function) { /* ... */ }

// Фабрика декоратора (с параметрами):
function Entity(tableName: string) {
  return function (constructor: Function) { /* ... */ };
}

@sealed          // вызов декоратора напрямую
@Entity('users') // вызов фабрики -> возвращает декоратор -> применяется к классу
class User {}
```

### 6.2 Типизированная фабрика

Создание универсальной фабрики с полной типизацией:

```ts
function WithDefaults<T extends Record<string, any>>(defaults: T) {
  return function <Ctor extends { new (...args: any[]): {} }>(Base: Ctor) {
    return class extends Base {
      constructor(...args: any[]) {
        super(...args);
        Object.assign(this, defaults);
      }
    };
  };
}

@WithDefaults({ role: 'user', isActive: true, loginCount: 0 })
class Account {
  constructor(public email: string) {}
}

const acc = new Account('test@mail.com');
// acc.role === 'user', acc.isActive === true, acc.loginCount === 0
```

### 6.3 Конфигурационные паттерны

Фабрики позволяют строить декораторы с развитым API конфигурации:

```ts
interface CacheOptions {
  ttl: number;            // время жизни в ms
  maxSize: number;        // максимальное количество записей
  keyGenerator?: (...args: any[]) => string;
}

function Cache(options: CacheOptions) {
  return function (
    target: Object,
    propertyKey: string,
    descriptor: PropertyDescriptor
  ): void {
    const original = descriptor.value;
    const cache = new Map<string, { value: any; expires: number }>();
    const keyGen = options.keyGenerator ?? ((...args) => JSON.stringify(args));

    descriptor.value = function (this: any, ...args: any[]) {
      const key = keyGen(...args);
      const cached = cache.get(key);

      if (cached && cached.expires > Date.now()) {
        return cached.value;
      }

      // Очистка при превышении размера
      if (cache.size >= options.maxSize) {
        const oldest = cache.keys().next().value!;
        cache.delete(oldest);
      }

      const result = original.apply(this, args);
      cache.set(key, { value: result, expires: Date.now() + options.ttl });
      return result;
    };
  };
}

class ApiClient {
  @Cache({ ttl: 60_000, maxSize: 100 })
  fetchUser(id: number): Promise<any> {
    return fetch(`/api/users/${id}`).then(r => r.json());
  }
}
```

### 6.4 Композиция фабрик

Несколько фабрик могут быть скомбинированы для создания декларативного API:

```ts
function compose(...decorators: MethodDecorator[]): MethodDecorator {
  return (target, propertyKey, descriptor) => {
    // Применяем в обратном порядке (как при стекировании)
    for (let i = decorators.length - 1; i >= 0; i--) {
      decorators[i](target, propertyKey, descriptor);
    }
  };
}

const SecureEndpoint = compose(
  Authorize('admin'),
  Log,
  Throttle(1000)
);

class AdminController {
  @SecureEndpoint
  deleteUser(id: number): void { /* ... */ }
}
```

## 7. Порядок выполнения декораторов

### 7.1 Две фазы: evaluation и execution

Декораторы проходят через **две фазы**:

1. **Evaluation (вычисление)** --- вызов фабрик декораторов для получения функций-декораторов. Происходит **сверху вниз**.
2. **Execution (применение)** --- вызов самих декораторов. Происходит **снизу вверх**.

```ts
function first() {
  console.log('1: evaluation first');
  return function (target: any, key: string, desc: PropertyDescriptor) {
    console.log('1: execution first');
  };
}

function second() {
  console.log('2: evaluation second');
  return function (target: any, key: string, desc: PropertyDescriptor) {
    console.log('2: execution second');
  };
}

class Example {
  @first()
  @second()
  method() {}
}

// Вывод:
// 1: evaluation first    <-- фабрики сверху вниз
// 2: evaluation second
// 2: execution second    <-- декораторы снизу вверх
// 1: execution first
```

### 7.2 Полный порядок внутри класса

Спецификация TypeScript определяет строгий порядок выполнения декораторов:

| Приоритет | Тип декоратора | Порядок внутри группы |
|---|---|---|
| 1 | Декораторы параметров (instance) | Для каждого метода, справа налево |
| 2 | Декораторы методов / accessor / свойств (instance) | Снизу вверх по порядку в коде |
| 3 | Декораторы параметров (static) | Для каждого метода, справа налево |
| 4 | Декораторы методов / accessor / свойств (static) | Снизу вверх по порядку в коде |
| 5 | Декораторы параметров конструктора | Справа налево |
| 6 | Декоратор класса | Снизу вверх (если несколько) |

### 7.3 Демонстрация полного порядка

```ts
function d(name: string) {
  return function (...args: any[]) {
    console.log(name);
  };
}

function pd(name: string): ParameterDecorator {
  return function (target, key, index) {
    console.log(name);
  };
}

@d('8: class decorator')
class FullOrder {
  @d('2: instance property')
  prop: string = '';

  @d('5: static property')
  static staticProp: string = '';

  constructor(@pd('7: constructor param') x: number) {}

  @d('3: instance method')
  method(@pd('1: instance param') a: string): void {}

  @d('6: static method')
  static staticMethod(@pd('4: static param') b: string): void {}
}

// Порядок вывода:
// 1: instance param
// 2: instance property
// 3: instance method
// 4: static param
// 5: static property
// 6: static method
// 7: constructor param
// 8: class decorator
```

**Ключевое правило:** instance-члены обрабатываются раньше static-членов, параметры --- раньше своих методов, а декоратор класса всегда **последний**.

## 8. TC39 декораторы (Stage 3) vs Legacy

### 8.1 Новый API: value + context

В TC39 Stage 3 декоратор получает **два аргумента** вместо трёх:

```ts
type Decorator = (
  value: Function | undefined,  // декорируемое значение (метод, accessor, class)
  context: DecoratorContext      // объект контекста с метаинформацией
) => Function | void;

interface ClassMethodDecoratorContext {
  kind: 'method';
  name: string | symbol;
  static: boolean;
  private: boolean;
  access: { get(obj: any): any };
  addInitializer(fn: () => void): void;
  metadata: Record<string | symbol, any>;
}
```

### 8.2 Сравнительная таблица API

| Возможность | Legacy (`experimentalDecorators`) | TC39 Stage 3 (TS 5.0+) |
|---|---|---|
| Аргументы декоратора метода | `(target, key, descriptor)` | `(value, context)` |
| Замена метода | `descriptor.value = newFn` | `return newFn` |
| Доступ к имени | `propertyKey` | `context.name` |
| Определение static | `target === Constructor` | `context.static` |
| Определение private | Невозможно | `context.private` |
| Добавление инициализатора | Через замену конструктора | `context.addInitializer()` |
| Метаданные | `reflect-metadata` (сторонний) | `context.metadata` (встроенный) |
| Декоратор параметра | Поддерживается | **Не поддерживается** |
| Декоратор свойства (field) | Без descriptor | Получает `undefined`, может вернуть initializer |
| Auto-accessor | Не поддерживается | `accessor` keyword + decorator |

### 8.3 Пример TC39 декоратора метода

```ts
// TC39 Stage 3 — НЕ требует experimentalDecorators
function logged(
  originalMethod: Function,
  context: ClassMethodDecoratorContext
): Function {
  const methodName = String(context.name);

  function replacementMethod(this: any, ...args: any[]) {
    console.log(`[LOG] ${methodName} called`);
    const result = originalMethod.call(this, ...args);
    console.log(`[LOG] ${methodName} returned`);
    return result;
  }

  return replacementMethod;
}

class Calculator {
  @logged
  add(a: number, b: number): number {
    return a + b;
  }
}
```

### 8.4 Auto-accessor и addInitializer

TC39 вводит новый тип члена класса --- `accessor`, который создаёт getter/setter автоматически:

```ts
function clamp(min: number, max: number) {
  return function (
    _value: ClassAccessorDecoratorTarget<any, number>,
    context: ClassAccessorDecoratorContext
  ): ClassAccessorDecoratorResult<any, number> {
    return {
      set(value: number) {
        const clamped = Math.max(min, Math.min(max, value));
        context.access.set(this, clamped);  // вызов исходного setter
      },
      init(value: number) {
        return Math.max(min, Math.min(max, value));
      }
    };
  };
}

class Slider {
  @clamp(0, 100)
  accessor value: number = 50;
}

const s = new Slider();
s.value = 200;   // value === 100  (clamped)
s.value = -10;   // value === 0    (clamped)
```

`addInitializer` позволяет добавить код, выполняемый при создании экземпляра:

```ts
function bound(
  originalMethod: Function,
  context: ClassMethodDecoratorContext
): void {
  context.addInitializer(function (this: any) {
    this[context.name] = this[context.name].bind(this);
  });
}

class Button {
  label = 'Click me';

  @bound
  onClick() {
    console.log(this.label);
  }
}

const btn = new Button();
const handler = btn.onClick;
handler(); // 'Click me' --- this привязан корректно
```

### 8.5 Миграция с Legacy на TC39

Основные шаги миграции:

1. Удалить `"experimentalDecorators": true` из `tsconfig.json`
2. Заменить `(target, key, descriptor)` на `(value, context)` + `return`
3. Заменить `reflect-metadata` на `context.metadata`
4. Переписать декораторы параметров (через свойства или `addInitializer`)
5. Заменить `descriptor.value = ...` на `return newFunction`

### 9.1 Dependency Injection (NestJS-стиль)

```ts
// Регистрация зависимостей через декораторы класса и конструктора
const registry = new Map<string, { ctor: any; deps: string[] }>();

function Service(name?: string): ClassDecorator {
  return function (constructor: Function) {
    const paramTypes: any[] =
      Reflect.getMetadata('design:paramtypes', constructor) ?? [];
    const deps = paramTypes.map((t: any) => t.name);
    registry.set(name ?? constructor.name, { ctor: constructor, deps });
  };
}

@Service()
class UserRepository {
  findById(id: number) { return { id, name: 'John' }; }
}

@Service()
class UserService {
  constructor(private repo: UserRepository) {}
  getUser(id: number) { return this.repo.findById(id); }
}

// DI-контейнер резолвит зависимости по метаданным design:paramtypes
```

### 9.2 ORM Entity / Column

```ts
const ENTITY_META = Symbol('entity');
const COLUMN_META = Symbol('columns');

function Entity(table: string): ClassDecorator {
  return (target) => Reflect.defineMetadata(ENTITY_META, table, target);
}

function Column(opts: { type: string; primary?: boolean }): PropertyDecorator {
  return (target, key) => {
    const cols = Reflect.getMetadata(COLUMN_META, target.constructor) ?? [];
    cols.push({ key, ...opts });
    Reflect.defineMetadata(COLUMN_META, cols, target.constructor);
  };
}

@Entity('products')
class Product {
  @Column({ type: 'serial', primary: true })
  id!: number;

  @Column({ type: 'varchar(255)' })
  name!: string;

  @Column({ type: 'decimal(10,2)' })
  price!: number;
}

// SQL-генерация на основе метаданных:
const table = Reflect.getMetadata(ENTITY_META, Product);     // 'products'
const columns = Reflect.getMetadata(COLUMN_META, Product);   // [{ key: 'id', type: 'serial', ... }, ...]
// CREATE TABLE products (id serial PRIMARY KEY, name varchar(255), price decimal(10,2));
```

### 9.3 Валидация (class-validator стиль)

```ts
const VALIDATORS = Symbol('validators');

type ValidatorFn = (value: any) => string | null;

function registerValidator(target: Object, key: string | symbol, fn: ValidatorFn): void {
  const existing: Map<string | symbol, ValidatorFn[]> =
    Reflect.getMetadata(VALIDATORS, target) ?? new Map();
  const fns = existing.get(key) ?? [];
  fns.push(fn);
  existing.set(key, fns);
  Reflect.defineMetadata(VALIDATORS, existing, target);
}

function IsEmail(): PropertyDecorator {
  return (target, key) =>
    registerValidator(target, key, (v) =>
      /^[^\s@]+@[^\s@]+\.[^\s@]+$/.test(v) ? null : `${String(key)} must be a valid email`
    );
}

function MinLength(min: number): PropertyDecorator {
  return (target, key) =>
    registerValidator(target, key, (v) =>
      typeof v === 'string' && v.length >= min ? null : `${String(key)} must be at least ${min} chars`
    );
}

function validate<T extends object>(instance: T): string[] {
  const validators: Map<string, ValidatorFn[]> =
    Reflect.getMetadata(VALIDATORS, Object.getPrototypeOf(instance)) ?? new Map();
  const errors: string[] = [];

  for (const [key, fns] of validators) {
    for (const fn of fns) {
      const error = fn((instance as any)[key]);
      if (error) errors.push(error);
    }
  }
  return errors;
}

class CreateUserDto {
  @IsEmail()
  email!: string;

  @MinLength(8)
  password!: string;
}

const dto = new CreateUserDto();
dto.email = 'invalid';
dto.password = '123';
validate(dto);
// ['email must be a valid email', 'password must be at least 8 chars']
```

### 9.4 Route Decorators (Express/NestJS паттерн)

```ts
const ROUTES = Symbol('routes');

interface RouteDefinition {
  method: 'get' | 'post' | 'put' | 'delete';
  path: string;
  handlerName: string;
}

function Controller(basePath: string): ClassDecorator {
  return (target) => Reflect.defineMetadata('basePath', basePath, target);
}

function createRouteDecorator(method: RouteDefinition['method']) {
  return function (path: string): MethodDecorator {
    return (target, propertyKey) => {
      const routes: RouteDefinition[] =
        Reflect.getMetadata(ROUTES, target.constructor) ?? [];
      routes.push({ method, path, handlerName: String(propertyKey) });
      Reflect.defineMetadata(ROUTES, routes, target.constructor);
    };
  };
}

const Get = createRouteDecorator('get');
const Post = createRouteDecorator('post');
const Delete = createRouteDecorator('delete');

@Controller('/api/users')
class UserController {
  @Get('/')
  findAll(): any[] { return []; }

  @Get('/:id')
  findOne(): any { return {}; }

  @Post('/')
  create(): any { return {}; }

  @Delete('/:id')
  remove(): void {}
}

// Регистрация в Express:
function registerController(app: any, ControllerClass: any): void {
  const basePath = Reflect.getMetadata('basePath', ControllerClass);
  const routes: RouteDefinition[] = Reflect.getMetadata(ROUTES, ControllerClass) ?? [];
  const instance = new ControllerClass();

  for (const route of routes) {
    app[route.method](basePath + route.path, (req: any, res: any) => {
      const result = instance[route.handlerName](req, res);
      res.json(result);
    });
  }
}
// registerController(app, UserController);
// GET /api/users/ -> findAll
// GET /api/users/:id -> findOne
// POST /api/users/ -> create
// DELETE /api/users/:id -> remove
```

### 9.5 Авторизация и Guards

```ts
function Authorize(...roles: string[]): MethodDecorator {
  return (target, propertyKey, descriptor: PropertyDescriptor) => {
    const original = descriptor.value;

    descriptor.value = function (this: any, ...args: any[]) {
      const user = this.currentUser ?? args[0]?.user;

      if (!user) {
        throw new Error('Unauthorized: no user context');
      }
      if (roles.length > 0 && !roles.some(r => user.roles?.includes(r))) {
        throw new Error(`Forbidden: requires one of [${roles.join(', ')}]`);
      }

      return original.apply(this, args);
    };
  };
}

class AdminController {
  currentUser = { roles: ['user'] };

  @Authorize('admin', 'superadmin')
  deleteDatabase(): void {
    console.log('Database deleted');
  }

  @Authorize()  // любой аутентифицированный пользователь
  getProfile(): object {
    return { name: 'John' };
  }
}

const ctrl = new AdminController();
ctrl.getProfile();      // OK
ctrl.deleteDatabase();  // Error: Forbidden: requires one of [admin, superadmin]
```
