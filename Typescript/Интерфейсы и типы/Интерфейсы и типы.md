# Интерфейсы и типы — полное руководство

> В TypeScript существуют два основных механизма описания формы данных: `interface` и `type alias`.
> Несмотря на значительное пересечение возможностей, каждый из них имеет уникальные свойства,
> определяющие выбор в конкретных ситуациях.

## 1. `type` vs `interface` — полное сравнение

### 1.1 Базовый синтаксис

`interface` описывает контракт объекта. `type` создаёт псевдоним для **любого** типа.

```typescript
// interface — только объектные формы
interface User {
  id: number;
  name: string;
}

// type alias — любой тип: примитив, объединение, кортеж, функция
type ID = number | string;
type Pair = [string, number];
type Callback = (data: string) => void;

// type для объектной формы — синтаксически идентичен interface
type Product = {
  sku: string;
  price: number;
};
```

### 1.2 Declaration Merging — ключевое отличие

Только `interface` поддерживает **слияние объявлений** (declaration merging). Повторное объявление `type` с тем же именем вызывает ошибку компиляции:

```typescript
interface Window {
  analytics: Analytics;
}
interface Window {
  dataLayer: unknown[];
}
// Результат: Window имеет и analytics, и dataLayer

type Point = { x: number };
type Point = { y: number }; // Error: Duplicate identifier 'Point'
```

### 1.3 Union и Intersection — преимущество `type`

`interface` не может описать union type напрямую. Это исключительная прерогатива `type`:

```typescript
// Только type может создать union
type Result = Success | Failure;
type StringOrNumber = string | number;

// interface не может:
// interface Result = Success | Failure; // Синтаксическая ошибка

// Intersection доступен обоим, но синтаксис отличается:
type Combined = A & B;        // type — через &
interface Combined extends A, B {} // interface — через extends
```

### 1.4 Computed Properties и Mapped Types

`type` поддерживает **mapped types** и `in` operator. `interface` — нет:

```typescript
type Flags<T extends string> = {
  [K in T]: boolean;
};

type FeatureFlags = Flags<"darkMode" | "newUI" | "beta">;
// { darkMode: boolean; newUI: boolean; beta: boolean }

// interface не может использовать mapped types:
// interface Flags<T extends string> { [K in T]: boolean } // Error
```

### 1.5 Производительность компилятора

**Важно:** `interface` создаёт **именованный тип** в реестре компилятора, к которому можно обращаться по имени. `type` с intersection (`&`) создаёт анонимную структуру, которую компилятор каждый раз разворачивает.

```typescript
// interface — кэшируется по имени, быстрая проверка совместимости
interface UserA {
  id: number;
  name: string;
  email: string;
}

// type с intersection — компилятор развернёт на каждой проверке
type UserB = { id: number } & { name: string } & { email: string };

// В проектах с тысячами типов interface может быть быстрее при type-checking
// (точная разница зависит от проекта). Рекомендация TypeScript team: предпочитайте
// interface для объектных форм, type — для union, tuple и mapped types.
```

### 1.6 Сводная таблица возможностей

| Возможность                     | `interface` | `type`  |
| ------------------------------- | ----------- | ------- |
| Описание объектной формы        | Да          | Да      |
| Declaration Merging             | **Да**      | Нет     |
| `extends` (наследование)        | Да          | Нет (`&` вместо) |
| `implements` (реализация классом) | Да        | Да (с ограничениями) |
| Union types                     | Нет         | **Да**  |
| Tuple types                     | Нет         | **Да**  |
| Mapped types                    | Нет         | **Да**  |
| Primitive alias                 | Нет         | **Да**  |
| Conditional types               | Нет         | **Да**  |
| Computed properties (`in`)      | Нет         | **Да**  |
| Именованный тип в ошибках       | **Да** (имя) | Развёрнутая структура |
| Скорость проверки типов         | Быстрее    | Медленнее (intersections) |

## 2. Declaration Merging

### 2.1 Механизм слияния интерфейсов

Когда компилятор TypeScript встречает несколько объявлений `interface` с одним именем в одной области видимости, он **сливает** их в единый интерфейс. Порядок слияния определён спецификацией: последнее объявление имеет **более высокий приоритет** для перегрузок методов.

```typescript
interface Document {
  createElement(tagName: "div"): HTMLDivElement;
}

interface Document {
  createElement(tagName: "span"): HTMLSpanElement;
}

interface Document {
  createElement(tagName: string): HTMLElement;
}

// Результат слияния (порядок перегрузок — от последнего к первому):
// interface Document {
//   createElement(tagName: string): HTMLElement;    ← из 3-го блока
//   createElement(tagName: "span"): HTMLSpanElement; ← из 2-го блока
//   createElement(tagName: "div"): HTMLDivElement;   ← из 1-го блока
// }
```

**Важно:** Исключение из правила «последнее выше» — перегрузки с **string literal** параметрами всегда поднимаются наверх внутри каждого блока.

### 2.2 Правила совместимости при слиянии

Если одно и то же свойство (не метод) объявлено в нескольких блоках, их типы должны быть **идентичны**, иначе компилятор выдаст ошибку:

```typescript
interface Config {
  debug: boolean;
}

interface Config {
  debug: boolean; // OK — тип совпадает
}

interface Config {
  debug: string; // Error: Subsequent property declarations must have the same type.
}
```

### 2.3 Module Augmentation — расширение сторонних типов

`declare module` позволяет добавлять свойства к типам из внешних библиотек без модификации их исходного кода:

```typescript
// Расширяем тип Express.Request
import "express";

declare module "express" {
  interface Request {
    userId?: string;
    sessionToken?: string;
  }
}

// Теперь в обработчиках Express:
app.get("/api", (req, res) => {
  console.log(req.userId); // OK — свойство доступно без ошибок
});
```

### 2.4 Global Augmentation

Для добавления свойств к глобальным объектам используется `declare global`:

```typescript
// В .ts файле (модуле — есть import/export)
export {};

declare global {
  interface Window {
    __APP_VERSION__: string;
    __DEBUG_MODE__: boolean;
  }

  // Расширение глобального интерфейса Array
  interface Array<T> {
    customShuffle(): T[];
  }
}

// Использование:
window.__APP_VERSION__ = "2.1.0"; // OK
[1, 2, 3].customShuffle();        // OK по типам (реализация отдельно)
```

### 2.5 Ambient Declarations для нетипизированных модулей

Когда библиотека не имеет `.d.ts` файлов, можно создать ambient declaration:

```typescript
// types/untyped-lib.d.ts
declare module "legacy-analytics" {
  export function track(event: string, data?: Record<string, unknown>): void;
  export function identify(userId: string): void;

  interface AnalyticsConfig {
    apiKey: string;
    debug?: boolean;
  }

  export function init(config: AnalyticsConfig): void;
}
```

## 3. `extends` vs `implements`

### 3.1 Interface extending Interface

`extends` создаёт новый интерфейс, наследующий все свойства родительского. При конфликте типов свойств компилятор требует, чтобы дочерний тип был **совместим** (более узкий или идентичный):

```typescript
interface Animal {
  name: string;
  sound(): string;
}

interface Dog extends Animal {
  breed: string;
  // sound() наследуется автоматически
}

const rex: Dog = {
  name: "Rex",
  breed: "Shepherd",
  sound() { return "Woof!"; },
};
```

### 3.2 Multiple extends

Интерфейс может наследовать от **нескольких** интерфейсов одновременно:

```typescript
interface Serializable {
  serialize(): string;
}

interface Loggable {
  log(level: "info" | "warn" | "error"): void;
}

interface Timestamped {
  createdAt: Date;
  updatedAt: Date;
}

// Множественное наследование
interface AuditableEntity extends Serializable, Loggable, Timestamped {
  auditId: string;
}

// AuditableEntity объединяет ВСЕ свойства из трёх интерфейсов + своё auditId
```

### 3.3 Interface extending Type

`interface` может расширять `type`, если тип описывает объектную форму:

```typescript
type BaseConfig = {
  host: string;
  port: number;
};

interface ServerConfig extends BaseConfig {
  ssl: boolean;
  cert?: string;
}

// Нельзя наследовать от union type:
type MixedInput = string | number;
// interface Parser extends MixedInput {} // Error: An interface can only extend
//                                        // an object type or intersection of object types
```

### 3.4 Class implementing Interface

`implements` указывает, что класс **обязан** реализовать все свойства и методы интерфейса. При этом `implements` не добавляет типы автоматически — класс должен объявить их явно:

```typescript
interface Repository<T> {
  findById(id: string): Promise<T | null>;
  findAll(): Promise<T[]>;
  save(entity: T): Promise<void>;
  delete(id: string): Promise<boolean>;
}

class UserRepository implements Repository<User> {
  // Каждый метод ДОЛЖЕН быть реализован
  async findById(id: string): Promise<User | null> {
    return db.users.findOne({ id });
  }

  async findAll(): Promise<User[]> {
    return db.users.find({});
  }

  async save(entity: User): Promise<void> {
    await db.users.upsert(entity);
  }

  async delete(id: string): Promise<boolean> {
    const result = await db.users.deleteOne({ id });
    return result.deletedCount > 0;
  }
}
```

### 3.5 Множественный `implements`

Класс может реализовать несколько интерфейсов, но **не** может реализовать union type:

```typescript
interface Printable {
  print(): string;
}

interface Comparable<T> {
  compareTo(other: T): number;
}

class Invoice implements Printable, Comparable<Invoice> {
  constructor(public amount: number, public date: Date) {}

  print(): string {
    return `Invoice: $${this.amount} on ${this.date.toISOString()}`;
  }

  compareTo(other: Invoice): number {
    return this.amount - other.amount;
  }
}
```

### 3.6 Ключевые различия `extends` и `implements`

| Аспект               | `extends`                                        | `implements`                                       |
| -------------------- | ------------------------------------------------ | -------------------------------------------------- |
| Кто использует       | Интерфейс / класс                               | Только класс                                       |
| Что делает           | Наследует тип и (для классов) реализацию         | Проверяет контракт, **не наследует** реализацию    |
| Runtime эффект       | Да (для классов — прототипная цепочка)           | Нет — чисто compile-time проверка                  |
| Множественный        | Интерфейс — да, класс — нет (одиночное наследование) | Да (сколько угодно)                           |
| Автоматические типы  | Да — тип свойства выводится из родителя          | Нет — нужно объявить типы повторно                 |

## 4. Объединение и пересечение типов (Union & Intersection)

### 4.1 Union Types (`A | B`)

Union означает, что значение может быть **одним из** перечисленных типов. До сужения (narrowing) доступны только **общие** свойства:

```typescript
type Shape =
  | { kind: "circle"; radius: number }
  | { kind: "rect"; width: number; height: number }
  | { kind: "triangle"; base: number; height: number };

function area(shape: Shape): number {
  switch (shape.kind) {
    case "circle":
      // TypeScript сузил тип до { kind: "circle"; radius: number }
      return Math.PI * shape.radius ** 2;
    case "rect":
      return shape.width * shape.height;
    case "triangle":
      return (shape.base * shape.height) / 2;
  }
}
```

### 4.2 Exhaustive check с `never`

Чтобы компилятор гарантировал обработку всех вариантов union, используется `never`:

```typescript
function assertNever(value: never): never {
  throw new Error(`Unhandled case: ${JSON.stringify(value)}`);
}

function describe(shape: Shape): string {
  switch (shape.kind) {
    case "circle":
      return `Circle r=${shape.radius}`;
    case "rect":
      return `Rectangle ${shape.width}x${shape.height}`;
    case "triangle":
      return `Triangle b=${shape.base} h=${shape.height}`;
    default:
      // Если добавить новый вариант в Shape и забыть обработать —
      // компилятор покажет ошибку: Argument of type '...' is not assignable to 'never'
      return assertNever(shape);
  }
}
```

### 4.3 Intersection Types (`A & B`)

Intersection объединяет **все** свойства из обоих типов в один:

```typescript
type WithId = { id: string };
type WithTimestamps = { createdAt: Date; updatedAt: Date };
type WithSoftDelete = { deletedAt: Date | null };

type BaseEntity = WithId & WithTimestamps & WithSoftDelete;
// Результат: { id: string; createdAt: Date; updatedAt: Date; deletedAt: Date | null }

// Практический паттерн — mixin-подход:
type ApiResponse<T> = {
  data: T;
  status: number;
} & WithTimestamps;

const response: ApiResponse<User[]> = {
  data: [{ id: "1", name: "Alice" }],
  status: 200,
  createdAt: new Date(),
  updatedAt: new Date(),
};
```

### 4.4 `never` при пересечении несовместимых типов

Пересечение примитивных типов, не имеющих общих значений, даёт `never`:

```typescript
type Impossible = string & number; // never — нет значения, которое одновременно string и number

// Для объектных типов конфликт проявляется на уровне свойств:
type A = { value: string };
type B = { value: number };
type C = A & B;
// C = { value: string & number } = { value: never }
// Тип C существует, но свойство value невозможно присвоить

const obj: C = { value: "hello" as never }; // единственный способ — каст через never
```

### 4.5 Distributive Conditional Types

В conditional types union **распределяется** (distributive behavior):

```typescript
type ToArray<T> = T extends unknown ? T[] : never;

// Подставляется union → распределение по каждому члену:
type Result = ToArray<string | number>;
// = (string extends unknown ? string[] : never) | (number extends unknown ? number[] : never)
// = string[] | number[]

// Без distributive (обернуть в tuple):
type ToArrayNonDist<T> = [T] extends [unknown] ? T[] : never;

type Result2 = ToArrayNonDist<string | number>;
// = (string | number)[]  ← единый массив, а не union массивов
```

### 4.6 Narrowing union через `in`, `typeof`, `instanceof`

```typescript
type Fish = { swim(): void; name: string };
type Bird = { fly(): void; name: string };

function move(animal: Fish | Bird): string {
  // in operator — проверяет наличие свойства
  if ("swim" in animal) {
    animal.swim(); // TypeScript знает: это Fish
    return `${animal.name} swims`;
  }
  animal.fly(); // TypeScript знает: это Bird
  return `${animal.name} flies`;
}

// typeof — для примитивных union
function format(value: string | number): string {
  if (typeof value === "string") {
    return value.toUpperCase(); // string
  }
  return value.toFixed(2); // number
}
```

## 5. Индексные сигнатуры (Index Signatures)

### 5.1 String Index Signature

Индексная сигнатура описывает тип значений для **произвольных** ключей:

```typescript
interface StringMap {
  [key: string]: string;
}

const headers: StringMap = {
  "Content-Type": "application/json",
  "Authorization": "Bearer token123",
  // Любой строковый ключ допустим
};

headers["X-Custom"] = "value"; // OK
headers["anything"] = 42;      // Error: Type 'number' is not assignable to type 'string'
```

### 5.2 Number Index Signature

Числовой индекс используется для описания массивоподобных структур:

```typescript
interface StringArray {
  [index: number]: string;
  length: number;
}

const arr: StringArray = {
  0: "hello",
  1: "world",
  length: 2,
};
```

### 5.3 Взаимодействие string и number индексов

**Критическое правило:** числовой индекс должен возвращать **подтип** строкового индекса, потому что JavaScript преобразует числовые ключи в строки (`obj[0]` === `obj["0"]`):

```typescript
interface Valid {
  [key: string]: Animal;
  [index: number]: Dog; // OK — Dog extends Animal
}

interface Invalid {
  [key: string]: Dog;
  [index: number]: Animal; // Error: 'Animal' is not assignable to 'Dog'
  // Нарушение: число-индекс должен быть подтипом строкового
}
```

### 5.4 Совмещение индексной сигнатуры с явными свойствами

Все явные свойства должны быть совместимы с индексной сигнатурой:

```typescript
interface Config {
  [key: string]: string | number | boolean;

  host: string;       // OK — string совместим с string | number | boolean
  port: number;       // OK
  debug: boolean;     // OK
  // tags: string[];  // Error — string[] не совместим с string | number | boolean
}
```

### 5.5 `Record<K, V>` как альтернатива

`Record` создаёт объектный тип с фиксированным набором ключей. В отличие от индексной сигнатуры, `Record` ограничивает набор допустимых ключей:

```typescript
// Индексная сигнатура — любой строковый ключ
type DictA = { [key: string]: number };

// Record — только указанные ключи
type DictB = Record<"x" | "y" | "z", number>;

const a: DictA = { x: 1, anything: 2 };         // OK
const b: DictB = { x: 1, y: 2, z: 3 };          // OK
const c: DictB = { x: 1, y: 2, z: 3, w: 4 };    // Error: 'w' does not exist

// Record с union ключей — мощный паттерн для enum-like объектов:
type HttpMethod = "GET" | "POST" | "PUT" | "DELETE";
type RouteHandler = (req: Request) => Response;

type Routes = Record<HttpMethod, RouteHandler>;
```

### 5.6 Template Literal Index Signatures (TS 4.4+)

TypeScript позволяет использовать template literal types в индексных сигнатурах:

```typescript
interface CSSVariables {
  [key: `--${string}`]: string;
}

const styles: CSSVariables = {
  "--primary-color": "#3b82f6",
  "--font-size": "16px",
  // color: "red",  // Error: 'color' is not assignable — нет префикса '--'
};

// Комбинация с явными свойствами:
interface DataAttributes {
  [key: `data-${string}`]: string;
  id: string;
  className: string;
}
```

## 6. Опциональные свойства и Exact types

### 6.1 Опциональные свойства (`?`)

Символ `?` после имени свойства делает его необязательным. Тип автоматически расширяется на `undefined`:

```typescript
interface UserProfile {
  name: string;
  email: string;
  bio?: string;       // string | undefined
  avatarUrl?: string;  // string | undefined
}

// Присвоение undefined явно допустимо:
const user: UserProfile = {
  name: "Alice",
  email: "alice@example.com",
  bio: undefined, // OK
  // avatarUrl пропущен — тоже OK
};
```

**Важно:** с `strictNullChecks: true` (рекомендуется) необходимо проверять optional свойства перед использованием:

```typescript
function displayBio(profile: UserProfile): string {
  // profile.bio может быть undefined
  if (profile.bio !== undefined) {
    return profile.bio.toUpperCase(); // OK — сужение до string
  }
  return "No bio provided";
}
```

### 6.2 Excess Property Checking — строгая проверка литералов

TypeScript применяет **строгую проверку лишних свойств** только к **свежим объектным литералам** (fresh object literals):

```typescript
interface Point {
  x: number;
  y: number;
}

// Fresh literal — строгая проверка:
const p1: Point = { x: 1, y: 2, z: 3 }; // Error: 'z' does not exist in type 'Point'

// Через промежуточную переменную — проверки нет (structural compatibility):
const temp = { x: 1, y: 2, z: 3 };
const p2: Point = temp; // OK — temp структурно совместим с Point

// В аргументах функции — аналогично:
function draw(point: Point) {}
draw({ x: 1, y: 2, z: 3 });         // Error — fresh literal
draw(temp);                           // OK — не fresh
```

### 6.3 Weak Types

Если **все** свойства интерфейса опциональны, TypeScript применяет дополнительную проверку: объект должен содержать **хотя бы одно** свойство из интерфейса (Weak Type Detection):

```typescript
interface PaginationOptions {
  page?: number;
  limit?: number;
  offset?: number;
}

function paginate(opts: PaginationOptions) {}

paginate({ page: 1 });                   // OK
paginate({});                             // OK — все свойства опциональны
paginate({ sort: "name" } as any);        // без as any — Error
// paginate({ sort: "name" });            // Error: Type '{ sort: string }' has no
                                          // properties in common with type 'PaginationOptions'
```

### 6.4 Workaround для Exact Types

TypeScript **не** поддерживает exact types нативно (в отличие от Flow). Но есть паттерны для эмуляции:

```typescript
// Паттерн 1: Generic constraint
type Exact<T, Shape> = T extends Shape
  ? Exclude<keyof T, keyof Shape> extends never
    ? T
    : never
  : never;

function createPoint<T extends Point>(point: Exact<T, Point>): Point {
  return point;
}

createPoint({ x: 1, y: 2 });           // OK
// createPoint({ x: 1, y: 2, z: 3 });  // Error — z не входит в Point

// Паттерн 2: satisfies (TS 4.9+) — проверяет тип без расширения
const config = {
  host: "localhost",
  port: 3000,
  debug: true,
} satisfies Record<string, string | number | boolean>;
// Тип config сохраняет литеральные типы: { host: "localhost", port: 3000, debug: true }
```

## 7. Call Signatures и Construct Signatures

### 7.1 Call Signatures — вызываемый интерфейс

Call signature описывает интерфейс, экземпляры которого можно **вызывать** как функцию:

```typescript
interface Formatter {
  (input: string): string;
}

const upperCase: Formatter = (input) => input.toUpperCase();
const result = upperCase("hello"); // "HELLO"

// Эквивалент через type:
type FormatterFn = (input: string) => string;
```

### 7.2 Construct Signatures — newable интерфейс

Construct signature описывает объект, который можно вызвать через `new`:

```typescript
interface Constructor<T> {
  new (name: string): T;
}

class Animal {
  constructor(public name: string) {}
}

function create<T>(Ctor: Constructor<T>, name: string): T {
  return new Ctor(name);
}

const dog = create(Animal, "Rex"); // Animal
```

### 7.3 Hybrid Types — вызываемый объект со свойствами

Интерфейс может описать объект, который одновременно **вызывается** и имеет **свойства**. Это распространённый паттерн в JavaScript-библиотеках (jQuery, Express):

```typescript
interface Counter {
  // Call signature
  (start: number): void;

  // Свойства
  count: number;
  reset(): void;
  increment(): void;
}

function createCounter(): Counter {
  const fn = function (start: number) {
    fn.count = start;
  } as Counter;

  fn.count = 0;
  fn.reset = () => { fn.count = 0; };
  fn.increment = () => { fn.count++; };

  return fn;
}

const counter = createCounter();
counter(10);          // Вызов как функция — count = 10
counter.increment();  // Метод — count = 11
counter.count;        // Свойство — 11
```

### 7.4 Overloaded Call Signatures

Интерфейс может содержать несколько call signatures — это **перегрузки**:

```typescript
interface EventEmitter {
  // Перегрузки для конкретных событий
  on(event: "click", handler: (e: MouseEvent) => void): void;
  on(event: "keydown", handler: (e: KeyboardEvent) => void): void;
  on(event: "scroll", handler: (e: Event) => void): void;

  // Общий fallback
  on(event: string, handler: (e: Event) => void): void;
}

declare const emitter: EventEmitter;

emitter.on("click", (e) => {
  // e: MouseEvent — TypeScript выбрал первую перегрузку
  console.log(e.clientX, e.clientY);
});

emitter.on("keydown", (e) => {
  // e: KeyboardEvent — вторая перегрузка
  console.log(e.key);
});
```

### 7.5 Комбинация Call + Construct Signature

Некоторые объекты поддерживают оба вызова (пример — `Date` в JavaScript):

```typescript
interface DateConstructor {
  // Construct signature — new Date()
  new (): Date;
  new (value: number): Date;
  new (dateString: string): Date;

  // Call signature — Date() без new
  (): string;

  // Статические методы
  now(): number;
  parse(dateString: string): number;
}
```

## 8. Рекурсивные типы

### 8.1 Самоссылающиеся типы — основы

TypeScript поддерживает рекурсивные ссылки в определении типа — тип может ссылаться сам на себя:

```typescript
// Простейший пример — связный список
type ListNode<T> = {
  value: T;
  next: ListNode<T> | null;
};

const list: ListNode<number> = {
  value: 1,
  next: {
    value: 2,
    next: {
      value: 3,
      next: null,
    },
  },
};
```

### 8.2 JSON type — классический пример рекурсивного типа

```typescript
// Тип, описывающий любое допустимое JSON-значение
type JSONValue =
  | string
  | number
  | boolean
  | null
  | JSONValue[]          // массив JSON-значений (рекурсия)
  | { [key: string]: JSONValue }; // объект с JSON-значениями (рекурсия)

// Использование:
const data: JSONValue = {
  name: "Alice",
  age: 30,
  active: true,
  address: {
    city: "Moscow",
    coords: [55.75, 37.62], // вложенный массив
  },
  tags: ["admin", "user"],
  metadata: null,
};

// Компилятор корректно проверяет невалидные значения:
const invalid: JSONValue = {
  handler: () => {},  // Error: Type '() => void' is not assignable to type 'JSONValue'
  date: new Date(),   // Error: Type 'Date' is not assignable to type 'JSONValue'
};
```

### 8.3 Древовидные структуры

```typescript
// Файловая система
interface FileNode {
  name: string;
  type: "file";
  size: number;
}

interface DirectoryNode {
  name: string;
  type: "directory";
  children: TreeNode[]; // Рекурсия через union
}

type TreeNode = FileNode | DirectoryNode;

const projectTree: TreeNode = {
  name: "src",
  type: "directory",
  children: [
    { name: "index.ts", type: "file", size: 1024 },
    {
      name: "components",
      type: "directory",
      children: [
        { name: "App.tsx", type: "file", size: 2048 },
        {
          name: "ui",
          type: "directory",
          children: [
            { name: "Button.tsx", type: "file", size: 512 },
          ],
        },
      ],
    },
  ],
};

// Рекурсивная функция обхода с корректным narrowing:
function totalSize(node: TreeNode): number {
  if (node.type === "file") {
    return node.size;
  }
  return node.children.reduce((sum, child) => sum + totalSize(child), 0);
}
```

### 8.4 Рекурсивные Conditional Types

TypeScript 4.1+ разрешил рекурсию в conditional types, что открыло мощные возможности для глубокой трансформации типов:

```typescript
// DeepReadonly — рекурсивно делает все свойства readonly
type DeepReadonly<T> = T extends (infer U)[]
  ? ReadonlyArray<DeepReadonly<U>>
  : T extends object
    ? { readonly [K in keyof T]: DeepReadonly<T[K]> }
    : T;

interface Config {
  db: {
    host: string;
    credentials: {
      user: string;
      password: string;
    };
  };
  features: string[];
}

type ReadonlyConfig = DeepReadonly<Config>;
// Результат:
// {
//   readonly db: {
//     readonly host: string;
//     readonly credentials: {
//       readonly user: string;
//       readonly password: string;
//     };
//   };
//   readonly features: ReadonlyArray<string>;
// }
```

### 8.5 Глубокий Partial и DeepRequired

```typescript
// DeepPartial — все свойства на всех уровнях вложенности опциональны
type DeepPartial<T> = T extends object
  ? { [K in keyof T]?: DeepPartial<T[K]> }
  : T;

// Использование — удобно для patch/merge операций:
function mergeConfig(base: Config, patch: DeepPartial<Config>): Config {
  return deepMerge(base, patch) as Config;
}

// Можно передать только нужные вложенные поля:
mergeConfig(defaultConfig, {
  db: { credentials: { password: "new-password" } },
});
```

### 8.6 Ограничения рекурсии и обработка циклов компилятором

**Важно:** компилятор TypeScript имеет ограничение глубины рекурсии типов (по умолчанию ~50 уровней для conditional types). При превышении лимита компилятор выдаёт ошибку `Type instantiation is excessively deep and possibly infinite`.

```typescript
// Пример искусственного ограничения глубины:
type MaxDepth = 10;

type DeepNested<T, Depth extends unknown[] = []> =
  Depth["length"] extends MaxDepth
    ? T // Прекращаем рекурсию на глубине MaxDepth
    : T extends object
      ? { [K in keyof T]: DeepNested<T[K], [...Depth, unknown]> }
      : T;

// Circular references в interface обрабатываются корректно,
// потому что interface использует ленивое (lazy) разрешение типов:
interface Category {
  name: string;
  parent: Category | null;     // OK — interface разрешает лениво
  subcategories: Category[];   // OK — рекурсивная ссылка
}

// type alias с прямой рекурсией объектной формы тоже работает (с TS 3.7+):
type CategoryType = {
  name: string;
  parent: CategoryType | null;
  subcategories: CategoryType[];
};
```
