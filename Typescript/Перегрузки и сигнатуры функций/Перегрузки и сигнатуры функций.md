# Перегрузки и сигнатуры функций — полное руководство

> В TypeScript перегрузки функций (function overloads) позволяют описать несколько
> вариантов вызова одной и той же функции с разными типами параметров и возвращаемых
> значений. Это мощный инструмент для создания точных и безопасных API, недоступный
> в чистом JavaScript.

## 1. Перегрузки функций (Function Overloads)

### 1.1 Базовый механизм

Перегрузка функции в TypeScript состоит из двух частей: **overload signatures** (сигнатуры перегрузок) и **implementation signature** (сигнатура реализации). Overload signatures описывают допустимые варианты вызова, а implementation signature содержит тело функции и должна быть совместима со всеми перегрузками.

```typescript
// Overload signatures — видны вызывающему коду
function format(value: string): string;
function format(value: number): string;
function format(value: Date): string;

// Implementation signature — НЕ видна вызывающему коду
function format(value: string | number | Date): string {
  if (typeof value === "string") return value.trim();
  if (typeof value === "number") return value.toFixed(2);
  return value.toISOString();
}

format("hello");     // OK — соответствует первой перегрузке
format(42);          // OK — соответствует второй перегрузке
format(new Date());  // OK — соответствует третьей перегрузке
format(true);        // Error: No overload matches this call
```

### 1.2 Порядок разрешения перегрузок

Компилятор TypeScript перебирает overload signatures **сверху вниз** и выбирает **первую** подходящую. Это значит, что порядок критически важен — более узкие (specific) типы должны идти **раньше** широких:

```typescript
// ПРАВИЛЬНО: узкий тип перед широким
function process(value: "admin"): AdminUser;
function process(value: string): User;
function process(value: string): AdminUser | User {
  return value === "admin" ? createAdmin() : createUser(value);
}

const admin = process("admin"); // AdminUser — подошла первая перегрузка
const user = process("guest");  // User — подошла вторая перегрузка

// НЕПРАВИЛЬНО: широкий тип первым «перехватывает» всё
function processBad(value: string): User;
function processBad(value: "admin"): AdminUser; // никогда не будет выбрана!
function processBad(value: string): AdminUser | User {
  return value === "admin" ? createAdmin() : createUser(value);
}

const result = processBad("admin"); // User, а НЕ AdminUser!
```

### 1.3 Связь параметров и возвращаемого типа

Главное преимущество перегрузок — возможность связать конкретный тип аргумента с конкретным типом возвращаемого значения:

```typescript
function getElementById(id: string): HTMLElement | null;
function getElementById(id: string, required: true): HTMLElement;
function getElementById(id: string, required: false): HTMLElement | null;
function getElementById(id: string, required?: boolean): HTMLElement | null {
  const el = document.getElementById(id);
  if (required && !el) throw new Error(`Element #${id} not found`);
  return el;
}

// Компилятор точно знает тип возвращаемого значения
const maybeEl = getElementById("app");        // HTMLElement | null
const definiteEl = getElementById("app", true); // HTMLElement — без null!
```

**Важно:** без перегрузок пришлось бы возвращать `HTMLElement | null` во всех случаях, и вызывающий код был бы вынужден делать лишние проверки на `null`.

## 2. Правила написания перегрузок

### 2.1 Implementation signature не является вызываемой

Сигнатура реализации — это «внутренний контракт» функции. Она не входит в список доступных для вызова перегрузок:

```typescript
function createId(value: number): string;
function createId(value: string): string;
function createId(value: number | string): string {
  return `id_${value}`;
}

createId(42);      // OK
createId("abc");   // OK
createId(true);    // Error — нет подходящей перегрузки
// Даже если implementation принимает boolean:
// function createId(value: number | string | boolean): string
// ...вызов createId(true) всё равно ошибка, потому что
// ни одна overload signature не принимает boolean
```

### 2.2 Количество перегрузок

Допустима даже **одна** overload signature + implementation signature. Это полезно, когда нужно скрыть от вызывающего кода более широкий тип реализации (например, implementation принимает `string | number`, но публичный API ограничен `string`):

```typescript
// Одна overload signature — ограничивает публичный API
function parseId(input: string): number;
function parseId(input: string | number): number {
  return typeof input === "number" ? input : parseInt(input, 10);
}

parseId("42");  // OK — соответствует overload signature
parseId(42);    // Error — implementation принимает number, но overload не разрешает
```

Чаще всего используются **две и более** overload signatures — для связи конкретного типа аргумента с конкретным типом результата:

### 2.3 Совместимость перегрузок с реализацией

Каждая overload signature **должна** быть совместима (assignable) с implementation signature. Параметры реализации должны быть достаточно широкими, а возвращаемый тип — достаточно общим:

```typescript
// Error: параметр реализации слишком узкий
function parse(input: string): object;
function parse(input: Buffer): object;
function parse(input: string): object { // Error! Buffer не assignable к string
  return JSON.parse(input.toString());
}

// Правильно:
function parse(input: string): object;
function parse(input: Buffer): object;
function parse(input: string | Buffer): object {
  return JSON.parse(input.toString());
}
```

### 2.4 Типичные ошибки

| Ошибка | Описание | Решение |
|---|---|---|
| Широкий тип перед узким | Узкая перегрузка никогда не будет выбрана | Располагать узкие типы первыми |
| Несовместимая реализация | Параметры реализации не покрывают все перегрузки | Расширить тип параметров реализации через union |
| Одна перегрузка без цели | Одна overload signature с тем же типом, что и реализация, избыточна | Убрать перегрузку или использовать её для сужения публичного API |
| Забыли `return` для ветки | Runtime ошибка при вызове конкретной перегрузки | Добавить exhaustive check в реализации |
| Перегрузка только ради union-параметра | Избыточная сложность без выгоды | Использовать union тип напрямую |

**Важно:** реализация перегрузки должна корректно обрабатывать **все** варианты вызова. TypeScript проверяет совместимость сигнатур, но **не** проверяет, что тело функции правильно обрабатывает каждый случай.

## 3. Перегрузки vs Union типы

### 3.1 Когда union достаточно

Если связь между типом параметра и типом результата **не нужна**, union-тип проще и предпочтительнее:

```typescript
// Перегрузка ИЗБЫТОЧНА — обе ветки возвращают string
function toUpper(value: string): string;
function toUpper(value: string[]): string;
function toUpper(value: string | string[]): string {
  return Array.isArray(value) ? value.join(", ").toUpperCase() : value.toUpperCase();
}

// Union-тип — проще и чище:
function toUpper(value: string | string[]): string {
  return Array.isArray(value) ? value.join(", ").toUpperCase() : value.toUpperCase();
}
```

### 3.2 Когда перегрузки необходимы

Перегрузки дают преимущество, когда тип возвращаемого значения **зависит** от типа аргументов:

```typescript
// С перегрузками — точный возвращаемый тип
function clone(value: string): string;
function clone(value: number): number;
function clone(value: boolean): boolean;
function clone(value: string | number | boolean): string | number | boolean {
  return value;
}

const s = clone("hello"); // string — точный тип
const n = clone(42);      // number — точный тип

// Без перегрузок — union на выходе
function cloneBad(value: string | number | boolean): string | number | boolean {
  return value;
}
const result = cloneBad("hello"); // string | number | boolean — неточно!
```

### 3.3 Сравнительная таблица

| Критерий | Перегрузки | Union типы | Conditional Return |
|---|---|---|---|
| Связь input → output | Точная для каждой перегрузки | Всегда полный union | Точная, но сложнее читать |
| Читаемость | Хорошая при 2-3 перегрузках | Отличная | Ухудшается при вложенности |
| Расширяемость | Добавить новую перегрузку | Расширить union | Добавить ветку в conditional |
| Inference для generic | Ограничен (берётся из первой подошедшей) | Полноценный | Полноценный |
| Вывод типа в callback | Выбирается конкретная перегрузка | Union на входе | Зависит от conditional |
| Intellisense / подсказки | Показывает каждую перегрузку отдельно | Один вариант | Один вариант |

### 3.4 Conditional Return Type как альтернатива

Вместо перегрузок можно использовать conditional type на возвращаемом значении:

```typescript
type CloneReturn<T> = T extends string ? string
  : T extends number ? number
  : boolean;

function clone<T extends string | number | boolean>(value: T): CloneReturn<T> {
  return value as CloneReturn<T>;
}

const s = clone("hello"); // string
const n = clone(42);      // number
```

**Важно:** conditional return types лучше работают с generics, но требуют `as` приведения внутри реализации, поскольку TypeScript не может автоматически вывести соответствие conditional типу внутри тела функции.

## 4. Перегрузки методов в классах

### 4.1 Перегрузка обычных методов

Синтаксис перегрузки методов аналогичен обычным функциям — overload signatures идут перед implementation signature:

```typescript
class Formatter {
  // Overload signatures
  format(value: string): string;
  format(value: number, precision: number): string;
  format(value: Date, locale: string): string;

  // Implementation signature
  format(value: string | number | Date, extra?: number | string): string {
    if (typeof value === "string") return value.trim();
    if (typeof value === "number") return value.toFixed(extra as number);
    return value.toLocaleDateString(extra as string);
  }
}

const fmt = new Formatter();
fmt.format("  hello ");          // string
fmt.format(3.14159, 2);          // string — "3.14"
fmt.format(new Date(), "ru-RU"); // string — дата на русском
```

### 4.2 Перегрузки конструктора

Конструктор класса также поддерживает перегрузки. Это полезно, когда объект можно создать из разных источников данных:

```typescript
class Point {
  x: number;
  y: number;

  constructor(x: number, y: number);
  constructor(coords: [number, number]);
  constructor(point: { x: number; y: number });
  constructor(xOrCoords: number | [number, number] | { x: number; y: number }, y?: number) {
    if (typeof xOrCoords === "number") {
      this.x = xOrCoords;
      this.y = y!;
    } else if (Array.isArray(xOrCoords)) {
      [this.x, this.y] = xOrCoords;
    } else {
      this.x = xOrCoords.x;
      this.y = xOrCoords.y;
    }
  }
}

new Point(1, 2);            // OK — первый конструктор
new Point([3, 4]);          // OK — второй конструктор
new Point({ x: 5, y: 6 }); // OK — третий конструктор
```

### 4.3 Перегрузки статических методов

Статические методы перегружаются точно так же, как и обычные:

```typescript
class EventEmitter {
  static create(type: "click"): ClickEmitter;
  static create(type: "keydown"): KeydownEmitter;
  static create(type: string): EventEmitter;
  static create(type: string): EventEmitter {
    switch (type) {
      case "click": return new ClickEmitter();
      case "keydown": return new KeydownEmitter();
      default: return new EventEmitter();
    }
  }
}

const click = EventEmitter.create("click");     // ClickEmitter
const keydown = EventEmitter.create("keydown"); // KeydownEmitter
const custom = EventEmitter.create("custom");   // EventEmitter
```

### 4.4 Перегрузки в абстрактных классах и интерфейсах

В интерфейсах и абстрактных классах записываются **только** overload signatures без реализации:

```typescript
interface StringParser {
  parse(input: string): string[];
  parse(input: string, limit: number): string[];
}

abstract class BaseParser {
  abstract parse(input: string): string[];
  abstract parse(input: string, limit: number): string[];
}

class CsvParser extends BaseParser {
  parse(input: string): string[];
  parse(input: string, limit: number): string[];
  parse(input: string, limit?: number): string[] {
    const parts = input.split(",");
    return limit !== undefined ? parts.slice(0, limit) : parts;
  }
}
```

## 5. Типизация `this` параметра

### 5.1 Явный параметр `this`

TypeScript позволяет указать тип `this` как **первый** псевдо-параметр функции. Этот параметр удаляется при компиляции и не влияет на рантайм — он существует только для проверки типов:

```typescript
interface User {
  name: string;
  greet(this: User): string;
}

const user: User = {
  name: "Alice",
  greet() {
    return `Hello, ${this.name}`; // this типизирован как User
  },
};

user.greet(); // OK

const greetFn = user.greet;
greetFn(); // Error: The 'this' context of type 'void' is not assignable
           // to method's 'this' of type 'User'.
```

### 5.2 `this: void` — запрет контекста

Указание `this: void` гарантирует, что функция **не использует** `this` и может быть безопасно извлечена и вызвана без контекста:

```typescript
function pureCalculation(this: void, a: number, b: number): number {
  // this.something — Error: Property 'something' does not exist on type 'void'
  return a + b;
}

// Безопасно передавать как callback — контекст не важен
[1, 2, 3].reduce(pureCalculation, 0); // OK
```

### 5.3 Утилитарные типы для `this`

TypeScript предоставляет два встроенных utility types для работы с `this` параметром:

```typescript
function greet(this: { name: string }, greeting: string): string {
  return `${greeting}, ${this.name}!`;
}

// ThisParameterType<T> — извлекает тип this
type GreetThis = ThisParameterType<typeof greet>;
// { name: string }

// OmitThisParameter<T> — убирает this, оставляя остальные параметры
type GreetFn = OmitThisParameter<typeof greet>;
// (greeting: string) => string

// Применение: создание обёртки без this
const boundGreet: GreetFn = greet.bind({ name: "Alice" });
boundGreet("Hello"); // "Hello, Alice!"
```

### 5.4 Потеря контекста `this` и паттерны защиты

Классическая проблема — потеря `this` при передаче метода как callback:

```typescript
class Counter {
  count = 0;

  // Проблема: обычный метод теряет this
  increment(this: Counter) {
    this.count++;
  }

  // Решение 1: arrow function property (создаёт новую функцию для каждого экземпляра)
  incrementSafe = () => {
    this.count++;
  };

  // Решение 2: декоратор @bound (Stage 3)
  // Решение 3: явный bind в конструкторе
}

const counter = new Counter();
const fn = counter.increment;
fn(); // Error: 'this' context of type 'void' is not assignable to type 'Counter'

const safeFn = counter.incrementSafe;
safeFn(); // OK — arrow function захватывает this лексически
```

**Важно:** arrow function properties создают **новый экземпляр функции** для каждого объекта, что увеличивает потребление памяти. Для hot-path кода с множеством экземпляров предпочтительнее `.bind()` в конструкторе.

## 6. Call Signatures и Construct Signatures

### 6.1 Call Signature — тип вызываемого объекта

Call signature описывает функцию на уровне типов, используя объектный синтаксис. Это альтернатива стрелочному синтаксису `(args) => returnType`:

```typescript
// Стрелочный синтаксис — краткая запись
type Adder = (a: number, b: number) => number;

// Call signature — объектный синтаксис
type AdderObj = {
  (a: number, b: number): number;
};

// Эквивалентны:
const add: Adder = (a, b) => a + b;
const addObj: AdderObj = (a, b) => a + b;
```

### 6.2 Construct Signature — тип конструктора

Construct signature описывает объект, который можно вызвать с `new`:

```typescript
// Тип конструктора, создающего экземпляры User
type UserConstructor = {
  new (name: string, age: number): User;
};

interface User {
  name: string;
  age: number;
}

class UserImpl implements User {
  constructor(public name: string, public age: number) {}
}

function createUser(Ctor: UserConstructor, name: string, age: number): User {
  return new Ctor(name, age);
}

createUser(UserImpl, "Alice", 30); // OK
```

### 6.3 Гибридные типы — callable с properties

Call signature в объектном синтаксисе позволяет создавать **гибридные типы** — функции, у которых есть собственные свойства:

```typescript
interface Counter {
  // Call signature — объект можно вызвать
  (start: number): number;
  // Properties — у объекта есть свойства
  interval: number;
  reset(): void;
}

function createCounter(): Counter {
  const counter = ((start: number) => start + counter.interval) as Counter;
  counter.interval = 1;
  counter.reset = () => { counter.interval = 1; };
  return counter;
}

const c = createCounter();
c(10);         // 11 — вызов как функции
c.interval = 5;
c(10);         // 15
c.reset();     // сброс interval
```

### 6.4 Совмещение call и construct signatures

Некоторые встроенные объекты (например, `Date`) можно вызывать и с `new`, и без. TypeScript позволяет описать такое поведение:

```typescript
interface DateLike {
  new (timestamp: number): Date;   // construct signature
  (timestamp: number): string;     // call signature
}

// Пример с абстрактным construct signature
type AbstractConstructor<T> = abstract new (...args: any[]) => T;

function mixin<T>(Base: AbstractConstructor<T>) {
  return class extends (Base as any) {
    mixinMethod() { return "mixed"; }
  };
}
```

## 7. Типизация callback-функций

### 7.1 Базовая типизация callback

Callback — функция, передаваемая в качестве аргумента. Её тип описывается через стрелочный синтаксис или call signature:

```typescript
// Стрелочный синтаксис для типа callback
function fetchData(url: string, onSuccess: (data: string) => void): void {
  // ...
  onSuccess(responseData);
}

// Контекстная типизация — TypeScript выводит типы параметров callback
fetchData("/api/users", (data) => {
  // data: string — тип выведен автоматически!
  console.log(data.toUpperCase());
});
```

### 7.2 Опциональные параметры в callback

**Не делайте параметры callback опциональными**, если вызывающий код всегда передаёт значение. Вместо этого callback с меньшим числом параметров совместим с большим:

```typescript
// НЕПРАВИЛЬНО: опциональный параметр в callback
type BadHandler = (value: string, index?: number) => void;

// ПРАВИЛЬНО: callback сам решает, нужен ли ему index
type GoodHandler = (value: string, index: number) => void;

// Callback с меньшим числом параметров совместим:
const handler: GoodHandler = (value) => console.log(value); // OK!
// TypeScript разрешает игнорировать «лишние» параметры —
// это substitutability principle (принцип подстановки)

["a", "b"].forEach((item) => console.log(item));
// forEach ожидает (value, index, array) => void,
// но (value) => void тоже подходит
```

### 7.3 Возвращаемый тип `void` в callback

Тип `void` в возвращаемом значении callback имеет особое поведение — он **не запрещает** возвращать значение. Это позволяет использовать функции, которые что-то возвращают, в контексте, где результат не используется:

```typescript
type VoidCallback = () => void;

// Все эти присваивания валидны!
const fn1: VoidCallback = () => true;          // OK
const fn2: VoidCallback = () => "hello";       // OK
const fn3: VoidCallback = () => ({ x: 1 });    // OK

// Но результат типизирован как void:
const result = fn1(); // void — нельзя использовать как boolean

// Практический пример — Array.prototype.push возвращает number,
// но forEach ожидает void:
const arr: number[] = [];
[1, 2, 3].forEach((n) => arr.push(n)); // OK! push возвращает number,
                                         // но forEach игнорирует результат
```

**Важно:** это правило применяется **только** к callback-типам через контекстную типизацию (contextual typing). Если функция объявлена с явным `void`, возврат значения — ошибка:

```typescript
// Явное объявление — возврат значения запрещён
function explicit(): void {
  return 42; // Error: Type 'number' is not assignable to type 'void'
}
```

### 7.4 Ковариантность возвращаемого типа

Callback с более узким возвращаемым типом совместим с callback с более широким:

```typescript
type StringCallback = () => string;
type ObjectCallback = () => string | number;

const narrow: StringCallback = () => "hello";
// string assignable к string | number — ковариантность
const wide: ObjectCallback = narrow; // OK
```

## 8. Generic Function Overloads

### 8.1 Generics + перегрузки

Перегрузки можно комбинировать с generic-типами для создания высокоточных API:

```typescript
function first<T>(arr: T[]): T | undefined;
function first<T>(arr: T[], defaultValue: T): T;
function first<T>(arr: T[], defaultValue?: T): T | undefined {
  return arr.length > 0 ? arr[0] : defaultValue;
}

const a = first([1, 2, 3]);      // number | undefined
const b = first([1, 2, 3], 0);   // number — без undefined!
const c = first([] as string[]); // string | undefined
```

### 8.2 Паттерн: различные generic-параметры в перегрузках

Каждая перегрузка может иметь **собственные** generic-параметры:

```typescript
function wrap<T extends string>(value: T): { type: "string"; value: T };
function wrap<T extends number>(value: T): { type: "number"; value: T };
function wrap(value: string | number): { type: string; value: string | number } {
  if (typeof value === "string") return { type: "string", value };
  return { type: "number", value };
}

const s = wrap("hello"); // { type: "string"; value: "hello" }
const n = wrap(42);       // { type: "number"; value: 42 }
```

### 8.3 Inference при перегрузках с generics

Компилятор выводит generic-параметры из **выбранной** перегрузки, а не из implementation signature:

```typescript
function merge<T extends object>(target: T, source: Partial<T>): T;
function merge<T extends object, U extends object>(target: T, source: U): T & U;
function merge(target: object, source: object): object {
  return { ...target, ...source };
}

const user = { name: "Alice", age: 30 };

// Первая перегрузка: source выводится как Partial<typeof user>
const updated = merge(user, { age: 31 });
// typeof updated = { name: string; age: number }

// Вторая перегрузка: T & U
const extended = merge(user, { role: "admin" as const });
// typeof extended = { name: string; age: number } & { role: "admin" }
```

### 8.4 Ограничения: generic overloads vs conditional types

Generic-перегрузки не всегда идеально работают с inference. В сложных сценариях conditional types могут быть точнее:

```typescript
// Перегрузки: ограничены конечным набором вариантов
function parse<T extends "json">(input: string, format: T): object;
function parse<T extends "csv">(input: string, format: T): string[][];
function parse(input: string, format: string): object | string[][] {
  return format === "json" ? JSON.parse(input) : input.split("\n").map((r) => r.split(","));
}

// Conditional type: охватывает все варианты в одной сигнатуре
type ParseResult<F> = F extends "json" ? object : F extends "csv" ? string[][] : never;

function parseAlt<F extends "json" | "csv">(input: string, format: F): ParseResult<F> {
  return (format === "json"
    ? JSON.parse(input)
    : input.split("\n").map((r) => r.split(","))) as ParseResult<F>;
}
```

## 9. Rest Parameters и Spread Types

### 9.1 Типизированные rest-параметры

Rest-параметры типизируются как массив. TypeScript выводит точный тип из union элементов:

```typescript
function sum(...numbers: number[]): number {
  return numbers.reduce((acc, n) => acc + n, 0);
}

sum(1, 2, 3);        // OK
sum(1, "2", 3);      // Error: Argument of type 'string' is not assignable

// Rest-параметр с предшествующими фиксированными параметрами
function log(level: "info" | "warn" | "error", ...messages: string[]): void {
  console[level](...messages);
}

log("info", "Server started", "on port 3000"); // OK
```

### 9.2 Tuple rest-параметры

Rest-параметр может быть типизирован как **tuple**, что фиксирует количество и типы аргументов:

```typescript
function makeEntry(...args: [key: string, value: number]): [string, number] {
  return args;
}

makeEntry("age", 30);    // OK
makeEntry("age");         // Error: Expected 2 arguments, but got 1
makeEntry("age", "30");   // Error: Argument of type 'string' is not assignable
```

### 9.3 Labeled tuple elements

Начиная с TypeScript 4.0, элементы кортежей могут иметь **имена** (labels), улучшающие подсказки в IDE:

```typescript
type EventHandler = (...args: [event: MouseEvent, context: { target: HTMLElement }]) => void;

// В IDE подсказка: (event: MouseEvent, context: { target: HTMLElement }) => void
// Без labels было бы: (args_0: MouseEvent, args_1: { target: HTMLElement }) => void

// Labels в параметрах функции
function connect(...args: [host: string, port: number, secure?: boolean]): void {
  const [host, port, secure = false] = args;
  console.log(`Connecting to ${host}:${port} (secure: ${secure})`);
}

connect("localhost", 8080);       // OK
connect("localhost", 8080, true); // OK
```

### 9.4 Variadic Tuple Types

Начиная с TypeScript 4.0, **variadic tuple types** позволяют выражать spread-операции на уровне типов:

```typescript
// Конкатенация кортежей на уровне типов
type Concat<A extends readonly unknown[], B extends readonly unknown[]> = [...A, ...B];

type Result = Concat<[1, 2], [3, 4]>; // [1, 2, 3, 4]

// Практическое применение: типизированный pipe / compose
function concat<T extends unknown[], U extends unknown[]>(
  a: [...T],
  b: [...U]
): [...T, ...U] {
  return [...a, ...b];
}

const result = concat([1, "hello"] as const, [true, 42] as const);
// readonly [1, "hello", true, 42]

// Prefix / Suffix паттерны
type Prepend<T, Tail extends unknown[]> = [T, ...Tail];
type Append<Init extends unknown[], T> = [...Init, T];

type A = Prepend<string, [number, boolean]>; // [string, number, boolean]
type B = Append<[string, number], boolean>;  // [string, number, boolean]
```

### 9.5 `Parameters<T>` и извлечение типов параметров

Утилитарный тип `Parameters<T>` извлекает типы параметров функции в виде tuple:

```typescript
function request(url: string, method: "GET" | "POST", body?: object): Promise<Response> {
  return fetch(url, { method, body: body ? JSON.stringify(body) : undefined });
}

type RequestParams = Parameters<typeof request>;
// [url: string, method: "GET" | "POST", body?: object]

// Использование для создания обёртки
function cachedRequest(...args: Parameters<typeof request>): Promise<Response> {
  const key = args[0] + args[1];
  // проверка кеша ...
  return request(...args);
}

// Извлечение одного параметра
type SecondParam = Parameters<typeof request>[1]; // "GET" | "POST"

// Работа с перегрузками — Parameters берёт ПОСЛЕДНЮЮ перегрузку
function overloaded(x: string): string;
function overloaded(x: number): number;
function overloaded(x: string | number): string | number { return x; }

type OverloadedParams = Parameters<typeof overloaded>;
// [x: number] — последняя overload signature!
```

**Важно:** при использовании `Parameters<T>` с перегруженной функцией TypeScript извлекает параметры **последней** overload signature. Это ограничение системы типов, и обойти его можно только с помощью ручного описания типов или специальных conditional-конструкций.

### 9.6 Rest-параметры в перегрузках

Rest-параметры эффективно комбинируются с перегрузками для создания полиморфных API:

```typescript
function emit(event: "click", x: number, y: number): void;
function emit(event: "keydown", key: string, code: number): void;
function emit(event: "resize", width: number, height: number): void;
function emit(event: string, ...args: unknown[]): void {
  console.log(`Event: ${event}`, ...args);
}

emit("click", 100, 200);        // OK
emit("keydown", "Enter", 13);   // OK
emit("click", "wrong", "args"); // Error: типы аргументов не совпадают
```
