# Система типов TypeScript — полное руководство

> TypeScript реализует **структурную систему типов** (structural type system) с поддержкой
> literal types, algebraic data types, conditional types и мощного вывода типов.
> Понимание того, как компилятор работает с типами, — фундамент для написания
> безопасного и выразительного кода.

## 1. Примитивные типы в TypeScript

### 1.1 Соответствие типов TypeScript и JavaScript

TypeScript добавляет статическую типизацию поверх существующих рантайм-типов JavaScript.
Каждый примитивный тип TS имеет прямое соответствие в JS — после компиляции все аннотации
стираются (type erasure), и остаётся чистый JavaScript.

| TypeScript тип | JS runtime `typeof`  | Описание                                               |
| -------------- | -------------------- | ------------------------------------------------------ |
| `string`       | `"string"`           | Строки — UTF-16 последовательности                     |
| `number`       | `"number"`           | IEEE 754 double (64 бита), включая `NaN`, `±Infinity`  |
| `boolean`      | `"boolean"`          | `true` или `false`                                     |
| `bigint`       | `"bigint"`           | Целые числа произвольной длины (ES2020+)               |
| `symbol`       | `"symbol"`           | Уникальные идентификаторы (ES2015+)                    |
| `null`         | `"object"` (баг JS)  | Единственное значение `null`                           |
| `undefined`    | `"undefined"`        | Единственное значение `undefined`                      |

**Важно:** типы `string`, `number`, `boolean` в TypeScript — это **не** обёрточные объекты
`String`, `Number`, `Boolean`. Использование обёрток в аннотациях — ошибка:

```ts
// Правильно — примитивные типы (lowercase)
let name: string = "Alice";
let age: number = 30;
let active: boolean = true;

// НЕПРАВИЛЬНО — обёрточные объекты (uppercase)
let name: String = "Alice";  // Работает, но String !== string
// String — это интерфейс обёрточного объекта, а не примитив

// Компилятор TS различает эти типы:
let primitive: string = "hello";
let wrapper: String = new String("hello");

primitive = wrapper; // Ошибка! Type 'String' is not assignable to type 'string'
wrapper = primitive; // OK — примитив совместим с обёрткой
```

### 1.2 Literal types vs widened types

TypeScript различает **литеральный тип** (конкретное значение) и **расширенный тип**
(widened type — весь примитивный тип). Это ключевое поведение при выводе типов:

```ts
// const → литеральный тип (literal type)
const x = "hello";     // тип: "hello" (строковый литерал)
const n = 42;          // тип: 42 (числовой литерал)
const b = true;        // тип: true (булевый литерал)

// let/var → расширенный тип (widened type)
let y = "hello";       // тип: string (расширен до string)
let m = 42;            // тип: number
let c = true;          // тип: boolean
```

Расширение (widening) происходит потому, что `let` допускает переприсваивание —
компилятор предполагает, что значение может измениться на другое значение того же типа.
`const` гарантирует неизменность, поэтому тип сужается до конкретного литерала.

### 1.3 `null` и `undefined` в контексте `strictNullChecks`

Поведение `null` и `undefined` радикально меняется в зависимости от флага `strictNullChecks`:

```ts
// strictNullChecks: false (по умолчанию в старых проектах)
let x: string = null;      // OK — null совместим с любым типом
let y: number = undefined;  // OK — undefined тоже

// strictNullChecks: true (рекомендуемый режим)
let x: string = null;       // Ошибка! Type 'null' is not assignable to type 'string'
let y: number = undefined;   // Ошибка!

// Для nullable-значений используйте union:
let x: string | null = null;           // OK
let y: number | undefined = undefined; // OK
let z: string | null | undefined;      // OK — может быть и null, и undefined
```

**В системе типов с `strictNullChecks: true`:** `null` и `undefined` — это отдельные типы
(unit types), содержащие ровно по одному значению. Они не являются подтипами других типов
и требуют явного включения в union, если значение может отсутствовать.

### 1.4 `bigint` и `symbol`

```ts
// bigint — доступен начиная с ES2020 (target: "es2020"+)
const big: bigint = 100n;
const alsoBig: bigint = BigInt(100);

// bigint и number НЕ совместимы — нельзя смешивать в арифметике:
const sum = big + 1;    // Ошибка! Operator '+' cannot be applied to types 'bigint' and 'number'
const sum = big + 1n;   // OK: 101n

// symbol — создаёт уникальный идентификатор
const sym1: symbol = Symbol("key");
const sym2: symbol = Symbol("key");
// sym1 !== sym2 — каждый Symbol уникален

// unique symbol — специальный подтип symbol для const:
const uniqueSym: unique symbol = Symbol("id");
// typeof uniqueSym — это уникальный тип, а не просто symbol

// unique symbol можно использовать как ключ типа:
interface Config {
  [uniqueSym]: string;
}
```

## 2. Специальные типы: `any`, `unknown`, `void`, `never`

### 2.1 Сравнительная таблица

| Свойство                          | `any`                        | `unknown`                      | `void`                     | `never`                      |
| --------------------------------- | ---------------------------- | ------------------------------ | -------------------------- | ---------------------------- |
| Позиция в системе типов           | Особый тип (выход из системы типов) | Top type (безопасный)    | Unit type (пустота)        | Bottom type (невозможность)  |
| Можно присвоить **любой** тип     | Да                           | Да                             | Нет                        | Нет                          |
| Можно присвоить **чему угодно**   | Да (заражение!)              | Нет (только `unknown`/`any`)   | Только `void`/`any`        | Да (подтип всех типов)       |
| Доступ к свойствам без проверки   | Да                           | Нет — ошибка                   | Нет                        | Нет (код недостижим)         |
| Вызов как функция без проверки    | Да                           | Нет — ошибка                   | Нет                        | Нет (код недостижим)         |
| Типичное применение               | Миграция с JS, обход типов   | Безопасный приём любых данных  | Возврат из void-функций    | Exhaustiveness, throw, бесконечные циклы |

### 2.2 `any` — выход из системы типов

`any` полностью отключает проверку типов. Компилятор не выполняет ни assignability check,
ни member access check для значений типа `any`. Это полезно при миграции с JavaScript,
но опасно в продакшн-коде.

```ts
let x: any = "hello";
x = 42;          // OK
x = { foo: 1 };  // OK
x.bar.baz.qux;   // OK — компилятор не проверяет (рантайм-ошибка!)
x();              // OK — компилятор не проверяет

// «Заражение» типов — any распространяется через операции:
let a: any = "test";
let b = a + 1;       // b: any — тип «заразился»
let c = a.length;    // c: any — тоже заразился
let d = [a, 1, "x"]; // d: any[] — массив заражён

// Неявный any (при noImplicitAny: false):
function greet(name) {  // name: any — неявно, без аннотации
  return name.toUpperCase();
}
```

**Правило:** включайте `noImplicitAny: true` в `tsconfig.json` — это заставляет
явно указывать тип параметров, предотвращая случайный `any`.

### 2.3 `unknown` — безопасная альтернатива `any`

`unknown` принимает любое значение (top type), но **запрещает** любые операции
без предварительного сужения (narrowing). Это заставляет программиста проверить тип
перед использованием.

```ts
function processInput(input: unknown): string {
  // input.toUpperCase();  // Ошибка! Object is of type 'unknown'
  // input + 1;            // Ошибка!

  // Сужение через typeof:
  if (typeof input === "string") {
    return input.toUpperCase(); // OK — input сужен до string
  }

  // Сужение через instanceof:
  if (input instanceof Date) {
    return input.toISOString(); // OK — input сужен до Date
  }

  // Сужение через type guard:
  if (isError(input)) {
    return input.message; // OK — input сужен до Error
  }

  return String(input);
}

function isError(value: unknown): value is Error {
  return value instanceof Error;
}
```

**Паттерн:** используйте `unknown` вместо `any` для входных данных из внешних источников
(API-ответы, `JSON.parse`, пользовательский ввод). Это вынуждает проверять структуру данных.

### 2.4 `void` — отсутствие возвращаемого значения

`void` обозначает, что функция **не возвращает значимого значения**. В отличие от `undefined`,
`void` имеет особое поведение в контекстных типах callback-ов:

```ts
// Явный void — функция ничего не возвращает
function logMessage(msg: string): void {
  console.log(msg);
  // return; — допустимо
  // return undefined; — допустимо
  // return "value"; — Ошибка!
}

// Контекстный void в callback-ах — ВАЖНАЯ особенность:
// Тип callback-а с возвратом void РАЗРЕШАЕТ функции, которые что-то возвращают:
type Callback = (x: number) => void;

const arr = [1, 2, 3];

// Array.prototype.forEach ожидает callback, возвращающий void:
arr.forEach((item) => {
  return item * 2; // OK! Возвращаемое значение игнорируется
});

// Это позволяет передавать push как callback:
const result: number[] = [];
arr.forEach((item) => result.push(item)); // push возвращает number, но это OK
```

**Внутренняя механика:** в checker.ts компилятора TypeScript (`isTypeAssignableTo`)
при проверке совместимости callback-ов с `void`-возвратом — возвращаемый тип
callback-а не проверяется. Это сделано для ergonomics — иначе `.forEach`, `.map`
и десятки других API были бы неудобны.

### 2.5 `never` — bottom type (тип невозможности)

`never` — это **bottom type** в теории типов: тип, который является подтипом
**каждого** типа, но ни один тип не является подтипом `never` (кроме самого `never`).
Значение типа `never` не может существовать.

```ts
// Функция, которая НИКОГДА не возвращает управление:
function throwError(message: string): never {
  throw new Error(message);
}

function infiniteLoop(): never {
  while (true) {
    // бесконечный цикл
  }
}

// never как результат exhaustive check:
type Shape = "circle" | "square" | "triangle";

function getArea(shape: Shape): number {
  switch (shape) {
    case "circle":    return Math.PI * 10 ** 2;
    case "square":    return 10 ** 2;
    case "triangle":  return (10 * 10) / 2;
    default:
      // Если все случаи обработаны, shape здесь имеет тип never
      const _exhaustive: never = shape;
      return _exhaustive;
  }
}

// Если добавить "rectangle" в Shape, но не добавить case —
// компилятор выдаст ошибку: Type '"rectangle"' is not assignable to type 'never'
```

**Свойства `never` в системе типов:**

```ts
// never — нейтральный элемент для union (поглощается):
type A = string | never;  // string — never исчезает из union

// never — поглощающий элемент для intersection:
type B = string & never;  // never — пересечение с never даёт never

// never[] — массив, который не может содержать элементы:
const empty: never[] = []; // OK — пустой массив
// empty.push(1); // Ошибка! Argument of type 'number' is not assignable to type 'never'

// Conditional types с never:
type IsNever<T> = [T] extends [never] ? true : false;
type Test1 = IsNever<never>;   // true
type Test2 = IsNever<string>;  // false
```

## 3. Литеральные типы (Literal Types)

### 3.1 Строковые, числовые и булевые литералы

Литеральный тип — это тип, который содержит **ровно одно** конкретное значение.
Это подтип (subtype) соответствующего примитивного типа:

```ts
// Строковые литералы:
type Direction = "north" | "south" | "east" | "west";
let dir: Direction = "north"; // OK
dir = "up";                   // Ошибка! Type '"up"' is not assignable to type 'Direction'

// Числовые литералы:
type DiceRoll = 1 | 2 | 3 | 4 | 5 | 6;
let roll: DiceRoll = 3; // OK
roll = 7;                // Ошибка!

// Булевые литералы:
type True = true;
type False = false;
// boolean — это фактически тип true | false:
type Bool = true | false; // эквивалент boolean

// Template literal types (TS 4.1+):
type EventName = `on${Capitalize<"click" | "focus" | "blur">}`;
// "onClick" | "onFocus" | "onBlur"

type HTTPMethod = "GET" | "POST" | "PUT" | "DELETE";
type APIPath = "/users" | "/orders";
type Endpoint = `${HTTPMethod} ${APIPath}`;
// "GET /users" | "GET /orders" | "POST /users" | "POST /orders" | ...
```

### 3.2 Widening (расширение) литеральных типов

Литеральные типы подвержены **расширению** (widening) в определённых контекстах.
Компилятор решает, когда сохранить литеральный тип, а когда расширить до примитива:

```ts
// const → литеральный тип сохраняется:
const x = "hello";  // "hello"
const n = 42;        // 42

// let → литерал расширяется до примитива:
let y = "hello";    // string
let m = 42;          // number

// Передача литерала в функцию — расширяется:
function identity<T>(value: T): T { return value; }
const val = identity("hello"); // val: "hello" — generic сохраняет литерал

// Объектные свойства — расширяются (mutable по умолчанию):
const config = {
  method: "GET",     // string (расширен!) — свойство может быть изменено
  url: "/api",       // string
  retries: 3,        // number
};
// config.method = "POST"; — допустимо, поэтому TS расширил тип

// Проблема: несовместимость с литеральным union:
function request(method: "GET" | "POST", url: string) {}
request(config.method, config.url);
// Ошибка! Argument of type 'string' is not assignable to parameter of type '"GET" | "POST"'
```

### 3.3 `as const` — заморозка литеральных типов

`as const` — это const assertion, которая предотвращает widening и делает
все значения readonly на всю глубину объекта:

```ts
// as const на примитиве — фиксирует литерал:
let method = "GET" as const; // тип: "GET" (не string!)
method = "POST";              // Ошибка!

// as const на объекте — глубокая readonly + литералы:
const config = {
  method: "GET",
  url: "/api",
  retries: 3,
} as const;
// Тип: { readonly method: "GET"; readonly url: "/api"; readonly retries: 3 }

// Теперь request(config.method, config.url) — OK!

// as const на массиве — превращает в readonly tuple:
const colors = ["red", "green", "blue"] as const;
// Тип: readonly ["red", "green", "blue"]
// colors[0] — тип "red", а не string
// colors.push("yellow"); — Ошибка! Property 'push' does not exist on type 'readonly [...]'

// Практический паттерн — union из массива:
const ROLES = ["admin", "user", "guest"] as const;
type Role = (typeof ROLES)[number]; // "admin" | "user" | "guest"
```

### 3.4 Когда TypeScript выводит литеральные типы

Правила вывода литералов (inference rules) в компиляторе:

1. **`const` переменные** с примитивным значением → литеральный тип
2. **`let`/`var` переменные** → расширяется до примитива
3. **Свойства объектов** → расширяются (объект мутабелен)
4. **`as const`** → литерал + readonly на любом уровне
5. **Generic параметры** → литерал сохраняется при выводе `T`
6. **Параметры функций с литеральным типом** → сохраняются при narrowing

## 4. Enum

### 4.1 Числовые перечисления (Numeric Enums)

Числовой enum — это коллекция именованных констант, каждая из которых получает
числовое значение. По умолчанию нумерация начинается с `0` и автоинкрементируется:

```ts
enum Direction {
  Up,      // 0
  Down,    // 1
  Left,    // 2
  Right,   // 3
}

// Можно указать начальное значение:
enum StatusCode {
  OK = 200,
  NotFound = 404,
  ServerError = 500,
}

// Скомпилированный JavaScript (numeric enum):
// var Direction;
// (function (Direction) {
//   Direction[Direction["Up"] = 0] = "Up";
//   Direction[Direction["Down"] = 1] = "Down";
//   Direction[Direction["Left"] = 2] = "Left";
//   Direction[Direction["Right"] = 3] = "Right";
// })(Direction || (Direction = {}));
```

### 4.2 Reverse Mapping (обратное отображение)

Числовые enum создают **двустороннюю** привязку: от имени к значению и обратно:

```ts
enum Color {
  Red,    // 0
  Green,  // 1
  Blue,   // 2
}

console.log(Color.Red);   // 0
console.log(Color[0]);    // "Red" — обратное отображение
console.log(Color[1]);    // "Green"

// Это работает потому, что скомпилированный JS содержит:
// Color["Red"] = 0 и Color[0] = "Red"
```

**Внимание:** строковые enum **не** имеют reverse mapping.

### 4.3 Строковые перечисления (String Enums)

```ts
enum LogLevel {
  Debug = "DEBUG",
  Info = "INFO",
  Warn = "WARN",
  Error = "ERROR",
}

// В скомпилированном JS:
// LogLevel["Debug"] = "DEBUG";  — нет обратного отображения
// LogLevel["DEBUG"] — не существует!

// Строковые enum — более безопасны для сериализации:
const level: LogLevel = LogLevel.Error;
console.log(level); // "ERROR" — читаемое значение
```

### 4.4 `const enum` — инлайнинг на этапе компиляции

`const enum` полностью стирается при компиляции — все обращения к его членам
заменяются инлайн-значениями:

```ts
const enum MathConstants {
  Pi = 3.14159,
  E = 2.71828,
  Phi = 1.61803,
}

// Исходный TypeScript:
const area = MathConstants.Pi * radius ** 2;

// Скомпилированный JavaScript:
// const area = 3.14159 /* MathConstants.Pi */ * radius ** 2;
// enum объекта НЕТ в рантайме — нулевой overhead
```

**Ограничения `const enum`:**
- Нет reverse mapping (объект не существует в рантайме)
- Нельзя использовать computed members
- При `isolatedModules: true` (Babel, esbuild) — `const enum` из другого файла не инлайнится
- Флаг `preserveConstEnums` сохраняет enum-объект для отладки

### 4.5 Ambient Enums (`declare enum`)

```ts
// Ambient enum описывает enum, существующий во внешнем коде:
declare enum ExternalStatus {
  Active = 1,
  Inactive = 2,
}

// Компилятор не генерирует JS-код для ambient enum.
// Ожидается, что объект ExternalStatus предоставляется внешним скриптом.
```

### 4.6 Enum vs Union of Literals — когда что использовать

| Критерий                     | `enum`                         | Union of Literals                  |
| ---------------------------- | ------------------------------ | ---------------------------------- |
| Рантайм-артефакт             | Да (объект в JS)               | Нет (стирается при компиляции)     |
| Tree-shaking                 | Не всегда (IIFE)               | Полный — типы стираются            |
| Reverse mapping              | Да (числовые)                  | Нет                                |
| Итерация по значениям        | `Object.values(MyEnum)`        | Требует массив + `as const`        |
| Читаемость в DevTools        | Значение enum (число/строка)   | Само значение                      |
| Расширяемость                | Нет (closed)                   | Да (union можно расширить `\|`)    |
| Использование с `isolatedModules` | Проблемы с `const enum`   | Без проблем                        |

```ts
// Рекомендация: предпочитайте union of literals в большинстве случаев:
type Status = "active" | "inactive" | "pending";

// Enum оправдан, когда:
// 1. Нужен reverse mapping (числовые enum)
// 2. Нужна итерация по всем значениям в рантайме
// 3. Значения являются непрозрачными идентификаторами (не важно конкретное значение)
```

## 5. Кортежи (Tuples)

### 5.1 Базовые кортежи — типизированные массивы фиксированной длины

Tuple в TypeScript — это массив с **фиксированным количеством** элементов,
каждый из которых имеет **свой тип**:

```ts
// Базовый tuple:
let point: [number, number] = [10, 20];
let entry: [string, number] = ["age", 30];

// Типы элементов проверяются по позиции:
point[0]; // number
point[1]; // number
entry[0]; // string
entry[1]; // number

// Длина фиксирована:
point = [1, 2, 3]; // Ошибка! Type '[number, number, number]' is not assignable to '[number, number]'
point = [1];        // Ошибка! Source has 1 element(s) but target requires 2

// ВНИМАНИЕ: мутирующие методы массива НЕ блокируются:
point.push(3);       // OK на уровне типов (!)
console.log(point);  // [10, 20, 3] — длина нарушена в рантайме
// Это известное ограничение — используйте readonly tuple для защиты
```

### 5.2 Именованные кортежи (Labeled Tuples, TS 4.0+)

Метки улучшают читаемость и подсказки IDE, но **не влияют** на проверку типов:

```ts
type Point3D = [x: number, y: number, z: number];
type HTTPResponse = [status: number, body: string, headers: Record<string, string>];

// Метки видны в подсказках IDE:
function getPoint(): Point3D {
  return [1, 2, 3]; // IDE покажет: x: number, y: number, z: number
}

const [x, y, z] = getPoint(); // Деструктуризация как обычно
```

### 5.3 Optional и Rest элементы в кортежах

```ts
// Optional элементы (суффикс ?):
type FlexPoint = [number, number, number?];
const p2d: FlexPoint = [1, 2];     // OK — z необязателен
const p3d: FlexPoint = [1, 2, 3];  // OK

// Rest элементы — переменная длина в конце:
type StringAndNumbers = [string, ...number[]];
const a: StringAndNumbers = ["hello"];           // OK
const b: StringAndNumbers = ["hello", 1, 2, 3]; // OK

// Rest элемент в середине (TS 4.2+):
type Padded = [number, ...string[], number];
const c: Padded = [1, "a", "b", "c", 2]; // OK
const d: Padded = [1, 2];                 // OK — ноль string элементов

// Spread в типах функций:
type Args = [string, number, boolean];
function fn(...args: Args) {
  const [name, age, active] = args;
  // name: string, age: number, active: boolean
}
```

### 5.4 Readonly Tuples

```ts
// readonly tuple — полная защита от мутации:
type ReadonlyPoint = readonly [number, number];

const p: ReadonlyPoint = [1, 2];
p[0] = 5;      // Ошибка! Cannot assign to '0' because it is a read-only property
p.push(3);     // Ошибка! Property 'push' does not exist on type 'readonly [number, number]'

// as const создаёт readonly tuple с литеральными типами:
const coords = [10, 20] as const;
// Тип: readonly [10, 20]
```

### 5.5 Tuple Spread и вывод типов

```ts
// Spread tuple в другой tuple:
type First = [string, number];
type Second = [boolean];
type Combined = [...First, ...Second]; // [string, number, boolean]

// Конкатенация tuple типов через generic:
type Concat<A extends readonly unknown[], B extends readonly unknown[]> = [...A, ...B];
type Result = Concat<[1, 2], [3, 4]>; // [1, 2, 3, 4]

// Variadic tuple types (TS 4.0+) — мощная абстракция:
function concat<T extends unknown[], U extends unknown[]>(
  a: [...T],
  b: [...U]
): [...T, ...U] {
  return [...a, ...b];
}

const result = concat([1, "hello"], [true, 42]);
// Тип: [number, string, boolean, number]
```

## 6. `readonly` и `as const`

### 6.1 Модификатор `readonly` для свойств

`readonly` запрещает **переприсваивание** свойства после инициализации:

```ts
interface User {
  readonly id: number;
  name: string;
}

const user: User = { id: 1, name: "Alice" };
user.name = "Bob";  // OK
user.id = 2;        // Ошибка! Cannot assign to 'id' because it is a read-only property

// readonly в классах:
class Point {
  readonly x: number;
  readonly y: number;

  constructor(x: number, y: number) {
    this.x = x; // OK — инициализация в конструкторе разрешена
    this.y = y;
  }

  move() {
    this.x = 10; // Ошибка! Даже внутри класса нельзя менять readonly
  }
}
```

**Важно:** `readonly` — это **compile-time** ограничение. В рантайме JavaScript
не запрещает запись. Для реальной иммутабельности используйте `Object.freeze`.

### 6.2 `ReadonlyArray<T>` и `readonly T[]`

```ts
// Два эквивалентных синтаксиса:
const arr1: ReadonlyArray<number> = [1, 2, 3];
const arr2: readonly number[] = [1, 2, 3];

// Все мутирующие методы недоступны:
arr1.push(4);     // Ошибка!
arr1[0] = 10;     // Ошибка!
arr1.sort();      // Ошибка!
arr1.splice(0,1); // Ошибка!

// Немутирующие методы доступны:
arr1.map(x => x * 2);    // OK — возвращает новый массив
arr1.filter(x => x > 1); // OK
arr1.slice(0, 2);         // OK
arr1.indexOf(2);           // OK

// readonly массив можно присвоить обычному — НЕТ:
const mutable: number[] = arr1;
// Ошибка! Type 'readonly number[]' is not assignable to type 'number[]'
//   Property 'push' is missing in type 'readonly number[]'

// Но обычный можно присвоить readonly:
const readOnly: readonly number[] = [1, 2, 3]; // OK
```

### 6.3 `as const` — глубокая иммутабельность

`as const` делает три вещи одновременно:
1. Все свойства становятся `readonly` (на всех уровнях вложенности)
2. Все литеральные значения сохраняют **литеральный тип** (без widening)
3. Массивы становятся `readonly` tuple

```ts
const config = {
  api: {
    baseUrl: "https://api.example.com",
    timeout: 5000,
  },
  features: ["auth", "logging", "cache"],
} as const;

// Тип:
// {
//   readonly api: {
//     readonly baseUrl: "https://api.example.com";
//     readonly timeout: 5000;
//   };
//   readonly features: readonly ["auth", "logging", "cache"];
// }

config.api.baseUrl = "x";       // Ошибка!
config.features.push("new");     // Ошибка!
config.api.timeout;              // тип: 5000 (литерал, не number)
```

### 6.4 Разница `readonly` vs `as const`

| Аспект                  | `readonly` (модификатор)         | `as const` (assertion)                |
| ----------------------- | -------------------------------- | ------------------------------------- |
| Глубина                 | Только первый уровень            | Рекурсивно — вся глубина             |
| Литеральные типы        | Не влияет                        | Фиксирует литералы                   |
| Применимость            | Свойства, параметры, массивы     | Любое выражение-значение             |
| Объявление типов        | В interface/type                 | Только при инициализации значения     |

### 6.5 Паттерн `DeepReadonly`

Для рекурсивной иммутабельности произвольного типа:

```ts
type DeepReadonly<T> =
  T extends (infer U)[]
    ? DeepReadonlyArray<U>
    : T extends object
      ? { readonly [K in keyof T]: DeepReadonly<T[K]> }
      : T;

interface DeepReadonlyArray<T> extends ReadonlyArray<DeepReadonly<T>> {}

// Использование:
interface MutableConfig {
  db: {
    host: string;
    port: number;
    credentials: {
      user: string;
      password: string;
    };
  };
  features: string[];
}

type ImmutableConfig = DeepReadonly<MutableConfig>;
// Все свойства на всех уровнях — readonly
// features: DeepReadonlyArray<string> (без push, splice и т.д.)
```

## 7. Структурная типизация

### 7.1 Структурная vs номинальная типизация

TypeScript использует **структурную систему типов** (structural type system):
совместимость типов определяется **структурой** (набором свойств и их типов),
а не **именем** или **местом объявления** типа.

В номинальных системах (Java, C#, Rust) два типа с идентичной структурой,
но разными именами — **несовместимы**. В TypeScript — **совместимы**:

```ts
// Два разных интерфейса с одинаковой структурой:
interface Point2D {
  x: number;
  y: number;
}

interface Vector2D {
  x: number;
  y: number;
}

// Полностью совместимы:
const point: Point2D = { x: 1, y: 2 };
const vector: Vector2D = point; // OK! Структура совпадает

// Даже класс совместим, если структура подходит:
class Coordinates {
  constructor(public x: number, public y: number) {}
}

const coord = new Coordinates(3, 4);
const p: Point2D = coord; // OK! Координаты имеют x и y

// Duck typing — «если ходит как утка и крякает как утка...»
function printPoint(p: Point2D) {
  console.log(`(${p.x}, ${p.y})`);
}

printPoint({ x: 10, y: 20 });                // OK
printPoint({ x: 10, y: 20, z: 30 });         // Ошибка! (excess property check)
printPoint({ x: 10, y: 20, z: 30 } as any);  // OK (обход проверки)

const obj3d = { x: 10, y: 20, z: 30 };
printPoint(obj3d); // OK! Excess property check НЕ применяется к переменным
```

### 7.2 Excess Property Checking (проверка избыточных свойств)

TypeScript применяет **дополнительную проверку** только к **свежим объектным литералам**
(fresh object literals) — объектам, переданным напрямую в место, ожидающее определённый тип:

```ts
interface Config {
  host: string;
  port: number;
}

// Свежий литерал — excess property check ВКЛЮЧЕНА:
const cfg1: Config = {
  host: "localhost",
  port: 3000,
  debug: true,    // Ошибка! Object literal may only specify known properties
};

// Промежуточная переменная — excess property check ОТКЛЮЧЕНА:
const temp = { host: "localhost", port: 3000, debug: true };
const cfg2: Config = temp; // OK! Лишние свойства игнорируются

// Передача в функцию:
function connect(config: Config) {}
connect({ host: "localhost", port: 3000, debug: true }); // Ошибка! (свежий литерал)
connect(temp);                                            // OK! (переменная)
```

**Почему так?** Excess property checking — это эвристика для выявления опечаток.
Если вы передаёте литерал `{ hoost: "..." }` вместо `{ host: "..." }` — это скорее
всего ошибка. Но при передаче переменной дополнительные свойства — нормальная практика
(объект может использоваться в разных контекстах).

### 7.3 Branding Pattern — эмуляция номинальных типов

Иногда структурная типизация **мешает** — например, когда `UserId` и `OrderId`
оба являются `number`, но их нельзя путать. Паттерн **branding** добавляет
phantom property (свойство-фантом), создающее несовместимость:

```ts
// Определяем branded types:
type Brand<T, B extends string> = T & { readonly __brand: B };

type UserId = Brand<number, "UserId">;
type OrderId = Brand<number, "OrderId">;

// Конструирующие функции:
function createUserId(id: number): UserId {
  return id as UserId;
}

function createOrderId(id: number): OrderId {
  return id as OrderId;
}

// Использование:
function getUser(id: UserId) { /* ... */ }
function getOrder(id: OrderId) { /* ... */ }

const userId = createUserId(1);
const orderId = createOrderId(1);

getUser(userId);    // OK
getUser(orderId);   // Ошибка! Type 'OrderId' is not assignable to type 'UserId'
getUser(1);         // Ошибка! Type 'number' is not assignable to type 'UserId'

// В рантайме __brand не существует — нулевой overhead:
console.log(userId);        // 1
console.log(typeof userId); // "number"
```

### 7.4 Совместимость функций

Структурная типизация для функций следует правилам **ко- и контравариантности**:

```ts
// Параметры — контравариантны (strictFunctionTypes: true):
type Handler = (event: MouseEvent) => void;

const specificHandler: (event: Event) => void = (e) => {};
// const handler: Handler = specificHandler;
// Ошибка при strictFunctionTypes!
// Type '(event: Event) => void' is not assignable to type '(event: MouseEvent) => void'.
// Параметры контравариантны: Event шире MouseEvent, поэтому функция,
// принимающая Event, НЕ может быть подставлена туда, где ожидается MouseEvent.
// Внутри Handler могут использоваться свойства MouseEvent, которых нет у Event.

const tooSpecific: (event: PointerEvent) => void = (e) => {};
const handler2: Handler = tooSpecific; // OK — PointerEvent extends MouseEvent,
// функция, принимающая более узкий тип, безопасно принимает и более широкий

// Возвращаемый тип — ковариантен:
type Factory = () => Event;
const mouseFactory: () => MouseEvent = () => new MouseEvent("click");
const factory: Factory = mouseFactory; // OK — MouseEvent extends Event

// Меньше параметров — совместимо (excess parameters игнорируются):
type Callback = (a: number, b: string) => void;
const cb1: Callback = (a) => {};          // OK — 1 параметр вместо 2
const cb2: Callback = () => {};           // OK — 0 параметров
const cb3: Callback = (a, b, c) => {};    // TypeScript разрешает лишние параметры в callbacks,
// но параметр `c` не получает контекстуальный тип (implicit any).
// При включённом `noImplicitAny` будет ошибка: Parameter 'c' implicitly has an 'any' type.
```

## 8. Type Assertions

### 8.1 Синтаксис `as Type` и `<Type>`

Type assertion — это способ сказать компилятору «я знаю тип лучше, чем ты».
Assertion **не** выполняет преобразование в рантайме — это чисто compile-time операция:

```ts
// Синтаксис as (предпочтительный):
const input = document.getElementById("name") as HTMLInputElement;
input.value = "Hello";

// Угловые скобки (несовместимы с JSX):
const input2 = <HTMLInputElement>document.getElementById("name");

// ВАЖНО: assertion НЕ меняет рантайм-значение:
const x = "hello" as number; // Ошибка! Conversion of type 'string' to type 'number'
                              // may be a mistake — типы слишком далеки

// Assertion работает только когда один тип является подтипом другого:
const el = document.getElementById("app"); // HTMLElement | null
const div = el as HTMLDivElement;           // OK — HTMLDivElement extends HTMLElement
```

### 8.2 Double Assertion (двойное приведение)

Когда типы полностью несовместимы, можно использовать промежуточный `unknown`:

```ts
// Прямое assertion — ошибка:
const x = "hello" as number;
// Ошибка! Conversion of type 'string' to type 'number' may be a mistake

// Double assertion через unknown:
const x = "hello" as unknown as number; // OK — но ОПАСНО!
// В рантайме x всё ещё "hello", а тип говорит number

// Когда double assertion оправдано — тестирование:
interface ComplexAPI {
  method1(): Promise<Response>;
  method2(data: FormData): void;
  // ... 20 методов
}

// В тесте нужен mock только одного метода:
const mockAPI = {
  method1: jest.fn(),
} as unknown as ComplexAPI;
// Проще, чем мокать все 20 методов
```

### 8.3 Non-null Assertion (`!`)

Оператор `!` (non-null assertion) убирает `null` и `undefined` из типа:

```ts
// Ситуация: компилятор не может доказать, что значение не null:
function getElement(id: string): HTMLElement {
  const el = document.getElementById(id);
  // el: HTMLElement | null

  return el!; // ! убирает null из типа
  // Если el реально null — рантайм-ошибка
}

// Definite Assignment Assertion (! в объявлении):
class Component {
  el!: HTMLElement; // Без ! — ошибка: не инициализировано в конструкторе

  init() {
    this.el = document.createElement("div");
  }
}

// ОПАСНОСТЬ: ! обходит проверку null-safety:
const map = new Map<string, number>();
const value = map.get("key")!; // Если ключа нет — undefined, но тип говорит number
// Предпочитайте проверку: if (map.has("key")) { ... }
```

### 8.4 `as const` — assertion неизменяемости

`as const` — это особый вид assertion, который (в отличие от остальных) **сужает** тип:

```ts
// Обычная assertion расширяет/сохраняет тип:
const x = "hello" as string; // string — расширили

// as const сужает тип:
const y = "hello" as const;  // "hello" — сузили до литерала

// as const в аргументах функций (TS 5.0+ — const type parameters):
function createPair<const T extends readonly [unknown, unknown]>(pair: T): T {
  return pair;
}
const pair = createPair(["hello", 42]);
// Тип: readonly ["hello", 42] — литералы сохранены благодаря const T
```

### 8.5 Когда assertions опасны

```ts
// Assertion может скрыть реальную ошибку:
interface User {
  id: number;
  name: string;
  email: string;
}

// API вернул неполные данные, а мы утверждаем полный тип:
const data = JSON.parse(response) as User;
// Если в response нет email — рантайм-ошибка при data.email.toLowerCase()

// Безопасная альтернатива — validation:
function isUser(data: unknown): data is User {
  return (
    typeof data === "object" && data !== null &&
    "id" in data && typeof (data as any).id === "number" &&
    "name" in data && typeof (data as any).name === "string" &&
    "email" in data && typeof (data as any).email === "string"
  );
}

const parsed: unknown = JSON.parse(response);
if (isUser(parsed)) {
  parsed.email.toLowerCase(); // OK — тип гарантирован type guard-ом
}
```

## 9. Вывод типов (Type Inference)

### 9.1 Best Common Type (наилучший общий тип)

Когда TypeScript выводит тип массива или выражения с несколькими значениями,
он ищет **наилучший общий тип** — тип, который является супертипом всех элементов:

```ts
// Все элементы одного типа:
const nums = [1, 2, 3];       // number[]

// Разные подтипы — ищется общий:
class Animal {}
class Dog extends Animal { bark() {} }
class Cat extends Animal { meow() {} }

const pets = [new Dog(), new Cat()]; // (Dog | Cat)[]
// НЕ Animal[] — TS берёт union, а не ищет общего предка

// Смешанные примитивы:
const mixed = [1, "hello", true]; // (string | number | boolean)[]

// null и undefined при strictNullChecks:
const arr = [1, null];            // (number | null)[]
```

### 9.2 Contextual Typing (контекстная типизация)

Контекстная типизация — это вывод типа **от ожидаемого контекста** к выражению
(типизация «снаружи внутрь», а не «изнутри наружу»):

```ts
// Тип параметра callback выводится из контекста forEach:
const numbers = [1, 2, 3];
numbers.forEach((item) => {
  // item: number — тип выведен из Array<number>.forEach
  console.log(item.toFixed(2));
});

// Контекстная типизация обработчиков событий:
document.addEventListener("click", (event) => {
  // event: MouseEvent — выведен из сигнатуры addEventListener для "click"
  console.log(event.clientX, event.clientY);
});

// Контекстная типизация через аннотацию переменной:
const handler: (a: number, b: string) => boolean = (a, b) => {
  // a: number, b: string — выведены из типа переменной handler
  return a > b.length;
};

// Контекстная типизация в object literal:
interface EventMap {
  click: (e: MouseEvent) => void;
  keydown: (e: KeyboardEvent) => void;
}

const handlers: EventMap = {
  click: (e) => { /* e: MouseEvent */ },
  keydown: (e) => { /* e: KeyboardEvent */ },
};
```

### 9.3 Return Type Inference (вывод типа возврата)

TypeScript анализирует **все пути** возврата (`return`) функции и объединяет их:

```ts
// Один путь возврата:
function add(a: number, b: number) {
  return a + b; // Выведен тип: number
}

// Несколько путей — union:
function parse(input: string) {
  if (input === "true") return true;
  if (input === "false") return false;
  return input;
}
// Выведен тип: string | boolean

// Рекурсивный вывод:
function fibonacci(n: number): number {
  // Аннотация ОБЯЗАТЕЛЬНА — TS не может вывести рекурсивный тип неявно
  if (n <= 1) return n;
  return fibonacci(n - 1) + fibonacci(n - 2);
}
```

### 9.4 Generic Type Argument Inference

TypeScript выводит аргументы generic функций из переданных аргументов:

```ts
function identity<T>(value: T): T {
  return value;
}

// T выводится из аргумента:
const a = identity("hello");  // T = "hello", результат: "hello"
const b = identity(42);       // T = 42, результат: 42

// Множественные generic параметры:
function map<T, U>(arr: T[], fn: (item: T) => U): U[] {
  return arr.map(fn);
}

const result = map([1, 2, 3], (n) => n.toString());
// T = number (из [1,2,3]), U = string (из return n.toString())
// Результат: string[]

// Когда вывод не справляется — указываем явно:
function create<T>(): T[] {
  return [];
}
const arr = create<string>(); // T = string — невозможно вывести без аргументов

// Partial inference (частичный вывод) с default:
function fetch<T = unknown, E = Error>(url: string): Promise<T> {
  return globalThis.fetch(url).then(r => r.json());
}
```

### 9.5 Control Flow Analysis (анализ потока управления)

Компилятор TypeScript отслеживает изменения типа переменной через условия,
guard-ы и присваивания — это **control flow-based type narrowing**:

```ts
function process(value: string | number | null) {
  // value: string | number | null

  if (value === null) {
    // value: null
    return;
  }
  // value: string | number (null исключён)

  if (typeof value === "string") {
    // value: string
    console.log(value.toUpperCase());
  } else {
    // value: number
    console.log(value.toFixed(2));
  }
}

// Narrowing через truthiness:
function printLength(str: string | undefined) {
  if (str) {
    // str: string (undefined и "" исключены)
    console.log(str.length);
  }
}

// Narrowing через `in` оператор:
interface Fish { swim(): void }
interface Bird { fly(): void }

function move(animal: Fish | Bird) {
  if ("swim" in animal) {
    animal.swim(); // animal: Fish
  } else {
    animal.fly();  // animal: Bird
  }
}

// Narrowing через discriminated unions:
type Result =
  | { status: "success"; data: string }
  | { status: "error"; error: Error };

function handle(result: Result) {
  if (result.status === "success") {
    console.log(result.data);   // OK — data доступна
  } else {
    console.log(result.error);  // OK — error доступна
  }
}

// Narrowing через assignment:
let x: string | number;
x = "hello";
// x: string (после присваивания строки)
x.toUpperCase(); // OK

x = 42;
// x: number (после присваивания числа)
x.toFixed(2); // OK
```

### 9.6 Оператор `satisfies` (TypeScript 4.9+)

`satisfies` проверяет, что выражение соответствует типу, но **не расширяет** тип —
сохраняются литеральные типы и конкретные формы значений:

```ts
// Проблема без satisfies:
type ColorMap = Record<string, string | number[]>;

// Вариант 1: аннотация — теряем конкретику:
const colors1: ColorMap = {
  red: "#ff0000",
  green: [0, 255, 0],
};
colors1.red.toUpperCase(); // Ошибка! Property 'toUpperCase' does not exist on 'string | number[]'
// Тип red — string | number[], хотя мы знаем, что это string

// Вариант 2: без аннотации — нет проверки:
const colors2 = {
  red: "#ff0000",
  green: [0, 255, 0],
  blue: true, // Нет ошибки! Ничего не проверяет тип
};

// Вариант 3: satisfies — и проверка, и конкретика:
const colors3 = {
  red: "#ff0000",
  green: [0, 255, 0],
  blue: true, // Ошибка! Type 'boolean' does not satisfy 'string | number[]'
} satisfies ColorMap;

colors3.red.toUpperCase();  // OK! red: string (не string | number[])
colors3.green.map(x => x);  // OK! green: number[] (не string | number[])

// satisfies с as const — максимальная точность:
const routes = {
  home: "/",
  about: "/about",
  users: "/users",
} as const satisfies Record<string, string>;
// Тип: { readonly home: "/"; readonly about: "/about"; readonly users: "/users" }
// И проверено, что все значения — строки
```

**Внутренняя механика `satisfies`:** в checker.ts компилятора вызывается
`checkSatisfiesExpression`, который выполняет `isTypeAssignableTo(exprType, targetType)` —
ту же проверку совместимости, что и аннотация. Но тип **выражения** не заменяется на
`targetType` — остаётся исходный выведенный тип. Это ключевое отличие от `: Type`.

## 10. Explicit Resource Management (`using` / `await using`)

> Начиная с **TypeScript 5.2** поддерживается proposal [ECMAScript Explicit Resource Management](https://github.com/tc39/proposal-explicit-resource-management) (Stage 3). Это механизм автоматической очистки ресурсов при выходе из области видимости — аналог `try-with-resources` (Java), `using` (C#), `with` (Python), RAII (C++).

### 10.1 Основные интерфейсы

TypeScript вводит два встроенных интерфейса:

```ts
interface Disposable {
  [Symbol.dispose](): void;
}

interface AsyncDisposable {
  [Symbol.asyncDispose](): Promise<void>;
}
```

Любой объект, реализующий `Symbol.dispose` или `Symbol.asyncDispose`, может использоваться
с ключевыми словами `using` и `await using` соответственно.

### 10.2 Синхронный `using`

Объявление `using` автоматически вызывает `[Symbol.dispose]()` при выходе из блока:

```ts
class FileHandle implements Disposable {
  constructor(private path: string) {
    console.log(`Открыт: ${path}`);
  }

  read(): string {
    return "содержимое файла";
  }

  [Symbol.dispose](): void {
    console.log(`Закрыт: ${this.path}`);
  }
}

function processFile() {
  using file = new FileHandle("/tmp/data.txt");
  // Открыт: /tmp/data.txt

  const content = file.read();
  console.log(content);

  // При выходе из функции автоматически вызывается file[Symbol.dispose]()
  // Закрыт: /tmp/data.txt
}
```

**Важно:** `using` объявляет `const`-привязку — переприсваивание запрещено:

```ts
using handle = getResource();
handle = getAnotherResource(); // Ошибка! Cannot assign to 'handle' because it is a using declaration.
```

### 10.3 Асинхронный `await using`

Для ресурсов, требующих асинхронной очистки, используется `await using`:

```ts
class DatabaseConnection implements AsyncDisposable {
  private constructor(private connectionId: string) {}

  static async connect(url: string): Promise<DatabaseConnection> {
    const conn = new DatabaseConnection(url);
    console.log(`Подключено: ${url}`);
    return conn;
  }

  async query(sql: string): Promise<unknown[]> {
    return [{ id: 1 }];
  }

  async [Symbol.asyncDispose](): Promise<void> {
    console.log(`Отключено: ${this.connectionId}`);
    // await actualDisconnect();
  }
}

async function fetchUsers() {
  await using db = await DatabaseConnection.connect("postgres://localhost/mydb");

  const users = await db.query("SELECT * FROM users");
  console.log(users);

  // При выходе вызывается await db[Symbol.asyncDispose]()
}
```

### 10.4 `DisposableStack` и `AsyncDisposableStack`

Для управления группой ресурсов предусмотрены стековые контейнеры.
Ресурсы освобождаются в порядке, обратном добавлению (LIFO):

```ts
async function complexOperation() {
  await using stack = new AsyncDisposableStack();

  const db = stack.use(await DatabaseConnection.connect("postgres://..."));
  const cache = stack.use(await CacheClient.connect("redis://..."));

  // stack.defer() — для произвольных действий при очистке:
  stack.defer(() => console.log("Все ресурсы освобождены"));

  // При выходе: сначала defer-callback, потом cache, потом db
}
```

### 10.5 Порядок вызова dispose и обработка ошибок

- Если блок содержит несколько `using`-объявлений, `[Symbol.dispose]()` вызывается
  в **обратном порядке** объявления (как деструкторы в стеке).
- Если и тело блока, и `dispose` выбрасывают ошибку, обе сохраняются
  через новый тип `SuppressedError`:

```ts
using a = getResourceA(); // dispose вызовется вторым
using b = getResourceB(); // dispose вызовется первым

// Эквивалент сгенерированного кода:
// try { ... }
// finally { b[Symbol.dispose](); a[Symbol.dispose](); }
```

### 10.6 Требования `tsconfig.json`

Для использования `using` / `await using` необходимо:

```jsonc
{
  "compilerOptions": {
    "target": "es2022",      // или выше
    "lib": ["es2022", "esnext.disposable"] // esnext.disposable для Symbol.dispose и интерфейсов
  }
}
```

**Практическая рекомендация:** `using` особенно полезен для работы с файлами, соединениями
с БД, блокировками, транзакциями и любыми ресурсами, требующими гарантированной очистки.
Он устраняет класс багов, связанных с забытым `finally` или `close()`.
