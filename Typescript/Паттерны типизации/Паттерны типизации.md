## 1. Discriminated Unions (Размеченные объединения)

### 1.1 Базовый паттерн

Discriminated Union — объединение типов с общим **литеральным полем-дискриминантом**, позволяющим компилятору точно сузить тип в ветвлении.

```ts
type Circle   = { kind: 'circle';   radius: number };
type Square   = { kind: 'square';   side: number };
type Triangle = { kind: 'triangle'; base: number; height: number };
type Shape = Circle | Square | Triangle;

function area(shape: Shape): number {
  switch (shape.kind) {
    case 'circle':   return Math.PI * shape.radius ** 2;   // shape: Circle
    case 'square':   return shape.side ** 2;                // shape: Square
    case 'triangle': return 0.5 * shape.base * shape.height;
  }
}
```

**Важно:** дискриминант обязан быть **литеральным** типом. Общий `string` не даёт сужения.

### 1.2 State Machine и Redux Actions

```ts
type RequestState<T> =
  | { status: 'idle' }
  | { status: 'loading'; abort: AbortController }
  | { status: 'success'; data: T; receivedAt: Date }
  | { status: 'error';   error: Error; retryCount: number };

// В ветке 'loading' обращение к state.data — ошибка компиляции

type Action =
  | { type: 'ADD_TODO';    payload: { text: string } }
  | { type: 'TOGGLE_TODO'; payload: { id: number } }
  | { type: 'REMOVE_TODO'; payload: { id: number } };
```

| Критерий | DU | Классы |
|---|---|---|
| Новый вариант | Компилятор укажет необработанные `switch` | Наследование + абстрактные методы |
| Новая операция | Одна функция со `switch` | Метод в каждом классе |
| Tree-shaking / Сериализация | Полная / JSON из коробки | Хуже / Нужен `toJSON` |

## 2. Builder Pattern с типами

### 2.1 Type-safe Builder с трекингом полей

Generic-параметр отслеживает, какие поля установлены. `.build()` доступен **только** когда все обязательные поля присутствуют:

```ts
interface DBConfig { host: string; port: number; database: string; ssl?: boolean }

class DBConfigBuilder<Set extends Partial<Record<keyof DBConfig, true>> = {}> {
  private config: Partial<DBConfig> = {};

  host(v: string): DBConfigBuilder<Set & { host: true }> {
    this.config.host = v; return this as any;
  }
  port(v: number): DBConfigBuilder<Set & { port: true }> {
    this.config.port = v; return this as any;
  }
  database(v: string): DBConfigBuilder<Set & { database: true }> {
    this.config.database = v; return this as any;
  }
  ssl(v: boolean): DBConfigBuilder<Set & { ssl: true }> {
    this.config.ssl = v; return this as any;
  }

  build(this: DBConfigBuilder<{ host: true; port: true; database: true }>): DBConfig {
    return this.config as DBConfig;
  }
}

new DBConfigBuilder().host('localhost').port(5432).database('mydb').build(); // OK
new DBConfigBuilder().host('localhost').build(); // Ошибка: port и database не установлены
```

### 2.2 Fluent API с полиморфным `this`

Для наследуемых билдеров TypeScript позволяет вернуть `this`, сохраняя тип наследника:

```ts
class BaseQueryBuilder {
  protected clauses: string[] = [];
  where(cond: string): this { this.clauses.push(`WHERE ${cond}`); return this; }
  limit(n: number): this   { this.clauses.push(`LIMIT ${n}`); return this; }
}
class SelectBuilder extends BaseQueryBuilder {
  select(...c: string[]): this { /* ... */ return this; }
  toSQL(): string { /* ... */ return ''; }
}
// .where() возвращает SelectBuilder (не BaseQueryBuilder) — цепочка не теряет тип
new SelectBuilder().select('id', 'name').where('active = true').limit(10).toSQL();
```

## 3. Type-safe Event Emitter

### 3.1 Generic Event Map

Карта событий: ключ — имя, значение — тип payload. Методы `on`/`emit`/`off` параметризованы этой картой:

```ts
interface EventMap {
  connect:    { host: string; port: number };
  disconnect: { reason: string };
  message:    { from: string; body: string; timestamp: Date };
  error:      Error;
}

class TypedEmitter<Events extends Record<string, unknown>> {
  private listeners = new Map<keyof Events, Set<Function>>();

  on<K extends keyof Events>(event: K, handler: (payload: Events[K]) => void): this {
    if (!this.listeners.has(event)) this.listeners.set(event, new Set());
    this.listeners.get(event)!.add(handler);
    return this;
  }
  off<K extends keyof Events>(event: K, handler: (payload: Events[K]) => void): this {
    this.listeners.get(event)?.delete(handler);
    return this;
  }
  emit<K extends keyof Events>(event: K, payload: Events[K]): void {
    this.listeners.get(event)?.forEach(fn => fn(payload));
  }
}
```

### 3.2 Автодополнение и проверка payload

```ts
const emitter = new TypedEmitter<EventMap>();
emitter.on('connect', (p) => console.log(p.host));       // p: { host; port }
emitter.emit('message', { from: 'Alice', body: 'Hi' });  // Ошибка: нет timestamp
emitter.on('unknown_event', () => {});                     // Ошибка: нет в EventMap
```

## 4. Branded Types (Номинативные типы)

### 4.1 Проблема и решение

Структурно идентичные типы (`UserId = number`, `OrderId = number`) взаимозаменяемы. **Фантомное поле**, не существующее в runtime, делает их несовместимыми:

```ts
type Brand<T, B extends string> = T & { readonly __brand: B };

type UserId  = Brand<number, 'UserId'>;
type OrderId = Brand<number, 'OrderId'>;
type USD     = Brand<number, 'USD'>;
type EUR     = Brand<number, 'EUR'>;

// Фабричные функции — единственный способ создать branded-значение
function userId(id: number): UserId    { return id as UserId; }
function orderId(id: number): OrderId  { return id as OrderId; }

function getOrder(id: OrderId): void { /* ... */ }
getOrder(orderId(99)); // OK
getOrder(userId(42));  // Ошибка: UserId не совместим с OrderId
```

### 4.2 Validated Strings и альтернатива через unique symbol

```ts
type Email = Brand<string, 'Email'>;
function validateEmail(input: string): Email | null {
  return /^[^\s@]+@[^\s@]+\.[^\s@]+$/.test(input) ? (input as Email) : null;
}
function sendEmail(to: Email): void { /* ... */ }
// sendEmail('raw') — ошибка! Нужно провести через validateEmail

// Альтернатива: unique symbol не засоряет автодополнение
declare const __brand: unique symbol;
type Branded<T, B> = T & { [__brand]: B };
type Meters = Branded<number, 'Meters'>;
```

## 5. Exhaustive Pattern Matching

### 5.1 Функция assertNever

Гарантирует **на уровне компилятора**, что все варианты объединения обработаны:

```ts
function assertNever(value: never, msg?: string): never {
  throw new Error(msg ?? `Unexpected value: ${value}`);
}

function area(shape: Shape): number {
  switch (shape.kind) {
    case 'circle':   return Math.PI * shape.radius ** 2;
    case 'square':   return shape.side ** 2;
    case 'triangle': return 0.5 * shape.base * shape.height;
    default:         return assertNever(shape); // shape: never — все покрыты
  }
}
```

### 5.2 Реакция на новый вариант

```ts
type Shape = Circle | Square | Triangle | Ellipse; // добавили Ellipse

// В default: assertNever(shape)
// Ошибка: Argument of type 'Ellipse' is not assignable to parameter of type 'never'
```

**Принцип:** `never` — нижний тип. Если компилятор присваивает `shape` к `never`, все ветви исчерпаны.

### 5.3 Exhaustive Record и ts-pattern

```ts
// Объект-маппинг — пропуск ключа даёт ошибку компиляции
const calc: Record<Shape['kind'], (s: any) => number> = {
  circle: (s: Circle) => Math.PI * s.radius ** 2,
  square: (s: Square) => s.side ** 2,
  triangle: (s: Triangle) => 0.5 * s.base * s.height,
};

// ts-pattern — библиотечный pattern matching с .exhaustive()
import { match } from 'ts-pattern';
match(shape)
  .with({ kind: 'circle' },   (s) => Math.PI * s.radius ** 2)
  .with({ kind: 'square' },   (s) => s.side ** 2)
  .with({ kind: 'triangle' }, (s) => 0.5 * s.base * s.height)
  .exhaustive(); // compile-time ошибка при неполном покрытии
```

## 6. Type-safe API клиент

### 6.1 Типовая карта эндпоинтов

```ts
interface ApiEndpoints {
  'GET /users':        { response: User[]; query: { page?: number } };
  'GET /users/:id':    { response: User;   params: { id: string } };
  'POST /users':       { response: User;   body: CreateUserDTO };
  'PUT /users/:id':    { response: User;   params: { id: string }; body: UpdateUserDTO };
  'DELETE /users/:id': { response: void;   params: { id: string } };
}
```

### 6.2 Извлечение параметров из URL

```ts
type ExtractParams<T extends string> =
  T extends `${string}:${infer Param}/${infer Rest}`
    ? { [K in Param | keyof ExtractParams<Rest>]: string }
    : T extends `${string}:${infer Param}`
      ? { [K in Param]: string }
      : {};

type T1 = ExtractParams<'/users/:id'>;                       // { id: string }
type T2 = ExtractParams<'/posts/:postId/comments/:commentId'>; // { postId: string; commentId: string }
```

### 6.3 Generic клиент с условными аргументами

```ts
class ApiClient<E extends Record<string, { response: unknown }>> {
  constructor(private baseUrl: string) {}
  async request<R extends keyof E & string>(
    route: R,
    ...args: 'body' extends keyof E[R]
      ? [opts: { params?: Record<string, string>; body: E[R]['body'] }]
      : 'params' extends keyof E[R]
        ? [opts: { params: E[R]['params'] }]
        : [opts?: { query?: Record<string, string> }]
  ): Promise<E[R]['response']> { return {} as E[R]['response']; }
}

const api = new ApiClient<ApiEndpoints>('https://api.example.com');
const users = await api.request('GET /users');                               // User[]
const user  = await api.request('GET /users/:id', { params: { id: '1' } }); // User
await api.request('POST /users'); // Ошибка: body обязателен
```

## 7. Utility Types паттерны

### 7.1 Deep-версии стандартных утилит

```ts
type DeepPartial<T>  = T extends object ? { [K in keyof T]?: DeepPartial<T[K]> } : T;
type DeepReadonly<T> = T extends object ? { readonly [K in keyof T]: DeepReadonly<T[K]> } : T;
type DeepRequired<T> = T extends object ? { [K in keyof T]-?: DeepRequired<T[K]> } : T;
```

### 7.2 PickByType и OmitByType — фильтрация по типу значения

```ts
type PickByType<T, V> = { [K in keyof T as T[K] extends V ? K : never]: T[K] };
type OmitByType<T, V> = { [K in keyof T as T[K] extends V ? never : K]: T[K] };

interface User { id: number; name: string; email: string; active: boolean }
type Strings = PickByType<User, string>; // { name: string; email: string }
```

### 7.3 Dot-notation Paths

```ts
type Paths<T, P extends string = ''> = T extends object
  ? { [K in keyof T & string]: T[K] extends object
      ? `${P}${K}` | Paths<T[K], `${P}${K}.`> : `${P}${K}`
    }[keyof T & string] : never;

type FormPaths = Paths<{ user: { name: string; address: { city: string } } }>;
// 'user' | 'user.name' | 'user.address' | 'user.address.city'
```

### 7.4 StrictOmit

Встроенный `Omit` **не проверяет** существование ключа. `StrictOmit` ограничивает:

```ts
type StrictOmit<T, K extends keyof T> = Omit<T, K>;
type A = StrictOmit<User, 'nonExistent'>; // Ошибка компиляции!
```

## 8. Inference Patterns

### 8.1 Вывод из const-массивов и объектов

```ts
const ROLES = ['admin', 'editor', 'viewer'] as const;
type Role = typeof ROLES[number]; // 'admin' | 'editor' | 'viewer'

const STATUS = { ACTIVE: 'active', INACTIVE: 'inactive' } as const;
type StatusValue = typeof STATUS[keyof typeof STATUS]; // 'active' | 'inactive'
```

**Без `as const`** массив даёт `string[]`, а `typeof arr[number]` — просто `string`.

### 8.2 Извлечение props и infer из функций

```ts
import type { ComponentProps } from 'react';
type ButtonProps = ComponentProps<typeof Button>;  // props компонента
type DivProps    = ComponentProps<'div'>;           // props HTML-элемента

type FirstArg<T> = T extends (a: infer A, ...r: any[]) => any ? A : never;
type Awaited<T>  = T extends Promise<infer R> ? Awaited<R> : T;

function createStore<T>(init: T) {
  let state = init;
  return { get: () => state, set: (v: T) => { state = v; } };
}
type Store = ReturnType<typeof createStore<{ count: number }>>;
```

### 8.3 typeof import() для типов модулей

```ts
type Lodash   = typeof import('lodash');
type Debounce = typeof import('lodash')['debounce'];
async function load(): Promise<typeof import('./heavy')> { return import('./heavy'); }
```

## 9. Conditional Type Patterns

### 9.1 IsNever, IsAny, IsUnknown

```ts
type IsNever<T>   = [T] extends [never] ? true : false;        // tuple блокирует дистрибуцию
type IsAny<T>     = 0 extends (1 & T) ? true : false;          // 1 & any = any, 0 extends any
type IsUnknown<T> = IsAny<T> extends true ? false : unknown extends T ? true : false;
```

### 9.2 Equals — точное равенство типов

```ts
type Equals<A, B> =
  (<T>() => T extends A ? 1 : 2) extends
  (<T>() => T extends B ? 1 : 2) ? true : false;

type T1 = Equals<{ a: string }, { readonly a: string }>; // false
type T2 = Equals<any, unknown>;                           // false
type T3 = Equals<string, string>;                          // true
```

**Важно:** `Equals` — единственный надёжный способ проверить равенство, включая модификаторы `readonly`/`optional`.

### 9.3 UnionToIntersection

Контравариантность параметров функций превращает union в intersection:

```ts
type UnionToIntersection<U> =
  (U extends any ? (k: U) => void : never) extends (k: infer I) => void ? I : never;
type R = UnionToIntersection<{ a: 1 } | { b: 2 }>; // { a: 1 } & { b: 2 }
```

### 9.4 TupleToUnion, StringToUnion, LastOfUnion

```ts
type TupleToUnion<T extends readonly any[]> = T[number];
type Colors = TupleToUnion<['red', 'green', 'blue']>; // 'red' | 'green' | 'blue'

type StringToUnion<S extends string> =
  S extends `${infer C}${infer R}` ? C | StringToUnion<R> : never;
type Chars = StringToUnion<'hello'>; // 'h' | 'e' | 'l' | 'o'

type LastOfUnion<U> =
  UnionToIntersection<U extends any ? (x: U) => void : never> extends
  (x: infer L) => void ? L : never;
type Last = LastOfUnion<'a' | 'b' | 'c'>; // 'c'
```

**Предупреждение:** порядок элементов union не гарантирован. `LastOfUnion` не для production-логики.

## 10. Anti-patterns и ошибки типизации

### 10.1 Злоупотребление `any`

```ts
// ПЛОХО: any заражает всю цепочку
function process(data: any) { return data.foo.bar.baz(); } // нет ошибок, взрыв в runtime

// ХОРОШО: unknown требует сужения
function process(data: unknown) {
  if (typeof data === 'object' && data !== null && 'foo' in data) { /* ... */ }
}
```

| Тип | Присваивание | Операции |
|---|---|---|
| `any` | Что угодно | Что угодно (нет проверки) |
| `unknown` | Что угодно | Только после сужения |
| `never` | Ничего | Невозможно получить значение |

**Правило:** `"strict": true` + `"noImplicitAny": true` в `tsconfig.json`. Линтер: `@typescript-eslint/no-explicit-any`.

### 10.2 Type Assertions и `as unknown as T`

```ts
// ПЛОХО — assertion скрывает несовместимость
const user = JSON.parse(res) as User;
const num: number = 'hello' as unknown as number; // двойное приведение — runtime-баг

// ХОРОШО — runtime-валидация через type guard
function isUser(d: unknown): d is User {
  return typeof d === 'object' && d !== null && 'id' in d && 'name' in d;
}
// Двойное приведение допустимо ТОЛЬКО в тестах/моках
```

### 10.3 Сверхсложные типы

**Признаки проблемы:** ошибки TS > 10 строк, IDE тормозит, тип нечитаем за 30 секунд. Решение — разбивать на именованные вспомогательные типы с JSDoc-комментариями.

### 10.4 `@ts-ignore` vs `@ts-expect-error`

```ts
// @ts-ignore      — подавляет ошибку, молчит если ошибка исчезнет (мёртвый код)
// @ts-expect-error — подавляет ошибку, ПРЕДУПРЕЖДАЕТ если ошибки нет (самоочищается)

// @ts-expect-error — legacy API returns string instead of number (TICKET-1234)
const x: number = legacyApi.getValue();
```

**Правило:** `@typescript-eslint/prefer-ts-expect-error` запрещает `@ts-ignore`. Всегда указывайте **причину и номер задачи** в комментарии.
