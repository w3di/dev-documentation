## 1. VirtualizedList

`VirtualizedList` — базовый компонент виртуализации в React Native. `FlatList` и `SectionList` — обёртки над ним.

### Концепция виртуализации

Виртуализация = рендеринг **только видимых элементов** + небольшой буфер сверху и снизу:

```
Полный список: 10 000 элементов

Без виртуализации:              С виртуализацией:
┌───────────────────┐           ┌───────────────────┐
│ Item 1    (render)│           │                   │ ← unmounted
│ Item 2    (render)│           │                   │
│ Item 3    (render)│           │                   │
│ ...               │           ├───────────────────┤
│ Item 9998 (render)│           │ Item 48  (render) │ ← buffer
│ Item 9999 (render)│           │ Item 49  (render) │
│ Item 10000(render)│           │ Item 50  (render) │ ← visible
│                   │           │ Item 51  (render) │ ← visible
│ 10 000 Views в    │           │ Item 52  (render) │ ← visible
│ памяти            │           │ Item 53  (render) │ ← buffer
│                   │           │ Item 54  (render) │
│                   │           ├───────────────────┤
│                   │           │                   │ ← unmounted
└───────────────────┘           └───────────────────┘
                                ~10-20 Views в памяти
```

### Ключевые props

| Prop | Default | Описание |
|------|---------|----------|
| `initialNumToRender` | 10 | Количество элементов при первом рендере |
| `maxToRenderPerBatch` | 10 | Сколько элементов рендерить за один batch |
| `windowSize` | 21 | Размер окна в viewport'ах (21 = 10 экранов вверх + текущий + 10 вниз) |
| `updateCellsBatchingPeriod` | 50ms | Интервал между batch-рендерами |
| `removeClippedSubviews` | false | Удалять ли views за пределами viewport (Android) |

### Настройка windowSize

```jsx
// windowSize = 21 (default): рендерит 21 экран контента
// Для длинных списков можно уменьшить:
<FlatList
  windowSize={5}  // 2 экрана вверх + текущий + 2 вниз
  // Меньше памяти, но больше "пустых" областей при быстром скролле
/>
```

## 2. FlatList

### Базовое использование

```jsx
<FlatList
  data={items}                           // обязательный: массив данных
  renderItem={({ item, index }) => (     // обязательный: функция рендера
    <ItemComponent item={item} />
  )}
  keyExtractor={(item) => item.id}       // уникальный ключ
/>
```

### getItemLayout (критическая оптимизация)

Если все элементы имеют **фиксированную высоту**, `getItemLayout` позволяет пропустить измерение:

```jsx
const ITEM_HEIGHT = 72;
const SEPARATOR_HEIGHT = 1;

<FlatList
  data={items}
  renderItem={renderItem}
  getItemLayout={(data, index) => ({
    length: ITEM_HEIGHT,
    offset: (ITEM_HEIGHT + SEPARATOR_HEIGHT) * index,
    index,
  })}
  // Без getItemLayout: FlatList измеряет каждый элемент → лаги при scrollToIndex
  // С getItemLayout: мгновенный scrollToIndex, быстрый initial render
/>
```

### extraData

`FlatList` использует `PureComponent` и не ре-рендерится при изменении внешнего состояния:

```jsx
const [selectedId, setSelectedId] = useState(null);

<FlatList
  data={items}
  extraData={selectedId}  // ← передать внешние данные, влияющие на рендер
  renderItem={({ item }) => (
    <Item
      title={item.title}
      selected={item.id === selectedId}
      onPress={() => setSelectedId(item.id)}
    />
  )}
/>
```

### Основные props

```jsx
<FlatList
  data={items}
  renderItem={renderItem}
  keyExtractor={(item) => item.id}

  // Pull-to-refresh
  refreshing={isRefreshing}
  onRefresh={handleRefresh}

  // Бесконечная загрузка
  onEndReached={loadMore}
  onEndReachedThreshold={0.5}    // 0.5 = вызвать когда до конца осталось 50% экрана

  // Разделители
  ItemSeparatorComponent={() => <View style={{ height: 1, backgroundColor: '#eee' }} />}

  // Пустой список
  ListEmptyComponent={<Text>Нет данных</Text>}

  // Header и Footer
  ListHeaderComponent={<Header />}
  ListFooterComponent={isLoading ? <ActivityIndicator /> : null}

  // Многоколоночный список
  numColumns={2}
  columnWrapperStyle={{ gap: 8 }}

  // Горизонтальный список
  horizontal={true}
  showsHorizontalScrollIndicator={false}

  // Производительность
  initialNumToRender={10}
  maxToRenderPerBatch={5}
  windowSize={11}
  removeClippedSubviews={true}
  getItemLayout={getItemLayout}
/>
```

### Важная особенность

**Внутреннее состояние элементов теряется** при скролле за пределы render window. Если элемент имеет локальный state (раскрытый аккордеон, введённый текст), он будет сброшен. Решение — хранить такое состояние **вне компонента** (в store, в parent state).

## 3. SectionList

Для данных с секциями:

```jsx
const DATA = [
  {
    title: 'Фрукты',
    data: ['Яблоко', 'Банан', 'Апельсин'],
  },
  {
    title: 'Овощи',
    data: ['Морковь', 'Картофель', 'Огурец'],
  },
];

<SectionList
  sections={DATA}
  keyExtractor={(item, index) => item + index}
  renderItem={({ item }) => <Text>{item}</Text>}
  renderSectionHeader={({ section: { title } }) => (
    <Text style={styles.sectionHeader}>{title}</Text>
  )}
  stickySectionHeadersEnabled={true}  // "прилипающие" заголовки
/>
```

## 4. FlashList и Legend List

Официальная документация React Native рекомендует **FlashList** и **Legend List** как альтернативы FlatList для больших списков.

### FlashList (@shopify/flash-list)

FlashList использует **recycling** вместо виртуализации:

```
FlatList (virtualization):
Скролл вниз → unmount Item 1 → mount Item 11 (новый экземпляр)

FlashList (recycling):
Скролл вниз → Item 1 переиспользуется как Item 11 (тот же нативный view, новые данные)
```

Recycling значительно быстрее: не нужно создавать/удалять нативные views.

```jsx
import { FlashList } from '@shopify/flash-list';

<FlashList
  data={items}
  renderItem={({ item }) => <ItemComponent item={item} />}
  estimatedItemSize={72}  // обязательный: примерная высота элемента
  // FlashList использует это для оптимизации layout
/>
```

### Legend List (@legendapp/list)

Ещё одна высокопроизводительная альтернатива с recycling.

### Сравнение

| Аспект | FlatList | FlashList | Legend List |
|--------|----------|-----------|------------|
| Стратегия | Виртуализация | Recycling | Recycling |
| Blank areas | Часто при быстром скролле | Редко | Редко |
| Mount/Unmount | Каждый элемент | Переиспользование | Переиспользование |
| API | Встроенный | Почти как FlatList | Почти как FlatList |
| Требования | — | `estimatedItemSize` | — |

## 5. Оптимизация рендеринга списков

### React.memo для renderItem

```jsx
// ПЛОХО: компонент ре-рендерится при каждом скролле
const renderItem = ({ item }) => <Item data={item} />;

// ХОРОШО: мемоизированный компонент
const MemoizedItem = React.memo(({ data, onPress }) => {
  return (
    <Pressable onPress={() => onPress(data.id)}>
      <Text>{data.title}</Text>
    </Pressable>
  );
});

// ХОРОШО: стабильная ссылка на renderItem
const renderItem = useCallback(({ item }) => (
  <MemoizedItem data={item} onPress={handlePress} />
), [handlePress]);
```

### Избегайте анонимных функций в renderItem

```jsx
// ПЛОХО: новая функция при каждом рендере → React.memo не работает
renderItem={({ item }) => (
  <Item onPress={() => handlePress(item.id)} />
)}

// ХОРОШО: обработчик внутри мемоизированного компонента
const MemoizedItem = React.memo(({ item, onPress }) => {
  const handlePress = useCallback(() => {
    onPress(item.id);
  }, [item.id, onPress]);

  return <Pressable onPress={handlePress}><Text>{item.title}</Text></Pressable>;
});
```

### keyExtractor

```jsx
// ПЛОХО: index как ключ — проблемы при удалении/перемещении
keyExtractor={(item, index) => String(index)}

// ХОРОШО: уникальный стабильный ID
keyExtractor={(item) => item.id}
```

## 6. Общая производительность

### Release vs Debug

| Аспект | Debug | Release |
|--------|-------|---------|
| JS-движок | Hermes без оптимизаций | Hermes Bytecode (.hbc) |
| Dev tools | Включены | Отключены |
| LogBox | Активен | Отключён |
| Source maps | Загружены | Нет |
| `__DEV__` | `true` | `false` |
| Скорость JS | **2-5x медленнее** | Максимальная |

**Никогда не оценивайте производительность в debug-сборке.**

### console stripping

```js
// babel.config.js
module.exports = {
  presets: ['module:@react-native/babel-preset'],
  env: {
    production: {
      plugins: ['transform-remove-console'],
    },
  },
};
```

### Inline Requires

Lazy-загрузка модулей:

```js
// metro.config.js
module.exports = {
  transformer: {
    getTransformOptions: async () => ({
      transform: {
        inlineRequires: true, // модули загружаются при первом использовании
      },
    }),
  },
};
```

## 7. Оптимизация изображений

### Размер изображений

```jsx
// ПЛОХО: загрузка изображения 4000x3000 для отображения 200x150
<Image source={{ uri: largeImageUrl }} style={{ width: 200, height: 150 }} />

// ХОРОШО: запросить изображение нужного размера с сервера
const optimizedUri = `${imageBaseUrl}?w=400&h=300&fit=cover`;
<Image source={{ uri: optimizedUri }} style={{ width: 200, height: 150 }} />
```

### Кеширование

Встроенный `<Image>` имеет базовый кеш. Для продвинутого кеширования — `expo-image` или `react-native-fast-image`:

```jsx
import { Image } from 'expo-image';

<Image
  source={{ uri: imageUrl }}
  placeholder={blurhash}
  contentFit="cover"
  transition={200}
  cachePolicy="memory-disk" // кешировать в RAM и на диске
/>
```

### resizeMode

```jsx
<Image
  source={source}
  resizeMode="cover"    // заполняет, обрезая лишнее (default)
  // "contain"  — вписывает, сохраняя пропорции
  // "stretch"  — растягивает без сохранения пропорций
  // "center"   — центрирует без масштабирования
/>
```

### Анимация изображений

```jsx
// ПЛОХО: анимация width/height — пересчёт layout на каждый кадр
Animated.timing(widthAnim, { toValue: 200, useNativeDriver: false }).start();

// ХОРОШО: анимация scale — работает на native driver
Animated.timing(scaleAnim, { toValue: 1.5, useNativeDriver: true }).start();
// transform: [{ scale: scaleAnim }]
```

## 8. Работа с тяжёлыми вычислениями

### requestAnimationFrame

Откладывает выполнение до следующего кадра:

```jsx
function handleNavigation() {
  // Сначала запустить анимацию навигации
  navigation.navigate('Details');

  // Тяжёлую работу выполнить после анимации
  requestAnimationFrame(() => {
    processHeavyData();
  });
}
```

### Разбиение на чанки

```jsx
async function processLargeArray(items) {
  const CHUNK_SIZE = 50;

  for (let i = 0; i < items.length; i += CHUNK_SIZE) {
    const chunk = items.slice(i, i + CHUNK_SIZE);
    processChunk(chunk);

    // Дать UI потоку "подышать"
    await new Promise(resolve => requestAnimationFrame(resolve));
  }
}
```

### Native Driver для анимаций

```jsx
// useNativeDriver: true — анимация выполняется на UI Thread
// JS Thread может быть занят — анимация всё равно плавная

Animated.spring(translateY, {
  toValue: 100,
  useNativeDriver: true, // обязательно
  // Поддерживаемые свойства: transform, opacity
  // НЕ поддерживаются: width, height, padding, margin, backgroundColor
}).start();
```

## 9. Профилирование

### Performance Monitor

Dev Menu → "Perf Monitor":
- **JS FPS** — частота кадров JavaScript Thread
- **UI FPS** — частота кадров UI Thread
- **Views** — количество нативных view в иерархии
- **RAM** — потребление памяти

### React DevTools Profiler

Через React Native DevTools (Dev Menu → "Open DevTools"):
- Flamegraph рендеров
- Время рендера каждого компонента
- Причины ре-рендеров
- Component highlight при ре-рендере

### Hermes Profiler

```jsx
// Программный запуск профилирования
HermesInternal?.enableSamplingProfiler?.();
// ... код для профилирования ...
HermesInternal?.disableSamplingProfiler?.();
```

## 10. Чеклист производительности

### Сборка и окружение
- [ ] Тестировать в **release build**
- [ ] Удалить `console.log` в production (`transform-remove-console`)
- [ ] Включить `inlineRequires` в Metro
- [ ] Hermes включён (по умолчанию с 0.70+)

### Списки
- [ ] Использовать `FlatList` / `FlashList` вместо `ScrollView` для длинных списков
- [ ] Реализовать `getItemLayout` для элементов фиксированной высоты
- [ ] `keyExtractor` возвращает **стабильный уникальный** ID
- [ ] `renderItem` обёрнут в `React.memo`
- [ ] Нет анонимных функций в `renderItem`
- [ ] `extraData` передан при зависимости от внешнего state
- [ ] Настроить `windowSize`, `maxToRenderPerBatch` под конкретный случай

### Изображения
- [ ] Запрашивать изображения **нужного размера** с сервера
- [ ] Использовать `expo-image` или `fast-image` для кеширования
- [ ] Анимировать `transform: scale` вместо `width`/`height`

### Анимации
- [ ] `useNativeDriver: true` для всех анимаций (где возможно)
- [ ] Использовать `Reanimated` для сложных gesture-driven анимаций
- [ ] Native-backed stack navigator для навигации

### Рендеринг
- [ ] `React.memo` для компонентов, получающих те же props
- [ ] `useMemo` / `useCallback` для тяжёлых вычислений и стабильных ссылок
- [ ] Не создавать объекты/массивы inline в JSX
- [ ] Разбивать тяжёлые вычисления на чанки с `requestAnimationFrame`

### Сеть
- [ ] Кешировать API-ответы (React Query, SWR, Apollo Cache)
- [ ] Пагинация вместо загрузки всего списка
- [ ] Оптимистичные обновления UI
