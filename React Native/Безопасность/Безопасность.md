## 1. Хранение секретов

### Главный принцип

**Никогда не храните API ключи в коде приложения.** JS bundle можно извлечь из APK/IPA и прочитать — все строки в коде доступны в plain text.

```jsx
// ОПАСНО: ключ доступен в JS bundle
const API_KEY = 'sk-live-abc123';

// ОПАСНО: .env файлы (react-native-dotenv, react-native-config)
// тоже компилируются в bundle и доступны
process.env.API_KEY; // ← это НЕ секрет, это environment variable в bundle
```

### Правильный подход: серверная прослойка

```
Мобильное приложение
    │
    │ HTTPS (только auth token)
    ▼
Backend / API Gateway / Cloud Function
    │
    │ API_KEY (хранится на сервере)
    ▼
Внешний API (Stripe, OpenAI, etc.)
```

### Хранение токенов на устройстве

| Данные | Где хранить |
|--------|-----------|
| Access Token | **Secure Store** (Keychain / Android Keystore) |
| Refresh Token | **Secure Store** |
| Настройки (theme, language) | AsyncStorage / MMKV |
| Кеш данных | AsyncStorage / MMKV / SQLite |

```jsx
import * as SecureStore from 'expo-secure-store';

// Сохранение токена
await SecureStore.setItemAsync('access_token', token);

// Чтение
const token = await SecureStore.getItemAsync('access_token');
```

Под капотом:
- **iOS**: Keychain Services — данные зашифрованы аппаратно через Secure Enclave
- **Android**: Encrypted SharedPreferences с ключом в Android Keystore

## 2. Аутентификация

### OAuth2 + PKCE

Для мобильных приложений **обязателен** PKCE (Proof Key for Code Exchange) — защита от перехвата authorization code:

```
1. Приложение генерирует code_verifier (случайная строка)
2. Вычисляет code_challenge = SHA256(code_verifier)
3. Отправляет code_challenge на auth server
4. Получает authorization code
5. Обменивает code + code_verifier на токены
6. Сервер проверяет SHA256(code_verifier) === code_challenge

Без PKCE: перехватчик может использовать authorization code
С PKCE: перехватчик не знает code_verifier → не может получить токены
```

### react-native-app-auth

```jsx
import { authorize } from 'react-native-app-auth';

const config = {
  issuer: 'https://auth.example.com',
  clientId: 'my-app-client-id',
  redirectUrl: 'com.myapp://oauth/callback',
  scopes: ['openid', 'profile', 'email'],
  usePKCE: true,
};

const result = await authorize(config);
// result.accessToken, result.refreshToken, result.idToken
```

### Биометрическая аутентификация

```jsx
import * as LocalAuthentication from 'expo-local-authentication';

// Проверка поддержки
const hasHardware = await LocalAuthentication.hasHardwareAsync();
const isEnrolled = await LocalAuthentication.isEnrolledAsync();

// Аутентификация
const result = await LocalAuthentication.authenticateAsync({
  promptMessage: 'Подтвердите вход',
  fallbackLabel: 'Использовать пин-код',
  cancelLabel: 'Отмена',
});

if (result.success) {
  // Пользователь аутентифицирован
  const token = await SecureStore.getItemAsync('access_token');
}
```

## 3. Сетевая безопасность

### HTTPS

Всегда используйте HTTPS. iOS блокирует HTTP-запросы по умолчанию (App Transport Security). Android 9+ тоже блокирует cleartext по умолчанию.

### SSL/Certificate Pinning

Для высокобезопасных приложений — привязка к конкретному сертификату сервера:

```jsx
// react-native-ssl-pinning
import { fetch } from 'react-native-ssl-pinning';

const response = await fetch('https://api.myapp.com/data', {
  method: 'GET',
  sslPinning: {
    certs: ['my-server-cert'], // имя .cer файла в нативном проекте
  },
  headers: {
    Authorization: `Bearer ${token}`,
  },
});
```

**Важно**: сертификаты истекают (обычно каждые 1-2 года). Планируйте ротацию:
- Включайте в приложение **текущий и следующий** сертификат
- Обновляйте приложение с новым сертификатом **до** истечения старого

## 4. Deep Link безопасность

### URL Scheme — небезопасен

```
myapp://auth/callback?token=abc123
```

Любое приложение может зарегистрировать такую же URL scheme и перехватить callback. **Никогда не передавайте секреты через URL scheme.**

### Universal Links (iOS) / App Links (Android)

Безопасная альтернатива — привязка к **верифицированному домену**:

```
https://myapp.com/auth/callback?code=abc123
```

Для верификации:
- **iOS**: файл `apple-app-site-association` на сервере
- **Android**: файл `assetlinks.json` на сервере

Только ваше приложение может обработать ссылки на ваш домен.

## 5. Code Obfuscation

### Hermes Bytecode

Hermes bytecode (.hbc) в release-сборке **не является обфускацией**, но затрудняет чтение кода по сравнению с plain JS.

### ProGuard (Android)

Обфускация Java/Kotlin кода:

```groovy
// android/app/build.gradle
buildTypes {
    release {
        minifyEnabled true
        shrinkResources true
        proguardFiles getDefaultProguardFile('proguard-android.txt'), 'proguard-rules.pro'
    }
}
```

### JS-level обфускация

Для дополнительной защиты JS-кода можно использовать `metro-minify-terser` или `javascript-obfuscator`, но это:
- Увеличивает размер bundle
- Может влиять на производительность
- **Не является надёжной защитой** — determined attacker всё равно сможет прочитать код

## 6. Root/Jailbreak Detection

Для финансовых и высокобезопасных приложений:

```jsx
// react-native-jail-monkey или аналоги
import JailMonkey from 'jail-monkey';

if (JailMonkey.isJailBroken()) {
  // Устройство jailbroken/rooted
  // Показать предупреждение или ограничить функциональность
}

if (JailMonkey.isDebuggedMode()) {
  // Приложение запущено под отладчиком
}
```

**Предупреждение**: root/jailbreak detection можно обойти. Это **дополнительный** уровень защиты, а не основной.

## 7. Чеклист безопасности

### Секреты
- [ ] API ключи хранятся на **сервере**, не в коде приложения
- [ ] Токены хранятся в **Secure Store** (Keychain / Android Keystore)
- [ ] `.env` файлы используются только для **некритичных** конфигураций

### Аутентификация
- [ ] OAuth2 с **PKCE**
- [ ] Access Token — короткоживущий
- [ ] Refresh Token — в Secure Store
- [ ] Биометрия для повторного входа

### Сеть
- [ ] Только **HTTPS**
- [ ] **SSL Pinning** для критичных API (с планом ротации сертификатов)
- [ ] Не логировать тела запросов/ответов в production

### Deep Links
- [ ] **Universal Links / App Links** для auth callbacks
- [ ] Никаких секретов через URL Scheme

### Сборка
- [ ] **ProGuard** включён для Android release
- [ ] Hermes bytecode (по умолчанию)
- [ ] `console.log` удалён в production
- [ ] Source maps **не включены** в release bundle (загружены отдельно для crash reporting)
