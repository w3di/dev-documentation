## 1. Dev Menu

Доступ к Dev Menu:
- **iOS Simulator**: `Cmd + D`
- **Android Emulator**: `Cmd + M` (macOS) / `Ctrl + M` (Windows/Linux)
- **Устройство**: shake (встряхнуть)

### Основные опции

| Опция | Описание |
|-------|----------|
| **Open DevTools** | React Native DevTools (Console, Components, Profiler) |
| **Reload** | Перезагрузка JS bundle |
| **Fast Refresh** | Вкл/выкл hot reload |
| **Perf Monitor** | Overlay с FPS, RAM, Views |
| **Element Inspector** | Инспекция UI-элементов (аналог Chrome DevTools) |

Все инструменты отладки **отключены в release-сборке**.

## 2. React Native DevTools

Основной инструмент отладки. Доступ: Dev Menu → "Open DevTools" или нажать `j` в CLI.

### Console

Логи, ошибки, предупреждения. Поддерживает `console.log`, `console.warn`, `console.error`, `console.table`.

### React Components Inspector

- Дерево React-компонентов
- Props и state каждого компонента
- Highlight при ре-рендере

### Profiler

- Flamegraph рендеров
- Время каждого commit
- Причины ре-рендеров
- Ранкинг компонентов по времени рендера

### Breakpoints

```jsx
// Программная точка останова
debugger; // DevTools остановится здесь

// Или через DevTools → Sources → кликнуть на номер строки
```

## 3. LogBox

Внутренний компонент для отображения ошибок и предупреждений.

### Конфигурация

```jsx
import { LogBox } from 'react-native';

// Игнорировать конкретные предупреждения
LogBox.ignoreLogs([
  'Warning: componentWillReceiveProps',
  /GraphQL error:.*/,  // regex
]);

// Отключить все логи (НЕ рекомендуется)
LogBox.ignoreAllLogs();
```

### Типы уведомлений

- **Жёлтый** — предупреждение (`console.warn`). Можно закрыть
- **Красный** — ошибка (fatal). Нельзя закрыть до исправления

## 4. Performance Monitor

Dev Menu → "Perf Monitor". Отображает overlay:

```
┌─────────────────────────┐
│ JS: 60 fps   UI: 60 fps │
│ Views: 142   RAM: 87MB  │
└─────────────────────────┘
```

| Метрика | Цель | Проблема если |
|---------|------|--------------|
| **JS FPS** | 60 | < 30 — JS Thread перегружен |
| **UI FPS** | 60 | < 30 — слишком много views или тяжёлые эффекты |
| **Views** | Минимум | > 500 — возможно утечка views |
| **RAM** | Стабильно | Постоянный рост — утечка памяти |

## 5. Тестирование: Unit Tests

### Jest

Jest — дефолтный test runner для React Native:

```jsx
// __tests__/utils.test.ts
import { formatPrice, validateEmail } from '../utils';

describe('formatPrice', () => {
  it('formats number to price string', () => {
    expect(formatPrice(1234.5)).toBe('$1,234.50');
  });

  it('handles zero', () => {
    expect(formatPrice(0)).toBe('$0.00');
  });
});

describe('validateEmail', () => {
  it('accepts valid email', () => {
    expect(validateEmail('user@example.com')).toBe(true);
  });

  it('rejects invalid email', () => {
    expect(validateEmail('not-an-email')).toBe(false);
  });
});
```

### Моки нативных модулей

```jsx
// jest.setup.js
jest.mock('react-native/Libraries/Animated/NativeAnimatedHelper');

jest.mock('@react-native-async-storage/async-storage', () =>
  require('@react-native-async-storage/async-storage/jest/async-storage-mock')
);

jest.mock('react-native-mmkv', () => ({
  MMKV: jest.fn().mockImplementation(() => ({
    getString: jest.fn(),
    set: jest.fn(),
    delete: jest.fn(),
  })),
}));
```

## 6. Тестирование: Component Tests

### React Native Testing Library

```bash
npm install --save-dev @testing-library/react-native
```

```jsx
import { render, screen, fireEvent, waitFor } from '@testing-library/react-native';
import { LoginScreen } from '../LoginScreen';

describe('LoginScreen', () => {
  it('shows error on empty submit', () => {
    render(<LoginScreen />);

    fireEvent.press(screen.getByText('Войти'));

    expect(screen.getByText('Введите email')).toBeTruthy();
  });

  it('calls login on valid submit', async () => {
    const mockLogin = jest.fn().mockResolvedValue({ token: 'abc' });
    render(<LoginScreen onLogin={mockLogin} />);

    fireEvent.changeText(
      screen.getByPlaceholderText('Email'),
      'user@example.com'
    );
    fireEvent.changeText(
      screen.getByPlaceholderText('Пароль'),
      'password123'
    );
    fireEvent.press(screen.getByText('Войти'));

    await waitFor(() => {
      expect(mockLogin).toHaveBeenCalledWith('user@example.com', 'password123');
    });
  });

  it('shows loading state', async () => {
    const mockLogin = jest.fn(() => new Promise(() => {})); // never resolves
    render(<LoginScreen onLogin={mockLogin} />);

    fireEvent.changeText(screen.getByPlaceholderText('Email'), 'user@example.com');
    fireEvent.changeText(screen.getByPlaceholderText('Пароль'), 'pass');
    fireEvent.press(screen.getByText('Войти'));

    expect(screen.getByTestId('loading-indicator')).toBeTruthy();
  });
});
```

### Принципы тестирования

- Тестировать **поведение**, не реализацию
- Использовать `getByText`, `getByPlaceholderText`, `getByTestId` — как пользователь видит UI
- Не тестировать стили или внутренний state
- `testID` prop для элементов, которые сложно найти по тексту

## 7. Тестирование: E2E

### Maestro

Простой и стабильный E2E framework:

```yaml
# .maestro/login-flow.yaml
appId: com.myapp
---
- launchApp
- tapOn: "Email"
- inputText: "user@example.com"
- tapOn: "Пароль"
- inputText: "password123"
- tapOn: "Войти"
- assertVisible: "Главная"
```

```bash
# Запуск
maestro test .maestro/login-flow.yaml
```

### Detox (Wix)

Более мощный, но сложнее в настройке:

```js
// e2e/login.test.js
describe('Login', () => {
  beforeAll(async () => {
    await device.launchApp();
  });

  it('should login successfully', async () => {
    await element(by.id('email-input')).typeText('user@example.com');
    await element(by.id('password-input')).typeText('password123');
    await element(by.text('Войти')).tap();
    await expect(element(by.text('Главная'))).toBeVisible();
  });
});
```

### Сравнение E2E фреймворков

| Аспект | Maestro | Detox | Appium |
|--------|---------|-------|--------|
| Простота настройки | **Простая** | Средняя | Сложная |
| Язык тестов | **YAML** | JavaScript | Любой |
| Скорость | Быстро | **Очень быстро** | Медленно |
| Стабильность | Высокая | **Очень высокая** | Средняя |
| Кроссплатформенность | Да | Да | Да |
| CI/CD | Да | Да | Да |

## 8. Отладка нативного кода

### iOS (Xcode)

1. Открыть `ios/MyApp.xcworkspace` в Xcode
2. Product → Run
3. Breakpoints в Objective-C/Swift коде
4. View Hierarchy debugger (Debug → View Debugging → Capture View Hierarchy)
5. Instruments для профилирования (Memory, CPU, Network)

### Android (Android Studio)

1. Открыть `android/` в Android Studio
2. Run → Debug
3. Breakpoints в Java/Kotlin коде
4. Layout Inspector (Tools → Layout Inspector)
5. Android Profiler (CPU, Memory, Network)

### Logcat / Console

```bash
# Android логи
adb logcat | grep "ReactNative"
adb logcat *:E  # только ошибки

# iOS логи
# Xcode → Debug Area → Console
```

## 9. Crash Reporting

### Sentry

```jsx
import * as Sentry from '@sentry/react-native';

Sentry.init({
  dsn: 'https://xxx@sentry.io/xxx',
  tracesSampleRate: 1.0,
  enableAutoSessionTracking: true,
});

// Ручная отправка ошибки
try {
  riskyOperation();
} catch (error) {
  Sentry.captureException(error);
}

// Breadcrumbs для контекста
Sentry.addBreadcrumb({
  category: 'navigation',
  message: 'User navigated to Profile',
  level: 'info',
});
```

### Firebase Crashlytics

```jsx
import crashlytics from '@react-native-firebase/crashlytics';

// Автоматический сбор JS ошибок
// Ручная запись:
crashlytics().log('User signed in');
crashlytics().setUserId('user-123');

try {
  riskyOperation();
} catch (error) {
  crashlytics().recordError(error);
}
```

### Source Maps

Для читаемых stack traces в production нужны source maps:

```bash
# Загрузка source maps в Sentry
npx sentry-cli sourcemaps upload \
  --release "com.myapp@1.0.0" \
  --dist "1" \
  ./android/app/build/generated/sourcemaps/
```

Source maps **не включаются** в release bundle приложения — они загружаются отдельно в crash reporting сервис.
