## 1. Что такое JavaScriptCore

JavaScriptCore (JSC) — это **JavaScript-движок от Apple**, встроенный в WebKit (Safari).

- Был **дефолтным JS-движком** React Native до версии 0.70
- С 0.70 по 0.80 — оставался опциональным (Hermes по умолчанию)
- С 0.81 — **удалён из core**, вынесен в community-пакет

### Происхождение

```
WebKit (Safari)
  └── JavaScriptCore — JS-движок
        ├── Используется в Safari, iOS WebView, macOS
        ├── Был в React Native до версии 0.81
        └── Оптимизирован для десктопных/мобильных браузеров
```

### JSC на разных платформах (исторически)

| Платформа | Как поставлялся | Особенности |
|-----------|----------------|-------------|
| **iOS** | Системный JSC (встроен в iOS) | Не увеличивал размер приложения, Apple обновлял с iOS |
| **Android** | Bundled JSC (jsc-android) | Включался в APK (~3-5 MB), версия фиксирована |

## 2. Архитектура JSC

### Компоненты

```
JavaScript Source Code
        │
        ▼
┌─────────────────────────────────────────────┐
│             JavaScriptCore                   │
│                                              │
│  ┌──────────┐   ┌───────────┐   ┌────────┐  │
│  │  Lexer/  │──▶│    AST    │──▶│ LLInt  │  │  ← интерпретатор (Low Level Interpreter)
│  │  Parser  │   │           │   └───┬────┘  │
│  └──────────┘   └───────────┘       │       │
│                                     ▼       │
│                               ┌──────────┐  │
│                               │ Baseline  │  │  ← базовый JIT
│                               │   JIT    │  │
│                               └────┬─────┘  │
│                                    ▼        │
│                               ┌──────────┐  │
│                               │   DFG    │  │  ← оптимизирующий JIT
│                               │   JIT    │  │
│                               └────┬─────┘  │
│                                    ▼        │
│                               ┌──────────┐  │
│                               │   FTL    │  │  ← максимально оптимизирующий JIT
│                               │   JIT    │  │
│                               └──────────┘  │
└─────────────────────────────────────────────┘
```

### Pipeline выполнения

```
Source → Parse → AST → Bytecode → LLInt (interpret)
                                      │
                              горячая функция?
                                      │
                          ┌───────────┤
                          ▼           ▼
                    Baseline JIT   (остаётся в LLInt
                          │         если холодная)
                    ещё горячее?
                          │
                    ┌─────┤
                    ▼     ▼
                 DFG JIT  (остаётся Baseline)
                    │
              супергорячее?
                    │
                    ▼
                 FTL JIT (максимум оптимизаций)
```

JSC **профилирует** код во время выполнения и постепенно повышает уровень оптимизации для горячих путей.

## 3. JIT-компиляция

### Что такое JIT

JIT (Just-In-Time) — компиляция JavaScript в **машинный код** прямо во время выполнения. В отличие от AOT (Hermes), JIT компилирует код **по мере необходимости**:

```
JIT (JSC):
  1. Запуск: парсинг JS → интерпретация (медленно, но быстрый старт парсинга)
  2. Профилирование: JSC отслеживает какие функции вызываются часто
  3. Компиляция: горячие функции компилируются в машинный код
  4. Выполнение: скомпилированный код выполняется на скорости C/C++

AOT (Hermes):
  1. Сборка: JS → байткод (заранее)
  2. Запуск: загрузка байткода → выполнение (быстрый старт)
  3. Нет дополнительной компиляции в runtime
```

### Уровни JIT в JSC

| Уровень | Название | Скорость компиляции | Скорость выполнения | Когда |
|---------|----------|--------------------|--------------------|-------|
| 0 | **LLInt** | Мгновенно (интерпретация) | Медленно | Первый вызов |
| 1 | **Baseline JIT** | Быстро | Средне | ~100 вызовов |
| 2 | **DFG JIT** | Средне | Быстро | ~1000 вызовов |
| 3 | **FTL JIT** | Медленно | Очень быстро | ~10000 вызовов |

### Deoptimization

Если JIT сделал оптимистичное предположение (например, `x` всегда число), а оно оказалось неверным — происходит **deoptimization**: откат к менее оптимизированному уровню.

```javascript
function add(a, b) {
  return a + b;
}

// JIT видит: a и b всегда числа → компилирует как числовое сложение
add(1, 2);     // числа → быстрый путь
add(3, 4);     // числа → быстрый путь

add("hello", "world"); // строки! → deopt → перекомпиляция с учётом строк
```

### JIT на iOS

**Важный нюанс**: iOS запрещает создание **writable + executable** memory pages для сторонних приложений. Однако **системный JSC** имеет специальное разрешение от Apple (entitlement), поэтому JIT работает. Это одна из причин, почему Hermes не использует JIT — он не является системным компонентом iOS.

## 4. JSC в истории React Native

### Хронология

```
2015 — RN запущен с JSC как единственным движком
2019 — Meta создаёт Hermes, оптимизированный для мобильных
0.60 — Hermes доступен как opt-in для Android
0.64 — Hermes доступен для iOS
0.70 — Hermes становится дефолтным движком (JSC opt-in)
0.81 — JSC удалён из core React Native
0.82 — Bridge полностью удалён, New Architecture обязательна
```

### Как JSC работал (старая архитектура)

```
JS Thread (JSC)                 Bridge                    Native Thread
     │                            │                            │
     │  JSC выполняет JS код      │                            │
     │  React рендерит vDOM       │                            │
     │                            │                            │
     │  NativeModules.Camera      │                            │
     │    .takePicture()          │                            │
     │ ──── JSON.stringify() ───▶ │                            │
     │                            │ ──── JSON.parse() ───────▶ │
     │                            │                     Camera. │
     │                            │                  takePicture│
     │                            │ ◀─── JSON.stringify() ──── │
     │ ◀─── JSON.parse() ──────  │                            │
     │  callback(result)          │                            │
```

### Почему JSC проиграл Hermes в React Native

1. **Холодный старт**: JIT-движок должен распарсить и начать интерпретировать весь JS bundle при запуске — сотни миллисекунд для больших приложений
2. **Потребление RAM**: JIT-кеш, профили, скомпилированный машинный код — десятки MB дополнительной памяти
3. **Размер на Android**: jsc-android добавляет ~3-5 MB к APK
4. **Версионирование на Android**: bundled JSC мог отставать от системного JSC на iOS

## 5. Сравнение с Hermes

### Полная сравнительная таблица

| Характеристика | JavaScriptCore | Hermes |
|---------------|----------------|--------|
| **Создатель** | Apple (WebKit) | Meta (для React Native) |
| **Компиляция** | JIT (runtime) | AOT (build-time) |
| **Холодный старт** | Медленный (parse + interpret) | **Быстрый** (загрузка bytecode) |
| **Пиковая скорость** | **Выше** (JIT → машинный код) | Ниже (интерпретатор) |
| **Потребление RAM** | Выше (JIT-кеш, профили) | **Ниже** (~30-50% меньше) |
| **Размер (iOS)** | **0 MB** (системный) | ~2-3 MB (bundled) |
| **Размер (Android)** | ~3-5 MB (bundled) | **~2-3 MB** (bundled) |
| **ECMAScript** | Полная поддержка (системная) | Почти полная |
| **Отладка** | Safari DevTools (iOS) | Chrome DevTools Protocol |
| **GC** | Generational + Concurrent | Generational (GenGC) |
| **Статус в RN** | **Удалён из core** (0.81+) | **Единственный** движок из коробки |
| **JSI совместимость** | Да (jsi::Runtime) | Да (jsi::Runtime) |

### TTI — реальные замеры Meta (Facebook Marketplace)

```
TTI с JSC:    ~4.3 сек
TTI с Hermes: ~2.0 сек  (↓ 53%)

RAM с JSC:    ~185 MB
RAM с Hermes: ~136 MB   (↓ 27%)

APK с JSC:    ~41 MB
APK с Hermes: ~22 MB    (↓ 46%)
```

### Пиковая производительность

```
Тяжёлые вычисления (после прогрева JIT):
  JSC (FTL JIT):  ████████████████████ 100%   ← машинный код
  Hermes (interp): ████████████ 60%            ← байткод

Типичный UI код (без прогрева):
  JSC:             ████████████ 60%            ← ещё на LLInt/Baseline
  Hermes:          ████████████████ 80%        ← оптимизированный байткод сразу
```

## 6. Текущий статус (RN 0.81+)

### JSC удалён из core

С React Native 0.81 JSC **больше не поставляется** в составе React Native. Hermes — единственный JS-движок из коробки.

### Community-пакет

Если JSC всё ещё нужен, используй:

```bash
npm install @react-native-community/javascriptcore
```

**Ограничения community-пакета:**
- Поддерживает только RN 0.79+ с New Architecture
- Поддерживается сообществом, не Meta
- Может отставать от обновлений RN

### Когда JSC ещё может быть оправдан

- **CPU-intensive JS вычисления** — после прогрева JIT работает быстрее интерпретатора Hermes. Но лучше перенести такие задачи в нативный модуль
- **Полная ECMAScript совместимость** — если нужна фича, которую Hermes ещё не поддерживает (на практике разница минимальна)

### Рекомендация

Используй **Hermes**. JSC в контексте React Native — это legacy. Meta, Expo и community единогласно двигаются к Hermes как единственному движку. Hermes V1 (экспериментальный) улучшит производительность ещё больше.

### Проверка текущего движка

```javascript
const isHermes = () => !!global.HermesInternal;

if (isHermes()) {
  console.log('Hermes');
} else {
  console.log('JSC или другой движок');
}
```
