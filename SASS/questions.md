1. Что такое Sass и чем синтаксис SCSS отличается от него?
	- Sass - CSS-препроцессор, который добавляет переменные, вложенность, миксины, функции, условия, циклы, модули и другие возможности, недоступные в обычном CSS.
	- SCSS - один из синтаксисов Sass с синтаксисом, совместимым с CSS (`{}` и `;`).
2. Чем Sass/SCSS отличается от обычного CSS?
	- Sass Добавляет такие возможности как:
		1. Переменные ($var) с !default и !global.
		2. Вложенность селекторов и &.
		3. Миксины (@mixin, @include) с аргументами и @content.
		4. Наследование (@extend, %placeholder).
		5. Функции (@function) и встроенные (darken, lighten, mix, adjust-color, и др.).
		6. Списки и карты (list, map) с функциями (nth, length, map-get, map-merge).
		7. Модули и импорт (@use, @forward, устаревший @import).
		8. Вычисления и арифметика (числа, единицы, цвета, строки).
		9. Управляющие конструкции (@if, @else, @for, @each, @while).
3. Какие преимущества использования SCSS?
	1. Модульность и переиспользуемость: переменные, миксины и функции уменьшают дублирование кода
	2. Вложенность: структура кода отражает DOM
	3. Поддержка архитектуры и масштабируемость: модули, карты, циклы, условия позволяют строить крупные проекты с 7-1 структурой
4. Как в экосистеме Sass компилировать SCSS в CSS и какими инструментами?
	- Dart Sass (`sass`): `npx sass input.scss output.css`.
	- В сборщиках (Vite/Webpack) под капотом - Dart Sass.
5. Как в SCSS объявляются и используются переменные?
	- Переменные объявляются через `$`:
	```sass
	$primary-color: #3498db;
	$base-padding: 16px;
	```
6. Можно ли в SCSS использовать переменные в селекторах и имёнах классов?
	- Да, через интерполяцию
	 ```scss
	 $state: "active";
	.button-#{$state} {...};
	 ```
7. Как в SCSS работают глобальные и локальные переменные?
	- Локальные - объявленные внутри миксина, функции или блока `{}`: видны только внутри этого блока.
	- Глобальные в модуле - объявленные в файле-модуле (вне функций/миксинов): доступны внутри этого же модуля напрямую и из других файлов (через namespace модуля (`module.$var`) после `@use`).
	- Переопределять значения из другого файла можно только при подключении: `@use 'module' with ($var: value)` и только если переменная в модуле помечена `!default`.
8. Что в SCSS происходит при переопределении переменной?
	1. Если переменная объявлена с `!default`, она примет новое значение только если оно ещё не задано.
	2. Без `!default` переменные модулей нельзя переопределить через `with` при использовании `@use`; их значение остаётся фиксированным.
	3. Локальная переменная: не влияет на модуль, модульная переменная остаётся прежней.
	4. Переменные SCSS можно повторно присваивать в том же скоупе.
9. Что делают `!default` и `!global` в SCSS при работе с переменными?
	- `!default` - задаёт значение переменной, только если оно ещё не определено; позволяет переопределить её извне через `@use ... with`.
	- `!global` - расширяет область присваивания до всего текущего модуля (файла).
10. Как в SCSS работает вложенность правил?
	- Вложенность правил в SCSS позволяет писать селекторы внутри других селекторов, отражая структуру DOM. Внутренние селекторы компилируются в полные CSS-селекторы, комбинируя родительский путь с потомком.
11. Что делает `&` в SCSS и как его использовать?
	1. `&` представляет родительский селектор на текущем уровне вложенности.
	2. Можно использовать для создания псевдоклассов (`&:hover`), BEM-суффиксов (`&__element`, `&--modifier`), контекстных селекторов (`[dir=rtl] &`).
	3. В SassScript `&` возвращает текущий селектор как список списков. Вне правил стилей `&` равен `null`.
12. Почему чрезмерная вложенность в SCSS считается антипаттерном?
	1. Увеличивает специфичность селекторов
	2. Глубокие и сложные селекторы увеличивают количество сравнений при рендере и repaint
	3. Рекомендуется не более 3 уровней вложенности (Sass Guidelines)
13. Что такое `@mixin` и `@include` в SCSS?
	1. `@mixin` - это способ объявить набор стилей, который можно многократно переиспользовать.
	2. `@include` вставляет этот набор стилей в нужный селектор.
14. Как в SCSS передавать аргументы в миксины (включая значения по умолчанию)?
	- Аргументы объявляются при создании миксина с возможностью значений по умолчанию. При вставке миксина через `@include` значения аргументов передаются в круглых скобках, позиционно или по имени.

	```scss
	@mixin button($bg-color: blue, $text-color: white, $padding: 10px) {
	  background-color: $bg-color;
	  color: $text-color;
	  padding: $padding;
	}

	.btn-primary {
	  @include button(red, white, 15px); // позиционно
	  @include button($text-color: black, $bg-color: gray); // по имени
	  @include button; // все значения по умолчанию
	}
	```
15. Когда в SCSS использовать `@mixin`, а когда `@extend`?
	1. `@mixin`, когда нужен повторно используемый набор стилей с возможностью передачи аргументов, медиа-запросами или сложной вложенностью. При каждом использовании содержимое миксина копируется в итоговый CSS.
	2. `@extend`, когда нужно наследовать стили существующего селектора без дублирования правил, но оно работает только с простыми свойствами и селекторами. Стили наследуются, а не копируются.
	3. Sass Guidelines рекомендуют предпочитать `@mixin` -- `@extend` может привести к непредсказуемому росту селекторов.
16. Как `@mixin` влияет на размер итогового CSS в SCSS?
	- `@mixin` влияет на размер итогового CSS тем, что при каждом использовании миксина его содержимое копируется в итоговый CSS в отличии от `@extend` где идет наследование.
17. Как в SCSS работает `@extend`?
	- `@extend` позволяет одному селектору наследовать стили другого селектора или placeholder. В итоговом CSS это приводит к объединению селекторов, что уменьшает размер файла, но может порождать длинные и хрупкие цепочки.
	```scss
	%toolbelt {...}
	.error{...}
	.btn-primary {
	  @extend %toolbelt;
	  @extend %error;
	}
	```
18. Что такое placeholder-селекторы (`%placeholder`) в SCSS и зачем они нужны?
	- Placeholder-селекторы (`%placeholder`) в SCSS - это специальные селекторы, которые не генерируют CSS напрямую, а используются только для наследования через `@extend`. Они нужны, чтобы избегать дублирования кода и не засорять итоговый CSS лишними классами.
19. Как в SCSS создать placeholder-селектор?
	- Placeholder-селектор создаётся через знак `%` перед именем. Приватные плейсхолдеры (начинаются с `-` или `_`) доступны только в пределах своего файла.
	```scss
	%toolbelt {...}
	.btn-primary {
	  @extend %toolbelt;
	}
	```
20. Что такое функции в SCSS и для чего они нужны?
	- Функции в SCSS - это блоки кода, которые принимают аргументы, выполняют вычисления или трансформации и возвращают значение. Функции должны быть чистыми (без побочных эффектов). Для побочных эффектов используйте миксины.

	```scss
	@use "sass:math";
	@function rem($px) {
	  @return math.div($px, 16px) * 1rem;
	}

	.text {
	  font-size: rem(24px);
	}
	```
21. Как объявлять функции через `@function` в SCSS?
	- Функции объявляются через `@function`, принимают аргументы и используют `@return` для возврата значения:

	```scss
	@function calculate-width($base, $multiplier: 2) {
	  @return $base * $multiplier;
	}

	.container {
	  width: calculate-width(100px, 3);
	}
	```
22. Какие встроенные модули существуют в SCSS?
	- Рекомендуется модульный импорт: `@use 'sass:color'`, `@use 'sass:math'`, `@use 'sass:string'`, `@use 'sass:list'`, `@use 'sass:map'`, `@use 'sass:selector'`, `@use 'sass:meta'`.
	- Многие старые глобальные функции имеют модульные аналоги (`darken()` -> `color.adjust()`, `lighten()` -> `color.scale()`).
23. Что такое списки (`list`) и карты (`map`) в SCSS?
	- Списки (`list`) - упорядоченные наборы значений, разделённые пробелами, запятыми или слэшами. Неизменяемы -- все функции возвращают новые списки.
	- Карты (`map`) - ассоциативные массивы ключ-значение. Поддерживают вложенность (Dart Sass 1.27.0+: `map.get($map, $key1, $key2)`). Тоже неизменяемы.

	```scss
	@use "sass:map";
	$colors: red, green, blue;
	$theme: (
	  "primary": #007bff,
	  "secondary": #6c757d
	);
	$primary-color: map.get($theme, "primary"); // #007bff
	```
24. Как в SCSS выполнять арифметику и операции с единицами измерения?
	- Поддерживаются `+`, `-`, `*`, `%`. Деление `/` устарело -- используйте `math.div()`.
	- Совместимые единицы автоматически конвертируются: `1in + 6px` = `102px`.
	- Несовместимые единицы вызывают ошибку: `1in + 1s` -- Error.
	- Безразмерные числа совместимы с любыми единицами.

25. Что такое `@use`, `@forward`, `@import` в Sass?
	- `@use` - современный способ подключать Sass-модули с namespace и однократной загрузкой.
	- `@forward` - проброс содержимого одного модуля через другой, создавая публичный интерфейс. Поддерживает `show`, `hide`, `as prefix-*`.
	- `@import` - устаревший способ (будет удален в Sass 3.0). Глобальный скоуп, повторная загрузка.
26. Почему `@import` в Sass устарел и чем его заменить?
	- `@import` устарел из-за: глобального скоупа, конфликтов имен, повторного выполнения файлов, отсутствия приватности, непредсказуемого `@extend`. Замена: `@use` и `@forward`. Инструмент миграции: `npx sass-migrator module --migrate-deps input.scss`.
27. Как в Sass использовать namespace при `@use`?
	- Namespace создаётся автоматически по имени файла или задаётся через `as`. Подстановка в глобальный скоуп через `as *` возможна, но нежелательна.
	```scss
	@use "src/corners" as c;       // Кастомное
	@use "src/corners" as *;       // Без namespace (осторожно!)
	```
28. Как в SCSS работают `@if`, `@else`, `@for`, `@each`, `@while`?
	- `@if` / `@else` - условные ветвления. Truthiness: только `false` и `null` ложны. `0`, `""`, `()` -- истинны!
	- `@for` - числовой цикл. `through` включает границу, `to` исключает.
	- `@each` - перебор списков и карт с деструктуризацией.
	- `@while` - цикл «пока истинно». Предпочтительны `@for`/`@each`.
29. Как в SCSS использовать `@content` внутри миксинов?
	- `@content` позволяет вставлять блок кода при вызове миксина. Блоки контента имеют лексическую область видимости -- видят переменные вызывающего кода, не миксина.
	- С Dart Sass 1.15.0+ можно передавать аргументы в `@content` через `using`.

	```scss
	@mixin media($types...) {
	  @each $type in $types {
	    @media #{$type} {
	      @content($type);
	    }
	  }
	}
	@include media(screen, print) using ($type) {
	  h1 { font-size: 40px; }
	}
	```
30. Что такое 7-1 архитектура SCSS?
	- Соглашение сообщества: 7 папок для разных типов стилей и один главный файл `main.scss`. Частичные файлы оформляют как partials с префиксом `_` и подключают через `@use`.

	```
	scss/
	├── abstracts/    # переменные, миксины, функции
	├── base/         # reset, типографика
	├── components/   # UI-компоненты
	├── layout/       # макет, сетка
	├── pages/        # стили страниц
	├── themes/       # темы
	├── vendors/      # сторонние стили
	└── main.scss
	```
31. Из каких папок состоит архитектура 7-1 в SCSS?
	1. abstracts/ - переменные, миксины, функции, плейсхолдеры. Не генерирует CSS при отдельной компиляции.
	2. base/ - reset, типографика, общие элементы.
	3. components/ - мелкие UI-компоненты.
	4. layout/ - макет страницы: header, footer, сетка.
	5. pages/ - стили конкретных страниц.
	6. themes/ - темы оформления.
	7. vendors/ - сторонние библиотеки.
	8. main.scss - основной файл, собирающий все модули через `@use`.
32. Как в SCSS избегать дублирования и избыточной специфичности?
	1. Миксины, функции, переменные, карты и плейсхолдеры вместо повторяющихся правил
	2. Минимизация вложенности (не более 3 уровней)
	3. Модульная архитектура с `@use`/`@forward`
	4. BEM-методология снижает потребность во вложенности

33. Как уменьшить размер итогового CSS при использовании SCSS?
	1. Переиспользование миксинов и плейсхолдеров
	2. `--style=compressed` для минификации
	3. Удаление неиспользуемых стилей (PurgeCSS)
	4. Использование `%placeholder` вместо расширения обычных классов

34. Какие виды комментариев есть в SCSS?
	1. `//` - строчный комментарий, не попадает в итоговый CSS.
	2. `/* ... */` - блочный комментарий, попадает в CSS (в `compressed` удаляется).
	3. `/*! ... */` - важный комментарий, не удаляется даже в compressed.
	4. `///` - документационный комментарий SassDoc.
35. Для чего используется `@at-root` в SCSS?
	1. Выводит правила на корневой уровень, игнорируя текущую вложенность.
	2. Поддерживает `(without: media)` и `(with: rule)` для контроля at-правил.
36. Что делают `@error`, `@warn`, `@debug`?
	1. `@error` - бросает ошибку и останавливает компиляцию.
	2. `@warn` - пишет предупреждение, компиляция продолжается. Подавляется через `--quiet`.
	3. `@debug` - выводит значение выражения с файлом и строкой. Принимает любой тип.
37. Как расширенно использовать `@forward` (show/hide/as)?
	1. `@forward 'module' show $var, mixin-name;` - показать только перечисленное.
	2. `@forward 'module' hide mixin-name;` - скрыть часть API.
	3. `@forward 'module' as theme-*;` - добавить префикс ко всем членам.
	4. `@forward 'module' with ($var: value !default);` - промежуточная конфигурация.
38. Какие операторы поддерживает SCSS?
	1. Равенства/отношения: `==`, `!=`, `<`, `<=`, `>`, `>=` (с учетом типов/единиц).
	2. Числовые: `+`, `-`, `*`, `%`; деление `/` устарело -- `math.div()`.
	3. Строковые: конкатенация через `+` (если любой операнд в кавычках -- результат в кавычках).
	4. Логические: `and`, `or`, `not`. Порядок: `not` > `and` > `or`.
39. Как работает интерполяция `#{}` в SCSS и где её можно использовать?
	- Интерполяция `#{}` встраивает SassScript-выражения в CSS. Можно использовать в: селекторах, именах свойств, значениях Custom Properties, at-правилах, строках, комментариях.
	- Не используйте для значений свойств (`color: $var`, не `color: #{$var}`) и с числами (`$width * 1px`, не `#{$width}px` -- последнее создает строку).
40. Какие типы значений существуют в SCSS?
	1. **Numbers** -- числа с единицами или без: `16px`, `0.5`, `5.2e3`
	2. **Strings** -- в кавычках (`"hello"`) и без (`bold`). Внутренне одинаковы.
	3. **Colors** -- все CSS цветовые пространства: rgb, hsl, hwb, lab, lch, oklch и др.
	4. **Lists** -- последовательности через запятые, пробелы или слэши. Неизменяемы.
	5. **Maps** -- пары ключ-значение. Поддерживают вложенность. Неизменяемы.
	6. **Booleans** -- `true` и `false`
	7. **null** -- отсутствие значения, пропускается в CSS-выводе
	8. **Calculations** -- `calc()`, `clamp()`, `min()`, `max()`. Sass упрощает по возможности.
	9. **Functions** -- функции как значения через `meta.get-function()`
41. Что такое truthiness в SCSS и чем отличается от JavaScript?
	- В Sass только `false` и `null` ложны. Все остальное -- включая `0`, `""` (пустая строка) и `()` (пустой список) -- **истинно**. В JavaScript `0`, `""`, `null`, `undefined`, `NaN` -- все falsy.
42. Чем отличаются `color.adjust()`, `color.change()` и `color.scale()` в SCSS?
	- `adjust` -- прибавляет/вычитает фиксированное количество к каналу: `color.adjust($c, $lightness: -20%)` (lightness 60% -> 40%)
	- `change` -- устанавливает абсолютное значение канала: `color.change($c, $red: 100)`
	- `scale` -- масштабирует % от текущей позиции к max/min: `color.scale($c, $lightness: -20%)` (lightness 60% -> 48%, т.е. 20% от пути к 0)
	- `color.scale()` обычно более интуитивен и рекомендуется.
43. Что такое partials и индексные файлы в SCSS?
	- **Partials** -- файлы с префиксом `_` (например, `_variables.scss`), не компилируются в отдельные CSS-файлы. При `@use` подчеркивание опускается.
	- **Индексные файлы** -- `_index.scss` в папке автоматически загружается при `@use 'folder'`. Обычно содержит `@forward` для всех файлов папки.
44. Как работает sass:meta модуль для интроспекции?
	- `meta.type-of($value)` -- тип значения (number, string, color, list, map и др.)
	- `meta.variable-exists($name)` / `meta.function-exists($name)` / `meta.mixin-exists($name)` -- проверка существования
	- `meta.get-function($name)` / `meta.call($fn, $args...)` -- функции как first-class values
	- `meta.module-variables($module)` / `meta.module-functions($module)` -- карты содержимого модуля
	- `meta.load-css($url, $with)` -- динамическая загрузка CSS
45. Какие основные критические изменения ожидаются в Sass 3.0?
	- Удаление `@import` (использовать `@use`/`@forward`)
	- Удаление `/` как оператора деления (использовать `math.div()`)
	- Удаление глобальных цветовых функций (`darken()`, `lighten()` -> `color.adjust()`, `color.scale()`)
	- Удаление глобальных встроенных функций (использовать модули `sass:*`)
	- Инструмент миграции: `npx sass-migrator module --migrate-deps input.scss`
46. Какой порядок объявлений рекомендуется внутри SCSS-правила?
	1. `@extend`
	2. `@include` (без `@content`)
	3. Обычные свойства
	4. `@include` с `@content` (медиа-запросы)
	5. Вложенные правила
47. Как в SCSS работает вложенность свойств (property nesting)?
	- Свойства с общим префиксом можно вкладывать. Можно комбинировать сокращенное значение с вложенными:
	```scss
	.enlarge {
	  transition: {
	    property: font-size;
	    duration: 4s;
	    delay: 2s;
	  }
	}
	// transition-property: font-size; transition-duration: 4s; transition-delay: 2s;
	```
48. Как в SCSS использовать произвольные аргументы в миксинах и функциях?
	- `$args...` собирает все дополнительные позиционные аргументы в список. `meta.keywords($args)` преобразует именованные аргументы в карту. Можно "развернуть" список/карту через `$list...` при вызове.
	```scss
	@mixin syntax-colors($args...) {
	  @each $name, $color in meta.keywords($args) {
	    pre span.stx-#{$name} { color: $color; }
	  }
	}
	@include syntax-colors($string: #080, $comment: #800);
	```
49. Как правильно взаимодействовать с CSS Custom Properties из SCSS?
	- CSS Custom Properties парсятся как CSS -- все токены передаются как есть. Для вставки Sass-значений используйте интерполяцию `#{}`:
	```scss
	$primary: #81899b;
	:root {
	  --primary: #{$primary};        // Работает: --primary: #81899b
	  --broken: $primary;            // Не работает: буквально "$primary"
	}
	```
50. Что такое вычисления (Calculations) в SCSS и как с ними работать?
	- `calc()`, `clamp()`, `min()`, `max()` парсятся как вычисления. Sass упрощает совместимые единицы. Нельзя использовать обычные операторы с вычислениями -- пишите внутри `calc()`:
	```scss
	$width: calc(100% + 10px);
	// $width * 2 -- ошибка!
	calc($width * 2) // calc((100% + 10px) * 2) -- правильно
	```
