# Модульная система (@use, @forward, @import)

> Модульная система Sass позволяет разбивать стили на файлы, контролировать видимость
> и избегать глобальных конфликтов имен. `@use` и `@forward` -- современная замена `@import`.

## 1. @use

`@use` загружает миксины, функции и переменные из других файлов Sass и объединяет CSS из нескольких файлов. Загруженные файлы называются "модулями".

**Совместимость:** Только Dart Sass (с 1.23.0). В LibSass и Ruby Sass используйте `@import`.

**Правило размещения:** `@use` должен быть до любых правил, кроме `@forward`. Переменные для конфигурации могут быть объявлены до `@use`.

### Доступ к членам модуля

Члены модуля (переменные, функции, миксины) доступны через пространство имен: `<namespace>.<member>`. По умолчанию пространство имен -- последний компонент URL без расширения.

```scss
// src/_corners.scss
$radius: 3px;
@mixin rounded { border-radius: $radius; }

// style.scss
@use "src/corners";

.button {
  @include corners.rounded;
  padding: 5px + corners.$radius;
}
```

### Выбор пространства имен

```scss
@use "src/corners" as c;       // Кастомное пространство имен
@use "src/corners" as *;       // Без пространства имен (осторожно: конфликты!)
```

`as *` рекомендуется только для файлов, которые вы контролируете.

### Приватные члены

Члены, начинающиеся с `-` или `_`, приватны и недоступны извне:

```scss
// _helpers.scss
$-radius: 3px;            // Приватная переменная
@mixin _hidden { ... }    // Приватный миксин
```

### Конфигурация модулей

Модули могут определять конфигурируемые переменные через `!default`. Переопределение при подключении:

```scss
// _library.scss
$black: #000 !default;
$border-radius: 0.25rem !default;
$box-shadow: 0 0.5rem 1rem rgba($black, 0.15) !default;

code {
  border-radius: $border-radius;
  box-shadow: $box-shadow;
}

// style.scss
@use 'library' with (
  $black: #222,
  $border-radius: 0.1rem
);
```

**Важно:** `@use ... with` можно использовать только один раз для каждого модуля -- при первой загрузке.

Порядок: `as` до `with`: `@use ... as ... with ...`

### Переназначение переменных модуля

После загрузки модуля можно переназначить его переменные:

```scss
@use 'library';
library.$color: blue;
```

### Нахождение модуля

- Sass автоматически разрешает расширения файлов (`.scss`, `.sass`, `.css`)
- Используйте только прямые слэши `/`, даже на Windows
- URL чувствительны к регистру
- Частичные файлы (partials): начинаются с `_`, при импорте подчеркивание опускается
- Индексные файлы: `_index.scss` в папке загружается при обращении к папке

### Загрузка CSS

Sass может загружать `.css` файлы. Они не могут предоставлять переменные, функции или миксины Sass.

### pkg: URLs

Схема `pkg:` для загрузки стилей из пакетных менеджеров (Dart Sass 1.71.0+). Node.js Package Importer включается через `--pkg-importer=node`.

## 2. @forward

`@forward` загружает модуль и делает его публичные члены доступными для потребителей вашего модуля. Ваш модуль становится "транзитным":

```scss
// src/_list.scss
@mixin reset {
  margin: 0;
  padding: 0;
  list-style: none;
}

// bootstrap.scss
@forward "src/list" as list-*;

// styles.scss
@use "bootstrap";
li { @include bootstrap.list-reset; }
```

### Добавление префикса

`@forward "<url>" as <prefix>-*` добавляет префикс ко всем переправляемым членам.

### Контроль видимости

```scss
@forward "<url>" hide $var, mixin-name;   // Скрыть конкретные члены
@forward "<url>" show $var, mixin-name;   // Показать только указанные
```

### Конфигурация при переправке

```scss
@forward 'module' with ($variable: value !default);
```

Создает промежуточный слой конфигурации: нижестоящие пользователи все еще могут переопределять настройки.

**Рекомендация:** При использовании `@forward` и `@use` для одного модуля, `@forward` должен быть первым.

## 3. @import (устарел)

> **Устарел в Dart Sass 1.80.0, будет удален в 3.0.0. Используйте `@use`.**

`@import` расширяет CSS-правило импорта, загружая Sass и CSS файлы. В отличие от CSS, все происходит во время компиляции.

### Проблемы @import

- Все переменные, миксины, функции становятся глобальными
- Библиотеки вынуждены добавлять префиксы для избежания конфликтов
- `@extend` работает глобально и непредсказуемо
- Каждый файл выполняется и генерирует CSS при каждом импорте
- Нет механизма приватности

```scss
@import 'foundation/code', 'foundation/lists';
```

### Вложенный импорт

```scss
.theme-sample {
  @import "theme";
}
// CSS из theme оборачивается в .theme-sample
```

### Import-Only Files

Файлы `<name>.import.scss` загружаются только при `@import`, а не при `@use`:

```scss
// _reset.scss -- для @use
@mixin list() { ul { margin: 0; padding: 0; list-style: none; } }

// _reset.import.scss -- для @import
@forward "reset" as reset-*;
```

### Простой CSS @import

Sass передает в CSS без обработки импорты с:
- URL, оканчивающимися на `.css`
- URL, начинающимися с `http://` или `https://`
- URL в `url()`
- Импорты с media queries

## 4. Partials и индексные файлы

### Partials (частичные файлы)

Файлы, начинающиеся с `_`, не компилируются в отдельные CSS-файлы:

```
styles/
├── _variables.scss    // partial -- не компилируется отдельно
├── _mixins.scss       // partial
├── _base.scss         // partial
└── main.scss          // компилируется в main.css
```

```scss
// main.scss
@use 'variables';
@use 'mixins';
@use 'base';
```

### Индексные файлы

`_index.scss` в папке автоматически загружается при обращении к папке:

```
styles/
├── components/
│   ├── _index.scss    // @forward 'button'; @forward 'card';
│   ├── _button.scss
│   └── _card.scss
└── main.scss
```

```scss
// main.scss
@use 'components';  // Загружает components/_index.scss
```

## 5. Сравнение @use vs @import

| @use | @import |
|---|---|
| Область видимости ограничена текущим файлом | Все становится глобальным |
| Каждый файл загружается один раз | Файл выполняется каждый раз при импорте |
| Должен быть в начале файла | Может быть вложенным |
| Один URL на правило | Может содержать несколько URL |
| URL всегда в кавычках | Кавычки необязательны в indented syntax |
| Пространства имен | Все в глобальной области |
| Приватность (`-` / `_` префикс) | Нет приватности |
| Конфигурация через `with` | Нет механизма конфигурации |
