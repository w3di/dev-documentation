## 1. Синтаксис и форматирование

### Основные правила

- **SCSS** предпочтительнее Indented Syntax -- ближе к CSS, легче для команды
- **2 пробела** для отступов (не табы)
- **80 символов** максимальная ширина строки
- Каждое объявление свойства на **отдельной строке**
- **Пустая строка** между вложенными правилами
- **Пробел перед `{`** и `{` на той же строке
- **`}` на отдельной строке**

### Порядок объявлений внутри правила

```scss
.selector {
  // 1. @extend
  @extend %placeholder;

  // 2. @include (без @content)
  @include font-size(14px);

  // 3. Обычные свойства (в логическом порядке, не по алфавиту)
  display: block;
  overflow: hidden;
  padding: 0 1em;
  color: $color-text;
  background: $color-bg;

  // 4. @include с @content
  @include respond-to("md") {
    padding: 0 2em;
  }

  // 5. Вложенные правила
  &__element {
    // ...
  }
}
```

### Форматирование чисел

```scss
// Хорошо
.foo { padding: 2em; opacity: 0.5; }

// Плохо
.foo { padding: 2.0em; opacity: .5; }
```

- Всегда ведущий **ноль** перед десятичной точкой: `0.5`, не `.5`
- Не ставьте завершающие нули: `2em`, не `2.0em`
- Не добавляйте единицы к нулю: `0`, не `0px`

### Строки

- Всегда в **одинарных кавычках** (единообразие)
- URL тоже в кавычках: `background-image: url('/images/kittens.jpg')`

### Списки

```scss
// Короткие -- на одной строке
$font-stack: ('Helvetica', 'Arial', sans-serif);

// Длинные -- многострочные с запятыми в конце
$breakpoints: (
  'small': 767px,
  'medium': 992px,
  'large': 1200px,
);
```

Всегда используйте **завершающую запятую** в многострочных списках и картах.

## 2. Именование

### Общие правила

- **kebab-case** для всего: переменных, миксинов, функций, плейсхолдеров
- Имена должны быть **осмысленными и на английском**
- Не используйте верблюжий регистр: `$camelCase` -> `$kebab-case`

### Соглашения

```scss
// Переменные -- описательные имена
$color-primary: #007bff;
$font-size-base: 16px;
$spacing-unit: 8px;

// Миксины -- глаголы или действия
@mixin respond-to($breakpoint) { ... }
@mixin set-font($size, $weight) { ... }

// Плейсхолдеры -- существительные
%button-base { ... }
%clearfix { ... }

// Приватные -- начинаются с _ или -
$_internal-spacing: 4px;
@mixin _helper() { ... }
```

### Пространства имен для компонентов

```scss
// Компонент "card"
$card-padding: 1rem;
$card-border-radius: 4px;
@mixin card-shadow($level: 1) { ... }
```

## 4. Архитектура: 7-1 паттерн

7 папок + 1 файл-точка входа. Масштабируемая структура для средних и крупных проектов.

```
sass/
├── abstracts/          # Инструменты, не генерирующие CSS
│   ├── _variables.scss     # Все переменные
│   ├── _functions.scss     # Все функции
│   ├── _mixins.scss        # Все миксины
│   └── _index.scss         # @forward всех файлов
│
├── vendors/            # Стили сторонних библиотек
│   ├── _normalize.scss
│   └── _index.scss
│
├── base/               # Базовые стили (reset, типографика)
│   ├── _reset.scss
│   ├── _typography.scss
│   ├── _animations.scss
│   └── _index.scss
│
├── layout/             # Макет (сетка, шапка, подвал)
│   ├── _grid.scss
│   ├── _header.scss
│   ├── _footer.scss
│   ├── _sidebar.scss
│   └── _index.scss
│
├── components/         # UI-компоненты (кнопки, карточки)
│   ├── _button.scss
│   ├── _card.scss
│   ├── _modal.scss
│   └── _index.scss
│
├── pages/              # Стили конкретных страниц
│   ├── _home.scss
│   ├── _about.scss
│   └── _index.scss
│
├── themes/             # Темы (светлая, темная)
│   ├── _default.scss
│   ├── _dark.scss
│   └── _index.scss
│
└── main.scss           # Точка входа -- только @use
```

### main.scss

```scss
@use 'abstracts';
@use 'vendors';
@use 'base';
@use 'layout';
@use 'components';
@use 'pages';
@use 'themes';
```

### _index.scss (пример для components)

```scss
@forward 'button';
@forward 'card';
@forward 'modal';
```

### Упрощенная структура для малых проектов

```
sass/
├── abstracts/
│   ├── _variables.scss
│   └── _mixins.scss
├── base/
│   └── _base.scss
├── components/
│   ├── _button.scss
│   └── _form.scss
├── layout/
│   └── _layout.scss
└── main.scss
```

### Правила организации

- **Один компонент -- один файл**
- **abstracts/** не должна генерировать ни одной строки CSS при компиляции отдельно
- Порядок импортов важен: abstracts -> vendors -> base -> layout -> components -> pages -> themes
- Используйте `_index.scss` в каждой папке для централизованного `@forward`

## 5. Переменные: рекомендации

### Организация

```scss
// _variables.scss -- группируйте по назначению

// Цвета
$color-primary: #007bff;
$color-secondary: #6c757d;
$color-success: #28a745;
$color-danger: #dc3545;
$color-text: #212529;
$color-bg: #ffffff;

// Типографика
$font-family-base: ('Roboto', 'Helvetica Neue', sans-serif);
$font-family-mono: ('Fira Code', monospace);
$font-size-base: 1rem;
$line-height-base: 1.5;

// Отступы
$spacing-unit: 8px;

// Брейкпоинты
$breakpoints: (
  'sm': 576px,
  'md': 768px,
  'lg': 992px,
  'xl': 1200px,
);

// z-index
$z-layers: (
  'modal': 100,
  'dropdown': 50,
  'header': 30,
  'default': 1,
);
```

### Рекомендации

- `!default` для всех переменных в библиотеках
- Группируйте переменные по назначению, не по типу
- Используйте карты для связанных значений (брейкпоинты, цвета тем, z-index)
- Избегайте магических чисел -- выносите в именованные переменные
- Не создавайте переменную для значения, используемого один раз

## 6. Миксины: рекомендации

### Когда создавать миксин

- Блок стилей повторяется 2+ раз
- Нужна параметризация
- Нужен `@content` (обертки для медиа-запросов)

### Когда НЕ создавать миксин

- Для одного свойства без параметров -- просто напишите свойство
- Если нет параметров и не нужен `@content` -- рассмотрите `@extend` с `%placeholder`

### Рекомендуемые миксины

```scss
// Медиа-запросы
@mixin respond-to($breakpoint) {
  $value: map.get($breakpoints, $breakpoint);
  @if not $value {
    @error "Unknown breakpoint: #{$breakpoint}";
  }
  @media (min-width: $value) { @content; }
}

// Текст с многоточием
@mixin truncate($lines: 1) {
  @if $lines == 1 {
    white-space: nowrap;
    overflow: hidden;
    text-overflow: ellipsis;
  } @else {
    display: -webkit-box;
    -webkit-line-clamp: $lines;
    -webkit-box-orient: vertical;
    overflow: hidden;
  }
}

// Визуально скрытый (для screen readers)
@mixin visually-hidden {
  position: absolute;
  width: 1px;
  height: 1px;
  padding: 0;
  margin: -1px;
  overflow: hidden;
  clip: rect(0, 0, 0, 0);
  white-space: nowrap;
  border: 0;
}
```

### Аргументы

- Не более 4-5 аргументов (иначе используйте карту)
- Всегда значения по умолчанию для необязательных
- Документируйте через SassDoc для публичных миксинов

## 7. @extend: рекомендации

> **Общая рекомендация: предпочитайте `@mixin` перед `@extend`.**

### Проблемы @extend

- Непредсказуемый рост селекторов
- Невозможность использования в `@media`
- Сложность отладки получившихся селекторов
- Может ухудшить gzip-сжатие (разбросанные стили хуже сжимаются, чем повторяющиеся)

### Если используете @extend

- Только с **плейсхолдерами `%`**, никогда с обычными классами
- Только в пределах одного файла/модуля
- Не расширяйте вложенные селекторы

```scss
// Хорошо
%button-base {
  display: inline-flex;
  padding: 8px 16px;
}
.btn { @extend %button-base; }

// Плохо
.btn { display: inline-flex; padding: 8px 16px; }
.btn-primary { @extend .btn; }  // Расширяет обычный класс
```

## 8. Вложенность: рекомендации

### Максимум 3 уровня

```scss
// Хорошо -- 2 уровня
.page-container {
  .content {
    .profile { ... }
  }
}

// Плохо -- 4+ уровня
.page-container {
  .content {
    .profile {
      .avatar {
        img { ... }
      }
    }
  }
}
```

### BEM снижает потребность во вложенности

```scss
.card {
  &__header { ... }
  &__body { ... }
  &__footer { ... }
  &--featured { ... }
}
// Результат: .card__header, .card__body, .card--featured
// Всё плоское, один уровень вложенности
```

### Когда вложенность допустима

- Псевдоклассы и псевдоэлементы: `&:hover`, `&::before`
- Контекстные модификаторы: `[dir=rtl] &`, `.dark-theme &`
- BEM-элементы и модификаторы: `&__element`, `&--modifier`

## 9. Условия и циклы: рекомендации

### @if

- Не тестируйте на `true/false` явно: `@if $value` вместо `@if $value == true`
- Используйте `@error` в ветке `@else` для невозможных случаев
- Помните: `0`, `""`, `()` истинны в Sass

### @each

- Предпочтительнее `@for` и `@while` для итерации по коллекциям
- Используйте деструктуризацию для карт и вложенных списков

### @for

- Используйте для числовых последовательностей (сетки, утилиты)
- Помните разницу `through` (включительно) vs `to` (исключительно)

### @while

- Используйте только когда количество итераций заранее неизвестно
- Убедитесь, что цикл **гарантированно завершится**

## 10. Предупреждения и ошибки: рекомендации

### @error

- Для невалидных аргументов
- Для критических ошибок конфигурации
- Включайте в сообщение допустимые значения

### @warn

- Для устаревших API
- Для неоптимальных значений
- Пользователь может подавить через `--quiet`

### @debug

- Только для разработки
- Удаляйте перед коммитом

| Инструмент | Описание |
|---|---|
| **SassDoc** | Генерация документации из `///` комментариев |

### Миграция с @import на @use

```bash
# Автоматический инструмент миграции
npx sass-migrator module --migrate-deps input.scss
```

Мигратор автоматически:
- Заменяет `@import` на `@use` / `@forward`
- Добавляет пространства имен
- Обновляет ссылки на встроенные функции (`darken()` -> `color.adjust()`)
