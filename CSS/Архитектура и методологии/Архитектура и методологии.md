## 1. BEM — Block, Element, Modifier

### Концепция

BEM (Block, Element, Modifier) — методология именования CSS-классов, разработанная в Яндексе. Основная цель — создать **предсказуемую**, **масштабируемую** и **поддерживаемую** систему CSS.

### Naming Convention

```
block__element--modifier
```

- **Block** — самостоятельный компонент, имеющий смысл сам по себе.
- **Element** — часть блока, не имеющая самостоятельного смысла. Отделяется **двойным подчёркиванием** `__`.
- **Modifier** — вариация блока или элемента. Отделяется **двойным дефисом** `--`.

```css
/* Block */
.card { }

/* Elements */
.card__header { }
.card__body { }
.card__footer { }
.card__title { }
.card__image { }

/* Modifiers */
.card--featured { }
.card--compact { }
.card__title--large { }
.card__image--rounded { }
```

```html
<article class="card card--featured">
  <div class="card__header">
    <h2 class="card__title card__title--large">Заголовок</h2>
  </div>
  <div class="card__body">
    <img class="card__image card__image--rounded" src="..." alt="">
    <p class="card__text">Текст карточки</p>
  </div>
  <div class="card__footer">
    <button class="card__button">Подробнее</button>
  </div>
</article>
```

### Правила BEM

1. **Нет вложенных элементов в именовании:** `card__header__title` — **неправильно**. Используйте `card__title`.

```css
/* Неправильно */
.card__header__title { }

/* Правильно */
.card__title { }
```

2. **Элемент принадлежит блоку, не другому элементу.** В CSS-селекторах не используйте вложенность:

```css
/* Неправильно — привязка к DOM-структуре */
.card .card__title { }
.card__header .card__title { }

/* Правильно — плоская структура */
.card__title { }
```

3. **Modifier не используется без блока/элемента:**

```html
<!-- Неправильно -->
<div class="card--featured">...</div>

<!-- Правильно -->
<div class="card card--featured">...</div>
```

### Mix — сочетание блоков

```html
<!-- Элемент одного блока является другим блоком -->
<nav class="nav">
  <a class="nav__link button" href="#">Ссылка-кнопка</a>
</nav>
```

### Преимущества BEM

| Преимущество | Описание |
|-------------|----------|
| Предсказуемость | По имени класса понятно, к какому компоненту он относится |
| Низкая специфичность | Все селекторы — одиночные классы (0, 1, 0) |
| Нет конфликтов | Имена изолированы контекстом блока |
| Переносимость | Компоненты легко переносить между проектами |
| Самодокументирование | HTML читается как описание структуры |

### Недостатки BEM

| Недостаток | Описание |
|-----------|----------|
| Длинные имена | `search-form__input--disabled` |
| Многословный HTML | Множество классов на элементе |
| Субъективность | Где граница между Block и Element? |
| Дисциплина | Требует строгого следования конвенции всей командой |

### Вариации BEM

```css
/* Оригинальный Yandex BEM */
.block__element_modifier_value { }

/* Harry Roberts' style (самая распространённая) */
.block__element--modifier { }

/* CamelCase BEM */
.BlockName__elementName--modifierName { }

/* SUIT CSS */
.BlockName-elementName--modifierName { }
```

## 2. OOCSS — Object-Oriented CSS

### Принципы

OOCSS (Object-Oriented CSS), предложенный Nicole Sullivan, основан на двух принципах:

#### Принцип 1: Separation of Structure and Skin

Разделение **структуры** (размеры, позиционирование) и **оформления** (цвета, тени, градиенты).

```css
/* Структура */
.media {
  display: flex;
  align-items: flex-start;
  gap: 1rem;
}

.media__image {
  flex-shrink: 0;
}

.media__body {
  flex: 1;
  min-width: 0;
}

/* Skin */
.skin-bordered {
  border: 1px solid #ddd;
  border-radius: 8px;
  padding: 1rem;
}

.skin-shadow {
  box-shadow: 0 2px 8px rgba(0,0,0,0.1);
  padding: 1rem;
}
```

```html
<!-- Один объект — разные скины -->
<div class="media skin-bordered">...</div>
<div class="media skin-shadow">...</div>
```

#### Принцип 2: Separation of Container and Content

Контент не должен зависеть от контейнера. Стили объекта не должны меняться в зависимости от того, где он размещён.

```css
/* Плохо — привязка к контейнеру */
.sidebar h3 {
  font-size: 0.9rem;
  color: #666;
}

.main-content h3 {
  font-size: 1.2rem;
  color: #333;
}

/* Хорошо — независимые объекты */
.heading-small {
  font-size: 0.9rem;
  color: #666;
}

.heading-medium {
  font-size: 1.2rem;
  color: #333;
}
```

### Media Object — каноничный пример OOCSS

```css
.media {
  display: flex;
  align-items: flex-start;
}

.media__img {
  margin-right: 1rem;
}

.media__img--rev {
  order: 1;
  margin-right: 0;
  margin-left: 1rem;
}

.media__body {
  flex: 1;
}
```

> **Историческая справка:** Media Object — один из самых повторяемых паттернов в вебе. Nicole Sullivan подсчитала, что Facebook использовал сотни вариаций этого паттерна. Выделение его в объект сократило CSS на тысячи строк.

## 3. SMACSS — Scalable and Modular Architecture for CSS

### Категории

SMACSS (произносится "smacks"), разработанный Jonathan Snook, делит CSS на пять категорий:

### Base — базовые стили

Стили для HTML-элементов без классов. Это ваш reset/normalize.

```css
/* Base */
*, *::before, *::after {
  box-sizing: border-box;
}

body {
  font-family: system-ui, sans-serif;
  line-height: 1.5;
  color: #333;
}

a {
  color: #3498db;
  text-decoration: none;
}

a:hover {
  text-decoration: underline;
}

img {
  max-width: 100%;
  height: auto;
  display: block;
}
```

### Layout — крупные структурные блоки

Правила layout определяют основные секции страницы. Префикс `l-`.

```css
.l-header {
  position: sticky;
  top: 0;
  z-index: 100;
}

.l-sidebar {
  width: 300px;
  flex-shrink: 0;
}

.l-main {
  flex: 1;
  min-width: 0;
}

.l-footer {
  margin-top: auto;
}

.l-grid {
  display: grid;
  grid-template-columns: repeat(auto-fill, minmax(300px, 1fr));
  gap: 1.5rem;
}
```

### Module — переиспользуемые компоненты

Основная часть CSS. Модули — это дискретные компоненты: карточки, навигация, модалки и т.д.

```css
/* Module: card */
.card { }
.card-header { }
.card-body { }
.card-footer { }

/* Module: nav */
.nav { }
.nav-item { }
.nav-link { }
```

> **Замечание:** В SMACSS дочерние элементы модуля именуются через **дефис**, а не двойное подчёркивание как в BEM.

### State — состояния

Описывают динамические изменения модулей. Префикс `is-`.

```css
.is-hidden { display: none !important; }
.is-visible { display: block !important; }
.is-active { }
.is-disabled {
  opacity: 0.5;
  pointer-events: none;
}
.is-loading {
  position: relative;
}
.is-collapsed { }
.is-expanded { }

/* State модуля */
.nav-item.is-active {
  border-bottom: 2px solid currentColor;
  font-weight: bold;
}
```

> **Замечание:** `!important` допустим для state-правил в SMACSS, поскольку состояния должны **гарантированно** переопределять модульные стили.

### Theme — темы

Переопределение цветов, шрифтов, фонов для тематизации.

```css
/* Default theme */
.card {
  background: white;
  color: #333;
  border: 1px solid #ddd;
}

/* Dark theme */
.theme-dark .card {
  background: #1a1a2e;
  color: #e0e0e0;
  border: 1px solid #333;
}
```

### Файловая структура SMACSS

```
styles/
├── base/
│   ├── _reset.css
│   ├── _typography.css
│   └── _base.css
├── layout/
│   ├── _header.css
│   ├── _sidebar.css
│   └── _grid.css
├── modules/
│   ├── _card.css
│   ├── _nav.css
│   ├── _modal.css
│   └── _button.css
├── state/
│   └── _state.css
├── theme/
│   ├── _default.css
│   └── _dark.css
└── main.css
```

## 4. ITCSS — Inverted Triangle CSS

### Концепция

ITCSS (Inverted Triangle CSS), предложенный Harry Roberts, организует CSS в виде **перевёрнутого треугольника** — от общего к частному, от низкой специфичности к высокой.

```
     ╱ Settings ╲        ← Самый широкий охват, самая низкая специфичность
    ╱   Tools    ╲
   ╱   Generic    ╲
  ╱   Elements     ╲
 ╱    Objects       ╲
╱    Components      ╲
╲     Utilities      ╱   ← Самый узкий охват, самая высокая специфичность
```

### Слои ITCSS

#### 1. Settings — переменные и конфигурация

```css
/* _settings.css */
:root {
  /* Colors */
  --color-primary: #3498db;
  --color-secondary: #2ecc71;
  --color-danger: #e74c3c;
  --color-warning: #f39c12;

  /* Typography */
  --font-family-base: system-ui, -apple-system, sans-serif;
  --font-family-heading: 'Inter', sans-serif;
  --font-size-base: 1rem;
  --line-height-base: 1.5;

  /* Spacing */
  --spacing-xs: 0.25rem;
  --spacing-sm: 0.5rem;
  --spacing-md: 1rem;
  --spacing-lg: 1.5rem;
  --spacing-xl: 2rem;

  /* Breakpoints (используются через media queries) */
  /* --bp-sm: 576px; */
  /* --bp-md: 768px; */
  /* --bp-lg: 1024px; */
  /* --bp-xl: 1280px; */

  /* Shadows */
  --shadow-sm: 0 1px 3px rgba(0,0,0,0.12);
  --shadow-md: 0 4px 6px rgba(0,0,0,0.1);
  --shadow-lg: 0 10px 25px rgba(0,0,0,0.15);

  /* Border radius */
  --radius-sm: 4px;
  --radius-md: 8px;
  --radius-lg: 16px;
  --radius-full: 9999px;
}
```

#### 2. Tools — миксины и функции (для препроцессоров)

В чистом CSS этот слой менее актуален, но с препроцессорами:

```css
/* В контексте чистого CSS — утилитарные custom properties и calc() паттерны */

/* Fluid typography tool */
/* font-size: clamp(min, preferred, max) */
/* Пример: от 16px на 320px viewport до 20px на 1200px viewport */
```

#### 3. Generic — reset/normalize, box-sizing

```css
/* _generic.css */
*, *::before, *::after {
  box-sizing: border-box;
  margin: 0;
  padding: 0;
}

html {
  -webkit-text-size-adjust: 100%;
  -moz-tab-size: 4;
  tab-size: 4;
}

body {
  min-height: 100vh;
  text-rendering: optimizeLegibility;
  -webkit-font-smoothing: antialiased;
  -moz-osx-font-smoothing: grayscale;
}
```

#### 4. Elements — стили для голых HTML-элементов

```css
/* _elements.css */
body {
  font-family: var(--font-family-base);
  font-size: var(--font-size-base);
  line-height: var(--line-height-base);
  color: var(--color-text);
  background-color: var(--color-background);
}

h1, h2, h3, h4, h5, h6 {
  font-family: var(--font-family-heading);
  line-height: 1.2;
  font-weight: 700;
}

a {
  color: var(--color-primary);
  text-decoration-skip-ink: auto;
}

img, video {
  max-width: 100%;
  height: auto;
  display: block;
}

table {
  border-collapse: collapse;
  width: 100%;
}
```

#### 5. Objects — OOCSS-паттерны без оформления

```css
/* _objects.css */
.o-container {
  max-width: 1200px;
  margin-inline: auto;
  padding-inline: var(--spacing-md);
}

.o-stack > * + * {
  margin-top: var(--spacing-md);
}

.o-cluster {
  display: flex;
  flex-wrap: wrap;
  gap: var(--spacing-sm);
  align-items: center;
}

.o-sidebar {
  display: flex;
  flex-wrap: wrap;
  gap: var(--spacing-lg);
}

.o-sidebar > :first-child {
  flex-basis: 300px;
  flex-grow: 1;
}

.o-sidebar > :last-child {
  flex-basis: 0;
  flex-grow: 999;
  min-width: 50%;
}

.o-grid {
  display: grid;
  grid-template-columns: repeat(auto-fit, minmax(min(250px, 100%), 1fr));
  gap: var(--spacing-md);
}
```

#### 6. Components — конкретные UI-компоненты

```css
/* _components.css */
.c-button {
  display: inline-flex;
  align-items: center;
  gap: var(--spacing-xs);
  padding: var(--spacing-sm) var(--spacing-md);
  border: 2px solid transparent;
  border-radius: var(--radius-md);
  font-size: var(--font-size-base);
  font-weight: 600;
  cursor: pointer;
  transition: all 0.2s ease;
}

.c-button--primary {
  background: var(--color-primary);
  color: white;
}

.c-button--primary:hover {
  background: color-mix(in srgb, var(--color-primary), black 15%);
}

.c-card {
  background: white;
  border-radius: var(--radius-md);
  box-shadow: var(--shadow-sm);
  overflow: hidden;
}

.c-card__header {
  padding: var(--spacing-md);
  border-bottom: 1px solid #eee;
}

.c-card__body {
  padding: var(--spacing-md);
}
```

#### 7. Utilities — утилиты с !important

```css
/* _utilities.css */
.u-visually-hidden {
  position: absolute !important;
  width: 1px !important;
  height: 1px !important;
  overflow: hidden !important;
  clip: rect(0, 0, 0, 0) !important;
  white-space: nowrap !important;
  border: 0 !important;
}

.u-text-center { text-align: center !important; }
.u-text-right { text-align: right !important; }
.u-font-bold { font-weight: bold !important; }
.u-mt-0 { margin-top: 0 !important; }
.u-mb-md { margin-bottom: var(--spacing-md) !important; }
.u-hidden { display: none !important; }
```

### Преимущества ITCSS

- Чёткий порядок импорта — специфичность растёт постепенно.
- Нет конфликтов — каждый слой знает своё место.
- Масштабируется — новые компоненты добавляются в свой слой.
- Совместим с BEM и другими naming conventions.

## 5. Atomic CSS / Utility-First

### Концепция

Atomic CSS (также Functional CSS или Utility-First CSS) — подход, при котором каждый CSS-класс отвечает за **одно** свойство.

```html
<div class="flex items-center gap-4 p-4 bg-white rounded-lg shadow-md">
  <img class="w-12 h-12 rounded-full" src="avatar.jpg" alt="Avatar">
  <div class="flex-1">
    <h3 class="text-lg font-semibold text-gray-900">Имя пользователя</h3>
    <p class="text-sm text-gray-500">Описание</p>
  </div>
</div>
```

### Tailwind CSS — доминирующий фреймворк

```css
/* Tailwind генерирует утилиты на основе конфигурации */

/* Spacing */
.p-4 { padding: 1rem; }
.mt-2 { margin-top: 0.5rem; }
.gap-4 { gap: 1rem; }

/* Colors */
.bg-blue-500 { background-color: #3b82f6; }
.text-white { color: #ffffff; }

/* Layout */
.flex { display: flex; }
.grid { display: grid; }
.items-center { align-items: center; }

/* Typography */
.text-lg { font-size: 1.125rem; line-height: 1.75rem; }
.font-bold { font-weight: 700; }

/* Responsive */
.md\:grid-cols-2 { /* ... */ }
.lg\:text-xl { /* ... */ }

/* State */
.hover\:bg-blue-600:hover { background-color: #2563eb; }
```

### Преимущества Utility-First

| Преимущество | Описание |
|-------------|----------|
| Нет naming проблем | Не нужно придумывать имена классов |
| Предсказуемость | Каждый класс делает ровно одно |
| Нет dead CSS | Утилиты shared между компонентами |
| Малый итоговый размер | С PurgeCSS — только используемые классы |
| Прототипирование | Быстрое создание UI без написания CSS |
| Consistency | Значения из design system |

### Недостатки Utility-First

| Недостаток | Описание |
|-----------|----------|
| Читаемость HTML | `class="flex items-center justify-between p-4 bg-white..."` |
| Обучение | Нужно выучить naming convention фреймворка |
| Компоненты | Без component abstraction (React/Vue) — дублирование |
| Кастомизация | Выход за рамки design system требует конфигурации |
| Разделение ответственности | Стили в HTML — нарушение separation of concerns |

### Когда использовать

```
Utility-First подходит когда:
✓ Компонентная архитектура (React, Vue, Svelte)
✓ Нужна скорость разработки
✓ Жёсткий design system
✓ Команда согласна с подходом

Utility-First НЕ подходит когда:
✗ Серверный рендеринг без компонентов (plain HTML)
✗ Сложная кастомная анимация
✗ CMS с пользовательским контентом
✗ Команда предпочитает semantic CSS
```

## 6. CSS Modules — scoped styles

### Концепция

CSS Modules — это файлы CSS, в которых все имена классов и анимаций по умолчанию **локальны** (scoped). Реализация на уровне build tool (webpack, Vite, esbuild).

### Как работает

```css
/* Button.module.css */
.button {
  padding: 8px 16px;
  border-radius: 4px;
  border: none;
  cursor: pointer;
}

.primary {
  background: #3498db;
  color: white;
}

.large {
  padding: 12px 24px;
  font-size: 1.1rem;
}
```

```jsx
// Button.jsx
import styles from './Button.module.css';

function Button({ variant, size, children }) {
  return (
    <button className={`${styles.button} ${styles[variant]} ${styles[size]}`}>
      {children}
    </button>
  );
}
```

Результат в DOM:

```html
<button class="Button_button_x7d2k Button_primary_a3f1j Button_large_m9p2q">
  Click me
</button>
```

### :global — выход из scope

```css
/* Button.module.css */

/* Локальный (по умолчанию) */
.button { }

/* Глобальный */
:global(.is-active) {
  font-weight: bold;
}

/* Комбинация */
.button :global(.icon) {
  margin-right: 8px;
}

/* Переключение режима */
:global {
  .some-global-class { }
  .another-global-class { }
}
```

### Composition (composes)

```css
/* base.module.css */
.flex-center {
  display: flex;
  align-items: center;
  justify-content: center;
}

/* Button.module.css */
.button {
  composes: flex-center from './base.module.css';
  padding: 8px 16px;
}

/* Composition из того же файла */
.base {
  border: none;
  cursor: pointer;
}

.primary {
  composes: base;
  background: blue;
  color: white;
}
```

### Интеграция с bundlers

#### Webpack

```javascript
// webpack.config.js
module.exports = {
  module: {
    rules: [
      {
        test: /\.module\.css$/,
        use: [
          'style-loader',
          {
            loader: 'css-loader',
            options: {
              modules: {
                localIdentName: '[name]__[local]--[hash:base64:5]',
              },
            },
          },
        ],
      },
    ],
  },
};
```

#### Vite

```javascript
// vite.config.js — CSS Modules работают "из коробки"
// Файлы с суффиксом .module.css автоматически обрабатываются
export default {
  css: {
    modules: {
      localsConvention: 'camelCaseOnly',
      generateScopedName: '[name]__[local]___[hash:base64:5]',
    },
  },
};
```

### Преимущества CSS Modules

- **Истинная изоляция** — конфликты имён невозможны.
- **Стандартный CSS** — нет нового синтаксиса для изучения (кроме `composes`).
- **Статический анализ** — неиспользуемые стили можно обнаружить.
- **Нет runtime overhead** — всё происходит на этапе сборки.
- **TypeScript support** — можно генерировать типы для стилей.

### Недостатки CSS Modules

- Зависимость от build tool.
- Сложность с динамическими стилями.
- Нет поддержки `:global` нативно (это расширение bundler).
- Composition ограничена — нет миксинов, наследования.

## 7. CSS-in-JS

### Обзор подходов

CSS-in-JS — семейство решений, где CSS пишется внутри JavaScript.

### Runtime CSS-in-JS

#### styled-components

```javascript
import styled from 'styled-components';

const Button = styled.button`
  padding: ${props => props.$size === 'large' ? '12px 24px' : '8px 16px'};
  background: ${props => props.$variant === 'primary' ? '#3498db' : 'transparent'};
  color: ${props => props.$variant === 'primary' ? 'white' : '#3498db'};
  border: 2px solid #3498db;
  border-radius: 4px;
  cursor: pointer;
  transition: all 0.2s;

  &:hover {
    background: ${props => props.$variant === 'primary' ? '#2980b9' : '#ebf5fb'};
  }
`;

// Использование
<Button $variant="primary" $size="large">Click</Button>
```

#### Emotion

```javascript
/** @jsxImportSource @emotion/react */
import { css } from '@emotion/react';
import styled from '@emotion/styled';

// CSS prop
const buttonStyles = css`
  padding: 8px 16px;
  background: #3498db;
  color: white;
  border: none;
  border-radius: 4px;
`;

<button css={buttonStyles}>Click</button>

// Styled API (аналогично styled-components)
const Card = styled.div`
  background: white;
  border-radius: 8px;
  box-shadow: 0 2px 8px rgba(0,0,0,0.1);
  padding: 1rem;
`;
```

### Zero-runtime CSS-in-JS

Zero-runtime решения извлекают CSS на этапе сборки, устраняя runtime overhead.

#### Vanilla Extract

```typescript
// button.css.ts
import { style, styleVariants } from '@vanilla-extract/css';

const base = style({
  padding: '8px 16px',
  border: 'none',
  borderRadius: '4px',
  cursor: 'pointer',
  transition: 'all 0.2s',
});

export const variants = styleVariants({
  primary: [base, { background: '#3498db', color: 'white' }],
  secondary: [base, { background: 'transparent', color: '#3498db', border: '2px solid #3498db' }],
});
```

#### Panda CSS

```typescript
// Utility-first + CSS-in-JS
import { css } from '../styled-system/css';

function Button() {
  return (
    <button className={css({
      padding: '8px 16px',
      bg: 'blue.500',
      color: 'white',
      borderRadius: 'md',
      _hover: { bg: 'blue.600' },
    })}>
      Click
    </button>
  );
}
```

### Сравнение Runtime vs Zero-Runtime

| Аспект | Runtime | Zero-Runtime |
|--------|---------|-------------|
| Динамические стили | Полная поддержка | Ограничена (CSS variables) |
| Bundle size | Runtime library (~10-15KB) | 0 KB runtime |
| SSR | Требует setup | Работает нативно |
| First paint | Замедляет (JS → CSS) | Не влияет |
| DX | Отличный | Хороший |
| Type safety | Частичная | Полная (Vanilla Extract) |

### Performance implications

```
Runtime CSS-in-JS:
├── JS parsing (library code ~10KB gzipped)
├── Style generation (interpolation, hashing)
├── Style injection (создание <style> тегов)
├── Re-renders (пересоздание стилей при prop changes)
└── Hydration mismatch (SSR → client)

Zero-Runtime:
├── Static CSS files (стандартная загрузка)
├── Нет JS overhead
├── CSS переменные для динамических значений
└── Стандартный CSS caching
```

> **Тренд индустрии (2024-2026):** Движение от runtime к zero-runtime CSS-in-JS. Многие проекты мигрируют с styled-components на Vanilla Extract, Panda CSS, или возвращаются к CSS Modules и Tailwind. React Server Components также плохо совместимы с runtime CSS-in-JS.

## 8. Cascade Layers (@layer) как архитектурный инструмент

### Основы

`@layer` позволяет **явно управлять порядком каскада**, независимо от порядка появления стилей или их специфичности.

```css
/* Объявление порядка слоёв */
@layer reset, base, components, utilities;

/* Стили в слоях */
@layer reset {
  *, *::before, *::after {
    margin: 0;
    padding: 0;
    box-sizing: border-box;
  }
}

@layer base {
  body {
    font-family: system-ui;
    line-height: 1.5;
  }

  a { color: #3498db; }
}

@layer components {
  .button {
    padding: 8px 16px;
    border-radius: 4px;
  }

  .card {
    background: white;
    border-radius: 8px;
    box-shadow: 0 2px 8px rgba(0,0,0,0.1);
  }
}

@layer utilities {
  .sr-only {
    position: absolute;
    width: 1px;
    height: 1px;
    overflow: hidden;
    clip: rect(0,0,0,0);
  }

  .text-center { text-align: center; }
}
```

### Порядок приоритета

```
Стили без @layer (unlayered)   ← САМЫЙ ВЫСОКИЙ приоритет
@layer utilities               ← Высокий
@layer components
@layer base
@layer reset                   ← Самый низкий
```

> **Ключевой момент:** Стили **вне** `@layer` **всегда побеждают** стили внутри `@layer`, независимо от специфичности. Это фундаментальное правило.

### Third-party resets

```css
/* Объявляем порядок ДО импорта */
@layer reset, third-party, base, components, overrides;

/* Третьесторонний CSS идёт в свой слой */
@import url('normalize.css') layer(reset);
@import url('some-library.css') layer(third-party);

/* Ваши стили гарантированно побеждают */
@layer components {
  .button {
    /* Этот стиль ВСЕГДА победит стили из third-party,
       даже если у третьей стороны выше специфичность */
    background: #3498db;
  }
}
```

### Вложенные слои

```css
@layer framework {
  @layer base {
    /* framework.base */
  }

  @layer components {
    /* framework.components */
  }
}

/* Обращение к вложенному слою */
@layer framework.components {
  .fw-button { }
}
```

### Design System с @layer

```css
@layer tokens, reset, base, layout, components, patterns, utilities, overrides;

@layer tokens {
  :root {
    --color-primary: #3498db;
    --spacing-unit: 8px;
  }
}

@layer reset {
  /* CSS Reset */
}

@layer base {
  /* Element styles */
}

@layer layout {
  /* Grid, container */
}

@layer components {
  /* Buttons, cards, modals */
}

@layer patterns {
  /* Composite patterns (hero, pricing table) */
}

@layer utilities {
  /* Single-purpose classes */
}

@layer overrides {
  /* Page-specific overrides */
}
```

### revert-layer

```css
@layer base {
  a { color: blue; }
}

@layer components {
  .nav-link {
    color: revert-layer;
    /* Откатывается к значению из предыдущего слоя (base) — blue */
  }
}
```

## 9. CSS Scoping (@scope)

### Концепция

`@scope` позволяет ограничить применение стилей **областью видимости** — определить верхнюю и нижнюю границы.

```css
@scope (.card) {
  /* Стили применяются только внутри .card */

  .title {
    font-size: 1.2rem;
    font-weight: bold;
  }

  .body {
    padding: 1rem;
  }

  img {
    border-radius: 8px;
  }
}
```

### Нижняя граница (lower boundary)

```css
@scope (.card) to (.card__footer) {
  /* Стили НЕ проникают в .card__footer и его потомков */

  p {
    color: #333;
    line-height: 1.6;
  }
}
```

```html
<div class="card">
  <p>Этот параграф будет стилизован</p>     <!-- ✓ -->
  <div class="card__footer">
    <p>Этот параграф НЕ будет стилизован</p> <!-- ✗ -->
  </div>
</div>
```

### Scope proximity

Когда два `@scope` правила имеют одинаковую специфичность, побеждает **ближайший** scope (по proximity в DOM).

```css
@scope (.light) {
  p { color: black; }
}

@scope (.dark) {
  p { color: white; }
}
```

```html
<div class="light">
  <div class="dark">
    <p>Белый текст — .dark ближе</p>
  </div>
</div>
```

### Специфичность @scope

`@scope` **не добавляет** специфичность. Селекторы внутри `@scope` имеют свою обычную специфичность.

```css
@scope (.card) {
  .title { /* Специфичность: (0, 1, 0) — только от .title */ }
}
```

### Использование с :scope

```css
@scope (.card) {
  /* :scope ссылается на scoping root (.card) */
  :scope {
    border: 1px solid #ddd;
    border-radius: 8px;
  }

  /* Прямые потомки scope root */
  :scope > .header {
    padding: 1rem;
  }
}
```

### Inline scope (без прелюда)

```html
<div class="widget">
  <style>
    @scope {
      /* Scope привязывается к ближайшему родительскому элементу <style> */
      p { color: red; }
    }
  </style>
  <p>Красный текст</p>
</div>
```

## 10. Design Tokens — CSS custom properties as tokens

### Что такое Design Tokens

Design tokens — это **атомарные единицы** дизайн-системы: цвета, шрифты, размеры, отступы, тени и т.д. CSS custom properties — идеальный инструмент для их реализации.

### Naming Convention

#### Трёхуровневая система

```css
:root {
  /* Tier 1: Global tokens (primitive values) */
  --blue-50: #ebf5fb;
  --blue-100: #d6eaf8;
  --blue-500: #3498db;
  --blue-600: #2980b9;
  --blue-900: #1a5276;

  --gray-50: #f8f9fa;
  --gray-100: #f1f3f5;
  --gray-500: #adb5bd;
  --gray-900: #212529;

  --spacing-1: 0.25rem;   /* 4px */
  --spacing-2: 0.5rem;    /* 8px */
  --spacing-3: 0.75rem;   /* 12px */
  --spacing-4: 1rem;      /* 16px */
  --spacing-6: 1.5rem;    /* 24px */
  --spacing-8: 2rem;      /* 32px */

  --font-size-xs: 0.75rem;
  --font-size-sm: 0.875rem;
  --font-size-md: 1rem;
  --font-size-lg: 1.125rem;
  --font-size-xl: 1.25rem;
  --font-size-2xl: 1.5rem;

  /* Tier 2: Semantic tokens (aliases) */
  --color-primary: var(--blue-500);
  --color-primary-hover: var(--blue-600);
  --color-background: var(--gray-50);
  --color-surface: white;
  --color-text: var(--gray-900);
  --color-text-muted: var(--gray-500);
  --color-border: var(--gray-100);
  --color-danger: #e74c3c;

  --font-size-body: var(--font-size-md);
  --font-size-heading: var(--font-size-2xl);
  --font-size-caption: var(--font-size-sm);

  /* Tier 3: Component tokens */
  --button-padding-x: var(--spacing-4);
  --button-padding-y: var(--spacing-2);

  --button-bg: var(--color-primary);
```

### Theme switching

```css
    --color-background: #1a1a2e;
```

```javascript
// Переключение темы
```

### Преимущества Design Tokens

- **Единый источник правды** — изменение токена обновляет все компоненты.
- **Темизация** — переключение темы одной строкой JS.
- **Consistency** — разработчики используют заданные значения.
- **Кроссплатформенность** — токены можно экспортировать в iOS, Android, Design tools.

## 11. Критерии выбора методологии

### Матрица принятия решений

| Критерий | BEM | OOCSS | SMACSS | ITCSS | Utility | CSS Modules | CSS-in-JS |
|----------|-----|-------|--------|-------|---------|-------------|-----------|
| Маленький проект | ✓ | ✓ | ○ | ○ | ✓ | ○ | ○ |
| Большой проект | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ |
| Без build tools | ✓ | ✓ | ✓ | ✓ | ○ | ✗ | ✗ |
| React/Vue/Svelte | ✓ | ○ | ○ | ○ | ✓ | ✓ | ✓ |
| Большая команда | ✓ | ○ | ✓ | ✓ | ✓ | ✓ | ✓ |
| Быстрый прототип | ○ | ○ | ○ | ○ | ✓ | ○ | ✓ |
| Design system | ✓ | ○ | ✓ | ✓ | ✓ | ✓ | ✓ |
| CMS/WordPress | ✓ | ✓ | ✓ | ✓ | ○ | ✗ | ✗ |
| Performance-critical | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ | ○ |

✓ — хорошо подходит, ○ — нормально, ✗ — плохо подходит

### Факторы выбора

#### 1. Размер проекта

- **Лендинг / маленький сайт** — BEM или Utility CSS. Не нужна сложная архитектура.
- **Средний проект (10-50 страниц)** — BEM + ITCSS или CSS Modules.
- **Крупное приложение (SPA)** — CSS Modules, CSS-in-JS, или Utility-First с компонентным фреймворком.
- **Design System** — ITCSS + BEM + @layer для максимальной структурированности.

#### 2. Команда

- **1-3 разработчика** — любая методология, которая нравится команде.
- **5+ разработчиков** — нужна формализованная методология с чёткими правилами (BEM, Utility-First).
- **Смешанная команда (frontend + backend)** — Utility-First (Tailwind) снижает барьер входа.

#### 3. Framework

- **Vanilla HTML/CSS** — BEM, SMACSS, ITCSS.
- **React** — CSS Modules, styled-components, Tailwind, Vanilla Extract.
- **Vue** — Scoped styles (встроенные), CSS Modules, Tailwind.
- **Svelte** — Scoped styles (встроенные), Tailwind.
- **Next.js / Nuxt** — CSS Modules (built-in), Tailwind, Vanilla Extract.

#### 4. Maintenance

- **Долгосрочный проект** — строгая методология (BEM + ITCSS) с документацией.
- **Быстрая итерация** — Utility-First для скорости.
- **Legacy codebase** — постепенное внедрение @layer для управления каскадом.

### Комбинирование подходов

Современные проекты часто **комбинируют** методологии:

```css
/* @layer для архитектуры (ITCSS) */
@layer reset, base, layout, components, utilities;

/* BEM для именования компонентов */
@layer components {
  .card { }
  .card__header { }
  .card__body { }
  .card--featured { }
}

/* Utility classes для мелких корректировок */
@layer utilities {
  .u-text-center { text-align: center !important; }
  .u-mt-0 { margin-top: 0 !important; }
}

/* Design tokens для consistency */
@layer base {
  :root {
    --color-primary: #3498db;
    --spacing-md: 1rem;
  }
}
```

> **Рекомендация:** Не бойтесь комбинировать. Используйте BEM для компонентов, ITCSS для структуры, @layer для управления каскадом, и design tokens для consistency. Идеальная методология — та, которую ваша команда **реально** соблюдает.
