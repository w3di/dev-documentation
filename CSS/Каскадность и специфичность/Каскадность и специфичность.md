## 1. Каскад — порядок определения стилей

### 1.1 Что такое каскад

**Каскад (Cascade)** — алгоритм, определяющий, какое CSS-объявление «побеждает», когда несколько правил применяются к одному элементу. Каскад учитывает несколько факторов в строгом порядке приоритетов.

Когда браузер определяет конечное значение CSS-свойства для элемента, он проходит через следующие шаги:

1. **Origin & Importance** (источник и важность)
2. **Context** (контекст — shadow DOM и т.д.)
3. **Element-attached styles** (inline-стили)
4. **Layers** (каскадные слои)
5. **Specificity** (специфичность)
6. **Order of Appearance** (порядок появления)

Если на каком-либо шаге есть однозначный «победитель», последующие шаги не рассматриваются.

### 1.2 Origins (источники стилей)

CSS-стили поступают из трёх источников:

| Origin | Описание | Пример |
|--------|----------|--------|
| **User-Agent** | Стили браузера по умолчанию | `display: block` для `<div>`, `font-weight: bold` для `<b>` |
| **User** | Стили, установленные пользователем | Accessibility-настройки, расширения |
| **Author** | Стили, написанные разработчиком | Все ваши CSS-файлы |

Для обычных (не-`!important`) объявлений порядок приоритетов:

```
User-Agent < User < Author
(самый низкий)     (самый высокий)
```

### 1.3 Importance (!important)

`!important` **инвертирует** порядок origins:

```css
.element {
  color: red !important;     /* Author !important */
}
```

Для `!important` объявлений:

```
Author !important < User !important < User-Agent !important
(самый низкий)                        (самый высокий)
```

> **Почему инверсия?** Это обеспечивает, что пользовательские настройки accessibility (увеличенный шрифт, высокий контраст) всегда могут перебить стили автора, а стили браузера для встроенных элементов (например, `hidden`) не могут быть случайно отключены.

### 1.4 Полная модель каскада (CSS Cascading Level 5+)

Современная модель включает дополнительные факторы:

```
1. Transition declarations
2. Origin & Importance
   a. User-Agent Normal
   b. User Normal
   c. Author Normal (с учётом @layer)
   d. Animation declarations
   e. Author !important (с учётом @layer — в обратном порядке!)
   f. User !important
   g. User-Agent !important
   h. Transition declarations
3. Context (encapsulation context — Shadow DOM)
4. Element-attached styles (style attribute)
5. Layers
6. Specificity
7. Order of Appearance
```

## 2. Cascade Layers

### 2.1 Основы @layer

`@layer` позволяет явно определить порядок приоритетов стилей, независимо от специфичности:

```css
/* Определение порядка слоёв (декларация) */
@layer reset, base, components, utilities;

/* Наполнение слоёв */
@layer reset {
  * {
    margin: 0;
    padding: 0;
    box-sizing: border-box;
  }
}

@layer base {
  h1 { font-size: 2rem; }
  p { line-height: 1.6; }
  a { color: var(--link-color, blue); }
}

@layer components {
  .card {
    border: 1px solid #e5e7eb;
    border-radius: 8px;
    padding: 1rem;
  }
  .button {
    padding: 0.5rem 1rem;
    background: blue;
    color: white;
  }
}

@layer utilities {
  .sr-only {
    position: absolute;
    width: 1px;
    height: 1px;
    overflow: hidden;
    clip: rect(0, 0, 0, 0);
  }
  .hidden { display: none; }
  .text-center { text-align: center; }
}
```

**Порядок приоритетов:** Более поздний слой побеждает:
```
reset < base < components < utilities
```

Правило в `utilities` перебьёт правило в `components`, **независимо от специфичности**:

```css
@layer components {
  #main .sidebar .nav a.link.active { /* Специфичность: 1-3-1 */
    color: blue;
  }
}

@layer utilities {
  .text-red { /* Специфичность: 0-1-0 */
    color: red;
  }
}

/* .text-red ПОБЕДИТ, т.к. utilities объявлен после components */
```

### 2.2 Способы определения слоёв

```css
/* 1. Декларация порядка (пустые слои) */
@layer reset, base, components;

/* 2. Блочный синтаксис */
@layer reset {
  /* стили */
}

/* 3. Через @import */
@import url("framework.css") layer(framework);
@import url("overrides.css") layer(overrides);

/* 4. Анонимный слой (нельзя дополнить позже) */
@layer {
  /* стили */
}

/* 5. Дополнение существующего слоя */
@layer base {
  body { font-family: sans-serif; }
}
/* Позже... */
@layer base {
  body { line-height: 1.5; } /* Добавляется в тот же слой "base" */
}
```

### 2.3 Вложенные слои

```css
@layer framework {
  @layer base {
    a { color: blue; }
  }
  @layer components {
    .btn { padding: 0.5rem 1rem; }
  }
}

/* Обращение к вложенному слою через точечную нотацию */
@layer framework.base {
  a { color: red; } /* Дополняет framework.base */
}

/* Декларация порядка вложенных слоёв */
@layer framework {
  @layer base, components, utilities;
}
```

### 2.4 Unlayered styles

Стили **вне** любого `@layer` имеют **наивысший приоритет** среди обычных (не-`!important`) стилей:

```css
@layer base {
  p { color: blue; }
}

/* Unlayered — побеждает любой layer */
p { color: red; } /* Этот стиль победит */
```

> **Важно:** Это ключевая концепция. Unlayered styles всегда выше layered, независимо от специфичности в layer.

### 2.5 revert-layer

Откатывает значение к предыдущему слою:

```css
@layer base {
  a { color: blue; }
}

@layer components {
  .nav a { color: green; }
}

@layer overrides {
  .special-nav a {
    color: revert-layer; /* Откатится к components: green */
  }
}
```

## 3. Специфичность — алгоритм подсчёта

### 3.1 Три компонента специфичности

Специфичность вычисляется как тройка `(A, B, C)`:

| Компонент | Что считается | Примеры |
|-----------|--------------|---------|
| **A** (ID) | Количество ID-селекторов | `#header`, `#main` |
| **B** (CLASS) | Количество class-селекторов, attribute-селекторов, pseudo-classes | `.active`, `[type]`, `:hover`, `:nth-child()` |
| **C** (TYPE) | Количество type-селекторов, pseudo-elements | `div`, `p`, `::before`, `::after` |

### 3.2 Правила подсчёта

```css
/* (0, 0, 0) — нулевая специфичность */
* { }
:where(.anything) { }

/* (0, 0, 1) — один type */
p { }
div { }
::before { }

/* (0, 0, 2) — два type */
ul li { }
div p { }
li::marker { }

/* (0, 1, 0) — один class */
.active { }
[type="text"] { }
:hover { }
:first-child { }

/* (0, 1, 1) — один class + один type */
p.active { }
div:hover { }
a::before { }   /* ОШИБКА: это (0, 0, 2), не (0, 1, 1) */
a:hover { }      /* ЭТО (0, 1, 1) */

/* (0, 2, 0) — два class */
.card.active { }
[type="text"]:focus { }

/* (0, 2, 1) — два class + один type */
div.card.active { }

/* (1, 0, 0) — один ID */
#header { }

/* (1, 0, 1) — один ID + один type */
#header nav { }

/* (1, 1, 0) — один ID + один class */
#header .nav { }

/* (1, 1, 3) — один ID + один class + три type */
#main div ul li a { }
/* Нет, пересчитаем: #main(1-0-0) div(0-0-1) ul(0-0-1) li(0-0-1) a(0-0-1) = (1-0-4) */

/* Правильный подсчёт #main .content div ul li */
/* #main = (1,0,0) + .content = (0,1,0) + div = (0,0,1) + ul = (0,0,1) + li = (0,0,1) */
/* Итого: (1, 1, 3) */
```

### 3.3 Сравнение специфичности

Специфичности сравниваются покомпонентно, **слева направо**:

```
(1, 0, 0) > (0, 99, 99)   — ID всегда побеждает CLASS и TYPE
(0, 2, 0) > (0, 1, 99)    — при равных ID, больше CLASS побеждает
(0, 0, 3) > (0, 0, 2)     — при равных ID и CLASS, больше TYPE побеждает
(0, 1, 0) = (0, 1, 0)     — при равной специфичности → порядок появления
```

### 3.4 Примеры расчёта

```css
/* Пример 1 */
body header nav ul li a.active { }
/* body(T) header(T) nav(T) ul(T) li(T) a(T).active(C) */
/* = (0, 1, 6) */

/* Пример 2 */
#sidebar .widget > h3:first-child::after { }
/* #sidebar(ID) .widget(C) h3(T) :first-child(C) ::after(T) */
/* = (1, 2, 2) */

/* Пример 3 */
div:not(.active):hover { }
/* div(T) :not(.active → C) :hover(C) */
/* = (0, 2, 1) */
/* Примечание: :not() сам не добавляет специфичности, считается его аргумент */

/* Пример 4 */
:is(#header, .nav) a { }
/* :is(#header → ID) a(T) */
/* = (1, 0, 1) — :is() берёт МАКСИМУМ из аргументов */

/* Пример 5 */
:where(#header, .nav) a { }
/* :where(...) a(T) */
/* = (0, 0, 1) — :where() ВСЕГДА ноль */

/* Пример 6 */
:has(> .active) .title { }
/* :has(.active → C) .title(C) */
/* = (0, 2, 0) */

/* Пример 7 */
[id="header"] { }
/* = (0, 1, 0) — attribute selector, NOT ID selector! */
/* Хак для понижения специфичности ID */
```

### 3.5 Таблица для быстрого подсчёта

| Селектор | A (ID) | B (CLASS) | C (TYPE) | Итого |
|----------|--------|-----------|----------|-------|
| `*` | 0 | 0 | 0 | (0,0,0) |
| `div` | 0 | 0 | 1 | (0,0,1) |
| `div p` | 0 | 0 | 2 | (0,0,2) |
| `.card` | 0 | 1 | 0 | (0,1,0) |
| `div.card` | 0 | 1 | 1 | (0,1,1) |
| `.card.active` | 0 | 2 | 0 | (0,2,0) |
| `#header` | 1 | 0 | 0 | (1,0,0) |
| `#header .nav` | 1 | 1 | 0 | (1,1,0) |
| `#header .nav li.active` | 1 | 2 | 1 | (1,2,1) |
| `style=""` (inline) | — | — | — | всегда выше |
| `!important` | — | — | — | см. cascade order |

## 4. Вес селекторов

### 4.1 !important

```css
.element {
  color: red !important;
}
```

`!important` не влияет на специфичность — он меняет **уровень каскада**. Объявление с `!important` попадает в отдельную категорию origin (см. раздел 9).

**Когда использование `!important` оправдано:**
- Утилитарные классы (`.hidden { display: none !important; }`)
- Переопределение inline-стилей, которые вы не контролируете
- Переопределение стилей третьих библиотек
- Accessibility-стили пользователя

**Когда `!important` — антипаттерн:**
- «Быстрое решение» проблем специфичности
- Массовое использование в основных стилях
- Вместо правильной организации каскада

> **Правило:** Если вы часто используете `!important`, это сигнал о проблемах в архитектуре CSS.

### 4.2 Inline Styles

```html
<div style="color: red;">Текст</div>
```

Inline-стили побеждают **любую** специфичность из stylesheet, но проигрывают `!important`:

```css
/* Не сработает — inline стиль сильнее */
#main .content div.special p { color: blue; }

/* Сработает — !important побеждает inline */
p { color: blue !important; }
```

### 4.3 Специфичность :where() — всегда ноль

```css
:where(#header .nav ul li a.active:hover) {
  color: red;
}
/* Специфичность: (0, 0, 0) — ноль, несмотря на #id и классы внутри */

/* Любой самый простой селектор перебьёт */
a { color: blue; } /* (0, 0, 1) > (0, 0, 0) → победит blue */
```

### 4.4 Полная иерархия «весов»

От **наименьшего** к **наибольшему** приоритету для author-стилей:

```
1. :where()          → (0, 0, 0)
2. *, combinator     → (0, 0, 0)
3. type, ::pseudo    → (0, 0, 1+)
4. .class, [attr], :pseudo → (0, 1+, 0+)
5. #id               → (1+, 0, 0)
6. inline style=""   → выше любого селектора
7. !important        → выше inline (с инверсией origins)
```

## 5. Специфичность pseudo-classes

### 5.1 :is() — специфичность = максимум из аргументов

```css
:is(.nav, #header, footer) a { }
/* :is() берёт специфичность наиболее специфичного аргумента */
/* .nav = (0,1,0), #header = (1,0,0), footer = (0,0,1) */
/* Максимум = (1,0,0) */
/* + a = (0,0,1) */
/* Итого: (1, 0, 1) */
```

> **Gotcha:** Это значит, что `:is(.nav, #header) a` будет иметь специфичность `(1,0,1)` даже для `footer a`, хотя `footer` — type selector с низкой специфичностью. Специфичность определяется **всем списком**, а не конкретным совпавшим аргументом.

### 5.2 :where() — специфичность = всегда ноль

```css
:where(#header, .nav, footer) a { }
/* Специфичность :where() = (0, 0, 0) */
/* + a = (0, 0, 1) */
/* Итого: (0, 0, 1) */
```

### 5.3 :not() — специфичность = аргумент

```css
p:not(.special) { }
/* p = (0,0,1), :not(.special) → .special = (0,1,0) */
/* Итого: (0, 1, 1) */

p:not(#unique) { }
/* p = (0,0,1), :not(#unique) → #unique = (1,0,0) */
/* Итого: (1, 0, 1) */

/* Множественные аргументы — берётся максимум */
p:not(.a, #b) { }
/* p = (0,0,1), :not(.a, #b) → max(0-1-0, 1-0-0) = (1,0,0) */
/* Итого: (1, 0, 1) */
```

### 5.4 :has() — специфичность = аргумент

```css
.card:has(.active) { }
/* .card = (0,1,0), :has(.active) → .active = (0,1,0) */
/* Итого: (0, 2, 0) */

.card:has(#main) { }
/* .card = (0,1,0), :has(#main) → #main = (1,0,0) */
/* Итого: (1, 1, 0) */

div:has(> .item:hover) { }
/* div = (0,0,1), :has(> .item:hover) → .item(0,1,0) + :hover(0,1,0) = (0,2,0) */
/* Итого: (0, 2, 1) */
```

### 5.5 :nth-child() с of S — специфичность

```css
:nth-child(2n+1 of .active) { }
/* :nth-child() = (0,1,0) как pseudo-class */
/* + of .active → .active = (0,1,0) */
/* Итого: (0, 2, 0) */

:nth-child(odd of #main, .sidebar) { }
/* :nth-child() = (0,1,0) */
/* + of #main → max(1-0-0, 0-1-0) = (1,0,0) */
/* Итого: (1, 1, 0) */
```

### 5.6 Сводная таблица

| Pseudo-class | Специфичность | Forgiving |
|-------------|--------------|-----------|
| `:is(S)` | max(S) | Да |
| `:where(S)` | (0,0,0) | Да |
| `:not(S)` | max(S) | Нет |
| `:has(S)` | max(S) | Нет |
| `:nth-child(An+B of S)` | (0,1,0) + max(S) | Нет |
| `:hover`, `:focus` и т.д. | (0,1,0) | — |
| `:first-child`, `:last-child` | (0,1,0) | — |

## 6. Порядок появления

### 6.1 Правило «последний побеждает»

При **равной специфичности** и **одинаковом origin** побеждает объявление, появляющееся **позже** в коде:

```css
.button { color: blue; }  /* Первое */
.button { color: red; }   /* Второе — победит */
```

### 6.2 Порядок подключения файлов

```html
<!-- Порядок подключения определяет порядок появления -->
<link rel="stylesheet" href="base.css">      <!-- Первый -->
<link rel="stylesheet" href="components.css"> <!-- Второй -->
<link rel="stylesheet" href="utilities.css">  <!-- Третий — приоритетнее -->

<style>
  /* Internal стили идут после external */
</style>
```

### 6.3 Порядок внутри at-rules

```css
/* Медиа-запросы не создают дополнительной специфичности */
.element { color: blue; }

@media (min-width: 768px) {
  .element { color: red; } /* Побеждает (позже в файле) при совпадении условия */
}

/* При равной специфичности — порядок в файле */
@media (max-width: 768px) {
  .element { color: green; }
}

@media (max-width: 600px) {
  .element { color: orange; } /* На экранах < 600px побеждает */
}
/* На экранах 600-768px: color: green (раньше, но max-width: 768px совпадает) */
```

> **Рекомендация по медиа-запросам:** Для mobile-first используйте `min-width` и располагайте от меньшего к большему. Для desktop-first используйте `max-width` от большего к меньшему. Это обеспечивает правильный каскад.

```css
/* Mobile-first (правильный порядок) */
.element { font-size: 14px; }                /* Базовый (mobile) */
@media (min-width: 768px) { .element { font-size: 16px; } }  /* Tablet */
@media (min-width: 1024px) { .element { font-size: 18px; } } /* Desktop */
```

### 6.4 Порядок и @import

```css
/* @import вставляет стили на место импорта */
@import url("reset.css");    /* Как если бы содержимое было здесь */
@import url("base.css");     /* Потом здесь */

/* Стили после @import имеют более высокий порядок */
.my-styles { }
```

## 7. Наследование

### 7.1 Наследуемые свойства

Наследование — механизм, при котором дочерние элементы получают значения свойств от родителей. Это отдельный от каскада механизм, который срабатывает **только если каскад не определил значение**.

**Полный список основных наследуемых свойств:**

| Категория | Свойства |
|-----------|----------|
| Текст | `color`, `font`, `font-family`, `font-size`, `font-style`, `font-variant`, `font-weight`, `letter-spacing`, `line-height`, `text-align`, `text-indent`, `text-transform`, `white-space`, `word-spacing`, `word-break`, `overflow-wrap`, `text-wrap` |
| Списки | `list-style`, `list-style-type`, `list-style-position`, `list-style-image` |
| Таблицы | `border-collapse`, `border-spacing`, `caption-side`, `empty-cells` |
| Другие | `visibility`, `cursor`, `direction`, `writing-mode`, `quotes`, `orphans`, `widows`, `tab-size` |

### 7.2 Ненаследуемые свойства

**Важные ненаследуемые:**

| Категория | Свойства |
|-----------|----------|
| Box model | `width`, `height`, `margin`, `padding`, `border` |
| Background | `background`, `background-color`, `background-image` |
| Display | `display`, `float`, `clear`, `overflow` |
| Position | `position`, `top`, `right`, `bottom`, `left`, `z-index` |
| Flex/Grid | `flex`, `grid-*`, `align-items`, `justify-content` |
| Visual | `opacity`, `transform`, `box-shadow`, `outline` |
| Transition | `transition`, `animation` |

### 7.3 Ключевые слова

```css
.child {
  /* inherit — принудительное наследование */
  border: inherit;   /* Наследует border от родителя (обычно не наследуется) */
  margin: inherit;   /* Наследует margin от родителя */

  /* initial — начальное значение из спецификации */
  color: initial;    /* Обычно чёрный (зависит от спецификации) */
  display: initial;  /* inline (начальное значение display) */

  /* unset — "умный" сброс */
  color: unset;      /* → inherit (color наследуется) */
  border: unset;     /* → initial (border не наследуется) */

  /* revert — откат к предыдущему origin */
  display: revert;   /* Откат к user-agent стилю */

  /* revert-layer — откат к предыдущему @layer */
  color: revert-layer;
}
```

### 7.4 Свойство all

```css
/* Сброс всех свойств, кроме direction и unicode-bidi */
.reset-element {
  all: initial;       /* Все свойства → initial */
}

.isolated {
  all: revert;        /* Все свойства → user-agent defaults */
}

/* Полезно для создания изолированных компонентов */
.widget {
  all: initial;
  display: block;
  font-family: system-ui;
  /* Начинаем стилизацию с чистого листа */
}
```

> **Осторожно с `all: initial`:** `display: initial` = `inline`, `font-size: initial` = `medium` (не 16px!), `color: initial` = `canvastext` (зависит от системных настроек). Результат может быть неожиданным. `all: revert` обычно предсказуемее.

### 7.5 Наследование и Custom Properties

Custom Properties **наследуются по умолчанию**, если не указано иное через `@property`:

```css
:root {
  --spacing: 8px;
}

.parent {
  --text-color: blue;
}

.parent .child {
  color: var(--text-color); /* blue — унаследовано */
  margin: var(--spacing);   /* 8px — унаследовано от :root */
}

/* Запрет наследования через @property */
@property --component-bg {
  syntax: '<color>';
  initial-value: white;
  inherits: false;
}
```

## 8. @layer глубоко

### 8.1 Unlayered styles vs Layered styles

**Unlayered** стили (написанные вне `@layer`) имеют более высокий приоритет, чем любые layered стили:

```css
@layer base {
  #main .content .article p.highlight {
    color: blue; /* Специфичность: (1, 3, 1) */
  }
}

/* Unlayered — побеждает при любой специфичности */
p {
  color: red; /* Специфичность: (0, 0, 1) — но unlayered! */
}
/* Результат: color будет red */
```

**Порядок приоритетов (normal declarations):**
```
Layered (в порядке объявления слоёв) < Unlayered
```

### 8.2 Important Order Reversal

Для `!important` объявлений порядок слоёв **инвертируется**:

```css
@layer reset, base, components, utilities;

/* Normal declarations: reset < base < components < utilities < unlayered */
/* !important declarations: unlayered < utilities < components < base < reset */
```

Это значит, что `!important` в раннем слое сильнее, чем `!important` в позднем:

```css
@layer reset {
  * {
    box-sizing: border-box !important; /* САМЫЙ СИЛЬНЫЙ !important */
  }
}

@layer utilities {
  .content-box {
    box-sizing: content-box !important; /* Слабее, чем reset !important */
  }
}
```

> **Логика инверсии:** Слой с более низким приоритетом (ранний) считается «более фундаментальным». Если он использует `!important`, он действительно хочет гарантировать это значение и должен побеждать `!important` из менее фундаментальных слоёв.

### 8.3 Layer Ordering Algorithm

Алгоритм определения порядка слоёв:

1. Слои, объявленные раньше в коде, имеют **более низкий** приоритет
2. Порядок определяется первым появлением имени слоя
3. Повторные объявления `@layer name` дополняют существующий слой, но не меняют порядок
4. Анонимные `@layer {}` всегда создают новый слой в текущей позиции

```css
/* Объявление порядка */
@layer A, B, C;

@layer C {
  /* Содержимое добавляется в C, но порядок уже определён */
}

@layer A {
  /* Содержимое добавляется в A */
}

/* Порядок: A < B < C (определён первой декларацией) */
```

```css
/* Без явного объявления порядка */
@layer B { p { color: blue; } }
@layer A { p { color: red; } }
@layer C { p { color: green; } }

/* Порядок: B < A < C (по первому появлению) */
/* Результат: color = green */
```

### 8.4 Вложенные слои и порядок

```css
@layer framework {
  @layer reset, base, components;

  @layer reset {
    * { margin: 0; }
  }

  @layer components {
    .btn { padding: 0.5rem; }
  }
}

@layer app {
  @layer components, utilities;

  @layer components {
    .card { border: 1px solid #ccc; }
  }
}

/* Полный порядок (плоский):
   framework.reset
   framework.base
   framework.components
   app.components
   app.utilities
   (unlayered)
*/
```

### 8.5 @import с layers

```css
/* Определяем порядок слоёв, затем импортируем */
@layer reset, vendor, components, utilities;

@import url("normalize.css") layer(reset);
@import url("tailwind-base.css") layer(vendor);

@layer components {
  .custom-card { /* ... */ }
}

@layer utilities {
  .mt-4 { margin-top: 1rem; }
}
```

### 8.6 Практический пример организации

```css
/* styles.css — точка входа */

/* 1. Определяем порядок всех слоёв */
@layer reset, vendor, tokens, base, layouts, components, utilities;

/* 2. Импорт стилей в соответствующие слои */
@import url("reset.css") layer(reset);
@import url("vendor/some-library.css") layer(vendor);

/* 3. Наполняем слои */
@layer tokens {
  :root {
    --color-primary: #3b82f6;
    --color-error: #ef4444;
    --spacing-sm: 0.5rem;
    --spacing-md: 1rem;
    --radius: 4px;
  }
}

@layer base {
  body {
    font-family: system-ui, sans-serif;
    line-height: 1.5;
    color: var(--color-text, #333);
  }
  a { color: var(--color-primary); }
  img { max-width: 100%; height: auto; }
}

@layer layouts {
  .container { max-width: 1200px; margin: 0 auto; padding: 0 1rem; }
  .grid { display: grid; gap: var(--spacing-md); }
}

@layer components {
  .card { /* ... */ }
  .button { /* ... */ }
  .modal { /* ... */ }
}

@layer utilities {
  .hidden { display: none !important; }
  .sr-only { /* ... */ }
  .text-center { text-align: center; }
}
```

## 9. Cascade origin order — полная таблица приоритетов

### 9.1 Полный порядок (от наименьшего к наибольшему приоритету)

```
 1.  User-Agent Normal          — Стили браузера по умолчанию
 2.  User Normal                — Пользовательские стили
 3.  Author Normal (layered)    — Авторские стили в @layer (в порядке слоёв)
 4.  Author Normal (unlayered)  — Авторские стили без @layer
 5.  Author Normal (inline)     — style=""
 6.  Animations (@keyframes)    — CSS-анимации в процессе выполнения
 7.  Author !important (inline) — style="...!important"
 8.  Author !important (unlayered) — !important без @layer
 9.  Author !important (layered)   — !important в @layer (ОБРАТНЫЙ порядок слоёв!)
10.  User !important             — Пользовательские !important
11.  User-Agent !important       — Браузерные !important
12.  Transitions                 — CSS-переходы (transition)
```

### 9.2 Визуальная таблица

| # | Origin | Importance | Layer | Приоритет |
|---|--------|------------|-------|-----------|
| 1 | User-Agent | Normal | — | Самый низкий |
| 2 | User | Normal | — | |
| 3 | Author | Normal | @layer (по порядку слоёв) | |
| 4 | Author | Normal | Unlayered | |
| 5 | Author | Normal | Inline (style="") | |
| 6 | — | — | Animations | |
| 7 | Author | !important | Inline !important | |
| 8 | Author | !important | Unlayered | |
| 9 | Author | !important | @layer (ОБРАТНЫЙ порядок!) | |
| 10 | User | !important | — | |
| 11 | User-Agent | !important | — | |
| 12 | — | — | Transitions | Самый высокий |

### 9.3 Примеры определения победителя

**Пример 1: Layer vs Unlayered**
```css
@layer base {
  p { color: blue; }  /* Author normal, layered */
}

p { color: red; }     /* Author normal, unlayered */

/* Победитель: red (unlayered > layered) */
```

**Пример 2: Important layer inversion**
```css
@layer A, B;

@layer A {
  p { color: blue !important; }  /* A !important */
}

@layer B {
  p { color: red !important; }   /* B !important */
}

/* Normal: A < B, но !important ИНВЕРТИРУЕТ: B < A */
/* Победитель: blue (A !important сильнее B !important) */
```

**Пример 3: Important unlayered vs layered**
```css
@layer utils {
  .text-red { color: red !important; }  /* layered !important */
}

p { color: blue !important; }  /* unlayered !important */

/* !important: unlayered < layered (инверсия normal порядка) */
/* Победитель: red (layered !important сильнее unlayered !important) */
```

**Пример 4: Transition vs Everything**
```css
.element {
  color: blue !important;       /* !important */
  transition: color 0.3s;
}

.element:hover {
  color: red;                    /* Normal */
}

/* Transition в процессе анимации побеждает ВСЁ */
/* При hover: transition value (промежуточное значение) будет активно */
```

**Пример 5: Animation specifics**
```css
.element {
  color: blue;           /* Normal */
  animation: change 2s;
}

@keyframes change {
  to { color: red; }     /* Animation */
}

/* Animation побеждает normal declarations, но ПРОИГРЫВАЕТ !important */

.element {
  color: blue !important; /* !important побеждает animation */
}
```

## 10. Практические задачи

### 10.1 Задача: Определите цвет текста

```html
<div id="wrapper">
  <p class="text highlight">Какой цвет?</p>
</div>
```

```css
@layer base, theme;

@layer base {
  #wrapper p { color: blue; }
}

@layer theme {
  .text { color: green; }
}

p.highlight { color: red; }
```

**Ответ:** `red`

**Объяснение:**
1. `#wrapper p` — layered (base), специфичность (1,0,1)
2. `.text` — layered (theme), специфичность (0,1,0)
3. `p.highlight` — **unlayered**, специфичность (0,1,1)

Unlayered всегда побеждает layered. Результат: `red`.

### 10.2 Задача: Important в layers

```css
@layer A, B;

@layer A {
  .text { color: blue !important; }
}

@layer B {
  .text { color: green !important; }
}

.text { color: red !important; }
```

**Ответ:** `blue`

**Объяснение:**
Для `!important` порядок инвертируется:
- Normal: A < B < unlayered
- !important: unlayered < B < A
Самый ранний layer с `!important` побеждает. Результат: `blue`.

### 10.3 Задача: Специфичность :is() и :where()

```css
:where(#main) .card { color: blue; }   /* (0, 1, 0) */
:is(footer) .card { color: green; }    /* (0, 1, 1) */
div .card { color: red; }             /* (0, 1, 1) */
```

**Ответ:** `red` (последний при равной специфичности)

**Объяснение:**
- `:where(#main) .card` → (0, 0, 0) + (0, 1, 0) = **(0, 1, 0)**
- `:is(footer) .card` → (0, 0, 1) + (0, 1, 0) = **(0, 1, 1)**
- `div .card` → (0, 0, 1) + (0, 1, 0) = **(0, 1, 1)**

`:is(footer) .card` и `div .card` имеют одинаковую специфичность (0, 1, 1). При равной специфичности побеждает последний по порядку → `red`.

### 10.4 Задача: Наследование vs каскад

```html
<div class="parent">
  <p class="child">Текст</p>
</div>
```

```css
.parent { color: blue; }
p { color: green; }
```

**Ответ:** `green`

**Объяснение:** Каскад имеет приоритет над наследованием. `p` непосредственно устанавливает `color: green` на элементе `<p>`. Наследование от `.parent` (blue) игнорируется, потому что есть прямое совпадение через каскад.

### 10.5 Задача: :has() и специфичность

```css
.card:has(> .badge) { background: yellow; }  /* (0, 2, 0) */
.card.featured { background: blue; }         /* (0, 2, 0) */
```

Для `<div class="card featured">` с `<span class="badge">`:

**Ответ:** `blue` (последний при равной специфичности)

**Объяснение:**
- `.card:has(> .badge)` → .card(0,1,0) + :has(.badge)(0,1,0) = **(0, 2, 0)**
- `.card.featured` → .card(0,1,0) + .featured(0,1,0) = **(0, 2, 0)**

Равная специфичность → побеждает последний в коде → `blue`.

### 10.6 Задача: Inline style vs !important

```html
<p style="color: red;">Текст</p>
```

```css
p { color: blue !important; }
```

**Ответ:** `blue`

**Объяснение:** `!important` из stylesheet побеждает inline style без `!important`. В cascade order:
- `style="color: red"` → Author Normal Inline (#5)
- `p { color: blue !important }` → Author !important Unlayered (#8)

#8 > #5 → `blue`.

### 10.7 Задача: Сложный каскад

```css
@layer framework, app;

@layer framework {
  .btn {
    background: gray;
    color: white !important;
  }
}

@layer app {
  .primary-btn {
    background: blue;
    color: black;
  }
}

.btn {
  background: green;  /* unlayered normal */
}
```

Для `<button class="btn primary-btn">`:

**Ответ:**
- `background: green` (unlayered normal > layered normal)
- `color: white` (framework !important > всего, т.к. для !important ранний layer = самый сильный)

**Объяснение:**
- `background`:
  - gray (framework layer, normal)
  - blue (app layer, normal)
  - green (unlayered, normal)
  - Normal order: framework < app < unlayered → **green**

- `color`:
  - white !important (framework layer)
  - black (app layer, normal)
  - !important инвертирует порядок: unlayered < app < framework
  - **white** побеждает

### 10.8 Debugging Specificity Wars

Стратегии решения проблем со специфичностью:

```css
/* 1. Используйте @layer для структурирования */
@layer base, components, utilities;

/* 2. Используйте :where() для «мягких» стилей */
:where(.default-styles) p {
  color: gray; /* Легко переопределить */
}

/* 3. Вместо ID-селектора — attribute selector */
[id="header"] { } /* (0,1,0) вместо (1,0,0) */

/* 4. Удвоение класса для повышения специфичности (хак) */
.button.button { } /* (0,2,0) вместо (0,1,0) */

/* 5. :is() для повышения специфичности без ID */
:is(.wrapper) .card { } /* (0,2,0) */
```

**Инструменты для отладки:**
- Browser DevTools: вкладка Computed Styles показывает все объявления и их приоритет
- Перечёркнутые стили — проигравшие в каскаде
- Специфичность отображается при наведении на селектор в DevTools

## Заключение

Каскад и специфичность — фундамент CSS, определяющий, какие стили применяются к элементам. Ключевые выводы:

- **Каскад** — многоуровневая система приоритетов: origin, importance, layers, specificity, order
- **`@layer`** — революционное дополнение, позволяющее управлять приоритетами на уровне архитектуры, не прибегая к «войнам специфичности»
- **Инверсия порядка для `!important`** — ключевая концепция `@layer`, где ранние слои становятся сильнее поздних
- **Unlayered стили** занимают особое положение: выше всех layers для normal, но ниже всех для `!important`
- **`:where()`** с нулевой специфичностью и **`:is()`** с максимальной специфичностью из аргументов — мощные инструменты для контроля приоритетов
- **Наследование** работает только когда каскад не определил значение

Грамотная организация каскада через `@layer`, продуманная система классов и минимальное использование `!important` — признак зрелой CSS-архитектуры.
